## Findings

- [blocker] `ERR-CORE-001-swallowed-cleanup` Deferred isolation cleanup can swallow failure — RunPerformance defers `if isolationActive { _ = isolation.cleanup() }` discarding the returned error. If the function returns via the success path while isolation is still active (interrupt, panic, early return not through finishFailure), cleanup uncertainty is lost. This violates ERR-CORE-001 (no failure may disappear, must emit structured failure and explicit terminal state) and ERR-DATA-001/ERR-TASK-001 which require cleanup proof and explicit blocked/cleanup_uncertain outcome.
  - action: Do not discard cleanup error. Join it into the return error, set outcome to cleanup_uncertain, and emit a structured diagnostic. Ensure every exit path either proves cleanup or records cleanup_uncertain as the existing finishPerformanceFailure helper does.
  - citation: `target/internal/sprint/performance.go:346-350`
- [high] `ERR-CODE-001-free-form-domain-errors` Domain and dependency errors use sentences as codes — internal/sprint performance errors are created with free-form sentences ("benchmark output was truncated", "performance process cleanup is uncertain", "invalid performance attempt ID", "performance is disabled for this project") via fmt.Errorf. ERR-CODE-001 forbids sentences/exception names as codes and requires {category}.{reason} stability. ERR-DEP-001 and ERR-DATA-001 also require classified subcodes with timeout/retry semantics and distinct persistence vs not-found signals, which are lost.
  - action: Introduce typed performance error constructors (e.g., NewPerformanceError with Category performance/dependency/timeout/data/workflow) or wrap with sentinel errors and use errors.As at boundaries. Ensure dependency (process/runner) and persistence failures emit distinct codes and retryable flags per ERR-DEP-001/ERR-DATA-001.
  - citation: `target/internal/sprint/performance_measure.go:32-35`
  - citation: `target/internal/sprint/performance_state.go:286-290`
  - citation: `target/internal/sprint/performance.go:212-224`
- [high] `ERR-CODE-001-perf-generic-code` Performance CLI collapses distinct failures into single code — sprint_commands.go write() for performance always emits code "performance.failed" regardless of whether the cause is validation, dependency timeout, persistence conflict, process cleanup uncertainty, or admission block. This violates ERR-CODE-001 (stable machine-usable codes, no catch-all) and ERR-SHAPE-001/ERR-IO-001 which require stable category-aligned codes preserved through CLI/JSON boundaries. QA path correctly maps qa.<category> codes; performance path does not.
  - action: Replace the catch-all with stable codes such as performance.validation.missing_prereq, performance.dependency.cleanup_uncertain, performance.data.conflict, performance.workflow.blocked and populate OperationError.category/code/retryable per ERR-SHAPE-001. Map them through the same stableCommandError/stableQACommandError pattern used for QA.
  - citation: `target/internal/app/sprint_commands.go:945-948`
- [high] `ERR-DATA-001-unclassified-persistence` Performance persistence failures not distinct from not-found — PerformanceStore.publishBytes/PublishJSON return generic fmt.Errorf("publish performance %s: %w") and ReadBytes checks `hashBytes != digest` with the same generic message. Errors do not carry distinct category (data.integrity vs data.connectivity vs not-found) and the caller cannot distinguish storage outage from missing rows, violating ERR-DATA-001 which requires separate mapping, entity IDs and explicit write-confirmation failure distinct from not-found.
  - action: Use the same QAError taxonomy for performance store (e.g., data.conflict, data.integrity, data.not_found) or introduce PerformanceError with Category data and preserve entity id (attemptID/name) and operation. Ensure callers preserve code/category through translation per ERR-TRANS-001.
  - citation: `target/internal/sprint/performance_state.go:286-338`
- [low] `DOC-ARCH-001-performance-rationale` Architecture section describes result without explicit alternatives/trade-offs — docs/architecture.md 262-289 correctly assigns activation to internal/project, sole target authority to requirements.md, closed go-benchmark-v1/ultraplan-json-v1 descriptors, and private immutable evidence, but does not record why closed descriptors/frozen manifest were chosen over runtime-authored commands or the consequence of that choice, which DOC-ARCH-001 expects for a new verification phase. The full trade-off is in sprint reasoning, but the durable architecture doc should retain a 2-3 line ADR pointer.
