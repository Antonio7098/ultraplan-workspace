## Relevant Patterns

- **Thin transport over an application boundary:** The structural report finds stable one-way delegation in Helm's command-to-action split (`helm/pkg/cmd/install.go:347`, `helm/pkg/action/install.go:73-140`) and gdu's swappable UI interface (`gdu/cmd/gdu/app/app.go:30-49`). For this sprint, that evidence creates pressure for HTTP handlers and templates to translate requests/results rather than acquire product workflow semantics.
- **Explicit composition with narrow, substitutable dependencies:** Gh-cli gathers lazy dependencies in `gh-cli/pkg/cmdutil/factory.go:16-43`; opencode constructs services centrally at `opencode/internal/app/app.go:42-81`; restic defines bounded backend contracts at `restic/internal/backend/backend.go:19-90`. This pattern may support one operation capability surface shared by CLI, TUI, and web while keeping fakes cheap.
- **Context-owned operation lifecycle:** Helm wires signals to cancellation at `helm/pkg/cmd/install.go:333-347`; go-task coordinates sibling cancellation with `errgroup.WithContext` at `go-task/task.go:89`; opencode tracks cancellable requests at `opencode/internal/llm/agent/agent.go:117-133`. This evidence raises the distinction between cancellation propagated into an existing work context and cancellation inferred from an SSE connection.
- **Explicit lock or deduplication ownership near shared state:** Restic models repository exclusion with a typed lock at `restic/internal/restic/lock.go:47,105`; go-task keys in-flight executions and waits on their contexts at `go-task/executor.go:81` and `go-task/task.go:438-469`. These examples create pressure around whether sprint mutation exclusion belongs with the product state owner and whether conflicts need typed outcomes.
- **Bounded publish/subscribe with independent consumers:** Opencode's broker has an explicit subscription cleanup path at `opencode/internal/pubsub/broker.go:67-82`, while its performance model accepts slow-consumer event drops (`opencode/internal/llm/provider/provider.go:56`). K9s bounds workers with a semaphore at `k9s/internal/pool.go:26-48`. For SSE reasoning, these examples expose bounded delivery, non-backpressure, rollover, and recovery as related concerns without resolving their treatment in this sprint.
- **Typed errors plus separate safe projection:** Restic carries lock-conflict data in `restic/internal/restic/lock.go:47`; Go Task carries correction data in `go-task/errors/errors_task.go:13-32`; K9s emits both operational logging and a user message at `k9s/internal/model/flash.go:100-103`. These examples raise a candidate separation between rich app errors and safe API, HTML, or progress projections; sprint reasoning still needs to determine that boundary.
- **Post-resolution validation and explicit fingerprints:** Configuration studies show validation after merge at `k9s/internal/config/k9s.go:423-451` and explicit override detection at `restic/internal/global/global.go:139,147`. The analogous pressure for confirmation is to normalize and validate complete effective operation inputs before binding approval, while sprint reasoning determines the exact fingerprint contents and stale-input policy.
- **Structured, correlated operation events:** K9s centralizes stable field names at `k9s/internal/slogs/keys.go:6-231`; opencode wraps structured logging at `opencode/internal/logging/logger.go:25-62`; restic adds observation through a backend decorator at `restic/internal/backend/logger/log.go:22-77`. SSE events and logs may benefit from a common safe correlation vocabulary without equating diagnostic logs with user progress.
- **Production/test constructors at volatile boundaries:** Gh-cli's `IOStreams.Test()` returns in-memory streams at `gh-cli/pkg/iostreams/iostreams.go:551-568`; restic supplies `MockTerminal` at `restic/internal/ui/mock.go:10-53` and functional backend mocks at `restic/internal/backend/mock/backend.go:14-26`; existing HTTP examples use `httptest` at `chezmoi/internal/cmd/applycmd_test.go:220-241`. This is directly relevant to deterministic operation, route, SSE, cancellation, and redaction tests.
- **Stream or retain only bounded data:** Age processes fixed-size chunks at `age/internal/stream/stream.go:20,195-219`; yq processes one document at a time at `yq/pkg/yqlib/stream_evaluator.go:78-113`; rclone caps pooled memory with a semaphore at `rclone/lib/pool/pool.go:17-24,52-53`. An ephemeral event hub faces the same pressure to bound event count, payload size, subscribers, active operations, and retention.

## Trade-Offs

| Trade-Off | Benefit | Cost | When It Matters |
| --- | --- | --- | --- |
| Constructor injection vs context-carried services | Constructor injection makes operation dependencies visible and compile-time checked, as in `gh-cli/pkg/cmdutil/factory.go:16-43`. | Passing dependencies through deep call chains adds plumbing; context lookup is terser but implicit and runtime-checked, as shown by `k9s/internal/keys.go:10-38`. | When defining how web, app, hub, clock, and product operations are composed and tested. |
| Typed error types vs sentinels | Typed errors can carry conflict scope, stale details, or remediation data, as in `restic/internal/restic/lock.go:47`; sentinels permit simple `errors.Is` branching, as in `helm/pkg/storage/driver/driver.go:27-36`. | Typed taxonomies add maintenance; sentinels provide only boolean identity and can force details into strings. | When mapping conflict, stale confirmation, cancellation, timeout, validation, and internal failures to stable API envelopes. |
| `errgroup` vs `WaitGroup` plus semaphore | `errgroup.WithContext` gives sibling cancellation and error propagation (`go-task/task.go:87`); semaphore-based pools make capacity explicit (`k9s/internal/pool.go:21,30,37`). | `errgroup` has no implicit capacity bound and assumes related failure; `WaitGroup` leaves error and cancellation handling to surrounding code. | When deciding whether hub housekeeping, operation execution, and shutdown work are coupled or independent. |
| Drop/refresh vs blocking event delivery | Slow-consumer dropping keeps producer work responsive, as observed in opencode's event streaming (`opencode/internal/llm/provider/provider.go:56`). | Subscribers can miss transient events and need an explicit replay or durable-refresh path. | When defining full-buffer behavior, reconnect, `Last-Event-ID`, and terminal-result recovery. |
| In-memory ephemeral state vs durable persistence | In-memory state is fast and avoids a second product state model; bounded structures mirror opencode's streaming approach and K9s's bounded workers. | Restart loses transport history and requires authoritative state reconstruction; retained terminal results are available only temporarily. | When specifying operation retention, restart behavior, and what the browser displays after hub loss. |
| Golden output tests vs focused assertions | Golden fixtures reveal complete user-visible changes, as in `helm/internal/test/test.go:43`. | Golden updates can be noisy or stale; focused assertions are easier to maintain but can miss projection regressions. | When testing HTML pages, JSON envelopes, SSE encoding, and progress/result views. |
| Lazy initialization vs eager preflight | Lazy factories avoid paying for unused resources (`gh-cli/pkg/cmdutil/factory.go:27-42`). | First-use failures occur later and lazy error caching can complicate recovery. | When preparing runtime/model/harness summaries without starting expensive dependencies or work. |
| Centralized app state vs smaller capability interfaces | A composition root makes ownership and wiring traceable (`opencode/internal/app/app.go:25-40`). | A large app/config object can become a god object; the state-context report explicitly notes this risk. | When deciding the minimum operation interface exposed to `internal/web` without broadening its authority. |

## Anti-Patterns And Warnings

- **Connection presence treated as operation state:** The concurrency report warns against fire-and-forget goroutines with no cleanup (`dive/cmd/dive/cli/internal/command/adapter/resolver.go:70`). Inferring completion, failure, or product cancellation from an SSE disconnect risks coupling transport presence to work state.
- **Slow subscribers blocking producers:** Unbuffered delivery can deadlock if a reader stops (`rclone/client.go:981`), and `WaitGroup.Wait()` without a timeout can hang indefinitely (`gh-cli/pkg/cmd/extension/manager.go:205`). This evidence highlights bounded subscriber and shutdown behavior as a reasoning concern.
- **Replacement of caller context during long work:** `context.Background()` in cancellable operations severs lifecycle propagation (`dive/image/analysis.go:20`, `chezmoi/internal/cmd/templatefuncs.go:215`). The observed failure mode is cancellation that no longer reaches runtime, product cleanup, or external-process boundaries.
- **Dependencies hidden in globals or service-locator context values:** Global config and caches contaminate tests (`rclone/fs/cache/cache.go:16-21`), while unchecked context lookup can panic (`k9s/internal/dao/ds.go:72`). The evidence raises test isolation and dependency visibility concerns for hub, clock, operation capability, and security collaborators.
- **API classification from error strings:** The error report contrasts structured `errors.Is`/`errors.As` inspection with `%w` omissions that break inspection (`mitchellh-cli/cli.go:205-206`). It identifies string matching as a fragility risk for conflict, cancellation, timeout, and stale-confirmation mappings.
- **Diagnostics retained or projected without redaction:** The security report shows dedicated redaction at `restic/internal/options/secret_string.go:15-20`, `helm/pkg/registry/transport.go:37-41`, and `gh-cli/status.go:332-338`. Raw provider payloads, unrestricted stderr, authorization data, and absolute paths present disclosure risk in retained events.
- **Executable strings assembled from browser input:** Explicit argv prevents shell metacharacters from becoming code (`lazygit/cmd_obj_builder.go:38`), while unrestricted pass-through is identified as a risk at `dive/cmd/dive/cli/internal/command/build.go:25`. The contrast makes typed capability mapping and browser-authored shell commands alternatives whose fit and risk need sprint-specific reasoning.
- **Speculative pooling or plugin machinery:** The performance report limits buffer pooling to profiled hot paths (`restic/internal/archiver/buffer.go:24-46`), and the extensibility report shows adapters/factories can provide evolution without dynamic loading (`dive/cmd/dive/cli/internal/command/adapter/analyzer.go:13-15`). These findings caution against conflating bounded transport-state needs with a generic extension platform.
- **Tests asserting incidental implementation details:** K9s's exact hint-count assertion (`k9s/internal/view/pod_test.go:23`) is cited as brittle. The trade-off is between behavioral coverage of lifecycle, ordering, bounds, cancellation, security, and rendering versus coupling tests to private collection sizes.

## Design Pressures

- The thin-entrypoint and adapter evidence (`helm/pkg/cmd/install.go:347`, `dive/cmd/dive/cli/internal/command/adapter/analyzer.go:13-15`) creates tension between exposing enough typed capability for current operations and accidentally creating another workflow engine.
- Post-merge validation at `k9s/internal/config/k9s.go:423-451` makes confirmation binding to a normalized, validated effective request relevant evidence; preparation side effects and preflight depth remain unresolved.
- Context propagation and delayed cleanup evidence (`helm/pkg/cmd/install.go:333-347`, `restic/internal/restic/lock.go:290-305`) highlights distinct ownership questions for operation cancellation, subscription cancellation, server shutdown, and product cleanup.
- Restic's structured lock error (`restic/internal/restic/lock.go:47`) creates pressure around conflict enforcement beyond HTTP and around safe, actionable conflict projection.
- Opencode's pub/sub cleanup and slow-consumer behavior (`opencode/internal/pubsub/broker.go:67-82`, `opencode/internal/llm/provider/provider.go:56`) expose tension among truthful ordering, terminal status, bounded producer memory, and subscriber impact.
- Ephemeral retention creates a risk that event history or terminal results appear authoritative after loss, rollover, or restart; the relationship between retained observations and product state remains a reasoning question.
- Secret-safe value and credential-scrubbing evidence (`restic/internal/options/secret_string.go:15-20`, `helm/pkg/registry/transport.go:37-41`) creates pressure to examine every point at which browser-facing data is retained or rendered.
- Active-operation, event-buffer, subscriber, body, payload, stream, timeout, and retention bounds interact. The trade-off is process protection versus load shedding that could be mistaken for operation failure.
- Testability depends on explicit seams for operations, clocks, IDs, I/O, runtime/harness dependencies, and disconnect timing; in-memory constructors and functional fakes (`gh-cli/pkg/iostreams/iostreams.go:551-568`, `restic/internal/backend/mock/backend.go:14-26`) show viable patterns.
- K9s's brittle implementation-detail assertion at `k9s/internal/view/pod_test.go:23` creates pressure to reason about whether cross-surface agreement is better evidenced through shared behavior and safe projections, and how duplicated command execution would affect that evidence.

## Open Questions For Reasoning

- What is the smallest typed app operation capability that covers prepare, start, inspect, result, and cancel without exposing product-module or transport-specific concepts?
- Which normalized fields and governed artifacts participate in the confirmation fingerprint, and what exact changes make a token stale?
- Are confirmation tokens single-use, how are they scoped to a server/session, and which safe diagnostic distinguishes expiry, mismatch, replay, and stale input?
- Which operation classes acquire sprint-owned mutation locks, which may coexist, and what lock identity and recovery information is safe to return?
- Who owns cancellation at each layer, and how are repeated cancellation, already-terminal work, cleanup timeout, and server shutdown distinguished?
- What are the explicit limits for active operations, recent events, event bytes, subscribers, streams, heartbeats, request bodies, and terminal-result retention?
- What happens when a subscriber falls behind: disconnect, drop oldest, emit a gap marker, or require durable refresh? How does `Last-Event-ID` interact with buffer rollover?
- Which app/runtime events are safe and useful enough to become browser progress events, and which remain operational logs only?
- How are monotonic SSE IDs assigned when events arrive concurrently, and are IDs scoped per operation or server?
- What status/result information remains available from durable product state after hub eviction or server restart, and how is unavailable ephemeral history represented truthfully?
- Which typed error categories and safe fields form the compatibility-controlled API envelope for conflicts, stale confirmation, validation, timeout, cancellation, prerequisites, runtime failure, and internal failure?
- How can a slow or disconnected browser be simulated deterministically so tests prove that producer completion and durable state are unaffected?
- Which projections require golden coverage, and which are better protected by semantic assertions to avoid brittle tests?
- Which dependencies are candidates for eager preparation-time preflight, and which are candidates for lazy resolution to avoid side effects or startup cost?
- At which boundaries can redaction prevent unsafe data from entering logs, event buffers, terminal results, JSON, HTML, or reconnect replay?
