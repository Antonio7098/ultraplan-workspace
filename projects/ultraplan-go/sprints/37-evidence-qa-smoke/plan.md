## Decisions To Execute

| Decision | Source Section | Execution Implication |
| --- | --- | --- |
| Keep one product-owned QA workflow with a runtime admission gate | `reasoning.md#decision-1-keep-one-product-owned-qa-workflow-with-a-runtime-admission-gate` | Put QA admission, evidence policy, adjudication, assessment, and verification publication in `internal/sprint`. Recheck current Sprint 36 evidence before every writable run. Keep process mechanics in `internal/platform/process`, lifecycle authority in `internal/runcontrol`, and all adapters behind `internal/app`. |
| Use full-copy, product-mediated, fail-closed writable isolation | `reasoning.md#decision-2-use-full-copy-product-mediated-fail-closed-writable-isolation` | Create one private copy per shard attempt, validate links and entry types, materialize only approved new files, run the copied source read-only through a proven Linux containment backend, and return `blocked` before generated writes when any capability is uncertain. |
| Freeze bounded evidence plans and use verification-scoped identities | `reasoning.md#decision-3-freeze-bounded-evidence-plans-and-use-verification-scoped-identities` | Validate all conditions, paths, generated bytes, argv, cwd, environment, timeout, output bounds, cleanup obligations, and repeatability before writing. Bind records with scoped SHA-256 identities and explicit schema versions. |
| Make adjudication and assessment deterministic product decisions | `reasoning.md#decision-4-make-adjudication-and-assessment-deterministic-product-decisions` | Treat runtime and model results as untrusted evidence inputs. Product code alone validates evidence, groups root causes, promotes issues, classifies repair eligibility and regression candidates, and computes the canonical assessment. |
| Publish immutable attempts and recover the `state.json`/`qa.md` generation as one unit | `reasoning.md#decision-5-publish-immutable-attempts-and-recover-the-statejsonqamd-generation-as-one-unit` | Extend the live Sprint 36 verification schema explicitly, publish immutable attempt directories in dependency order, fence root publication, journal the state/report pair, retain the prior valid generation, and update `flow-state.json` last with a bounded projection. |
| Implement smoke-as-QA by direct delegation to the existing smoke authority | `reasoning.md#decision-6-implement-smoke-as-qa-by-direct-delegation-to-the-existing-smoke-authority` | Refactor only enough to let `smoke` and `qa --suite smoke` call the same smoke execution path without nested mutation locks. Preserve manifest, selection, invocation, evidence, cancellation, cleanup, verdict, run identity, and `smoke.md` behavior exactly. |
| Expose one bounded app operation and keep durable run control authoritative | `reasoning.md#decision-7-expose-one-bounded-app-operation-and-keep-durable-run-control-authoritative` | Add one typed QA start request, bounded summary reads, immutable paged detail reads, stable errors, and existing durable acceptance, fencing, replay, cancellation, and terminal arbitration. Do not add QA-specific run or event authority. |
| Present QA through bounded server rendering and a feature-owned TUI view | `reasoning.md#decision-8-present-qa-through-bounded-server-rendering-and-a-feature-owned-tui-view` | Show current and canonical attempts separately through app DTOs. Keep server rendering complete without JavaScript, use JavaScript only for progressive observation and control, sanitize hostile text per medium, and keep all lists and fields bounded. |
| Enforce fixed execution budgets and prove behavior with layered tests and dogfood | `reasoning.md#decision-9-enforce-fixed-execution-budgets-and-prove-behavior-with-layered-tests-and-dogfood` | Resolve and validate one `QASettings` value, serialize writable attempts, enforce per-item and aggregate limits, use deterministic fakes for normal tests, and require race, review, build, and gated real-repository evidence before completion. |
