## Relevant Patterns

- **Thin adapters over one product operation.** Helm keeps command setup separate from actions at `helm/pkg/cmd/install.go:132-145`, while gh-cli centralizes command dependencies at `gh-cli/pkg/cmdutil/factory.go:16-43`. For this sprint, that pattern supports one typed QA operation observed through CLI, TUI, and HTTP. The adapters should parse, authorize, invoke, and render; they should not adjudicate evidence or derive assessment. Evidence: `studies/go-cli-study/reports/final/01-project-structure.md`, "Thin CLI Entry Point"; `studies/go-cli-study/reports/final/02-command-architecture.md`, "Thin-Delegate Pattern."

- **Product policy and generic mechanics stay on opposite sides of an interface.** Restic defines domain interfaces separately from implementations at `restic/internal/restic/repository.go:18-66` and `restic/internal/repository/repository.go:1`; dive wraps operational concerns with adapters at `dive/cmd/dive/cli/internal/command/adapter/resolver.go:17-21`. Applied here, copy, process, timeout, output-cap, and cleanup mechanics can remain generic while QA code decides whether identities, containment, cleanup, and evidence are sufficient. Evidence: `studies/go-cli-study/reports/final/01-project-structure.md`, "Domain Interface/Implementation Split"; `studies/go-cli-study/reports/final/03-dependency-injection.md`, "Decorator Pattern for Cross-Cutting Concerns."

- **Manual composition at volatile boundaries.** The studied projects do not use reflection-based DI frameworks. Gh-cli injects lazy functions through its factory at `gh-cli/pkg/cmd/factory/default.go:26-46`; restic wraps backends explicitly at `restic/internal/global/global.go:592-627`. QA isolation, process execution, clocks, stores, and runtime calls are similarly volatile and benefit from explicit construction and fault-capable replacements. Evidence: `studies/go-cli-study/reports/final/03-dependency-injection.md`, "Centralized Composition Root" and "No DI Frameworks."

- **Validate a complete request before side effects.** Dive validates option structs after loading at `dive/cmd/dive/cli/internal/options/analysis.go:48-53`; k9s validates structured configuration at `k9s/internal/config/json/validator.go:1-187`. A QA attempt has many interdependent inputs, so reasoning should examine a preflight that validates the merged limits, target identity, workspace policy, approved paths, argv, environment, timeout, output cap, and cleanup capability before writable work starts. Evidence: `studies/go-cli-study/reports/final/04-configuration-management.md`, "PostLoad Validation Hook" and "Centralized Validation."

- **Cancellation is a tree, while cleanup may need its own bounded context.** `errgroup.WithContext` coordinates sibling failure in `go-task/task.go:89`; signal cancellation reaches Helm work at `helm/pkg/cmd/install.go:333-347`; restic uses a delayed cleanup context at `restic/internal/restic/lock.go:290-305`. This distinction maps closely to stopping new QA scheduling, cancelling active children, preserving completed evidence, and allowing bounded cleanup after the work context is cancelled. Evidence: `studies/go-cli-study/reports/final/07-state-context.md`, "Signal-Context Wiring," "errgroup for Structured Concurrency," and "Separate cleanup context from work context."

- **Bounded fan-out with explicit ownership.** Gdu and k9s use semaphore-backed limits at `gdu/pkg/analyze/parallel.go:13,36` and `k9s/internal/pool.go:21,30,37`; opencode adds an explicit shutdown timeout at `opencode/cmd/root.go:261-279`. The evidence favors localized launch sites and finite waits. It does not answer whether Sprint 37 should remain sequential or allow limited parallel writable attempts; that remains a reasoning question tied to proof of workspace and descendant independence. Evidence: `studies/go-cli-study/reports/final/08-concurrency.md`, "WaitGroup + Semaphore" and "Deferred Cancel + Explicit Wait with Timeout."

- **Structured failure facts survive presentation changes.** Go-task carries exit behavior in `TaskError` at `go-task/errors/errors.go:47-50`; restic distinguishes fatal errors at `restic/internal/errors/fatal.go:10-53`; gh-cli maps categories to stable exit codes at `gh-cli/internal/ghcmd/cmd.go:44-49`. QA needs equivalent machine-level distinctions among invalid evidence, blocked preflight, cancellation, timeout, cleanup uncertainty, stale state, and failed checks. Human hints can then vary by interface without changing the underlying result. Evidence: `studies/go-cli-study/reports/final/05-error-handling.md`, "Typed Errors with Structured Data," "User vs Operational Error Separation," and "Exit Code Mapping from Error Types."

- **Injectable IO and process fakes support adversarial tests.** Restic's filesystem and backend interfaces at `restic/internal/fs/interface.go:10-31` and `restic/internal/backend/backend.go:19-90` support in-memory and failure-injected tests; lazygit records command invocations through `lazygit/pkg/commands/oscommands/fake_cmd_obj_runner.go:17-26`. These patterns fit isolation tests that must force partial copy, command, cancellation, descendant, removal, and publication failures without depending on host timing. Evidence: `studies/go-cli-study/reports/final/06-io-abstraction.md`, "System Interface for Filesystem" and "Backend Interface for Network/Storage"; `studies/go-cli-study/reports/final/11-testing-strategy.md`, "Fake/Stub Command Runner."

- **Golden compatibility tests complement state-machine tests.** Chezmoi runs command scenarios through txtar at `chezmoi/internal/cmd/main_test.go:64-174`; Helm compares stable output with `AssertGoldenString` at `helm/internal/test/test.go:43`; rclone drives scenario-based golden comparisons at `rclone/cmd/bisync/bisync_test.go:1435-1479`. Sprint 37 has both semantic state and user-visible compatibility, so fixtures can compare assessment inputs and transitions separately from stable JSON, `qa.md`, `smoke.md`, and adapter output. Evidence: `studies/go-cli-study/reports/final/11-testing-strategy.md`, "testscript Integration Layer" and "Golden File Regression Prevention."

- **Delegate compatibility modes to the existing authority.** Helm's versioned plugin metadata and runtime adapters at `helm/internal/plugin/metadata_v1.go:24-48` and `helm/internal/plugin/runtime_subprocess.go:65-79` show how an adapter can preserve an existing protocol rather than reinterpret it. The relevant lesson is narrower than adding a plugin system: a smoke QA suite should call the established smoke discovery, selection, invocation, and validation path, then project its result into QA. Evidence: `studies/go-cli-study/reports/final/12-extensibility.md`, "Versioned Schema/Metadata" and "Subprocess Plugin Isolation."

- **Trust boundaries need mechanical enforcement.** Explicit argument arrays prevent shell interpretation, private temporary directories reduce exposure, and permission checks create a visible decision point. Examples include lazygit's command builder at `lazygit/cmd_obj_builder.go:38`, chezmoi's private temporary directory at `chezmoi/gpgencryption.go:151-165`, and opencode's permission request flow at `opencode/internal/permission/permission.go:44-108`. For QA, prose claims about containment are not enough; path, symlink, environment, process, and cleanup facts need checks and records. Evidence: `studies/go-cli-study/reports/final/13-security.md`, "Shell-Safe Argument Construction," "Private Temp Directory," and "Permission Request Flow."

- **Bound memory and output at every untrusted edge.** Age processes fixed-size chunks at `age/internal/stream/stream.go:20,195-219`; restic excludes oversized buffers from its pool at `restic/internal/archiver/buffer.go:24-46`; gdu limits parallel traversal at `gdu/pkg/analyze/parallel.go:13`. Generated patches, stdout, stderr, evidence lists, issue lists, retries, and rendered views all have the same pressure: a valid bound must exist before execution and truncation must remain visible in evidence. Evidence: `studies/go-cli-study/reports/final/14-performance.md`, "Chunked Streaming with Bounded Memory" and "Concurrency Bounding via Semaphore Channel."

- **Progress is observation, not authority.** Restic serializes terminal status updates through a goroutine at `restic/internal/ui/termstatus/status.go:197-205`; lazygit makes streaming interruptible at `lazygit/pkg/tasks/tasks.go:31-435`; structured logging separates diagnostics from user output in Helm at `helm/internal/logging/logging.go:31-71`. The sprint's interfaces can show bounded progress and reconnect, but durable run and QA state must determine the result. Evidence: `studies/go-cli-study/reports/final/09-terminal-ux.md`, "Progressive Streaming with Interruptibility"; `studies/go-cli-study/reports/final/10-logging-observability.md`, "Output Separation Strategies."

## Trade-Offs

| Trade-Off | Benefit | Cost | When It Matters |
| --- | --- | --- | --- |
| Sequential writable attempts vs bounded parallelism | Sequential execution simplifies target-drift checks, workspace ownership, cleanup proof, and publication order. Bounded parallelism can reduce run time. | Sequential work may be slow across many shards. Parallel work adds race, process-tree, storage, and stale-writer failure modes. | Reasoning must decide whether current isolation mechanics prove independence strongly enough to permit more than one writable attempt. The evidence contrasts structured `errgroup` fan-out at `restic/internal/repository/repository.go:567` with semaphore control at `k9s/internal/pool.go:21-37`. |
| Full filesystem copy vs an optimized workspace mechanism | A local copy can represent dirty, uncommitted, and non-Git targets without relying on repository history. | Copying large trees costs time and disk and must handle links, metadata, exclusions, partial failure, and cleanup. | The sprint must support non-Git and dirty targets. Performance evidence favors streaming and bounds, but does not select a copy mechanism. See `age/internal/stream/stream.go:195-219` and `gdu/pkg/analyze/parallel.go:13`. |
| Constructor injection vs context-carried services | Constructor injection makes dependencies visible and compile-time checked. Context values reduce plumbing through deep UI or operation stacks. | Constructor signatures can grow. Context service lookup hides requirements and can panic or fall back silently. | Process, store, clock, runtime, and adjudication dependencies cross several layers. K9s shows the convenience and risk at `k9s/internal/keys.go:10-38`; gh-cli shows explicit factories at `gh-cli/pkg/cmdutil/factory.go:16-43`. |
| Rich typed state vs smaller summaries | Detailed typed records make adjudication, recovery, and compatibility checks deterministic. Small projections are cheap to render and migrate. | Rich schemas increase validation, migration, digest, publication, and fixture burden. Small summaries cannot preserve evidence lineage. | Detailed verification attempts and bounded interface projections have different jobs. Error and state evidence supports keeping machine decisions structured, as in `go-task/errors/errors_task.go:13-32` and `restic/internal/restic/lock.go:47`. |
| Golden files vs field-level assertions | Golden files catch accidental Markdown, help, and JSON changes and make parity diffs visible. | They can be brittle, large, or regenerated without enough review. | Canonical `qa.md`, `smoke.md`, CLI JSON, HTML, and TUI fixtures need compatibility coverage, while internal transition tests should avoid snapshotting incidental detail. See `helm/internal/test/test.go:43` and the warning at `k9s/internal/view/pod_test.go:23`. |
| Preserve complete outputs vs cap retained evidence | Larger evidence helps diagnosis and later adjudication. Caps prevent memory, disk, JSON, and UI exhaustion. | Truncation may remove the decisive line and can make evidence inconclusive. | Every command and record needs finite limits. Reasoning must define whether truncation invalidates, weakens, or merely annotates a result. Restic's bounded pool at `restic/internal/archiver/buffer.go:24-46` and lazygit's streaming at `lazygit/pkg/tasks/tasks.go:189-217` show different responses to volume. |
| Centralized validation vs validation near each record type | A central pass can enforce cross-record identity, freshness, and limit invariants. Local validation keeps each type understandable. | Central validators can become monoliths. Distributed checks can miss cross-record contradictions. | Evidence plans, command results, workspace facts, adjudication, issues, and summary pointers have both local and relational rules. K9s centralizes schema checks at `k9s/internal/config/json/validator.go:1-187`; dive uses local post-load checks at `dive/cmd/dive/cli/internal/options/analysis.go:48-53`. |
| Reuse the smoke execution path vs normalize smoke into a new QA-native model | Delegation preserves protocol and compatibility. A uniform QA-native model could simplify consumers. | Delegation requires a careful adapter and may expose asymmetries. Reimplementation risks drift in discovery, containment, evidence, and verdict rules. | `qa --suite smoke` must remain equivalent to `smoke`. Helm's versioned adapter model at `helm/internal/plugin/metadata.go:114-130` offers useful evidence, but the sprint should not infer a general plugin architecture from it. |
| Human hints vs stable machine classifications | Hints tell operators how to recover. Stable categories let CLI, TUI, web, and automation agree. | Maintaining both paths adds mapping work; prose can drift from machine state. | Blocked isolation, stale evidence, cancellation, cleanup uncertainty, and invalid state each need precise machine outcomes plus concise recovery guidance. See `age/cmd/age/tui.go:47-54` and `gh-cli/internal/ghcmd/cmd.go:281-301`. |

## Anti-Patterns And Warnings

- **Do not put product adjudication in generic process code.** The project-structure evidence favors one-way dependencies and domain ownership. A process package that knows evidence sufficiency, issue promotion, or QA assessment would reverse that boundary. Compare `restic/internal/restic/repository.go:18` with its implementation package in `studies/go-cli-study/reports/final/01-project-structure.md`.

- **Do not treat command failure or model prose as an issue.** Typed error systems distinguish execution facts from product decisions. A non-zero exit is evidence input, not proof of root cause, severity, or repair eligibility. See `rclone/fs/fserrors/error.go:22-192` and `go-task/errors/errors.go:47-50` in `studies/go-cli-study/reports/final/05-error-handling.md`.

- **Do not hide uncertain cleanup behind success.** Fire-and-forget goroutines and unbounded waits are recurring failure modes. Dive's unwaited notification at `dive/cmd/dive/cli/internal/command/adapter/resolver.go:70` and gh-cli's wait without timeout at `gh-cli/pkg/cmd/extension/manager.go:205` are cautionary examples from `studies/go-cli-study/reports/final/08-concurrency.md`.

- **Do not create fresh background contexts inside cancellable work.** Chezmoi's template calls at `chezmoi/internal/cmd/templatefuncs.go:215`, go-task's deferred work at `go-task/task.go:341`, and opencode background operations show how cancellation can stop at an accidental boundary. Evidence: `studies/go-cli-study/reports/final/07-state-context.md`, "Anti-Patterns / Caution Signs."

- **Do not rely on global mutable registries or config for attempt isolation.** Rclone's global config fallback at `rclone/fs/config.go:793` and cache singleton at `rclone/fs/cache/cache.go:16-21` can mask missing dependencies and pollute tests. Evidence: `studies/go-cli-study/reports/final/03-dependency-injection.md`, "Context Shadowing" and "Singleton Cache Pollution."

- **Do not pass writable commands through a shell string.** The security report treats explicit argument arrays as the baseline. Shell concatenation or commands parsed from prose make containment and audit impossible. Evidence: `studies/go-cli-study/reports/final/13-security.md`, "Shell-Safe Argument Construction," including `lazygit/cmd_obj_builder.go:38`.

- **Do not accept path checks that ignore canonical paths and links.** The security report calls out raw-path matching in `gdu/internal/common/ignore.go:16-37`. An apparently contained lexical path can still escape through symlinks or replacement races. Evidence: `studies/go-cli-study/reports/final/13-security.md`, "No path canonicalization before comparison."

- **Do not let direct `os.*` or process calls bypass test seams.** Dive bypasses output injection at `dive/image/docker/cli.go:27`; rclone does so at `rclone/cmd/ls/ls.go:42`. Similar bypasses in QA would leave target writes, environment forwarding, cancellation, and cleanup untestable. Evidence: `studies/go-cli-study/reports/final/06-io-abstraction.md`, "Anti-Patterns / Caution Signs."

- **Do not let UI delivery become the run record.** TUI and progress systems can lose subscribers or suppress output on non-TTYs. Presentation should recover from product and durable operation state rather than infer completion from a closed stream. Evidence: `studies/go-cli-study/reports/final/09-terminal-ux.md`, "Interruptibility Depth" and `gh-cli/iostreams/iostreams.go:514-516`.

- **Do not silently drop diagnostics or mix them into data output.** Discard-by-default logging can lose evidence if setup is missed, while debug text on stdout breaks automation. Dive's discard logger at `dive/internal/log/log.go:9` and fzf's stats output at `fzf/src/core.go:325` show both failures. Evidence: `studies/go-cli-study/reports/final/10-logging-observability.md`.

- **Do not snapshot incidental implementation details.** K9s's fixed hint-count assertion at `k9s/internal/view/pod_test.go:23` breaks when harmless UI details change. QA tests should freeze contracts, identities, bounds, state transitions, and rendered schemas, not internal collection sizes without semantic meaning. Evidence: `studies/go-cli-study/reports/final/11-testing-strategy.md`, "Behavior vs. Implementation Testing."

- **Do not add a second smoke registry or plugin framework.** Registry systems can silently overwrite names, as `rclone/fs/rc/registry.go:41-48` does. Sprint 37 needs a constrained adapter to an existing authority, not runtime extension infrastructure. Evidence: `studies/go-cli-study/reports/final/12-extensibility.md`, "Registry Pattern with Global Map" and "No error on plugin name collision."

- **Do not optimize before establishing hard limits.** Pools and parallelism help only after profiling and ownership are clear. Global pools can contend, and unbounded in-memory accumulation can fail abruptly. Evidence: `studies/go-cli-study/reports/final/14-performance.md`, "Buffer Pooling" and "Anti-Patterns / Caution Signs."

## Design Pressures

- Writable evidence is useful only if the target remains unchanged. Workspace identity, target identity, before-and-after checks, path containment, process containment, and cleanup certainty therefore carry more weight than command exit status.
- Dirty and non-Git targets rule out designs that equate identity with a commit or assume a clean checkout. The isolation design must represent current filesystem content without mutating Git.
- Evidence has two lifetimes. The writable workspace is temporary, while generated patches, bounded command facts, and adjudication references must survive cleanup with verifiable identity links.
- Cancellation has several distinct effects: stop scheduling, signal active work, terminate descendants, perform bounded cleanup, retain completed evidence, and publish a truthful terminal state. One undifferentiated `cancelled` flag cannot express all of them.
- Cleanup uncertainty is a first-class outcome. Platforms that cannot prove descendant termination or workspace removal cannot support a passing assessment through optimism.
- Evidence validation is relational. A locally valid JSON object can still be stale, linked to the wrong target, generated from the wrong map or shard, or detached from its patch and command identity.
- Adjudication must distrust investigator output while retaining enough rejected material for audit. This creates pressure for strict input bounds, deterministic grouping, explicit rejection reasons, and no self-promotion path.
- Canonical assessment combines several authorities without merging them. Conformance Review keeps its own verdict, smoke keeps external raw evidence authority, run control owns execution facts, and QA owns adjudication and assessment.
- Failed reruns need two visible truths: the last complete canonical report and the current failed attempt. Publication and interface projections must not blur them.
- Smoke parity is broader than selecting the same test names. Invocation, cwd, environment, timeout, cancellation, cleanup, evidence validation, verdict, retained links, and compatibility summaries must stay aligned.
- Cross-interface parity competes with bounded rendering. CLI text, JSON, TUI, HTML, durable run views, and Markdown need the same identities and outcome, but none should render unbounded command output or issue sets.
- Browser security adds request-bound authorization without changing observation authority. Disconnect, session rotation, and replay gaps must not mutate QA state or imply cancellation.
- Finite limits interact. Per-command output, evidence count, patch size, attempt count, retry count, follow-up count, total duration, and total storage need a coherent budget rather than independent maxima that multiply into an unsafe total.
- Deterministic offline tests need stronger seams than production happy paths. Copy, identity, command, descendant cleanup, atomic publication, stale writers, and external smoke results all need controllable faults.
- The Sprint 36 entry gate is itself evidence, not a boolean assumed from chronology. Missing or stale map, review, smoke, cancellation, synthesis, and non-mutation proof must block writable QA.

- Which environment variables may reach investigator commands and smoke execution? How are inherited secrets represented as omitted or redacted without losing evidence that allowlisting occurred?

- Does output truncation make a command result invalid, inconclusive, or admissible with reduced evidence weight? Can a decisive result rely on bytes beyond the retained cap?

- Which test layer owns each guarantee: pure validation tables, fake filesystem/process tests, package race tests, command fixtures, adapter parity fixtures, or gated real-repository dogfood?
- What evidence proves the Sprint 36 admission gate on every writable run, and how is that proof invalidated when governed inputs or implementation identity change?
