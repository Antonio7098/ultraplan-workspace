## Relevant Patterns

- **Thin interface adapters over an owning product service:** Helm separates command construction from action behavior, and restic keeps the command-to-domain dependency direction inward (`studies/go-cli-study/reports/final/01-project-structure.md`; `helm/pkg/cmd/install.go:347`, `helm/pkg/action/install.go:73-140`, `restic/internal/restic/repository.go:18`). This pattern matters because the sprint must expose one stage through CLI and web without duplicating stage semantics in either surface.
- **Explicit composition and narrow volatile-boundary seams:** gh-cli and opencode construct dependencies at visible roots, while restic defines interfaces around repositories and backends (`studies/go-cli-study/reports/final/03-dependency-injection.md`; `gh-cli/internal/ghcmd/cmd.go:52-132`, `opencode/internal/app/app.go:42-81`, `restic/internal/restic/repository.go:18-66`). The applicable pressure is to make runtime, repository access, and persistence replaceable where tests or volatility require it without abstracting every stage helper.
- **Command-local options plus shared lifecycle wrappers:** gh-cli and restic separate parsed options from dependencies, while rclone centralizes retry, accounting, reporting, and cleanup around command execution (`studies/go-cli-study/reports/final/02-command-architecture.md`; `gh-cli/pkg/cmd/issue/list/list.go:25-118`, `restic/cmd/restic/cmd_backup.go:84-115`, `rclone/cmd/cmd.go:240-340`). This offers evidence for keeping prompt, validation, flow, status, progress, cancellation, and recovery projections consistent without concentrating them in a large handler.
- **Source-aware configuration resolution:** go-task applies a generic precedence accessor, restic distinguishes explicitly changed flags, and k9s validates the merged result (`studies/go-cli-study/reports/final/04-configuration-management.md`; `go-task/internal/flags/flags.go:314-327`, `restic/internal/global/global.go:139,147`, `k9s/internal/config/k9s.go:423-451`). This directly applies to stage model/variant overrides where omitted flags must not mask configured fallback values.
- **Wrapped errors with stable classification at boundaries:** gh-cli wraps context while preserving identity, Helm uses typed/sentinel conditions, and gh-cli maps categories to command outcomes (`studies/go-cli-study/reports/final/05-error-handling.md`; `gh-cli/pkg/ssh/ssh_keys.go:64`, `helm/pkg/storage/driver/driver.go:27-48`, `gh-cli/internal/ghcmd/cmd.go:44-49`). This addresses the need to distinguish validation, cancellation, conflict, runtime, and persistence failures while presenting safe actionable diagnostics.
- **Caller-owned context reaches actual work and cleanup is explicit:** Helm propagates a signal context into execution, go-task coordinates sibling work through `errgroup`, and restic deliberately gives selected cleanup a replacement context (`studies/go-cli-study/reports/final/07-state-context.md`; `helm/pkg/cmd/install.go:333-347`, `go-task/task.go:89,321,341`, `restic/internal/restic/lock.go:290-305`). The pattern highlights both cancellation propagation and the separate question of bounded artifact/state reconciliation after cancellation.
- **Independent source and output IO boundaries:** gh-cli provides a test IO constructor, while chezmoi and restic provide substitutable system/filesystem or backend seams (`studies/go-cli-study/reports/final/06-io-abstraction.md`; `gh-cli/pkg/iostreams/iostreams.go:551-568`, `chezmoi/internal/chezmoi/system.go:25`, `restic/internal/fs/interface.go:10-31`). This is relevant to proving repository reads and single-artifact writes independently rather than relying only on runtime exit behavior.
- **Localized and bounded asynchronous ownership:** restic groups asynchronous repository work, lazygit tracks background tasks, and opencode cancels then waits for a bounded interval (`studies/go-cli-study/reports/final/08-concurrency.md`; `restic/internal/repository/repository.go:567`, `lazygit/pkg/gui/background.go:35,46,123`, `opencode/root.go:261-279`). This pattern matters if operation execution, event forwarding, or shutdown introduces goroutines; it does not by itself justify parallel repository inspection.
- **Structured diagnostics separated from result output:** Helm dynamically controls structured logging, k9s standardizes field names, and go-task routes output through an interface (`studies/go-cli-study/reports/final/10-logging-observability.md`; `helm/internal/logging/logging.go:31-71`, `k9s/internal/slogs/keys.go:6-231`, `go-task/internal/output/output.go:12-14`). This supports safe stage/attempt/model/status metadata while keeping prompts, provider payloads, and unbounded stderr out of public projections.
- **Layer tests according to the behavior under proof:** chezmoi exercises command behavior, gh-cli has acceptance tests, Helm uses golden support, and restic constructs isolated integration environments (`studies/go-cli-study/reports/final/11-testing-strategy.md`; `chezmoi/internal/cmd/main_test.go:64-174`, `gh-cli/acceptance/acceptance_test.go:26-29`, `helm/internal/test/test.go:43`, `restic/cmd/restic/integration_helpers_test.go:188-235`). The sprint needs different evidence for structural validation, stage wiring, atomic filesystem behavior, compatibility, and CLI/app/web agreement.
- **Central trust-boundary validation and redaction:** k9s centralizes structural validation, restic protects secrets through dedicated formatting behavior, and Helm scrubs transport diagnostics (`studies/go-cli-study/reports/final/13-security.md`; `k9s/internal/config/json/validator.go:146`, `restic/internal/options/secret_string.go:15-20`, `helm/pkg/registry/transport.go:37-41`). This pattern applies to contained repository-relative references and bounded safe operational projections, but it cannot establish semantic completeness of generated context.
- **Prefer additive internal seams over premature plugin machinery:** go-task evolves construction through functional options, gh-cli injects command dependencies through a factory, while rclone registries expose collision and initialization concerns (`studies/go-cli-study/reports/final/12-extensibility.md`; `go-task/executor.go:20-24,91-122`, `gh-cli/pkg/cmdutil/factory.go:16-43`, `rclone/fs/rc/registry.go:41-48`). This matters because the sprint adds a fixed canonical stage, not an independently contributed plugin ecosystem.

## Trade-Offs

| Trade-Off | Benefit | Cost | When It Matters |
| --- | --- | --- | --- |
| Thin adapters and delegated stage behavior | Reuses the same operation across CLI and web and makes stage behavior directly testable. | Adds wiring and package indirection. | When multiple surfaces expose the same capability; compare `helm/pkg/cmd/install.go:132-145` with `helm/pkg/action/install.go:73-140` in `studies/go-cli-study/reports/final/02-command-architecture.md`. |
| Central composition object versus focused constructors | A central root makes dependency construction and replacement traceable. | It can become a god object coupling unrelated commands and mutable state. | When adding runtime/config/store dependencies; `chezmoi/internal/cmd/config.go:193-291,362` demonstrates both value and growth risk in `studies/go-cli-study/reports/final/03-dependency-injection.md`. |
| Eager versus lazy runtime dependency resolution | Lazy functions avoid constructing expensive resources for prompt, status, or dry-run paths. | Failures occur later and may be harder to attribute to preflight versus execution. | When non-runtime commands share a composition root; see `gh-cli/pkg/cmd/factory/default.go:26-46` in `studies/go-cli-study/reports/final/03-dependency-injection.md`. |
| Fixed precedence chain versus generalized priority resolver | A fixed chain is easy to audit; a generalized resolver consistently handles many sources and keys. | Generalization makes effective-source behavior less obvious and carries more metadata. | When stage model and variant values must preserve explicit override and fallback truth; compare `fzf/src/options.go:3865-3899` and `urfave-cli/value_source.go:94-102` in `studies/go-cli-study/reports/final/04-configuration-management.md`. |
| Rich typed error taxonomy versus simpler wrapped errors | Typed categories let CLI/web/status branch reliably and preserve recovery guidance. | Every category expands a compatibility surface and maintenance burden. | When cancellation, invalid output, conflict, runtime failure, and persistence failure require different outcomes; see `rclone/fs/fserrors/error.go:22-29,92-99` and `go-task/errors/errors.go:47-50` in `studies/go-cli-study/reports/final/05-error-handling.md`. |
| Work-context cancellation versus bounded cleanup context | Immediate propagation improves responsiveness; a bounded replacement context can finish lock or artifact reconciliation. | A replacement context can delay return and creates an uncertainty policy if cleanup times out. | During atomic rerun, cancellation, and shutdown; compare `go-task/task.go:341` with `restic/internal/restic/lock.go:290-305` in `studies/go-cli-study/reports/final/07-state-context.md`. |
| In-memory fakes versus real temporary repositories | Fakes are fast and deterministic; temporary repositories exercise permissions, containment, rename, and actual filesystem behavior. | Real filesystem tests are slower and more environment-sensitive. | When proving output isolation and atomic replacement; see `chezmoi/internal/chezmoitest/chezmoitest.go:86-92` and `gdu/internal/testdir/test_dir.go:9` in `studies/go-cli-study/reports/final/11-testing-strategy.md`. |
| Sequential orchestration versus concurrent fan-out | Sequential work is easier to audit and avoids race/leak complexity; concurrency can reduce latency for genuinely independent work. | Concurrency requires ownership, cancellation, synchronization, waiting, and bounds. | Only if repository inspection or event handling has demonstrated independent expensive units; compare `urfave-cli/command_run.go:92` and `restic/internal/repository/repository.go:567` in `studies/go-cli-study/reports/final/08-concurrency.md`. |
| Golden output tests versus structural assertions | Goldens protect stable embedded defaults and user-facing formats. | They create regeneration/review cost and become brittle for dynamic diagnostics. | For prompt/template parity and stable projections, not timestamps or provider details; see `helm/internal/test/test.go:43` and `go-task/task_test.go:166-169` in `studies/go-cli-study/reports/final/11-testing-strategy.md`. |
| Explicit canonical registration versus dynamic registry | Explicit wiring is discoverable and type-safe for a fixed set of stages. | Central lists grow and can drift if repeated in multiple projections. | When stage order is closed at compile time; compare `helm/pkg/cmd/root.go:267-303` with `rclone/fs/registry.go:407` in `studies/go-cli-study/reports/final/02-command-architecture.md` and `studies/go-cli-study/reports/final/12-extensibility.md`. |

## Anti-Patterns And Warnings

- **Do not grow a large command handler:** Opencode's root handler combines dependency construction, subscriptions, dispatch, and cleanup across `opencode/cmd/root.go:49-183` (`studies/go-cli-study/reports/final/02-command-architecture.md`). Concentrating the new stage there would obscure ownership and make shared-surface behavior harder to test.
- **Do not use package-global mutable runtime, config, or test hooks:** yq, dive, age, and restic show global parser/logger/bus or test overrides that can contaminate tests and race (`studies/go-cli-study/reports/final/03-dependency-injection.md`; `yq/pkg/yqlib/lib.go:13,21`, `dive/internal/bus/bus.go:5`; `studies/go-cli-study/reports/final/06-io-abstraction.md`; `age/plugin/client.go:424`, `restic/cmd/restic/cmd_backup.go:166`).
- **Do not let bound defaults masquerade as explicit overrides:** `gdu/cmd/gdu/main.go:46-112` illustrates how flag binding can blur whether the user supplied a value (`studies/go-cli-study/reports/final/04-configuration-management.md`). That can silently defeat stage-specific fallback and source reporting.
- **Do not accept a context and detach the workload:** `dive/image/analysis.go:20` replaces caller cancellation, and unchecked context-value lookup in `k9s/internal/keys.go:10-38` hides dependencies and can panic (`studies/go-cli-study/reports/final/07-state-context.md`). Context should not become either decoration or an untyped service locator.
- **Do not launch fire-and-forget or unbounded work:** `dive/cmd/dive/cli/internal/command/adapter/resolver.go:70` lacks clear ownership, while `gh-cli/pkg/cmd/extension/manager.go:196-206` fans out per item (`studies/go-cli-study/reports/final/08-concurrency.md`). Late output, leaks, and uncertain terminal state conflict with truthful recovery.
- **Do not mix global streams with otherwise injectable IO:** Direct writes in `chezmoi/internal/cmd/templatefuncs.go:296`, `rclone/cmd/ls/ls.go:42`, and `urfave-cli/cli.go:47` bypass configured routing (`studies/go-cli-study/reports/final/06-io-abstraction.md`). Diagnostics on stdout can also corrupt structured output, as shown by `fzf/src/core.go:325` (`studies/go-cli-study/reports/final/10-logging-observability.md`).
- **Do not treat runtime exit success as artifact success:** The report evidence favors explicit validation gates and failure classifications rather than process status alone; see custom validation in `k9s/internal/config/json/validator.go:146` (`studies/go-cli-study/reports/final/13-security.md`) and command-level behavior tests in `chezmoi/internal/cmd/main_test.go:64-174` (`studies/go-cli-study/reports/final/11-testing-strategy.md`). Structural validation must still avoid claiming semantic completeness.
- **Do not expose raw diagnostics or assume redaction happens elsewhere:** Restic's `internal/options/secret_string.go:15-20` and Helm's `pkg/registry/transport.go:37-41` exist because ordinary formatting and transport logs can disclose sensitive material (`studies/go-cli-study/reports/final/13-security.md`). Full prompts, environment, raw provider payloads, and unrestricted stderr should not flow into shared projections.
- **Do not build shell commands from inspected or user-controlled text:** Lazygit's explicit argument construction at `lazygit/cmd_obj_builder.go:38` contrasts with shell parsing risks documented at `restic/internal/backend/shell_split.go:45-76` (`studies/go-cli-study/reports/final/13-security.md`). A read-only policy also cannot be inferred merely from use of a non-shell interpreter.
- **Do not introduce registry or plugin machinery for one fixed stage:** Rclone's registry permits late registration and exposes collision/initialization concerns at `rclone/fs/rc/registry.go:41-48`, while Helm plugin metadata requires a broader versioned lifecycle at `helm/internal/plugin/plugin.go:27-50` and `helm/internal/plugin/metadata_v1.go:24-48` (`studies/go-cli-study/reports/final/12-extensibility.md`).
- **Do not overfit tests to incidental internals:** Exact UI-hint counts at `k9s/internal/view/pod_test.go:23` and loose output regexes at `gh-cli/pkg/cmd/issue/list/list_test.go:88-91` are fragile (`studies/go-cli-study/reports/final/11-testing-strategy.md`). Tests should prove stage contracts, isolation, and observable outcomes.

## Design Pressures

- Stage semantics need one inward-owned boundary while CLI and web remain projections; the thin command/action evidence at `helm/pkg/cmd/install.go:347` and `helm/pkg/action/install.go:73-140` supports the pressure but does not select the exact service shape (`studies/go-cli-study/reports/final/01-project-structure.md`).
- The stage adds runtime, target-resolution, validation, persistence, configuration, and operation concerns; explicit composition improves traceability, but `chezmoi/internal/cmd/config.go:193-291` shows the risk of one container absorbing unrelated state (`studies/go-cli-study/reports/final/03-dependency-injection.md`).
- Effective model/variant behavior must remain explainable across explicit flags and fallbacks; `restic/internal/global/global.go:139,147` and `go-task/internal/flags/flags.go:314-327` show that source metadata is part of truthful resolution (`studies/go-cli-study/reports/final/04-configuration-management.md`).
- Runtime failure, invalid/missing output, cancellation, conflict, and persistence failure need enough identity for recovery without proliferating an unbounded error taxonomy; compare `helm/pkg/storage/driver/driver.go:27-48` and `rclone/fs/fserrors/error.go:22-29,92-99` (`studies/go-cli-study/reports/final/05-error-handling.md`).
- Prompt preview and status should not force expensive runtime construction, but deferred construction moves preflight errors later; `gh-cli/pkg/cmd/factory/default.go:26-46` makes that tension visible (`studies/go-cli-study/reports/final/03-dependency-injection.md`).
- Repository reads and sprint-artifact writes must be independently testable, while real filesystem behavior is still required for atomic replacement and containment evidence; compare `restic/internal/fs/interface.go:10-31` with `gdu/internal/testdir/test_dir.go:9` (`studies/go-cli-study/reports/final/06-io-abstraction.md`; `studies/go-cli-study/reports/final/11-testing-strategy.md`).
- Cancellation responsiveness competes with the need to preserve or reconcile the last valid artifact and durable state; `go-task/task.go:341` and `restic/internal/restic/lock.go:290-305` demonstrate different cleanup-context choices (`studies/go-cli-study/reports/final/07-state-context.md`).
- Operation events must remain visible enough for recovery but bounded and safe enough for CLI/JSON/web projections; `k9s/internal/slogs/keys.go:6-231`, `fzf/src/core.go:325`, and `helm/pkg/registry/transport.go:37-41` expose the observability/disclosure tension (`studies/go-cli-study/reports/final/10-logging-observability.md`; `studies/go-cli-study/reports/final/13-security.md`).
- A canonical fixed stage must be projected consistently without either parallel lists drifting or a dynamic plugin registry exceeding scope; compare explicit root registration at `helm/pkg/cmd/root.go:267-303` with rclone registration at `rclone/fs/registry.go:407` (`studies/go-cli-study/reports/final/02-command-architecture.md`; `studies/go-cli-study/reports/final/12-extensibility.md`).
- Structural validation can reject malformed paths, ranges, sections, and excerpts, but the central validation evidence at `k9s/internal/config/json/validator.go:146` does not justify a semantic-completeness claim (`studies/go-cli-study/reports/final/13-security.md`).
- The evidence for concurrency is about ownership and bounds, not a mandate to parallelize. Sequential examples at `urfave-cli/command_run.go:92` and `yq/pkg/yqlib/stream_evaluator.go:52` keep open whether this single stage needs fan-out (`studies/go-cli-study/reports/final/08-concurrency.md`).

## Open Questions For Reasoning
