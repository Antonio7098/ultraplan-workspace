## Sprint Purpose

- **Goal:** Deliver one deterministic, sprint-owned shared prompt prefix that preserves exact validated requirements and code-context bytes, resolves reference-only context entries into bounded transient source evidence, and is reused by every downstream agent-backed sprint operation from sprint-index through smoke authoring.
- **Non-Goals:** Repository indexing, retrieval, RAG, embeddings, provider cache controls or cache-hit claims, parallel context manifests, source staleness/provenance/amendment systems, QA or repair, a generic prompt/stage/plugin framework, route-specific browser behavior, alternate artifact persistence, hosted or multi-user operation, remote workers, issue tracking, and Git mutation.
- **Depends On:** Sprint 33's accepted code-context stage, validator, state compatibility, cancellation, atomic rerun, and last-valid-artifact behavior; Sprint 32's shared application/interface boundary and truthful gated-evidence rule; the configured implementation repository; and an available gated runtime for real-repository dogfood.

## Sprint Technical Handbook Summary

- **Relevant Patterns:** Product-owned composition behind a one-way boundary; explicit stage delegation; manual construction rather than DI frameworks; complete I/O seams; root-context cancellation; wrapped/classified errors; functional-output and diagnostic separation; exact golden plus command-path tests; central trust-boundary validation; bounded targeted reads; and abstractions earned by concrete need.

## Decisions

The authoritative decisions are specified in full under **Final Decisions** below:

1. Establish one sprint-owned, operation-scoped common-prefix byte contract with exact governed artifact slices and one explicit stage boundary.
2. Resolve reference-only source evidence sequentially through a contained, fail-closed policy with a 256 KiB prefix ceiling and 64 KiB suffix reserve.
3. Integrate the shared prefix explicitly at every downstream agent boundary while leaving generic runtime and interface adapters product-neutral.
4. Preserve canonical workflow/state authority, execute code-context exactly once in cumulative flow, and make the manual skill delegate to the canonical CLI operation.
5. Release through layered exact-byte, integration, flow, skill, interface, documentation, review, release-gate, and truthful gated-dogfood evidence.

## Final Decisions

### Decision 1: One Sprint-Owned, Operation-Scoped Byte Contract

- **Decision:** Add one concrete package-local renderer in `internal/sprint/prompt_context.go`. It accepts the operation context, project/sprint identity, governed artifact paths, resolved implementation root, and product-owned source-evidence budget, and returns one Go `string` plus error. `internal/sprint/prompts.go` owns stable shared instructions, fixed framing, and one constant stage-specific boundary marker. The renderer emits, in order: stable shared instructions; stable project/sprint identity; an opening frame, exact `requirements.md` bytes, and closing frame; an opening frame, exact `code-context.md` bytes, and closing frame; transient source evidence in authored order; any genuinely common stable content; and the boundary marker as the final prefix bytes. It does not trim, normalize line endings, add a newline inside artifact slices, reserialize, or regenerate either artifact. Each top-level operation builds the prefix once and reuses that immutable string for all of its requests; a later operation rebuilds from current governed files and source bytes.
- **Rationale:** This creates a precise byte range that can be compared across stages while keeping product prompt semantics within their owning module. Operation-scoped reuse prevents source races inside review/smoke fan-out without inventing persistent cache or staleness state.
- **Study / Source Grounding:** `technical-handbook.md` patterns "Product-owned composition," "Explicit stage delegation," "Manual wiring," "Observable bytes," and "Functional output separated from diagnostics"; `01-project-structure` via Helm/yq one-way boundaries; `02-command-architecture` via gh-cli's explicit factory; `03-dependency-injection` via manual composition; `10-logging-observability` via k9s stable fields; `11-testing-strategy` via Helm/go-task goldens. The reports do not define Sprint 34's exact frame text or return type; `requirements.md` and `reasoning/architecture.md:25-49` decide those details.
- **Trade-Offs Accepted:** A concrete buffered string retains memory for the operation and explicit callers must all use it. Fixed framing becomes compatibility-sensitive. These costs buy immutable fan-out reuse, exact-byte tests, and no new interface/framework.
- **Technical Debt / Future Impact:** Prompt framing must be intentionally versioned if changed. The renderer must stay limited to stable common content so it does not become a stage-policy god object. No cache, source fingerprint, or persisted prefix is introduced.
- **Alternatives Rejected:** Stage-local assembly is rejected because it permits whitespace/order drift. Generic runtime middleware or a sprint-aware runtime request field is rejected because it reverses the product/platform boundary. A DI container, registry, one-implementation interface, mutable shared `[]byte`, and persisted prefix cache are rejected as unearned complexity or divergent-state risks. Rebuilding for every reviewer is rejected because live source can change within fan-out.
- **Contracts Satisfied:** Architecture, Observability, Testing, Documentation, LLM Runtime, Performance, Persistence And Migrations; `AC-02`-`AC-06`, `AC-12`, `AC-14`, `AC-16`; `C-01`, `C-02`, `C-04`, `C-11`.
- **Evidence Required:** Exact renderer goldens; direct raw-slice comparisons for LF, CRLF, and missing-final-newline artifacts; fixed order and boundary-count assertions; operation fan-out pointer/value reuse or exact-byte equality; tests proving stage/output/run/time/session data occurs only after the boundary; and Architecture Review confirmation that runtime/platform packages know no sprint semantics.

### Decision 2: Deterministic, Contained, Bounded Transient Source Resolution

- **Decision:** Parse only validated `Path`, exact `Lines`, optional `Symbol`, and `Rationale` fields from `code-context.md`; do not rewrite it or create another manifest. Resolve entries sequentially in document order. Preserve duplicates and overlaps as authored, counting each occurrence against the budget. For each path, reject empty, absolute, volume-qualified, and lexically escaping values; canonicalize root and candidate; reject any symlink component and non-regular file; open and verify the handle; read only the selected range with context checks; verify file identity and canonical containment before and after; reject malformed, descending, zero, or out-of-range lines, changed files, and invalid UTF-8. Preserve selected source bytes and line endings. Frame every excerpt with stable path/range/symbol/rationale metadata and label it untrusted transient evidence that neither resides in `code-context.md` nor restricts further live inspection.
- **Decision:** Enforce a product-owned maximum of 256 KiB for the complete rendered common prefix and reserve 64 KiB for the largest supported stage suffix before runtime request overhead. Exact requirements, exact code-context, stable framing, and transient evidence all count toward the 256 KiB prefix ceiling. Use checked arithmetic before allocation and during bounded range reads. If the fixed artifacts/framing leave no source budget, or any selected reference would exceed the remaining bytes, fail with the offending reference and allowed/observed size. Never truncate, omit, summarize, prioritize, or silently continue. The constants are implementation-owned safeguards, not provider cache or token guarantees.
- **Rationale:** Generated references and repository source are untrusted. A deterministic fail-closed path makes the prepared evidence truthful, preserves authored selection semantics, and prevents repository-wide reads or unbounded prompts. A conservative byte ceiling is reviewable and provider-neutral; dogfood can reveal whether a later explicit compatibility change is required.
- **Study / Source Grounding:** `technical-handbook.md` patterns "Complete I/O seam," "Bounded selected source handling," and "Trust boundaries"; `06-io-abstraction` via restic/chezmoi filesystem seams and rclone bypass warning; `07-state-context` via Helm/go-task cancellation; `13-security` via k9s validation, OpenCode permissions, and gdu canonicalization weakness; `14-performance` via age streaming, yq incremental processing, and gdu bounded workers; `15-philosophy` simplicity-first guidance. No selected repository establishes the exact 256/64 KiB limits or a portable symlink algorithm; those are sprint-specific safety decisions required by `C-03` and the Architecture reasoning.
- **Trade-Offs Accepted:** Sequential reads may be slower; strict symlink rejection may exclude valid selections; any bad reference blocks the stage; full prefix buffering consumes up to the fixed ceiling; and separate operations may observe changed live source. These are accepted in exchange for deterministic, complete, contained evidence.
- **Technical Debt / Future Impact:** The Markdown parser remains coupled to Sprint 33's validated shape. Hard-link ancestry and repository-wide transactional consistency remain residual risks. Byte limits approximate rather than guarantee provider token fit and may require a reviewed adjustment after representative evidence.
- **Alternatives Rejected:** Lexical prefix checks alone, following symlinks, recursive scans, unbounded `os.ReadFile`, concurrent reads before measurement, silent truncation/omission, heuristic prioritization, persisted excerpts, JSON manifests, source fingerprints, indexing, RAG, and embeddings are rejected for security, truthfulness, determinism, or scope reasons.
- **Contracts Satisfied:** Errors, Security, Testing, LLM Runtime, LLM Evaluation / Cost / Safety, Performance, Persistence And Migrations; `AC-01`-`AC-03`, `AC-06`, `AC-12`, `AC-16`; `C-02`-`C-04`, `C-06`, `C-08`, `C-09`, `C-11`.
- **Evidence Required:** Temporary-repository tests for valid ranges, authored order, duplicates/overlaps, LF/CRLF, invalid UTF-8, cancellation, missing/out-of-range references, every unsafe path class, symlink components, non-regular files, changed-during-read detection, exact budget fit, one-byte overflow, checked-size failure, and no repository recursion or mutation. Errors must preserve safe relative path/range context and cancellation identity.

### Decision 3: Explicit Integration At Every Agent Boundary

- **Decision:** The existing sprint composition path prepares the prefix lazily only when an operation will invoke an agent. Planning stages from sprint-index through plan call the shared composition operation in `service.go`; execute calls it in `execute.go`; every independent Conformance Review request calls it in `review.go`; and every agent-backed smoke-author request calls it in `smoke_author.go`. Each call appends all stage identity, output contract, selected evidence, review identity, smoke scope, output path, model/runtime details, run/session/attempt/timestamp data, and other request-specific material after the fixed boundary. ### Decision 5: Release Through Layered Evidence, Documentation, And Truthful Dogfood

- **Decision:** Verification is layered. Renderer tests prove exact bytes and security properties. Stage tests capture real request construction through fake runtimes. - **Decision:** Real-repository requirements-to-plan dogfood runs only in a disposable representative workspace through the gated runtime. - **Rationale:** Exact-byte behavior needs focused tests, but release confidence also requires production call-path, state, race, documentation, and real-runtime evidence. Truthful blocked outcomes preserve the product principle that runtime availability and runtime exit are not product success.
- **Study / Source Grounding:** `technical-handbook.md` patterns "Observable bytes tested at more than one level," "Functional output separated from diagnostics," and warnings against substring-only tests and overstated dogfood. `11-testing-strategy` supplies Helm/go-task goldens and chezmoi command-pipeline evidence; `10-logging-observability` supports structured diagnostic separation; `13-security` supports permission/trust gates; `15-philosophy` supports explicit non-goals. - **Alternatives Rejected:** Substring-only assertions, renderer-only tests, treating fake runtime as live evidence, inferring pass from exit code or artifact presence, mutating the production workspace during dogfood, skipping blocked prerequisites, and claiming provider cache hits are rejected as insufficient or misleading evidence.

## Implementation Constraints

- `internal/sprint` owns all shared-context semantics, source resolution, stage composition, and flow ordering; `internal/platform/runtime` and agentwrap remain generic.
- Use one concrete renderer in `internal/sprint/prompt_context.go` and stable shared framing/composition helpers in `internal/sprint/prompts.go`; do not add a subpackage, DI framework, registry, plugin, middleware chain, or package-global mutable state.
- Context carries cancellation/deadlines only, never services or renderer dependencies.
- The common prefix ends with one constant boundary marker. No stage identity, output contract/path, selected stage evidence, model/runtime, run/session/attempt/timestamp, reviewer identity, smoke scope, or diagnostics may precede it.
- Preserve the exact bytes of `requirements.md` and `code-context.md` inside external fixed frames. Do not trim, normalize, re-encode, reserialize, or add bytes inside either artifact slice.
- Build the prefix once per top-level operation and reuse it for all requests in that operation. Do not persist or cache it across operations.
- Parse only `Path`, `Lines`, optional `Symbol`, and `Rationale` from the validated reference-only context pack. Preserve document order, duplicates, and overlaps.
- Resolve only repository-relative selected references. Reject absolute/volume/escaping paths, symlink components, non-regular files, invalid UTF-8, invalid ranges, changed files, and containment uncertainty.
- Use sequential bounded reads with context checks. Do not recursively scan, execute source content, follow links, fetch network content, or inspect references not selected by the pack during renderer preparation.
- Cap the complete common prefix at 256 KiB and reserve 64 KiB for stage suffixes. Use checked arithmetic and fail before runtime launch on overflow; never truncate or omit selected evidence.
- Frame source as untrusted transient prepared evidence, state that it is not stored in `code-context.md`, and explicitly permit agents to inspect additional live repository files.
- Preserve lower-level causes with `%w`; preserve `context.Canceled` and `context.DeadlineExceeded`; expose safe sprint-owned categories for path, containment, file-kind, missing source, range, changed-read, encoding, and budget failures.
- Do not log source bytes, complete prompts, secrets, or default absolute paths. Keep dynamic diagnostics in existing structured logs/events/runtime metadata and outside canonical prefix bytes.
- Integrate through explicit product call sites in `service.go`, `execute.go`, `review.go`, and `smoke_author.go`; do not alter review fan-out, verdict ownership, smoke selection, or agent-free behavior.
- `flow.go` remains the only cumulative ordering authority and must invoke the canonical code-context operation once after requirements and before sprint-index.
- Preserve Sprint 33 validation, cancellation, atomic replacement, last-valid-artifact, recovery, and legacy compatibility behavior. Prefix construction itself performs no durable write or state advancement.
- The manual skill must remain manual-only and delegate exactly to the canonical CLI flow through code-context; it must not reproduce product logic.
- CLI, TUI, and web continue through typed app operations. No interface adapter composes prompts, inspects source, invokes the UltraPlan binary, or persists alternate state.
- Normal tests are offline and deterministic. Real-runtime dogfood is gated, disposable, mutation-contained, and truthfully `pass` or `blocked`.
- Do not introduce any excluded cache, retrieval, index, manifest, staleness, provenance, QA/repair, persistence, framework, hosted, issue, or Git-mutation capability.
