# Area reasoning template: Run explorer experience

## Purpose

Define the first Aren browser experience for understanding one live or completed execution. This area owns information hierarchy, interaction, language, state presentation, accessibility, responsive behaviour, and the visual distinction between canonical and diagnostic evidence.

## Required inputs

- Phase 1 PRD and observability mandate;
- accepted observation DTO and service decisions;
- actual Phase 1 event, outcome, failure, cancellation, and benchmark examples;
- frontend and accessibility contracts.

## Questions to resolve

1. What must an engineer understand in the first screen without opening raw evidence?
2. How do summary, ordered timeline, structured outcome, diagnostics, and performance evidence relate?
3. How are cancellation request and terminal cancellation kept visibly distinct?
4. How are canonical facts distinguished from sampled or diagnostic information without relying on colour?
5. What happens in empty, connecting, live, terminal, disconnected, malformed, and unsupported-version states?
6. How do keyboard, focus, screen-reader, reduced-motion, narrow-screen, and dense-evidence use remain coherent?
7. Which raw details remain available for investigation without overwhelming the default view?

## Required output

- job, audience, and primary comprehension goal;
- route and information hierarchy;
- live and terminal state model;
- timeline and evidence-disclosure behaviour;
- failure and cancellation language;
- accessibility and responsive rules;
- realistic minimum and maximum content cases;
- component ownership and reuse boundaries.
