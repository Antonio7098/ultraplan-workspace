## Trade-Offs

**Retaining partial reports preserves useful evidence but requires stricter citations.** E10’s three material sources still expose cooperative cancellation limits; E13’s two material sources still show cause-preserving classification; E18–E19 still demonstrate surface enforcement and behavioral-contract gaps. Rejecting them wholesale would lose useful evidence. Treating their nominal source lists as complete comparisons would be worse. Downstream documents should cite the particular populated-source finding and retain the availability caveat. [E10, E13, E18, E19]

**Final syntheses reduce reading cost but lose local qualifications.** The supplied excerpts contain source references, yet omit much of the per-source reasoning, test setup and negative evidence. They cannot establish that a named test asserts the claimed property, that a skipped test ran, or that a local mechanism closes all end-to-end paths. Targeted inspection is warranted when one such detail decides a design choice; rereading every repository is not. [P08; E20 P1; E22 Rating Summary and Evidence Index; E23 Rating Summary]

**Closer Go evidence still comes from different products.** Conc is smaller and closer to the in-process boundary, but does not provide Aren’s live history and multi-waiter contract. Temporal SDK has stronger explicit machines but durable proposal/confirmation semantics. Docker Agent has a useful handoff mechanism but an upstream lossy pipeline. No source is a complete implementation template for Phase 1. [E20 Approach Models; E21 Conc discussion; E23 Docker Agent model]

**Excluding low-applicability material avoids architecture leakage but leaves some questions to local proof.** Durable replay reports cannot settle cursor ergonomics; network API reports cannot settle Go capability types; broad agent error reports cannot settle exact context-cause matching. The PRD remains authoritative, and small executable cases are more informative than expanding the catalog indiscriminately. [P02 Excluded Evidence; P03; E05, E13, E18, E19, E21]

**Historical Aren evidence deserves priority without automatic trust.** Its mutable-outcome, missing-timing, parent-bypass and recursive-invariant failures match Phase 1 unusually well. Its original tests also included false positives, and its performance evidence has explicit comparability limits. The correct response is to reproduce the defect class in new verification, not to copy either prototype architecture or historical completion claims. [P07 §§4, 6–8, 15]

**A broad assessment has a finite purpose.** This map is necessarily wider than any one downstream decision because the manifest selects 23 reports. It should become a reusable filter, not a reason for every thematic area to restate all 23 assessments. A downstream area should consume the routed findings and close its actual questions. [P02, P05 Evidence-Grounded Planning, P08]
