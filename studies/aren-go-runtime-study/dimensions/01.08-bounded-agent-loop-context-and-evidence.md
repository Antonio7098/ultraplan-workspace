# 01.08 Bounded Agent Loop, Context, and Evidence

Roadmap priority 8. Targets Aren Phases 9 and 10 using production agent runtimes rather than generic orchestration analogies.

## Purpose

Compare bounded Go agent loops that keep model turns, tool calls, budgets, context compaction, evidence, and cancellation coherent without turning Aren into a prompt framework.

## Steps

- Trace the complete loop from user input to model response, tool calls, tool results, subsequent turns, and terminal answer.
- Inventory iteration, token, time, cost, tool-call, output, and context limits and where each is enforced.
- Inspect transcript invariants, especially assistant tool calls paired with tool results during compaction.
- Find provenance, source-reference, artifact, or evidence-preservation mechanisms.
- Check cancellation and failure at every boundary between provider, loop, tool, persistence, and UI.

## Questions

- What guarantees that a loop terminates even when the model keeps requesting tools?
- Can compaction orphan a tool call or remove the evidence supporting the final result?
- Which budgets are enforced before work begins and which are only reported afterward?
- Does cancellation reach an active model stream and active tool at the same time?
