# 01.09 Resource Accounting, Overload, and Bounded Work

Roadmap priority 9. Applies Aren's performance discipline continuously and prepares the concrete pressure needed for Phase 13 resource governance.

## Purpose

Study how Go systems measure and bound goroutines, queued work, memory, disk, model residency, subprocesses, streams, and per-run costs while keeping overload behaviour explicit and testable.

## Steps

- Identify every queue, pool, semaphore, cache, buffer, and retained-history boundary on the relevant path.
- Trace admission, reservation, actual usage, release, and correction after failure or cancellation.
- Inspect overload responses, fairness, queue deadlines, load shedding, and slow-consumer handling.
- Find metrics that correspond to actionable limits rather than aggregate vanity counters.
- Examine benchmarks and saturation tests for steady state, bursts, and long-lived sessions.

## Questions

- Which resources are bounded per run, per workspace, and process-wide?
- What happens before memory pressure becomes an out-of-memory crash?
- Are estimates reconciled with actual use and always released on failure?
- Can one run monopolise workers, model memory, event buffers, or disk?
