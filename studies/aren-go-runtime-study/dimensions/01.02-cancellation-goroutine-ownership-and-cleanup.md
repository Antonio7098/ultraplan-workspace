# 01.02 Cancellation, Goroutine Ownership, and Cleanup

Roadmap priority 2. Covers the Phase 1 cancellation contract and the Phase 2 pressure introduced by realistic cleanup and long-lived work.

## Purpose

Establish practical Go patterns for context propagation, goroutine ownership, bounded shutdown, cleanup ordering, and truthful completion when underlying work is cooperative, blocking, or externally supervised.

## Steps

- Build an ownership tree for contexts, goroutines, channels, processes, and closers.
- Trace cancellation from caller request to the deepest cancellable operation and back to terminal publication.
- Inspect shutdown ordering, timeout escalation, repeated cancellation, and cleanup failure handling.
- Find detached goroutines, background contexts, unbounded channel operations, and close or send races.
- Examine leak tests and shutdown tests under partial startup and concurrent failure.

## Questions

- Who is responsible for waiting for every goroutine started on behalf of a run?
- What does the API claim when cancellation is requested but work has not stopped?
- Can cleanup block forever or overwrite the primary failure?
- How is shutdown made idempotent under concurrent callers?
