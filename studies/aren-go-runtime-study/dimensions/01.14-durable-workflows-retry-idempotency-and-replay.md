# 01.14 Durable Workflows, Retry, Idempotency, and Replay

Roadmap priority 14. Covers Phase 16 after persistence and composition, and treats workflow machinery as earned complexity rather than a starting abstraction.

## Purpose

Study durable Go workflow contracts for deterministic decision replay, activity effects, retries, timeouts, child workflows, cancellation, checkpoints, and idempotency without confusing replayable control flow with exactly-once effects.

## Steps

- Separate deterministic workflow decisions from effectful activities, executors, or allocations.
- Trace history recording, replay, versioning, retry policy, timers, cancellation, and child ownership.
- Inspect idempotency requirements and deduplication at effect boundaries.
- Examine worker loss, redelivery, duplicate execution, poison work, and operator intervention.
- Identify the minimum subset that would answer an Aren need and the machinery that should remain deferred.

## Questions

- Which code must remain deterministic and which code may perform external effects?
- What can execute more than once after worker or daemon failure?
- How are workflow definition changes made compatible with existing histories?
- What concrete Aren use would justify adopting any of this machinery?
