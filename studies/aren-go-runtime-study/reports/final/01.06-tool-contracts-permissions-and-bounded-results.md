## Executive Summary

Two Go runtimes solve Aren Phases 7-8 with the same invariant — permission is decided before any governed effect starts — but implement it at different layers and bound large results with opposite strategies.

Crush (6/10) builds a generics-typed registry (`fantasy.AgentTool[TParams]` at `internal/agent/tools/bash.go:24-30`, `internal/agent/coordinator.go:679`) whose schemas derive from Go struct tags, wraps every tool with `hookedTool` (`internal/agent/hooked_tool.go:31`) so `PreToolUse` hooks fire before `permission.Service.Request` (`internal/permission/permission.go:181`), and bounds results per-tool with byte/line caps plus visible truncation markers (`internal/agent/tools/bash.go:54,427-442`, `internal/agent/tools/view.go:76-89`, `internal/agent/tools/fetch.go:22`). Denied calls never reach `bgManager.Start`, `os.WriteFile`, or `http.NewRequest` (`internal/agent/tools/bash.go:227-255`, `internal/agent/tools/write.go:108-138`, `internal/agent/tools/fetch.go:80-97`), and malformed JSON is sanitized to `{}` at `internal/agent/agent.go:2276-2287` before any handler sees it.

Docker-agent (8/10) centralizes the invariant in `runtime/toolexec.Dispatcher` (`pkg/runtime/toolexec/dispatcher.go:195-276,353-415`), the single choke point that evaluates `Checker.CheckWithArgs` (`pkg/permissions/permissions.go:99-117`) through a tiered `Decide` + mode table (`pkg/runtime/toolexec/permissions.go:84-150`), consults two-lane `pre_tool_use` hooks (`pkg/runtime/toolexec/dispatcher.go:419-510`), and only then invokes `Handler` (`pkg/tools/tools.go:25-52`). Duplicate names are deduped first-wins (`pkg/agent/agent.go:442-465`), unknown tools return `IsError` without handler invocation (`pkg/runtime/toolexec/dispatcher.go:384-392`), and oversized outputs are never silently truncated — the always-injected `limit_large_tool_results` `tool_response_transform` hook (`pkg/hooks/builtins/limit_large_tool_results.go:25-105`, `pkg/hooks/builtins/builtins.go:161-165`) spills to `os.TempDir()/docker-agent-tool-results/<session>/` and returns a bounded excerpt with file reference.

The transferable core for Aren is structural, not stylistic: a typed registry as the contract boundary, a single permission choke point ordered hook→permission→execution, typed `IsError`/multimodal result preservation without string flattening, and externalization with explicit markers rather than silent discard. Crush proves the per-tool-cap pattern works but leaves `download` uncapped (`internal/agent/tools/download.go:152`) and redacts only logs (`internal/agent/tools/crush_logs.go:60-70`); docker-agent proves the universal transform + spill pattern scales to MCP/a2a categories but still holds the full payload in memory before spill and has no global quota.

## Core Thesis

**Tool safety is not a check — it is an ordering guarantee made structural by where you place the choke point, how strictly you parse at the boundary, and whether large results are externalized rather than truncated.**

Both sources enforce `hook → permission → side effect` in code shape, not just convention. Crush does it via decorator (`hookedTool.Run` at `internal/agent/hooked_tool.go:54-84` stamps `WithHookApproval` then `permission.Request` at `internal/permission/permission.go:192-202` gates before `os.WriteFile`/`bgManager.Start`). Docker-agent does it via dispatcher stages (`approveAndRun` at `pkg/runtime/toolexec/dispatcher.go:419-510` sequences `pre_tool_use_pre_yolo → Decide → pre_tool_use → askUser → runTool` at `pkg/runtime/toolexec/dispatcher.go:974-993`). Where they diverge — per-tool truncation versus universal spill, `sanitize-to-{}` versus strict-first-with-repairs (`pkg/tools/tools.go:34-52`, `internal/agent/agent.go:2276-2287`), pub/sub permission broker versus tiered checker+mode table — is not a quality ranking but a response to different product constraints: crush optimizes for local UX with `safeCommands` bypass (`internal/agent/tools/safe.go:9-75`) and paginated `view`; docker-agent optimizes for unattended/agent-to-agent safety with `preempt_yolo` that cannot be bypassed (`pkg/runtime/toolexec/dispatcher.go:442-471`) and `NonInteractive` fail-closed deny (`pkg/runtime/toolexec/dispatcher.go:796-807`).

The second half of the thesis is that typed contracts and typed results must travel together. `fantasy.AgentTool[TParams]` (`internal/agent/coordinator.go:679`) and `tools.NewHandler[T]` (`pkg/tools/tools.go:25-52`) both make schema code, not YAML, and both preserve `IsError`/`Images`/`StructuredContent` alongside `Output` (`internal/agent/agent.go:2091-2131`, `pkg/tools/tools.go:95-126`). Flattening to strings loses tool-specific semantics; preserving the envelope lets the LLM, the transcript, and the provider adapter each see what they need. Silent truncation breaks that envelope; explicit markers plus pagination or artifact references keep it.

## Approach Models

**Crush — Library-typed registry with decorator-ordered policy and per-tool bounding.** Discovery is `coordinator.buildTools` (`internal/agent/coordinator.go:679,714-759`) aggregating static built-ins, conditional LSP, and dynamic MCP (`internal/agent/tools/mcp-tools.go:24`), filtered by `agent.AllowedTools` (`internal/agent/coordinator.go:761-790`), sorted, then `wrapToolsWithHooks` (`internal/agent/coordinator.go:795-801`). Contracts are `fantasy.NewAgentTool[TParams]` generics where `TParams` struct tags (`json`, `description` at `internal/agent/tools/bash.go:24-30`, `internal/agent/tools/view.go:47-51`) drive JSON Schema; MCP schemas are passthrough `InputSchema map[string]any` (`internal/agent/tools/mcp-tools.go:70-97`) with `mcp_<server>_<tool>` prefix (`internal/agent/tools/mcp-tools.go:58-60`). Parsing is two-layer: `sanitizeToolInput` (`internal/agent/agent.go:2276-2287`) replaces invalid JSON with `{}`, then each handler validates required fields (`internal/agent/tools/bash.go:202-204`, `internal/agent/tools/write.go:57-59`) before any I/O. Policy ordering is decorator-enforced: `hookedTool.Run` (`internal/agent/hooked_tool.go:54-84`) → `permission.Service.Request` (`internal/permission/permission.go:181`) → `bgManager.Start`/`os.WriteFile`/`http.NewRequest` (`internal/agent/tools/bash.go:227-255`, `internal/agent/tools/write.go:108-138`, `internal/agent/tools/fetch.go:80-97`). Bounding is per-tool: `MaxOutputLength 30000` centered truncation (`internal/agent/tools/bash.go:427-442`), `MaxViewSize 200KB` + pagination (`internal/agent/tools/view.go:235-256`), `MaxFetchSize 100KB` via `LimitReader` (`internal/agent/tools/fetch.go:130-185`), `grep/glob/ls` count caps with `Truncated` metadata (`internal/agent/tools/grep.go:143-181`, `internal/agent/tools/glob.go:70-88`, `internal/agent/tools/ls.go:52-54`). MCP lifecycle is a state machine with generation fencing (`internal/agent/tools/mcp/init.go:140-165,815-870`) but no sandbox.

This model fits a local interactive agent that favors typed safety, low ceremony, and paginated reads, accepting that large-result handling is scattered and that `download`/`MCP` remain unbounded.

**Docker-agent — Registry-owned neutral interface with dispatcher-owned policy and universal spill.** Discovery is `ToolSet.Tools(ctx) ([]Tool,error)` (`pkg/tools/tools.go:12-15`) where `Tool` carries `Parameters any`, `OutputSchema`, `Category`, `Annotations`, `Metadata` (`pkg/tools/tools.go:147-170`); schemas from `jsonschema.For[T]` via `MustSchemaFor[T]` (`pkg/tools/schema.go:9-15`) normalized by `SchemaToMap` (`pkg/tools/schema.go:25-60`). Contracts are enforced by `NewHandler[T]`/`NewRuntimeHandler[T]` which `aijson.Unmarshal` the `ToolCall.Function.Arguments` string strict-first with narrow repairs and `tool_input_repaired` telemetry (`pkg/tools/tools.go:25-52`). Dedup is `collectTools` first-wins with `duplicate tool %q` warning (`pkg/agent/agent.go:442-465,528-552`); unknown tools are rejected in `call.run` before selection (`pkg/runtime/toolexec/dispatcher.go:384-392`). Policy is dispatcher-owned: `Dispatcher.Process` (`pkg/runtime/toolexec/dispatcher.go:195-276`) → `call.run` builds `runTool` closure without invoking → `approveAndRun` (`pkg/runtime/toolexec/dispatcher.go:419-510`) stages `pre_tool_use_pre_yolo` (un-bypassable), `Decide` (`pkg/runtime/toolexec/permissions.go:84-111`), `consultPreToolUseHook`, `askUser` (`pkg/runtime/toolexec/dispatcher.go:796-807`) serialized by `confirmationMu` → only `OutcomeAllow` calls `runHandler`/`runToolset` (`pkg/runtime/toolexec/dispatcher.go:974-993`) which does `exec`/`MCP.CallTool`. Bounding is a universal `tool_response_transform`: `limit_large_tool_results` (`pkg/hooks/builtins/limit_large_tool_results.go:25-105`) always prepended (`pkg/hooks/builtins/builtins.go:161-165`) caps categories `filesystem/shell/mcp/a2a` at 50 KiB or 2000 lines, spills to temp file, returns `head` for `read_file` with continuation or `tail` otherwise, rewrites before `EmitToolCallResponse`/`recordToolResponse`/`postHook` (`pkg/runtime/toolexec/dispatcher.go:1063-1109`), and cleans on `EventSessionEnd` (`pkg/hooks/builtins/limit_large_tool_results.go:67-70`). Secrets are three-leg `portcullis` (`pkg/hooks/builtins/redact_secrets.go:37-151`).

This model fits a daemon/multi-tenant system that needs explicit tiered policy, unbypassable safety lanes, and uniform large-result handling at the cost of dispatcher complexity and temp-file lifecycle.

## Pattern Catalog

### 1. Generics-typed tool registry as contract boundary (schema is code)

- **Problem:** Model-selected calls must be validated against a schema without per-tool bespoke parsers, and duplicate/unknown names must not cause provider 400s or panics.
- **Demonstrated by:** crush `fantasy.AgentTool[TParams]` (`internal/agent/tools/bash.go:24-30`, `internal/agent/coordinator.go:679`) where `BashParams`/`ViewParams` tags drive schema, plus `mcp_<server>_<tool>` prefix (`internal/agent/tools/mcp-tools.go:58-60`); docker-agent `ToolSet`+`Tool{Parameters, OutputSchema}` (`pkg/tools/tools.go:12-15,147-170`) with `MustSchemaFor[T]` via `jsonschema.For[T]` (`pkg/tools/schema.go:9-15`) and `collectTools` dedup (`pkg/agent/agent.go:442-465`).
- **Why it works:** Compile-time typing makes missing `file_path` a structured `NewTextErrorResponse` before I/O (`internal/agent/tools/write.go:57-59`, `internal/agent/tools/bash.go:202-204`); first-wins dedup makes `toolByName` lookup deterministic and prevents Anthropic 400 on duplicate names.
- **When to copy:** Any runtime with >5 tools or with MCP/plugin dynamic tools. Use generics or `jsonschema.For[T]` rather than external YAML.
- **Overkill/risky:** For 2-3 static tools, the indirection hides nothing; MCP passthrough schemas (`internal/agent/tools/mcp-tools.go:70-97`) are intentionally untyped and must tolerate provider-supplied `InputSchema` drift.
- **Evidence:** `internal/agent/coordinator.go:679,714-790`; `pkg/tools/tools.go:12-15,147-170`; `pkg/tools/schema.go:9-60`; `internal/agent/tools/mcp-tools.go:58-97`; `pkg/agent/agent.go:442-465`.

### 2. Single choke point with strict hook→permission→execution ordering

- **Problem:** Permission must be decided before a governed effect (process start, network egress, filesystem mutation) starts, and hooks that rewrite or deny must precede deterministic policy.
- **Demonstrated by:** crush `hookedTool.Run` (`internal/agent/hooked_tool.go:54-84`) executes `PreToolUse` synchronously, returns without `inner.Run` on `Deny`/`Halt`, stamps `WithHookApproval(ctx, call.ID)` on allow; docker-agent `approveAndRun` (`pkg/runtime/toolexec/dispatcher.go:419-510`) orders `pre_tool_use_pre_yolo → Decide → pre_tool_use → askUser → runTool` (`pkg/runtime/toolexec/dispatcher.go:974-993`).
- **Why it works:** Ordering is structural (decorator or dispatcher stages), not advisory; `permission.Request` short-circuits on `hookApproved` (`internal/permission/permission.go:192-202`) and `permissionDecision` is `Deny > Allow > Ask` (`pkg/permissions/permissions.go:99-117`) so deny always wins before `exec.Cmd.Start` or `MCP.CallTool` (`pkg/runtime/toolexec/dispatcher.go:396-415`).
- **When to copy:** Always for Aren — this is the Phase 8 governance rule (`phased-roadmap.md#phase-13`). Make the choke point the only path to `Handler`.
- **Risk:** `safeCommands` bypass (`internal/agent/tools/safe.go:9-75`) and yolo/`--no-permissions` collapse the gate to zero latency; audit must still emit `Granted` notification (`internal/permission/permission.go:192-202`).
- **Evidence:** `internal/agent/hooked_tool.go:54-84`; `internal/permission/permission.go:181,192-202,298-310`; `internal/agent/tools/bash.go:227-255`, `internal/agent/tools/write.go:108-138`, `internal/agent/tools/fetch.go:80-97`; `pkg/runtime/toolexec/dispatcher.go:419-510,974-993`.

### 3. Two-layer call parsing: provider JSON sanitization + handler required-field validation

- **Problem:** Malformed or ambiguous arguments must not reach a handler, panic the agent loop, or be silently defaulted.
- **Demonstrated by:** crush `sanitizeToolInput` (`internal/agent/agent.go:2276-2287`) checks `json.Valid`, replaces with `{}` and records `sanitizedToolCalls[callID]=true`, then `OnToolResult` (`internal/agent/agent.go:967-972`) surfaces an error result; every handler validates presence (`internal/agent/tools/bash.go:202-204`, `internal/agent/tools/write.go:57-59`, `internal/agent/tools/edit.go:69-71`, `internal/agent/tools/view.go:102-104`, `internal/agent/tools/grep.go:129-131`). Docker-agent `NewRuntimeHandler` (`pkg/tools/tools.go:25-52`) `aijson.Unmarshal` strict-first with narrow repairs and error propagation to `ResultError` without calling the typed function, plus `RunShellArgs.UnmarshalJSON` alias (`pkg/tools/builtin/shell/shell.go:99-123`) and MCP null-strip (`pkg/tools/mcp/mcp.go:730-759`).
- **Why it works:** Failure is typed (`IsError:true` via `NewTextErrorResponse` at `internal/agent/tools/tools.go:66-70`, `pkg/tools/tools.go:95-126` `ResultError`) and surfaced as a tool result the model can self-correct, not an exception.
- **When to copy:** Always — the model will emit `{"paths":"only.txt"}` (`pkg/tools/tools_test.go:99-122`) and `null` for optional params; handle it at the boundary, not in each tool.
- **Overkill/risky:** `sanitize-to-{}` can cause retried empty-object calls; `aijson` repairs mask drift — mitigate with `tool_input_repaired` telemetry (`pkg/tools/tools_test.go:154-179`) or a typed `ToolParamsError`.
- **Evidence:** `internal/agent/agent.go:2276-2287,967-972,2091-2131`; `pkg/tools/tools.go:25-52`; `pkg/tools/builtin/shell/shell.go:99-139`; `pkg/tools/mcp/mcp.go:730-759`.

### 4. Pre-effect permission with explicit safe bypass and unbypassable safety lane

- **Problem:** UX needs low-friction reads but must still block chaining/obfuscation and allow safety policy to override team allows and `--yolo`.
- **Demonstrated by:** crush `safeCommands` + `containsCommandChaining` (`internal/agent/tools/safe.go:9-75`, `internal/agent/tools/bash.go:209-222`) skips `permissions.Request` only for `ls`, `git status` etc. without `;|&&$(`` `; docker-agent `pre_tool_use_pre_yolo` lane (`pkg/runtime/toolexec/dispatcher.go:442-471`, `pkg/hooks/types.go:210-231`) that cannot be bypassed by `Decide` allow, plus `sessionPermissionsAllow` with `shellGrantCoversCommand` word-boundary check (`pkg/runtime/toolexec/dispatcher.go:555-580`, `pkg/runtime/toolexec/shell_grant.go:1-40`) so `mkdir*` does not grant `mkdir x && rm -rf ~`.
- **Why it works:** Safe reads stay fast, safety hooks stay fail-closed; the override check is explicit and tested (`TestDispatcher_DenyByPermissionsEmitsErrorResponse` at `pkg/runtime/toolexec/dispatcher_test.go:1074-1104` panics if denied handler runs).
- **When to copy:** If you offer a safe-read bypass or yolo mode, add a pre-yolo lane and a strict grant-coverage check on the override path. Otherwise keep `Deny>Allow>Ask` without bypass.
- **Risk:** Chaining checks that miss `||`, `>`, `<` (`internal/agent/tools/safe.go:9-75` gap) or permissive glob prefix match (`pkg/permissions/permissions.go:260-266` `HasPrefix` fast path) grant more than intended outside the hardened path.
- **Evidence:** `internal/agent/tools/safe.go:9-75`, `internal/agent/tools/bash.go:209-255`; `pkg/runtime/toolexec/dispatcher.go:442-471,555-580,796-807`; `pkg/runtime/toolexec/shell_grant.go:1-40`; `pkg/runtime/toolexec/dispatcher_test.go:694-1104`.

### 5. Bounded results with explicit markers: per-tool caps versus universal spill

- **Problem:** Large outputs must not silently discard evidence or blow up the context window.
- **Demonstrated by:** crush per-tool caps — `bash` 30k centered `... [N lines truncated] ...` (`internal/agent/tools/bash.go:427-442`) + auto-background after 60s, `view` 200KB + `MaxLineLength 2000` + `(File has more lines. Use 'offset'...)` pagination (`internal/agent/tools/view.go:76-89,235-256,337-341`), `fetch` 100KB via `LimitReader` + `[Content truncated to 102400 bytes]` (`internal/agent/tools/fetch.go:130-185`), `grep/glob/ls` 100/100/1000 caps with `Truncated` bool and `(Results are truncated...)` (`internal/agent/tools/grep.go:143-181`, `internal/agent/tools/glob.go:70-88`, `internal/agent/tools/ls.go:138-164`). Docker-agent universal transform — `limit_large_tool_results` (`pkg/hooks/builtins/limit_large_tool_results.go:25-105`) 50 KiB/2000 lines, head for `read_file` with `nextReadFileLine`/byte-range advice vs tail for others, spill to `docker-agent-tool-results/<session>/tool-result-*.txt` with counts, path, and continuation, injected before emit/record/post-hook (`pkg/runtime/toolexec/dispatcher.go:1063-1109`).
- **Why it works:** Every truncation is visible in content and in typed metadata (`BashResponseMetadata`, `GrepResponseMetadata{Truncated}` at `internal/agent/tools/bash.go:275-283`, `internal/agent/tools/grep.go:183-189`; docker-agent `MaxSearchFileSize/OutputBytes` at `pkg/tools/builtin/filesystem/limit.go:10-21`). The model knows to paginate or `read_file` the spill.
- **When to copy:** For Aren, copy the spill pattern for any external category (MCP/a2a/shell) where per-tool caps cannot be centrally enforced. Copy per-tool caps when you want pagination without file lifecycle.
- **Risk:** Uncapped `download` (`internal/agent/tools/download.go:152` `io.Copy` with only timeout) and uncapped MCP `TextContent` concatenation (`internal/agent/tools/mcp/tools.go:58` forwarded at `internal/agent/tools/mcp-tools.go:149`) inflate context; spill without quota can fill `/tmp` if `session_end` cleanup fails (`pkg/hooks/builtins/limit_large_tool_results.go:67-70`).
- **Evidence:** `internal/agent/tools/bash.go:54,427-442`; `internal/agent/tools/view.go:76-256,337-341`; `internal/agent/tools/fetch.go:22,130-185`; `internal/agent/tools/grep.go:143-215,349`; `internal/agent/tools/glob.go:70-189`; `internal/agent/tools/ls.go:52-164`; `pkg/hooks/builtins/limit_large_tool_results.go:25-192`; `pkg/hooks/builtins/builtins.go:161-165`.

### 6. Typed result envelope preserving tool-specific semantics

- **Problem:** Tool output is not just a string — errors, binaries, structured content, and per-tool metadata must survive without flattening.
- **Demonstrated by:** crush `fantasy.ToolResponse` → `message.ToolResult{Content, IsError, Data, MIMEType}` via `convertToToolResult` (`internal/agent/agent.go:2091-2131`) with `NewTextErrorResponse IsError=true` (`internal/agent/tools/tools.go:66-70`), `NewImageResponse`/`NewMediaResponse` with `getImageMimeType`/`http.DetectContentType` (`internal/agent/tools/view.go:204-228,387-400`), and `WithResponseMetadata` typed per tool (`internal/agent/tools/bash.go:275-283`, `internal/agent/tools/view.go:261-277`). Docker-agent `ToolCallResult{Output, IsError, Images/Audios/Documents, StructuredContent, Meta}` (`pkg/tools/tools.go:95-126`) → `BuildToolResultMultiContent` (`pkg/chat/tool_result.go:14-33`) → provider `convertToolResultBlock` emitting `Text` + `Document`/`Image Base64` blocks (`pkg/model/provider/anthropic/tool_result_attachments_test.go:37-122`), with `Tool.Category`/`Annotations`/`Metadata` precedence (`pkg/runtime/toolexec/dispatcher.go:901-924`).
- **Why it works:** The LLM sees text, while `Meta`/`Truncated`/`ResourceType` travel alongside for policy and UI; provider adapters (`internal/agent/agent.go:2132` `workaroundProviderMediaLimitations`, `pkg/tools/mcp/mcp.go:829-883` `processMCPContent`) map without loss.
- **When to copy:** Always — use `Output:IsError:Media:StructuredContent:Meta` rather than bare string, and validate base64 at the conversion boundary (`internal/agent/agent.go:2110`).
- **Evidence:** `internal/agent/agent.go:2091-2148`; `internal/agent/tools/tools.go:66-70`; `internal/agent/tools/view.go:204-400`; `pkg/tools/tools.go:95-126`; `pkg/chat/tool_result.go:14-65`; `pkg/tools/mcp/mcp.go:829-883`.

### 7. Multi-leg secret redaction + binary/media preservation

- **Problem:** Secrets in tool args, message history, or tool output must not be persisted or shown to the model, while images remain first-class.
- **Demonstrated by:** crush narrow log-only redaction `sensitiveKeys` → `[REDACTED]` (`internal/agent/tools/crush_logs.go:60-70,414-439`); docker-agent three-leg `redact_secrets` dispatching on `pre_tool_use → UpdatedInput`, `before_llm_call → UpdatedMessages`, `tool_response_transform → UpdatedToolResponse` via `portcullis.Redact` (`pkg/hooks/builtins/redact_secrets.go:37-151`).
- **Why it works:** Redacting at `tool_response_transform` (`pkg/runtime/toolexec/dispatcher.go:1063-1109` runs before emit/record/post-hook) scrubs once for all consumers; `portcullis` handles `bash`/`fetch``/`grep payloads, not just logs.
- **When to copy:** If you run against real credentials, copy the three-leg pattern. Log-only redaction is insufficient — `bash` output containing `API_KEY=sk-...` is returned verbatim in crush without pipeline scrubbing.
- **Evidence:** `internal/agent/tools/crush_logs.go:60-70,414-439`, `internal/agent/tools/crush_info_test.go:236-243`; `pkg/hooks/builtins/redact_secrets.go:37-151`; `pkg/tools/mcp/mcp.go:133-148,197-248`; `internal/agent/tools/view.go:387-400`.

## Tradeoffs

- **Side-effect isolation vs latency.** *Benefit:* Pre-effect gating (`permission.go:181` pub/sub with `select` on `ctx.Done`/`respCh` at `permission.go:270`; `askUser` blocking on `Resume` at `dispatcher.go:796-845`) makes `Denied` provably side-effect-free. *Cost:* Every non-safe mutation blocks on human prompt (`requestMu` serialized at `permission.go:204`; `confirmationMu` at `dispatcher.go:810-845`) — single confirmation at a time despite parallel batch. *Best-fit:* Interactive sessions. *Failure mode:* `ctx` cancellation returns `ctx.Err()` without `Denied` notification (`permission.go:272`; `dispatcher.go:377-382` early `ctx.Err()` check then `cancelBatch` `dispatcher.go:253-267`) losing audit. *Alternative:* docker-agent `NonInteractive` deny + `TierSession ForceAsk` always prompts versus crush `SkipRequests`/`AutoApproveSession` collapse to zero latency with no audit.

- **Per-tool caps vs universal spill.** *Benefit:* Per-tool caps (`bash.go:54` 30k, `view.go:76` 200KB, `fetch.go:22` 100KB) are grep-friendly and keep truncation intent local. *Cost:* New tools inherit no bound unless they add one (`download` missed; MCP `TextContent` missed). Universal spill (`limit_large_tool_results.go:25-105` categories `filesystem/shell/mcp/a2a`) catches unknown tools but still buffers full `payload` as `string` before `len` check and does `MkdirAll`+`CreateTemp`+`WriteString` with no quota. *Best-fit:* Combine — per-tool `LimitReader` at the source plus transform as safety net. *Failure mode:* Spill dir fills `/tmp` on looping `cat` without `session_end` GC.

- **Strictness vs repair.** *Benefit:* `aijson` repairs (`tools.go:42-47` stringified array, bare scalar, null stripping at `mcp.go:730-759`) prevent wasted turns on `{"paths":"only.txt"}`. *Cost:* Masks model schema drift; `sanitize-to-{}` prevents panic (`agent.go:2276-2287`) but causes repeated empty-object retries rather than a distinct `ToolParamsError`. *Best-fit:* Keep repairs behind telemetry (`tool_input_repaired` per `(tool, Kind)` at `tools_test.go:154-179`) and make them configurable per safety mode.

- **Prefix-match permissiveness vs strict grant coverage.** *Benefit:* `matchGlob` `HasPrefix` fast path (`permissions.go:260-266`) when pattern is `mkdir*` makes allow rules ergonomic. *Cost:* `shellGrantCoversCommand` strict word-boundary/no-metachar check (`shell_grant.go:1-40`) is only on the preempt-Ask override path (`dispatcher.go:566-580`); generic allows remain prefix-granting (`mkdir x && rm -rf ~` could match). *Best-fit:* Promote strictness to `CheckWithArgs` for `shell:cmd` or introduce `shell:cmd_strict=` qualifier.

- **Typed envelope vs LLM string.** *Benefit:* `Meta`/`Truncated`/`StructuredContent` (`tools.go:95-126`, `bash.go:275-283`) survive alongside `Output` so policy can branch without parsing text. *Cost:* At the LLM boundary all text is concatenated (`<file>`/`cwd` wrappers at `view.go:261-277`, `bash.go:275-283`) and structured metadata is out-of-band — the model sees markers, not fields. *Failure mode:* `workaroundProviderMediaLimitations` (`agent.go:2132`) rewrites media into synthetic `FilePart` user messages for text-only providers; without it, media is lost.

## Decision Guide

- **If you are building a single-binary interactive agent and want minimal infrastructure:** Copy crush. Use `fantasy.AgentTool[TParams]`-style generics or `jsonschema.For[T]` (`schema.go:9-60`), a `hookedTool` decorator (`hooked_tool.go:23-31`) ordered before `permission.Service.Request` (`permission.go:181`), and per-tool `LimitReader`/count caps with explicit pagination (`view.go:235-256`) or backgrounding (`bash.go:53` `DefaultAutoBackgroundAfter`). Add a `LimitReader` to `download` (mirror `fetch.go:130`) and a registry duplicate guard before shipping MCP.

- **If you are building a daemon, multi-tool batch, or team-policy system that must be fail-closed unattended:** Copy docker-agent. Implement `ToolSet`+`Tool` (`tools.go:12-170`), `collectTools` first-wins (`agent.go:442-465`), and a `Dispatcher` choke point (`dispatcher.go:195-415`) with `Decide` + mode table (`permissions.go:84-150`) and two-lane `pre_tool_use` (`dispatcher.go:442-510`) where `preempt_yolo` is un-bypassable. Inject `limit_large_tool_results` as `ToolResponseTransform` (`builtins.go:161-165`, `dispatcher.go:1063-1109`) for all `filesystem/shell/mcp/a2a` results and enforce `NonInteractive` deny (`dispatcher.go:796-807`).

- **Choosing bounding:** Use per-tool `io.LimitReader` + `Truncated` metadata as the first line, and a universal transform as the second line. For `read_file`, return `head` + `line`/`limit` or byte-range continuation when `!strings.Contains(head,"\n")` (`limit_large_tool_results.go:115-133`); for shell/logs, return `tail`. Never silently discard.

- **Choosing permission UX:** Interactive `safeCommands` bypass must require `containsCommandChaining` negative check (`safe.go:9-75`) and still be overridable by a safety hook `Deny` (`hooked_tool.go:54` `DecisionDeny` returns without `inner.Run`); for unattended, use `restricted` mode that denies instead of asking (`permissions.go:113-150`).

- **MCP readiness for Aren:** Both ship MCP via `Supervisor`/`ClientInfo` state machine (`mcp/init.go:140-165,659-771`, `mcp/mcp.go:166-215,535-568`) with generation fencing (`mcp/init.go:91` `gens`) and `ToolListChanged` invalidation (`mcp/mcp.go:535-568`). Copy the fencing and `renewMus` serialization, but add payload size caps and sandbox egress/FS policy — neither source proves isolation (`mcp-tools.go:106` permission prompts but does not constrain the child).

## Practical Tips

1. Put the only path to `Handler` behind one function. Either `hookedTool.Run` (`hooked_tool.go:54`) or `Dispatcher.approveAndRun → runTool` (`dispatcher.go:396-415,974-993`); forbid direct `Handler` calls elsewhere with a lint rule.

2. Derive schemas from Go types. `BashParams json:"command" description:"..."` (`bash.go:24-30`) or `MustSchemaFor[T]` (`schema.go:9-15`) plus `stripNullFromRequiredTypes` (`schema_test.go:197-229`); test required-field `IsError` before I/O (`bash.go:202-204`, `write.go:57-59`, `grep.go:129-131`).

3. Validate call identifiers as opaque but auditable. Both treat `call.ID` as passthrough (`permission.go:112`, `mcp-tools.go:112`, docker-agent `RecordToolResponse` via `cmp.Or` at `dispatcher.go:1136-1156`); add provider-specific prefix checks (`toolu_*`/`call_*`) only as diagnostics, not gates.

4. Enforce `Deny > Allow > Ask` (`permissions.go:99-117`) and test it with `panic("must not run")` handlers (`dispatcher_test.go:1074-1104`). Assert unknown tools emit `not available` `IsError` without handler invocation (`dispatcher_test.go:301-320`).

5. Add `io.LimitReader` at the source and a safety-net transform after. `fetch` 100KB (`fetch.go:130`), `bash` 30k centered with `N lines truncated` (`bash.go:427-442`), `grep/glob` 100 with `Truncated` (`grep.go:178`), plus `limit_large_tool_results` 50 KiB/2000 lines with spill (`limit_large_tool_results.go:25-105`) before `Emit`/`record`/`postHook` (`dispatcher.go:1063-1109`).

6. Preserve envelope, not just string. `NewTextErrorResponse IsError:true` (`tools.go:66-70`, `tools.go:95-126`), `convertToToolResult` mapping `IsError/Data/MIMEType` (`agent.go:2091-2131`), `WithResponseMetadata` (`bash.go:275-283`, `grep.go:183-189`), and `BuildToolResultMultiContent` (`chat/tool_result.go:14-33`) for `Images/Documents`.

7. Redact at three legs. `pre_tool_use` args, `before_llm_call` messages, and `tool_response_transform` output via `portcullis` (`redact_secrets.go:37-151`) so `bash`/`fetch`/`grep` bodies cannot leak `API_KEY`; log-only redaction (`crush_logs.go:60-70`) alone is insufficient.

8. For shell grants that override a safety `Ask`, apply `shellGrantCoversCommand` word-boundary/no-metachar strictness (`shell_grant.go:1-40`, `dispatcher.go:555-580`) — never `HasPrefix` on raw `command` strings.

9. Escape session-derived paths with `url.PathEscape(sessionID)` (`limit_large_tool_results.go:187-192`) and clean on `EventSessionEnd` (`limit_large_tool_results.go:67-70`) with a global per-session byte quota and age-based GC (neither source has this yet).

10. Cap binary content after decode. `ensureRawBytes` (`mcp-tools.go:133-148`) and `processMCPContent` (`mcp/mcp.go:829-883`) re-encode without size check; add decoded-size + `MediaContent.Data` length guard before `NewImageResponse` (`view.go:387-400`).

## Anti-Patterns / Caution Signs

- **Hook or permission not in the structural path.** If a tool can be invoked without passing `hookedTool.Run` (`hooked_tool.go:54`) or `Dispatcher.Process` (`dispatcher.go:195`), the Phase 8 rule is advisory. Gate is the choke point, not a helper.

- **Uncapped artifact producer.** `download` `io.Copy` with only `5m` timeout (`download.go:152`), MCP `TextContent` concatenation without cap (`mcp/tools.go:58` via `mcp-tools.go:149`), and `crush_logs` `1MB` line skip without accounting are the scent — every producer that can return >50 KiB needs a `LimitReader` or spill.

- **Silent discard without marker.** Returning `""` or truncated content without `Truncated:true` metadata or `[N lines truncated]`/`[Content truncated to ...]` marker (`bash.go:427-442`, `fetch.go:184`, `grep.go:178`, `limit_large_tool_results.go:25-105` notice) breaks evidence preservation. If the LLM-visible suffix is missing in an E2E round-trip (gap noted in both sources), the bound is lossy.

- **Prefix-match allow for shell.** `matchGlob` `HasPrefix` when `trailing *` with no other glob chars (`permissions.go:260-266`) means `allowed: ["mkdir*"]` covers `mkdir x; rm -rf`. Treat shell command allows as strict unless qualified.

- **Sanitize-to-empty that loops.** `sanitizeToolInput` `{} `→ `file_path is required` (`agent.go:2276` + `write.go:57`) can cause tight model retries on malformed JSON. Emit a distinct typed error or `FinishReason` so the loop can be detected, not just retried.

- **Whitespace fallback that hides edits.** `findAndReplace` `normalizedReplace` silent fallback (`edit.go:201` `whitespaceCorrectedNote`) changes newline semantics without the model realizing — surface the correction as a warning, not a silent fix.

- **Single `Resume` channel serialized by one mutex.** `confirmationMu` (`dispatcher.go:810-845`) plus unkeyed `Resume <-chan ResumeRequest` limits to one interactive confirmation per batch; parallel `Process` (`dispatcher.go:258-268`) then misses parallelism — key by `ToolCallID` if you need concurrent asks.

- **Generation-fenced cache without size policy.** `cacheGen` bump on `invalidateCache` (`mcp/mcp.go:645-701`) prevents stale `ToolList` but unbounded retry (`RestartAndWait 35s` single retry at `mcp/mcp.go:783-789`) and unbounded `candidatePool=max(limit*20,1000)` (`glob.go:134`) can still OOM under `~/` scale.

## Notable Absences

- No global duplicate-name rejection at `SetTools` time in crush beyond `mcp_` prefix — unknown-tool and duplicate-name E2E tests absent (`Questions / Gaps` notes no crush-side unit test for unknown-tool dispatch; docker-agent has `TestDispatcher_UnknownToolEmitsErrorResponse` at `dispatcher_test.go:301-320` but still no truncated-ID validation).
- No shared byte quota or streaming spill — both hold full `payload` as `string` before `len` check (`limit_large_tool_results.go:86-88` `writeLargeToolResult` still allocates; crush `readTextFile` similarly). No artifact store (`artifact://<id>`) alternative to temp file.
- No central secret scrubbing before `convertToToolResult`/`recordToolResponse` in crush — only `sensitiveKeys` in log formatting (`crush_logs.go:60-70`, `crush_info_test.go:236-243`); `bash`/`fetch`/`grep` payloads that contain `token=...` travel verbatim to model and transcript.
- No binary/media size limit in either source for `Images/Audios/Documents` (`mcp.go:829-883` `encodeMedia` without cap; `chat/tool_result.go:14-33` `BuildToolResultMultiContent` without cap; docker-agent gap note confirms).
- No provider-specific `tool_call_id` validation (Anthropic `toolu_*`, OpenAI `call_*`) — both treat `call.ID` as opaque (`permission.go:112`, `mcp-tools.go:112`).
- No preservation of truncated output alongside error as durable artifact — docker-agent spill is best-available but `writeLargeToolResult` failure falls back to raw oversized payload (`limit_large_tool_results.go:86-88` `Warn` and `return nil`); crush `download` has no marker at all.
- No MCP sandbox proof — lifecycle proves liveness fencing and OAuth handling (`mcp/init.go:659-771`) but not capability drop, filesystem scoping, or egress filtering (`mcp-tools.go:106` permission still prompts but does not constrain the child).
