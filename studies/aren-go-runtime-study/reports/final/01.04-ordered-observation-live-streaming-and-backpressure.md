## Executive Summary

Two agent runtimes (crush, docker-agent), one infrastructure broker (nats-server), and one model server (ollama) implement four different answers to the same dimension. Crush (8/10) and docker-agent (8/10) both solve the Aren Phase 1 -> Phase 4 problem — preserving ordering and terminal truth while isolating slow observers and surviving reconnect — but with opposite bets: crush makes the event stream lossy by design and pushes correctness into a durable SQLite state store that clients refetch, while docker-agent keeps a sequenced, replayable per-session ring (1024 events, monotonic `seq`) with an explicit `gap` protocol and snapshot-advertised cursor. NATS (6/10) shows the production-hardened extreme of the same split at infrastructure scale: per-client isolated outbound staging (`out.nb/pb`, pooled buffers, per-write `WriteDeadline`) with hard disconnect for core clients (`MAX_PENDING_SIZE=64 MiB` + `SlowConsumerPendingBytes/WriteDeadline`) and flow-controlled stall (`JsFlowControlMaxPending=32 MiB`, `MaxAckPending`, `pbytes>maxpb`) for durable JetStream consumers that can replay infinitely from `sseq`/`dseq`/`asflr` cursors. Ollama (3/10) is the negative control — a per-request unbuffered `chan any` feeding NDJSON `done:true` frames with pure TCP backpressure, no fan-out, no sequence, no replay, no drop accounting.

Across all four, the load-bearing insight is that no high-scoring source tries to make a single mechanism do everything. Durable facts (lifecycle, terminal, turn-boundary) travel a different path — via a second delivery class, a second buffer, or a second store — than lossy progress (token deltas, partial tool-call args). Ordering is total only where it is cheap to enforce (single stream sequence, per-subscriber FIFO, run-correlated terminal); cross-domain ordering is deliberately abandoned and compensated with payload self-sufficiency. Backpressure always answers the same question with a bounded choice: block the producer (runtime channel 128), drop the observer (SSE listener disconnect, lossy publish), or stall the consumer (flow-control window), never grow unbounded.

For Aren, the immediate transfer is not a component to copy wholesale but a set of composable decisions proven combat-tested: bake the durable-vs-lossy taxonomy into the publisher interface, put a bounded coalescing/throttling layer strictly at the presentation boundary, deliver terminal truth via close-or-sequenced-frame rather than best-effort data frame, do replay/live registration under one lock, and define reconnect as snapshot+cursor with an explicit `gap` signal — not silent resume.

## Core Thesis

Ordered observation that survives slow consumers and reconnect is not a single queue with knobs — it is a **two-path architecture** where the durable truth path and the live progress path have different bounds, different delivery guarantees, different retention, and different reconnect semantics, unified only by a small set of bridge invariants.

The high-scoring sources share the same decomposition even though they place the cut in different places:

*At the edge that produces execution*, backpressure is allowed to propagate (crush does not — `channelSink` in `pkg/runtime/event_sink.go:35-38` blocks the model reader into a 128-slot channel `pkg/runtime/defaults.go:17`; docker-agent's runtime observers are explicitly synchronous `pkg/runtime/observer.go:14-18`; nats-server intentionally throttles fast producers via `stc`/`stalledWait` up to 10 ms `server/client.go:3622-3624,3711-3749`). The producer must feel pressure rather than allocate infinitely.

*At every fan-out edge that serves observers*, delivery switches to isolation: per-subscriber buffers (`crush internal/pubsub/broker.go:34-40` size 4096; `docker-agent pkg/app/app.go:932` size 1024; `nats-server server/client.go:349-361` `out.nb/pb` per client), non-blocking scatter (`select/default`), and a per-observer penalty (drop-count, eviction, or disconnect). No observer ever blocks another observer, and — with documented exceptions at the runtime observer boundary — no observer blocks execution; execution blocks only on its own bounded producer channel.

*Between durable and live*, sources that succeed keep exactly one source of truth durable (SQLite in crush `internal/message/message.go:33-45`, ring+store in docker-agent, `memStore`/`filestore` in nats-server `server/memstore.go:288-324`) and let the live stream be advisory. The stream may coalesce (`33 ms debounce` in crush `internal/message/message.go:16-21`; `50 ms throttle+merge` in docker-agent `pkg/app/app.go:146,1591-1698`), may drop (crush lossy `Publish` `internal/pubsub/broker.go:165-188`; docker-agent turn-boundary eviction `pkg/app/app.go:971-984`; nats-server per-client disconnect `server/client.go:2598-2615`), but durable facts take a separate guaranteed path (crush `PublishMustDeliver` with 50 ms timeout `internal/pubsub/broker.go:42-45`; docker-agent sequenced `eventLog.append` `pkg/server/eventlog.go:91-93`; nats-server JetStream `loopAndGatherMsgs` stall `server/consumer.go:5418-5442`). Terminal truth is never just "the last data frame" — it is a distinct signal: channel close (`docker-agent pkg/runtime/loop.go:196-211`), sequenced `session_exited` (`pkg/server/eventlog.go:113-129`), or `RunComplete` with embedded reconciliation payload (`crush internal/agent/agent.go:735-781`).

The consistent price of this split is complexity at the handoff: the fan-in choice must name the delivery class (`setupSubscriberMustDeliver` vs `setupSubscriber` `internal/app/app.go:636-666`), the throttle must know which events are boundary (`isTurnBoundaryEvent` `pkg/app/app.go:994-1005`), the replay registration must snapshot and subscribe atomically (`pkg/server/eventlog.go:146-160`), and the gap must be explicit (`gapEvent` `pkg/server/eventlog.go:19-26` vs crush's honest "gone" `internal/workspace/workspace.go:44-48`). Ollama, which pays none of those costs — one `make(chan any)` `server/routes.go:649`, one `gin.Context.Stream` `server/routes.go:2097-2144`, zero envelope — demonstrates what the dimension loses when the split is omitted: every token is honest, every slow client stalls generation, and every disconnect restarts from scratch.

## Approach Models

**crush — Dual-class notification bus on a durable state store.** Twelve domain brokers fan into one `tea.Msg` broker (`internal/app/app.go:585-609`). Each publish site declares its class: lossy `Publish` for progress deltas, bounded-blocking `PublishMustDeliver` (fast-path non-blocking, slow-path 50 ms `internal/pubsub/broker.go:201-236`) for terminal facts. The message service coalesces streaming updates behind a 33 ms write-behind debounce and classifies snapshots as structural vs progress via `shouldFlushNow` (`internal/message/message.go:414-447`) — terminal flushes synchronously and publishes must-deliver, progress stays lossy. The event envelope carries no sequence; durability lives in SQLite (`internal/message/message.go:33-45`). Reconnect is deliberately resync-only: `ErrStreamClosed` `internal/workspace/workspace.go:44-49` documents "are lost for good," recovery re-creates the workspace from snapshot (`internal/workspace/client_workspace.go:899-942`) and reloads the session. A stalled SSE handler blocks on its own channel only; buffer 4096 then drop-per-subscriber (`internal/pubsub/broker.go:177-187`) — isolation without observer accounting.

**docker-agent — Bonded blocking core with layered lossy-then-durable isolation.** Tier 1 (runtime): `LocalRuntime.RunStream` → blocking `channelSink` (`pkg/runtime/event_sink.go:35-38`) into `channelCapacity=128` (`pkg/runtime/defaults.go:17`); observers run synchronously on the forward goroutine and back-pressure by contract (`pkg/runtime/observer.go:14-18`). Tier 2 (process): single `startFanOut` goroutine (`pkg/app/app.go:956-988`) clones the subscriber list and scatters with `select/default`, throttles 50 ms, merges adjacent deltas (`pkg/app/app.go:1591-1698`), and on overflow evicts oldest pending delta to admit turn-boundary events (`isTurnBoundaryEvent` `pkg/app/app.go:990-1006`). Tier 3 (transport): per-session `eventLog` (`pkg/server/eventlog.go:42-73`) assigns monotonic `seq` under lock (`eventlog.go:91-93`), retains 1024-event ring, delivers to per-listener buffered channels non-blocking — full listener → `close`+remove (`eventlog.go:106-110`), and registers backlog+listener under one lock for exactly-once handoff (`eventlog.go:146-160`). Reconnect uses `?since=` / `Last-Event-ID` (`pkg/server/server.go:652-662`), each frame `id: <seq>` (`server.go:715-750`), plus sequenced `session_exited` terminal (`eventlog.go:113-129`) and periodic `: ping` heartbeats serialized under `writeMu` (`server.go:686-713`). Outside the window it sends seq-0 `gapEvent` (`eventlog.go:19-26`) so the client re-snapshots via `GetSessionSnapshot` `LastEventSeq` (`pkg/server/session_manager.go:512-557`) then re-tails.

**nats-server — Infrastructure broker with isolated staging and durable cursor log.** Per-client `out{ nb net.Buffers, pb, wnb, mp, wdl, stc }` (`server/client.go:349-361`) owns pooled slices (`nbPoolSmall/Medium/Large` `client.go:363-408`). Producers do `queueOutbound` per `subscription.client` (`client.go:3976-3995`); each client's `writeLoop` (`client.go:1368-1413`) does `flushOutbound` by swapping `nb→wnb` outside the producer lock, framing outside the lock, then `WriteTo` in `nbMaxVectorSize=1024` batches each with `SetWriteDeadline(time.Now().Add(wdl))` (`client.go:1842-1856`, `const.go:132`). Core backpressure is hard: `pb>mp` (`MAX_PENDING_SIZE=64 MiB` `const.go:101-102`) → `SlowConsumerPendingBytes` disconnect (`client.go:2598-2615`); write timeout → `SlowConsumerWriteDeadline` disconnect or `Retry` for mesh kinds typed by `WriteTimeoutPolicy` (`client.go:736-752`). A producer that hits a `pb>3/4 mp` consumer is throttled via per-client `stc` gate + `stalledWait` 2–5 ms up to 10 ms total (`client.go:3622-3624,3711-3749`). JetStream keeps a total-ordered store (`seq==LastSeq+1` `memstore.go:288-324`, `StreamState.FirstSeq/LastSeq`) and per-consumer cursor state (`sseq/dseq/asflr/adflr/pending/rdq` `consumer.go:450-453,5889-6067`). Delivery via `loopAndGatherMsgs` (`consumer.go:5343-5608`) stalls honestly on `pbytes>maxpb` (`JsFlowControlMaxPending=32 MiB` `consumer.go:601-602`, `maxpb/16`, `consumer.go:5418-5442`) and `MaxAckPending` (`consumer.go:4921,5418`), with adaptive `maxpb*=2` flow-control window (`consumer.go:5854-5856`) and `push`/`pull`+`waitingRequest` timeout semantics (`408`/`404` `consumer.go:5084-5095`). Durable consumers persist `sseq/asflr` and resume from `+1` with `rdq` redelivery (`consumer.go:6014-6045`); ephemeral core subs get `DeliverAll/Last/LastPerSubject/ByStartSeq/New` start (`consumer.go:6328-6444`) but no cursor continuity.

**ollama — Unbuffered single-observer pipe.** Each `POST /api/generate|chat` creates one `ch:=make(chan any)` `server/routes.go:649,2745`, one `r.Completion(ctx, ..., func(cr){ ch <- res })` callback that blocks synchronously inside the llama-server scanner loop (`llm/llama_server.go:1703-1708`), and one `streamResponse(c,ch)` that loops `val,ok:=<-ch` → `json.Marshal` → `w.Write(+ '\n')` with `c.Stream`/`c.Writer.Flush()` (`server/routes.go:2097-2144,359-374`). Ordering is chan FIFO + TCP byte order; no envelope, no seq, no fan-out, no queue. Backpressure is implicit TCP flow control pausing the writer → pausing `ch <-` → pausing the scanner. Terminal is a final frame `Done:true` (`api/types.go:891-930`, `llm/llama_server.go:1711-1727`) mapped to `TotalDuration/LoadDuration` (`server/routes.go:707-710`) — or, if no bytes yet, an HTTP error status (`server/routes.go:2116-2123`). Non-streaming (`stream:false`) accumulates all deltas into one `c.JSON` (`server/routes.go:750-793`). No retention, no replay, no cursor (`api/types.go:1-1348` searched, zero hits).

## Pattern Catalog

### 1. Two-class publisher baked into the interface

- **Problem:** uniform delivery either loses terminal facts or buffers forever for progress deltas.
- **Demonstrated by:** crush explicitly (`Publisher[T]{ Publish, PublishMustDeliver }` `internal/pubsub/events.go:56-67`, fan-in choosing per service `internal/app/app.go:636-666`); docker-agent implicitly via priority eviction (`isTurnBoundaryEvent` `pkg/app/app.go:963-1005`) plus separate runtime best-effort `StreamStopped` vs close; nats-server via dual regime (core disconnect vs JetStream stall `server/client.go:2598-2615` vs `server/consumer.go:5418-5442`); ollama by absence (single `chan any` conflates the two).
- **Why it works:** the call site declares "is this replaceable display data or an irrecoverable fact?" and the machinery honors it without per-event configuration. Greppability (`Publisher[T]`, `isTurnBoundaryEvent`, `WriteTimeoutPolicy`) makes the taxonomy auditable.
- **When to copy:** whenever the system has both turn-boundary/mutating facts and high-volume progress deltas — which is every Aren phase beyond trivial request/response.
- **Overkill/risky:** for pure 1:1 RPC without observers or without distinct terminal facts, a single class suffices; adding a second class doubles the test surface (crush's must-deliver chain crosses two brokers with two drop opportunities `internal/app/app.go:643-666`).
- **Evidence:** crush `internal/pubsub/broker.go:4-24` doc, `broker.go:165-236` both paths; docker-agent `pkg/app/app.go:990-1006`; nats-server `server/client.go:736-752`, `server/consumer.go:4921`.

### 2. Write-behind coalescing with structural preemption

- **Problem:** token deltas arrive at per-token rate; persisting + publishing each one saturates store and bus.
- **Demonstrated by:** crush 33 ms debounce classifying `shouldFlushNow` — message finished, tool-call set grew, tool finished, reasoning ended (`internal/message/message.go:16-21,215-274,414-447`) flushing terminal synchronously and coalescing progress; docker-agent 50 ms `mergeEvents` merging adjacent `AgentChoice/Reasoning/PartialToolCall/ToolCallOutput` via `strings.Builder` (`pkg/app/app.go:146,1591-1698`); nats-server has no coalescing (explicit gap `server/memstore.go:333-337` is retention, not observer optimization); ollama has none in streaming and does whole-response coalescing only in `stream:false` (`server/routes.go:750-789`).
- **Why it works:** collapsing N deltas into one write + one pub preserves final-state convergence (`internal/message/message_test.go:272-315` in crush proves convergence) while barrier events bypass the window, so structural transitions never wait.
- **When to copy:** any streaming path that persists per-delta or fans out per-delta; put it strictly at the presentation/write boundary (docker-agent only throttles in the App, not in runtime or `eventLog` — `pkg/app/app.go:1591-1598` vs `pkg/server/eventlog.go:91-101`).
- **Overkill:** if the store is not on the hot path or volume is low, direct write is simpler and avoids timer/flush-state bugs (`internal/message/message.go:71-102` `flushing` flag spin, `message.go:264-271` detached timer).
- **Evidence:** crush `internal/message/message.go:16-21,250-259,343-351,376-383`; docker-agent `pkg/app/app.go:146,1591-1698`.

### 3. Flush-before-terminal plus payload-embedded reconciliation

- **Problem:** terminal fact must never be observed before the state it terminates, but ordering across brokers/buffers is not guaranteed; dropping the terminal is catastrophic.
- **Demonstrated by:** crush drains all debounced deltas with a bounded 5 s detached-context flush before publishing `RunComplete{MessageID,Text}` (`internal/agent/agent.go:735-781`); `crush run` waits only for RunID-matching terminal and prints embedded `Text` if message events lag (`internal/cmd/run.go:319-333`, `internal/cmd/run_stream_test.go:89-103`). Docker-agent's runtime does the converse: best-effort `StreamStopped` before close (`pkg/runtime/loop.go:196-211`, `event.go:580-588`) with close as guarantee; SSE terminal is a real sequenced `session_exited` (`pkg/server/eventlog.go:113-129`). Nats-server's lacking primitive (`server/consumer.go:5438-5442` EOF via `sseq>LastSeq` plus `408/404`) shows the cost of not having it.
- **Why it works:** the terminal is ordered correctly when possible and self-sufficient when not; even an inversion or a dropped progress tail still leaves the client able to render final truth.
- **When to copy:** every execution with streaming progress and a single completion summary; pair exactly-once emit (correlator/marker) with post-flush emit.
- **Risky:** fan-in hops multiply drop chances (crush must-deliver chain); nats-server shows a terminal-as-reach-the-tail approach is race-prone under truncation (`reconcileStateWithStream` `server/consumer.go:6267-6326`).
- **Evidence:** crush `internal/agent/agent.go:735-781,747-748` honest comment, `coordinator.go:281-336` coalesced publish, `backend/agent.go:87-122` fallback, `run_marker.go:27-47`; docker-agent `pkg/runtime/loop.go:187-200`, `pkg/server/eventlog.go:28-40`.

### 4. Single-lock exactly-once replay/live handoff

- **Problem:** gap between "snapshot the backlog" and "subscribe for live" loses or duplicates an event.
- **Demonstrated by:** docker-agent `eventLog` under one mutex hold (`pkg/server/eventlog.go:146-160`): copy backlog, register listener, handle concurrent appends; stress-proven by `TestEventLog_RegistrationIsGapless` 50 iterations (`pkg/server/eventlog_test.go:152-180`). Crush explicitly avoids the problem: `subscribe-before-AttachClient` (`internal/server/proto.go:281-337`) ensures presence implies delivery start, but since there is no backlog, no replay handoff exists. Nats-server's durable consumer `sseq=LastSeq+1` resume under store locks (`consumer.go:6328-6442`) is similar but distributed across `ipQueue`/`jsOutQ`/`internalLoop` (`stream.go:8497-8512`), not one lock.
- **Why it works:** atomicity makes the sequence space linearizable at the observer boundary; no bloom filter, no dedup window.
- **When to copy:** any reconnectable log; keep the log's ingest and subscribe paths under the same lock/epoch.
- **Overkill:** for resync-only designs like crush where the stream is volatile and recovery is full refetch (`internal/workspace/workspace.go:44-48`), this machinery is correctly omitted.
- **Evidence:** docker-agent `pkg/server/eventlog.go:146-160`, `eventlog_test.go:149-180`; crush `internal/server/proto.go:288-302` for contrast.

### 5. Per-observer isolated outbound staging (drop or disconnect, never block the pump)

- **Problem:** one slow client must not stall producers or other clients.
- **Demonstrated by:** crush per-subscriber chan 4096 lossy drop (`internal/pubsub/broker.go:165-188`) vs must-deliver timeout drop (`broker.go:201-236`); docker-agent per-subscriber chan 1024 lossy drop/evict (`pkg/app/app.go:956-988`) and per-listener ring buffer with full→disconnect (`pkg/server/eventlog.go:91-111`, `eventlog_test.go:247-291`); nats-server per-client `out.nb/pb` `server/client.go:349-361,2566-2596`, pooled buffers `client.go:363-408`, working-copy flush `client.go:1718-1945`; ollama's single `ch` is the counterexample — no isolation.
- **Why it works:** fan-out cost is map iteration plus non-blocking send; the slow observer's buffer fills and then loses only for itself; other observers' `pb`/`nb` are untouched (`server/client.go:2598-2615` explicitly per-client); multi-client isolation is end-to-end tested (`crush internal/server/e2e_test.go:335-425,516-560`, `docker-agent pkg/server/eventlog_test.go:247-291`).
- **When to copy:** every multi-consumer hop; decide upfront the per-observer penalty — count-and-continue (crush) vs evict-boundary (docker-agent) vs disconnect (nats-server core, docker-agent SSE).
- **Overkill:** for 1:1 pipes (ollama's original local-daemon shape) per-observer staging is wasted memory.
- **Evidence:** crush `internal/pubsub/broker.go:34-40,165-188`; docker-agent `pkg/app/app.go:911-944,956-1006`, `pkg/server/eventlog.go:42-129`; nats-server `server/client.go:349-361,1718-1945`, `const.go:101-102`.

### 6. Bounded blocking at the producer edge, non-blocking at the fan-out edge

- **Problem:** unbounded buffering leaks memory; unbounded dropping loses correctness.
- **Demonstrated by:** docker-agent blocks exactly at `channelSink`→128 (`pkg/runtime/event_sink.go:35-38`, `defaults.go:9-17`) and non-blocks everywhere else (`pkg/app/app.go:947-949`, `pkg/server/eventlog.go:75-79`); nats-server blocks producers only via small `stc` gate (`server/client.go:3622-3624`) while still non-blocking on `jsOutQ/ipQueue`/`outq` (`stream.go:8497-8512`); crush does the opposite by design — no producer blocking at all, always non-blocking publish — and puts the bound in the consumer buffer only (4096). Ollama blocks everywhere (`make(chan any)` `server/routes.go:649`).
- **Why it works:** backpressure is honest where execution can tolerate it (bounded stall) and replaced by drop/disconnect where execution cannot (observer fan-out); memory stays bounded in both regimes.
- **When to copy:** default to blocking producer core + non-blocking fan-out unless the producer is the model-stream reader itself — then bound the reader via context `idle-timeout` (`docker-agent pkg/runtime/streaming.go:342-355`) not via infinite growth.
- **Evidence:** docker-agent `pkg/runtime/event_sink.go:18-22`, `pkg/app/app.go:697-704,754-767`; nats-server `server/client.go:1934-1937,3622-3749`; crush `internal/backend/agent.go:30-61` fire-and-forget vs `pkg/runtime/event_sink.go:40-68` non-blocking variant for long-lived goroutines.

### 7. Heartbeat + write serialization + subscription handshake

- **Problem:** quiet streams look dead; concurrent writers interleave frames; subscriber that registers after attach misses the first events.
- **Demonstrated by:** docker-agent `: ping` every 15 s + `writeMu` between heartbeat goroutine and event sender (`pkg/server/server.go:39-43,649,686-713`), `GetSessionSnapshot` returning `LastEventSeq` for gap resumption (`pkg/server/session_manager.go:512-557`); crush `subscribe-before-AttachClient` plus immediate header flush so quiet workspaces don't block handshake (`internal/server/proto.go:281-337`, `proto.go:307-312`); nats-server heartbeat `100 Idle Heartbeat` with `JSLastConsumerSeq/JSLastStreamSeq` (`server/consumer.go:5610-5621`) and `JSConsumerStalled` advisory.
- **Why it works:** liveness, framing, and presence become explicit protocol, not inferred from silence.
- **When to copy:** any SSE/NDJSON stream expected to go quiet (agent thinking, queue dwell); always serialize header/data and heartbeat/data under one write mutex.
- **Evidence:** docker-agent `pkg/server/server.go:670-713`, `pkg/server/eventlog.go:31-36`; crush `internal/server/proto.go:288-312`; nats-server `server/consumer.go:5610-5621`.

### 8. Explicit gap signal and snapshot+cursor resync

- **Problem:** retention is bounded; long disconnects outrun the backlog; silent resume lies.
- **Demonstrated by:** docker-agent `gapEvent` seq-0, no `id:` (`pkg/server/eventlog.go:19-26`, `pkg/server/server.go:722-726`) when `since+1 < oldest` (`eventlog.go:204-235`), then client re-snapshots (`session_manager.go:537,554`); nats-server defers to `DeliverAll/Last/New` and `pending==0 && sseq>LastSeq` EOF rather than a gap frame, relying on durable cursor to avoid gaps within retention; crush documents honest non-recovery: "lost for good" `internal/workspace/workspace.go:44-48`, recovery by full workspace re-creation (`client_workspace.go:899-942`) and UI session reload (`internal/ui/model/ui.go:1509-1512`); ollama has nothing.
- **Why it works:** the client learns whether it is caught up (ordered replay), barely caught up (snapshot delta), or blind — not "connected but stale."
- **When to copy:** whenever retention is smaller than plausible disconnect duration; pair a zero-id control frame with a cursor-advertising snapshot endpoint.
- **Overkill:** for ephemeral display-only streams without durability relevance, resync-only is cheaper and honest — crush's choice matches its TUI-resync shape.
- **Evidence:** docker-agent `pkg/server/eventlog.go:19-26,204-235`, `pkg/server/session_manager.go:512-557`; crush `internal/workspace/workspace.go:44-49`; nats-server `server/consumer.go:6328-6444`.

## Key Differences

**Retention and liveness decide the architecture, not engineering taste.**

- **Durable-vs-lossy cut placement.** Crush keeps durability entirely outside the stream (SQLite state store `internal/message/message.go:33-45`; stream = notification). Docker-agent splits it: runtime & App are lossy/coalescing, `eventLog` ring is durable for its window. Nats-server keeps durability in JetStream store (`memStore`/`filestore`) and uses `outq/pbytes/pending` as the live view. Ollama collapses them — no durable leg. The cut moves where cost is justified: crush avoids sequencing/replay complexity at the price of full resync on every blip (`internal/ui/model/ui.go:1509-1512`); docker-agent pays sequencing + snapshot to keep blips cheap; nats-server pays durable cursors + redelivery timers to keep them invisible within retention.

- **Ordering scope.** Nats-server offers total per-stream order (`LastSeq` `memstore.go:288-293`) and per-consumer ordered cursors (`sseq/dseq/asflr` `consumer.go:450-453`). Docker-agent offers total per-session order (`seq` `eventlog.go:91-93`). Crush offers per-subscriber FIFO per broker, but explicitly best-effort across the multi-broker fan-in (`internal/agent/agent.go:747-748`) — compensated by RunID correlation (`internal/agent/coordinator.go:272-336`) and embedded payload. Ollama has trivial single-producer FIFO (`server/routes.go:2129-2140`). The pattern: enforce order where one writer exists, do not pretend to serialize independent writers.

- **Bound and penalty.** Crush `bufferSize=4096` (`broker.go:34-40`) drop-counts; docker-agent `subscriber=1024`, `eventLog=1024`, `throttle=128` (`app.go:145,932,1593`) drop/evict vs disconnect; nats-server `MAX_PENDING_SIZE=64 MiB` (`const.go:102`) + `WriteDeadline` + `maxpb=2 MiB`/`pblimit=32 MiB` (`consumer.go:601-602,1845`) hard-disconnect vs flow stall; ollama `8 MB` line cap (`llm/server.go:162`, `api/client.go:168`) error-not-drop. The penalty tracks the customer: internal goroutine → drop; external HTTP consumer → disconnect; durable consumer → stall.

- **Terminal truth mechanism.** Crush: must-deliver `RunComplete` web plus `MarkRunCompletePublished` dedup (`agent/run_marker.go:27-47`) and deferred flush-first ordering. Docker-agent: in-process `close` is guarantee (`loop.go:196-211`) while SSE uses sequenced `session_exited` with late-subscriber replay (`eventlog_test.go:230-245`). Nats-server: no terminal primitive — EOF is `sseq>LastSeq` plus pull terminators `408/404` (`consumer.go:5084-5095`), requiring client idempotence. Ollama: final `done:true` NDJSON line (`api/types.go:891-930`) which is best-effort and vanishes on `ctx.Done()` (`llm/llama_server.go:1667-1671`). Only the first two are "exactly one" by construction.

- **Isolation completeness.** Crush and nats-server both claim "slow observer does not delay others" and both have a bounded exception: crush `PublishMustDeliver` holds `RLock` up to 50 ms per slow subscriber (`broker.go:214-235`); nats-server `stc`/`stalledWait` throttles fast producers up to 10 ms on a `pb>3/4 mp` slow client (`client.go:3622-3624,3711-3749`); docker-agent's App fan-out has no such exception (pure `select/default` `app.go:963-985`) but its runtime observers do — synchronous invocation with no timeout (`observer.go:71-79`) violating the ideal observer-never-controls-execution contract, noted as the study's clearest pass-through coupling.

- **Reconnect posture.** Docker-agent: semantic recovery inside window, declared `gap` outside. Nats-server: semantic recovery for durables, best-effort `DeliverNew` for ephemerals. Crush: best-effort transport + semantic recovery via state resync (never stream replay). Ollama: no recovery. These are not quality grades but constraint responses: a single-user local TUI (crush) tolerates resync; a daemon serving browsers/ACPs (docker-agent) must replay without reloading the whole transcript; an infrastructure broker must do both and expose it as `Durable` config (`consumer.go:90`).

## Tradeoffs

- **Lossiness vs. memory vs. terminal honesty.** Crush's always-non-blocking publish (`broker.go:165-188`) guarantees producers never stall at the cost of silent mid-stream deltas that are invisible until disconnect — acceptable because correctness lives in SQLite, priced as full-session reload (`internal/workspace/client_workspace.go:961-977`). Docker-agent pays the sequencing + retention cost (copied `copy(l.buf,...)` `eventlog.go:96-101` O(capacity) per eviction) to make mid-stream loss detectable (`gapEvent`). Nats-server pays the heaviest: per-client buffers * pooled slices * `writeLoop` goroutine per connection (scales with `DEFAULT_MAX_CONNECTIONS=64k` `const.go:105`) plus adaptive flow window bookkeeping (`consumer.go:5854-5856` that can overshoot on bursts). Best-fit: lossy-notification (crush) for local-agent TUI shape; sequenced log (docker-agent) for multi-consumer daemons; staged outbound+flow (nats-server) for mesh infrastructure. Failure mode when mis-applied: lossy stream carrying irrecoverable facts (would need must-deliver retrofitting); durable log carrying gigs of token deltas.

- **Bounded blocking vs guaranteed progress.** Docker-agent's runtime `channelCapacity=128` stalls the model reader until the consumer drains (`defaults.go:9-17`, `event_sink.go:35-38`) — max 128 deltas, then generation paces. Nats-server's `stc` 10 ms gate throttles but does not pause indefinitely (`client.go:127`). Crush never blocks execution; ollama blocks execution 1:1 on the HTTP writer. The stall-vs-drop decision moves with the invariant: if duplicates or loss are worse than latency, stall; if availability matters more, drop+count+reconnect.

- **Subscribe-before-attach vs duplicate-friendly idempotence.** Crush serializes subscribe then attach (`proto.go:281-337`) to avoid a one-event race; docker-agent solves the same race via atomic snapshot+subscribe lock (`eventlog.go:146-160`). Without either, the only safe answer is idempotent client handling (nats-server's client-side deduplication pressure).

- **Heartbeat/writeMu vs chunked flush latency.** Docker-agent's `: ping` + `writeMu` (`server.go:686-713`) buys liveness at an extra syscall per 15 s and a lock on every frame; ollama's `copyProxyResponseBody` `flusher.Flush()` per 32 KB (`server/cloud_proxy.go:480-504`) favors live token latency over throughput (documented TODO to batch). Crush flushes headers immediately (`proto.go:307-312`) for handshake latency but otherwise does not heartbeat the SSE stream.

- **Single-lock replay handoff synthesis cost.** Docker-agent's correctness depends on holding `eventLog.mu` across backlog copy *and* listener registration — latency under contention grows with ring size; alternative is epoch/sequence linearization but this study finds no source attempting it at application level. Crush's avoidance (no replay) is the alternative.

- **Producer stall gate shadow cost.** Nats-server's 75% threshold (`client.go:3622`) `stc` gate couples a fast fan-in publisher to the slowest consumer on that `readLoop` (`client.go:3711-3749`, `1450-1455`). Under 1:N fan-out one slow client throttles all producers routed through that loop iteration — protection for the slow consumer becomes punishment for fast ones. Docker-agent's symmetric risk is the synchronous observer chain.

## Decision Guide

- **If the product is a local agent TUI like crush (single workspace, SQLite nearby):** Copy crush's split exactly. Put the taxonomy in the type system (`Publisher[T]` two methods `internal/pubsub/events.go:63-66`), make the message buffer write-behind with barrier preemption (`internal/message/message.go:414-447`), emit terminal via must-deliver after a detached-context flush (`internal/agent/agent.go:750-755`), and define reconnect as snapshot reload with cap-exponential backoff (`internal/workspace/client_workspace.go:827-896`). Do not add sequencing or replay; instead embed reconciliation payload in the terminal (`agent.go:735-781`) and test out-of-order reconciliation (`internal/cmd/run_stream_test.go:89-103`).

- **If the product is a daemon serving multiple SSE/EventSource observers that should not full-resync on every blip:** Copy docker-agent's transport tier. Add per-session monotonic `seq` under the same lock as the ring (`pkg/server/eventlog.go:91-93`), single-lock backlog+register (`eventlog.go:146-160`), each frame `id: <seq>` (`server.go:715-750`), `Last-Event-ID`/`?since=` parsing (`server.go:652-662`), `gapEvent` seq-0 when evicted (`eventlog.go:19-26,204-235`), `session_exited` sequenced terminal (`eventlog.go:113-129`), `: ping` heartbeats with `writeMu` (`server.go:686-713`), and `GetSessionSnapshot` returning `LastEventSeq` (`session_manager.go:512-557`). Keep throttling/coalescing strictly in the process fan-out, not in the log (`app.go:1591-1598` vs `eventlog.go:91-101`), and protect boundary events (`isTurnBoundaryEvent` `app.go:994-1005`) during eviction.

- **If the system is infrastructure with many concurrent clients and a durable log (JetStream-like):** Copy nats-server's staging. Per-client `out.nb/pb/wnb/mp/wdl/stc` (`client.go:349-361`) with pooled buffers, dedicated `writeLoop` per connection (`client.go:1368-1413`) with `wnb` copy outside lock + `nbMaxVectorSize` batched `WriteTo` + per-batch `SetWriteDeadline` (`client.go:1830-1842`), hard `pb>mp` disconnect (`client.go:2598-2615`) for ephemeral observers, flow-control + `MaxAckPending` stall (`consumer.go:5824-5842,5418-5421`) for durables, and bounded `ipQueue`/`jsOutQ` with ingress shedding (`ipqueue.go:114-189`, `jetstream_api.go:940-956`). Avoid the `stc` global-stall pathology by not sharing the readLoop stall gate across many producers — scope it per-destination or replace with per-consumer credit.

- **If starting from an ollama-like 1:1 pipe:** The cheapest durable-vs-lossy separation is already halfway there — the non-streaming accumulator (`server/routes.go:750-789`) is the "facts" path. Evolve it by (a) replacing `make(chan any)` (`routes.go:649`) with a bounded `chan Frame` (e.g. 256–1024) and a policy (`Block` vs `DropOldest+count`), (b) moving backpressure off the runner via an intermediate buffer goroutine so drain rate does not hold the `sem` slot (`llm/llama_server.go:1546-1553`), (c) adding an envelope `{seq, dropped_count, kind}` and a small per-execution ring so `done:true` becomes a sequenced terminal, and (d) not reusing the same channel for both progress and lifecycle facts.

- **Choosing the backpressure penalty:** `Block` (stall producer) when loss would violate correctness (execution admission `sched.go:93`, runtime bounded channel); `Drop with count` when data is superseded (token deltas, agent choices); `DropOldest+priority-eviction` when boundary events must win; `Disconnect the slow observer` when an external client's `pb` would otherwise grow unbounded. No source succeeds with a single penalty everywhere; the three sources that mix penalties all documentation-annotate where each applies.

- **For the terminal:** never reuse a data-frame kind. Use `close` (in-process `loop.go:196-211`) or a sequenced control frame with its own id space (SSE `session_exited` `eventlog.go:28-40`, crush `RunComplete` with marker `run_marker.go:27-47`). Poll terminators (`408/404` `consumer.go:5084-5095`) and errors mid-stream are not terminals — they are retry signals.

## Practical Tips

1. Paste the two-method publisher contract on day one. `Publisher[T]{ Publish(T), PublishMustDeliver(T) }` (`crush internal/pubsub/events.go:56-67`) is the cheapest grep-friendly forcing function for "durable vs lossy." Put the drop/timeout/drop-counter behavior in package-level docs (`internal/pubsub/broker.go:4-24`) before any implementation — it prevents later "just add a flag" drift.

2. Keep coalescing at one boundary. Crush's debounce lives in the message service, docker-agent's throttle lives in the App — neither puts it in the sequenced log. Code delta-only partial tool calls (`streaming.go:243-263`) equivalently: send only newly received bytes, not the accumulation. Prove convergence with a coalesced-vs-zero-debounce test (`crush internal/message/message_test.go:272-315`).

3. Make the terminal self-sufficient and flush-first. Detach the final flush's context (`context.WithoutCancel` + 5 s `internal/agent/agent.go:750-755`) so cancel cannot strand deltas before `RunComplete`. Embed `MessageID+Text`/`Metrics`/`Reason` in the terminal payload (`api/types.go:891-930`, `event.go:580-606`) and test that a consumer can reconstruct the final answer out of order (`internal/cmd/run_stream_test.go:83-132`, `internal/agent/run_complete_test.go:200-221`).

4. Do the replay/live handoff under one lock. The whole gaplessness guarantee in docker-agent is the 10-line critical section (`eventlog.go:146-160`); stress it with concurrent append+subscribe loops (50 iterations `eventlog_test.go:152-180`). Do not add replay later without that lock.

5. Heartbeat and serialize writes. Add `: ping` at a fixed interval (`server.go:39-43`) and guard every `Write` (payload *and* heartbeat) with one `writeMu` (`server.go:688-712`). Without it, a long SSE line interleaves mid-frame under concurrency — nats-server shows the parallel for `wnb` framing outside the lock (`client.go:1764-1783`).

6. Define subscribe-before-attach (crush `proto.go:281-337`) or snapshot-plus-cursor (docker-agent `session_manager.go:512-557`) as handshake, not hint. Document the degraded state explicitly: "events while away are lost for good" (`workspace.go:44-49`) vs `gap` + re-snapshot. Do not let clients pretend they are caught up.

7. Give drop counters a reader. Crush exports `DropCount/MustDeliverDropCount` with the comment "so callers can surface saturation" (`broker.go:22-23,146-157`) and then never reads them; docker-agent logs at warn on overflow (`app.go:968,982`) but counters are not exported; nats-server tracks `slowConsumers/scStats` (`client.go:1974-1993`, `server.go:421`) precisely to make saturation observable. Wire them to health/metrics before calling the subsystem done — unobserved backpressure is the same as no backpressure.

8. Cap the scanner, but also cap the stream. All sources bound line size (ollama 8 MB `llm/server.go:162`, crush/dask internal limits) yet only nats-server bounds total pending (`const.go:102`, `consumer.go:601-602`). Without a total bound, millions of tiny tokens can still OOM via TCP buffers even with per-line caps — bound queue depth or bytes in addition to line length.

9. Distinguish delivery class at the fan-in, not at the handler. `setupSubscriberMustDeliver` vs `setupSubscriber` (`app.go:636-666`) puts the must-deliver decision where the taxonomy lives; pushing it into per-handler `if` logic scatters the invariant.

10. For the scheduler's admission vs observation queues, reuse the same naming discipline: `pendingReqCh (maxQueue)` `server/sched.go:93` and `jsAPIRoutedReqs (JSDefaultRequestQueueLimit)` `jetstream_api.go:403-405` both bound edges explicitly — do not reuse admission queue sizing for observation buffering.

## Anti-Patterns / Caution Signs

- **Unbuffered channel as the only backpressure (`make(chan any)` `server/routes.go:649`).** Any live HTTP handler built this way stalls the runner/LLM SSE reader on TCP flow control (`llm/llama_server.go:1703-1708`). Symptom: `EvalDuration` grows with network latency and the `sem` slot (`llm/llama_server.go:1546`) stays held. Fix by inserting a bounded intermediate stage with an explicit drop/block policy and documenting which side owns the `sem`.

- **Synchronous observer invocation on the forward goroutine** (`pkg/runtime/observer.go:71-79`). The contract ("slow observer back-pressures both downstream observers and the consumer `observer.go:14-18`") is honest but unenforceable without a timeout/goroutine-per-observer wrapper. Caution: observer docs that say "must fan out privately" with no panic isolation or per-observer goroutine — audit every registered observer for network I/O.

- **Shared fan-out feeding the durable log** (`cmd/root/run_listen.go:52-62` control-plane pumped from App's throttled fan-out). When the lossy tier sits upstream of the replay log, a dropped-at-fan-out event never reaches sequencing — replay guarantees apply only to what reached the log (docker-agent tradeoffs `consumer.go:5418-5442` caveat). Always tap the log from the runtime/ingest path, not the presentation path.

- **`stc` stall gate that couples one slow consumer to all producers** (`server/client.go:3622-3624,3711-3749` with 75% threshold and `stallTotalAllowed=10ms` `client.go:127`). Smell: any global or loop-shared gate closed by one observer's `pb` and waited on by producers for unrelated observers. Gate must be per-destination or per-consumer credit, not per-readLoop.

- **`copy`-down ring eviction** (`pkg/server/eventlog.go:96-101` `copy(l.buf, l.buf[1:])`). O(capacity) memmove per append once full (≈1024×pointer moves) is fine at low event rates but hot at token-stream rates. Switch to head/tail-indexed circular buffer when steady-state full-ring appends dominate.

- **Drop counters with no production reader** (`internal/pubsub/broker.go:146-157` exported but only tested; `pkg/app/app.go:968,982` warned but not counted). If `DropCount` never reaches telemetry/health, saturation is log-noise. Add a counter-to-metric bridge before declaring backpressure "done."

- **Must-deliver across two brokers** (`internal/app/app.go:643-666` service→`app.events` each with its own timeout). Each hop multiplies latency and a second drop opportunity. Collapse to one must-deliver hop (direct terminal from agent to SSE `eventLog`) or raise the end-to-end test to cover both hops under saturation.

- **Fixed line cap without total-stream cap** (ollama 8 MB `api/client.go:168, llm/server.go:162` with unbounded `strings.Builder` accumulation in `stream:false` `server/routes.go:754-786`). A 1M-token `stream:false` run grows until `c.JSON` serialize, with no cap — the unbounded accumulator is the counterpart to the stall-gate issue.

- **Terminal as a data frame.** Ollama mid-stream `w.Write` failure after streaming started may end the stream with no `done:true` (`server/routes.go:2131` `return false`) — indistinguishable from disconnect without an explicit end-of-stream sentinel. Any terminal that shares framing with data must be sequenced or close-based.

- **Global per-subject limits silently dropping old facts** (`server/memstore.go:333-337` `MaxMsgsPer` replace-oldest) with only `StreamState` shift as notification. Observers replaying `DeliverAll` via `FilteredState` (`memstore.go:601-818`) see gaps with no tombstone — add an explicit tombstone/gap signal if the stream is observed.

## Notable Absences

Across all four sources, with high confidence (each claimed as searched with zero hits unless noted):

- **No source sequences the whole observation world.** Nats-server sequences per-stream; docker-agent per-session; crush per-subscriber FIFO; ollama none. Cross-broker/cross-subject/service ordering remains best-effort and compensated by payload identity rather than sequence — no Aren-relevant adoption of vector clocks or global `seq` appears anywhere.

- **No `Last-Event-ID`/cursor support in crush or ollama.** Searches for `Last-Event-ID`, `cursor`, `since`, `replay`, `sequence` across `internal/server`, `internal/client`, `internal/proto`, `internal/pubsub` (crush) and `api/`, `server/`, `llm/` (ollama) return zero relevant hits; only per-test run IDs exist (crush `e2e_agent_test.go:55-64`). Nats-server and docker-agent both have cursor paths; the absence in the other two is deliberate design, not oversight.

- **No durable/live tagging in envelope.** The wire envelope (`Event[T]{Type,Payload}` `internal/pubsub/events.go:8-12`, `Payload{Type,PayloadType,RawMessage}` `events.go:35-54`; docker-agent `eventLog` seq vs `throttle` deltas; nats-server `JSLastConsumerSeq/JSLastStreamSeq` headers `consumer.go:5612-5620`) never tags "fact vs delta" explicitly — separation lives in code path and buffer choice. No evidence of a typed durability flag in any transport envelope.

- **No coalescing in nats-server, no retention accounting by bytes in docker-agent.** Search for `coalesce/delta` in `nats-server` yielded no observer optimization; per-subject retention there is message replacement (`memstore.go:333-337`), not live delta merging. Docker-agent's `eventLog` window counts events (`eventlog.go:8-11` default 1024), not bytes — no byte-budget evidence found (`eventlog.go` searched). Oversized `msg` + small count can still fit while large total bytes escape retention math.

- **No compile-time linkage for turn-boundary completeness.** `isTurnBoundaryEvent` enumerates six types (`pkg/app/app.go:994-1005`); no source links that list to the canonical event type list (`pkg/runtime/event.go`); a new lifecycle event silently defaults to droppable. No analogous linkage searched in crush's `shouldFlushNow` (`message.go:419-447`) but the same drift hazard applies.

- **No `SSE`/`EventSource` subscription transport in nats-server itself.** Search for `SSE|EventSource|text/event-stream` in `server/**/*.go` returned zero hits there — any SSE gap in nats-server deployments would live in client-side code outside this repo, so evidence for SSE ordering there is client-derived.

- **No consumer-visible truncation marker for `Won't` loss in crush.** A stalled SSE client's 4096 slots fill then drop newer events (`broker.go:177-187`) with no gap signal to the client (`client/proto.go:132-199` no gap detection) — loss mid-stream without disconnect is invisible; only full close triggers resync.

- **Telemetry gap for dropped counters.** Beyond `slowConsumers` in nats-server (`server.go:421`, `client.go:1974-1993`), no source exposes drop accounting on a scrappable endpoint; crush's `DropCount` text promises telemetry (`broker.go:22-23`) with zero production readers; docker-agent warnings stay in logs; ollama has no counter to expose.

## Per-Source Notes

**crush (8/10) — Notification-as-decor, SQLite as truth.** Exemplary interface design: the `Publisher[T]` contract (`internal/pubsub/events.go:63-66`) plus package-level backpressure taxonomy (`internal/pubsub/broker.go:4-24`) and enforced two-hop fan-in (`internal/app/app.go:585-666`) make the durable/lossy split legible and testable. The write-behind `pending` map with `flushing` serialization (`internal/message/message.go:71-102,304-331`), detached timer flush (`message.go:264-271`), and detached cancel-context final flush (`internal/agent/agent.go:508-510,750-755`) shows unusually careful persistence-vs-cancellation handling. End-to-end coverage is unusually strong (out-of-order `RunComplete` reconciliation `internal/cmd/run_stream_test.go:89-103`, cross-client cancel `internal/server/e2e_agent_test.go:324-375`, queued-drop terminal `internal/agent/run_complete_test.go:255-284`). The honest cost is that reconnect is resync-only by documentation (`internal/workspace/workspace.go:44-48`); any transient blip reloads the open session (`internal/ui/model/ui.go:1509-1512`) even when the gap was a handful of events, and the package-global `lspBroker` (`internal/app/lsp_events.go:41`) stands out as the one unscoped broker in an otherwise workspace-scoped design.

**docker-agent (8/10) — The reference for reconnectable live streaming in this cohort.** The cleanest separation of tiers in the study (blocking runtime core `pkg/runtime/event_sink.go:18-38`, lossy presentation fan-out `pkg/app/app.go:956-1006`, sequenced transport log `pkg/server/eventlog.go:42-129`), the most complete replay protocol (monotonic `seq`, single-lock handoff `eventlog.go:146-160` with race test `eventlog_test.go:152-180`, `gapEvent` `eventlog.go:19-26`, `Last-Event-ID` `server.go:652-662`, `writeMu` `server.go:686-713`, `LastEventSeq` snapshot `session_manager.go:512-557`), and the most explicit terminal framing (runtime `close` `loop.go:196-211` vs SSE `session_exited` `eventlog.go:113-129` with `TestEventLog_LateSubscriberSeesTerminalEvent` `eventlog_test.go:230-245`). Points docked precisely where the report says: runtime observers remain synchronous by contract (`observer.go:14-24`), the `--listen` event source taps the wrong upstream (`cmd/root/run_listen.go:52-62`), the ring `copy` is O(N) (`eventlog.go:96-101`), and the Go remote client (`pkg/runtime/client.go:496-499`) ships none of the protocol its server implements.

**nats-server (6/10) — Production broker that happens to contain the hardest version of this dimension.** Durability, ordering, and fan-out here are infrastructure-grade: store-level total order (`memstore.go:288-324`), per-consumer cursor state with `rdq` redelivery and `AckWait/BackOff` (`consumer.go:5889-6067,6070-6186`), bounded `ipQueue/jsOutQ` with per-queue limits (`ipqueue.go:68-82, jetstream_api.go:940-956`), pooled `jsPubMsg/StoreMsg` (`stream.go:8468-8494`), and an explicit in-repo statement of per-observer isolation (`out.nb/pb/wnb` `client.go:349-361`, `queueOutbound` per `subscription.client` `client.go:3976-3995`, `flushOutbound` `wnb` working copy `client.go:1718-1945`). Value for Aren is less as a template than as a proof of scale tradeoffs: fixed `MAX_PENDING_SIZE=64 MiB` uniformity (`const.go:102`, `opts.go:6128` tunable but global), the `stc` producer-coupling pathology (`client.go:3622-3749`), and the lack of delta coalescing or terminal-primitive (replaced by `sseq>LastSeq` + `408/404` terminators `consumer.go:5084-5095`, `5672-5683`) illustrate the prices an infrastructure product pays for guarantees Aren may not need.

**ollama (3/10) — Single-stream NDJSON plumbing, not an observation subsystem.** The counterexample that sharpens the dimension's vocabulary: one `make(chan any)` `server/routes.go:649`, one `gin.Context.Stream` `routes.go:2097-2144`, one `api/types.go:891-930` `Done:true` convention, and 8 MB scanner caps both directions (`llm/server.go:162`, `api/client.go:168`) is all there is. Every useful property of the other three — multi-observer fan-out, drop vs stall policy, coalescing, sequence, cursor, replay, `dropped_count`, durable store — is absent and searched-for with zero hits. Useful exactly as a baseline: this is what ordered observation looks like when the product shape is a local model server rather than a runtime control plane, and why Aren Phase 4 must diverge from it.

Whether the dropped-event accounting promised by `DropCount` (`internal/pubsub/broker.go:22-23`) was intended to be surfaced via telemetry or an SSE `retry`/`gap` frame is unresolved; current implementation leaves a stalled-but-not-closed stream silently gapped.

- **What consumes `DropCount`/`MustDeliverDropCount` in crush, and at what threshold?** Doc comment claims they exist "so callers can surface saturation" (`broker.go:22-23`) yet no non-test caller found; docker-agent's `must-deliver honors timeout then drops` test (`message_test.go:424-461`) similarly lacks a production reader. Whether Aren should expose them via `/v1/health` vs heartbeat vs log-on-threshold is open.

- **Should the App-level `eventLog` tap the runtime observer chain rather than the lossy fan-out?** Docker-agent's report flags this as a real gap: events dropped at `startFanOut` (`app.go:966-970`) never reach sequenced replay.
