## Executive Summary

Two Go agent runtimes answer the same Aren Phases 3-6 problem — how to keep lifecycle code free of vendor SDK detail while still translating requests per provider, normalizing streams, accounting usage, enforcing structured output, and retrying with discipline — with opposite ownership bets that converge on the same lesson.

Crush (5/10) outsources the entire boundary to `charm.land/fantasy` (`internal/agent/agent.go:154`, `fantasy/retry.go:38-105`, `fantasy/errors.go:189-270`). A `Coordinator` resolves `catwalk.Model`+`ProviderConfig` into `fantasy.Provider/LanguageModel` via `buildProvider` (`internal/agent/coordinator.go:1099-1162`) and drives one `fantasy.NewAgent(...).Stream(AgentStreamCall{OnTextDelta,OnRetry,...})` (`internal/agent/agent.go:685-796`). The streaming contract and `ProviderError/RetryError/Usage` taxonomy are neutral, but the translation seam is not: `getProviderOptions`/`mergeCallOptions` (`internal/agent/coordinator.go:360-622`) is a 320+ line vendor switch parsing per-provider options and injecting `reasoning_effort`/`thinking`/`extra_body` per provider ID. Fantasy owns the retry budget (MaxRetries 3, InitialDelay 5s, BackoffFactor 2, no jitter, `Retry-After` aware); crush only adds content-reset (`OnRetry` `internal/agent/agent.go:931-941`) and single-shot credential repair (`makeAuthRefreshCallback` `internal/agent/coordinator.go:1349`). Structured output (`fantasy.ObjectCall` `fantasy/object.go:14-70`) exists in the dependency but is never called on the production path; there is no schema conversion, validation, or repair loop.

Docker-agent (6/10) owns its boundary. A minimal `Provider` (`pkg/model/provider/provider.go:38` `CreateChatCompletionStream(ctx, []chat.Message, []tools.Tool) (chat.MessageStream, error)`) is dispatched by a `Registry` (`pkg/model/provider/factory.go:104`) to leaf clients for OpenAI (chat + responses), Anthropic, Gemini, DMR, Bedrock (`pkg/model/provider/providers/providers.go:22`). Each leaf owns request translation, stream decoding, and error wrapping into `StatusError` (`pkg/modelerrors/modelerrors.go:25`), while `fallbackExecutor` (`pkg/runtime/fallback.go:226`) owns the attempt budget (`1+fallbackRetries` `fallback.go:259`, `backoff.Calculate` `pkg/backoff/backoff.go:25` 200ms·2^attempt capped 2s ±10% jitter, `Retry-After` capped 60s `fallback.go:438`), fallback chain, and cooldown pinning. Structured output is the only source with a real loop: native schema forwarding via `options.WithStructuredOutput` (`pkg/model/provider/options/options.go:118`) *or* tool-mode internal tool `__structured_output__` (`pkg/tools/builtin/structuredoutput/structuredoutput.go:27`) validated by `gojsonschema` with bounded runtime repair (`maxStructuredOutputReminders=2` `pkg/runtime/structured_output.go:27`). Both sources handle in-band 200 failures, distinguish cancellation as non-retryable, and both discard partial output on late truncation — one by design (reset), one by omission.

For Aren, the transferable core is not which library wraps the SDK, but that the neutral event/error vocabulary, the vendor-specific translation registry, the retry classification, the transport-vs-validation retry split, and the usage/partial-output policy each need explicit ownership. Neither source bounds the whole lifecycle with a per-request deadline, neither caps total retry stall, and neither preserves late-stream usage alongside the error.

## Core Thesis

**A provider-neutral boundary is not one abstraction — it is three separated concerns that fail when conflated: a neutral streaming interface, a registry-dispatched vendor translation layer, and an independently owned retry/repair budget with typed error discrimination.**

Both sources prove that a narrow stream contract (`fantasy.AgentStreamCall` / `Provider.CreateChatCompletionStream → chat.MessageStream`) is sufficient to keep lifecycle code off vendor types (`pkg/chat/chat.go:147` `MessageStreamResponse`, `internal/agent/agent.go:880-1062` callbacks). But keeping the call site neutral does not make the system neutral: the translation load moves somewhere, and where it sits decides evolvability. Crush pushes it into one coordinator switch that grows with every vendor quirk (`internal/agent/coordinator.go:414-608` openai/anthropic/google branches, 8+ provider constructors `coordinator.go:891-1090`); docker-agent scatters it into leaf clients behind a `Registry` but still leaks through an untyped `provider_opts map[string]any` (`pkg/model/provider/options/options.go:12`, `pkg/model/provider/anthropic/client.go:294`).

The second separation — retry taxonomy — determines correctness more than the interface does. Success at HTTP level is not success at execution level: mid-stream SSE `error` events inside 200 (`fantasy/errors.go:257` `TransientStreamErrorTypes`, `pkg/model/provider/anthropic/wrap.go:36`), content-filter finish reasons (`internal/agent/agent.go:995-1005`, `pkg/modelerrors/modelerrors.go:238`), and schema validation failures (`pkg/runtime/structured_output.go:155`) must each map to a typed error with its own retry policy. Both sources converge on a four-way split — (1) retryable transport/server (5xx/408/429 with jitter vs Retry-After, network, truncation), (2) auth-repairable (single-shot OAuth/AWS refresh in crush, not retryable same-model in docker-agent), (3) overflow/context-too-large requiring compaction not retry, and (4) cancellation never retried (`fantasy/retry.go:198-205`, `pkg/modelerrors/modelerrors.go:587`).

The consistent price of getting the first two right without the third is late-failure data loss. Both systems accumulate `fullContent`/`currentAssistant` deltas but discard them on the error return path (`pkg/runtime/streaming.go:186` empty `streamResult` on `Recv` error; `internal/agent/agent.go:937-940` `ResetStreamedContent` on `OnRetry` and preserved partial only under `FinishReasonError` via detached `cleanupCtx` `agent.go:1097-1141`). Usage is similarly fragile: crush falls back to `approxTokenCount=(len+3)/4` with an `EstimatedUsage` flag (`internal/agent/usage_fallback.go:18-176`); docker-agent overwrites incremental `messageUsage` with the last chunk and loses it entirely on failure (`pkg/runtime/streaming.go:154-192`). No source attaches usage to the error or preserves partial durably for audit.

Aren should therefore copy the interface+registry+taxonomy shape, but explicitly own per-request deadlines, jitter, `Retry-After` ceilings, partial+usage preservation on truncation, and a bounded validation-repair loop distinct from transport retry.

## Approach Models

**Crush — Library-delegated boundary with coordinator-owned translation.** Credentials and model catalog come from `charm.land/catwalk` and `config.SelectedModel` → `ProviderConfig` → `fantasy.Provider` (`internal/agent/coordinator.go:806-1162`). The production execution is a single `fantasy.NewAgent(largeModel.Model).Stream(...)` with six callbacks (`internal/agent/agent.go:685-796`, `880-1062`). `fantasy` supplies the neutral types (`LanguageModel`, `AgentStreamCall`, `ProviderOptions`, `Usage`, `FinishReason`, `ProviderMetadata`) and the `errors`/`retry` implementation (`fantasy/errors.go:189-270`, `fantasy/retry.go:38-205`). The translation cost is paid locally: `mergeCallOptions` merges `jsons.Merge(catwalkOpts, providerCfgOpts, cfgOpts)` and then `getProviderOptions` branches per `providerCfg.Type` to call `openai.ParseOptions`/`anthropic.ParseOptions`/etc. and inject provider-ID-specific `reasoning_effort`/`thinking`/`extra_body` (`internal/agent/coordinator.go:388-609`). Media rewriting lives as a pre-request fixup (`workaroundProviderMediaLimitations` `internal/agent/agent.go:2133-2238`). Structured output is intentionally absent from the live path (`fantasy/object.go:14-70` defined but only faked in `internal/agent/dispatch_cancel_test.go:5-9`; schema use is `crush schema` `internal/cmd/schema.go:8-22`). This model fits a single binary that wants minimal provider code and can track a shared library's release cadence.

**Docker-agent — Registry-owned neutral interface with leaf-owned translation and runtime-owned retry.** The runtime programs against `type Provider interface { ID() modelsdev.ID; CreateChatCompletionStream(...) (chat.MessageStream, error); BaseConfig() base.Config }` (`pkg/model/provider/provider.go:38`) via `chat.MessageStreamResponse` (`pkg/chat/chat.go:147`, `pkg/chat/chat.go:175` `Usage`). `Registry.NewWithModels` (`pkg/model/provider/factory.go:104`) routes `provider`/`api_type`/`base_url`/`openAIVendor` (`factory.go:91`, `options.go:164` trusted bit) to typed factories (`providers.go:22` seven types). Each leaf — `openai/client.go:351` chat, `openai/client.go:613` responses, `anthropic/client.go:211`, `gemini/client.go:717` — builds its SDK request, decodes its SSE with a leaf adapter (`oaistream/adapter.go:35` accumulator with `toolCalls` map, `openai/response_stream.go:83` dedup by `output_index`, `anthropic/client.go:328` thinking adapters), and wraps errors (`oaistream/wrap.go:15`, `anthropic/wrap.go:27`, `gemini/wrap.go:16` with `errors.go` tiered overflow detection `modelerrors.go:238`). `fallbackExecutor` (`pkg/runtime/fallback.go:226-438`) classifies via `ClassifyModelError` (`modelerrors.go:581`) into rateLimited/overflow/cancelled/transient, applies `backoff.Calculate` (`backoff.go:25`) or `parseRetryAfterHeader` (`modelerrors.go:549`), walks `buildModelChain` (`fallback.go:74`), and pins via `recordSuccess`/`cooldown_manager`. Anthropic also owns a local single overflow retry (`anthropic/retry.go:8` `countTokens` then clamp). Structured output fans out: native forwarding (`options.go:118`, `openai/client.go:746`) versus tool-mode `__structured_output__` with `gojsonschema` validation and runtime reminder loop (`structured_output.go:23-102`, `structuredoutput.go:128`). This model fits a daemon that needs explicit control over fallback, instrumentation (`factory.go:122` `instrumentProvider`), and multi-model policy.

## Pattern Catalog

### 1. Neutral streaming interface with typed response envelope

- **Problem:** Lifecycle code must observe deltas, tool calls, and completion without importing SDK chunk types or SSE framing.
- **Demonstrated by:** crush's `fantasy.AgentStreamCall` (`internal/agent/agent.go:685,880-1062` callbacks `OnTextDelta/OnReasoningDelta/OnToolCall/OnStepFinish` plus `ProviderOptions` typed bag) and docker-agent's `chat.MessageStream` (`pkg/chat/chat.go:197`) yielding `MessageStreamResponse` (`chat.go:147`) with `Choices[].Delta`/`Usage`/`FinishReason` and handling via `handleStream` (`pkg/runtime/streaming.go:73`).
- **Why it works:** One generic reader (`Recv() (MessageStreamResponse, error)`) replaces per-SDK `Next()/Current()/Err()` loops; leaf adapters translate once (`oaistream/adapter.go:35`, `anthropic/client.go:328`). Telemetry and cost recording attach to the neutral `Usage` (`streaming.go:154`, `internal/agent/agent.go:1906-1937`).
- **When to copy:** Any runtime with >2 providers or with observers that must remain SDK-agnostic (Aren Phases 3-6).
- **Overkill/risky:** For a single-provider prototype the indirection hides SDK capabilities (embeddings, deferred tools) behind sub-interfaces (`provider.go:57` `EmbeddingProvider` via type assertion); expose them lazily.
- **Evidence:** `internal/agent/agent.go:154-158` no crush-defined interface; `pkg/model/provider/provider.go:38` neutral contract; `pkg/chat/chat.go:20,175`.

### 2. Registry-dispatched translation with explicit escape-hatch budget

- **Problem:** Provider-neutral model misses per-vendor knobs (`top_k`, `thinkingBudget`, `response_format`, `transport: websocket`, `api_version`).
- **Demonstrated by:** crush's centralized `buildProvider` switch (`coordinator.go:1099-1162`) plus `getProviderOptions` per-type `ParseOptions` and per-ID `extra_body` injection (`coordinator.go:414-608` IoNet/Alibaba/MiniMax/Baseten/Fireworks, `coordinator.go:1106-1112` anthropic-beta interleaved header); docker-agent's decentralized leaves with `provider_opts` untyped map and `openAIVendor` trusted bit (`options.go:12,164`, `factory.go:91`, `anthropic/client.go:294` `GetProviderOptBool`).
- **Why it works:** Keeps the interface small while giving each leaf a place to map a single YAML `thinking_budget` into `reasoning_effort`/`budget_tokens`/`ThinkingLevel` (`gemini/client.go:463`) or to shim `shouldMergeConsecutiveMessages` for Qwen/vLLM (`openai/client.go:293`). Docker-agent's factory-set bit prevents user spoofing.
- **When to copy:** When you must support openai-compatible gateways and provider-specific thinking/reasoning knobs — which Aren must.
- **Overkill/risky:** Untyped escape hatches lose compile-time safety (misspelled `top_k` silently ignored) and widen the translation surface without bound (crush's switch grows linearly per provider). Cap it: a typed `ProviderCapabilities` per provider or a `providerRegistry map[Type]func(...) (ProviderOptions,error)` (`crush Future Considerations`) keeps auditability.
- **Evidence:** `internal/agent/coordinator.go:360-622`; `pkg/model/provider/providers/providers.go:22`; `pkg/model/provider/openai/sampling_opts.go:1`.

### 3. HTTP 200 as typed execution failure

- **Problem:** A 200 can still be a failure — mid-stream SSE error, content-filter finish reason, or context overflow — and must not be treated as success downstream.
- **Demonstrated by:** crush: `TransientStreamErrorTypes = {server_error, overloaded_error, api_error, rate_limit_error, internal_error}` → `TransientError=true` → `IsRetryable=true` despite 200 (`fantasy/errors.go:257-268`); `FinishReasonContentFilter` mapped to `message.FinishReasonContentFilter` with UI banner (`internal/agent/agent.go:995-1005`); `NewIncompleteStreamError` (`errors.go:169-177`) for missing terminal. Docker-agent: Anthropic in-band `type: error` mapped by `wrapAnthropicError` to HTTP codes (`anthropic/wrap.go:36`) so `ClassifyModelError` treats 200-error as 500/529 (`modelerrors.go:599`); overflow tier1/tier2 detection wraps `ContextOverflowError` (`modelerrors.go:238`); tool-mode validation failure becomes `IsError=true` tool_result (`structured_output.go:102-157`).
- **Why it works:** Normalizing in-band errors to the same `ProviderError/StatusError` taxonomy as transport errors lets a single classifier decide retry/compaction/terminal rendering.
- **When to copy:** Every SSE-based provider integration — without it a truncated body is silently persisted as success.
- **Risk:** Unknown in-band types map to 500 and become retryable 5xx instead of overflow (`docker-agent Failure Modes`); crush's fallback never sets `ContextTooLarge` fields so genuine overflow can be misclassified as regular `RetryError`.
- **Evidence:** `fantasy/errors.go:60-97,169-270`; `pkg/modelerrors/modelerrors.go:118,238,428`.

### 4. Four-way retry classification with distinct budgets

- **Problem:** Not all failures deserve the same retry — transport blips should retry same model, rate limits should back off or switch models, overflow must compact not retry, auth must refresh once, validation must repair via prompt.
- **Demonstrated by:** crush: `IsRetryable` true for `TransientError`/`Cause==io.ErrUnexpectedEOF`/`IsTransportError`/428-429/5xx (`fantasy/errors.go:71-97`), `isAuthError` (`StatusCode==401` `retry.go:60-78`) triggers one detached credential refresh (`coordinator.go:1274-1358`, `aws_sso_refresh.go:45-90`) then restarts budget, `isAbortError` (`context.Canceled/DeadlineExceeded`) bypasses retry (`retry.go:198-205`), validation repair is local `sanitizeToolInput`/`filterOrphanedToolResults` (`agent.go:950-973,1626-1687`). Docker-agent: `ClassifyModelError` → `isRetryableStatusCode` 500/502/503/504/529/408 retryable, 429 rateLimited, overflow non-retryable (`modelerrors.go:332,587,593`), `fallbackExecutor.execute` loops `1+fallbackRetries` per model (`fallback.go:259`) with jitter vs `Retry-After` (`backoff.go:25,50`, `modelerrors.go:549`), Anthropic overflow single retry via `countTokens` (`anthropic/retry.go:24`), cancellation `fallback.classifyAttemptError` bubbles (`fallback.go:202`).
- **Why it works:** Single classifier (`ClassifyModelError` / `isRetryableError`) drives two different loops (per-model backoff vs cross-model fallback vs validation reminder) without conflating budgets.
- **When to copy:** Any multi-model runtime — keep authentication repair as a separate one-shot adapter (`OnAuthRefresh`) and validation repair as a runtime prompt loop, not transport backoff.
- **Risk:** Crush's hard-coded `InitialDelay=5s` with no jitter and no deadline means a transient blip costs 35s tail and an adversarial `Retry-After: 60` can stall `crush run` (`fantasy/retry.go:38-105`); docker-agent's multiplicative chain (3 models ×3 attempts =9) and Anthropic's extra single overflow retry double-count attempts.
- **Evidence:** `fantasy/retry.go:18-205`; `pkg/modelerrors/modelerrors.go:332-587`; `pkg/backoff/backoff.go:25`.

### 5. Bounded repair loops distinct from transport retry

- **Problem:** Invalid tool JSON, orphaned tool call/result, and structured-output schema failures are correctness errors, not transport errors — retrying the HTTP call reproduces them.
- **Demonstrated by:** crush: `sanitizeToolInput` replaces invalid JSON with `{}` and marks `sanitizedToolCalls` → synthetic error tool result (`internal/agent/agent.go:969-972,2272-2287`); `filterOrphanedToolResults`/`syntheticToolResultsForOrphanedCalls` (`agent.go:1626-1687`) drop/inject so next turn is not bricked by `400 invalid_json`. Docker-agent: `ConvertParametersToSchema` makes schemas strict (`openai/schema.go:20` `additionalProperties:false`, `gemini/client.go:561` normalize booleans/enums), `structuredoutput.Validate` via `gojsonschema` (`structuredoutput.go:128`), `handleStructuredOutputCalls` validates exclusive call then returns `IsError` tool_result for model self-repair (`runtime/structured_output.go:102`), bounded by `maxStructuredOutputReminders=2` before `ErrorCodeStructuredOutputFailed` (`structured_output.go:27`).
- **Why it works:** Repair stays in-domain (inject a tool_result the model sees) with a cap, instead of burning transport retry budget on deterministic failures.
- **When to copy:** Whenever tools or structured output are in the loop — without it one malformed tool call deadlocks the conversation forever.
- **Overkill:** Crush's `ObjectCall` path is deliberately left unused to avoid repair complexity; docker-agent's tool-mode adds an extra turn of latency versus native `response_format` forwarding.
- **Evidence:** `internal/agent/agent.go:950-973,1626-1687`; `pkg/tools/builtin/structuredoutput/structuredoutput.go:27-157`; `pkg/runtime/structured_output.go:27,74,256`.

### 6. Usage accounting with explicit estimation signaling, but partial-output fragility

- **Problem:** Providers may return zero usage; streams may truncate after partial tokens; callers need cost attribution even on failure.
- **Demonstrated by:** crush: `fallbackStepUsage` → `approxTokenCount(s)=(len+3)/4` when `usageIsZero` (`internal/agent/usage_fallback.go:18-176`), wired per-step (`agent.go:860-862,1027-1028`), `EstimatedUsage` flag on `session.Session` and `session.Cost` via `openrouterCost`/`extractHyperCredits` (`agent.go:1874-1937`), with provider-metadata cost branches. Docker-agent: `handleStream` keeps latest `messageUsage` and `recordUsage` (`streaming.go:154-192`) persisting `Input+Cached+Write→Total` and `tel.RecordTokenUsage`, but on `Recv` error returns `Stopped:true` with zero content/usage (`streaming.go:186`), and success path overwrites with last chunk.
- **Why it works:** Fallback estimation with an `estimated` flag lets budgets degrade gracefully; last-chunk overwrite suits chunked usage delivery (responses API `response.completed` only `response_stream.go:349`).
- **When to fail:** Both discard late-stream attribution: crush resets partial on `OnRetry` (`agent.go:937-940`) keeping it only under final `FinishReasonError` via `cleanupCtx` (`agent.go:1097-1188`); docker-agent discards `fullContent` and `messageUsage` on any truncation, though `AgentChoice` events (`streaming.go:326`) may have already reached the UI.
- **Evidence:** `internal/agent/usage_fallback.go:18-176`; `pkg/runtime/streaming.go:73,154,186,342`.

## Tradeoffs

- **Library reuse vs control.** *Benefit:* Crush's `fantasy` reuse avoids reimplementing SSE parsing, usage extraction, and error taxonomy per provider. *Cost:* Policy is frozen (no jitter, 5s initial, 3 retries) and vendor quirks still leak into the consumer via `getProviderOptions`. *Best-fit:* Small team, many providers, accept library cadence. *Failure mode:* Adversarial `retry-after: <date far future>` stalls caller (`fantasy/retry.go:48-53` no ceiling beyond 60s/exponential) until `ctx` cancels — worse without a per-request deadline. *Alternative:* docker-agent's owned retry lets policy be per-agent (`retries`/`cooldown`) and header-capped at 60s (`fallback.go:436`), but each new provider duplicates adapter code (`oaistream/middleware.go:20` `ErrorBodyMiddleware` per leaf).

- **Typed capability bag vs untyped `provider_opts`.** *Benefit:* `fantasy.ProviderOptions` map of typed structs (`internal/agent/agent.go:845-852` cache-control add) keeps crush code typed; docker-agent's `provider_opts map[string]any` keeps the `Provider` interface stable across providers (`options.go:12`). *Cost:* Typed bag still serializers per-provider structs outside the type system; untyped map silently ignores misspelled keys (`GetProviderOptBool` ok=false `anthropic/client.go:295`). *Best-fit:* Use typed per-provider caps with a registry validator rather than string keys. *Alternative:* Codegen `ProviderCapabilities` struct per provider (docker-agent Future Consideration) recovers compile safety.

- **Single auth-refresh vs per-401 refresh.** *Benefit:* One shot (`fantasy/retry.go:60-78`, `coordinator.go:1349-1358`) prevents infinite loops on permanently revoked tokens, with 5m `WaitForTokenChange` (`coordinator.go:1313`) for interactive reauth. *Cost:* A turn that hits 401, refreshes, then re-hits 401 on a later tool-call step (`ProviderExecuted=true`) surfaces original 401 instead of retrying. *Alternative:* K=2 refreshes per turn with idempotent `UpdateModels` would tolerate mid-loop expiry, at higher complexity.

- **Estimated usage vs last-chunk overwrite.** *Benefit:* Crush's `approxTokenCount` (`usage_fallback.go:171-176`) with `EstimatedUsage` flag keeps cost accounting monotonic even when providers emit zero; docker-agent's last-chunk overwrite correctly handles chunked `Usage` (Gemini) and `response.completed`-only (responses API). *Cost:* Heuristic diverges 10-30% from BPE tokenizers; last-chunk loses inter-chunk accumulation on truncated streams. *Alternative:* Tokenizer-aware fallback per model family retains the `estimated` flag but narrows error.

- **Reset-vs-discard partial on retry.** *Benefit:* Crush's `ResetStreamedContent` keeps retry concatenation correct; docker-agent's empty-on-error contract keeps `streamResult` simple. *Cost:* Successful retry erases the blip the user already saw streaming (flicker); late truncation loses all text for transcript/audit. *Alternative:* Return partial + usage alongside the error (`streamResult{Content: fullContent.String(), Usage: messageUsage}`) so transcript can persist and fallback can re-attribute tokens — docker-agent's own Future Consideration.

## Decision Guide

- **If you need 8+ providers quickly with minimal code and can live with library policy:** Copy crush's split. Depend on a neutral agent library for streaming/usage/error, keep credential resolution centralized (`Coordinator.buildAgentModels` chain), implement `OnRetry` content-reset, and add detached contexts for terminal writes (`internal/agent/agent.go:750-755`, `agent.go:1097-1100`, `aws_sso_refresh.go:62`). Budget for the switch: extract `getProviderOptions` into `providerRegistry map[Type]func(Model, ProviderConfig) (ProviderOptions, error)` before adding the third vendor.

- **If policy, observability, and fallback matter more than provider count:** Copy docker-agent. Define `Provider` as `CreateChatCompletionStream` returning `MessageStream` (`provider.go:38`), generate a `Registry`+`ProviderFactory` (`factory.go:17,104`), make each leaf wrap errors into `StatusError{StatusCode,RetryAfter}` (`oaistream/wrap.go:15`), centralize classification in `ClassifyModelError` (`modelerrors.go:581`), and own the budget in `fallbackExecutor` (`fallback.go:226-259`) with jitter (`backoff.go:25`) and `MaxRetryAfterWait=60s`. Wire `instrumentProvider` (`factory.go:122`) so CLIENT spans live on the leaf, not the executor.

- **For thinking/reasoning budgets:** Single YAML `thinking_budget: {tokens, effort}` fanning out per provider (docker-agent `gemini/client.go:463`, `openai/sampling_opts.go:1`) is proven clearer than crush's per-ID `reasoning_effort`/`thinking` switches; pair with the `openAIVendor` trusted bit pattern (`options.go:164`) so user YAML cannot spoof vendor-only fields.

- **For transport choices:** Do not use a global `transport: websocket` YAML escape hatch (`openai/client.go:865`). If both SSE and WebSocket are required, make the choice a capability negotiated at factory construction (like docker-agent's factory-set bit), not a per-request string that disables wrapping (`client.go:202`).

- **For terminals:** Preserve crush's detached-context and auto-close semantics for incomplete tool calls (`agent.go:1107-1154` autocloses with `Input="{}"` + synthetic `ToolResult{IsError:true}`) and filter orphaned pairs (`agent.go:1626-1687`); add docker-agent's placeholder injection for orphaned function_call (`openai/client.go:1080`) so the next request validates.

- **Choosing retry knobs:** Default to `200ms·2^n` ±10% capped 2s/60s (docker-agent) over `5s·2^n` with no jitter (crush) for agent-loop latency; expose per-agent `retries` and `cooldown` (docker-agent `modelerrors.go:72,76`) but also expose per-provider ceilings so a 3-model chain cannot implicitly attempt 9 times without intent.

## Practical Tips

1. Paste the neutral contract on day one: `Provider.CreateChatCompletionStream(ctx, []chat.Message, []tools.Tool) (chat.MessageStream, error)` (`provider.go:38`) and `chat.MessageStreamResponse{Choices[].Delta, Usage, FinishReason}` (`chat.go:147`). Put SDK imports only in `pkg/model/provider/*` leaf files. Forbid `openai-go`/`anthropic` imports outside the provider package with a lint rule — both sources leak only via `provider_opts`.

2. Generate a registry, not a switch. `Registry.NewWithModels` + `ProviderFactory` (`factory.go:17,104`) or crushed `providerRegistry` map avoids the `coordinator.go:360-622` growth pattern. Each entry registers its `ParseOptions` validator so misspelled knobs fail at construction, not at call time.

3. Wrap every SDK error into `StatusError{StatusCode, RetryAfter, Err}` (`modelerrors.go:25`) or `ProviderError{StatusCode, TransientError, RetryAfter}` (`fantasy/errors.go:63`). Include `parseRetryAfterHeader` (`modelerrors.go:549`) and `ErrorBodyMiddleware` (`oaistream/middleware.go:20`) so string bodies aren't lost before `gjson` extraction.

4. Centralize classification in one function (`ClassifyModelError` `modelerrors.go:581` / `isRetryableError` `fantasy/errors.go:71-97`) that lists status codes (`332` 500/502/503/504/529/408), network fragments, and stream-truncation (`modelerrors.go:428` `IsStreamTruncationError`) before the `invalid/quota` exclusion. Test it with table-driven `StatusError` mocks before adding fake servers.

5. Split budgets explicitly: transport retry (per-model `1+retries` + jitter, capped `Retry-After`), auth repair (single-shot `OnAuthRefresh` `retry.go:60-78` with detached 5m `WaitForTokenChange` `coordinator.go:1313-1318`), overflow/compaction (`ContextOverflowError` `modelerrors.go:118` not retried), validation repair (bounded prompt loop 1-2 reminders `structured_output.go:27`). Never burn transport retries on deterministic `400` schema errors.

6. Make validation repair tool-native: compile JSON schema at tool construction (`structuredoutput.New` `structuredoutput.go:40`), `Validate` with `gojsonschema` (`structuredoutput.go:128`), and on failure return `IsError` tool_result (`structured_output.go:155`) rather than throwing an execution error. Cap at `maxStructuredOutputReminders=2` then `ErrorCodeStructuredOutputFailed`. For native forwarding, enforce `additionalProperties:false` and required promotion (`openai/schema.go:20`).

7. Preserve partial+usage on late failure. Change `handleStream`'s error return (`streaming.go:186`) to `return streamResult{Content: fullContent.String(), Usage: messageUsage}, err` and fantasy's `OnRetry` path to keep first-attempt deltas in an audit buffer. Persist via `recordUsage` (`streaming.go:154`) even on truncated attempts so cost is attributable.

8. Enforce per-request deadlines. Wrap `CreateChatCompletionStream` with `context.WithTimeout` derived from model `contextLimit`/`SamplingConfig`; guard `defaultStreamIdleTimeout=5m` (`streaming.go:32`) is not a substitute for an overall request deadline. Clamp `Retry-After` to `min(exponentialDelay, 60s)` under all paths.

9. Add jitter and max-delay to any exponential backoff (`backoff.go:25,42` ±10% is sufficient) and cap `Retry-After` HTTP-date parsing (`fantasy/retry.go:48-53` needs the same 60s ceiling docker-agent applies at `fallback.go:438`). Without it, thundering herd on multi-agent retries and far-future date stall are inevitable.

10. Instrument cost branches behind the neutral `Usage` (`agent.go:1874-1904` `openrouterCost`/`extractHyperCredits` reading `ProviderMetadata["openrouter"/"openai"]`) but gate `tel.RecordTokenUsage`/`eventTokensUsed` on non-estimated data (`agent.go:1906-1922`, `streaming.go:154` only on success). Expose `EstimatedUsage` in session state so downstream budgets don't silently underbill.

## Anti-Patterns / Caution Signs

- **Provider switch that grows per vendor ID** (`internal/agent/coordinator.go:414-608` reasoning-effort branches per `catwalk.InferenceProviderIoNet/MiniMax/...` + `coordinator.go:891-1090` seven builders). Smell: adding one model requires editing the coordinator. Fix: registry map of `Type → (parse, build, adapt)` at startup.

- **Untyped `provider_opts map[string]any` with silent ignores** (`pkg/model/provider/options/options.go:12`, `GetProviderOptBool` returning `false` on typo). If `provider_opts` keys are not validated and tested, misspelled sampling knobs silently degrade quality.

- **Global `DefaultRetryOptions` with no jitter/deadline** (`fantasy/retry.go:88-94` `MaxRetries:3, InitialDelay:5s, BackoffFactor:2.0`). 35s tail on a blip, thundering herd, and `Retry-After: 60` stall are all consequences of the same missing discipline.

- **Auth refresh that republishes only inside the TUI** (`aws_sso_refresh.go:45-90` returns `errNoInteractiveAuth` when `notify==nil`; headless loses the actionable `aws sso login` hint). If refresh requires UI, make headless failure surface a typed `AuthError` with next-step text, not raw 401.

- **Post-refresh `UpdateModels` failure masking credential success** (`fantasy/retry.go:72-74`, `coordinator.go:1365` original 401 surfaced despite refreshed token due to catalog outage). Refresh and model reload must be separately observable; do not conflate their errors.

- **Discarding partial/usage on truncation** (`pkg/runtime/streaming.go:186` empty return; `fallback.go:338` no persistence). If `fullContent` is already emitted via `events.Emit(AgentChoice)` (`streaming.go:326`) but not returned, UI and transcript diverge — assert they converge in a fake-server truncation test.

- **Bridging tool/structured-output with nondurable repair** (`sanitizeToolInput` `agent.go:2272` silently replaces with `{}` + `slog.Warn(input_len)`). If malformed tool input is swallowed without recording the original body at debug level, postmortem is impossible.

- **`copy`-down lossy buffers upstream of a durable log** (docker-agent's `eventLog` correctly sits behind throttling, but the pattern warns: if any lossy fan-out sits upstream of the replay log, dropped tokens never reach sequencing).

- **No fake-server tests for wire failures.** Both sources have zero `httptest` coverage for malformed SSE frames/incomplete bodies/rate-limit/cancellation at the provider boundary — every retry claim is proven only via `StatusError` mocks. The next incident will be a frame-corruption that the taxonomy mishandles.

- No preservation of token usage or partial output alongside a late-stream error (docker-agent discards `fullContent`/`messageUsage` on `Recv` error; crush preserves partial only under terminal `FinishReasonError`, not per-retry for audit).

## Per-Source Notes

**crush (5/10) — Delegated neutrality over correctness where it counts.** The strongest takeaway is the two-layer retry shape: fantasy's exponential header-aware backoff plus crush's content-reset + credential-refresh adapter (`internal/agent/agent.go:931-941`, `coordinator.go:1349-1358`) cleanly separates transient retry from interactive auth without duplicating countdown logic, and detached contexts (`agent.go:750-755`, `1097-1100`) show end-to-end thinking about cancel not dropping terminal. The honest cost is that the "neutral" boundary is neutral only at the call site — the coordinator still carries vendor detail for every new provider, policy is untunable globals, structured output is unbuilt, and usage estimation is a fixed `(len+3)/4` (`usage_fallback.go:171-176`) that the `EstimatedUsage` flag only labels, not corrects.

**docker-agent (6/10) — Owned neutrality with policy and fallback.** Best available template for Aren's retry vocabulary: `StatusError` neutral wrapper (`modelerrors.go:25`), `ClassifyModelError` with 429 isolation vs 5xx retryability vs overflow identification (`modelerrors.go:332,587,593`), `backoff.Calculate` jitter (`backoff.go:25`), per-model `1+retries` loops plus cross-model `buildModelChain` with `DefaultCooldown=1m` pinning (`fallback.go:74,172`), and single-lock overflow retry via `CountTokens` (`anthropic/retry.go:24`). Structured-output dual path with `__structured_output__` validates with real schemas (`structuredoutput.go:40-128`) and bounded reminder (`structured_output.go:27-102`) is the only Phase 5-ready example in the study. The offsetting debts are fragmentation (escape hatches `provider_opts`/`transport`/`operationName` remain untyped), discard-on-error stream handling (`streaming.go:186`), and, like crush, no per-request deadline and no wire-level fake-server verification.
