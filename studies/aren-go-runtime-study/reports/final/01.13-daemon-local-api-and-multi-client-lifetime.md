## Executive Summary

All three sources are long-lived Go daemons that own accepted work after the submitting client exits, but they implement the dimension's loopback, workspace, detach, and multi-client guarantees at very different depths. nats-server (6/10) and nomad (8/10) both satisfy "client exit does not kill work": nats-server via a single `Server` owning `StoreDir`-backed JetStream streams/consumers (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:2258`, `studies/aren-go-runtime-study/sources/nats-server/server/filestore.go:438`) and durable names, nomad via Raft-committed `Job`/`Allocation` in `state.StateStore` (`studies/aren-go-runtime-study/sources/nomad/nomad/fsm.go:1036`, `studies/aren-go-runtime-study/sources/nomad/nomad/job_endpoint.go:990`) scheduled by server workers. Ollama (5/10) satisfies it only half: the `Scheduler` and loaded `llm.LlamaServer` runners resident via `refCount+expireTimer` (`studies/aren-go-runtime-study/sources/ollama/server/sched.go:393`) outlive any client, but the accepted generation itself is `c.Request.Context()`-bound (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:466`) and is lost on disconnect — there is no durable run queue.

Convergence: every production daemon separates the stable wire contract from Go internals, blocks on its own lifecycle (`WaitForShutdown` at `studies/aren-go-runtime-study/sources/nats-server/server/server.go:2769`, `Agent.Leave+Shutdown` at `studies/aren-go-runtime-study/sources/nomad/command/agent/agent.go:1493`, `server.Serve+Scheduler.Run` at `studies/aren-go-runtime-study/sources/ollama/server/routes.go:1949`), exposes multi-client inventory over the wire without shared memory (durable `$JS.API.*` subjects, HTTP `X-Nomad-Index`/event stream `?index=`, `GET /api/ps`/`/api/tags`), and implements whole-server graceful drain. No source uses a Unix-domain socket with `SO_PEERCRED` as primary loopback; all rely on TCP+token/mTLS/host filtering.

Divergence defines Aren's design space: nats-server has no run handle, no per-run workspace, no stream reconnect; nomad has cursor-index blocking queries and hijacked ndjson streams with `?index=N` reconnect and `X-Nomad-Token`+mTLS auth but logical `region`/`namespace` not filesystem workspace; ollama has global `OLLAMA_MODELS` and `keep_alive` expiry with no auth on local routes and no second-client cancel. The gap is precisely Phases 14-15: only nomad demonstrates a complete detach/reconnect/status-recovery primitive verifiable by a second client; the other two require Aren to add a run-id handle, per-workspace directory, and offset-based stream resume on top of their inventory models.

## Core Thesis

**Daemon lifetime is durable-inventory ownership plus a first-class status cursor, not just a process that stays up.** The sources that survive production separate three concerns that are often conflated: *who owns durable state after submit*, *how a second client re-finds that state*, and *how that client resumes observation*.

Three archetypes emerge along that separation:

- **nats-server — Broker daemon with named durables.** Ownership is `Server` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:168`) holding `clients`, `accounts`, `jetStream` and `StoreDir` (`studies/aren-go-runtime-study/sources/nats-server/server/opts.go:483`); work is a named stream/consumer created via `$JS.API.STREAM.CREATE.*` (`studies/aren-go-runtime-study/sources/nats-server/server/jetstream_api.go:54`) persisted to `filestore.go`. Discovery is by name over TCP pub/sub; observation is by re-subscribing to the same durable or `HTTP GET /jsz|/connz` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:3046`). There is no issued `run_id`, no offset stream resume, no per-run workspace. Versioning is coarse `PROTO=1` + `JSApiLevel` in `INFO` (`studies/aren-go-runtime-study/sources/nats-server/server/const.go:75`, `studies/aren-go-runtime-study/sources/nats-server/server/server.go:138`). Drain is whole-node `lameDuckMode` with `LDM INFO` fan-out and staggered `closeConnection(ServerShutdown)` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:4446`). Strength: minimal wire (`INFO/CONNECT/PUB/SUB`+JSON) is trivially polyglot. Cost: every multi-client notion must be built as naming conventions on top of streams.

- **nomad — Cluster daemon with Raft-linearizable state and index-cursor API.** Ownership is `Agent{Server,Client}` (`studies/aren-go-runtime-study/sources/nomad/command/agent/agent.go:72`) with Raft FSM (`studies/aren-go-runtime-study/sources/nomad/nomad/fsm.go:1036`) and `StateStore`. Discovery is HTTP long-poll: `GET /v1/job/:id?index=&wait=` with `X-Nomad-Index`/`X-Nomad-KnownLeader` (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:880`, `studies/aren-go-runtime-study/sources/nomad/nomad/job_endpoint.go:1498`), plus hijacked ndjson event stream `GET /v1/event/stream?index=N&topic=Job&topic=Allocation` with 30s heartbeat and `?index=lastSeen` reconnect (`studies/aren-go-runtime-study/sources/nomad/command/agent/event_endpoint.go:46`, `studies/aren-go-runtime-study/sources/nomad/nomad/event_endpoint.go:32`). Scoping is explicit `?region=&namespace=` (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:978`) not a directory; auth is `X-Nomad-Token`/`Bearer`+mTLS (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:1030`). Drain is cooperative `Agent.Leave→server.Leave/client.Leave` with `gracefulTimeout 5s+Drain.Deadline` (`studies/aren-go-runtime-study/sources/nomad/command/agent/command.go:1037`). Strength: any holder of a valid token can poll or stream the same durable evaluation without shared memory, and reconnect is idempotent via index. Cost: network-reachable by default, no `SO_PEERCRED`, no filesystem workspace lock.

- **ollama — Single-node residency daemon with request-scoped work.** Ownership is one `Server+Scheduler+http.Server` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:1983`) and a single `Scheduler` map `loaded[modelPath]*runnerRef` with `refCount`/`expireTimer` (`studies/aren-go-runtime-study/sources/ollama/server/sched.go:60`). Work (`Generate`/`Chat`) is synchronous to the HTTP request context (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:650`) and lost on cancel; only model residency persists per `keep_alive` (`studies/aren-go-runtime-study/sources/ollama/api/types.go:94`). Inventory is global `OLLAMA_MODELS`/`~/.ollama/models` (`studies/aren-go-runtime-study/sources/ollama/envconfig/config.go:112`). Second-client observability is `GET /api/ps`/`GET /api/tags` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:2271`) but not the inflight token stream — NDJSON `bufio.Scanner` splits on `\n` with no `offset` or session token (`studies/aren-go-runtime-study/sources/ollama/api/client.go:217`). Drain is immediate `srvr.Close()+unloadAllRunners()` on `SIGINT/SIGTERM` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:2022`), with a 5s desktop `stop(proc)` wrapper only in `app/server/server.go:146`. Strength: trivially thin `POST /api/generate|chat` JSON+ndjson contract; all clients benefit from warm runners. Cost: no durable run handle, no per-workspace, no second-client cancel beyond `keep_alive:0`.

Aren Phase 14-15 is nomad-shaped in lifetime requirements but ollama-shaped in deployment (single-Host daemon) — it needs nomad's cursor+token auth+second-client cancel, plus a filesystem workspace and `run_id` with offset resume that none of these sources provide completely.

## Approach Models

**Model A — Named durable over TCP pub/sub (nats-server).** `main.go:97-134` builds `Server`, `server/service.go:20` `Run` calls `s.Start()` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:2258`) and `main.go:133` blocks on `WaitForShutdown()` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:2769`). `AcceptLoop` binds `Opts.Host:Port` via `natsListen("tcp",hp)` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:2773`) with optional TLS/PROXY. Auth is per-connection `CONNECT {user,pass,auth_token,jwt,nkey}` vs `Info.AuthRequired/TLSRequired` (`studies/aren-go-runtime-study/sources/nats-server/server/auth.go:322`). Workspace is global `StoreDir` (`studies/aren-go-runtime-study/sources/nats-server/server/opts.go:483`) plus `Accounts` map (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:168`) and `ClientInfo.Account` header (`studies/aren-go-runtime-study/sources/nats-server/server/jetstream_api.go:1270`). Durables are addressed by subject `$JS.API.*` (`studies/aren-go-runtime-study/sources/nats-server/server/jetstream_api.go:38`) and persist in `filestore.go`. No UDS, no `work_dir` param, no `attach/stream` RPC (`studies/aren-go-runtime-study/sources/nats-server/server/jetstream_api.go:158` is pull `NEXT`, not run log). Best where inventory is a shared stream, not a per-run dir.

**Model B — HTTP-JSON state store with index cursors and hijacked streams (nomad).** `command/agent/command.go:818` `Command.Run→readConfig→NewAgent→NewHTTPServers→handleSignals` (`studies/aren-go-runtime-study/sources/nomad/command/agent/command.go:1421`) starts HTTP on `config.normalizedAddrs.HTTP` (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:117`) optionally TLS-wrapped (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:143`). Public contract is HTTP JSON (`command/agent/http.go:404` route table) translating to internal yamux/msgpack RPC over `net.Pipe` hijack (`studies/aren-go-runtime-study/sources/nomad/command/agent/event_endpoint.go:92`); thin clients never speak msgpack. Auth via `parseToken` (`X-Nomad-Token`/`Authorization: Bearer`) (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:1030`) with ACL `ResolveToken`→`ResolveACL` and `authMiddleware` for Task API (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:372`, `studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:1198`). Scoping is `parseRegion`/`parseNamespace` → `QueryOptions{Region,Namespace}` (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:978`). Status is `MinQueryIndex`/`MaxQueryTime` blocking query (`studies/aren-go-runtime-study/sources/nomad/nomad/job_endpoint.go:1498`) with `X-Nomad-Index` response headers (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:880`), stream is `SubscribeRequest{Index,Topics,Namespaces}`→ndjson hijack with `deadlineWriter` 40s and `ioutils.NewWriteFlusher` (`studies/aren-go-runtime-study/sources/nomad/command/agent/event_endpoint.go:26`, `studies/aren-go-runtime-study/sources/nomad/api/event_stream.go:184`). Second-client cancel is `DELETE /v1/job/:id`/`POST /v1/node/:id/drain` (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:404`). Shutdown is `terminateGracefully` `gracefulTimeout 5s+Drain.Deadline` with `sync.Once` `gracefulCh` and second-signal forced exit (`studies/aren-go-runtime-study/sources/nomad/command/agent/command.go:1037`). Best where leader failover and index-linearizable reconnect matter.

**Model C — Residency scheduler over loopback TCP with request-scoped streams (ollama).** `cmd/cmd.go:2015` `RunServer` does `net.Listen("tcp",envconfig.Host().Host)` (`studies/aren-go-runtime-study/sources/ollama/envconfig/config.go:22` default `127.0.0.1:11434`) then `server/routes.go:1949` `Serve` `InitScheduler(schedCtx)+sched.Run(schedCtx)+http.Server.Serve(ln)` (`studies/aren-go-runtime-study/sources/ollama/server/sched.go:60`, `studies/aren-go-runtime-study/sources/ollama/server/routes.go:2004`). `GenerateRoutes` installs only `cors+allowedHostsMiddleware` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:1871`, `studies/aren-go-runtime-study/sources/ollama/server/routes.go:1803` loopback/private/hostname check, bypass when `addr` non-loopback `server/routes.go:1811`). Version is `version.Version="0.0.0"` plus `GET /api/version` and `User-Agent: ollama/<version>` with warn-only mismatch (`studies/aren-go-runtime-study/sources/ollama/version/version.go:3`, `studies/aren-go-runtime-study/sources/ollama/cmd/cmd.go:2095`). Drain is `signal.Notify(SIGINT,SIGTERM)→srvr.Close()+schedDone()+unloadAllRunners()` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:2022`). Best where model warmth, not job durability, is the product.

Why models diverge: product shape (broker needing clustering `routes/gateways/leaf` all TCP → TCP-only makes sense at `studies/aren-go-runtime-study/sources/nats-server/server/server.go:2870`; cluster scheduler needing multi-host Raft/Serf/yamux → HTTP-over-msgpack hijack is cheaper than UDS; single-host inference needing `curl` interop → loopback TCP is least friction), isolation model (account/namespace vs filesystem dir), and operation envelope (nats `LDM 2m`, nomad `Drain.Deadline` per-node, ollama `5m keep_alive`).

## Pattern Catalog

### P1. Durable-inventory ownership that survives the submitter — named durables vs Raft jobs vs residency leases

- **Problem:** Phase 14 requires accepted work to continue after the submitting client exits; tying lifecycle to a TCP connection or request context violates it.
- **Demonstrated by:** All three, differently. nats-server: stream/consumer created via `$JS.API.STREAM.CREATE.*` (`studies/aren-go-runtime-study/sources/nats-server/server/jetstream_api.go:54`) persists in `StoreDir` (`studies/aren-go-runtime-study/sources/nats-server/server/filestore.go:438`) after publisher disconnect; `removeClient` only removes `*client` from `s.clients` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:3726`), not streams. Nomad: `Job.Register` Raft-committed via `job_endpoint.go:990` into `state.StateStore`, scheduling outlives CLI (`studies/aren-go-runtime-study/sources/nomad/nomad/fsm.go:1036`); `Agent` decouples Server from Client (`studies/aren-go-runtime-study/sources/nomad/command/agent/agent.go:72`). Ollama: `Scheduler` `loaded map + refCount + expireTimer` (`studies/aren-go-runtime-study/sources/ollama/server/sched.go:393`) and `getRunner` keeps runner after `pending.ctx.Done()` (`studies/aren-go-runtime-study/sources/ollama/server/sched.go:486`), but `scheduleRunner(c.Request.Context())` ties generation to request ctx (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:466`).
- **Why it works:** durable inventory is keyed by name/index not by connection fd; the daemon is the owner and clients are observers.
- **When to copy:** always for Phases 14-15; choose named durables when inventory is a log (nats), Raft-linearizable state when multi-server failover is needed (nomad), residency lease when value is warm model not per-run output (ollama).
- **When overkill/risky:** for pure request/response inference with no post-disconnect status, ollama's request-scoped work is correct — adding a run queue only delays TTFB.
- **Evidence:** `main.go:129` `WaitForShutdown`, `server/server.go:2579` `Shutdown`, `command/agent/agent.go:149` `NewAgent`, `server/sched.go:225` `processPending`.

### P2. Thin HTTP or text wire that hides Go types — the stable polyglot envelope

- **Problem:** thin non-Go clients must not need Go codegen or msgpack/yamux; server internals (`Server`, `client`, `jetStream`, `RaftNode`, `runnerRef`) must be free to evolve.
- **Demonstrated by:** nats-server: `INFO/CONNECT/PUB/SUB/PING/PONG/MSG/HMSG` text framing + JSON `ApiResponse{type,error}` (`studies/aren-go-runtime-study/sources/nats-server/server/client.go:82`, `studies/aren-go-runtime-study/sources/nats-server/server/jetstream_api.go:410`) plus `GET /varz|/connz|/jsz` HTTP monitoring (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:3014`). Nomad: public HTTP JSON + headers (`X-Nomad-Index`, `X-Nomad-Token`, ndjson) (`studies/aren-go-runtime-study/sources/nomad/api/api.go:675`, `studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:880`) hiding internal msgpack/yamux streaming RPC (`studies/aren-go-runtime-study/sources/nomad/command/agent/event_endpoint.go:92`, `studies/aren-go-runtime-study/sources/nomad/nomad/event_endpoint.go:36`). Ollama: `POST /api/generate|chat` `GenerateRequest{model,prompt,stream,keep_alive}` → ndjson `GenerateResponse{response,done,done_reason}` (`studies/aren-go-runtime-study/sources/ollama/api/types.go:62`, `studies/aren-go-runtime-study/sources/ollama/server/routes.go:2097`) plus `GET /api/tags|/ps|/version` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:1877`).
- **Why it works:** `newRequest`/`doRequest`+JSON+headers is implementable in any language with `http.Client` or `curl+jq`; Go-specific codec stays behind the hijack.
- **When to copy:** always — define the wire as `{method,url,params,token,json body,ndjson stream}` and test it with `curl`, not just the Go client.
- **Overkill:** for in-process-only embedding, `net.Pipe` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:2873`, `studies/aren-go-runtime-study/sources/nomad/command/agent/agent.go:1388` `bufconndialer`) is cheaper than HTTP.
- **Evidence:** `api/api.go:816` `newRequest`, `api/api.go:220` `Events` ndjson decode, `server/client.go:2454` `CONNECT` protocol check.

### P3. Index-cursor poll and stream reconnect — `?index=N&wait=` long-poll and `?index=lastSeen` stream resume

- **Problem:** second client must find the same run without shared memory and resume observation after disconnect without missing events.
- **Demonstrated by:** Nomad most completely — blocking query `GET /v1/job/:id/allocations?index=I&wait=60s` with server `X-Nomad-Index`/`X-Nomad-KnownLeader` (`studies/aren-go-runtime-study/sources/nomad/nomad/job_endpoint.go:1498`, `studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:924`) and event stream `GET /v1/event/stream?index=N&topic=Job&topic=Allocation` hijacked to ndjson with 30s heartbeat and `deadlineWriter` 40s (`studies/aren-go-runtime-study/sources/nomad/command/agent/event_endpoint.go:26`, `studies/aren-go-runtime-study/sources/nomad/nomad/event_endpoint.go:89`, `studies/aren-go-runtime-study/sources/nomad/api/event_stream.go:184`). nats-server analog: durable consumer `JSApiRequestNextT $JS.API.CONSUMER.MSG.NEXT.*` pull and `$JS.API.CONSUMER.INFO` naming (`studies/aren-go-runtime-study/sources/nats-server/server/jetstream_api.go:135`, `studies/aren-go-runtime-study/sources/nats-server/server/jetstream_api.go:158`) and HTTP `/jsz` polling — but no `offset` byte-stream resume. Ollama has no cursor — `ch chan any` + `c.Stream` with `bufio.Scanner` on `response.Body` (`studies/aren-go-runtime-study/sources/ollama/api/client.go:217`) and no `Range`/`after` param; partial `GenerateResponse{Context}` is lost on `Body.Close`.
- **Why it works:** monotonic `Index` (Raft `ModifyIndex`) is a linearizable cursor; re-issuing `?index=lastSeen` is idempotent and heartbeat distinguishes quiet from dead.
- **When to copy:** for Aren, use nomad's shape verbatim: `PUT /v1/runs→{run_id}` then `GET /v1/runs/:id?index=` plus `GET /v1/runs/:id/stream?after=offset` with heartbeat and typed error envelope `{"Err":…}` (`studies/aren-go-runtime-study/sources/nomad/nomad/event_endpoint.go:162`); pair with `X-Aren-Index` header.
- **Risky:** JetStream message-granular pull (`JSApiMsgGet` `studies/aren-go-runtime-study/sources/nats-server/server/jetstream_api.go:100`) and ollama byte-copied NDJSON both fail to resume mid-token; an offset journal per-run is needed.
- **Evidence:** `command/agent/http.go:978` region/namespace threading, `api/event_stream.go:228` empty heartbeat filtered, `server/routes.go:2097` NDJSON framing.

### P4. Explicit tenant/workspace scoping on every request — region/namespace/account vs `StoreDir`/`OLLAMA_MODELS`

- **Problem:** multi-client shared inventory needs isolation so one client's `job run` or `ollama pull` cannot pollute another's view and so cancellation is RBAC-scoped.
- **Demonstrated by:** Nomad: `?region=&namespace=` on every request, `QueryOptions{Region,Namespace}` + `WriteRequest{IdempotencyToken}` (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:1071`, `studies/aren-go-runtime-study/sources/nomad/api/api.go:58`) plus `*` expansion via `NamespaceNames()` and `AllowNsOp` ACL gating (`studies/aren-go-runtime-study/sources/nomad/nomad/event_endpoint.go:264`). nats-server: single `StoreDir`/`JetStreamConfig.StoreDir` (`studies/aren-go-runtime-study/sources/nomad/server/opts.go:483` / `studies/aren-go-runtime-study/sources/nats-server/server/opts.go:483`) keyed by `Accounts` map (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:195`) and `ClientInfo.Account` (`studies/aren-go-runtime-study/sources/nats-server/server/jetstream_api.go:1270`). Ollama: one global `Models()` `OLLAMA_MODELS or ~/.ollama/models` (`studies/aren-go-runtime-study/sources/ollama/envconfig/config.go:112`) with no per-request scoping (`api/types.go:62` has no `workspace` field).
- **Why it works/ fails:** query-param tenancy is cheap to implement for polyglots and composes with ACL; filesystem `StoreDir` gives persistence but not per-run lifecycle or `flock` isolation.
- **When to copy:** Aren Phase 14 should be logical tenancy like nomad (`?workspace=` or `X-Aren-Workspace` header hashing to `state_dir/<hash>/workspace.lock` with `flock`) *plus* a physical directory per workspace distinct from global blob store — neither source does both.
- **Overkill:** global blob store (ollama) suffices when there is only one tenant; adding per-workspace adds GC and quota complexity.
- **Evidence:** `server/filestore.go:61` `StoreDir` keying, `command/agent/http.go:996` `parseIdempotencyToken`.

### P5. Authentication as bearer-token/mTLS header, distinct from transport loopback proof

- **Problem:** local callers must be authenticated for shared inventory, but "local" cannot be inferred from `127.0.0.1` alone.
- **Demonstrated by:** nats-server: `Info.AuthRequired/TLSRequired` set from `Users/Nkeys/Username` (`studies/aren-go-runtime-study/sources/nats-server/server/auth.go:322`) and client `CONNECT {user,pass,auth_token,jwt,nkey,protocol}` (`studies/aren-go-runtime-study/sources/nats-server/server/client.go:2454`) — no UDS `SO_PEERCRED`; monitoring HTTP often unauthenticated without fronting. Nomad: `parseToken` `X-Nomad-Token`/`Authorization: Bearer` (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:1030`) → `Server.Authenticate→ResolveACL` (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:372`) plus optional mTLS `VerifyHTTPSClient` (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:143`) and `authMiddleware` for Task API (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:1198`); `unix://` parsed in `api/api.go:301` but server has no `Listener("unix",…)` for HTTP. Aren should offer both: `X-Aren-Token`+mTLS for cross-host and optional `unix://run/aren.sock` (`0700`+bearer file) with peer-cred check extending `parseToken`.
- **Copy:** bearer header + `IdempotencyToken` for idempotency, and treat `allowedHostsMiddleware` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:1803`) as defense-in-depth not auth.
- **Evidence:** `helper/tlsutil` TLS config, `api/api.go:338` default `127.0.0.1:4646`.

### P6. Signal-mapped graceful drain, leave, and forced shutdown with deadline — not just `Close()`

- **Problem:** daemon upgrade/restart must not strand work, corrupt inventory, or orphan Raft membership; second signal should force exit.
- **Demonstrated by:** nats-server: `signal.go:37` `handleSignals` subscribing `SIGINT/SIGTERM/SIGUSR1/SIGUSR2/SIGHUP` mapping to `Shutdown/Reload/ReOpenLogFile/lameDuckMode` with `Command`→`Signal` mapping (`studies/aren-go-runtime-study/sources/nats-server/server/const.go:22`, `studies/aren-go-runtime-study/sources/nats-server/server/signal.go:93`); `lameDuckMode` closes `listener`, transfers Raft leaders, sends `LDM INFO` filtered `ClientConnectURLs`, staggers `closeConnection(ServerShutdown)` over `DEFAULT_LAME_DUCK_DURATION 2m - GRACE_PERIOD 10s` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:4446`, `studies/aren-go-runtime-study/sources/nats-server/server/const.go:196`). Nomad: `handleSignals` `SIGINT/SIGTERM/SIGHUP/SIGPIPE` with `LeaveOnInt/LeaveOnTerm` (`studies/aren-go-runtime-study/sources/nomad/command/agent/command.go:1092`), `terminateGracefully` `5s+Drain.Deadline` with async `Agent.Leave()` (`studies/aren-go-runtime-study/sources/nomad/command/agent/agent.go:1493`, `studies/aren-go-runtime-study/sources/nomad/nomad/server.go:744`) running `sync.Once` `gracefulCh`+`Timer(timeout)` and second signal abandoning drain (`studies/aren-go-runtime-study/sources/nomad/command/agent/command.go:1069`), plus `SIGHUP→handleReload→Reload+reloadHTTPServer` (`studies/aren-go-runtime-study/sources/nomad/command/agent/command.go:1182`) without dropping Raft. Ollama: `signal.Notify(SIGINT,SIGTERM)→srvr.Close()+schedDone()+unloadAllRunners()` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:2022`) and app `Server.Run` `stop(proc)` `SIGTERM→5s→Kill` with `restartDelay 1s` (`studies/aren-go-runtime-study/sources/ollama/app/server/server.go:111`).
- **Why it works:** drain is whole-server, cooperative, and deadline-bounded; forced shutdown is an explicit second-signal path, not a timeout bug.
- **When to copy:** for Aren, combine nomad's `Leave+Shutdown` ordering (Serf leave, Raft `RemoveServer` at `studies/aren-go-runtime-study/sources/nomad/nomad/server.go:814`) with nats's staggered close and ollama-desktop's restart supervision; add `SIGUSR`-like reopen/reload for cert rotation.
- **Risky:** bare `srvr.Close()` (immediate) like ollama CLI without `Shutdown(context)` races `llm.LlamaServer.Close()` vs expiry timers (`studies/aren-go-runtime-study/sources/ollama/server/sched.go:1367`).
- **Evidence:** `server/server.go:2579` `Shutdown` CAS `shutdown` atomic and `close(shutdownComplete)`, `command/agent/agent.go:1509` `Shutdown` close ordering, `app/server/server.go:276` `pidFile`.

### P7. In-process loopback transport that preserves the wire contract — `net.Pipe`/`bufconndialer` as the UDS substitute

- **Problem:** tests, embedded agents, and loopback-only callers should speak the same contract without binding a public port.
- **Demonstrated by:** nats-server: `InProcessConn() { net.Pipe()→createClientInProcess }` respecting `DontListen` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:2873`) — same `INFO/CONNECT` handshake over pipe. Ollama: no in-process listener — `OLLAMA_HOST=0.0.0.0` exposure disables `allowedHostsMiddleware` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:1811`) instead of switching transport.
- **Why it works:** contract is enforced (auth, headers, JSON) even without TCP; embedding and zero-config tests use the same path as `curl`.
- **When to copy:** for Aren, expose both `tcp 127.0.0.1:<port>` and `unix:///run/aren.sock` listeners via the same `NewHTTPServers` helper (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:117`) and a `builtinListener` for agent-internal HTTP, so thin clients choose `OLLAMA_HOST`-like env `AREN_ADDR` (`studies/aren-go-runtime-study/sources/nomad/api/api.go:338`, `studies/aren-go-runtime-study/sources/ollama/envconfig/config.go:22`) without changing framing.
- **Overkill:** if daemon is always remote-reachable, in-process pipe adds complexity.
- **Evidence:** `command/agent/http.go:228` `taskAPIServer` bootstrap, `server/service.go:20` embedding.

## Key Differences

**Durability primitive.** nats-server streams/consumers: file-backed `filestore.go` keyed by account/stream/consumer; any TCP client can `SUB` the same subject after creator exits — no handle. Nomad jobs/allocs/evals: Raft FSM `StateStore` with `X-Nomad-Index` cursor; any HTTP client with token can `GET /v1/job/:id?index=` or `GET /v1/event/stream?index=` to re-observe — cursor-based, not name-based. Ollama models/runners: in-memory `loaded` + `keep_alive` TTL; any HTTP client can `GET /api/ps` to see residency but not the inflight NDJSON — warm-runner reuse via `getRunner !needsReload` (`studies/aren-go-runtime-study/sources/ollama/server/sched.go:201`). The durable primitive predicts the multi-client question's answer: name, index, or warm slot.

**Transport hardening.** All three default to TCP loopback (`0.0.0.0:4222` `studies/aren-go-runtime-study/sources/nats-server/server/const.go:78`, `127.0.0.1:4646` `studies/aren-go-runtime-study/sources/nomad/api/api.go:338`, `127.0.0.1:11434` `studies/aren-go-runtime-study/sources/ollama/envconfig/config.go:39`) with host/header filtering, not UDS+`SO_PEERCRED`. nats-server trusts account/JWT on every `CONNECT`; nomad trusts `X-Nomad-Token`+optional mTLS and per-IP `connLimit→429` (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:317`); ollama trusts `allowedHostsMiddleware` loopback/private/`isLocalIP` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:1775`) and optional unsigned `OLLAMA_AUTH`. None provide kernel peer-credential local proof — a shared gap that Aren should close.

**Stream reconnect capability.** Nomad: full — poll and stream both take `?index=` and server fans out from `publisher.Subscribe` with `atomic.Value` ACL refresh on timer (`studies/aren-go-runtime-study/sources/nomad/nomad/event_endpoint.go:73`) and handles hijack-unavailable fallback via `ioutils.NewWriteFlusher(resp)` (`studies/aren-go-runtime-study/sources/nomad/command/agent/event_endpoint.go:147`). nats-server: partial — HTTP monitor is poll-only, JetStream pull is message-granular (`JSApiMsgGet` `studies/aren-go-runtime-study/sources/nats-server/server/jetstream_api.go:100`), not run-log byte offset; no `stream_id`/`after` handle. Ollama: none — `streamResponse` bound to `http.ResponseWriter` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:2099`) with `maxBufferSize 8MiB` scanner (`studies/aren-go-runtime-study/sources/ollama/api/client.go:168`); disconnect → `Body.Close` → channel close → tokens lost.

**Cancellation from second client.** nats-server: none first-class as run cancel — `LDMClientByID`/`DisconnectClientByID` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:4760`) are privileged not wire-exposed; semantic cancel is `UNSUB`/`CONSUMER.DELETE`. Nomad: explicit — `DELETE /v1/job/:id` (deregister), `POST /v1/job/:id/gc`, `POST /v1/node/:id/drain`, `ClientAlloc` stop/signal (`studies/aren-go-runtime-study/sources/nomad/command/agent/node_endpoint.go:138`, `studies/aren-go-runtime-study/sources/nomad/nomad/node_endpoint.go:963`), ACL-gated. Ollama: weak — no cancel endpoint; `POST` with `keep_alive:0` expires runner (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:403`) and `DELETE /api/delete` removes manifest (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:1902`); only the owning client cancels via `context.WithCancel+SIGINT` (`studies/aren-go-runtime-study/sources/ollama/cmd/cmd.go:1770`).

**Versioning/compatibility.** nats-server: coarse `PROTO=1` in `CONNECT` (`studies/aren-go-runtime-study/sources/nats-server/server/client.go:82`) plus `INFO.JSApiLevel` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:138`) and `Nats-Required-Api-Level` header (`studies/aren-go-runtime-study/sources/nats-server/server/jetstream_api.go:352`) — minimal negotiation, fail-closed on `protocol!=0|1` (`studies/aren-go-runtime-study/sources/nats-server/server/client.go:2454`). Nomad: no per-request `ApiVersion`; `/v1/` prefix is stable (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:404`); pagination `per_page/next_token/filter/reverse` is additive (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:1089`). Ollama: `version.Version="0.0.0"` (`studies/aren-go-runtime-study/sources/ollama/version/version.go:3`) at `GET /api/version` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:1879`) and `User-Agent` with warn-only `versionHandler` (`studies/aren-go-runtime-study/sources/ollama/cmd/cmd.go:2095`). None give thin clients feature-detection beyond string compare.

**Shutdown semantics.** nats-server `Shutdown()` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:2579`) is CAS-idempotent, closes all listeners, waits `done+grWG`; signals are not queued and `SIGTERM` during `ldm` is ignored (`studies/aren-go-runtime-study/sources/nats-server/server/signal.go:66`). Nomad `Agent.Shutdown` closes `taskAPIServer` then `client.Shutdown`→`server.Shutdown`→`shutdownCh` (`studies/aren-go-runtime-study/sources/nomad/command/agent/agent.go:1509`) with workers `workerShutdownGracePeriod 5s` (`studies/aren-go-runtime-study/sources/nomad/nomad/server.go:94`). Ollama CLI path is raciest — `srvr.Close()` not `Shutdown` with timeout (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:2026`) — while desktop `app/server/server.go:276` adds supervision.

## Tradeoffs

**TCP-everywhere universal reach vs loopback-hardened UDS.** Benefit — TCP `127.0.0.1→0.0.0.0` switch via `Host()`/`ConnectableHost` (`studies/aren-go-runtime-study/sources/ollama/envconfig/config.go:62`) and nomad's `normalizedAddrs.HTTP` plus `api.Client` `Address`/`unix://` dial (`studies/aren-go-runtime-study/sources/nomad/api/api.go:301`) keep every language's `http.Client`/`curl` working and clustering (`routes/leaf/gateway`) simple. Cost — every source pays with weaker local-only proof (`allowedHostsMiddleware` hostname check at `studies/aren-go-runtime-study/sources/ollama/server/routes.go:1775` is spoofable via hosts file, monitoring `GET /varz` defaults unauthenticated). Best-fit: universal TCP for cross-host; add optional `unix://$HOME/.ollama/ollama.sock` `0700` + bearer file + `SO_PEERCRED` mapping to `X-Aren-Token` when `AREN_ADDR` is loopback — the future consideration common to all three reports. Alternative seen nowhere studied: exclusive UDS would break `0.0.0.0` container binds (`Dockerfile:318` `OLLAMA_HOST=0.0.0.0:11434`).

**Global `StoreDir`/`OLLAMA_MODELS`/`StateStore` vs per-run workspace directory.** Benefit — single tree enables zero-copy sharing and one `GC` story (`filestore.go:485`, `server/sched.go:110` `ModelPath/Digest` key, `nomad/state/state_store.go:*` map). Cost — no per-run env, `work_dir`, `flock`, output capture, or per-run GC signal; a single tenant can fill disk and affect all accounts (nats `jsLimits` quota `studies/aren-go-runtime-study/sources/nats-server/server/server.go:195` is soft). For Aren, global store for shared blobs plus `store_dir/<workspace_hash>/runs/<run_id>` with manifest+log is the synthesis; source analogues are `$G`/`$SYS` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:168`) and `region`/`namespace` sharding.

**Durable naming (nats) vs index cursor (nomad) vs residency TTL (ollama).** Durable naming is simple but forces clients to design namespace GC and duplicate handling; no `run_id` lease. Index cursor is linearizable (`X-Nomad-Index` + `?index=&wait=` `studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:924`) but requires Raft/metrics. Residency TTL (`keep_alive` `studies/aren-go-runtime-study/sources/ollama/api/types.go:94` → `sessionDuration` `studies/aren-go-runtime-study/sources/ollama/server/sched.go:32` → `expireTimer` `studies/aren-go-runtime-study/sources/ollama/server/sched.go:395`) shares liveness and last-writer-wins (`studies/aren-go-runtime-study/sources/ollama/server/sched.go:486` overwrites `sessionDuration`) — a short-lived script can unload a model an interactive chat still needs. For Aren's daemon capacity this predicts a need for run-scoped keep-alive not model-scoped.

**Whole-server drain vs per-run cancel.** Whole-server `lameDuckMode`/`terminateGracefully`/`srvr.Close+unloadAll` drains the node cleanly for upgrades with `LDMDuration 2m` batching hazard (`si=dur/numClients` `studies/aren-go-runtime-study/sources/nats-server/server/server.go:4511` storms) and second-signal abandonment (`studies/aren-go-runtime-study/sources/nomad/command/agent/command.go:1069`). Cost — no `Cancel(run_id)` or `Detach(handle)` RPC for a second client to kill one run; `keep_alive:0` / `UNSUB` are side-effects. Best-fit flips by resource: use whole-server drain for node upgrade; add per-run cancel for Phases 14-15 (nomad's `ClientAlloc` signal shape `studies/aren-go-runtime-study/sources/nomad/nomad/node_endpoint.go:963` is the closest wire analogue).

**Bearer token/mTLS vs always-auth.** Unauthenticated loopback matches dev ergonomics (`ollama run llama3.2` zero-config) and makes `curl http://127.0.0.1:11434/api/generate` work; hardened the same way fails multi-tenant. Nomad's `X-Nomad-Token` per-request solves tenancy at cost of a secret manager; nats-server JWT/nkey (`studies/aren-go-runtime-study/sources/nats-server/server/auth.go:322`) solves cockpit identity but not `GET /varz` without fronting. The tradeoff reported gap is consistent: auth is opt-in or per-subsystem, never unified as a stable loopback contract — Aren should document `Authorization: Bearer <X-Aren-Token>` on every route including streams.

## Decision Guide

Answer four questions from the dimension — use the sources as calibration tools, not as vendors to pick wholly.

1. **Must work outlive the HTTP/TCP connection?** No → ollama's request-scoped `ch chan any` + `c.Request.Context()` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:650`) is simplest and correctly ties cost to context — terminate on `ctx.Done()` and close `ch`. Yes → do not use a request-scoped context; issue a server-owned `run_id` (like nomad's `JobID`/`EvalID` `studies/aren-go-runtime-study/sources/nomad/nomad/job_endpoint.go:304`) durably committed (Raft or `filestore.go`-style WAL) and decoupled from `pending.ctx` by mapping `pending.ctx.Done→finishedReqCh` (`studies/aren-go-runtime-study/sources/ollama/server/sched.go:486`) only for abandon, not for success. The source contrast is explicit: `ats-server: No ephemeral consumer is the exception` vs `nomad: Yes via streaming RPC` vs `ollama: Partially` — only nomad survives assignment grading for "work outlives client".

2. **Must a second client resume observation without shared memory?** If just inventory (models, streams, allocs) → `GET /api/ps|/tags`, `$JS.API.* INFO`, `/v1/job/:id?index=` all suffice. If live token/log stream → only nomad's `?index=lastSeen` hijacked ndjson with cursor header (`studies/aren-go-runtime-study/sources/nomad/api/event_stream.go:184`) and heartbeat (`studies/aren-go-runtime-study/sources/nomad/command/agent/event_endpoint.go:26`) proves reconnect; nats `JSApiMsgGet` and ollama `bufio.Scanner` (`studies/aren-go-runtime-study/sources/ollama/api/client.go:217`) do not. Decision rule: if disconnect can outlast the client's `stream:false` aggregation memory, add explicit `GET /runs/:id/stream?after=offset` with `offset` from `GenerateResponse{Context}` or `X-Nomad-Index`-like header — do not reuse `$JS.API.CONSUMER.NAMES.*` as the stream.

3. **How are callers authenticated and workspaces isolated?** Single-user loopback dev → `allowedHostsMiddleware` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:1803`) + global `OLLAMA_MODELS` is cheapest but unauditable (any `local` process enumerates `GET /api/tags` at `studies/aren-go-runtime-study/sources/ollama/server/routes.go:1902`). Multi-client shared host / Phase 15 → `X-Aren-Token`/`X-Nomad-Token` (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:1032`) + `region`/`namespace`/`workspace` param (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:978`) + ACL `AllowNsOp` (`studies/aren-go-runtime-study/sources/nomad/nomad/event_endpoint.go:283`) gate every RPC including streams; check `exp` from token claims before each `jsonStream.Send` (`studies/aren-go-runtime-study/sources/nomad/nomad/event_endpoint.go:132`) so rotation doesn't kill existing streams. Add `unix://` + `SO_PEERCRED` only for the zero-config single-user niche — the per-source gaps all call for it but none implement it.

4. **What must a non-Go client implement — and what must it not?** Stable is: TCP connect → read `INFO` → `CONNECT {protocol}` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:108`, `studies/aren-go-runtime-study/sources/nats-server/server/client.go:82`), or HTTP `method+url+params+token+JSON body+ndjson stream` (`studies/aren-go-runtime-study/sources/nomad/api/api.go:675`, `studies/aren-go-runtime-study/sources/ollama/api/types.go:62`). Unstable is: `Server`, `client`, `Options`, `jetStream`, `RaftNode`, `Scheduling`, `runnerRef`, `LlmRequest`, `Scheduler` Go types, plus internal msgpack/yamux (`studies/aren-go-runtime-study/sources/nomad/command/agent/event_endpoint.go:92`). Decision rule: pick one framing and document it as the versioned contract — nats text framing + `$JS.API.*` JSON schemas, nomad `X-Nomad-Index` + ndjson `Events` envelope (`studies/aren-go-runtime-study/sources/nomad/api/event_stream.go:220`), or ollama `GenerateRequest/Response` types (`studies/aren-go-runtime-study/sources/ollama/api/types.go:518`) — and bump a single `PROTO`/`JSApiLevel`/`api_version` integer on breaking changes.

**When to borrow from each source:**
- From nats-server: `Run→Start→WaitForShutdown` embedding shape (`studies/aren-go-runtime-study/sources/nats-server/server/service.go:20`), `NoSigs` opt-out (`studies/aren-go-runtime-study/sources/nats-server/server/opts.go:426`), `delayedAPIResponse` ordered timer queue (`studies/aren-go-runtime-study/sources/nats-server/server/jetstream_api.go:1122`), and `InProcessConn`/`DontListen` embedding (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:2873`) for Aren-internal callers.
- From nomad: `Agent` `Server+Client` under one `shutdownCh` (`studies/aren-go-runtime-study/sources/nomad/command/agent/agent.go:72`), `NewHTTPServers`+`tls.NewListener`+`builtinListener` trio (`studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:117`), hijacked ndjson with `deadlineWriter`+`WriteFlusher`+`?index=lastSeen` (`studies/aren-go-runtime-study/sources/nomad/command/agent/event_endpoint.go:92`, `studies/aren-go-runtime-study/sources/nomad/api/event_stream.go:228`), `parseToken`+`ResolveACL`+`exp` atomic refresh inside subscription (`studies/aren-go-runtime-study/sources/nomad/nomad/event_endpoint.go:73`), and `Leave+Shutdown` ordering with `gracefulTimeout` (`studies/aren-go-runtime-study/sources/nomad/command/agent/agent.go:1493`).
- From ollama: `OLLAMA_HOST`/`AREN_ADDR` env default loopback with `AllowedOrigins` CORS (`studies/aren-go-runtime-study/sources/ollama/envconfig/config.go:22`, `studies/aren-go-runtime-study/sources/ollama/server/routes.go:1841`), `Sched.Run+processPending+processCompleted` channel-trio ownership (`studies/aren-go-runtime-study/sources/ollama/server/sched.go:214`) minus request-scoped work, and the minimal `POST /api/generate|chat` JSON+ndjson contract (`studies/aren-go-runtime-study/sources/ollama/api/types.go:62`) as the Phase-14 thin envelope.

**Do not borrow yet:** nomad's default network-reachable bind without workspace `flock`; nats-server's no-workspace `StoreDir` singleton; ollama's opt-in local auth, `srvr.Close()` bare drain, and `pendingReqCh` `MaxQueue=512` drop (`studies/aren-go-runtime-study/sources/ollama/envconfig/config.go:279`, `studies/aren-go-runtime-study/sources/ollama/server/routes.go:3113`) without `Retry-After` for run admission.

## Practical Tips

1. **Make `run_id` the durable inventory key, not a stream/consumer name.** Nats proves naming alone works but forces clients to invent GC; nomad's `EvalID/JobID→X-Nomad-Index` shows a server-issued handle with cursor is strictly stronger. Create `POST /v1/runs→{run_id}` Raft- or WAL-committed, then `GET /v1/runs/:id?index=`, `GET /v1/runs/:id/stream?after=offset`, `POST /v1/runs/:id/cancel` (modeled on `DELETE /v1/job/:id` `studies/aren-go-runtime-study/sources/nomad/command/agent/http.go:404` and `ClientAlloc` signal `studies/aren-go-runtime-study/sources/nomad/nomad/node_endpoint.go:963`), plus `GET /v1/runs/:id/files` for workspace artifacts under `state_dir/<workspace_hash>/runs/<run_id>`.

## Anti-Patterns / Caution Signs

- **Global `StoreDir` single-tree masquerading as workspace isolation.** `filepath.Join(StoreDir,msgDir)` (`studies/aren-go-runtime-study/sources/nats-server/server/filestore.go:61`) and `~/.ollama/models` (`studies/aren-go-runtime-study/sources/ollama/envconfig/config.go:112`) show the failure: no per-request `workspace` field → no `flock` → concurrent `Job.Register` with same `(namespace,jobID)` last-wins only via `ModifyIndex` optimistic concurrency (`studies/aren-go-runtime-study/sources/nomad/api/jobs.go:573`) not a lock. Caution sign: two `aren run --workspace ./ws` from different dirs corrupt the same `RunComplete` if `ws` is only a client-side path.

- **LDM close staggering and second-signal abandonment as the only backpressure.** `si=dur/numClients` batch math (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:4511`) still storms with thousands of clients and short `LameDuckDuration`; `terminateGracefully` second-signal returns `1` immediately (`studies/aren-go-runtime-study/sources/nomad/command/agent/command.go:1069`) abandoning drain — orphaned allocs until `allocGCEligible` (`studies/aren-go-runtime-study/sources/nomad/nomad/core_sched.go:689`). Add `QueueStats.Depth`/`wait_time` histograms (`studies/aren-go-runtime-study/sources/nomad/nomad/eval_broker.go:1019`) and `429+Retry-After` not just `LDM INFO`.

- **Unauthenticated monitoring / inventory enumeration.** Nats `StartMonitoring /varz/connz` without auth (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:3130` no auth), ollama `GET /api/tags|/ps|/show` no token even when `OLLAMA_AUTH=1` (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:1871`), and nomad `GET /v1/allocations?prefix=` gated only by ACL — but every local process can still dial `127.0.0.1:4646` if `addresses.http` is `0.0.0.0` (`studies/aren-go-runtime-study/sources/nomad/command/agent/config.go:1109`). Caution sign: `allowedHostsMiddleware` early-return `c.Next()` when bound non-loopback (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:1811`) — exposing `0.0.0.0` intentionally disables host checks.

- **`allowedHostsMiddleware` as auth and `OLLAMA_AUTH` as decoration.** Auth header signed but never verified on local routes (`studies/aren-go-runtime-study/sources/ollama/server/routes.go:1871` only `cors+allowedHosts`; auth only on `cloud_proxy.go:384`). Any `curl http://127.0.0.1:11434/api/generate` works. Require envelope auth independent of bind.

- **Head-of-line `evictAllAndWait` / `waitForVRAMRecovery` ignoring `ctx.Done()`.** `processPending` `case <-unloadedCh: continue` without `case <-pending.ctx.Done()` (`studies/aren-go-runtime-study/sources/ollama/server/sched.go:350`) lets a cancelled head still block `pendingReqCh` `MaxQueue 512` (`studies/aren-go-runtime-study/sources/ollama/envconfig/config.go:279`) and `s.expiredCh <- runner` under `refMu` with buffer 512 while `processCompleted` stalls in `waitForVRAMRecovery` (`studies/aren-go-runtime-study/sources/ollama/server/sched.go:1726`, `studies/aren-go-runtime-study/sources/ollama/server/sched.go:414`) creates lock-channel deadlock. Make every wait `ctx`-aware.

- **Buffered signals with at-most-once `CompareAndSwap`.** `shutdown.CompareAndSwap(false,true)` (`studies/aren-go-runtime-study/sources/nats-server/server/server.go:2584`) makes second `Shutdown()` a no-op but `SIGTERM` during `ldm` ignored (`studies/aren-go-runtime-study/sources/nats-server/server/signal.go:66`) while `SIGINT→Shutdown+Wait+Exit(0)` races `lameDuckMode`'s own shutdown — daemon can double-`Exit`. Document the signal state machine explicitly.

- **Sharing `keep_alive` liveness with model residency.** `runner.sessionDuration` overwritten by any client's `keep_alive` (`studies/aren-go-runtime-study/sources/ollama/server/sched.go:486`); `KeepAlive=-1→MaxInt64` (`studies/aren-go-runtime-study/sources/ollama/envconfig/config.go:140`) pins VRAM forever for one client's `--keepalive -1` at cost of all later evictions. Scope TTL to `run_id` not `model`.

- **Coarse protocol version promising compatibility without per-method negotiation.** `PROTO` single int (`studies/aren-go-runtime-study/sources/nats-server/server/const.go:75`) and ollama `Version` string warn-only (`studies/aren-go-runtime-study/sources/ollama/cmd/cmd.go:2107`) cannot express breaking `$JS.API.*` or `ThinkValue`/`Tool` (`studies/aren-go-runtime-study/sources/ollama/api/types.go:890`) changes — add `Nats-Required-Api-Level` style header and `api_version:int` with `Accept` negotiation.

## Open Questions

- **Should Aren standardize on HTTP JSON+ndjson vs NATS text framing as the thin contract?** nats proves text framing is polyglot and 1-lang but JetStream JSON over subjects still needs `Nats-Required-Api-Level`; nomad and ollama prove HTTP+JSON+ndjson with `X-Nomad-Index`-like cursor is equally thin and already `curl`-friendly — which wins for Aren's `aren run` TUI + daemon?
- **Filesystem workspace vs logical tenancy — or both?** No source implements a per-run `work_dir` with `flock` and artifact GC; nomad's `region/namespace` query avoids `flock` but leaves concurrent writer races to optimistic `ModifyIndex` — does Aren need both a `?workspace=` header hashing to `state_dir/<hash>/workspace.lock` *and* a `runs/<run_id>` directory?
- **Per-run vs whole-server drain ordering for Phase 15 upgrades.** Sources agree drain is whole-server (`lameDuckMode 2m`, `terminateGracefully 5s+Drain.Deadline`, `unloadAllRunners`). How does Aren's rolling upgrade fence per-run `cancel` against `SIGTERM` during `ldm` without abandoning in-flight runs — and where does the fencing token live (`SnapshotIndex`/`RefreshIndex` analogue)?
- **Versioning strategy.** nats `PROTO=1`/`JSApiLevel` vs nomad `/v1/` additive-fields vs ollama `Version` string warn-only — none give per-method breaking-change negotiation. Should Aren enforce `X-Aren-Api-Level:int` + `Accept: application/vnd.aren.v1+json` and make it fail-closed like nats's `ErrBadClientProtocol` (`studies/aren-go-runtime-study/sources/nats-server/server/client.go:2454`) from day one?
- **Unix socket as mandatory or optional.** Every report's `Future Considerations` proposes `unix://$RUN/aren.sock` `0700`+bearer+`SO_PEERCRED`. Is the UDS the *primary* loopback API for Aren's local-only mode (with TCP as opt-in for remote) or a secondary alongside TCP loopback+`allowedHostsMiddleware`?
- **Gap test coverage for shutdown-under-load and concurrent second-client.** nats `server_test.go:170` `TestStartupAndShutdown` alone, nomad no `Shutdown`-mid-apply under load evidence, ollama no HTTP disconnect mid-stream test (`server/sched_test.go` covers `load/needsReload` only). Will Aren's conformance suite enforce `go test -race -run Shutdown` + `TestEventLog_RegistrationIsGapless`-style 50-iteration gapless poll/stream tests from day one?
