## Executive Summary

All three sources score 8/10 but arrive there by different durability postures. nats-server and pebble both own the filesystem and make atomicity explicit via ordered WAL appends, atomic-file renames with directory fsync, and recovery that distinguishes corruption from truncated tails. temporal-sdk-go owns no files and delegates durability entirely to the Temporal Server as a remote WAL, achieving crash-safety by construction while shifting all atomicity and versioning into a single RPC batch and marker-based code evolution.

The convergence is striking: the atomic unit in every source is Aren-owned lifecycle state — never an external side-effect. Pebble batches (`sources/pebble/batch.go:192-240`) and nats-server's per-record `N.blk` framing (`server/filestore.go:7680-7726`) and small-file `writeAtomically` (`server/filestore.go:14562-14599`) and temporal's whole-WFT `RespondWorkflowTaskCompleted` (`internal/internal_task_pollers.go:569-632`) all commit state/events/outcomes together before any tool runs. Recovery in all three is honest about duplication: Raft replay can re-apply a state machine, Pebble's visibility-before-sync window can lose a just-visible batch, and Temporal activities can re-execute if their schedule-commit and completion straddle a failure (`workflow/doc.go:77`). No source pretends to be exactly-once for external tools.

The divergence is the durability contract and schema strategy. Embedded stores (nats-server, pebble) chase throughput via `SyncAlways` off by default and periodic checkpoint flushes (`server/filestore.go:12103-12130`, `sources/pebble/commit.go:175-180`), then repair with per-record CRC/highwayhash and read-ahead disambiguation (`server/filestore.go:7713-7726`, `sources/pebble/record/record.go:452-586`). Temporal avoids the window entirely by never buffering locally — at the cost of a mandatory server and RPC round-trip. For schema, nats-server uses per-file version constants with min/max refusal (`server/filestore.go:12096-12100`, `server/filestore.go:2004-2008`), pebble uses a monotonic `FormatMajorVersion` ratchet with idempotent migration closures (`sources/pebble/format_major_version.go:352-424`), and temporal uses immutable history plus `GetVersion` markers and SDK flags (`internal/internal_event_handlers.go:944-1002`, `internal/internal_flags.go:98-160`) — no file migration at all.

For Aren Phase 11 the lesson is: choose one atomic batch for own-state+events+artifact manifest, checkpoint before calling tools, and treat format evolution as forward-only with explicit refusal. Copy pebble's two-dir-sync marker for any pointer file, nats-server's per-record hash for append-only logs, and temporal's marker-based routing for live code changes.

## Core Thesis

Durable, coherently recoverable persistence requires three separable commitments that all three sources implement differently but correctly: (1) an atomic batch that contains **only** Aren-owned state (state, outcome, events, artifact pointers) and is committed via an ordered WAL+visibility barrier; (2) a recovery path that separates **corruption from incomplete tail** and distinguishes interrupted from completed work by authoritative watermarks (`minUnflushedLogNum`, `LastSeqNum`/`lchk`, history event presence); and (3) forward-only schema evolution gated at open time, with refusal or marker fallback rather than silent coercion. External effects must sit outside the atomic unit and be made idempotent by sequence-number or deduplication keys — exactly-once must never be implied by storage alone. The two embedded sources prove this with fsync-or-CRC discipline; the stateless SDK proves it by delegating — both are valid responses to their constraints (throughput-controlled single binary vs. server-dependent fleet).

## Approach Models

**Cluster A — Embedded Durable Log (nats-server, pebble).** Both own files and must close the fsync/rename/reorder window themselves. Writers serialize through a single pipeline (`commitPipeline.mu` in `sources/pebble/commit.go:146-215`; file-store's `dios` semaphore + `LogWriter.flushLoop` in `sources/pebble/record/log_writer.go:415-778` vs `server/filestore.go:180-206`), append to a WAL/block log with per-record integrity (CRC vs highwayhash), and periodically checkpoint a separate manifest/snapshot (`index.db`/`MANIFEST`). The pointer to the manifest is moved atomically with two directory fsyncs. Schema is versioned integers with refusal (`fullStateVersion=4` `server/filestore.go:12096-12100` vs `FormatMajorVersion` `sources/pebble/format_major_version.go:32-283`). This cluster maximizes throughput and single-binary operability at the cost of an explicit durability window and complex reader logic for mixed-format files.

**Cluster B — Delegated Durability (temporal-sdk-go).** The SDK holds no WAL, manifest, or checkpoint files — grep for `fsync|WAL|manifest` is empty outside `testsuite/devserver.go:236`. The atomic unit is the entire workflow task: `commandsHelper.orderedCommands` → `RespondWorkflowTaskCompletedRequest` in `internal/internal_task_pollers.go:569-632`. Recovery is history replay: sticky cache validated by `history.Events[0].EventId == previousStartedEventID+1` in `internal/internal_task_handlers.go:817-825` or else full refetch via `resetHistory`. Schema evolution is code evolution: `GetVersion` markers (`internal/internal_event_handlers.go:944-1002`), SDK flags (`internal/internal_flags.go:48-58`), binary checksum/build-id (`internal/checksum.go:1-51`). This cluster maximizes correctness simplicity and rolling-deploy safety at the cost of server dependence, RPC latency, and no offline single-binary story.

Why clusters diverge: product shape (nats-server needs per-stream replicated logs and Raft; pebble needs high-write LSM; SDK needs polyglot fleet with server-grade durability), operational constraints (pebble and nats-server must survive power loss on one node; temporal-sdk-go can assume server durability config), and maturity (pebble and nats-server have been fault-injected for years; SDK leans on `test/replaytests/` compatibility).

## Pattern Catalog

**1. Atomic file replacement — temp + Close + Rename + dir Sync**
- *Problem:* Torn small-state files (meta, index, term/vote, marker) leave partial bytes on crash mid-write.
- *Sources:* nats-server `writeAtomically`/`writeAtomicallyWithTemp` `server/filestore.go:14562-14599` and `writeFileWithSync` for `peers.idx`/`tav.idx` `server/raft.go:5287-5307`; pebble `atomicfs.Marker.Move` `sources/pebble/vfs/atomicfs/marker.go:189-241` (Create→Sync(file)→dir Sync→Move→dir Sync, panic on dir fsync error) and `versionSet.UpdateVersionLocked` `sources/pebble/version_set.go:351-585`; pebble OPTIONS tmp+Rename `sources/pebble/open.go:74-485`. Temporal explicitly has no local file (negative evidence via exhaustive grep — valuable contrast).
- *Why it works:* `rename` is atomic on POSIX; the directory fsync persists the directory entry so crash cannot lose the rename. Two dir syncs close the "marker points to undurably created file" window.
- *Copy when:* Any pointer file watermarks recovery (state snapshot, smallest-unflushed, format version). Aren's `state/checkpoint/artifact-manifest` pointer needs this.
- *Overkill when:* Content is derived and rebuildable (e.g., nats `index.db` is fast-path only; plain `os.WriteFile` in `server/filestore.go:12364` is tolerated because `recoverMsgs` rebuilds).
- *Evidence:* `server/filestore.go:14560,14591-14597`; `sources/pebble/vfs/atomicfs/marker.go:189-241`.

**2. WAL-before-visibility commit ordering**
- *Problem:* Concurrent writers publish state that must survive crash; reordering WAL vs visibility loses acknowledged work.
- *Sources:* pebble five-step `commitPipeline` (`assign seqnum under mu → write WAL → optional Sync queue → concurrent memtable apply → ordered visible-seqnum publish via commitQueue` `sources/pebble/commit.go:146-215,430-520` and `logSeqNum`/`visibleSeqNum` ratchet `sources/pebble/version_set.go:34-49`); nats-server `storeToWAL` via `StoreMsg` `server/raft.go:4990-5014` plus `flushPendingMsgsLocked` `server/filestore.go:8655-8766` and `SyncAlways` gate `server/filestore.go:14549-14556`; temporal's whole-batch RPC `RespondWorkflowTaskCompleted` `internal/internal_task_pollers.go:698-764` (no local visibility window).
- *Why it works:* Only after WAL bytes are appended can publish advance. Temporal takes this to the limit: visibility equals server durability.
- *Copy when:* Aren batches own-state+PROMISE before invoking tools. Use `Sync=true` or group commit.
- *Risk:* Pebble documents visibility can ratchet before sync (`sources/pebble/commit.go:175-180`) — readers see not-yet-durable data. Nats-server's `SyncAlways` off gives similar window. Must not ack external caller on local visibility alone.

**3. Fast snapshot + authoritative log scan (trust-but-verify)**
- *Problem:* Cold start must be O(blocks) but remain correct if snapshot is stale/corrupt.
- *Sources:* nats-server `index.db` v4 vs `recoverMsgs` fallback `server/filestore.go:518-557,1950-2242,2167-2212`; pebble `recoverVersion` on MANIFEST then `replayWAL` `sources/pebble/recovery.go:302-436,457-661` with `minUnflushedLogNum` partition `sources/pebble/recovery.go:177-191`; temporal sticky cache `GetOrCreateWorkflowContext` `internal/internal_task_handlers.go:794-878` vs full replay via `retrievingHistoryIterator` `internal/internal_task_pollers.go:1284-1325`.
- *Why it works:* Fast path validated by checksum/seqnum discontinuity (`mb.lastChecksum()!=lchk` `server/filestore.go:2182-2212`, `BulkVersionEdit` invariants `sources/pebble/internal/manifest/version_edit.go:1137-1210`, `isFullHistory` check `internal/internal_task_handlers.go:880-885`). Fallback is authoritative scan.
- *Copy when:* Any large state store. Checkpoint `flushStreamStateLoop` every ~2 min `server/filestore.go:12103-12130` and pebble `maybeScheduleFlush` `sources/pebble/open.go:74-485` are templates.

**4. Per-record integrity with truncated-tail disambiguation**
- *Problem:* Append-only logs tear mid-record on power loss; reader must not mistake torn tail for corruption.
- *Sources:* nats-server per-record highwayhash + `rebuildStateFromBufLocked` truncation `server/filestore.go:7713-7726,1777-1800` + `LostStreamData` reporting `server/filestore.go:1714-1721`; pebble 32 KiB blocked chunks with CRC + logNum/syncedOffset + `record.Reader.nextChunk` `sources/pebble/record/record.go:52-99,300-429` + `readAheadForCorruption`/`syncedOffset` promise `sources/pebble/record/record.go:452-586` + `strictWALTail` flag in `replayWAL` `sources/pebble/recovery.go:524-568`. Temporal has no log but applies same distinction to history gaps `internal/internal_task_handlers.go:471-477`.
- *Why it works:* CRC/highwayhash rejects torn bytes; synthetic field `syncedOffset` lets reader distinguish "invalid because torn preallocated tail" (return `ErrUnexpectedEOF`, drop last record) vs "invalid should have been durable" (return `ErrCorruption`, refuse to open).
- *Copy when:* Aren uses an event log. Pebble's WAL-sync header (8-byte syncedOffset watermark) is lightweight alternative to per-record fsync.

**5. Sentinel-driven crash recovery for multi-file mutations**
- *Problem:* Directory swaps and multi-step edits need a crash witness.
- *Sources:* nats-server purge `__new_msgs__/N.blk` presence sentinel `server/filestore.go:10706-10748` (block moved last `server/filestore.go:10664-10684`); Raft WAL `ae.pindex != index-1` gap → `truncateAndErr` `server/raft.go:583-625`; pebble `marker.<name>.<iter>.<value>` lexical iter + `LocateMarker` deferred cleanup `sources/pebble/vfs/atomicfs/marker.go:189-241`; temporal history event presence (`ActivityTaskScheduled` vs `Completed`) `internal/internal_command_state_machine.go:500-507`.
- *Copy when:* Any staged directory mutation or ingest. Make sentinel be the last file moved.

**6. Monotonic format version with min/max refusal**
- *Problem:* Newer binary must never misinterpret older bytes; older binary must refuse newer files cleanly.
- *Sources:* nats-server `fullStateVersion=4`/`fullStateMinVersion=1` `server/filestore.go:12096-12100` with `version < min || version > max → errCorruptState` `server/filestore.go:2004-2008` plus `streamStateVersion`/`consumer magic=22 version=2` `server/store.go:213-225`, `server/filestore.go:299-307`; pebble `FormatMajorVersion` iota + `internalFormatNewest`/`FormatMinSupported` + `lookupFormatMajorVersion` refusing too-new/too-old `sources/pebble/format_major_version.go:32-283,428-466` + `ratchetFormatMajorVersionLocked` `sources/pebble/format_major_version.go:515-580`; temporal SDK flags `tryUse` gated by `capabilities.SdkMetadata` `internal/internal_flags.go:98-160` and `GetVersion` min/max panic `internal/internal_event_handlers.go:944-956`.
- *Copy when:* Any persisted format. Forward-only ratchet + idempotent migration closures are simplest and match Cockroach's arbitrarily-old replay.

**7. Idempotent replay by sequence-number / dedup keys**
- *Problem:* Replayed state-machine work must not duplicate external effects or corrupt store.
- *Sources:* nats-server tombstone `tbit` `server/filestore.go:7748-7759``1807-1816` + `Duplicates` window `server/stream.go:5728-5751`; pebble `SeqNum`+`Count` header `sources/pebble/batch.go:192-240` + `BulkVersionEdit` double-add forbids `sources/pebble/internal/manifest/version_edit.go:1137-1149` + `visibleSeqNum` ordering; temporal `ActivityID=getStringID(scheduleID)` `internal/internal_event_handlers.go:792-802` + `commandState` enum `Created→Initiated→Completed` `internal/internal_command_state_machine.go:183-196`.
- *Copy when:* Separating Aren-owned batch (idempotent) from tool calls (outside atomic unit). Key tool invocations by `(workflowID, seqnum)`.

**8. VFS/deterministic crash seam for fault-injection**
- *Problem:* Testing torn-write windows without real power loss.
- *Sources:* pebble `vfs.FS` + `vfs/errorfs` typed fault DSL `sources/pebble/vfs/errorfs/errorfs.go:279-296` + `vfs/mem_fs.go:129-160` `MemFS.CrashClone(cfg)` sweeping `k-th write` at 0%/10% unsynced `sources/pebble/error_test.go:368-569` and `version_set_test.go:515-537`; nats-server `TestFileStoreMsgBlkFailOnKernelFaultLostDataReporting` `server/filestore_test.go:5126-5225` + purge key-rename `server/filestore_test.go:823-891` + NRG truncation tests `server/raft_test.go:1170,1384`.
- *Copy when:* Any embedded persistence. Temporal has no local WAL so validated via `test/replaytests/` JSON histories `test/replaytests/` + `TestWorkerHeartbeat` `test/worker_heartbeat_test.go:84-118` — different seam, same honesty.

## Key Differences

- **Where durability lives.** Nats-server and pebble fsync locally (`writeFileWithSync` `server/raft.go:5425-5450` for `tav.idx`/`peers.idx`; `atomicfs.Marker.Move` dir Sync `sources/pebble/vfs/atomicfs/marker.go:234-238`). Temporal has no `fsync`/`rename` WAL at all (exhaustive grep 0 hits) — correctness depends on server configuration. Nats-server pays the latency on demand (`SyncAlways` off default `server/filestore.go:14549-14556`), pebble hides it via `flushLoop` coalescing `sources/pebble/record/log_writer.go:415-778`, temporal pays it as RPC latency once per WFT. *Implication for Aren:* single-binary/offline host must copy nats-server/pebble posture; fleet with Temporal Server can copy SDK posture.

- **Checkpoint shape.** Nats-server checkpoints `index.db` via background loop every ~2 min + jitter `server/filestore.go:12103-12130` plus synchronous purge/compaction triggers; pebble checkpoints via `Checkpoint` hard-link/copy filtered by `visibleSeqNum` `sources/pebble/checkpoint.go:134-467` (fast even at 100 GiB, but skips remote objects) and `versionSet.UpdateVersionLocked` snapshot of `manifestSize` `sources/pebble/version_set.go:207-250`; temporal has no file checkpoint — sticky LRU cache `internal/internal_task_handlers.go:104-125` is a hot-cache checkpoint, full replay is the recovery scan. The fast-load snapshot is always verified against the log in embedded stores; temporal verifies sticky hit via `EventId` continuity.

- **Corruption handling strictness.** Pebble promotes a corrupt chunk to `ErrCorruption` only if `syncedOffset > invalidOffset` confirms it should have been valid `sources/pebble/record/record.go:452-586`; otherwise truncated tail is discarded (last WAL only, via `strictWALTail=false` `sources/pebble/recovery.go:524-568`). Nats-server is similar but coarser: torn last block → truncate to last good index `server/filestore.go:1747-1753,1777-1800` and report `LostStreamData`; no finer per-record skip. Temporal never has local torn bytes — gaps are `missing history events, expectedNextEventID=...` `internal/internal_task_handlers.go:471-477` leading to `RespondWorkflowTaskFailed` + full refetch.

- ** WAL format evolution.** Pebble supports three wire formats simultaneously (legacy/recyclable/WAL-sync) selected by FMV closure `sources/pebble/record/log_writer.go:566-570`, with recyclable avoiding metadata fsync but complicating the reader with log-number-tagged chunks `sources/pebble/record/record.go:74-99`. Nats-server likewise tolerates mixed `index.db` versions via `if version>=2/3/4` `server/filestore.go:2097-2103`. Temporal has no WAL format shift — evolution is history markers whose presence is idempotent (`tryUse` only on non-replay `internal/internal_flags.go:116-136`).

- **Schema evolution enforcement.** Nats-server refuses unknown versions and deletes bad `index.db` `server/filestore.go:2004-2008` (and validates `streamStateMagic` `server/store.go:262-362`); pebble refuses unknown FMV via `lookupFormatMajorVersion` `sources/pebble/format_major_version.go:428-466` and ratchets forward via `finalizeFormatVersUpgrade` `sources/pebble/format_major_version.go:515-580`; temporal never refuses files — it fails the workflow task with `WORKFLOW_TASK_FAILED_CAUSE_NON_DETERMINISTIC_ERROR` (`internal/internal_task_handlers.go:1286-1293`) and by default blocks forever (`BlockWorkflow` `internal/worker.go:539-544`) until code is fixed. Nats-server and pebble are instance-level refusals; temporal is execution-level blocking.

- **Acknowledgement boundaries.** All three make the atomic unit exactly Aren-owned state. Nats-server's unit is a single record or single small file (not producer ack — ack requires WAL durability plus optional `SyncAlways`); pebble's unit is a `Batch+VersionEdit` (visibility may precede durability); temporal's unit is the whole WFT command batch + SDK flags + protocol messages. Tool effects are always outside: nats-server has no external tools, pebble's `Batch.Apply` forbids mixing ingested SST batches `sources/pebble/batch.go:1238-1244`, temporal documents `Execution must be idempotent` `workflow/doc.go:77` and activity at-most-once guidance `temporal/doc.go:72`.

## Tradeoffs

- **Throughput vs durability window.** *Benefit:* Default `Sync=false`/ `SyncAlways` off gives lower p95 latency; `flushLoop` coalesces syncs `sources/pebble/record/log_writer.go:546-587`, nats-server's `syncBlocks` + `defaultSyncInterval=2min` `server/filestore.go:339,8163-8322` similarly spreads fsync cost. *Cost:* Crash can lose last visible batch (pebble `commit.go:175-180`) or messages in block cache (nats `server/filestore.go:12118-12124`). *Best fit:* High-write ingest where R≥3 replication (nats) or retryable producers compensate. *Alternative:* temporal's always-durable WFT batch pays RPC latency per decision but has no local window. *Failure mode:* Permission denied on flush shuts down JetStream `server/filestore.go:7421-7428` — fail-closed.

- **Recyclable WAL reuse vs reader complexity.** *Benefit:* Reusing WAL files via `Recycler.Peek` + `ReuseForWrite` `sources/pebble/wal/standalone_manager.go:136-239` avoids file-metadata fsync on rotation — critical for high-sync workloads. *Cost:* Recyclable bytes require log-number-tagged chunks and special InvalidChunk/ZeroedChunk handling `sources/pebble/record/record.go:300-429`, plus a transition window `FormatWALSyncChunks` where old WALs have weaker EOF-vs-corruption signal. Nats-server's analogous choice is block rotation + tombstones `server/filestore.go:7883-7893,7748-7759` — small blocks = many files+fsyncs, large blocks = bigger recovery scans.

- **Fast snapshot vs file count.** *Benefit:* `index.db` or `MANIFEST`+`visibleSeqNum` filter lets checkpoint hard-link SSTs without byte copy `sources/pebble/checkpoint.go:439-457` (pebble 100 GiB in ms). *Cost:* Snapshot staleness triggers full log scan (nats `rebuildStateFromBufLocked` `server/filestore.go:1589-1880`, pebble `replayWAL` per-record). Temporal's sticky cache trades the same: hot hit is µs, LRU thrash forces repeated full replay `internal/internal_task_pollers.go:1096-1154`.

- **Forward-only format vs operational rollback.** *Benefit:* Monotonic FMV eliminates downgrade migration matrix; `finalizeFormatVersUpgrade` is idempotent `sources/pebble/format_major_version.go:574-580`. *Cost:* Bad ratchet cannot be rolled back via binary downgrade — both pebble `FormatMinSupported` refusal `sources/pebble/format_major_version.go:287,428-466` and nats `fullStateMinVersion` `server/filestore.go:12096-12100` enforce that; temporal's `GetVersion` branches must be retained forever or history breaks. Forward-fix only.

- **Two-dir-sync atomic pointer vs torn-pointer risk.** *Benefit:* Double dir Sync closes marker-points-to-missing-file window `sources/pebble/version_set.go:207-240`, `sources/pebble/vfs/atomicfs/marker.go:189-241` (also nats `syncDir` `server/filestore.go:8308-8315`). *Cost:* Panic on dir fsync error philosophy `sources/pebble/vfs/atomicfs/marker.go:234-238` — unrecoverable durability is treated as fatal, not retryable. Nats-server's snapshot `snap.<term>.<index>` without tmp+rename `server/raft.go:1596-1638` is the anti-example — partial write can leave corrupt snapshot at expected path.

- **Deterministic CrashClone at FS layer vs kernel reordering fidelity.** *Benefit:* `CrashClone` at 0%/10% unsynced `sources/pebble/error_test.go:368-569` iterates 100s of crash points without process kills; `errorfs` injects per-op errors `sources/pebble/vfs/errorfs/errorfs.go:279-296`. *Cost:* Does not simulate 512 B sector tear or NVM reordering beyond unsynced-bytes probabilistic drop `sources/pebble/vfs/mem_fs.go:707-724`. Nats-server's fault tests cover file deletion/corruption but not process kill between WAL write and next fsync (noted as gap `server/filestore_test.go:5126`).

## Decision Guide

- **If Aren must run as single binary / offline / air-gapped → copy pebble + nats-server embedded model.** Use a single `Batch`-like atomic unit for state+outcome+events+artifact manifest, ordered WAL-before-visibility, atomic pointer files via `atomicfs.Marker` pattern, and deterministic CrashClone tests. Accept `Sync` gating or group commit; never imply exactly-once for tools.

- **If Aren runs as fleet against a durable control plane (Temporal Server, or your own coordination service) → copy temporal-sdk-go delegation.** Make the SDK stateless, make the server the WAL, and make the WFT batch the only commit boundary (`commandsHelper` + single RPC). Use history replay as recovery and marker-based code versioning. Pay RPC latency; gain zero local fsync code.

- **Choosing between nats-server file store vs pebble LSM.** Nats is the template when primary data is an append-only log with stream/consumer semantics, tombstones, per-block encryption/compression, and Raft-replicated logs (`StoreMsg` as WAL `server/raft.go:4990-5014` plus `peers.idx`/`tav.idx`). Pebble is the template when primary data is key-value with range deletions, compactions, and snapshot-isolated checkpoints. If Aren's state is small-pointer + blob artifacts, pebble's `Batch+VersionEdit` + checkpoint hard-links fit; if it's ordered event streams, nats's `.blk` + `index.db` fits.

- **Sync policy rule of thumb.** Default `Sync=false` + `minSyncInterval` (pebble) or `SyncAlways` off + `SyncInterval=2m` (nats) for throughput; require `Sync=true` or `LogData(nil,Sync)` group commit before acking external caller or before making tool idempotency visible. Model explicitly after pebble's `Checkpoint.WithFlushedWAL` empty sync record `sources/pebble/checkpoint.go:45-49`.

- **Checkpoint vs full replay.** For streams/logs: background loop every 1–2 min with jitter `server/filestore.go:12103-12130` plus synchronous trigger on purge/compact `server/filestore.go:10780`. For KV stores: snapshot-isolated hard-link checkpoint filtered by `visibleSeqNum` `sources/pebble/checkpoint.go:134-467`. For SDK delegation: sticky LRU sized to working set with `StickyCacheTotalForcedEviction` metric `internal/internal_task_pollers.go:1096-1154`.

- **Schema evolution choice.** For on-disk formats: monotonic FMV with `MinSupported` refusal and idempotent closures `sources/pebble/format_major_version.go:352-424,515-559`. For code-behavior evolution against immutable history: `GetVersion(changeID,min,max)` with `PreferredVersionProvider` rolling deploy `internal/worker.go:96-142` and SDK flags capability-gated `internal/internal_flags.go:98-160`. Do not attempt in-place file migration inside the atomic commit window.

## Practical Tips

- **Start with one atomic batch.** Put task status transition, outcome, event list, and artifact pointers in a single `Batch`/`VersionEdit` (pebble `sources/pebble/batch.go:192-240` + `sources/pebble/version_set.go:351-585`) or single WFT batch (`internal/internal_command_state_machine.go:152-154`); tool arguments live outside the batch. The SDK's deliberate fallback to `RespondWorkflowTaskFailed` on serialization failure `internal/internal_task_pollers.go:764-803` models half-commit prevention — copy that.

- **Encode the sequencer in the batch header.** Use `SeqNum+Count` `sources/pebble/batch.go:192-240` or `total_len+sequence+hash(8)` `server/filestore.go:7680-7715` to make re-application idempotent. Gate new mutation kinds by FMV (`batchKinds` `sources/pebble/batch.go:66-91`) so readers can reject unknown kinds early.

- **Make every pointer file use two dir syncs.** Wrap any `state`, `marker`, or `format-version` write with `Create→Sync(file)→Sync(dir)→Move→Sync(dir)` `sources/pebble/vfs/atomicfs/marker.go:189-241`. Panic on dir fsync error is defensible per PostgreSQL model `sources/pebble/vfs/atomicfs/marker.go:234-238`; at least `Fatal` and do not continue with uncertain durability.

- **Add per-record integrity and a synced-offset watermark.** Highwayhash `server/filestore.go:7713-7726` or CRC `sources/pebble/record/record.go:52-99` is enough; the cheaper win is the WAL-sync `syncedOffset` promise `sources/pebble/record/log_writer.go:481-489,1071-1107` that turns ambiguous tails into a precise corruption-vs-EOF test `sources/pebble/record/record.go:452-586`. Even for text logs, a trailing length+crc lets `recoverMsgs` truncate precisely `server/filestore.go:1744-1753`.

- **Stage multi-file mutations with sentinel-last.** For purge/compaction/ingest, write staging dir entries then rename old away and staging back, moving the data-bearing file last `server/filestore.go:10664-10684`. Recovery checks sentinel presence `server/filestore.go:10706-10748`. For ingest, encode file-number ratchet past `maxFilenumUsed` `sources/pebble/recovery.go:112-191` to avoid zombie resurrection.

- **Separate fast snapshot from truth log.** Write `index.db`/MANIFEST on a jittered background loop (avoid startup storms on big clusters `server/filestore.go:12103-12130`) but always validate via checksum and last-block `lchk` `server/filestore.go:2167-2212` or `minUnflushedLogNum` `sources/pebble/recovery.go:177-191`; fall back to full scan on mismatch. Temporal's stickiness check `history.Events[0].EventId == previousStartedEventID+1` `internal/internal_task_handlers.go:817-825` is the same idea for memory cache.

- **Version every persisted envelope.** Use `magic+version+size-guard+version-gated fields` triple at every decode boundary (nats `recoverFullState` `server/filestore.go:1972-2008`, pebble `VersionEdit` tags `sources/pebble/internal/manifest/version_edit.go:36-65`, temporal `SDKFlagUnknown` `internal/internal_flags.go:84-91`). Gate readers with `if version >= N` `server/filestore.go:2097-2103` and reject out-of-range `server/filestore.go:2004-2008`. For history-immutable systems, budget changeIDs (`changeVersionSearchAttrSizeLimit=2048` `internal/internal_event_handlers.go:985`) and compact via `ContinueAsNew`.

- **Expose a VFS/fault seam from day one.** Abstract `vfs.FS` `sources/pebble/vfs/vfs.go` so `MemFS.CrashClone(cfg)` `sources/pebble/vfs/mem_fs.go:129-160` and `errorfs` DSL `sources/pebble/vfs/errorfs/errorfs.go:279-296` can sweep `k-th write` without spawning processes `sources/pebble/error_test.go:368-569`. Even minimal `TestFileStoreMsgBlkFailOnKernelFaultLostDataReporting` `server/filestore_test.go:5126-5225` coverage is better than none. Log the `LostStreamData` gap explicitly; do not swallow truncation.

- **Keep tool calls outside the durability boundary and key them.** Schedule via command (`ScheduleActivityTask` → `ActivityID=getStringID(scheduleID)` `internal/internal_event_handlers.go:792-802`), execute out-of-band, heartbeat via `RecordActivityHeartbeat` `internal/activity.go:293-294`, and retry with `LastHeartbeatDetails` `internal/error.go:467-491`. For offline tools, store the same dedup key in the artifact manifest.

## Anti-Patterns / Caution Signs

- **Torn pointer without tmp+rename.** `index.db` via plain `os.WriteFile` `server/filestore.go:12364` and snapshot `snap.<term>.<index>` without staging `server/raft.go:1596-1638` rely on the block log as truth to mask the gap. If Aren promotes the snapshot to source of truth, this becomes a real torn-window — add `writeAtomically` there.

- **Acknowledging before sync.** Nats-server warns "messages in block cache could be lost" `server/filestore.go:12118-12124` and `storeMsg` `server/stream.go:7421-7428`; pebble documents visible-before-durable `sources/pebble/commit.go:175-180` and offers `ApplyNoSyncWait` `sources/pebble/db.go:769-786`. If external caller sees commit before durability, the window is user-visible — gate acks on `Sync=true` or server ack.

- **Coarse truncation masking silent loss.** Nats-server truncates the whole block on a torn record `server/filestore.go:1681-1711,1748-1753`, reporting one `LostStreamData` event. Valid records after the torn one are discarded. If per-record durability matters, a finer offset-trailer is required (noted as future work in nats analysis).

- **Format transition windows with weaker guarantees.** Pebble's recyclable→WAL-sync FMV gap and nats-server's mixed `index.db` versions both create periods where readers must tolerate weaker EOF-vs-corruption signals. Introducing a new format without ratcheting readers first is an anti-pattern.

- **Forward-only without forward-fix plan.** Both embedded stores refuse downgrade (`unknown format major version` `sources/pebble/format_major_version.go:428-466`, `version > fullStateVersion → errCorruptState` `server/filestore.go:2004-2008`). If Aren ratchets and then discovers a bug, rollback via binary downgrade corrupts or blocks — need checkpoint-based restore or forward patch, not file mutation.

- **Marker/state sprawl without compaction.** Temporal's `GetVersion` markers append forever; hitting `changeVersionSearchAttrSizeLimit` silently skips visibility upsert `internal/internal_event_handlers.go:985-989`. Similarly, `TemporalChangeVersion` search attribute bloat is invisible until debug. Cap changeIDs or schedule `ContinueAsNew`.

- **Distributed store without dirSync discipline.** Nats-server correctly gates `syncDir` behind `canFsyncDirectories` `server/filestore.go:14560,14591-14597` but skips on Windows — a caution for cross-platform Aren hosts. Missing directory fsync is the most common source of "rename vanished after crash."

- **Command batch bloat past transport limits.** Temporal's whole-WFT atomicity can exceed `GRPC_MESSAGE_TOO_LARGE` `internal/internal_task_pollers.go:764-803` and fail the WFT; nats-server's `dios` semaphore `server/filestore.go:180-206` serializes atomic renames under load. Lack of batch-size or concurrency caps is a latency tail risk.

- **Silent corruption recovery.** `BulkVersionEdit` invariant panics and `checkConsistency` size checks `sources/pebble/internal/manifest/version_edit.go:1137-1210` intentionally fail hard rather than silently degrade — copying that panic is correct if the invariant is truly broken, but unwinding to an earlier MANIFEST would be kinder when available.

## Notable Absences

- **No exactly-once for tools — universally and honestly absent.** All three sources explicitly do not claim it (nats-server at-least-once due to `SyncAlways` off, pebble idempotent state but external duplication, temporal `workflow/doc.go:77` idempotency requirement). This is the correct absence for Aren to preserve.

- **No systematic version-boundary reopen tests.** Nats-server has `TestFileStoreMessageTTLRecovered` `server/filestore_test.go:9473` but no harness exercising all `v1..v4` branches together; pebble's ratchet lacks a crash-during-migration test `sources/pebble/format_major_version.go:418-423`; temporal has no "deploy v2 then rollback to v1 and assert replay" harness — all three list this as a gap.

- **No rollback/downgrade path.** All schema evolution is forward-only (pebble `ratcheting` boolean `sources/pebble/db.go:362-363`, nats version refusal, temporal's requirement to retain old `GetVersion` branches). None supports restoring from a checkpoint downgrade automatically — an operational gap for Aren to design around.

- **No SDK-local durability seam.** Temporal-sdk-go's statelessness means no WAL corruption handling test exists by design (exhaustive grep confirms 0 `fsync|WAL|manifest` hits). Its durability is only as strong as the server's (`GetSystemInfo` capability gating `internal/internal_flags.go:98-136`).

- **No per-batch compression/encryption durability tests.** Pebble's table-format footers and compression counters `sources/pebble/db.go:559` are not swept by WAL crash tests; nats-server's per-block encryption key files `N.key` `server/filestore.go:5192-5215` have purge-rename coverage `server/filestore_test.go:823-891` but not power-loss between kernel write and `f.Sync()` on the block fd.

- **No worst-case lost-message count test.** Nats analysis searched for `kill|crash|chaos` and found none bounding "kill -9 between WAL write and next fsync, assert N messages lost" under `SyncInterval` — window is documented but not quantified by a test.

## Open Questions

1. **How many sequenced writes are allowed to be visible but not durable under Aren's eventual Sync policy?** Both embedded sources quantify the window (pebble `Sync=false` default, nats `SyncAlways` off + `SyncInterval`) but neither bounds worst-case lost count under `kill -9` in a test — needed to set an honest SLO for external ack.

2. **Does Aren need a rollback story beyond forward-only?** All three sources reject downgrade (pebble `FormatMinSupported`, nats `fullStateMinVersion`, temporal requires retaining old `GetVersion` branches). If Aren ships a bad ratchet, is restore-from-checkpoint hard-link `sources/pebble/checkpoint.go:134-467` sufficient or is an explicit downgrade migration required?

3. **Where should Aren's durability watermark live — WAL-sync offset vs per-record fsync vs group commit?** Pebble's `syncedOffset` header `sources/pebble/record/log_writer.go:1071-1107` is cheaper than per-record fsync; nats-server's `SyncAlways` `server/filestore.go:14549-14556` is simpler but higher latency; temporal sidesteps with server durability. Choice affects replay disambiguation strength.

4. **Can interrupted work be tagged without duplicating tools if heartbeat is user-driven?** Temporal heartbeat details piggyback on retry `internal/error.go:467-491` and require user cooperation (`RecordActivityHeartbeat`); nats and pebble have no analogous progress heartbeat inside a long-running batch. Should Aren's tool host heartbeat be system-managed?

5. **Is a single-RPC WFT-equivalent batch practical for Aren without a server?** Temporal proves atomic WFT batch works but bursts can overflow `GRPC_MESSAGE_TOO_LARGE` `internal/internal_task_pollers.go:764-803`. If Aren embeds the durable log, what's the correct batch cap and chunking strategy for large tool fans?

6. **Should Aren's manifest/checkpoint be the source of truth or a rebuildable fast path?** Nats-server tolerates stale `index.db` and rebuilds via `recoverMsgs`; pebble's MANIFEST is durable truth. The choice determines whether `index.db` analog needs `writeAtomically` or plain `os.WriteFile` is acceptable.
