## Summary

docker-agent implements a typed tool-registry + schema-driven validation + multi-stage approval pipeline that enforces policy before any side effect. Tools are exposed via `tools.ToolSet` with JSON Schema generated from Go types (`jsonschema-go`), validated at call time through `aijson.Unmarshal` (strict JSON first, narrow shape repairs only on failure with `tool_input_repaired` telemetry). The `runtime/toolexec.Dispatcher` is the single choke point: it resolves duplicate names (`first toolset in config wins`), rejects unknown tools, evaluates permissions (`Deny > Allow > Ask` + safety-mode table), consults pre_tool_use hooks (including a `preempt_yolo` lane that cannot be bypassed by `--yolo` or team allow rules), and only then invokes the handler via `invoke`. Denied/rejected calls never reach `exec.Cmd.Start`, `MCP.CallTool`, or filesystem mutations—verified by dispatcher tests that panic if a denied handler runs. Results preserve typed semantics (`Output` + `IsError` + `Images/Audios/Documents` + `StructuredContent` + `Meta/Category/Annotations`) and are never silently truncated: the always-injected `limit_large_tool_results` `tool_response_transform` hook spills oversized outputs (>50 KiB or >2000 lines) to a per-session temp file and returns an explicit bounded excerpt with file reference and continuation instructions. Secrets are scrubbed at three legs (`pre_tool_use` args, `before_llm_call` messages, `tool_response_transform` output) via `portcullis`. MCP lifecycle is supervisor-managed with generation-guarded caches and `ToolListChanged` invalidation.

## Rating

**8/10** — Comprehensive, auditable tool-contract chain (discovery → schema → parsed `ToolCall` → validated typed params → permission → pre-hook rewrite → execution → typed result → bounded transform → provider-specific multimodal conversion). Permission is structurally before effects, denied calls are provably side-effect-free, and large results are externalised with explicit markers. Deductions: `aijson` repairs mask some model schema drift (observable but lenient), `read_file` line-based continuation fails on single-line >50 KiB blobs, shell grant prefix matcher is work-around by extra strict check only on the preempt path, and no global artifact store—large results live as temp files with `session_end` cleanup only.

## Answers to Dimension Questions

**Can malformed or ambiguous arguments reach a tool implementation?**
No. The primary barrier is `tools.NewRuntimeHandler` (`pkg/tools/tools.go:34-52`): it defaults `args==""`→`"{}"` then `aijson.Unmarshal` with strict `encoding/json.Unmarshal` first; only on strict failure does it apply narrow shape repairs (stringified array, bare scalar where array expected, single-object placeholder, null for primitive) and emits `tool_input_repaired` telemetry. If unmarshal fails, the handler returns `(nil, err)` and the dispatcher translates it via `translateError` into a `ResultError` without calling the typed function. Shell adds its own alias layer (`pkg/tools/builtin/shell/shell.go:109-123`) accepting `command` as fallback for `cmd` but still validates `TrimSpace(cmd)==""` → `ResultError`. MCP (`pkg/tools/mcp/mcp.go:735-751`) parses `Arguments` as `map[string]any`, strips `null` values (models emitting `null` for optional params), and rejects invalid JSON via `fmt.Errorf("failed to parse...")`. On provider ingress, `a2a/adapter`, `chat` flows preserve `ToolCall.Function.Arguments` as opaque string until the typed unmarshal stage. Tests (`pkg/tools/tools_test.go:75-91`, `99-122`) pin that malformed JSON returns error and that repairs are observable. The only leniency is intentional: `aijson` repairs hide minor model drift rather than surfacing a hard error—but that is logged per `(tool, kind)` for auditing.

**Is permission checked before process start, network access, or filesystem mutation?**
Yes, structurally. Every tool call goes through `runtime/toolexec.Dispatcher.Process` → `call.run` → `approveAndRun` (`pkg/runtime/toolexec/dispatcher.go:353-416`, `442-510`). `run` first checks `ctx.Err()` and `!available`, then builds `runTool` closure (capturing `c.tool.Handler` or `Handlers[name]`) but does not invoke it. `approveAndRun` evaluates in order: 0) `consultPreToolUsePreYolo` (`preempt_yolo:true` hooks) can `Deny`/`Ask` and short-circuit before `Decide`; 1) `permissionDecision` via `Decide` (checker `Deny` > `Allow` > explicit `Ask` > mode table); 2) `consultPreToolUseHook` (LLM-judge) only when mode said `Ask`; 3) `legacyReadOnlyAutoApprove`; 4) `askUser` (which itself consults `permission_request` hook unless preempt asked, checks `NonInteractive` deny, serializes on `confirmationMu`, emits `ToolCallConfirmation` and blocks on `Resume`). Only `OutcomeAllow` or an explicit user/hook `Allow` invokes `runTool()` → `invoke` → `Handler` → `exec.Command.Start` / `MCP CallTool` / filesystem mutation. Deny paths call `errorResponse` (synthesised `IsError` tool message run through `tool_response_transform`) and return `CallOutcome{}` without touching the handler. Tests prove this: `TestDispatcher_DenyByPermissionsEmitsErrorResponse` and `TestDispatcher_RestrictedFailClosed` set handler to `panic("must not run")` and assert it never fires (`pkg/runtime/toolexec/dispatcher_test.go:1074-1104`, `694-783`). Even `session allow` override on preempt-Ask requires `shellGrantCoversCommand` word-boundary check (`pkg/runtime/toolexec/dispatcher.go:566-580`) to avoid prefix-match privilege escalation.

**How are large results represented without silently discarding evidence?**
Not truncated silently: the always-on `limit_large_tool_results` `tool_response_transform` builtin (`pkg/hooks/builtins/limit_large_tool_results.go:23-112`, injected in `pkg/hooks/builtins/builtins.go:161-165` and `pkg/runtime/hooks.go:21`) caps only high-volume categories (`filesystem`, `shell`, `mcp`, `a2a`; bounded categories like `memory`, `plan`, `tasks`, `think` are untouched). Threshold `>50 KiB` or `>2000` lines triggers `writeLargeToolResult` to `$(TempDir)/docker-agent-tool-results/<sessionID>/tool-result-*.txt` (mode `0700`). The transform returns `UpdatedToolResponse` containing: original byte/line counts, absolute file path, and a bounded excerpt—`tail` (last 2000 lines / 50 KiB) for most tools, `head` (first 2000 lines / 50 KiB) for `read_file` with `nextReadFileLine` continuation (`line`/`limit` args) or byte-range advice if first line alone exceeds limit. `Dispatcher.invoke` applies `applyToolResponseTransform` before `EmitToolCallResponse`, before `recordToolResponse` (session persistence), and before `postHook` input, so UI, persisted transcript, and downstream hooks all see the rewritten explicit marker, not raw truncation. Cleanup is via `EventSessionEnd` hook removing the per-session dir. Additional per-tool byte caps exist (`pkg/tools/builtin/filesystem/limit.go:10-21`: `maxSearchFileSize 10 MiB`, `maxSearchOutputBytes 1 MiB`) and image resizing (`pkg/tools/builtin/filesystem/filesystem.go:1305`).

**Does the abstraction preserve tool-specific semantics or flatten them into strings?**
Preserves. `Tool` (`pkg/tools/tools.go:147-170`) carries `Category`, `Annotations` (`ReadOnlyHint`, `DestructiveHint`, `Title`, `OpenWorldHint`), `OutputSchema`, `Parameters` (JSON Schema), and `Metadata` (merged into confirmation via `confirmationMetadata` with precedence `tool static < permission_request < safety label < preempt_yolo` at `pkg/runtime/toolexec/dispatcher.go:901-924`). `ToolCallResult` (`pkg/tools/tools.go:95-109`) is not a bare string: `Output string` + `IsError bool` + `Images/Audios []MediaContent{Data base64,MimeType}` + `Documents []DocumentContent{Name,URI,MimeType,Data/Text}` + `StructuredContent any` + `Meta any`. `WithoutPayload` strips only `Output/Images/Audios/Documents/StructuredContent` for telemetry. `MCP.processMCPContent` (`pkg/tools/mcp/mcp.go:829-883`) preserves `IsError`, `StructuredContent`, re-encodes binary to base64, and converts `EmbeddedResource` mime-typed blobs to typed `Document`/`Audio` vs text marker. `Dispatcher.invoke` → `recordToolResponse` (`pkg/runtime/toolexec/dispatcher.go:1136-1156`) builds `chat.Message{Role:tool, ToolCallID, IsError, MultiContent: BuildToolResultMultiContent}` where `pkg/chat/tool_result.go:14-33` emits `MessagePartTypeText` + `MessagePartTypeDocument`/`ImageURL` with `data:` URLs. Anthropic provider (`pkg/model/provider/anthropic/tool_result_attachments_test.go:45-91`) converts `MultiContent` to `ToolResult` content blocks (`OfText`/`OfDocument`/`OfImage` with `Base64` source), respecting model capabilities. Callers can still inspect `Tool.Category`, `Tool.Annotations`, and `Result.StructuredContent` downstream. The string `Output` is the LLM-facing primary channel, but structured/binary channels travel alongside without loss.

## Architectural Decisions

- **Single dispatcher choke point** (`pkg/runtime/toolexec/dispatcher.go:195-276`, `302-415`): per-batch `Dispatcher.Process` with `concurrent.MapSlice` parallel execution but serialized confirmations via `confirmationMu`; centralizes tracing (`gen_ai.*`), telemetry, hook dispatch, permission, and event emission. Tradeoff: concurrency is safe only insofar as `Emitter` is.
- **`aijson` strict-first with narrow repairs** (`pkg/tools/tools.go:21-24`, `42-47`): `encoding/json.Unmarshal` strict path hot; only on failure allow `stringified array`, `bare scalar where array expected`, etc., with `slog.Info tool_input_repaired` per `(tool, Kind)`. Preserves contract strictness while tolerating known model quirks without per-tool bespoke parsers.
- **Tiered checker + mode table** (`pkg/runtime/toolexec/permissions.go:84-150`, `pkg/permissions/permissions.go:99-117`): session tier (interactive grants, user intent) beats team tier; `Deny>Allow>ForceAsk`; `ForceAsk` from team yields to `Balanced/Restricted/Autonomous` (advisory). Modes are fail-closed for `Restricted` (deny instead of ask) for unattended runs.
- **Two-lane pre_tool_use** (`pkg/hooks/types.go:210-231`, `pkg/runtime/toolexec/dispatcher.go:442-471`, `600-624`): `EventPreToolUsePreYolo` lane runs before deterministic pipeline so security hooks cannot be bypassed by `--yolo` or allow rules; result cached (`preYoloComputed`) to avoid 3× dispatch. `UpdatedInput` rewrite cached and invalidates safety label.
- **`tool_response_transform` as universal rewrite** (`pkg/runtime/toolexec/dispatcher.go:1063-1109`, `pkg/hooks/types.go:177-191`): runs before emit/record/post-hook so `redact_secrets` and `limit_large_tool_results` scrub/bound once for all consumers. Short-circuits via `exec.Has(event)`.
- **Always-on large-result limiter** (`pkg/hooks/builtins/builtins.go:161-165`, `pkg/hooks/builtins/limit_large_tool_results.go:38-43`): categories bounded are those with no per-result limit upstream (MCP/a2a external), not high-volume internal tools. Head for `read_file` (line-oriented continuation), tail otherwise.
- **Duplicate tool dedup first-wins** (`pkg/agent/agent.go:448-464`): prevents provider 400s (Anthropic rejects duplicate names) and makes dispatcher `toolByName` lookup deterministic; collisions warned once per streak via `reportCollisions`.
- **CallTimeout bounded per-call not per-session** (`pkg/tools/mcp/mcp.go:772-792`, `pkg/tools/builtin/shell/shell.go:141-147`): `callTimeout` via `Lifecycle.Policy.CallTimeout`, detached session context not bounded—timeout only cancels the call, not the transport.

## Notable Patterns

- **Wrapper-chain capability probing** via `tools.As[T]` + `Unwrapper` (`pkg/tools/startable.go:704-717`, `pkg/tools/named.go:20-60`): every decorator (`StartableToolSet`, `namedToolSet`, MCP supervisor) remains unwrappable so `Instructable`, `Elicitable`, `Sampleable`, `Statable`, `Restartable` are discoverable without leaking Go types.
- **Generation-guarded caches** for MCP (`pkg/tools/mcp/mcp.go:645-701`, `722-727`): `cacheGen` bump on `invalidateCache`, fetch outside lock, populate only if gen unchanged—avoids stampede and stale ToolList after reconnect/notification.
- **FailureStreak de-duplication** (`pkg/tools/startable.go:42-69`, `pkg/agent/agent.go:528-554`): `startStreak`/`listStreak`/`recoveryStreak` emit warning once per consecutive failure streak, silent thereafter, reset on success/stop.
- **LifecycleMutex channel-based** (`pkg/tools/startable.go:197-251`): `LockContext` honors `ctx` deadline without busy-wait; `unlock` performs `StopIfStarted` handshake so a timed-out `StopIfStarted` request is not lost.
- **Preempt-yolo + session-allow interplay** (`pkg/runtime/toolexec/dispatcher.go:463-467`, `526-536`): `Ask` from preempt lane does not bypass `sessionPermissionsAllow` but does bypass team allow; shell grants additionally require `shellGrantCoversCommand` strict match (`pkg/runtime/toolexec/shell_grant.go`) to block `&&` smuggling.
- **Portcullis three-leg redaction** (`pkg/hooks/builtins/redact_secrets.go:154-170`, `43-65`): `redactToolInput` emits only changed keys so concurrent `pre_tool_use` hooks' `maps.Copy` aggregation does not clobber; `redactMessage` clones slices before mutating.

## Tradeoffs

- **Repair vs strictness**: `aijson` narrow repairs prevent wasted turns on `{"paths":"only.txt"}` but mask model drift; mitigated by per-repair-type telemetry and hot-path silence guarantee (`pkg/tools/tools_test.go:154-179`), yet still lenient compared to rejecting malformed calls outright.
- **Head vs tail excerpts**: `read_file` head preserves front-matter (imports, preamble) but forces model to use `line`/`limit` or byte-range shell for remainder; non-filesystem tools get tail (often more relevant for logs). Single-line >50 KiB impossible to paginate via `read_file`—notice directs to `shell` (`pkg/hooks/builtins/limit_large_tool_results.go:115-133`).
- **Shell prefix-match hardening scope**: strict `shellGrantCoversCommand` only applied on preempt-Ask override path; generic `permissions.Check` still uses regex prefix match (`matchGlob` fast path `HasPrefix` when `trailing *` with no other glob chars at `pkg/permissions/permissions.go:260-266`), which is intentionally permissive for normal allow rules but could grant more than intended outside the safety override.
- **Always-on limiter file I/O**: every oversized result does `MkdirAll` + `CreateTemp` + `WriteString` under `/tmp`; no quota, no streaming—full payload still held in memory as `string` before spill (`len(payload)` check). Bounded excerpt avoids token blowup but disk spill could accumulate if `session_end` hook fails or session ID is reused.
- **Parallel batch vs single Resume channel**: `Process` runs calls in parallel (`pkg/runtime/toolexec/dispatcher.go:258-268`) yet `Resume <-chan ResumeRequest` is unkeyed by `toolCallID` and serialized by `confirmationMu` (`pkg/runtime/toolexec/dispatcher.go:810-845`); avoids multiplex complexity but limits to one interactive confirmation at a time.
- **Permission glob translation cost**: `globToRegexp` per pattern compiled to anchored `(?s)\A...\z` via `globCache sync.Map` (`pkg/permissions/permissions.go:280-293`); cache bounded by config rule count, but dynamic per-call `args` map allocation still on hot path.
- **MCP remote retry one-hop**: `isConnectionError` triggers `RestartAndWait(sessionMissingRetryTimeout=35s)` then one retry (`pkg/tools/mcp/mcp.go:783-789`); transient flakes recover, but longer partition exceeds single retry and `callTimeout` may cover it as one budget (`pkg/tools/mcp/mcp.go:771-774`).

## Failure Modes / Edge Cases

- **Duplicate tool names**: without `collectTools` dedup, Anthropic/Bedrock would 400; docker-agent keeps first toolset in config order and warns (`pkg/agent/agent.go:456-460`). Collision key includes kept/dropped origins so a `ToolListChanged` introducing new collision is re-warned.
- **Unknown tool hallucination after handoff**: dispatcher returns `Tool 'X' is not available...` `IsError` tool response (`pkg/runtime/toolexec/dispatcher.go:387-389`) so model can self-correct; no handler invoked, no process spawned.
- **Context canceled mid-batch**: `run` checks `ctx.Err()` early (`pkg/runtime/toolexec/dispatcher.go:377-382`) and `askUser` checks before emitting confirmation (`pkg/runtime/toolexec/dispatcher.go:813-822`); `Process` cancels sibling calls via `cancelBatch(errBatchCanceledByUser)` (`pkg/runtime/toolexec/dispatcher.go:253-267`), each sibling emits `canceled` error response so Responses API orphan-check passes.
- **Non-interactive session reaching Ask**: `askUser` detects `sess.NonInteractive` and deterministically denies (`ApprovalSourceNonInteractiveDeny`) instead of blocking forever on `Resume` (`pkg/runtime/toolexec/dispatcher.go:796-807`).
- **Malformed tool arguments**: `NewRuntimeHandler` error propagates to `translateError` → `ResultError("Error calling tool: ...")`; MCP `callTool` returns `failed to parse tool arguments: ...` error similarly—both surfaced as `IsError:true` tool message, not panic.
- **Pre_tool_use hook returning malformed UpdatedInput**: `applyHookModifiedInput` (`pkg/runtime/toolexec/dispatcher.go:672-688`) logs `Warn Failed to marshal modified tool input` and ignores, preserving original args.
- **Hook denies vs allow precedence**: `Result.Allowed=false` + `DecisionAsk` handled; `consultPreToolUseHook` checks `!result.Allowed` first before `Decision` switch (`pkg/runtime/toolexec/dispatcher.go:652-658`), ensuring `block` wins even if `permission_decision=allow`.
- **Large result spill failure**: `writeLargeToolResult` failure is logged `Warn` and returns `nil, nil`—no rewrite, original oversized payload flows through rather than failing the tool call (`pkg/hooks/builtins/limit_large_tool_results.go:86-88`).
- **MCP callTimeout not disturbing lifecycle**: `classifyCallToolError` (`pkg/tools/mcp/mcp.go:808-827`) attributes `DeadlineExceeded` only when `ctx.Err()==nil` (parent not canceled) and asserts `StateReady` unchanged after timeout (`pkg/tools/mcp/mcp_test.go:666`).
- **Shell working dir missing**: `checkWorkDir` (`pkg/tools/builtin/shell/shell.go:317-331`) surfaces `Error: working directory does not exist: <cwd>` instead of cryptic `fork/exec <shell>: no such file or directory` caused by `SysProcAttr` raw fork path.
- **Single-line >50 KiB payload**: `headLargeToolResult` would byte-slice mid-line; `readFileHeadNotice` detects `!strings.Contains(head,"\n")` and renders byte-range advice instead of `line`/`limit` (`pkg/hooks/builtins/limit_large_tool_results.go:125-133`).
- **Temp file path escaping**: `largeToolResultDir` uses `url.PathEscape(sessionID)` (`pkg/hooks/builtins/limit_large_tool_results.go:187-192`) so `../` in session ID cannot escape `/tmp/docker-agent-tool-results`.
