## Summary

Ollama is a long-lived Go inference daemon: `cmd/cmd.go:2015` `RunServer` does `net.Listen("tcp", envconfig.Host().Host)` then `server.Serve(ln)` (`server/routes.go:1949`), which owns an `http.Server` and a `Scheduler` (`server/sched.go:60`) that outlives any submitting client. The scheduler (`server/sched.go:214` `Run`, `225` `processPending`, `367` `processCompleted`) manages `llm.LlamaServer` runners keyed by model path (`server/sched.go:110`) with `loaded map[string]*runnerRef` and `refCount` expiry timers (`server/sched.go:393-411`). Transport is plain TCP HTTP on loopback `127.0.0.1:11434` (`envconfig/config.go:22` `Host()` default), guarded only by `allowedHostsMiddleware` (`server/routes.go:1803`) and optional `OLLAMA_AUTH` ed25519 request signing (`api/client.go:119`, `auth/auth.go:53`), not Unix-socket peer credentials. Inventory is a single global filesystem `OLLAMA_MODELS` (`envconfig/config.go:112`, `~/.ollama/models`) with manifest/blob store, stateless HTTP JSON endpoints (`/api/generate`, `/api/chat`, `/api/tags`, `/api/ps`), and `application/x-ndjson` streaming (`server/routes.go:2097`). No workspace-per-run directory, no run handle/attach-detach/reconnect, no durable job queue — inference is synchronous to the HTTP request `Context`; client disconnect cancels the generation via `c.Request.Context()` (`server/routes.go:466, 650`) but the loaded model remains resident per `keep_alive` (`api/types.go:94`), observable by any second client via `/api/ps` or `/api/tags` without shared memory.

## Rating

**5/10** — Strong daemon ownership and production-grade scheduler/VRAM-aware graceful shutdown with multi-client shared model inventory, but minimal local-API hardening: no Unix socket, no per-request workspace, no durable run handle, no stream reconnect, and authentication is opt-in/not enforced for local loopback. Work (`Generate`/`Chat` inference) does not outlive the submitting HTTP connection except as cached model residency; thin-client contract is stable HTTP+JSON+NDJSON, yet the dimension's explicit workspace-scoped, detach-reconnect, version-negotiated lifetime is largely absent.

## Answers to Dimension Questions

**Does client exit affect the accepted run?**
Partially. The daemon process owns the model residency long after the client exits, but the *inference itself* is tied to the HTTP request lifecycle, not a durable job. `cmd/cmd.go:2020-2025` `net.Listen`+`Serve` keeps the `Scheduler` (`server/routes.go:2004-2005` `InitScheduler`+`Run`) alive independent of any client; `server/sched.go:393-411` keeps the `runnerRef` loaded with an `expireTimer` derived from `KeepAlive` (`envconfig/config.go:129` default `5m`, `api/types.go:94`) even after `<-pending.ctx.Done()` (`server/sched.go:486-492`). However `GenerateHandler`/`ChatHandler` tie the computation's `Context` to `c.Request.Context()` (`server/routes.go:466,650,771-772`) and the client `chat`/`generate` wrappers cancel on `SIGINT` (`cmd/cmd.go:1770-1779,1902-1912`). If the originating client disconnects, `context.Canceled` aborts `r.Completion`/`r.Chat` (`server/routes.go:734,2902`) and the streaming channel closes — the tokens are lost, no background completion continues, and a new `loadOrUnloadModel` with `keep_alive:0` is the only explicit server-side cancellation (`server/routes.go:403`). So: model stays, but the accepted generation does not outlive the client; there is no durable run queue.

**Can another client find and observe the same run without sharing process memory?**
Yes for *inventory* (models/runners), no for *inflight token streams*. Any second process with the same `OLLAMA_HOST` (`envconfig/config.go:22`) can construct `api.ClientFromEnvironment()` (`api/client.go:74`) and call `List()`→`GET /api/tags` (`api/client.go:367`), `ListRunning()`→`GET /api/ps` (`api/client.go:386`, `server/routes.go:2271` `PsHandler`), `Show()`→`POST /api/show` (`api/client.go:413`), or `Version()` (`api/client.go:454`) — all plain HTTP JSON over TCP, no Go shared memory. `server/routes.go:2271` serializes `sched.loadedModels()` into `ProcessResponse{Models: []ProcessModelResponse{Name, Digest, Size, ExpiresAt, ContextLength}}` so a new client can discover what is loaded and when it will expire. But there is no `run_id` handle to re-attach to the *same* `Generate`/`Chat` NDJSON stream: the only stream is `c.Stream` (`server/routes.go:2099`) bound to the original `http.ResponseWriter`; there is no `GET /api/runs/:id/stream?offset=` or SSE resume. A second client can start a *new* inference against the same model (benefiting from the warm runner via `getRunner` `!needsReload` `server/sched.go:201`), but cannot snoop or resume the first client's byte stream.

**How are local callers authenticated and workspaces identified?**
*Local transport:* TCP `127.0.0.1:11434` by default (`envconfig/config.go:39-45`), listen address `envconfig.Host().Host` (`cmd/cmd.go:2020`). `allowedHostsMiddleware` (`server/routes.go:1803-1838`) permits loopback/private/`isLocalIP`/`allowedHost` or OS hostname when bound to loopback; when `addr` is non-loopback it bypasses checks (`server/routes.go:1811`). CORS is `AllowedOrigins` loopback + `app://*,tauri://*` (`envconfig/config.go:86`).
*Authentication:* By default **unauthenticated**. Only if `OLLAMA_AUTH=1` or `Host==ollama.com` does `api/client.go:119-130,184-195` set `Authorization: <pubkey>:<sig>` where `<sig>` is `auth.Sign(challenge)` using `~/.ollama/id_ed25519` (`auth/auth.go:53-85`, created by `initializeKeypair` `cmd/cmd.go:2040`). The server has no filtering middleware for those headers on inference routes (`server/routes.go:1871` only `cors+allowedHosts`); auth is only verified for cloud passthrough/registry challenges (`server/auth.go:53`, `server/cloud_proxy.go:384`) and `/_auth` style 401 `AuthorizationError` responses (`api/types.go:43`). Any local process can `curl http://127.0.0.1:11434/api/generate` without a token.
*Workspaces:* Single global filesystem: `envconfig/config.go:112` `Models()` → `OLLAMA_MODELS` or `~/.ollama/models`; manifests/blobs under that path (`server/routes.go:1955`, `app/server/server.go:253`). No per-client, per-request, or per-workspace directory is created; `GenerateRequest`/`ChatRequest` carry no `workspace` field (`api/types.go:62-179`). All clients share the same durable inventory; `OLLAMA_MODELS` is the only isolation knob and it is global to the daemon.

**What is the smallest stable contract a non-Go client must implement?**
Pure HTTP+JSON+NDJSON — no Go types required:
1. Resolve host via `OLLAMA_HOST` (`http://127.0.0.1:11434` default `envconfig/config.go:22`) and set `User-Agent: ollama/<version>` if desired (`api/client.go:139`).
2. `GET /api/version → {version:string}` (`server/routes.go:1879`) to check skew (client merely warns `cmd/cmd.go:2107`).
3. `POST /api/generate` with `GenerateRequest{model, prompt, stream?:bool, keep_alive?: "5m"|"-1"|0, options?:Runner}` (`api/types.go:62`) or `POST /api/chat` with `ChatRequest{model, messages:[{role,content}], stream?:bool, tools?:[], think?:bool|"high", format?:json|schema}` (`api/types.go:132`). Optional `GET /api/tags`, `GET /api/ps`, `POST /api/show`.
4. Handle responses: when `stream:false`, `application/json` single object; when streaming (default), `application/x-ndjson` lines of `GenerateResponse{response,thinking,done,done_reason,context,metrics}` (`api/types.go:890`) or `ChatResponse{message{role,content,thinking,tool_calls},done}` (`api/types.go:518`) until `done:true`. Optional `GET /` `HEAD /` heartbeat (`api/client.go:422` `HEAD /`→`200 "Ollama is running"` `server/routes.go:1877`).
5. Optional auth: if the server sets `OLLAMA_AUTH`, sign `METHOD,path?ts=...` as `base64(pubkey):base64(sig)` (`auth/auth.go:84`) with query `?ts=` (`api/client.go:128`) — otherwise ignore.
All `api/types.go` JSON field names/types, durations as Go `time.Duration` strings (`api/types.go:1232`), NDJSON newline framing (`server/routes.go:2135`), and error shape `{"error":string}` (`api/types.go:22`) constitute the stable wire; scheduler `runnerRef`, `LlmRequest`, `Scheduler` internals are not wire-visible.

## Architectural Decisions

* **Single daemon + global scheduler owns everything.** `Serve` creates one `Server`+`Scheduler`+`http.Server` (`server/routes.go:1983-2019`) that multiplexes all clients; models are cached by `ModelPath/Digest` (`server/sched.go:110`) with `refCount` and `sessionDuration` expiry, not per-client jobs. Tradeoff: maximal sharing, minimal per-run bookkeeping, but no per-run lifecycle primitives.
* **TCP HTTP on loopback, no UDS.** `Host()` defaults to `127.0.0.1:11434` (`envconfig/config.go:39`) and `GenerateRoutes` binds to it (`cmd/cmd.go:2020`); `allowedHostsMiddleware` does hostname/IP filtering (`server/routes.go:1775-1838`) rather than filesystem permissions or `SO_PEERCRED`. Keeps clients trivial (`curl`, any language `http.Client`) at cost of weaker local-only guarantees.
* **Stateless JSON over stateful streaming via NDJSON.** Request/response types live in `api/types.go`; streaming is newline-delimited JSON scanned with `bufio.Scanner` (`api/client.go:217-267`) and served via `gin.Stream` (`server/routes.go:2099-2144`). No session token, range, or resume; simplicity over resumability.
* **Keep-alive as de facto lifetime, not job durability.** `KeepAlive` (`api/types.go:94`) flows into `LlmRequest.sessionDuration` (`server/sched.go:32`) and eventually `runner.expiresAt` (`server/sched.go:405`) with `time.AfterFunc` expiry (`server/sched.go:395`). Any client's request extends the same timer (`useLoadedRunner` `server/sched.go:483`), so lifetime is shared and last-writer-wins.
* **Auth opt-in, not mandatory.** Keypair is auto-generated (`cmd/cmd.go:2043-2074`) but only sent when `UseAuth()` (`envconfig/config.go:232`) or `ollama.com` host (`api/client.go:119`). Local daemon accepts unauthenticated inference by design for dev ergonomics.

## Notable Patterns

* **Context-cascaded cancellation.** Every inference goroutine derives from `c.Request.Context()` (`server/routes.go:466,655,771`) plus a per-generation `context.WithCancel`; HTTP disconnect propagates `Canceled` to `llm.Completion/Chat` and terminates the channel without expiring the runner.
* **Single-loader gate with parallel warm path.** `activeLoading llm.LlamaServer` ensures only one model loads at a time (`server/sched.go:518-607`); `getRunner` can `useLoadedRunner` immediately when `!needsReload` (`server/sched.go:201`), allowing concurrent inference across warm models up to `NumParallel`/`MaxRunners`.
* **VRAM-aware eviction + recovery wait.** `processPending` evicts via `findRunnerToUnload`/`evictAllAndWait` (`server/sched.go:322-358`) and `load` predicts VRAM (`PredictServerVRAM`) with 80% free threshold (`server/sched.go:550`) then `waitForVRAMRecovery` polling (`server/sched.go:1441-1499`) for discrete GPUs.
* **Cloud passthrough overlay.** `routes.go:377-399,308-400,2518-2608` and `cloud_proxy.go:384` keep local JSON shape but proxy to `RemoteHost/RemoteModel` when `model.Config.RemoteHost != ""`, with `OLLAMA_REMOTES` allowlist (`envconfig/config.go:166`) — invisible to thin clients.
* **Graceful drain is whole-server, not per-request.** Signal handler `srvr.Close()+schedDone()+unloadAllRunners` (`server/routes.go:2025-2029`) and desktop `stop(proc)` with 5s grace (`app/server/server.go:146-176`) are the only drains; no per-run abort from a second client.

## Tradeoffs

* **Loopback TCP vs UDS.** TCP gives universal client reach (any language `HTTP`+`curl`, container `0.0.0.0` bind) but loses `0700` socket + `SO_PEERCRED` local-only proof and filesystem-permission workspace isolation that a UDS would provide; `allowedHostsMiddleware` is a best-effort hostname check (`server/routes.go:1775`) not a kernel guarantee.
* **Global `OLLAMA_MODELS` vs per-workspace.** One manifest tree simplifies sharing and `GET /api/tags` visibility for all clients, but prevents Aren-style per-workspace directories, per-run env injection, or isolated GC; the daemon is single-tenant.
* **Request-scoped generation vs durable run.** Synchronous NDJSON is simple to implement and correctly ties cost to the request `Context`, but fails the dimension's "work must outlive client" requirement: a long `num_predict` generation cannot be detached and re-attached after disconnect, and there is no status polling endpoint for that `run_id`.
* **Opt-in auth vs always-auth.** Unauthenticated loopback matches local dev UX (`ollama run llama3.2` works zero-config) but would fail a hardened multi-tenant stage where workspace data must be access-controlled; `OLLAMA_AUTH` exists but is not documented as local-route enforcement.
* **Coarse version (`Version` string) vs negotiable proto.** `version.Version = "0.0.0"` (`version/version.go:3`) exposed as a string (`server/routes.go:1879`) and `User-Agent` (`api/client.go:139`) with only a warning on mismatch (`cmd/cmd.go:2107`) avoids breaking changes but gives thin clients no way to feature-detect or negotiate per-method schemas; `PROTO` integer like `nats-server` does not exist.

## Failure Modes / Edge Cases

* **Client disconnect drops tokens irreversibly.** Scanner loop ends on `Body.Close` (`api/client.go:215`); server goroutine receives `ctx.Done()` and closes `ch` (`server/routes.go:653,748`). No replay buffer, no offset header, no retry after `scanner.Err()`; partial `GenerateResponse{Context}` (conversation memory) is lost.
* **No forced shutdown drain timeout on bare `serve`.** `Serve` does `srvr.Close()` (immediate) not `Shutdown(context)` with timeout (`server/routes.go:2026`); inflight `Completion` goroutines are canceled but `llm.LlamaServer.Close()` may race with runner expiry timers (`server/sched.go:1367-1379`); desktop wrapper adds 5s `stop` grace (`app/server/server.go:157`) but CLI `ollama serve` does not.
* **Max queue starvation.** `pendingReqCh` buffered `MaxQueue=512` (`envconfig/config.go:279`, `server/sched.go:93`); `getRunner` `default: req.errCh <- ErrMaxQueue → 503` (`server/routes.go:3113-3114`); bursty second-client traffic fails fast with no backpressure signal beyond HTTP 503.
* **Shared keep-alive expiry race.** Any client's `keep_alive` overwrites `runner.sessionDuration` (`server/sched.go:486`); a short-lived script (`--keepalive 0`) can unload a model another interactive `chat` still needs, forcing reload and eviction of siblings.
* **Host header bypass when bound to 0.0.0.0.** `allowedHostsMiddleware` early-returns `c.Next()` if listener is non-loopback (`server/routes.go:1811-1813`), so exposing `OLLAMA_HOST=0.0.0.0` intentionally disables local-host checks and relies on network firewalling.
* **Unauthenticated inventory enumeration.** `GET /api/tags`, `/api/ps`, `/api/show` require no token even when `OLLAMA_AUTH=1`; any local process (or remote when `Expose`/`0.0.0.0`) can enumerate models and loaded runners.
* **Model pull not isolated per caller.** `PullModel`/`PushModel` stream progress via single `ch chan any` (`server/routes.go:1133-1160`); concurrent pulls of the same `model:tag` interleave on the same blobs directory with no locking beyond manifest file primitives; second client's error is not distinguished.
* **Disk-full/filesystem corruption halts all clients.** `fixBlobs`/`PruneLayers` on startup (`server/routes.go:1955-1979`) and `OLLAMA_MODELS` global means one client's `pull` filling disk fails `load` for every subsequent scheduler `predict` (`server/sched.go:550`) and startup `Manifests` listing (`server/routes.go:1223`).

## Future Considerations

* Add an optional Unix-domain socket listener (e.g., `$HOME/.ollama/ollama.sock` with `0700` + bearer token file) alongside TCP, and promote `allowedHostsMiddleware` to helper that checks `SO_PEERCRED` when `addr` is `unix`; keeps thin TCP clients working while satisfying a hardened loopback stage.
* Introduce a durable job primitive (`POST /api/runs → {run_id}`, `GET /api/runs/:id`, `GET /api/runs/:id/stream?after=offset`, `POST /api/runs/:id/cancel`) that decouples inference `Context` from the submitting HTTP connection, backed by a bounded file journal per `OLLAMA_MODELS/runs/<run_id>` — would enable true detach/reconnect and second-client `cancel` for Phases 14-15.
