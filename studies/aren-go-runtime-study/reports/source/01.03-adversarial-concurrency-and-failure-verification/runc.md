## Summary

runc verifies concurrency and failure invariants through layered empirical testing rather than formal methods: (1) a CI matrix that builds both the unit tests *and the `runc` binary itself* with `-race` and then runs ~60 bats end-to-end suites against the race-instrumented binary; (2) an exhaustive lifecycle state-machine transition test that checks every valid edge succeeds and every invalid edge is rejected with `stateTransitionError`; (3) real fd-leak detection by diffing `/proc/self/fd` across container runs with GC disabled; (4) CRIU-based checkpoint/restore ("crash-recovery-adjacent") coverage including lazy-pages, pre-dump, userns, and external-netns variants; (5) regression tests explicitly tied to historical race/deadlock bugs (issues 2425, 4047, 4394, 5003); and (6) kernel-level race mitigations — pidfd for PID-reuse-proof signaling, freeze-then-sweep cgroup kills, atomic temp-file+rename state persistence, and re-derivation of container status from kernel ground truth (`refreshState`) rather than trusting cached state. Fuzzing exists but is thin: two OSS-Fuzz targets, one of which references a package that no longer exists in-tree. There are no goroutine-leak detectors, no synthetic-clock or scheduler seams, no property-based/metamorphic tests, and one known-racy TTY test is skipped instead of fixed.

## Rating

**7 / 10** — Exceptional breadth of *empirical* adversarial verification: race-instrumented end-to-end runs, exhaustive state-transition matrices, leak diffs, checkpoint/restore round-trips, multi-distro/kernel/rootless/cgroup-driver matrices, and dozens of regression tests pinned to specific historical bugs. Deductions for: stale/minimal fuzz coverage (`tests/fuzzing/oss_fuzz_build.sh:11` targets a removed package), a skipped known-racy test rather than a fix (`libcontainer/integration/execin_test.go:231`), absence of goroutine-leak detection and deterministic scheduling/clock seams, non-fsynced state writes, and expensive CI legs marked `continue-on-error` so they do not gate merges.

## Answers to Dimension Questions

**Which concurrency failures would ordinary coverage miss?**
The ones runc explicitly targets with dedicated machinery: (a) PID reuse between container init death and a later signal — covered structurally by start-time comparison (`studies/aren-go-runtime-study/sources/runc/libcontainer/container_linux.go:948`) and pidfd (`studies/aren-go-runtime-study/sources/runc/libcontainer/init_linux.go:727`), and behaviorally by kill/delete tests where init is gone and runc runs from a different process tree (`studies/aren-go-runtime-study/sources/runc/tests/integration/kill.bats:108-134`); (b) fork-during-kill sweeps leaving stray processes — prevented by freeze-before-enumerate (`studies/aren-go-runtime-study/sources/runc/libcontainer/init_linux.go:699-714`) and regression-tested via issue 4394's shared-pidns case (`studies/aren-go-runtime-study/sources/runc/tests/integration/kill.bats:136-157`); (c) fd leaks across repeated library invocations in one process — invisible to functional tests, caught by the fd diff (`studies/aren-go-runtime-study/sources/runc/libcontainer/integration/exec_test.go:1774-1779`); (d) data races on the `Container` mutex during concurrent CLI invocation — caught only because CI ships a `-race` binary into the bats suites (`studies/aren-go-runtime-study/sources/runc/.github/workflows/test.yml:119-120`). Ordinary line coverage would miss all four.

**Can the suite force cancellation at every lifecycle boundary?**
Partially. The sync protocol defines explicit boundaries (mount request, seccomp install, hooks, ready/run — `studies/aren-go-runtime-study/sources/runc/libcontainer/sync.go:41-51`), and failure at boundaries is exercised indirectly: wrong seccomp listener path (`studies/aren-go-runtime-study/sources/runc/tests/integration/seccomp-notify.bats:146`), failing post-start hooks killing the container (`studies/aren-go-runtime-study/sources/runc/libcontainer/container_linux.go:346-349`), and `procReady`-never-received fallbacks (`studies/aren-go-runtime-study/sources/runc/libcontainer/process_linux.go:1057`). But there is no mechanism to inject failure *at* an arbitrary boundary (no fault-injection hooks around `writeSync`/`readSync`), no test cancels `runc create` mid-setup, and the one attempt to stress a boundary repeatedly (300× console socket loop) is skipped as racy (`studies/aren-go-runtime-study/sources/runc/libcontainer/integration/execin_test.go:231`). No evidence found of cancellation testing at the pause/resume/checkpoint boundaries beyond happy-path sequencing.

**How does it prove absence of duplicate terminal events, leaks, and partial commits?**
Leaks: fd-set diffing with GC quiesced (`studies/aren-go-runtime-study/sources/runc/libcontainer/integration/exec_test.go:1720-1780`) and zombie detection via `system.Stat` state (`studies/aren-go-runtime-study/sources/runc/libcontainer/container_linux.go:948`). Partial commits: state.json replaced atomically via rename so readers see old-or-new, never torn (`studies/aren-go-runtime-study/sources/runc/libcontainer/container_linux.go:882-906`); mount/setup failures abort via the sync protocol's procError channel (`studies/aren-go-runtime-study/sources/runc/libcontainer/sync.go:140-149`). Duplicate terminal events: no direct proof technique exists; instead the design avoids the problem — terminality is *derived* from kernel truth on each query (`refreshState`, `studies/aren-go-runtime-study/sources/runc/libcontainer/container_linux.go:919-936`) rather than emitted once and trusted. Note the durability caveat: neither the temp file nor the directory is fsynced (`studies/aren-go-runtime-study/sources/runc/libcontainer/utils/utils.go:29-36`), so a power-loss could leave a stale-but-valid state.json; runc accepts this because `refreshState` reconciles against live process state anyway.

**Which techniques are proportionate for Aren Phase 1 rather than infrastructure-scale theatre?**
Proportionate, directly portable patterns: the exhaustive valid+invalid transition-matrix unit test (`studies/aren-go-runtime-study/sources/runc/libcontainer/state_linux_test.go:26-50`); fd-leak diffing with GC disabled; the `-race`-instrumented binary driven by black-box tests; atomic temp+rename persistence; polling-with-bounds helpers instead of sleeps (`studies/aren-go-runtime-study/sources/runc/tests/integration/helpers.bash:708-735`); an env-var gate for tests that mutate host state (`studies/aren-go-runtime-study/sources/runc/tests/integration/helpers.bash:677-682`); and regression tests named after their bug. Theatre to skip at Aren's stage: 5-distro lima VM matrices, feature-powerset × driver × arch × Go-version CI multiplication (~32 legs), scheduled cross-branch reruns, and OSS-Fuzz wiring before parser surfaces stabilize — especially since runc's own fuzz setup has gone stale (`studies/aren-go-runtime-study/sources/runc/tests/fuzzing/oss_fuzz_build.sh:11`).

## Architectural Decisions

1. **Race detection applied to the artifact, not just the tests.** Rather than only racing unit tests, CI compiles `runc` with `-race` and points the entire bats integration corpus at it (`studies/aren-go-runtime-study/sources/runc/.github/workflows/test.yml:119-120`, `Makefile:47-49`). This converts every end-to-end lifecycle test into a data-race probe across the real fork/exec/setns codepaths.
2. **Kernel ground truth over cached state.** Every status query re-validates liveness, freezer state, and fifo presence (`studies/aren-go-runtime-study/sources/runc/libcontainer/container_linux.go:919-936`). This is a deliberate architectural answer to "what if our state.json is wrong" — including after crashes — and it is why missing fsync is survivable.
3. **Exhaustive-negative testing of the state machine.** The transition test enumerates all six states and requires rejection of every illegal edge with the exact error type (`studies/aren-go-runtime-study/sources/runc/libcontainer/state_linux_test.go:36-49`), making the lifecycle FSM an enforced invariant rather than convention.
4. **Regression tests anchored to upstream issues.** Tests cite and reproduce issues 2425, 4047, 4394, 5003 inline (`studies/aren-go-runtime-study/sources/runc/tests/integration/kill.bats:107-134`, `libcontainer/integration/execin_test.go:231`, `tests/rootless.sh:96-98` comment), preserving failure knowledge in executable form.
5. **Feature-combinatorial environment testing.** Rootless features are toggled per powerset element with enable/disable hooks mutating real system state (`studies/aren-go-runtime-study/sources/runc/tests/rootless.sh:31-170`), acknowledging that runc's failure surface is environment-shaped, not input-shaped.

## Notable Patterns

- **Poll, don't sleep:** bounded-attempt `retry`/`wait_for_container`/`wait_pids_gone` helpers keep integration timing robust yet diagnosable (`studies/aren-go-runtime-study/sources/runc/tests/integration/helpers.bash:708-776`).
- **Single-poll multiplexing with graceful degradation:** fifo readiness waits on {fifo, pidfd} together when pidfd exists, degrading to 100ms polling with liveness checks on old kernels (`studies/aren-go-runtime-study/sources/runc/libcontainer/container_linux.go:271-327`) — the same invariant verified on both scheduler paths.
- **Warm-up baseline before leak assertion:** the fd-leak test runs one container first to whitelist intentionally-lifelong fds, avoiding false positives (`studies/aren-go-runtime-study/sources/runc/libcontainer/integration/exec_test.go:1731-1746`).
- **Mock at interface boundaries, not internals:** `mockProcess`/`mockCgroupManager` satisfy the same interfaces as production types (`studies/aren-go-runtime-study/sources/runc/libcontainer/container_linux_test.go:13-116`); filesystem-backed subsystems (intelrdt) get fabricated directory trees instead of abstraction layers (`studies/aren-go-runtime-study/sources/runc/libcontainer/intelrdt/util_test.go:15-16`).
- **Real-protocol mocks:** the systemd notify test speaks actual sd_notify wire format including SCM_RIGHTS fd passing (`studies/aren-go-runtime-study/sources/runc/notify_socket_test.go:55-88`).
- **Dangerous tests behind explicit opt-in env var**, propagated uniformly through CI, dev container, and host bootstrap (`studies/aren-go-runtime-study/sources/runc/.github/workflows/test.yml:22`, `Dockerfile:88`).

## Tradeoffs

- **Coverage breadth vs gating strictness:** criu-dev and fedora-rawhide legs are `continue-on-error` (`studies/aren-go-runtime-study/sources/runc/.github/workflows/test.yml:148,152`), so genuine checkpoint regressions on those configurations can merge unnoticed; the trade buys a sub-30-minute presubmit.
- **Atomic rename vs durability:** rename gives tear-free reads cheaply but without fsync a crash may resurrect a stale state.json (`studies/aren-go-runtime-study/sources/runc/libcontainer/container_linux.go:882-906`); correctness is rescued by query-time reconciliation, at the cost of transient inconsistency windows.
- **Polling robustness vs determinism:** retry loops make tests pass on slow machines but convert timing-sensitive bugs into flaky passes; nothing records how close a test came to its retry bound.
- **Skip-vs-fix for known races:** quarantining `TestExecInTTY` keeps CI green but leaves issue 2425 unfalsified by automation (`studies/aren-go-runtime-study/sources/runc/libcontainer/integration/execin_test.go:231`).
- **Empirical matrices vs cost:** the powerset/driver/arch multiplication finds environment-specific breakage but is unaffordable per-commit; it survives only because it lives in scheduled/lima lanes outside presubmit.

## Failure Modes / Edge Cases

Covered by dedicated tests: init dies before writing exec fifo (empty-fifo EOF path — `studies/aren-go-runtime-study/sources/runc/libcontainer/container_linux.go:329-339`); kill after init exit (`studies/aren-go-runtime-study/sources/runc/tests/integration/kill.bats:119`); shared-pidns process leakage (`studies/aren-go-runtime-study/sources/runc/tests/integration/kill.bats:136-157`); delete --force on paused containers (`studies/aren-go-runtime-study/sources/runc/tests/integration/delete.bats:144`); update while paused preserving pause (`studies/aren-go-runtime-study/sources/runc/tests/integration/update.bats:856-878`); memory update rejected by pre-check leaving container running (`studies/aren-go-runtime-study/sources/runc/tests/integration/update.bats:880-920`); malformed child log output must not kill forwarder (`studies/aren-go-runtime-study/sources/runc/libcontainer/logs/logs_linux_test.go:24-36`); EINTR restart inside poll loops (`studies/aren-go-runtime-study/sources/runc/libcontainer/container_linux.go:289-296`).

Known gaps observable in-tree: no fault injection into CRIU mid-restore (checkpoint failures tested mostly as clean pre-flight errors, e.g. stdin/stdout redirection blocking checkpoint — `studies/aren-go-runtime-study/sources/runc/tests/integration/checkpoint.bats:96-115`); no goroutine-leak assertions anywhere (only fd leaks); no test exercises state.json corruption/tampering on disk; the stale fuzz target means user-lookup parsing currently has zero fuzz coverage despite being network/config adjacent (`studies/aren-go-runtime-study/sources/runc/tests/fuzzing/oss_fuzz_build.sh:11`).

## Future Considerations

For a Phase 1 runtime like Aren adopting these techniques: (1) adopt the exhaustive transition-matrix pattern for its own lifecycle FSM from day one — it is cheap and catches protocol drift immediately; (2) build the `-race`-binary-driven black-box suite early, since retrofitting it onto a mature runtime is what makes runc's approach expensive; (3) add fsync (or document reconciliation) when state durability starts mattering beyond runc's query-time refresh model; (4) consider `goleak`-style goroutine accounting in unit tests — runc lacks it and relies on 10s-timeout shutdown probes instead (`studies/aren-go-runtime-study/sources/runc/libcontainer/logs/logs_linux_test.go:61-65`); (5) keep fuzz targets co-located with the parsers they cover and CI-verified so they cannot rot the way runc's did; (6) track retry-bound proximity in polling helpers to detect slow drift toward flakiness.
