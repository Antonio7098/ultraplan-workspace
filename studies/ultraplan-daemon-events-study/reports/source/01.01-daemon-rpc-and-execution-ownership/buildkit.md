## Summary

BuildKit isolates long-lived execution in `buildkitd` (`cmd/buildkitd/main.go:127`). CLI clients (`buildctl`, Buildx, `moby/client`) are thin gRPC callers over Unix socket, named pipe, systemd fd, or TCP (`cmd/buildkitd/main.go:760`). The wire surface is the `Control` protobuf service (`api/services/control/control.proto:14`) plus a multiplexed session stream tunneled over that same connection via `grpchijack` (`session/grpchijack/dial.go:18`). Accepted builds become `llbsolver.Solver` jobs (`solver/llbsolver/solver.go:210`) tracked by `control.Controller` (`control/control.go:90`) and persisted to a BoltDB-backed `history.Queue` (`solver/llbsolver/history/buildhistory.go:51`). The daemon owns storage under an absolute `Root` (`cmd/buildkitd/main.go:366`) and filesystem permission/TLS for local auth — no token model. Compatibility versioning (`solver/llbsolver/compat/compat.go:9`), `Info` version exchange (`api/services/control/control.proto:21`, `control/control.go:663`), and gateway capability negotiation (`frontend/gateway/pb/caps.go:88`) provide protocol versioning. Workspace context never relies on the daemon CWD: all inputs are streamed from the client as `local://` mounts over the session (`client/solve.go:141`, `solver/pb/ops.proto:198`). Reconnect is partial: status and build history can be re-observed by `Ref` (`control/control.go:594`, `solver/llbsolver/solver.go:465`), but the unary `Solve` RPC is not detach-resilient — canceling the caller's context aborts the solver, and session loss aborts I/O-dependent builds.

## Rating

**7 / 10 — Clear model with tests, explicit interfaces, and operational safeguards**

Rationale: daemon ownership is explicit (lockfile `cmd/buildkitd/main.go:385`, single-root, controller+history), transport choices are concrete and tested, gRPC contracts are proto-defined, and shutdown/history give observability. Downgraded from 8–9 because (a) no true detach: `Solve` remains bound to the caller's gRPC context (`control/control.go:409`), (b) local auth is only filesystem permissions + optional mTLS (`cmd/buildkitd/main.go:813`) with no peer-identity binding, (c) workspace scoping is implicit in the definition graph rather than an explicit namespace/authorization construct, and (d) reconnect requires out-of-band `Ref` sharing and still needs the session for local-context builds.

## Answers to Dimension Questions

### 1. Does a client exit affect execution?

**Partially yes.** The daemon (`control.Controller` `control/control.go:90` + `llbsolver.Solver` `solver/llbsolver/solver.go:68`) owns the job after `Solve` is accepted (`control/control.go:409` creates `solver.NewJob(id)` at `solver/llbsolver/solver.go:210`). The job's context is the gRPC `Solve` call's context. Because `Solve` is a unary RPC (`api/services/control/control.proto:17`), if the submitting `buildctl`/`buildx` process dies its gRPC connection breaks and the server context is canceled — `Solver.Solve` then returns `context.Cause(ctx)` (`solver/llbsolver/solver.go:302`) and the build aborts, persistently recorded as failure (`solver/llbsolver/history/buildhistory.go:531`). The `Status` stream (`control/control.go:594`) and history blob (`history/buildhistory.go:351`) survive for re-observation, but the build itself does not detach by default. An exception is builds that have already finished and been persisted — they remain queryable. Builds that depend on the `session` (local contexts `local://`, secrets, SSH, registry auth via `authprovider`, OCI stores) abort immediately on session loss because `session.Manager.handleConn` cancels and deletes the session on `ctx.Done()` (`session/manager.go:141`) and `Session.Close` stops its embedded gRPC server (`session/session.go:123`). So: daemon owns storage/lifecycle, but the execution is still fate-shared with the caller's RPC and session liveness.

### 2. What exactly crosses the daemon boundary?

Minimal stable surface is `api/services/control/control.proto:14`: `SolveRequest` (`Ref`, `Definition(pb.Definition)`, `Exporters[]`, `Frontend`+`FrontendAttrs`+`FrontendInputs`, `Cache`, `Entitlements`, `Session` id, `SourcePolicy`, `CompatibilityVersion` `api/services/control/control.proto:61`) and streaming `StatusResponse` (`Vertex`, `VertexStatus`, `VertexLog`, `VertexWarning` `api/services/control/control.proto:120`). The heavier workspace never crosses as filesystem paths — it is streamed as content-addressed mounts over the multiplexed session: `client/solve.go:141` attaches `filesync.NewFSSyncProvider(syncedDirs)` and `filesync.NewFSSyncTarget` for exporter outputs, tunneled via `session/grpchijack` `BytesMessage` `session/grpchijack/dial.go:18` over the `Session(stream BytesMessage)->stream BytesMessage` RPC `api/services/control/control.proto:19`. Secrets/SSH/auth/OCI content stores similarly cross as session attachables (e.g., `cmd/buildctl/build.go:196` `authprovider.NewDockerAuthProvider`, `client/solve.go:232` `sessioncontent.NewAttachable`). The daemon never receives host paths; the solver gets opaque LLB definitions plus session-bound handlers.

### 3. Can a client reconnect and recover the same operation?

**For observation, yes; for control, limited.** Any client that knows the `Ref` (client-generated `identity.NewID()` in `client/solve.go:107` and plumbed through `api/services/control/control.proto:62`, `control/control.go:315`) can call `Status(StatusRequest{Ref})` `control/control.go:594`. The solver tries `history.Status` first, then live job status `solver/llbsolver/solver.go:465` — so finished builds are readable from the persisted blob (`history/buildhistory.go:351`), and active builds stream live vertices. Separately, `ListenBuildHistory` `control/control.go:336` / `history/buildhistory.go:770` allows discovery of active/complete records without knowing the ref (filters, `ActiveOnly`, `Ref` filter). However, re-attaching to *drive* an in-flight build requires the same `sessionID` (`solver/llbsolver/solver.go:266` `j.SessionID = sessionID`) because the solver resolves sessions via `session.Manager.Get` `session/manager.go:149`. A new process cannot resurrect the previous session's `grpcServer` — a second client must create a new session; only the status/history view is recoverable. No first-class `ReattachSolve` or detach-handle API exists, unlike a true workspace-scoped job handle.

### 4. How is the local caller authenticated?

Two layers, both optional and coarse:

* **Filesystem identity for Unix sockets.** `getLocalListener` `cmd/buildkitd/main_unix.go:52` calls `sys.GetLocalListener(listenAddr, uid, gid)` (`cmd/buildkitd/main.go:776`) where `uid/gid` come from `cfg.GRPC.UID/GID` (default `os.Getuid/Getgid` `cmd/buildkitd/main.go:684`). Windows uses a named-pipe SDDL `cmd/buildkitd/main_windows.go:29` derived from `--group`. After creation on Unix, `os.Chmod(listenerPath,0666)` `cmd/buildkitd/main_unix.go:58` makes the socket world-readable — relying on directory permissions and `Root` `0700` `cmd/buildkitd/main.go:372`, not peer-credential checks.
* **Mutual TLS for TCP (and optionally Unix, but warned off).** `serverCredentials` `cmd/buildkitd/main.go:813` loads `tlscert/tlskey/tlscacert` into `tls.Config{ClientAuth: RequireAndVerifyClientCert}` `cmd/buildkitd/main.go:845`; missing TLS on `tcp` logs `"TLS is not enabled ... highly recommended"` `cmd/buildkitd/main.go:787`. The client pairs `WithCredentials`/`WithServerConfig` `client/client.go:279`, `client/client.go:290` into `loadCredentials` `client/client.go:306`. No per-request token, capability token, or namespace ACL beyond this. If TLS is absent and the socket is `0666`, any local UID can call any `Control` method, including privileged `network.host` entitlements (gated only by `cfg.Entitlements` allowlist, not caller identity).

### 5. Does daemon code ever depend on its own current working directory?

**No.** The daemon absolutizes and persists state under `cfg.Root`: `root, err := filepath.Abs(cfg.Root)` `cmd/buildkitd/main.go:366`, `os.MkdirAll(root,0700)` `cmd/buildkitd/main.go:372`, with file-lock `filepath.Join(root,"buildkitd.lock")` `cmd/buildkitd/main.go:385`, BoltDB `filepath.Join(cfg.Root,"history.db")` `cmd/buildkitd/main.go:903`, cache `filepath.Join(cfg.Root,"cache.db")` `cmd/buildkitd/main.go:897`. Debug/trace sockets and config are also absolutized (`appdefaults` `util/appdefaults/appdefaults_linux.go:4`). The only `Cwd` references in the repo are container-exec specs (`worker/tests/common.go:96` `Cwd:"/"`) and `fsutil` copy logic, not daemon startup. Workspace inputs never touch daemon FS directly — they are filtered via `fsutil.NewFilterFS` `client/solve.go:499` and streamed. So a `chdir` of `buildkitd` does not change build semantics.

## Architectural Decisions

* **Single-daemon owner + file-lock singleton.** `buildkitd` is the sole execution owner; `flock.TryLock` `cmd/buildkitd/main.go:385` prevents split-brain. Tradeoff: no horizontal scale, but strong local consistency for content store/leases. Chosen over per-workspace daemons.
* **gRPC Control as narrow waist.** All orchestration funnels through `api/services/control/control.proto:14` unary+streaming methods. Keeps client language-agnostic (Go, JS via grpc-gateway not needed). Chosen over REST/event-bus.
* **Session as inner gRPC tunneled over Control.Session.** Instead of sidecar ports, BuildKit reuses the single listener: `Control.Session(stream BytesMessage)` carries an inner gRPC channel (`session/grpchijack` `session/grpchijack/dial.go:18`). This solves NAT/firewall and lets `filesync`, `auth`, `sshforward`, `content`, `sourcepolicy` share one connection. Cost is custom `streamToConn` framing and metadata propagation via `headerSession*` `session/session.go:21`.
* **BoltDB + containerd leases for durability.** History `history/buildhistory.go:51` uses `bbolt` bucket `_records` + lease manager in `ns+"_history"` `history/buildhistory.go:104` to GC blobs. Enables reconnect for completed builds without external DB. Cost is single-node durability only.
* **CompatibilityVersion + CapSet two-track versioning.** `CompatibilityVersion` `solver/llbsolver/compat/compat.go:9` for solver semantics, plus `apicaps.CapList`/`CapSet` `util/apicaps/caps.go:58` for gateway feature advertisement. Allows old clients to negotiate gracefully instead of hard proto breaks. Interceptors are trivial (`grpcerrors` `util/grpcerrors/intercept.go:13`) so errors map cleanly through `status.FromProto`.
* **Absolute Root + 0700 + abs config.** `filepath.Abs` at startup `cmd/buildkitd/main.go:366` decouples from invocation CWD. Robust for systemd/socket-activation (`fd://` `cmd/buildkitd/main_unix.go:24`).

## Notable Patterns

* **Ref-by-client, history-by-server.** Client mints `Ref = identity.NewID()` `client/solve.go:107`/`cmd/buildctl/build.go:253` and uses it as idempotency + status key. Server never mints jobs anonymously beyond `solver.NewJob(id)` `solver/llbsolver/solver.go:210`. Pattern appears in `history.Queue` `ps.Send` pubsub keyed by `Ref`.
* **Inactivity timer for Status.** `statusInactivityTimeout = 5s` `client/solve.go:255` + channel `statusActivity` `client/solve.go:256` drives session teardown after idle, avoiding leaked goroutines.
* **GracefulStop via channel-passing.** `Opt.GracefulStop <-chan struct{}` `control/control.go:86` threaded through `QueueOpt.GracefulStop` `history/buildhistory.go:48` into two goroutines (`gc` loop `history/buildhistory.go:131` and `ps.Close` `history/buildhistory.go:139`) that coordinate on finalizer drain `history/buildhistory.go:502`. Minimal code, explicit lifecycle.
* **Throttled GC.** `throttle.After(time.Minute, c.gc)` `control/control.go:143` avoids GC storms from bursty `Solve` calls — functional throttle wrapper.
* **Lease-scoped blob writers.** `Queue.OpenBlobWriter` creates temporary lease `history/buildhistory.go:567` and auto-deletes on discard, binding content lifetime to build lifetime without manual refcount on every blob.

## Tradeoffs

* **Unix socket 0666 after uid/gid selection trades security for compatibility.** `cmd/buildkitd/main_unix.go:58` `Chmod 0666` lets rootless/podman flows work, but widens attack surface vs SO_PEERCRED checks. Alternative (restrict to `0600` or group `0660`) would break existing Docker-in-Docker setups — intentionally relaxed, flagged as caveat.
* **TLS opt-in rather than mandatory for TCP.** `getListener` only warns `cmd/buildkitd/main.go:787` if `tlsConfig==nil`. Keeps quick-start ergonomics; documented as dangerous because executor containers can call `Control` `README.md:703`. Stricter default (require mTLS for `tcp://`) would be safer but would regress dev UX.
* **Unary Solve couples liveness to caller context.** Simple gRPC semantics (no detached job CRD) make cancellation propagate predictably (`control/control.go:409` ctx). Downside: kill the submitting `buildctl` kills the build — violates the "kill client after acceptance still owns work" ideal. A detached handle (job ID + explicit `Cancel` RPC) would fix it but needs job persistence beyond memory.
* **History as second-class reattach.** `Status` falling back to `history.Status` `solver/llbsolver/solver.go:465` and `ListenBuildHistory` `history/buildhistory.go:770` give observability without making history authoritative for live control. Cheaper than replicating full Build/Status state machine into BoltDB, but leaves live-parse race windows.
* **Single listener for all planes (control, session, Gateway, OTEL export).** Reduces port surface (`cmd/buildkitd/main.go:401` `newGRPCListeners`, `cmd/buildkitd/main.go:1097` trace socket) and firewall rules. Couples data-plane throughput to control-plane head-of-line blocking — mitigated by large `DefaultMaxRecvMsgSize` `cmd/buildkitd/main.go:360` `client/client.go:46`.

## Failure Modes / Edge Cases

* **Stale daemon loss without recovery.** No supervisor: crash of `buildkitd` drops in-memory `sessions` map `session/manager.go:30`, `solver.Solver` jobs `solver/llbsolver/solver.go:115`, and `pubsub` `history/buildhistory.go:57`. `history.Queue` persists finished records, but active builds become `orphans` cleaned by `clearOrphans` `history/buildhistory.go:200` (missing lease → deleted). Open file-locks on `buildkitd.lock` are removed on `Unlock` `cmd/buildkitd/main.go:395`, so a new daemon starts clean — prior active work is lost.
* **Session-dependent builds fail silently on disconnect.** `Manager.HandleConn` deletes session on `ctx.Done()` `session/manager.go:137`; next `Get` with `noWait=false` blocks then errors `"no active session for %s"` `session/manager.go:173`. LLB fetch stages needing `filesync` will error `"failed to dial"` `session/grpchijack/dial.go:18` wrapped as `failed to solve` `client/solve.go:338`. No retry of session re-dial is attempted in `client/solve.go:248`.
* **Duplicate socket bind race.** `newGRPCListeners` `cmd/buildkitd/main.go:494` loops addrs and on any failure closes already-opened listeners `cmd/buildkitd/main.go:515` but returns partial `listeners` slice plus error — caller `main.go:401` aborts. If two daemons race, `flock.TryLock` `cmd/buildkitd/main.go:388` yields `"another instance running?"` `cmd/buildkitd/main.go:392`, but a config that omits the lock region (containerd plugin mode) could bind same socket and corrupt BoltDB.
* **Compatibility version mismatch.** Unknown `CompatibilityVersion` > `Current` errors `"upgrade buildkit (max supported: %d)"` `solver/llbsolver/compat/compat.go:35`; older unsupported version errors enumerate supported versions `compat.go:37`. Client that does not send version defaults to `Current` `control/control.go:422` — could silently use newer semantics.
* **Large payloads / resource exhaustion.** `grpc.MaxRecvMsgSize(defaults.DefaultMaxRecvMsgSize)` `cmd/buildkitd/main.go:360` / `client/client.go:46` caps messages; `history.Queue.ImportStatus` allocates `buf 32KiB` and grows to `sz` `history/buildhistory.go:390` — a malicious client could request huge `sz` (4-byte LE header) causing OOM. No per-Ref rate limit.
* **CWD-like pitfall via relative `local` paths.** `client/solve.go:211` `os.MkdirAll(ex.OutputDir)` trusts caller-supplied exporter output path; not daemon CWD but still directory confusion if client supplies relative path — mitigated because `client/solve.go` validates `OutputDir` required `solve.go:189` and `parseLocal` likely absolutizes? Search shows no daemon-side `Getwd` guard, so client-side relative resolves against client's CWD — correctly not daemon's, yet operator must be aware.
* **GracefulStop deadlock if finalizers leak.** `Queue.AcquireFinalizer` `history/buildhistory.go:489` stores `sync.OnceFunc` + `done` chan; `Finalize` blocks on `<-done`. If a provider never calls the returned `done()` func, `ps.Close()` `history/buildhistory.go:508` never fires, leaving `ListenBuildHistory` hanging after SIGTERM.

## Future Considerations

* **True detached Solve handle.** Promote `Ref` to a persistent job resource with `CreateJob` → `Start` split and explicit `CancelJob` RPC, so `Solve` can return immediately and survive caller disconnect. Persist job descriptor (definition, session ID optional) in `history.db` before starting solver, mirroring `Queue.update` `history/buildhistory.go:418` but for active jobs. Enables `buildctl` to `--detach` and `buildctl status --ref $REF` polling.
* **Peer-credential authentication for Unix sockets.** Add `SO_PEERCRED`/`getpeereid` check in `session/manager.go:94` `handleConn` and `control/control.go` interceptors, optionally binding peer UID to allowed `Entitlements`/`Exporters`. Fallback to mTLS for TCP keeps model uniform; removes reliance on `0666` `cmd/buildkitd/main_unix.go:58`.
* **Explicit workspace/namespace scoping.** Introduce top-level `namespace` or `workspaceID` field on `SolveRequest` (like `temporal` namespace validator) validated in an interceptor; isolate `Root` subdir, history bucket prefix, and content namespace per workspace. Currently `ns+"_history"` `history/buildhistory.go:104` is global — multi-tenant use requires out-of-band isolation.
