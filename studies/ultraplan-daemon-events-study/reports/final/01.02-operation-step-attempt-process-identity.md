## Executive Summary

All four systems must answer "which execution is this event for?" but they distribute the answer across radically different identity lattices — and only one answers the rubric's late-arrival quarantine question completely.

Temporal (9/10) provides a four-level lattice Workflow → Run → Step → Attempt with four independent rejectors for a stale completion: `RunId` fence, monotonic `Attempt`, anti-ABA `Stamp`, and `VersionHistories`/`VersionedTransition` branch + `VectorClock` (`proto/internal/temporal/server/api/persistence/v1/executions.proto:57`, `proto/internal/temporal/server/api/token/v1/message.proto:44`, `service/history/api/isactivitytaskvalid/api.go:60`). Dagster (8/10) has a formally typed `DagsterRun` → `ExecutionPlanSnapshot` → `ExecutionStep` → retry hierarchy with inter-run isolation via new `run_id` and `parent_run_id`/`root_run_id` lineage (`python_modules/dagster/dagster/_core/storage/dagster_run.py:236`, `python_modules/dagster/dagster/_core/storage/tags.py:34`) but intra-run step retries reuse `run_id+step_key` behind a counter only (`python_modules/dagster/dagster/_core/execution/retries.py:65`). BuildKit (6/10) and containerd (5/10) have no attempt entity at all: BuildKit collapses distinct operations that hash to the same `Vertex.Digest()` into one `edge` and coalesces concurrent executions with `flightcontrol.Group` on key `"exec"` (`solver/jobs.go:1219`, `solver/types.go:17`); containerd has no operation ledger, rejecting only via `ErrAlreadyExists` on `CreateBucket` (`core/metadata/containers.go:148`) and explicitly warning callers to tolerate duplicate `TaskExit` events (`core/runtime/v2/shim.go:605`).

The consistent convergence is that **durable intent survives the submitting process** in every source: client-minted `Ref` + BoltDB lease in BuildKit (`client/solve.go:107`, `solver/llbsolver/history/buildhistory.go:104`), `Container`/`Sandbox` row + shim `bootstrap.json` bundle in containerd (`core/containers/containers.go:30`, `core/runtime/v2/shim.go:294`), `DagsterRun` row + `ExecutionPlanSnapshot` in Dagster, `WorkflowExecutionInfo` + history branch in Temporal. The consistent divergence is **where attempt identity lives**: temporal stamps every cross-process token; dagster stamps only re-executions; buildkit and containerd stamp nothing.

## Core Thesis

**Identity is fate: systems that treat "same work" as "same ID" cannot quarantine late work, while systems that mint a new ID per attempt can — and the price is paid in storage width, cache complexity, and deduplication.**

- **Content-identified, attempt-collapsed (buildkit):** `Digest(LLB op + inputs)` is the primary key (`solver/types.go:17`, `solver/cachekey.go:35`). Two builds computing the same content share one `edge`, one `CacheKey`, one `sharedOp.gExecRes` memo, and one `MultiWriter` progress stream (`solver/jobs.go:583`, `solver/jobs.go:992`). This maximizes cache hits and minimizes storage but intentionally erases per-build attribution; late duplicate results are unquarantinable by design because they are defined as identical.

- **Resource-identified, operation-absent (containerd):** `namespace + container_id (+ exec_id)` names a durable resource, not an operation (`core/containers/containers.go:30`, `pkg/namespaces/context.go:38`). Lifecycle is emergent from `Container` existence plus shim-held `State{Status,Pid,ExitStatus,ExitedAt}` (`core/runtime/task.go:119`). Events carry `container_id+pid+topic+timestamp` (`core/events/events.go:27`, `api/events/task.proto:59`) but no `operation_id/attempt_id/causation_id`; retry is caller-responsible and shim publisher requeues the identical `Envelope` with `maxRequeue=5` (`pkg/shim/publisher.go:40`).

- **Intent-identified, tiered attempts (dagster):** The run is the durable workflow; steps are `step_key`/`StepHandle`-addressed and event-sourced (`python_modules/dagster/dagster/_core/execution/plan/plan.py:664`, `python_modules/dagster/dagster/_core/events/log.py:31`). Inter-run retries fence correctly (new `run_id`, new row, lineage via column + tag at `python_modules/dagster/dagster/_core/instance/runs/run_domain.py:143` and `python_modules/dagster/dagster/_core/storage/runs/schema.py:17`); intra-run retries fence only by event order (`STEP_UP_FOR_RETRY` → `STEP_RESTARTED` at `python_modules/dagster/dagster/_core/execution/plan/execute_step.py:448` and `python_modules/dagster/dagster/_core/events/__init__.py:1089`).

- **Lattice-identified, attempt-fenced (temporal):** Every level has its own monotonic fencer: workflow `Attempt` (`executions.proto:122`), workflow-task `WorkflowTaskAttempt+WorkflowTaskStamp` (`executions.proto:85`, `executions.proto:108`), activity `Attempt+Stamp` (`executions.proto:615`, `executions.proto:673`), callback/Nexus `Attempt` (`executions.proto:875`). The token `tokenspb.Task{Attempt, ActivityAttemptStamp, clock, version, branch_token}` (`token/v1/message.proto:44`) and `request_ids` map (`executions.proto:394`) plus branch validation (`mutable_state_impl.go:1003`) give at least four independent rejectors.

The choice is not a quality gradient alone. BuildKit's collapse is rational for a content-addressed build cache where "same inputs → same output" is the correctness spec and per-attempt isolation would halve hit rates. Containerd's absence is rational for a low-level runtime that explicitly delegates workflow semantics to orchestrators (Kubelet, BuildKit). Dagster and Temporal both need run longevity for user-facing pipelines/workflows, but differ on failure cost: step-level retry-ability without run proliferation (dagster) vs. run-level failure atomicity with store-per-retry (temporal).

## Approach Models

Models cluster by **where attempt identity is minted** (nowhere → counter → row → token). Ordering is by fencing strength, not by overall quality.

### A. Content-Addressed, Attempt-Collapsed (buildkit — 6/10)

Primary identities are `SolveRequest.Ref` (`client/solve.go:107`, `api/services/control/control.proto:62`) scoped to `SessionID` (`session.Group` at `solver/jobs.go:80`) and, operationally, `Vertex.Digest()` (`solver/types.go:17`). The graph is `Solver.jobs map[string]*Job` (`solver/jobs.go:41`) multiplexed over `map[digest] *state` (`solver/jobs.go:43`) where each state holds `parents`/`childVtx` and `state.jobs` fan-out (`solver/jobs.go:52`). An `edge` is the smallest checkpointable unit (`solver/edge.go:41`, status at `solver/edge.go:14`) keyed by `(Vertex, Index)` (`solver/types.go:44`) with `result/cacheMap/keys/cacheRecords` and `CacheKey`(`ID,digest,vtx,output,deps,ids`) persisted via `CacheManager`/`CacheKeyStorage` (`solver/types.go:173`, `solver/cachekey.go:35`). Attempt identity is absent by design: `sharedOp.gExecRes Do(ctx,"exec",…)` memoizes one `Exec` call per digest (`solver/jobs.go:1219`) and `scheduler.edge.index.LoadOrStore` merges duplicate subgraphs (`solver/scheduler.go:156`, `solver/edge.go:124`). Correlation uses `Ref`, `SessionID`, `ProgressGroup`, and OTel `MultiSpan` (`solver/jobs.go:61`, `solver/jobs.go:1374`, `solver/llbsolver/provenance.go:449`) but no per-attempt token crosses `worker.Worker.Executor.Run(ctx,id,…)` (`worker/base/worker.go:80`) — `id` is an ephemeral container task handle (`worker/cacheresult.go:43`). The history layer adds durability after the fact: `BuildHistoryRecord{Ref,…}` in bbolt buckets `_records/_version` protected by lease `ref_<Ref>` in namespace `<ns>_history` (`api/services/control/control.proto:203`, `solver/llbsolver/history/buildhistory.go:38`, `solver/llbsolver/history/buildhistory.go:418`).

- Why it fits: build cache correctness is "same inputs → same bits" regardless of who asked; sharing saves orders of magnitude.
- Why it diverges on retries: there is no retry loop to fence — `solver` grep for `retry/Retry` returns only `attemptUnpackDockerCompatibility` (`solver/pb/ops.proto:356`) as negative evidence.

### B. Resource-Owned, Operation-Absent (containerd — 5/10)

Durable tier is `(Namespace, Container.ID)` and `(Namespace, Sandbox.ID)` (`core/containers/containers.go:30`, `core/sandbox/store.go:29`) persisted via Bolt transactions `CreatedAt/UpdatedAt` (`core/metadata/containers.go:142`) and mirrored on filesystem as `Bundle{ID,Path,Namespace}` at `<state>/<ns>/<id>` (`core/runtime/v2/bundle.go:121`). `Container.SandboxID` and bundle path give the only parent/root linkage (`core/containers/containers.go:80`, `core/runtime/runtime.go:54`). Ephemeral tier is `Task:Process+PID()` and `ExecProcess` (`core/runtime/task.go:63`, `core/runtime/task.go:35`) materialized as a shim OS process `ShimInstance{ID,Namespace,Bundle,Endpoint(address,version)}` (`core/runtime/v2/shim.go:228`) forked by `ShimManager.Start` (`core/runtime/v2/shim_manager.go:208`) and reattached via `bootstrap.json`/`restoreBootstrapParams` (`core/runtime/v2/shim.go:294`, `core/runtime/v2/shim_manager.go:353`). The smallest checkpoint is the Bolt transaction or, for tasks, a CRIU `Checkpoint(path)` (`core/runtime/task.go:78`). Event model is `Envelope{Timestamp,Namespace,Topic,Event:typeurl.Any}` (`core/events/events.go:27`, `api/types/event.proto:27`) with handler `Publish(ctx,topic,event)` deriving namespace from context (`core/events/exchange/exchange.go:81`) and per-task payloads `TaskExit{container_id,id,pid,exit_status,exited_at}` (`api/events/task.proto:59`). Processing shims forward via `RemoteEventsPublisher{queue, requeue}` with `maxRequeue=5` and `Sleep(1*count)` reuse of identical envelope (`pkg/shim/publisher.go:40`, `pkg/shim/publisher.go:102`, `pkg/shim/publisher.go:127`). Leases `Lease{ID,CreatedAt,Labels}` with GC via `gcContext` scan (`core/leases/lease.go:42`, `core/metadata/db.go:383`) replace any operation ledger.

- Why it fits: low-level runtime delegates orchestration semantics upward; leases/containers are the contract.
- Why it diverges: multi-process span is intentional (lifecycle `Create→Start→Wait→Delete` across distinct gRPC calls against `container_id==task_id` at `core/runtime/v2/task_manager.go:159`, `core/runtime/v2/shim.go:737`), but without an attempt key the documented duplicate `TaskExit`/`TaskDelete` from `cleanupAfterDeadShim` vs shim-on-close (`core/runtime/v2/shim.go:596`, `core/runtime/v2/shim.go:605`) must be tolerated by callers.

### C. Run-Centric with Two-Tier Retries (dagster — 8/10)

Durable intent is `DagsterRun{run_id,job_name,status,tags,root_run_id,parent_run_id,job_snapshot_id,execution_plan_snapshot_id,step_keys_to_execute}` (`python_modules/dagster/dagster/_core/storage/dagster_run.py:236`, status enum at `python_modules/dagster/dagster/_core/storage/dagster_run.py:54`, schema `RunsTable.c.run_id PK` at `python_modules/dagster/dagster/_core/storage/runs/schema.py:17` and `RunTagsTable.c.run_id FK ON DELETE CASCADE` at `python_modules/dagster/dagster/_core/storage/runs/schema.py:75`). The checkpoint is `ExecutionPlanSnapshot{steps,step_keys_to_execute,initial_known_state,snapshot_version=1,executor_name}` (`python_modules/dagster/dagster/_core/snap/execution_plan_snapshot.py:44`) plus `KnownExecutionState{previous_retry_attempts,mappings,ready_outputs,parent_state}` (`python_modules/dagster/dagster/_core/execution/plan/state.py:101`, `python_modules/dagster/dagster/_core/execution/plan/active.py:117`) and `PastExecutionState(run_id,produced_outputs,parent_state)` linked list (`python_modules/dagster/dagster/_core/execution/plan/state.py:32`). Intra-run retries use `RetryPolicy(max_retries,delay,backoff,jitter)` (`python_modules/dagster/dagster/_core/definitions/policy.py:34`) driving `RetryState._attempts` (`python_modules/dagster/dagster/_core/execution/retries.py:65`) and `ActiveExecution._waiting_to_retry/_pending` gated by `RetryMode.ENABLED/DISABLED/DEFERRED` (`python_modules/dagster/dagster/_core/execution/plan/active.py:550`, `python_modules/dagster/dagster/_core/execution/retries.py:30`). Inter-run retries mint new rows via `create_reexecuted_run/_reexecute_job` with `root_run_id=parent.root_run_id or parent.run_id, parent_run_id=parent.run_id` (`python_modules/dagster/dagster/_core/execution/api.py:569`, `python_modules/dagster/dagster/_core/instance/runs/run_domain.py:446`) and tag lineage `PARENT_RUN_ID_TAG/ROOT_RUN_ID_TAG` (`python_modules/dagster/dagster/_core/storage/tags.py:34`), enumerated by `get_run_group(run_id)` (`python_modules/dagster/dagster/_core/storage/runs/sql_run_storage.py:555`). - Why it fits: DB as source of truth makes runs survive any orchestrator process; two tiers separate transient step blips from run-level resume-from-failure and auto-retry (`auto_reexecution_should_retry_run` at `python_modules/dagster/dagster/_core/execution/retries.py:83`).

### D. Lattice-Fenced Durable Execution (temporal — 9/10)

Four levels, each with monotonic counter and fence:

- **Workflow (intent)** identified by `(NamespaceId,WorkflowId)` (`executions.proto:57`) with idempotency via `WorkflowExecutionState.create_request_id` + `request_ids map<RequestId,RequestIDInfo>` (`executions.proto:382`, `executions.proto:394`). Retried/continued workflows form a chain via `Attempt` (`executions.proto:122`), `NewExecutionRunId/SuccessorRunId` forward and `FirstExecutionRunId/OriginalExecutionRunId` back (`executions.proto:157`, `executions.proto:289`, `executions.proto:149`, `executions.proto:270`), plus `RootWorkflowId/RootRunId` (`executions.proto:227`) and `Parent{NamespaceId,WorkflowId,RunId,InitiatedId,Clock,InitiatedVersion}` (`executions.proto:59`, `service/history/workflow/retry.go:240`). `SetupNewWorkflowForRetryOrCron` increments `attempt = previous.Attempt+1` when `CONTINUE_AS_NEW_INITIATOR_RETRY` else `1` and writes it on `WorkflowExecutionStarted` and first WFT (`service/history/workflow/retry.go:271`, `service/history/workflow/retry.go:294`).

- **Run** is one `WorkflowExecutionState{run_id,state,status,…}` row (`executions.proto:381`) containing `VersionHistories{current_version_history_index,histories[branch_token,items[event_id,version]]}` (`history/v1/message.proto:19`) and `VersionedTransition{namespace_failover_version,transition_count}`/`transition_history` (`executions.proto:208`) for branch fencing; `MutableStateImpl` holds all pending maps keyed by stable event IDs (`service/history/workflow/mutable_state_impl.go:128`, identities at `mutable_state_impl.go:1003`, `mutable_state_impl.go:1011`).

- **Step** is a pending-map entry addressed by its scheduling event ID: `ActivityInfo{sched_batch_id,start_time,started_event_id,activity_id,attempt,stamp,paused,…}` by `scheduled_event_id` (`executions.proto:592`), `TimerInfo{timer_id,…}` (`executions.proto:750`), `ChildExecutionInfo{initiated_event_id,started_workflow_id,started_run_id,…}` (`executions.proto:761`), `SignalInfo/RequestCancelInfo` (`executions.proto:790`, `executions.proto:781`), `NexusOperationInfo/CallbackInfo` (`executions.proto:888`, `executions.proto:855`), and `sub_state_machines_by_type` for CHASM (`executions.proto:212`). Checkpoint is the `HistoryEvent` journal; transactional unit is one `hBuilder` append mutating one map entry (`mutable_state_impl.go:414`).

- **Attempt** is explicit per step: `WorkflowTaskAttempt`/`WorkflowTaskStamp`/`WorkflowTaskAttemptsSinceLastSuccess` (`executions.proto:85`, `executions.proto:108`, `executions.proto:114`), `ActivityInfo.Attempt+Stamp` where `UpdateActivityInfoForRetries(ai,…,attempt,…)` sets `ai.Attempt=attempt` and bumps `Stamp` iff `attempt>previousAttempt` then clears `StartedEventId/RequestId/StartedTime/StartedClock` (`service/history/workflow/activity.go:59`), computing next delay via `ExponentialBackoffAlgorithm(Attempt)` (`service/history/workflow/activity.go:222`); workflow-task lifecycle via `HasStartedWorkflowTask` and `AddFirstWorkflowTaskScheduled(parentClock,…)` (`mutable_state_impl.go:3394`, `mutable_state_impl.go:9574`), with transient vs. speculative distinction on `WorkflowTaskAttempt>1` (`service/history/ndc_task_util.go:272`).

Cross-process dispatch is fully tokenized: `tokenspb.Task{namespace_id,workflow_id,run_id,scheduled_event_id,attempt,activity_id,clock,started_event_id,version,activity_attempt_stamp}` (`token/v1/message.proto:39`) forged by `NewWorkflowTaskToken(…,attempt,clock,version)` and `NewActivityTaskToken(…,attempt,activityAttemptStamp,…)` (`common/tasktoken/token.go:9`, `common/tasktoken/token.go:33`) and routed via `TaskQueuePartition{task_queue,partition_id}` (`taskqueue/v1/message.proto:60`) to `PhysicalTaskQueueInfo{pollers[]}` (`taskqueue/v1/message.proto:40`). Activity binding records `task_queue/started_identity/worker_control_task_queue/priority/started_clock` (`executions.proto:629`). Causation carries `clockspb.VectorClock`, `Link{WorkflowEvent{EventRef/RequestIdRef}}`, and `Callback/HSMCompletionCallbackArg` (`executions.proto:62`, `executions.proto:810`, `service/history/workflow/mutable_state_impl.go:799`). Stale completions are rejected at `isActivityTaskValid`/`isWorkflowTaskValid` requiring `Stamp==request.Stamp` and `StartedEventId==Empty` (`service/history/api/isactivitytaskvalid/api.go:60`, `service/history/api/isworkflowtaskvalid/api.go:63`, `service/history/api/recordactivitytaskstarted/api.go:97`, `service/history/api/recordworkflowtaskstarted/api.go:78`) with `SanitizeMutableState`/`Checksum` guard (`mutable_state_impl.go:618`, `mutable_state_impl.go:557`).

- Why it fits: durable workflow service where any history/matching/frontend/worker host may die and any other must continue without ambiguity.

## Pattern Catalog

### Pattern 1: Durable Intent Key + Client-Minted Handle with Synchronous Persistence

**Problem:** After the submitter dies, an observer needs a stable handle to find the operation without scanning logs.

**Sources:** All four. BuildKit `SolveRequest.Ref = SolveOpt.Ref ?? identity.NewID()` returned before execution (`client/solve.go:107`, lease `ref_<Ref>` at `solver/llbsolver/history/buildhistory.go:279`); containerd `Container.ID` validated (`pkg/identifiers/validate.go:52`) and created via `CreateBucket` → `ErrAlreadyExists` on duplicate (`core/metadata/containers.go:148`) and filesystem bundle `<root>/<namespace>/<id>` (`core/runtime/v2/bundle.go:52`); Dagster `run_id = make_new_run_id()` + `ExecutionPlanSnapshot` in same `create_run` (`python_modules/dagster/dagster/_core/instance/runs/run_domain.py:86`, `python_modules/dagster/dagster/_core/storage/dagster_run.py:236`); Temporal `(WorkflowId,RunId)` + `WorkflowExecutionState.create_request_id` + `request_ids` map (`executions.proto:57`, `executions.proto:382`, `executions.proto:394`) deduping `StartWorkflowExecutionRequest.RequestId`.

**Why it works:** Handle is minted at submission edge, persisted before work starts, and is the join key for all later queries (`Status(Ref)`, `LoadContainer`, `get_run_by_id`, `DescribeWorkflowExecution`). Persistence is in the rendezvous (BoltDB, SQL, shard) not in the worker.

**When to copy:** Any operation that must survive submitter or daemon restart. Mint synchronously, return handle in the acceptance reply, store handle before dispatching work.

**When overkill/risky:** Ephemeral queries with no side effect; streaming-only transforms where materialization cost exceeds durability value. Weak ID entropy (BuildKit `NewID()` 129-bit random at `identity/randomid.go:43` or permissive `identifiers.Validate` `[A-Za-z0-9._-]{max 76}`) may still collide under hostile load — add server-side monotonic suffix if uniqueness is a safety property.

### Pattern 2: Parent/Root Lineage as First-Class Columns + Tag/Header Denormalization

**Problem:** Retries, re-executions, sandboxes, and child workflows need to answer "which logical operation does this belong to?" for grouping, GC, and UI without recursive scans.

**Sources:** Temporal `RootWorkflowId/RootRunId` and `Parent*` on every continuation/child (`executions.proto:59`, `executions.proto:227`, `service/history/workflow/retry.go:240`); Dagster `root_run_id`/`parent_run_id` columns plus mirrored tags `dagster/parent_run_id`/`dagster/root_run_id` (`python_modules/dagster/dagster/_core/storage/tags.py:34`, invariant check at `python_modules/dagster/dagster/_core/storage/dagster_run.py:311` and group query `get_run_group` by `ROOT_RUN_ID_TAG` at `python_modules/dagster/dagster/_core/storage/runs/sql_run_storage.py:555`); containerd `Container.SandboxID` and bundle namespace path (`core/containers/containers.go:80`, `core/runtime/v2/bundle.go:52`); BuildKit DAG `state.parents`/`childVtx` (`solver/jobs.go:52`) and synthetic export vertices `exporterVertexID(j.SessionID,i)` (`solver/llbsolver/solver.go:415`).

**Why it works:** Denormalizing lineage onto every descendant row gives O(1) group membership and O(index) enumeration. Dagster's dual encoding (column for invariant + tag for query reuse) shows backward-compat evolution. Temporal's `ParentClock`/`ParentInitiatedVersion` handles failover ordering.

**When to copy:** Any system with retry chains, sandboxed containers, or child workflows. Mirror to queryable tags/headers but keep authoritative fields as typed columns with `NOT NULL` paired invariants (`Must set both root_run_id and parent_run_id` at `dagster_run.py:311`).

**When overkill:** Single-level jobs with no children/retries. Beware unbounded tag/header growth and delete cascading (`RunTagsTable ON DELETE CASCADE` at `dagster storage/runs/schema.py:75` orphans `get_run_group`; Temporal's root tree is denormalized not transactional).

### Pattern 3: Event-Id-Addressed Step Identity (Not Just Name-Addressed)

**Problem:** Name collisions or redefinitions across retries need stable, pre-execution addressing so cancellation, retry, and heartbeat target the exact invocation.

**Sources:** Temporal `pendingActivityInfoIDs`/`pendingTimerInfoIDs`/`pendingChildExecutionInfoIDs` maps keyed by `ScheduledEventId`/`TimerId`/`InitiatedEventId` (`service/history/workflow/mutable_state_impl.go:128`, `executions.proto:592`, `executions.proto:750`, `executions.proto:761`); Dagster `ExecutionStep{step.key/handleType}` and `StepOutputHandle(step_key,output_name,mapping_key)` (`python_modules/dagster/dagster/_core/execution/plan/plan.py:664`) with `UnresolvedStepHandle`/`ResolvedFromDynamicStepHandle` taxonomy (`plan/plan.py:85`) and `dynamic_mappings` in state (`plan/state.py:108`); BuildKit `Edge{Vertex,Index}` per output index (`solver/types.go:44`) with content digest as identity (`solver/types.go:17`).

**Why it works:** The step is addressed at schedule time before any worker polls; late heartbeats and completions carry the scheduling `event_id` and can be validated even if outputs share a name. Dagster's `_update_tracking_dict` using `unresolved_form.to_key()` for resolved handles (`state.py:207`) and Temporal's empty-`StartedEventId` check illustrate subtle correctness.

**When to copy:** Any step that may be retried or dynamically expanded. Allocate `event_id`/`mapping_key` at scheduling, store it in mutable state, require it on every mutation.

**When risky:** If addressing is content-derived (BuildKit `Digest()`), distinct callers that happen to compute same content collapse — choose event-id vs content-id deliberately based on whether deduplication or isolation is the invariant.

### Pattern 4: Attempt Counter + Anti-ABA Stamp Pair for Fencing

**Problem:** A monotonic attempt number alone cannot distinguish ABA replays (1→2→1 after reset/pause). A raw token alone obscures user-visible retry count. Together they give observability and fencing.

**Sources:** Temporal gold standard: activity `Attempt` + `Stamp` where `Stamp` bumps iff `attempt>previousAttempt` (`service/history/workflow/activity.go:87`, `executions.proto:615`, `executions.proto:673`) and workflow-task `WorkflowTaskAttempt + WorkflowTaskStamp` (`executions.proto:85`, `executions.proto:108`), validated via `StartedEventId==Empty && Stamp==request.Stamp` (`service/history/api/isactivitytaskvalid/api.go:60`). Dagster partial: `RetryState._attempts[step_key]` + `KnownExecutionState.previous_retry_attempts` (`retries.py:65`, `state.py:101`) plus `STEP_RESTARTED` frontier but no stamp; Containerd/BuildKit absent (BuildKit's `flightcontrol` reuses `"exec"` key with no attempt, `solver/jobs.go:1219`; Containerd's `item.count` requeues same `Envelope` with no `attempt_id`, `pkg/shim/publisher.go:40`).

**Why it works:** Counter is human-meaningful for backoff/UI (`PendingActivityInfo.Attempt` at `activity.go:92`, dagster `RetryPolicy.calculate_delay`), stamp is the fencing nonce that invalidates stale tokens even if attempt value repeats after reset (`ResetActivity` resets to 1 at `activity.go:319`). Token validation fails closed with `ObsoleteMatchingTask`/`Activity task with this stamp not found`.

**When to copy:** Always when retries cross process boundaries and late completions are not benign. Expose counter to users/surfaces, keep stamp on the token and in mutable state only, compare equality not monotonicity on completion.

**When overkill:** In-process synchronous retries where straggler cannot outlive the call. Don't expose stamp to SDKs if you want to reserve format freedom (Temporal's `Stamp` invisible to SDKs trade-off at `activity.go:120`).

### Pattern 5: Tokenized Cross-Process Dispatch with Self-Describing Validation

**Problem:** Any host must be able to accept a worker's completion without session affinity, while rejecting stragglers.

**Sources:** Temporal `tokenspb.Task` (`token/v1/message.proto:39`) → `NewWorkflowTaskToken/NewActivityTaskToken` (`common/tasktoken/token.go:9`, `common/tasktoken/token.go:33`) validated on `RecordWorkflowTaskStarted`/`RecordActivityTaskStarted`/`IsActivityTaskValid` (`service/history/api/recordworkflowtaskstarted/api.go:78`, `service/history/api/recordactivitytaskstarted/api.go:97`). Analogues: containerd `bootstrap.json{address,protocol,version}` + `Endpoint()` (`core/runtime/v2/shim.go:294`, `core/runtime/v2/shim.go:464`) for shim reattachment; Dagster `ExecutionPlanSnapshot` ship + `rebuild_from_snapshot`/`can_isolate_steps` (`plan/plan.py:1027`, `plan/plan.py:1161`) and `LaunchRunContext`/`ResumeRunContext` (`launcher/base.py:15`) for multiprocess/k8s; BuildKit lease `ref_<Ref>` + `SessionID` + OTel `MultiSpan` (`history/buildhistory.go:279`, `solver/jobs.go:61`).

**Why it works:** Token packs `(namespace,workflow,run,scheduledEventId,attempt,stamp,clock,version,startedTime)` so the history host that receives the completion can load `WorkflowKey(namespace,workflow,run)` and reject if any coordinate mismatches without extra lookups. Dagster snapshot packs `executor_name`/`snapshot_version=1` similarly.

**When to copy:** Any fan-out to external executors. Pack all fencing coordinates, version them, sign or checksum if crossing trust boundary (`WorkflowMutableState.Checksum` at `executions.proto:804`, `mutable_state_impl.go:557`).

**When overkill:** In-process executor only.

### Pattern 6: Event-Sourced Checkpoint with Unified Envelope

**Problem:** Checkpoint granularity, audit, and UI metrics need a single timeline even when steps run in parallel processes.

**Sources:** Dagster `EventLogEntry(run_id,step_key)` + nested `dagster_event.step_handle` + `DagsterEventType{STEP_START,STEP_OUTPUT,STEP_SUCCESS,STEP_FAILURE,STEP_SKIPPED,STEP_UP_FOR_RETRY,STEP_RESTARTED}` replayed by `build_run_step_stats_from_events` to synthesize `attempts/attempts_list` (`events/log.py:31`, `events/__init__.py:476`, `__init__.py:1089`, `execution/stats.py:146`). Temporal `HistoryEvent{eventId,version,eventType,attributes}` journaled per branch (`history/v1/message.proto:19`, `message.proto:27`), grouped by `VersionHistories+VersionedTransition` (`executions.proto:147`, `executions.proto:208`) with links `Link.WorkflowEvent{EventRef/RequestIdRef}` and callbacks `Callback{links[]}` (`executions.proto:810`, `mutable_state_impl.go:799`). BuildKit `edge.status∈{initial,cacheFast,cacheSlow,complete}` state machine (`solver/edge.go:16`) plus `CacheKey`/`CacheRecord` and `edgeState` pipe fan-out (`solver/edge.go:731`); containerd `Envelope{Timestamp,Namespace,Topic,Event:typeurl.Any}` + task payloads (`core/events/events.go:27`, `api/events/task.proto:59`) routed via `validateEnvelope`/`Subscribe(filters)` (`core/events/exchange/exchange.go:224`, `core/events/exchange/exchange.go:128`).

**Why it works:**One envelope type lets storage, replay, and metrics share scanning code. Stable `step_key`/`eventId` keys make log replay deterministic. Dagster's `KnownExecutionState.ready_outputs: set[StepOutputHandle]` and Temporal's `ActivityInfo.LastAttemptCompleteTime/LastHeartbeatDetails` per-attempt persist recovery across crashes.

**When to copy:** Pipelines or workflows where steps may be retried by different processes and the UI must render per-step attempt counts without a separate attempts table.

**When risky:** Envelopes without attempt stamp (dagster/containerd) cannot filter stale attempt events without timestamp heuristics; envelopes with many subscribers (`MultiWriter` fan-out at `solver/jobs.go:583`, `Exchange.Subscribe` at `core/events/exchange/exchange.go:128`) need filtering by `(run_id,step_key)` to avoid cross-run noise.

### Pattern 7: Coalesce vs Isolate — Flightcontrol Singleflight with Explicit Boundary

**Problem:** Thundering herd on identical work needs coalescing, but retries need isolation.

**Sources:** BuildKit coalesces maximally: `sharedOp{gDigest,gCacheRes,gExecRes flightcontrol.Group}` (`solver/jobs.go:992`) with `gExecRes.Do(ctx,"exec",…)` (`solver/jobs.go:1219`) and `edge.index.LoadOrStore` + `edge.mergeTo` (`solver/scheduler.go:156`, `solver/scheduler.go:288`, `solver/edge.go:124`) including `releaserCount` ownership. Temporal isolates per attempt: new `RunId` per workflow retry, per-attempt `Stamp`, cleared `StartedEventId` before rescheduling (`activity.go:51`), and `ClearActivityStartedState` semantics. Dagster hybrid: `ActiveExecution._waiting_to_retry/_pending` with `RetryMode.ENABLED` (local re-queue) vs `DEFERRED` (orchestrator mints new `run_id`, step marked `_abandoned` at `plan/active.py:606`). Containerd neither coalesces nor isolates — callers must handle duplicate `TaskExit` (`shim.go:606`).

**Why it works:** Explicit choice of coalesce vs isolate per layer gives controlled reuse (BuildKit cache) without sacrificing fencing where needed (Temporal/Dagster run-level).

**When to copy:** If content dedup matters, key singleflight by content digest and make isolation opt-in via a distinct per-attempt key `(digest,attemptId)` or `(run_id,step_key,attempt)`, and expose a `forceAttempt` flag for retry paths. Dagster's `RetryMode.DEFERRED`/`ENABLED` split is the cleanest model for multiprocess topology where double-retry must be avoided.

**When overkill/risky:** Naïve copy of BuildKit's sharing layer (`state.jobs map[*Job]struct{}` at `solver/jobs.go:52`) without per-job progress routing breaks attribution; memoized `execErr`/`slowCacheErr` poisoning (`solver/jobs.go:1006`, `solver/jobs.go:1115`) couples failure isolation to eviction — add per-attempt invalidation or caller-scoped error.

## Key Differences

### Convergence — what holds despite different implementations

- **Durable handle before work.** All four persist an intent handle before dispatch (BuildKit `Ref` at `client/solve.go:107`, containerd `Container.ID` bucket at `core/metadata/containers.go:142`, Dagster `run_id` at `python_modules/dagster/dagster/_core/instance/runs/run_domain.py:257`, Temporal `RunId`+`RequestId` at `executions.proto:382`). Observers can recover by handle+scope — containerd `LoadContainer`/`LoadBundle` (`core/runtime/v2/bundle.go:52`), Dagster `get_run_group` (`sql_run_storage.py:555`), Temporal `GetWorkflowKey` (`mutable_state_impl.go:1003`), BuildKit `history.Status` fallback (`solver/llbsolver/solver.go:465`).

- **Checkpoint at transactional boundary, not arbitrary closure.** Smallest recoverable unit aligns with a storage transaction or journal append: BuildKit `edge` (`solver/edge.go:41`) with `CacheKey` fallback, containerd Bolt transaction or `Checkpoint(path)` (`core/runtime/task.go:78`), Dagster `STEP_START→STEP_OUTPUT→STEP_SUCCESS` event log (`events/__init__.py:1081`) plus `ExecutionPlanSnapshot`/`KnownExecutionState`, Temporal single `HistoryEvent` or single-map-entry mutation (`mutable_state_impl.go:128`). Buffering/heartbeats are best-effort (`LastAttemptCompleteTime/LastHeartbeatDetails` at `executions.proto:667`).

- **Operation spans many processes/calls.** Every source's single logical operation fans out: BuildKit `Solve(Ref)` → `edgePipe`→`Executor.Run`→export vertices (`solver/scheduler.go:210`, `worker/base/worker.go:376`, `solver/llbsolver/solver.go:504`); containerd `Create→Start→Wait→Delete` across distinct RPCs on same `container_id` (`task_manager.go:159`, `shim.go:737`, `shim.go:820`) surviving via shim bundle; Dagster `launch_run→ExecutionPlan.rebuild_from_snapshot→multiprocess fork` (`plan/plan.py:1027`, `launcher/base.py:62`); Temporal `PollWorkflowTaskQueue→RespondWorkflowTaskCompleted` on arbitrary worker with matching partitions (`taskqueue/message.proto:60`).

- **Namespace/workspace isolation as header.** Containerd `NamespaceRequired(ctx)` + `WriteBucket` scoping (`core/metadata/containers.go:56`, `core/metadata/buckets.go:241`), Temporal `namespace_id/workflow_id` root key (`executions.proto:57`) plus `NamespaceId` on tokens, Dagster `ROOT_RUN_ID_TAG`/`PARENT_RUN_ID_TAG` grouping (`storage/tags.py:34`), BuildKit `state.Session()` + `sessionGroup.NextSession()` propagation (`solver/jobs.go:80`, `solver/jobs.go:142`). Crossing namespace drops to error, not silence (`core/events/exchange/exchange.go:86`).

## Decision Guide

Use this as a flowchart. Start from the rubric question: **"if attempt 2 succeeds while attempt 1 returns late, which IDs reject attempt 1?"**

- **If the answer must be cryptographic fence (attempt 1 must be rejected even if timely) — i.e., financial workflow, reservation, or mutable side-effect that must not double-apply:**
  → Choose the **Temporal model**. Mint a new durable row + monotonic `Attempt` + anti-ABA `Stamp` (+ `branch_token`/`VectorClock` if you have failover) per retry. Dispatch via self-describing token `tokenspb.Task`-shaped (`token/v1/message.proto:39`) and validate equality on write (`isActivityTaskValid` pattern at `service/history/api/isactivitytaskvalid/api.go:60`). Persist `request_id → execution` mapping (`executions.proto:394`) for idempotent submission. This is the only pattern among the four where two `STEP_SUCCESS` never share `(entity,attempt)` keys.

- **If retries are rare and the whole pipeline can restart as a fresh group, and cache simplicity matters more than per-step late-arrival fencing:**
  → Use **Dagster-style two-tier**. For transient blips keep `RetryPolicy` with `previous_retry_attempts` counter + `STEP_RESTARTED` frontier (`retries.py:65`, `events/__init__.py:1089`). For fence-critical failures re-execute as a **new `run_id`** with `parent_run_id/root_run_id` lineage (`execution/api.py:569`) and `PastExecutionState`/`KnownExecutionState` (`state.py:32`, `state.py:101`) so stale events are naturally partitioned by `run_id`. If audit requires absolute quarantine, opt into the new-`run_id` path — document it as the "safe retry" guidance.

- **If "same work → same output" is correctness and duplicates must deduplicate, not fence — i.e., content cache, artifact build, snapshot ingest:**
  → Use **BuildKit-style content addressing**. Key steps by `Digest(content + inputs)` (`solver/types.go:17`, `solver/cachekey.go:35`) and coalesce with `flightcontrol.Group` + `edge.index` merging (`solver/jobs.go:1219`, `solver/scheduler.go:156`, `solver/cachemanager.go:65`). Accept that progress is `MultiWriter` multicast (`solver/jobs.go:583`) and late completions race on the same `CacheKey`. Add an explicit `forceAttempt` escape hatch that keys on `(digest,attemptId)` for operator-initiated "bust the cache" retries, and scope `CacheKey` leases per-build (`history/buildhistory.go:279`) to avoid cross-build poisoning.

- **If you are a low-level runtime with no business notion of "operation" and higher layers own workflow semantics:**
  → Adopt **containerd-style resource+lease** (`core/containers/containers.go:30`, `core/leases/lease.go:42`). Durable handles are `(namespace,container_id)`, multi-call lifecycle spans `Create→Start→Wait→Delete` on distinct RPCs (`task_manager.go:159`, `shim.go:737`), and process instance is `ShimInstance.Endpoint()` (`shim.go:464`) plus `Process.pid`/`Stdin/Stdout/Stderr` (`task.proto:35`). Document that `Envelope` has no `attempt_id` (`api/types/event.proto:27`) and specify at-least-once delivery (`publisher.go:127`) with consumer-retry guidance for duplicate `TaskExit`/`TaskDelete` (`shim.go:605`). Add an `attempt_id` header extension point (`typeurl.Any` extensions at `core/metadata/containers.go:412`) without making it part of the runtime contract.

- **Choosing checkpoint granularity:**
  → If any subprocess may die, checkpoint at **per-step event boundary** (Dagster `ExecutionPlanSnapshot` + event log; Temporal `HistoryEvent` journal) and ship `KnownExecutionState`/`PastExecutionState`. If only daemon may die, node-local Bolt transaction or single `edge` (`solver/edge.go:41`) is enough. Never checkpoint only in shim memory (`Task.State` at `core/runtime/task.go:119` queried via `State(ctx)` at `shim.go:882`) without an external `Lease`/`Checkpoint(path)` (`task.go:78`) if recovery matters.

## Practical Tips

### Patterns to copy

1. **Mint durable handles before execution and persist them in the rendezvous.** Client-generated `Ref`/`run_id`/`RequestId` fraction stored in Bolt/SQL/shard is the only thing that makes "another client with the same handle finds it" true (`client/solve.go:107`, `core/metadata/containers.go:142`, `run_domain.py:86`, `executions.proto:394`). Test with `kill -9 $SUBMITTER` right after acceptance.

2. **Make attempt monotonic and carry an anti-ABA nonce together.** Store both `Attempt` and `Stamp`/`VectorClock`/`VersionedTransition` on the row, increment atomically on reschedule (`service/history/workflow/activity.go:87`), and require equality on completion (`isActivityTaskValid` at `service/history/api/isactivitytaskvalid/api.go:60`). Use counter for backoff/UI, stamp for fencing.

3. **Address steps by scheduling event ID, not just by name.** Allocate `ScheduledEventId`/`InitiatedEventId`/`step_key+mapping_key` at schedule time and require it on every mutation (`mutable_state_impl.go:130`, `plan/plan.py:664`, `executions.proto:592`). Resolve dynamic fan-outs through explicit `ResolvedFromDynamicStepHandle` with `unresolved_form.to_key()` (`state.py:207`).

4. **Ship a reconstructable plan snapshot to workers.** `ExecutionPlanSnapshot(initial_known_state,snapshot_version=1)` at `snap/execution_plan_snapshot.py:44` plus `rebuild_from_snapshot` (`plan/plan.py:1027`) or `tokenspb.Task` (`token/v1/message.proto:39`) lets any host continue after any other host's crash. Version the snapshot and keep `executor_name`/`branch_token` inside.

5. **Denormalize lineage onto every descendant row but keep column authority.** `RootWorkflowId/RootRunId` and `Parent*` across continuations/children (`executions.proto:227`, `retry.go:240`) or `root_run_id/parent_run_id` + mirrored `ROOT_RUN_ID_TAG`/`PARENT_RUN_ID_TAG` (`dagster_run.py:311`, `tags.py:34`). Enforce `Must set both` invariant (`dagster_run.py:311`, `run_domain.py:143`) and index `run_tags(run_id)` (`runs/schema.py:168`).

6. **Keep a `request_ids` dedup map on the intent row.** Temporal's `WorkflowExecutionState.request_ids map<RequestIDInfo>` (`executions.proto:394`) gives idempotent `StartWorkflowExecution` without a separate table — include `create_request_id` (`executions.proto:382`) as the canonical.

7. **Use `RetryMode.DEFERRED` to avoid double retry.** When executors may themselves retry (`multiprocess`/`k8s`), delegate: orchestrator marks `_abandoned` and mints new `run_id` (`plan/active.py:606`, `retries.py:30`). Temporal's analogous `pause` (`executions.proto:676`, `activity.go:41`) and `ResetActivity` to `Attempt=1` (`activity.go:319`) freeze dispatch without dropping the step.

8. **Record external-process identity but do not use it as fencing.** Store `StartedIdentity`, `TaskQueue`, `WorkerDeploymentVersion`, `StartedClock`, `Pid` (`executions.proto:692`, `activity.go:107`) plus optional boot-id alongside `run_id+attempt` for forensics — never as the sole quarantine key (PID recycling at `task.proto:38`).

### Patterns to avoid or delay

1. **Singleflight on a static key (`"exec"`) with memoed `execErr` as a correctness layer.** BuildKit's `sharedOp.gExecRes` reuse (`solver/jobs.go:1219`) plus persisted `slowCacheErr` (`solver/jobs.go:1115`) is optimal for caching throughput but poisons retries until state evicted via `deleteIfUnreferenced` (`solver/jobs.go:1510`). Only use behind a cache where poison is recoverable; add per-attempt invalidation for retry paths.

2. **`MultiWriter` progress fan-out keyed only by vertex digest.** BuildKit's `progress.NewMultiWriter(WithMetadata("vertex",dgst))` + `MultiSpan` aggregating all jobs (`solver/jobs.go:583`, `solver/jobs.go:665`) makes status streams the union of all sharing jobs (`control.proto:120`). Useful for shared-cache efficiency but makes `VertexStatus`/`VertexLog` unfilterable by `(Ref,attempt)` — add `attemptId` to `Progress.meta` before calling cache hits observable.

3. **Forgetting attempt/branch on event requeue after partition.** Shim `RemoteEventsPublisher` reuses identical `Envelope.Timestamp` (`core/events/exchange/exchange.go:99`, `pkg/shim/publisher.go:127`) with `maxRequeue=5` and bounded `requeue` (`publisher.go:36`). Delay adding persistent retry until you have a monotonic `seq` or `attempt_id` to make deduplication possible.

4. **Materializing run groups by tag scan in write-hot path without indexing.** Dagster's `get_run_group` via `RunTagsTable where key==ROOT_RUN_ID_TAG` (`sql_run_storage.py:578`) is index-friendly (`idx_run_tags_run_idx` at `runs/schema.py:168`) but tags are written in a separate batch after `runs` insert — a crash mid-create yields an inconsistent group. Delay group-table optimization until scale justifies it, but add a tag-write-after-row invariant check.

5. **Sticky-queue as identity.** Temporal `StickyTaskQueue` (`executions.proto:118`) is an affinity hint; BuildKit `session.Group.NextSession()` tracing lineage (`solver/jobs.go:142`) similarly. Useful for latency, brittle as the only quarantine — clearing it must not change correctness.

### Decision rules

- Need quarantine of stale late completion? → token must pack `(namespace,intent,run,step_event_id,attempt,stamp,version/clock)` and be validated equality-against mutable state on write — not just monotonic `Timestamp` (`api/types/event.proto:27` wall-clock at `exchange.go:99` is insufficient).

- Single-node cache with high dedup value and no financial side effects? → content digest + singleflight is cheaper and more correct than per-attempt rows.

- Need cross-OS-process isolation but no workflow engine? → filesystem handle (`bootstrap.json` at `core/runtime/v2/shim.go:294`, Bolt bucket) or snapshot ship (`ExecutionPlanSnapshot` at `snap/execution_plan_snapshot.py:44`) suffices; don't add transition history.

### Caution signs (the design is becoming brittle)

- More than one layer reuses the same dedup key for logically distinct operations (e.g., concurrent `Solve(Ref)` sharing `state` with `MultiWriter` progress but distinct `Export` expectations) — audit attribution before adding another shared-vertex consumer; `secondaryExporters` loss noted as `TODO` at fork of `solver/scheduler.go:289` path is a live example.

- `Envelope.Timestamp = time.Now().UTC()` at publish (`core/events/exchange/exchange.go:99`) is the only ordering coordinate and there are multiple publishers for same `container_id` (`cleanupAfterDeadShim` vs TTRPC close at `shim.go:605`). If your consumer does `MAX(timestamp)` dedup, it will interleave late attempts non-deterministically.

- `previous_retry_attempts` lived only in memory until `get_known_state()` (`active.py:671`) ships it; dynamic `mapping_key` collapse if `ResolvedFromDynamicStepHandle.to_key()` vs `to_key()` chosen inconsistently (`state.py:207` correctness depends on it); tag-only lineage after `delete_run` orphans `get_run_group` (`runs/schema.py:75` cascade). Each is a sign the attempt layer is nearing its persistence boundary and needs to be promoted to a durable row or token.

- Two versioning columns maintained in parallel (`VersionHistories` and `TransitionHistory` at `mutable_state_impl.go:1148`) for rolling upgrades that never converge. Schedule a retirement gate (`shouldVerifyChecksum` at `mutable_state_impl.go:557`) rather than keeping both permanently.

## Anti-Patterns / Caution Signs

- **Attempt identity by timestamp only.** Containerd `Envelope.Timestamp` (`core/events/events.go:28`) and Dagster intra-step timestamp ordering both fail the late-arrival test where worker A's clock may lag worker B's; Temporal's `Stamp` equality proves wall-clock is replaceable with a monotonic fence (`activity.go:87`).

- **Proliferating copies of lineage that are not transactional together.** Temporal copies `RootWorkflowId/RootRunId` onto every descendant (`retry.go:240`), Dagster tags copy `root_run_id/parent_run_id` in a separate table scan (`sql_run_storage.py:555`). Once both systems have children-of-children, chasing the authoritative root vs the tag copy diverges under partial failure.

- **Progress multiplexing without consumer filter.** BuildKit `connectProgressFromState` fans `pw.Write(identity.NewID(), clientVertex)` to every `Job.pw` sharing the state (`solver/jobs.go:665`) and scheduler pushes identical `edgeState` to all `incoming` senders (`solver/edge.go:731`). Any log metric derived from `VertexStatus` that does not scope by `Ref` will double-count under shared-graph pressure.

- **Lease/GC interpreted from labels, not row state.** Containerd `containerd.io/gc.expire` label (`core/leases/lease.go:94`) and BuildKit `<ns>_history` lease (`history/buildhistory.go:104`) are decentralized and not synchronized with operation timeouts — if the operator shortens GC without shortening backoff, attempted retries may find their content already collected.

- **Attempt reset that reuses the same token slot without bumping the stamp.** Temporal explicitly separates `ResetActivity → Attempt=1` plus heartbeat clearing (`activity.go:80`, `activity.go:322`) from retry bump; a naive "retry counter reset to 1 but `StartedEventId` not cleared" (`activityPendingRetry` returns false while paused at `activity.go:41`, but ignores stamp) lets the original worker claim the slot.

- **Fat attempt/branch table kept for observability that is bounded only by `StatusResponse.repeated Vertex` growth.** BuildKit's 16-MiB proto cap and containerd bulk `Events` streams need streaming; large workflows already hit `WorkflowMutableState` blob limits (`ExecutionStats.history_size` at `executions.proto:370`).

- **Invisible fence token.** Temporal's `Stamp` excluded from `GetPendingActivityInfo` and SDK-observable fields (`activity.go:92` exposes `Attempt` but not `Stamp`) makes debugging "why was my valid completion rejected as `stamp not found`?" hard — mirror the token into verbose logs/metrics even if not in API.

## Notable Absences

- **Attempt id for intra-run retries in dagster and all of buildkit/containerd.** Confirmed by `EventLogEntry` lacking `attempt_id` (`dagster events/log.py:31`), no `Attempt` struct in BuildKit solver searches (`solver/pb/ops.proto:356` negative evidence), and `core/events/events.go:27`/`api/types/event.proto:27` lacking `operation_id/attempt_id/parent_envelope_id`. Only Dagster's inter-run `run_id` and Temporal's per-step `Stamp` fill this.

- **Correlation/causation envelope field for cross-orchestrator tracing.** Containerd envelope is `Namespace+Topic+typeurl.Any` (`events.go:27`); BuildKit progress metadata is `("vertex",digest)` (`solver/jobs.go:583`); Dagster tags carry run-group lineage (`tags.py:34`) but not OpenTelemetry span linkage; Temporal alone carries `clockspb.VectorClock`, `Link{WorkflowEvent}`, `Callback.links[]`, `HSMCompletionCallbackArg.last_event` (`executions.proto:62`, `executions.proto:810`, `executions.proto:841`).

- **External-process identity bound to attempt.** Shim `ShimInstance.ID()` (`shim.go:228`) returns `container_id` plus `Endpoint` host info, activity `StartedIdentity/StartedClock/Pid` (`executions.proto:629`, `task.proto:38`) record which worker holds the attempt, but no source durably pairs `(attempt_id, host PID + boot-id, container task ID)` such that `check_run_worker_health` (`dagster launcher/base.py:98` `run_worker_id`, `storage/tags.py:80` `RUN_WORKER_ID_TAG`) or `Executor.Run id` (`worker/base/worker.go:80`) can be joined to the event log without an external correlator.

- **Durable operation ledger bridging metadata and runtime in containerd and buildkit.** BuildKit history keeps `BuildHistoryRecord` (`control.proto:203`) but has no `attempts[]` child; containerd `core/metadata/db.go:84` tracks dirty but no `operation{attempt,status,retries}` row. Dagster (`RunsTable` + `RunTagsTable`) and Temporal (`WorkflowMutableState`) demonstrate what such a ledger looks like.

- **Lease/GC-aware branch-token validation on late artifact access.** BuildKit content `WorkerRef.ID() => workerID/refID` (`worker/result.go:21`) and containerd GC `gcContext` scan (`db.go:383`) can still GC content under a late `WorkerRef` holding — late worker completing writes to already-collected content relies on orphan GC tolerance, not explicit fencing.

## Per-Source Notes

### buildkit — 6/10 — Content-addressed DAG, attempt-collapsed

The content-address guarantee is the whole design. `solver.Solver` plus shared `state`/`edge` graph (`solver/jobs.go:41`, `solver/jobs.go:52`, `solver/types.go:44`) and `WorkerRef.ID()` leases (`worker/result.go:21`) make concurrent builds free-cache hits rather than redundant work. Three-phase cache (`initial/cacheFast/cacheSlow/complete` at `solver/edge.go:16`) and deterministic `edge.index.LoadOrStore` merging (`solver/scheduler.go:156`) maximize reuse at the cost of deliberately erasing per-request identity. The standout efficiency mechanism is `sharedOp flightcontrol.Group` co-locating `"exec"` and `"cachemap"` groups (`solver/jobs.go:992`); the caution is identical memo key reuse makes operator retry guidance "change something in the input slightly or restart daemon" rather than "retry the failed edge with a new attempt id." Future direction to add `attemptId` to `ProcessInfo` label + `WorkerRef.ID()` and to fan-in `MultiWriter` routing by `(Ref,digest)` would be incremental, not architectural.

### containerd — 5/10 — Resource-owned, operation-absent

The reference for survive-everything local resource ownership: namespace-validated Bolt buckets (`core/metadata/containers.go:56`, `core/metadata/buckets.go:241`), filesystem `Bundle` + `bootstrap.json` shim reattachment (`core/runtime/v2/bundle.go:121`, `core/runtime/v2/shim.go:294`), and dual `gRPC+TTRPC` with `NSMap[ShimInstance]` (`shim_manager.go:163`). The distinctive trade is leasing (`core/leases/lease.go:42`, `core/metadata/leases.go:184`) for GC protection instead of any `operation/step` ledger. The explicit contract `cleanupAfterDeadShim` "moby should handle duplicates" (`shim.go:606`) and requeued identical `Envelope` (`publisher.go:102`) are not oversights but layer boundary — the runtime tells callers "you own retry semantics." The gap only matters when containerd is used as the sole orchestrator.

### dagster — 8/10 — Run-centric, two-tier

The strongest attempt model short of Temporal, achieved without Temporal's sharding complexity: immutable `run_id` + `ExecutionPlanSnapshot` + `KnownExecutionState` stateless worker rebuild is the portable core (`snap/execution_plan_snapshot.py:44`, `plan/plan.py:1027`, `plan/state.py:101`). The standout correctness detail is dual lineage encoding (columns + tags) and `PastExecutionState` minimized linked list (`state.py:32`) plus dynamic-handle resolution (`plan/plan.py:85`) and `RetryMode.DEFERRED` avoiding double-retry in multiprocess executors (`retries.py:30`). The detectable weakening is intra-run fence: `RetryState._attempts` is in-memory until snapshotted (`active.py:671`) and event-replay dependent (`stats.py:146`), so late `STEP_OUTPUT` with stale data under same `run_id+step_key` has only ordering-based rejection, not stamp-based — the report's own warning at `plan/active.py:579` and `stats.py:217` about counting attempts post-hoc is load-bearing.

### temporal — 9/10 — Lattice-fenced

Defines the reference lattice for the dimension. Four levels with typed attempt counters + anti-ABA `Stamp` (`executions.proto:122`, `executions.proto:673`), self-describing `tokenspb.Task` (`token/v1/message.proto:39`) carrying `Attempt`+`ActivityAttemptStamp`+`clock`+`version`+`branch_token` (`token.go:9`), `VectorClock` + `VersionHistories/VersionedTransition` branch fencing (`executions.proto:62`, `executions.proto:147`, `executions.proto:208`), idempotent `request_ids` map (`executions.proto:394`), and repeated `Stamp`-gated validators (`isactivitytaskvalid/api.go:60`, `isworkflowtaskvalid/api.go:63`) that make the counterfactual decidable by four independent coordinates (`RunId` mismatch → `WorkflowKey` miss at `mutable_state_impl.go:1003`; `Attempt` chain mismatch → `first_execution_run_id` chain; `Stamp` mismatch → `ObsoleteMatchingTask`; branch mismatch → `GetCurrentBranchToken` at `mutable_state_impl.go:1011`). Deductions only for dual-track versioning burden (`mutable_state_impl.go:1148`) and wide-row cost (`mutable_state_impl.go:984`). The `CHASM` extensibility (`sub_state_machines_by_type` at `executions.proto:212`) proves the lattice handles arbitrary custom steps beyond activities/timers/children.
