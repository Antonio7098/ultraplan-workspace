## Executive Summary

All four sources separate long-lived execution from the submitting client, but they do it from opposite ends of the spectrum. containerd and temporal achieve the strongest detach: accepted work is durably owned outside any client connection — in bolt metadata + shim re-parenting (containerd `core/metadata`, `containerd-shim-runc-v2`) and in history-shard state machines behind the frontend (temporal `service/frontend/workflow_handler.go:570`). Dagster achieves the same durability by a different route — no daemon RPC at all, with `RunStorage` as the rendezvous and `dagster-daemon` as a polling controller (`python_modules/dagster/dagster/_daemon/controller.py:133`). BuildKit is the outlier on detach: the daemon does own jobs (`control/control.go:90`, `solver/llbsolver/solver.go:210`, `history/buildhistory.go:51`) but the unary `Solve` RPC remains fate-shared with the caller's gRPC context (`control/control.go:409`), so killing `buildctl` aborts the build despite BoltDB history surviving for re-observation.

The narrowest stable wire is remarkably consistent where gRPC is used: a protobuf `Control`/`Tasks`/`WorkflowService` service over a local transport (Unix socket preferred, named pipe on Windows, TCP+mTLS opt-in) plus interceptors for cross-cutting concerns. Dagster's outlier — 28-RPC `DagsterApi` (`python_modules/dagster/dagster/_grpc/protos/dagster_api.proto:7`) tunneled over loopback/UDS but carrying serde JSON inside proto strings — and temporal's TCP-only choice (`common/rpc/rpc.go:200`) book-end the transport trade: filesystem DAC is cheap and zero-network-exposure where it exists; TCP-only pays TLS overhead even for localhost but simplifies deployment.

The converged lesson: detach requires a persistent handle minted before execution (`Ref` in buildkit `client/solve.go:107`, container ID+namespace in containerd `client/client.go:380`, `DagsterRun` row ID in dagster `python_modules/dagster/dagster/_core/storage/runs/sql_run_storage.py:427`, `WorkflowId+RunId+namespace` in temporal) plus an absolute-root daemon that never depends on its own CWD (`cmd/buildkitd/main.go:366`, `cmd/containerd/command/main.go:311`). Authentication is the universal weak spot: three sources default to insecure or permission-bit trust (`buildkit cmd/buildkitd/main_unix.go:58` `0666`, containerd `pkg/sys/socket_unix.go:57` `0660`+`insecure.NewCredentials()`, dagster `python_modules/dagster/dagster/_grpc/client.py:131` `insecure_channel`); only temporal has a production interceptor chain (mTLS+JWT, `common/authorization/interceptor.go:129`) and even it warns with a noop authorizer by default (`cmd/server/main.go:203`).

## Core Thesis

**Execution ownership is decided by what survives the death of the submitting connection — and that splits this dimension into two camps: RPC-coupled execution versus rendezvous-owned execution.**

- **RPC-coupled (buildkit):** The job is daemon-owned but execution liveness is tied to the caller's `Solve` context and to a `Session` stream (`session/manager.go:94`, `session/grpchijack/dial.go:18`). The daemon owns storage/leases/caches, but the operation has no first-class detach handle — history (`history/buildhistory.go:351`) gives observability after the fact, not continuation. This is sufficient for interactive builds where the invoking CLI is expected to stay alive, and the `local://` session model makes sense when inputs are streamed from the client (`client/solve.go:141`).

- **Rendezvous-owned (containerd, dagster, temporal):** Acceptance writes a durable record outside any connection — bolt container/task metadata (containerd), a `DagsterRun` row (dagster), a workflow mutable-state shard (temporal). After acceptance nothing holds a reference to the client connection. Observers reconnect by re-listing the rendezvous with the same handle and namespace: `LoadContainer`/`Task` + FIFO reattach (containerd `client/container.go:479`), `get_run_by_id` (dagster), `DescribeWorkflowExecution` by `(namespace, WorkflowId)` (temporal), or `Status(Ref)` routed to `history.Status` (buildkit's partial version of the same idea at `solver/llbsolver/solver.go:465`).

Three orthogonal axes separate the implementations across the rendezvous-owned camp:

1. **What the rendezvous is**: containerd uses the daemon's own bolt store plus shim processes; dagster uses an external SQL DB; temporal uses partitioned history shards behind a stateless frontend. The cost moves with it — bolt is single-node and needs orphan GC (`history/buildhistory.go:200`, `pkg/shim`), SQL needs heartbeat polling (`python_modules/dagster/dagster/_daemon/types.py:25`, `controller.py:424`), shards need ownership redirect (`client/history/caching_redirector.go:205`).

2. **How local transport authenticates**: filesystem DAC on a Unix domain socket (buildkit+containerd+dagster's UDS path `python_modules/dagster/dagster/_grpc/client.py:71`) versus TCP+TLS+JWT interceptors (temporal's chain at `service/frontend/fx.go:286`). The former is zero-bootstrap but group-permission-only; the latter is production-ready but pays setup cost even for localhost.

3. **How workspace is scoped**: explicit header/origin propagated per-RPC (containerd `containerd-namespace` at `pkg/namespaces/grpc.go:27`, dagster `LoadableTargetOrigin.working_directory` at `python_modules/dagster/dagster/_core/types/loadable_target_origin.py:16`, temporal namespace validator at `common/rpc/interceptor/namespace_validator.go:42`) versus implicit graph content (buildkit's `Definition` graph carrying `local://` mounts). Explicit headers survive restarts and are interceptable; implicit graphs tie workspace to the client's session liveness.

The frameworks that score highest (temporal 8, buildkit/containerd 7) share typed protobuf contracts, explicit transport setup, and deliberate shutdown/drain semantics. The mid-scoring source (dagster 6) trades those guarantees for DB-simplicity and Python schemaless serde — maximally detached but minimally authenticated, versioned, or observable without DB polling.

## Approach Models

Sources cluster into four ownership models ordered by **what owns work after the submitting connection dies**.

### A. Single-Daemon, RPC-Coupled (buildkit)

One long-lived `buildkitd` (`cmd/buildkitd/main.go:127`) is the sole owner, gated by `flock.TryLock` (`cmd/buildkitd/main.go:385`). Jobs are `llbsolver.Solver` jobs (`solver/llbsolver/solver.go:210`) tracked by `control.Controller` (`control/control.go:90`) with persistent blobs in `history.Queue` (`history/buildhistory.go:51`). The wire is `Control` (`api/services/control/control.proto:14`) — `Solve` (unary), `Status` (streaming), `Session(stream BytesMessage)` — where `Session` tunnels an inner gRPC channel via `grpchijack` (`session/grpchijack/dial.go:18`, `session/manager.go:29`). Workspace never crosses as paths: `local://` mounts stream over the session (`client/solve.go:141`). Versioning is two-track: `CompatibilityVersion` (`solver/llbsolver/compat/compat.go:9`) plus `CapSet` (`frontend/gateway/pb/caps.go:88`). Shutdown uses `GracefulStop` coordinated through history finalizers (`history/buildhistory.go:139`). Divergence: because `Solve` is unary, `kill -9 $CLIENT` cancels the server context and aborts the build (`solver/llbsolver/solver.go:302`); `Status` survives via `history.Status` fallback (`solver/llbsolver/solver.go:465`) but cannot re-drive execution.

- Why it fits buildkit: builds are invoked by a nearby CLI that streams local contexts; the session model avoids host-path exposure and works with a single listener.

### B. Single-Daemon, Shim-Delegated with Persistent Store (containerd)

One `containerd` daemon (`cmd/containerd/main.go:29`, `cmd/containerd/command/main.go:132`) owns metadata in `core/metadata` bolt; actual tasks outlive both client and daemon via per-container `containerd-shim-runc-v2` plus FIFOs (`client/container.go:226`). The wire is `Tasks`/`Containers`/`Snapshots`/`Content` protobufs (`api/services/tasks/v1/tasks.proto:31`) over Unix socket (`plugins/server/grpc/plugin.go:66`) and parallel TTRPC (`plugins/server/ttrpc/plugin.go:48`) with an optional TLS TCP plane (`plugins/server/grpc/plugin.go:142`). Namespace is explicit metadata handled by interceptors (`plugins/server/grpc/namespace.go:26`, `pkg/namespaces/grpc.go:27`). Reconnect is `Client.Reconnect()` via a stored `connector` closure (`client/client.go:237`, `pkg/ttrpcutil/client.go:62`) plus `LoadContainer`/`Task(ctx, attach)` FIFO reattach (`client/container.go:479`). `Wait` is server-side blocking independent of the creator (`client/task.go:342`, `plugins/services/tasks/local.go:414`).

- Why it fits containerd: containerd is a node-local runtime — OS DAC (`0660`/`chown` at `pkg/sys/socket_unix.go:57`) matches the trust model, shims give survivor semantics even across daemon restarts (tested at `integration/client/container_linux_test.go:401`).

### C. DB-Polling Controller, No Daemon RPC (dagster)

No `DagsterDaemon` gRPC service exists — `dagster_api.proto:7` defines only the user-code `DagsterApi` (28 RPCs). The daemon (`python_modules/dagster/dagster/_daemon/controller.py:88`) is a controller that spawns one thread per daemon type (`controller.py:188`), writes `DaemonHeartbeat` rows (`daemon.py:147`, `sql_run_storage.py:852`), and decides health via DB reads (`controller.py:424`). Work is submitted by writing `DagsterRun` rows (`sensor.py:755`); the daemon merely ticks and enqueues. Code intelligence crosses a separate local gRPC to per-location user-code servers (`_grpc/server.py:392`, `open_server_process` at `server.py:1643`) over UDS or loopback (`client.py:71` port XOR socket, `server.py:1492`), with `LoadableTargetOrigin.working_directory` carrying workspace context (`loadable_target_origin.py:16`). Liveness is `heartbeat_ttl=20` daemon / 45 webserver heartbeats with a watcher thread (`client.py:59`, `server.py:535`, `server_watcher.py:24`).

- Why it fits dagster: Python orchestration where runs must survive any request process — DB as single source of truth trades API latency for maximal detach and multi-location workspaces.

### D. Distributed Shard-Owned, Stateless TCP Frontends (temporal)

Ownership lives in history-shard state machines; the frontend (`service/frontend/service.go:504`) is stateless and handoffs accepted writes immediately (`workflow_handler.go:570` via `client/history/caching_redirector.go:82` shard routing with `ShardOwnershipLost` retry at `caching_redirector.go:205`). Workers are decoupled via pull-based long polls (`matching/handler.go:225`, `client/matching/client.go:33` 5-min default). Transport is plain TCP listeners per service (`common/rpc/rpc.go:196`) with round-robin DNS + capped backoff reconnect (`common/rpc/grpc.go:21`, `64`) and internode caches (`rpc.go:317`). Every request passes the interceptor chain: error masking → business-ID extraction → namespace validation (`namespace_validator.go:34`) → JWT/mTLS authorization (`authorization/interceptor.go:129`) → redirect → telemetry → rate-limit → version check (`headers/version_checker.go:115`) at `frontend/fx.go:286`. Workspace is `namespace` validated per-API with allowed-state gates (`namespace_validator.go:42`). Shutdown is drain-before-stop: fail health → `SetDraining(true)` (`membership/interfaces.go:59`) → wait failure-detection window → `GracefulStop` with deadline → hard `Stop` (`frontend/service.go:543`).

- Why it fits temporal: multi-tenant, multi-frontend workflow service requiring survive-any-frontend semantics and pull-based worker detach.

## Pattern Catalog

### Pattern 1: Persistent Handle Minted Before Execution

**Problem:** Without a durable handle, killing the submitter loses the ability to find the operation.

**Sources:** buildkit `Ref = identity.NewID()` (`client/solve.go:107`, `api/services/control/control.proto:62`), containerd container/task ID + namespace (`client/client.go:379`, `client/container.go:206`), dagster `DagsterRun` row + cursor IDs (`sensor.py:755`, `sql_run_storage.py:1122`), temporal `(namespace, WorkflowId, RunId)` + `RequestId` (`workflow_handler.go:661`, `chasm/lib/workflow/workflow.go:176`).

**Why it works:** The handle is created by the client or assigned at enqueue time and stored in a durable rendezvous (bolt, SQL, history shard). Any new client with the same handle and scope can call `Status(Ref)` / `LoadContainer` / `get_run_by_id` / `DescribeWorkflowExecution` to recover. Reconnect tests exist: containerd `TestClientReconnect` (`integration/client/client_test.go:499`), buildkit's `history.Status` fallback (`solver/llbsolver/solver.go:465`), temporal's duplicate `StartWorkflowExecution` collapsing via workflow-ID reuse (`chasm/lib/workflow/workflow.go:441`).

**When to copy:** Always for any operation that must outlive its submitter. Mint the ID at submission boundary, return it synchronously, and require it for status/attach.

**When overkill:** Ephemeral streaming RPCs where the operation has no durable side effect (e.g., `GetSystemInfo` at `service/frontend/workflow_handler.go:3498`) — a request-ID idempotency key suffices.

**Evidence:** `buildkit client/solve.go:107`, `containerd client/client.go:379`, `dagster sensor.py:755`, `temporal service/frontend/workflow_handler.go:570`.

### Pattern 2: Absolute Root + No CWD Dependence

**Problem:** Daemons started from different working directories must have deterministic socket and storage locations.

**Sources:** buildkit `filepath.Abs(cfg.Root)` (`cmd/buildkitd/main.go:366`) + `Root` lock (`cmd/buildkitd/main.go:385`); containerd `filepath.Abs` for `Root/State` (`cmd/containerd/command/main.go:311`) + `CreateTopLevelDirectories` (`server/server.go:60`); dagster `LoadableTargetOrigin.working_directory` (`loadable_target_origin.py:16`, `utils.py:19`) + `WorkspaceLoadTarget` (`controller.py:88`); temporal embedded template default avoids CWD, legacy flag warned (`cmd/server/main.go:41-53`).

**Why it works:** Storage, locks, sockets, and workspace resolution never call `os.Getwd` or `os.Chdir` at runtime. Workspace context is propagated as data (`working_directory` field, namespace header, mount descriptors) rather than inherited. Exceptions are flagged and scoped: containerd shim's `os.Getwd()` at `pkg/shim/shim.go:460` is isolated to shim execution, not central dispatch; temporal's CWD coupling only affects deprecated flag path.

**When to copy:** Any daemon that binds sockets or persists state — absolutize at startup and propagate explicit workspace on every request.

**When overkill:** Single-process CLIs with no persistent storage.

**Evidence:** `buildkit cmd/buildkitd/main.go:366`, `containerd cmd/containerd/command/main.go:311`, `dagster loadable_target_origin.py:21`, `temporal cmd/server/main.go:167`.

### Pattern 3: Unix Domain Socket (or Named Pipe) as Zero-Bootstrap Local Transport + Optional TLS TCP

**Problem:** Local clients need authenticated, low-overhead transport without key distribution.

**Sources:** buildkit `getListener` dispatching `unix`→`sys.GetLocalListener`/`npipe`/`fd`/`tcp` (`cmd/buildkitd/main.go:760`, `main_unix.go:52`, `main_windows.go:22`) with `appdefaults` (`appdefaults_linux.go:4`); containerd `GetLocalListener` + `CreateUnixSocket` (`pkg/sys/socket_unix.go:31`, `46`) + `winio.DialPipe` (`dialer_windows.go:34`); dagster `unix:abspath(socket)` vs `host:port` XOR enforced (`client.py:71`, `server.py:1492`); temporal shows the alternative — TCP-only (`rpc.go:200`) paying TLS cost for localhost.

**Why it works:** `sys.GetLocalListener` + `0660`/`chown` + directory `0700` gives OS DAC without certs; `grpc.NewServer` reuses health/otel/prometheus interceptors (`plugins/server/grpc/plugin.go:88`). TLS TCP is reserved for remote or Windows store paths (`plugins/server/grpc/plugin.go:186`, `buildkit client/client.go:306`). Watch window: socket path 104-char limit (`containerd pkg/sys/socket_unix.go:33`).

**When to copy:** Node-local daemons where clients share a host and group membership is the trust boundary.

**When overkill or risky:** Multi-host services or internet-exposed APIs — temporal's TCP+mTLS+JWT choice is correct there; buildkit's `0666` after `Chmod` (`main_unix.go:58`) widens surface for compatibility with rootless/podman and needs `SO_PEERCRED` hardening if multitenancy matters.

**Evidence:** `buildkit cmd/buildkitd/main.go:760`, `containerd pkg/sys/socket_unix.go:46`, `dagster _grpc/client.py:71`, `temporal common/rpc/rpc.go:196`.

### Pattern 4: Explicit Workspace/Namespace Header Validated by Interceptor

**Problem:** A single daemon multiplexing workspaces must isolate without separate sockets.

**Sources:** containerd `containerd-namespace` via `metadata.Pairs` (`pkg/namespaces/grpc.go:27`) + `unaryNamespaceInterceptor`/`streamNamespaceInterceptor` (`plugins/server/grpc/namespace.go:26`); dagster `WorkspaceProcessContext` + `CurrentWorkspace` snapshot per request (`context.py:888`) and `LoadableTargetOrigin` per location; temporal `namespace_validator.go:34` with per-API allowed-state gates (`namespace_validator.go:42`).

**Why it works:** The header is injected by client interceptors (`containerd client/client.go:159`, `pkg/namespaces/context.go:38`) and restored into `context.WithValue` on the server, so handlers are workspace-agnostic and validation is per-API without handler code. `NamespaceRequired` fails closed (`pkg/namespaces/context.go:68`). Dagster's `check_workspace_freshness` (`controller.py:275`) handles stale origins.

**When to copy:** Any multi-tenant daemon. Make the header required, default it explicitly (containerd `CONTAINERD_NAMESPACE=default` at `context.go:29` / `cmd/ctr/app/main.go:122`), and gate per state.

**When overkill:** Single-tenant local daemon.

**Evidence:** `containerd pkg/namespaces/grpc.go:27`, `dagster context.py:958`, `temporal common/rpc/interceptor/namespace_validator.go:39`.

### Pattern 5: Interceptor Chain as Security and Cross-Cutting Envelope

**Problem:** Auth, validation, rate limiting, and versioning must not be re-implemented per handler.

**Sources:** temporal's ordered chain at `service/frontend/fx.go:286` (masking outermost → business-ID → namespace validation → auth → handover → redirect → telemetry → rate limits → SDK version → retry innermost); containerd's `Chain*Interceptor` appending prometheus/otel (`plugins/server/grpc/plugin.go:82`); buildkit's `grpcerrors` interceptors (`util/grpcerrors/intercept.go:13`); dagster's absence is the counter-example — no auth interceptor on `_grpc/server.py:1525` `add_insecure_port`.

**Why it works:** One registration point orders security invariants (headers stripped at `authorization/interceptor.go:156` even when auth disabled) and makes additive evolution cheap. Temporal's `streamNamespaceInterceptor` mirrors unary at `authorization/interceptor.go:187`.

**When to copy:** Any gRPC service with more than two cross-cutting concerns. Document the ordering in code, as temporal does.

**When overkill:** A tiny daemon with a single RPC and one concern.

**Evidence:** `temporal service/frontend/fx.go:286`, `containerd plugins/server/grpc/plugin.go:82`, `buildkit util/grpcerrors/intercept.go:13`.

### Pattern 6: Heartbeat / Lease for Liveness Without Locks

**Problem:** Detect dead or split-brain daemons without distributed locking.

**Sources:** dagster `DaemonHeartbeat` (`daemon/types.py:25`) upsert in `DaemonHeartbeatsTable` (`sql_run_storage.py:852`) read by `get_daemon_statuses` (`controller.py:424`) with `DEFAULT_DAEMON_HEARTBEAT_TOLERANCE_SECONDS=1800` + `DAEMON_GRPC_SERVER_HEARTBEAT_TTL=20` (`controller.py:59`) and `_clear_old_processes` (`grpc_server_registry.py:246`); buildkit history lease in `ns+"_history"` (`history/buildhistory.go:104`) + orphan cleanup (`history/buildhistory.go:200`); containerd lease via `WithLease` (`client/client.go:342`) + `Client.Reconnect` liveness on channel (`client/client.go:311`); temporal membership draining (`membership/interfaces.go:50`, `frontend/service.go:544`) plus retry on `ShardOwnershipLost` (`caching_redirector.go:205`).

**Why it works:** Rows/leases are advisory and low-contention; consumers poll on intervals (`controller.py:51` `RELOAD_WORKSPACE_INTERVAL=60s`). Orphans self-terminate when heartbeat TTL expires (`_grpc/server.py:535`).

**When to copy:** Polling controllers and shim/code-server lifecycles.

**When overkill:** Request-response services where connection failure is sufficient — use health checks instead.

**Evidence:** `dagster daemon.py:147`, `buildkit history/buildhistory.go:104`, `containerd client/client.go:342`, `temporal frontend/service.go:543`.

### Pattern 7: Graceful Drain Before Stop (Fail Health → Drain → Deadline → Hard Stop)

**Problem:** Rolling restarts must not black-hole in-flight RPCs.

**Sources:** temporal `service/frontend/service.go:543` (fail health → `SetDraining(true)` → wait failure-detection time → `GracefulStop` with deadline → `Stop`); buildkit `appcontext.Context()` two-stage cancel (`util/appcontext/appcontext.go:15`) + `server.GracefulStop()` (`cmd/buildkitd/main.go:452`) coordinating `history.Queue.ps.Close()` only after finalizers drain (`history/buildhistory.go:139`); containerd reverse-order `server.Stop` (`server/server.go:282`) and `liveness-check` propagation (`controller.py:123` analogue).

**Why it works:** Health failure steers new traffic away via ringpop/LB before sockets close; the drain window covers long polls (matching 5 min, frontend 3 min at `client/frontend/client.go:18`, `client/matching/client.go:33`). buildkit's `throttle.After` (`control/control.go:143`) avoids GC storms during drain.

**When to copy:** Any daemon behind load balancing or with long polls/streams.

**When overkill:** Short-lived CLI helpers.

**Evidence:** `temporal service/frontend/service.go:543`, `buildkit util/appcontext/appcontext.go:15`, `containerd server/server.go:282`.

### Pattern 8: Capability / Compatibility Version Negotiation

**Problem:** Old clients must degrade gracefully without hard proto breaks.

**Sources:** buildkit `CompatibilityVersion` 10/20/30 (`compat/compat.go:9`) + `SolveRequest.CompatibilityVersion` (`control/control.proto:80`) + gateway `Caps` (`caps.go:88`, `apicaps/caps.go:107`) + `Info` version exchange (`control/control.go:663`); containerd `ConfigVersion=4` with `MigrateConfigTo` (`version/version.go:41`, `config/config.go:49`); dagster `server_id = uuid4()` (`server.py:433`) + `DefsStateInfo` diff (`server.py:757`) + `UNIMPLEMENTED` fallback (`client.py:545`); temporal SDK `ClientSupported` vs `ServerVersionNotSupported` (`headers/version_checker.go:115`) + `GetSystemInfo` hardcoded capability booleans (`workflow_handler.go:3506`).

**Why it works:** Additive booleans or enumerated versions let servers imply `false` when fields are missing (`workflow_handler.go:3508`), so no handshake round-trip is needed. Fallback shims (`client.py:583` streaming vs sync) keep rolling upgrades safe.

**When to copy:** Any persisted wire surface with multi-version fleet.

**When overkill:** Single-version internal tooling.

**Evidence:** `buildkit solver/llbsolver/compat/compat.go:9`, `containerd version/version.go:41`, `dagster _grpc/server.py:433`, `temporal common/headers/version_checker.go:124`.

## Key Differences

### Ownership boundary: connection vs. rendezvous

- **BuildKit couples liveness to connection + session.** `Controller.Solve` delegates to `solver.Solve` (`control/control.go:409`, `solver/llbsolver/solver.go:210`) but the job's context is the caller's gRPC context; cancel → abort (`solver/llbsolver/solver.go:302`). `Session` deletion on `ctx.Done()` (`session/manager.go:137`) aborts I/O-dependent builds. History persists for re-observation (`history/buildhistory.go:351`).
- **Containerd/Dagster/Temporal decouple via rendezvous.** containerd re-parents to shim + bolt; dagster persists run rows; temporal owns shard state. Killing the client mid-stream only cancels that stream's context, not the operation, and any new client with the same handle re-discovers it.

Why diverge: product shape. BuildKit's inputs are client-supplied local files streamed live — no session, no bytes. Containerd/Dagster/Temporal accept handle-first requests where content (snapshots, runs, workflows) is already addressable by persistable IDs.

### What crosses the boundary

- **BuildKit:** opaque `Definition` graph + session-carried mounts (`client/solve.go:141`, `solver/pb/ops.proto:198`, `filesync.NewFSSyncProvider`). Minimal but session-coupled.
- **Containerd:** protobuf RPCs + `Mount` arrays + FIFO path strings (`api/services/tasks/v1/tasks.proto:82`, `client/container.go:241`), leased content (`leases/service.go:38`).
- **Dagster:** no daemon boundary; daemon↔storage is `DaemonHeartbeat`/`DagsterRun`/cursor rows (`types.py:25`, `sql_run_storage.py:1122`), daemon↔code is `serialize_value` JSON-in-proto (`dagster_api.proto:64`) over gRPC, gzipped (`client.py:118`).
- **Temporal:** protobuf `WorkflowService` + task tokens + metadata headers (`namespace_validator.go:20`, `headers/version_checker.go:99`) and an optional HTTP/JSON projection (`fx.go:1046`).

Minimal stable surface is smallest in buildkit and temporal — a single typed `Control`/`WorkflowService` service plus streaming status — and widest in dagster where every domain object is schemaless JSON.

### Reconnect and re-observe

- **BuildKit:** re-observation yes via `Status(Ref)` fallback to history (`solver/llbsolver/solver.go:465`) and `ListenBuildHistory` (`history/buildhistory.go:770`); re-drive no — new session required, no `ReattachSolve`.
- **Containerd:** full re-observe + re-attach. `Reconnect()` (`client/client.go:237`) + `LoadContainer` (`client/client.go:379`) + `Task(ctx, attach)` FIFO reattach (`client/container.go:513`) recovers live work. Streaming `Wait`/`Subscribe` must be re-issued (`events.go:80`).
- **Dagster:** observer reconnect via `get_run_by_id`/`GetCurrentRuns` (`sql_run_storage.py:427`, `server.py:1466`); daemon iteration is not resumable mid-tick, next interval retries.
- **Temporal:** transport auto-reconnect (`rpc/grpc.go:64`, 10s cap) + semantic recovery by WorkflowId/RequestId (`workflow_handler.go:661`); no session re-attach — lost-update response recovered by polling update handle.

### Local caller authentication

- **BuildKit & Containerd:** filesystem DAC + insecure creds. `GetLocalListener` + `Chmod` (`buildkit main_unix.go:58` `0666`, containerd `socket_unix.go:57` `0660`+`Chown`), `insecure.NewCredentials()` on both ends (`client/client.go:144`). Optional mTLS for TCP (`buildkit main.go:813`, `containerd plugin.go:186`) that is warned not required on TCP (`buildkit main.go:787`).
- **Dagster:** unauthenticated — `insecure_channel` (`client.py:131`) with `use_ssl` bool only, no peer check; metadata plumbing unused for auth. Threat model is network/file isolation.
- **Temporal:** interceptor-based — optional mTLS (`rpc.go:131`, `interceptor.go:263`), JWT bearer token + pluggable claim mapper/authorizer (`interceptor.go:129`), spoof-header stripping always (`interceptor.go:156`). But noop authorizer default only warns (`main.go:203`).

Divergence reflects operational constraints: node-local runtimes accept DAC; multi-tenant temporal requires interceptors; dagster defers to DB and external Cloud auth.

### CWD dependence

All four claim CWD independence for the central daemon, with narrow, isolated exceptions: containerd shim (`pkg/shim/shim.go:460`), buildkit container-internal `Cwd:"/"` (`worker/tests/common.go:96`), dagster `working_directory=None` fallback, temporal legacy `root="."` flag. Dagster is most explicit via `LoadableTargetOrigin`; buildkit/containerd most defensive via early `Abs` normalization.

### Transport choice rationale

- **UDS/npipe-first (buildkit, containerd, dagster UDS mode):** zero handshake, OS DAC, but 104-char path and abstract-socket caveats.
- **TCP-only (temporal):** unified deployment (no socket perms) at cost of per-connection TLS even for localhost.
- **Dual TTRPC+gRPC (containerd):** low-overhead shim path (`address+".ttrpc"` at `plugins/server/ttrpc/plugin.go:50`) at cost of two listeners and file count.
- **Hijacked single-listener (buildkit grpchijack over `Control.Session`):** one listener for control+data planes, single firewall hole, at cost of custom framing (`streamToConn` at `grpchijack/dial.go:40`).

## Decision Guide

Use this as a flowchart. Start from the kill-test question: "kill the submitter after acceptance — what must still be true?"

- **If accepted work must outlive the submitter with shared-nothing observer recovery:**
  → Choose a **rendezvous-owned** model. If the work is node-local/container-lifecycle, use **containerd-style bolt+shim** (`client/client.go:237` connector + shim FIFOs). If it is cross-process orchestration on a shared DB, use **dagster-style DB rendezvous** and accept polling latency. If it is multi-tenant workflows with fan-out workers, use **temporal-style shard ownership + long polls**.

- **If the operation streams client-local inputs that cannot be pre-materialized to durable storage:**
  → RPC-coupled is defensible, but give it a **persistent handle + explicit Cancel RPC** and persist the descriptor before starting work. Copy buildkit's history pattern (`history/buildhistory.go:51`) and promote `Ref` to a first-class job resource with `CreateJob`/`Start` split.

- **Choosing transport:**
  → Node-local, same-host clients → **UDS/npipe + filesystem DAC** (`pkg/sys/socket_unix.go:46`). Absolutize addresses at both daemon and client, handle 104-char limit, and add `SO_PEERCRED` checks if any multitenancy exists. Remote or multi-tenant → **TCP + mTLS + header auth** with an ordered interceptor chain (`frontend/fx.go:286`). Do not expose TCP without TLS for executors — buildkit's README warning at `README.md:703` applies universally.

- **Workspace scoping:**
  → Always propagate workspace as **explicit per-RPC data** — namespace header (`pkg/namespaces/grpc.go:27`), `LoadableTargetOrigin.working_directory` (`loadable_target_origin.py:16`), or `SourcePolicy` scoped to caller identity. Never rely on daemon CWD. If the workspace is a DAG graph, make it opaque content-addressed data (buildkit `Definition`) not host paths.

- **Versioning:**
  → Ship **two-track** versioning from day one: a coarse compatibility version for semantics (`compat.go:9`) and capability sets (`caps.go:88`) for features. Return capabilities in an initial probe (`GetSystemInfo` at `workflow_handler.go:3498`, `Info` at `control/control.go:663`) so clients can degrade before issuing writes.

## Practical Tips

### Patterns to copy

1. **Mint a durable handle before execution and persist it.** Client-generated `Ref`/`RunId`/`RequestId` stored in the rendezvous is the only thing that makes "another client finds it" true. Test it with `kill -9 $SUBMITTER_PID` (`temporal interrupt.go:9`, containerd `integration/client/client_test.go:499` pattern).

2. **Absolutize all filesystem inputs at startup.** `filepath.Abs` for `Root`/`State` (`cmd/buildkitd/main.go:366`, `cmd/containerd/command/main.go:311`) plus `WorkspaceLoadTarget` validation eliminates CWD drift. Reject relative `python_file` without `working_directory` (`loadable_target_origin.py:30` contract).

3. **Make namespace/header required and default it explicitly.** `NamespaceRequired` failing closed (`pkg/namespaces/context.go:68`) + CLI default `CONTAINERD_NAMESPACE=default` (`cmd/ctr/app/main.go:122`) prevents the class of bugs where programmatic clients forget scoping.

4. **Give local and remote transports distinct auth profiles.** `GetLocalListener` with `uid/gid` + `0660` (`socket_unix.go:62`) for local; `credentials.NewTLS` with `RequireAndVerifyClientCert` (`cmd/buildkitd/main.go:845`, `rpc.go:164`) and JWT interceptors (`interceptor.go:129`) for TCP.

5. **Implement reconnect as a stored connector closure.** `Client.connector func() (*grpc.ClientConn, error)` (`client/client.go:227`, `ttrpcutil/client.go:33`) that `Reconnect()` just re-invokes makes reconnection transparent without leaking dial options.

6. **Poll liveness with bounded TTL + re-entrant cleanup.** `heartbeat_ttl=20/45` + watch thread (`server_watcher.py:24`) that shuts down after silence (`server.py:535`) and `_clear_old_processes` thread (`grpc_server_registry.py:246`) prevent orphans without locks.

7. **Drain before you close.** Health → `SetDraining(true)` (`membership/interfaces.go:59`) → wait → `GracefulStop` → hard `Stop` (`frontend/service.go:543`). BuildKit's two-stage `appContext`/`shutdownContext` (`appcontext.go:15`) variant covers SIGTERM coordination.

8. **Use interceptors for every cross-cutting concern and document the order.** Namespace before auth before rate limit (`frontend/fx.go:286`) — stripping spoofable headers unconditionally (`interceptor.go:156`) is the defense-in-depth detail worth copying.

### Patterns to avoid or delay

1. **Fatally exiting the serve goroutine on transient errors** (`plugins/server/internal/serve.go:35` `log.Fatal`). Replace with a drain that stops accepting, fails health, and exits with status — let the supervisor restart cleanly.

2. **`Chmod 0666` on a Unix socket** (`main_unix.go:58`) for convenience. Prefer `0660` + explicit group, or add `SO_PEERCRED`/`getpeereid` validation in the session handler. The compatibility argument is real but should be a flag, not the default.

3. **Unary RPCs for long-lived work without a reattach handle.** BuildKit's `Solve` being unary (`control.proto:17`) is the cautionary example — a `CreateJob`→`Start` split with a persistent descriptor avoids fate-sharing. Avoid until you have a lease/GC story (`history/buildhistory.go:104` lease pattern).

4. **Silent `0660` inherit + `127-char` TTRPC path.** Containerd's derivation `address+".ttrpc"` (`plugins/server/ttrpc/plugin.go:50` / `config.go:306`) can exceed 104 chars and doubles files without explicit per-listener config. Make TTRPC address explicit.

5. **Insecure-by-default local gRPC for TCP-equivalent paths** (`dagster client.py:131`, buildkit TCP without TLS warned at `main.go:787`). If the code-server could be on another host, never use `add_insecure_port` (`dagster server.py:1525`) or `insecure.NewCredentials()` (`client/client.go:144`) on that plane — use mTLS even for dev with auto-generated certs.

6. **CWD-relative `--address` / `--config` flags.** Both `client/client.go:167` and containerd's `DialAddress` don't `Abs`; `cmd/server/main.go:41` `root="."` joins with config dir. Absolutize addresses at flag parse or the client and daemon will disagree under different `cwd`.

7. **Lazy shared storage without fence for duplicate daemons.** Dagster's log-only duplicate detection (`daemon.py:182`) lets double-submit double-execute; add advisory locks or `SELECT FOR UPDATE` on `daemon_type` if sensor idempotency is not guaranteed by run-key dedup (`sensor.py:1131`).

### Decision rules

- **Need survivor after submitter exit and after daemon restart?** — persist to rendezvous and re-parent. Containerd's shim proves even `TestDaemonReconnectsToShimIOPipesOnRestart` (`container_linux_test.go:401`); dagster's `QueuedRunCoordinatorDaemon` (`queued_run_coordinator_daemon.py:194`) proves DB-re-read; temporal's shard handover (`caching_redirector.go:205`) proves replica takeover.

- **Inputs are local files that must not be copied?** — stream over a session (`client/solve.go:141` `FSSyncProvider`) but give the session a resumable `sharedKey` + `id` (`session/session.go:51`) and allow reconnect by same ID (`manager.go:149` wait logic). Don't abort on first `ctx.Done()` without retry.

- **Have >1 frontend or >1 daemon type?** — use membership draining + health, not just `bytes` persisted. Temporal's `SetDraining` used by both ringpop and LB is the model.

### Caution signs (the dimension is becoming brittle)

- **Client handle not returned synchronously on submit** — if `StartWorkflowExecution`/`Solve` returns before persisting the handle, kill-at-acceptance loses the operation. Pin a test for it.

- **Any `Getwd`/`Chdir` in daemon dispatch paths** outside startup absolutization — grep for it; containerd shim's `os.Getwd()` (`pkg/shim/shim.go:460`) is acceptable only because it's scope-limited.

- **Forgotten namespace/metadata on new RPCs** — if adding a service bypasses the namespace interceptor (`plugins/server/grpc/namespace.go:26`), tenancy is broken silently. Gate via interceptor registration, not handler discipline.

- **GracefulStop blocked on leaked finalizers** — `history/buildhistory.go:489` `AcquireFinalizer` `done` chan never fired → `ps.Close()` never fires → `ListenBuildHistory` hangs after SIGTERM. Every finalizer must be the only reference and must call `done()` on both success and cancel.

- **In-flight stream fate-sharing multiplying** — if more than one user-visible operation becomes session-dependent (`filesync` + `auth` + `sshforward` over one connection), tag each with independent liveness or multiplex needs backpressure (existing throttled GC at `control/control.go:143` is a hint that multiplexed-plane backpressure matters).

- **Version skew without capability probe** — if clients call new fields before `Info`/`GetSystemInfo`/`Ping` (`control/control.go:663`, `workflow_handler.go:3498`, `client.py:545` fallback), rolling upgrades break. Always probe capabilities before writes.

## Anti-Patterns / Caution Signs

- **0666 world-readable socket after setgid** (`buildkit main_unix.go:58`) and **`insecure.NewCredentials()` on Unix** (`containerd client/client.go:144`). Any local UID in the group — or on 0666, any UID — can invoke privileged entitlements (`network.host`, `snapshots.Prepare`). Mitigation is `0600/0660` + `SO_PEERCRED` or mandatory mTLS.

- **Optional TLS on TCP with warning only** (`buildkit main.go:787` `"TLS is not enabled ... highly recommended"`, containerd `plugins/server/grpc/plugin.go:186` absent file silently skips plugin). Plaintext executor traffic on TCP is the concrete risk — `README.md:703` flag.

- **Unary long-lived RPC tied to caller context as the only handle** (`buildkit control/control.go:409` `Solve`). Violates the kill-test invariant; a single `Close` on the client must not be a `Cancel` on the operation.

- **Noop authorizer that only warns** (`temporal cmd/server/main.go:203` `allow-no-auth`) and **DB trust with no token on code servers** (`dagster client.py:78` metadata plumbing unused). Serves as open deployment foot-gun; future hard-requirement warning exists but is not enforced.

- **Dial retry hot-loop on ENOENT** (`containerd pkg/dialer/dialer.go:49` 10ms poll) with no readiness notification. Masks startup ordering but can busy-wait under timeout.

- **Stale daemon not fenced** (`dagster daemon.py:182` log-only, `sql_run_storage.py:852` last-write-wins). Double daemon → double sensor ticks; guarantee must be run-key idempotency (`sensor.py:1131`) or explicit fence.

- **Socket path length 104-char hard failure** (`containerd pkg/sys/socket_unix.go:33`). No truncation or abstract-socket fallback; derived `".ttrpc"` path amplifies.

- **Fatal on serve error** (`plugins/server/internal/serve.go:35`). No drain, no status propagation — systemd sees crash-loop, not degraded health.

## Notable Absences

- **Peer-credential authentication for Unix sockets.** No source uses `SO_PEERCRED`/`SCM_CREDENTIALS` (`GetsockoptUcred` on `net.UnixConn`). Containerd and buildkit audit this as future work; current auth is permission-bit only.

- **First-class authenticated local transport in temporal.** Despite the most complete interceptor chain, there is no UDS/named-pipe listener (`rpc.go:200` TCP only). The study probes for it and it is absent.

- **Daemon RPC for dagster submission and health.** Confirmed absent — no `DagsterDaemon` service in `dagster_api.proto:7`, daemon health only via DB heartbeats, reconnect only by restarting the daemon process. A push/notify API and faster failure detection would require one.

- **True detached Solve / reattachable session in buildkit.** `Session` streams cannot be resumed by same `id+sharedKey` (`session/manager.go:149` already supports wait, but `client/solve.go:248` never retries), and no `ReattachSolve` RPC exists. `Status` is observable-only.

- **Per-RPC version negotiation in containerd.** Beyond `ConfigVersion` migration (`version/version.go:41`) and `Version` service (`plugins/services/version/service.go:54`), there is no capability handshake; clients discover version out-of-band.

- **Streaming resumption cursor for events.** Containerd `Subscribe` (`client/events.go:80`) and buildkit `Status` (`control/control.go:594` 5s inactivity timer at `client/solve.go:255`) both require manual re-issue after disconnect; no sequence cursor or replay. Same for dagster `event_log_storage`.

- **Token rotation for TCP TLS listeners.** `LoadX509KeyPair` at init (`plugins/server/grpc/plugin.go:186`, `buildkit main.go:813`) with no rotation without restart; no evidence of short-lived token fetching except temporal cross-cluster (`rpc.go:282`).

## Per-Source Notes

### buildkit — 7/10 — Single-daemon, RPC-coupled

The narrowest control plane of the four: `service Control` is the waist (`api/services/control/control.proto:14`) with `Solve`/`Status`/`Session` and BoltDB-backed `history.Queue` (`history/buildhistory.go:51`). The distinctive decision is `grpchijack` (`session/grpchijack/dial.go:18`) tunneling inner gRPC over a single listener — elegant for single-host builds, costly in framing/complexity. The standout mechanic is `Ref`-by-client (`client/solve.go:107`) plus history fallback for re-observation (`solver/llbsolver/solver.go:465`). The caution is fate-sharing: because execution is not detached from the `Solve` caller's context, the kill-test fails for in-flight builds. The report's future direction toward a `CreateJob`→`Start` split with explicit `CancelJob` would directly fix this without external DB.

### containerd — 7/10 — Single-daemon, shim-delegated

The reference for survive-everything local ownership: bolt metadata + `containerd-shim-runc-v2` so even daemon restart preserves tasks (`integration/issue7496_shutdown_linux_test.go:105`). Dual `gRPC + TTRPC` planes (`plugins/server/grpc/plugin.go:66`, `plugins/server/ttrpc/plugin.go:48`) split control and shim-local, and namespace is header-driven via interceptors (`plugins/server/grpc/namespace.go:26`). `Client.Reconnect()` via `connector` (`client/client.go:237`) is the cleanest reconnect abstraction of the four. The tradeoff is local-auth-only: `0660`/`chown` + `insecure` creds is zero-bootstrap but not least-privilege, and the 104-char limit (`pkg/sys/socket_unix.go:33`) is a real deploy trap.

### dagster — 6/10 — DB-polling controller

The most detached and the least authenticated. Work lives in `RunStorage`; the daemon polls (`daemon.py:88`, `controller.py:133`) and writes `DaemonHeartbeat` (`sql_run_storage.py:852`) read by `get_daemon_statuses` (`controller.py:424`). The separate gRPC surface is only to user-code servers (`_grpc/server.py:392`) with explicit `LoadableTargetOrigin.working_directory` (`loadable_target_origin.py:16`) and UDS-or-port XOR (`client.py:71`). Strength is that any observer with DB access recovers any operation; weakness is that liveness is polling (30m stale-healthy window), auth is `insecure_channel`, and versioning is `server_id` + `DefsStateInfo` only (`server.py:433`, `757`).

### temporal — 8/10 — Distributed shard-owned

The mature, production-facing answer: stateless frontends owning nothing durable (`workflow_handler.go:570` hands off to history), shard routing with ownership transfer (`caching_redirector.go:205`), long-poll execution delivery (`matching/handler.go:225`), and the most complete interceptor chain (`fx.go:286`, `authorization/interceptor.go:129`, `namespace_validator.go:34`, `version_checker.go:115`). Drain-before-stop (`frontend/service.go:543`) and round-robin TCP reconnect (`rpc/grpc.go:21`) are battle-tested. Deducted for TCP-only transport (`rpc.go:200`), noop-authorizer default, and legacy CWD-relative config (`main.go:41`) — the report explicitly calls these out as hardening targets.

## Open Questions

- **How would TLS cert rotation happen without restart for TCP listeners?** `plugins/server/grpc/*.go` and `buildkit cmd/buildkitd/main.go:813` only show static `LoadX509KeyPair`; no evidence of rotation or token refresh was found (containerd gaps, temporal gaps).

- **Where should a future dagster daemon health RPC live if DB polling becomes too slow?** No `DagsterDaemon` service exists (`dagster_api.proto:7` gap), destination for an authenticated gRPC/HTTP endpoint keeps being deferred to Cloud.

- **Can buildkit's `Session` be made resumable by `id+sharedKey`?** `session/manager.go:149` already supports wait and prefix-stripping; `client/solve.go:248` never re-dials — whether idempotent `filesync` replay can be made safe under capability negotiation (`session/session.go:105` `headerSessionMethod`) is the open design question.

- **How does containerd reconcile a mid-transfer `Pull` after daemon bounce beyond lease expiry?** `leases` and `transfer` services exist (`api/services/transfer/v1/transfer.proto`) but durability across `client.Close` was not traced beyond lease anchoring.

- **How are temporal queued matching tasks made durable across matching-host loss?** Handler boundary only traced (`service/matching/handler.go:225`); internal queue partition/durability needs a matching-internals pass, and which RPCs the HTTP gateway (`http_api_server.go`) actually exposes over long polls was not traced end-to-end.

- **Dagster `LoadableTargetOrigin` resolution for relative `python_file`?** `load_target.py` not inspected — whether paths resolve relative to config file or daemon CWD when `working_directory` is `None` determines the one remaining CWD fallback risk.
