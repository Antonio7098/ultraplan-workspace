## Executive Summary

Only one of four systems implements real fencing. Temporal (7/10) uses a monotonic `RangeID` checked atomically on every authoritative write; the other three score 2–3/10 and treat leases as GC roots or health telemetry, not ownership. BuildKit and containerd share the same containerd `Lease{ID, CreatedAt, Labels}` primitive (`sources/buildkit/vendor/github.com/containerd/containerd/v2/core/leases/lease.go:42-47`, `sources/containerd/core/leases/lease.go:42-47`) whose only effect is an RFC3339 `containerd.io/gc.expire` label (`sources/containerd/core/leases/lease.go:99`) evaluated lazily at GC mark (`sources/containerd/core/metadata/gc.go:501-581`). Dagster writes a single `daemon_heartbeats` row per `daemon_type` (`python_modules/dagster/dagster/_core/storage/runs/schema.py:94-107`) every 30s (`python_modules/dagster/dagster/_daemon/controller.py:36`) and considers a daemon healthy if `timestamp + 30 + 1800` is in the future (`python_modules/dagster/dagster/_daemon/controller.py:455-458`) — never consulting that health before `update_tick` (`python_modules/dagster/dagster/_core/storage/schedules/sql_schedule_storage.py:419-436`). Across all four, the answer to "pause an old worker until its lease is stolen, then let it finish — can it corrupt state?" is **yes** for buildkit, containerd, and dagster (last-write-wins or duplicate publish) and **no** for temporal (rejected via `ShardOwnershipLostError` / `ErrActivityTaskNotFound`). The convergence is intentional: three systems are single-daemon/single-node and optimize for cache reuse and availability; temporal is the only multi-host orchestrator and pays LWT/ CAS cost for linearizable ownership.

## Core Thesis

Fencing is not a stricter form of lease expiry — it is a different mechanism. A lease expiry that is only evaluated by a periodic janitor (`sources/buildkit/solver/llbsolver/history/buildhistory.go:131-137`, `sources/containerd/core/metadata/gc.go:571`) cannot prevent a stale writer that retains its context from committing a Bolt/DB transaction, because the transaction itself checks no token. Real stale-worker rejection requires a generation checked **inside the same atomic write** as the product-state mutation. Temporal proves this by bundling `IF range_id = ?` with every `Create/UpdateWorkflowExecution` batch (`sources/temporal/common/persistence/cassandra/mutable_state_store.go:453-463`), plus a per-workflow `DBRecordVersion`/`NextEventID` CAS and a token-borne `Attempt`/`ActivityAttemptStamp` check (`sources/temporal/common/tasktoken/token.go:33-61`, `sources/temporal/service/history/api/activity_util.go:58-80`). BuildKit's decorative `BuildHistoryRecord.Generation` (`sources/buildkit/api/services/control/control.proto:215`, bumped unconditionally at `sources/buildkit/solver/llbsolver/history/buildhistory.go:335`) and containerd's PID-as-identity (`sources/containerd/core/runtime/v2/shim.go:571`) show what happens when the field exists but is never a `WHERE` predicate: last-write-wins (`sources/buildkit/solver/llbsolver/history/buildhistory.go:485`) and duplicate `TaskExit{ExitStatus:255}` (`sources/containerd/core/runtime/v2/shim.go:170-179`) with the consumer told "moby should handle duplicate events" (`sources/containerd/core/runtime/v2/shim.go:605-611`). If you need multi-worker safety, copy Temporal's `RangeID`; if you are single-daemon, copy BuildKit's `flightcontrol.Group` dedup (`sources/buildkit/solver/jobs.go:1219-1220`) and be explicit that you do not fence.

## Approach Models

Three archetypes emerge; they are responses to different constraints, not a quality ladder.

**Model A — Implicit single-writer, GC lease for retention (buildkit, containerd).** Ownership is an in-memory mutex (`sources/buildkit/solver/jobs.go:687-712` `jl.mu`, `sources/containerd/core/metadata/db.go:89` `wlock`). A `Lease` is a GC root (`sources/containerd/core/leases/lease.go:32-39` `Create/List/Delete/AddResource` only) with a static wall-clock label (`WithExpiration` at `sources/buildkit/util/leaseutil/manager.go:31-39` and `sources/containerd/core/leases/lease.go:93-102`). Renewal and heartbeat do not exist; the only liveness signal is gRPC stream open (`sources/buildkit/session/manager.go:135-145`) or ttrpc `onClose` (`sources/containerd/core/runtime/v2/shim_manager.go:333-342`). Suitable for a single daemon whose BoltDB is local and whose correctness does not require cross-host fencing.

**Model B — Health heartbeats without fencing (dagster).** Each `DagsterDaemonController` mints `uuid4()` (`python_modules/dagster/dagster/_daemon/controller.py:156`) and UPSERTs `DaemonHeartbeat` (`python_modules/dagster/dagster/_daemon/types.py:25-52`) without CAS (`python_modules/dagster/dagster/_core/storage/runs/sql_run_storage.py:852-873`). Health is `curr_time <= timestamp + interval + tolerance` (`python_modules/dagster/dagster/_daemon/controller.py:452-468`) used only for display and warning (`python_modules/dagster/dagster/_daemon/daemon.py:176-191` logs but continues). The tick model (`python_modules/dagster/dagster/_core/scheduler/instigation.py:590-720`) has no `generation`/`owner_id`; `update_tick` is unconditional (`python_modules/dagster/dagster/_core/storage/schedules/sql_schedule_storage.py:419-436`). Suitable when deployment is guaranteed single-daemon by ops and the cost of a DB CAS on every tick exceeds the risk.

**Model C — Monotonic fencing token with bundled CAS (temporal).** Each shard row carries `RangeId` (`sources/temporal/common/persistence/data_interfaces.go:184-195`, `sources/temporal/common/persistence/cassandra/shard_store.go:29-37`). Acquisition is `UpdateShard IF range_id = PreviousRangeID` with `RangeId++` (`sources/temporal/common/persistence/cassandra/shard_store.go:119-152`, `sources/temporal/service/history/shard/context_impl.go:1164-1208`). Every workflow mutation bundles `RangeID` in the same logged batch as the workflow row CAS on `DBRecordVersion`/`NextEventID` (`sources/temporal/common/persistence/cassandra/mutable_state_store.go:453-463`, `701-712`). Activity completions are additionally fenced by token fields `Attempt`/`ActivityAttemptStamp` (`sources/temporal/common/tasktoken/token.go:33-61`) validated before any DB write (`sources/temporal/service/history/api/activity_util.go:58-80`). Membership (`sources/temporal/service/history/shard/ownership.go:132-147`) decides *should-own*; persistence decides *can-write*. Suitable for multi-host, multi-shard ownership that must survive membership churn without wall-clock dependence.

## Pattern Catalog

### 1. GC lease as retention root (not a fence)

*Problem:* Keep content/snapshots alive between `Prepare` and `Commit` across daemon crash or pull gap.
*Sources:* buildkit (`sources/buildkit/util/leaseutil/manager.go:31-39` 1h default, `sources/buildkit/solver/llbsolver/history/buildhistory.go:567` 5m blob lease), containerd (`sources/containerd/core/metadata/gc.go:594-658`, `sources/containerd/core/metadata/content.go:458` 24h ingest expiry, `sources/containerd/client/lease.go:27-53` no ticker).
*Why it works:* Zero contention on writes; leases survive crash without renewal; simple to inspect via `Labels["containerd.io/gc.expire"]`.
*When to copy:* Single-node daemon where you only need to defer GC, not revoke writers.
*When it is risky:* When you mistake retention for revocation. Expiry is evaluated only at `scanRoots`/`gc()` tick (`sources/containerd/core/metadata/gc.go:501`, `sources/buildkit/solver/llbsolver/history/buildhistory.go:131`), so a stale worker holding `WithLease(ctx, id)` can still `Update` after expiry.
*Evidence:* `sources/containerd/core/metadata/gc.go:501-581` `expThreshold.After(exp) { skip root }`; `sources/buildkit/util/leaseutil/manager.go:13-29` `WithLease` returns `Delete` closer, no ticker.

### 2. Content-addressed dedup + single-flight barrier as alternative to fencing

*Problem:* Prevent duplicate execution without distributed coordination.
*Sources:* buildkit (`sources/buildkit/solver/jobs.go:530-663` `actives[digest]` map, `sources/buildkit/solver/jobs.go:992-997` `sharedOp{gDigest,gCacheRes,gExecRes flightcontrol.Group}`, `sources/buildkit/solver/jobs.go:1219-1220` `gExecRes.Do(ctx,"exec",…)`), containerd (`sources/containerd/core/metadata/content.go:696-718` `createBlobBucket → ErrAlreadyExists` dedup).
*Why it works:* Canonicalizes work by `Vertex.Digest()` so two callers share one `Exec`; first result is cached in `execDone`/`execRes`, second caller gets cached value, not a racy overwrite.
*When to copy:* Cacheable, deterministic work in a single process where reuse > quarantine.
*When it is overkill/risky:* When you need to quarantine a suspect execution — there is no `(Ref,attempt)` key; only `IgnoreCache` escapes (`sources/buildkit/solver/jobs.go:563-565`). Memory-pressure eviction of `actives` is untested for paused exec (`sources/buildkit/solver/jobs.go:745-783`).
*Evidence:* buildkit report Section "Architectural Decisions — Single-daemon, single-writer, collapse-duplicates".

### 3. Bundled RangeID + workflow CAS in one atomic batch

*Problem:* Ensure shard ownership and workflow linearizability in one round-trip without distributed transaction.
*Sources:* temporal (`sources/temporal/common/persistence/cassandra/mutable_state_store.go:453-463`, `701-712`, `833-844`, `sources/temporal/common/persistence/sql/execution.go:73,354,470`).
*Why it works:* Logged batch/Paxos predicate checks both `IF range_id = ?` and `IF db_record_version = ?`; priority sorting (`sources/temporal/common/persistence/cassandra/errors.go:18-24` `ShardOwnershipLostError` > `CurrentWorkflowConditionFailedError` > `WorkflowConditionFailedError`) surfaces the right retry signal.
*When to copy:* Any multi-writer service over Cassandra/SQL where you can pay LWT cost and want lease revocation without clock.
*Cost:* Per-shard `ioSemaphore` throttling (`sources/temporal/service/history/shard/context_impl.go:129-130`) limits write throughput; SQL path needs `SELECT FOR UPDATE` on `shards`.
*Evidence:* temporal report "Conditional updates" evidence rows 31–45; `handleWriteErrorLocked` forces `transition(Stop{OwnershipLost})` on failure (`sources/temporal/service/history/shard/context_impl.go:1491-1550`).

### 4. Token-borne generation for late-completion shedding

*Problem:* Reject a late `RespondActivityTaskCompleted` from a superseded attempt without a DB read.
*Sources:* temporal (`sources/temporal/common/tasktoken/token.go:33-61` `Attempt`, `ActivityAttemptStamp`, `StartVersion`, `sources/temporal/service/history/api/activity_util.go:58-80` `IsActivityTaskNotFoundForToken`, `sources/temporal/service/history/consts/const.go:31-40` `ErrStaleReference`), dagster partial analogue (`python_modules/dagster/dagster/_daemon/sensor.py:1339-1375` `run_key` dedup and `python_modules/dagster/dagster/_daemon/sensor.py:1292-1336` `fetch_existing_runs`).
*Why it works:* Token encodes `(ScheduledEventId, Attempt, ActivityAttemptStamp)` at dispatch; validation happens before `GetAndUpdateWorkflowWithNew`, so superseded attempt yields `NotFound` without touching workflow row. Dagster's `RUN_KEY_TAG` dedup is weaker — it prevents duplicate `NOT_STARTED` runs but not cursor overwrite.
*When to copy:* Stateless workers where the controller mints the capability; always include `attempt` + `stamp`/`nonce`, not just event ID.
*When it is risky:* If `ActivityAttemptStamp` is omitted or `Attempt` alone is checked, retries with same attempt number pass.
*Evidence:* temporal `service/history/api/respondactivitytaskcompleted/api.go:85-86` returns `ErrActivityTaskNotFound`; dagster `SensorLaunchContext._write` unconditionally `update_tick` then `update_instigator_state` (`python_modules/dagster/dagster/_daemon/sensor.py:232-282`) still overwrites cursor.

### 5. Warning-only multi-writer detection (anti-pattern to fix)

*Problem:* Detect split-brain.
*Sources:* dagster (`python_modules/dagster/dagster/_daemon/daemon.py:176-191` logs "Another … daemon is still sending heartbeats" then writes anyway), containerd (`sources/containerd/core/runtime/v2/shim.go:605-611` notes duplicate `TaskExit` and delegates to "moby should handle"), buildkit (no detection; second `NewJob(same Ref)` returns `job ID exists` only for identical `Ref`, but different `Ref` with same digest shares state).
*Why it fails:* Detection without enforcement leaves `update_tick`/`TaskExit`/`b.Put` to last-write-wins.
*When to copy (fixed):* Change log to `abort` or `LeaseLost` and make the next mutation `WHERE owner = expected` fail (`python_modules/dagster/dagster/_daemon/daemon.py:182` → exit/renew).
*Evidence:* dagster report "Warning-only multi-writer detection" notable pattern; containerd `pkg/shim/publisher.go:40-127` requeues same `Envelope` up to 5 times.

### 6. Drain-then-bump and detached persistence context

*Problem:* Avoid spurious fence failures and ambiguous commit outcomes.
*Sources:* temporal (`sources/temporal/service/history/shard/context_impl.go:1164-1208` `drainTaskRequests()` before `UpdateShard`, `sources/temporal/service/history/shard/context_impl.go:2408-2433` `newDetachedContext`).
*Why it works:* Draining guarantees no in-flight `AddHistoryTasks` is conditioned on a stale `RangeID` when the bump commits; detached context prevents caller cancellation from leaving `LWT` outcome unknown (then `handleWriteErrorLocked` `transition(Lost)` forces reacquire).
*When to copy:* Any renew path where renewal increments a fencing token shared with concurrent writes.
*Evidence:* temporal report Architectural Decisions table rows 4–5.

### 7. UUID + monotonic sequence for process incarnation (observability, not fence)

*Problem:* Distinguish PID reuse.
*Sources:* temporal (`sources/temporal/service/history/shard/context_impl.go:2198-2203` `hostIdentity-sequenceID-uuid`), dagster (`python_modules/dagster/dagster/_daemon/controller.py:156` `uuid4()`, `python_modules/dagster/dagster/_daemon/types.py:32` `daemon_id`), containerd negative example (`sources/containerd/core/runtime/v2/shim.go:571` raw `Pid uint32`, `sources/containerd/api/events/task.proto:59` `TaskExit.Pid`).
*Why it works (when fenced):* Random nonce distinguishes restarts; must be part of CAS predicate to be effective. Temporal currently stores `ShardInfo.Owner` but never checks it in CAS (`sources/temporal/common/persistence/cassandra/shard_store.go:126-134` only checks `range_id`); dagster stores `daemon_id` but only logs it.
*When to copy:* Always prefer UUID/nonce over PID; if you need PID fencing, pair it with `boot_id` or `shim_generation` in `bootstrap.json` (`sources/containerd/core/runtime/v2/shim.go:294`) and include in predicate.
*Evidence:* temporal Q4, containerd Q4, dagster Q4 answers.

## Key Differences

**What converges:** Despite different stacks (Go/BoltDB, Python/SQLAlchemy, Go/Cassandra), buildkit, containerd, and dagster converge on *leases-as-advisory* — expiry is wall-clock, evaluated by a janitor, never checked before mutation. BuildKit's `WithLease` (`sources/buildkit/util/leaseutil/manager.go:13-29`), containerd's `WithLease` (`sources/containerd/client/lease.go:27-53`), and Dagster's `add_daemon_heartbeat` (`python_modules/dagster/dagster/_daemon/daemon.py:194-201`) all last-write-wins. All three explicitly document single-writer deployment as the safety model (BuildKit single daemon, containerd single-host `bbolt`, Dagster "not supported" log at `python_modules/dagster/dagster/_daemon/daemon.py:183-184`). All three lack conditional updates on product state: `history.Queue.update` does unconditional `b.Put` (`sources/buildkit/solver/llbsolver/history/buildhistory.go:485`), `containerStore.Update` does read-modify-write without `expected revision` (`sources/containerd/core/metadata/containers.go:194-279`), `update_tick` does `UPDATE WHERE id` without version (`python_modules/dagster/dagster/_core/storage/schedules/sql_schedule_storage.py:432`).

**Why sources diverge:** Product shape and operational constraints explain the gap, not just maturity.
* Temporal must survive host failure and rebalancing across shards; wall-clock leases would require cross-DC clock trust and still not bound staleness without writes. It chose computation-free monotonic `RangeID` (`sources/temporal/common/persistence/cassandra/shard_store.go:119-152`) plus membership oracle (`sources/temporal/service/history/shard/ownership.go:132-147`) — correct for an orchestrator where workflow correctness is primary.
* BuildKit optimizes for cache sharing; fencing would break `actives[digest]` sharing and `flightcontrol.Group` reuse. Its GC leases (1h default, 5m blob at `sources/buildkit/solver/llbsolver/history/buildhistory.go:568`) exist to keep intermediate blobs alive for export (`sources/buildkit/solver/llbsolver/solver.go:381-386`), not to fence.
* Containerd optimizes for zero-contention hot path; adding a `Revision` to every Bolt `Update` would serialize writers under `wlock` and complicate the tricolor GC (`sources/containerd/core/metadata/gc.go:64-194`). Its duplicate-tolerant `TaskExit` contract (`sources/containerd/core/runtime/v2/shim.go:605`) pushes dedup to moby/kubelet, which already reconcile via `Task.State`.
* Dagster optimizes for DB portability (any SQL backend) and low write load; a lease table with `FENCING_TOKEN BIGSERIAL` and `WHERE generation = ?` would require migration and CAS retry loops, but the current heuristic (`MAX_TIME_TO_RESUME_TICK_SECONDS = 24h` at `python_modules/dagster/dagster/_daemon/sensor.py:74-77`) already papers over short outages. Its `daemon_skip_heartbeats_without_errors` flag (`python_modules/dagster/dagster/_core/instance/methods/daemon_methods.py:122-126`) even allows heartbeats to be skipped in Cloud, confirming they are telemetry.

**Fencing scope — where checks live:** Temporal fences product state (workflow rows) *and* artifact dispatch (task queues via `RangeID` at `sources/temporal/common/persistence/data_interfaces.go:498-513`) — but not history branch appends (`AppendHistoryNodes` at `sources/temporal/service/history/shard/context_impl.go:871-908` has no `RangeID`) or delete stages 2–3 (`sources/temporal/service/history/shard/context_impl.go:1040-1085`). BuildKit fences nothing, not even history vs. export vs. content. Containerd fences nothing on Bolt; its `createBlobBucket → ErrAlreadyExists` is dedup, not fence. Dagster fences step concurrency via `SELECT … FOR UPDATE SKIP LOCKED` on `concurrency_slots` (`python_modules/dagster/dagster/_core/storage/event_log/sql_event_log.py:2772-2794`) — which is orthogonal to daemon ownership.

## Tradeoffs

**Monotonic token CAS (temporal) vs. wall-clock expiry (buildkit/containerd/dagster).**
Benefit of CAS: no clock dependence, linearizable revocation on next write, explicit `ShardOwnershipLostError` (`sources/temporal/common/persistence/data_interfaces.go:148-152`) that callers handle. Cost: every write pays LWT/Paxos latency and `ioSemaphore` contention; idle shard never fenced. Benefit of wall-clock: stateless, debuggable (`ctr leases` label), zero contention, survives GC scan interval. Cost: expiry only enforced at jenitor cadence; clock skew extends/shortens real lifetime; invalid RFC3339 is fail-open (`sources/containerd/core/metadata/gc.go:572-576` logs and keeps lease). Best fit: CAS for multi-host correctness; wall-clock for single-host retention.

**Collapse-duplicates (buildkit) vs. quarantine-by-attempt (temporal).**
BuildKit's `flightcontrol.Group` + `actives` gives maximal cache hit rate across builds; no `(Ref,attempt)` key to force re-execution except `IgnoreCache`. Temporal's `ActivityAttemptStamp` + `Attempt` gives per-attempt isolation so late `Attempt=1` cannot overwrite `Attempt=2`. BuildKit fails open (late writer's result adopted if first hasn't cached), temporal fails closed (`NotFound`). Choose dedup when work is deterministic and cheap to reuse; choose quarantine when side-effects must not be duplicated.

**Availability-over-fencing (temporal linger, containerd duplicate tolerance) vs. fail-fast (dagster warning, buildkit `job ID exists`).**
Temporal lingers old shard up to `min(ShardLingerTimeLimit, 1m)` (`sources/temporal/service/history/shard/controller_impl.go:300-373`) polling no-op `AssertOwnership` — keeps serving reads during rebalance but extends dual-ownership window. Containerd's "moby should handle duplicates" keeps runtime simple. Dagster's log-and-continue keeps daemon alive but silently corrupts cursor. Failing fast (exit on heartbeat mismatch, `Renew` failure) would reduce corruption at cost of operator-visible flapping; linger improves graceful handover at cost of bounded inconsistency.

**Per-workflow version fencing vs. no version.**
Temporal's `DBRecordVersion`/`NextEventID` (`sources/temporal/common/persistence/cassandra/mutable_state_store.go:107-123`) provides linearizability even within one shard owner; clients retry on `WorkflowConditionFailedError`. BuildKit, containerd, dagster have no per-object version, so concurrent `UpdateRef`/`Update`/`update_tick` both read `G`, both write `G+1`, last writer silently overwrites (`sources/buildkit/solver/llbsolver/history/buildhistory.go:335-485`, `python_modules/dagster/dagster/_core/storage/schedules/sql_schedule_storage.py:419-436`).

## Decision Guide

Use this when choosing a model for a new daemon/service.

*Choose Temporal's RangeID pattern if* you run multiple hosts, rebalancing is possible, or correctness under split-brain matters. Steps: (1) add `range_id`/`fencing_token BIGINT` + `previous_range_id` to ownership table; (2) increment via `IF range_id = ?`; (3) bundle `IF range_id = ?` with every authoritative mutation in the same batch/transaction; (4) surface `OwnershipLost` as non-retryable and transition shard to `Stopping`/`Lost` (`sources/temporal/service/history/shard/context_impl.go:1491-1549`); (5) drain in-flight writes before bump and use detached context for persistence calls.

*Choose GC leases (buildkit/containerd style) if* you are single-host, state is local Bolt/bbolt, and you only need to prevent GC between related writes (content ingest → snapshot → container). Keep expiries short and do not call them leases; document they do not fence. Accept duplicate-tolerant events or last-write-wins explicitly.

*Choose Dagster-style heartbeats only if* single-daemon is enforced by deployment (k8s `replicas:1`, systemd) and you can tolerate manual recovery. If you stay here, tighten it: add a unique lease row per `daemon_type` with `holder_id + expires_at` and make tick updates `WHERE owner = :expected` with `LeaseLost` handling. Do not keep the 30-min tolerance (`python_modules/dagster/dagster/_daemon/controller.py:36`) if you do — use `expires_at = now() + 2*interval` and renew at `interval/3`.

*Do not* add a decorative `Generation`/`version` column without wiring it to `WHERE version = ?`. BuildKit's unconditional `br.Generation++` (`sources/buildkit/solver/llbsolver/history/buildhistory.go:335`) and Temporal's unused `ShardInfo.Owner` (`sources/temporal/service/history/shard/context_impl.go:1914`) both prove a field without a predicate gives observability but no safety. If you store it, enforce it, expose `expectedGeneration` on the API, and return `Conflict`.

*Identity:* always mint a random nonce per incarnation (UUID/nonce, not PID). Use it in the fencing predicate or at least in logs. If you must use PID, add `boot_id`/`shim_generation` in `bootstrap.json` (`sources/containerd/core/runtime/v2/shim.go:294`) and include it in `TaskExit` validation.

## Practical Tips

**Patterns to copy**
- Bundle ownership check with the business write atomically. Copy temporal's `templateUpdateLeaseQuery` inside the same batch as the workflow row (`sources/temporal/common/persistence/cassandra/mutable_state_store.go:453-463`) — never in a separate RPC.
- Drain then bump (`sources/temporal/service/history/shard/context_impl.go:1165-1171` `drainTaskRequests()` before `UpdateShard`) whenever renewal shares a token with concurrent writes.
- Use detached context for persistence (`sources/temporal/service/history/shard/context_impl.go:2408-2433`) so caller cancellation does not leave outcome ambiguous.
- For stateless workers, encode `Attempt` + `Stamp`/`nonce` in the capability token (`sources/temporal/common/tasktoken/token.go:33-61`) and validate before any DB access.
- For single-daemon cache reuse, keep `flightcontrol.Group` + `actives[digest]` (`sources/buildkit/solver/jobs.go:992-997`, `530-663`) — but document it is dedup, not fencing, and provide `IgnoreCache`-like escape hatch.

**Patterns to avoid or delay**
- Do not use `WithExpiration(24h)`/`Labels["containerd.io/gc.expire"]` as revocation (`sources/containerd/core/leases/lease.go:93-102`, `sources/containerd/core/metadata/gc.go:501`). It is retention. Call it `gc_grace_period`.
- Do not implement `AssertOwnership` as no-op (`sources/temporal/common/persistence/cassandra/shard_store.go:158-164`, `sources/temporal/common/persistence/sql/shard.go:115-121`) and then linger waiting on it (`sources/temporal/service/history/shard/controller_impl.go:369`). If you linger, assert must read `range_id`.
- Do not log split-brain and continue (`python_modules/dagster/dagster/_daemon/daemon.py:182-191`). Fail the tick or exit the process.
- Do not use `context.TODO()` for post-completion writers (`sources/buildkit/solver/llbsolver/history.go:318-327`). Propagate the fencing token instead; otherwise a new incarnation with same `ref_<Ref>` (`sources/buildkit/solver/llbsolver/history/buildhistory.go:279`) races with the old finalizer.
- Do not fail open on parse error (`sources/containerd/core/metadata/gc.go:572-576` `log Info` + keep lease). Fail closed or delete the label.

**Caution signs the design is becoming brittle**
- A `generation`/`version`/`revision` field is incremented but never appears in a `WHERE` clause — as in buildkit `Generation` (`sources/buildkit/solver/llbsolver/history/buildhistory.go:335`).
- Lease/heartbeat logic has no heartbeat loop and no `Renew` on the manager interface (`sources/containerd/core/leases/lease.go:32-39` has `Create,Delete,List,AddResource` only; grep for `heartbeat` returns zero).
- Authoritative mutations are `UPDATE WHERE id` / `b.Put` / `DB.Update` without expected-value predicate (`python_modules/dagster/dagster/_core/storage/schedules/sql_schedule_storage.py:432`, `sources/buildkit/solver/llbsolver/history/buildhistory.go:485`, `sources/containerd/core/metadata/containers.go:194`).
- Late completions are documented as caller-responsible ("moby should handle duplicate events" at `sources/containerd/core/runtime/v2/shim.go:610`).
- `Envelope.Timestamp`/`DaemonHeartbeat.timestamp` wall-clock is compared without monotonic guard (`python_modules/dagster/dagster/_daemon/controller.py:432-458`, `sources/containerd/core/events/events.go:27-32`).

## Anti-Patterns / Caution Signs

- **Decorative generation.** `BuildHistoryRecord.Generation` (`sources/buildkit/api/services/control/control.proto:215`) bumped unconditionally and never checked. Same shape as adding `revision` to containerd `Lease` without using it.
- **Lease as lock.** `Manager.Create(WithRandomID, WithExpiration(1h))` (`sources/buildkit/util/leaseutil/manager.go:32`) and `client.WithLease` default 24h (`sources/containerd/client/lease.go:41`) look like locks but are GC hints. `LeaseRef.Adopt` copy-then-async-`Discard` (`sources/buildkit/util/leaseutil/manager.go:54-81`) has a window where resources are reachable from two leases.
- **Wall-clock labels with RFC3339 without monotonic.** `WithExpiration(d)` formats `time.Now().Add(d).Format(RFC3339)` (`sources/containerd/core/leases/lease.go:99`); `scanRoots` parses with `time.Parse` (`sources/containerd/core/metadata/gc.go:572`). Seconds precision loses sub-second ordering; invalid label is kept forever.
- **In-memory dedup as distributed lock.** `sensor_tick_futures[selector_id]` (`python_modules/dagster/dagster/_daemon/sensor.py:474-492`) guards only within one OS process; two hosts race.
- **Warning without enforcement.** Heartbeat mismatch (`python_modules/dagster/dagster/_daemon/daemon.py:176-191`), duplicate `TaskExit` tolerance, linger with no-op `AssertOwnership` — all observe but do not fence.
- **Last-write-wins on authoritative state.** `SensorLaunchContext._write` (`python_modules/dagster/dagster/_daemon/sensor.py:232-282`) overwrites `cursor`/`last_tick_success_timestamp`, `history.Queue.update` overwrites `Trace` after `COMPLETE` (`sources/buildkit/solver/llbsolver/history.go:285-331`), `containerStore.Update` overwrites `Labels/Spec` — none return `Conflict`.

## Notable Absences

- **No heartbeat/renewal loop in three sources.** BuildKit `WithLease` returns a `Delete` closer with no ticker (`sources/buildkit/util/leaseutil/manager.go:13-29`); containerd has zero `heartbeat` hits in `core/`; dagster throttles on local `self._last_heartbeat_time` (`python_modules/dagster/dagster/_daemon/daemon.py:147-192`) but renewal is not tied to ownership.
- **No CAS on product-state mutations in three sources.** BuildKit `b.Put` (`sources/buildkit/solver/llbsolver/history/buildhistory.go:485`), containerd `view readContainer → writeContainer` (`sources/containerd/core/metadata/containers.go:194-279`), dagster `UPDATE WHERE id` (`python_modules/dagster/dagster/_core/storage/schedules/sql_schedule_storage.py:419-436`) — no `WHERE version = expected`.
- **No stale-writer tests in three sources.** BuildKit grep returns only `cachemiss_stale_dep_test.go` (cache-key staleness); containerd `TestLeases` covers `Create/List/Delete` and GC liveness (`sources/containerd/core/metadata/leases_test.go:32-418`) but no fencing; dagster heartbeat tests cover serialization only (`python_modules/dagster/dagster_tests/storage_tests/utils/run_storage.py:1328-1370`); no end-to-end "pause until stolen, resume, assert no corruption".
- **No time-bounded revocation in the fenced system.** Temporal has no lease TTL/keepalive (`sources/temporal/service/history/shard/ownership.go:79-101` ticker is `AcquireShardInterval` membership, not RangeID heartbeat); an idle shard is never fenced without a write. `AppendHistoryNodes` (`sources/temporal/service/history/shard/context_impl.go:871-908`) and delete stages 2–3 (`sources/temporal/service/history/shard/context_impl.go:1040-1085`) lack `RangeID` — flagged in temporal report as gaps.
- **No generation on tick/sensor state.** Dagster `TickData`/`InstigatorTick` (`python_modules/dagster/dagster/_core/scheduler/instigation.py:590-720`) carry `tick_id`/`status`/`cursor` but no `generation`/`owner_id`/`lease_expiry`; no FK to `daemon_heartbeats`.
- **Process identity never participates in CAS.** Temporal `ShardInfo.Owner` (`sources/temporal/service/history/shard/context_impl.go:2201`), dagster `daemon_id` (`python_modules/dagster/dagster/_daemon/types.py:32`), containerd `Pid uint32` — none are fencing predicates. Reuse after `Job.Discard` 10s grace (`sources/buildkit/solver/jobs.go:890-897`) allows same `Ref` to be re-inserted with new `Job` but same `ref_<Ref>` lease.

## Per-Source Notes

**buildkit (3/10) — Intentional single-daemon, unfenced.** Evidence is strongest for "no fence by design": `Solver` holds `jobs` + `actives` under `jl.mu` (`sources/buildkit/solver/jobs.go:42-44`, `687-712`), `sharedOp.gExecRes.Do` guarantees at-most-one `Exec` (`sources/buildkit/solver/jobs.go:1219`), and leases are GC roots with 1h/5m expiries never renewed. The `Generation` field is the clearest near-miss — easy to harden into CAS by adding `if br.Generation != expected { return ErrConflict }` at `sources/buildkit/solver/llbsolver/history/buildhistory.go:335` and exposing `expectedGeneration` on `UpdateBuildHistoryRequest` (`sources/buildkit/api/services/control/control.proto:227`). Late completion is deduped at the scheduler layer but last-write-wins at the history layer (async `UpdateRef` with `context.TODO()`).

**containerd (3/10) — GC correctness is mature; fencing is absent.** The label-ref callback graph (`sources/containerd/core/metadata/gc.go:223-446`) and `GC.Tricolor`/`ConcurrentMark` are the most thorough GC mechanism in the study, with well-tested `WithLease` context propagation (`sources/containerd/core/leases/context.go:23-40`, `grpc.go:30-57`). That maturity makes the absence of fencing more load-bearing: callers like moby must be idempotent because `TaskExit` can be delivered twice (`sources/containerd/core/runtime/v2/shim.go:605-611`) and Bolt `Update` is last-writer-wins. Minimal hardening is adding `Revision uint64` + `UpdateIfMatch` on `Container` inside the existing `Update` txn at `sources/containerd/core/metadata/containers.go:205`.

**dagster (2/10) — Telemetry, not a lease.** The study found the most explicit documentation that fencing is out of scope: heartbeat interval 30s + 30-min tolerance for display, `daemon_skip_heartbeats_without_errors` to reduce writes, and a 24h heuristic to `SKIPPED` abandoned ticks (`python_modules/dagster/dagster/_daemon/sensor.py:538-555`). The `run_key` dedup (`python_modules/dagster/dagster/_daemon/sensor.py:1339-1375`) is the only mitigation that survives stale resume, but `SensorLaunchContext._write` still corrupts `cursor`. Adding a `daemon_leases` table with `fencing_token` checked in `update_tick` is the cited path forward.

**temporal (7/10) — Reference model for fencing.** Every primary write path is shard-fenced and workflow-version-fenced in one batch, error priority ensures `ShardOwnershipLostError` (`sources/temporal/common/persistence/cassandra/errors.go:18-24`, `48-104`) surfaces first, and token validation sheds late completions before touching DB. Gaps that keep it from 9/10 are all heartbeat/revocation related: lazy revocation (no TTL), `AssertShardOwnership` no-op (`sources/temporal/common/persistence/cassandra/shard_store.go:158-164`), unfenced delete/history-append, and `Owner` string not in CAS. The "pause until stolen, let it finish" test is described in report Section "Architectural Decisions" but not found as an integration test.
