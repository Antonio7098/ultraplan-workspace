## Executive Summary

All four sources reconcile desired-vs-observed state, but they split into two camps on execution semantics. BuildKit is the outlier: an in-memory DAG reconciler with at-most-once-per-process semantics, content-key dedup, and no step-retry policy — correct for hermetic builds, unsafe for side-effecting steps. Containerd, Dagster, and Temporal all assume the same logical step *can and will* execute more than once, and make that safe through idempotency guards rather than exactly-once machinery — but with very different maturity. Containerd achieves at-least-once implicitly via five independent, stacked retry loops with no shared policy object and no durability for its hottest redelivery queue. Dagster makes at-least-once explicit via tick/queue reconciliation, idempotency keys in run tags, and five *budgeted* retry layers with crash-injection tests — but budgets stack multiplicatively and one launch-vs-STARTED race is acknowledged unfixed. Temporal is the mature reference: durable retry state machines with explicit attempts+time budgets, a published failure taxonomy, centralized backoff/jitter primitives, fair/priority dispatch with rate limits, crash recovery by re-reading persistence, and duplicate-dispatch tests at every layer. The convergent lesson: state the at-least-once contract, separate durable (survives crash) from ephemeral (in-memory) retries, classify failures before budgeting retries, bind every dispatch to an idempotency key plus an attempt generation, and keep scheduled intent distinct from started lease.

## Core Thesis

Durable at-least-once scheduling is not a retry loop — it is a stack of four separable decisions: (1) a desired-vs-observed reconciliation loop with a durable anchor row, (2) an explicit failure taxonomy that decides *what may* retry, (3) a budgeted backoff policy that decides *when and how often*, and (4) an idempotency mechanism (dedup key + attempt token) that makes the inevitable duplicate safe. Sources that conflate these (BuildKit: dedup without retry; containerd: retries without shared taxonomy or durability) stay fragile; sources that separate them (Dagster: tick vs run vs op budgets with tag keys; Temporal: durable timer-owned retries vs ephemeral RPC `ThrottleRetry` with `RequestId` + token generation checks) scale and recover. Capacity recovery follows the same split: process-local semaphores reset on crash (BuildKit, containerd transfer limiters) while durable desired-state re-derives capacity from the store on the next tick (containerd restart labels, Dagster DB re-query, Temporal persistence re-read).

## Approach Models

- **BuildKit — in-memory DAG reconciliation with dedup-as-concurrency-control.** One `scheduler.loop` goroutine owns all graph mutation (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/scheduler.go:61-97`); pressure propagates as `desiredState` escalation (`initial → cache-fast → cache-slow → complete`, `studies/ultraplan-daemon-events-study/sources/buildkit/solver/edge.go:14-25`) through `pipe` channels. Identical vertices coalesce via `edgeIndex.LoadOrStore` + `mergeTo` (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/index.go:81-121`, `studies/ultraplan-daemon-events-study/sources/buildkit/solver/scheduler.go:153-178`) plus `flightcontrol.Group` single-flight (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/jobs.go:995-997`). Capacity lives one layer down as a `semaphore.Weighted` in op `Acquire()` (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/llbsolver/ops/exec.go:592-603`). No retry budget, no taxonomy beyond canceled/not-canceled (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/errdefs/context.go:12-27`), RAM-only memoization. Net: at-most-once per daemon lifetime with content-cache idempotency on reads.
- **Containerd — fragmented controllers, each owning its retry.** No single scheduler: GC threshold-paced reconciler (`studies/ultraplan-daemon-events-study/sources/containerd/plugins/gc/scheduler.go:236`), 10s poll-based restart monitor (`studies/ultraplan-daemon-events-study/sources/containerd/plugins/restart/monitor.go:90`), per-key CRI `EventMonitor` backoff 1s→5min (`studies/ultraplan-daemon-events-study/sources/containerd/internal/cri/server/events/events.go:34`), registry transport (5 attempts, 50ms) + status-code (408/429/5xx) retries (`studies/ultraplan-daemon-events-study/sources/containerd/core/remotes/docker/resolver.go:772`), transfer weighted semaphores (`studies/ultraplan-daemon-events-study/sources/containerd/core/transfer/local/transfer.go:50`). Classification is `errdefs` (`IsNotFound`/`IsAlreadyExists`/`IsUnavailable`) doubling as idempotency signals. At-least-once is never stated; it emerges from redelivery loops plus guards.
- **Dagster — daemon fleet with tick-as-record and queue-with-quotas.** Each daemon is an infinite generator loop with heartbeat liveness (`python_modules/dagster/dagster/_daemon/daemon.py:88`); scheduler aligns iterations to minute boundaries (`python_modules/dagster/dagster/_scheduler/scheduler.py:194`). Desired state comes from code locations, observed from the instance DB (`python_modules/dagster/dagster/_scheduler/scheduler.py:291`); scheduling record is a `TickStatus STARTED/SKIPPED/SUCCESS/FAILURE` with per-tick and cross-tick counters (`python_modules/dagster/dagster/_core/scheduler/instigation.py:305`, `python_modules/dagster/dagster/_core/scheduler/instigation.py:605`). Dequeue computes `max_runs_to_launch = max_concurrent_runs - len(in_progress)` (`python_modules/dagster/dagster/_daemon/run_coordinator/queued_run_coordinator_daemon.py:192`), priority-sorts stable (`python_modules/dagster/dagster/_daemon/run_coordinator/queued_run_coordinator_daemon.py:345`), enforces tag + op-concurrency-pool quotas (`python_modules/dagster/dagster/_daemon/run_coordinator/queued_run_coordinator_daemon.py:269`). Five stacked budgets: op `RetryPolicy` (`python_modules/dagster/dagster/_core/definitions/policy.py:35`), run auto-reexecution (`python_modules/dagster/dagster/_core/execution/retries.py:83`), dequeue re-queue (`python_modules/dagster/dagster/_daemon/run_coordinator/queued_run_coordinator_daemon.py:426`), tick redo (`python_modules/dagster/dagster/_scheduler/scheduler.py:572`), run-health resume (`python_modules/dagster/dagster/_daemon/monitoring/run_monitoring.py:108`). Explicit at-least-once with tag-based idempotency keys.
- **Temporal — durable layered scheduler with timer-owned retries.** Matching runs sync-rendezvous (`service/matching/matcher.go:108-116`, `service/matching/matcher.go:270-372`) plus persistent backlog readers (`service/matching/task_reader.go:46-60`, `service/matching/fair_task_reader.go:245-338`) with priority matcher and `fairLevel{pass,id}` ordering (`service/matching/pri_matcher.go:28-58`, `service/matching/fair_level.go:15-31`); history runs queue readers (`service/history/queues/reader.go:144-159`), a priority scheduler with weighted round-robin (`service/history/queues/scheduler.go:95-185`), executables with `HandleErr` classification (`service/history/queues/executable.go:256-401`), and a `Rescheduler` crash-retry buffer (`service/history/queues/rescheduler.go:23-72`). Durable retries are timer-driven state machines (`RetryActivity`, `service/history/workflow/mutable_state_impl.go:6875-6971`; workflow `getBackoffInterval`, `service/history/workflow/retry.go:31-112`) interpreting one `RetryPolicy` object (`MaximumAttempts`/`MaximumInterval`/expiry, `common/retrypolicy/retry_policy.go:66-141`) gated by `IsRetryableFailure` (`common/retrypolicy/retry_policy.go:27-64`); ephemeral RPC retries are `ThrottleRetry` loops (`common/backoff/retry.go:41-163`) with per-client factories (`common/util.go:38-288`). Backoff is exponential with 20% jitter (`common/backoff/retrypolicy.go:141-185`, `common/backoff/jitter.go:6-22`). At-least-once is the documented design, made safe by `RequestId` dedup + token attempt/clock/version checks.

## Pattern Catalog

- **Single-owner reconcile loop with async work off-thread.** Problem: graph mutation races. Sources: BuildKit (`loop()` owns mutation, `pipe.NewWithFunction` runs work), Dagster (`run_daemon_loop` + `Thread` per daemon, `python_modules/dagster/dagster/_daemon/controller.py:133`), Temporal (queue reader `eventLoop` on `shutdownCh` vs `notifyCh`, `service/history/queues/reader.go:144-159`). Why it works: serializes state transitions while keeping I/O concurrent. Copy when: any DAG/queue controller. Overkill when: single-shot CLI with no concurrency. Evidence: BuildKit `studies/ultraplan-daemon-events-study/sources/buildkit/solver/scheduler.go:61-97`; containerd GC `studies/ultraplan-daemon-events-study/sources/containerd/plugins/gc/scheduler.go:236`.
- **Desired-vs-observed with an explicit intermediate state.** Problem: distinguishing "wanted" from "happening". Sources: BuildKit 4-state `edgeStatusType` + `edgeRequest{desiredState,currentState,currentKeys}` (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/edge.go:14-25`, `studies/ultraplan-daemon-events-study/sources/buildkit/solver/edge.go:116-120`); Dagster code-location desired vs DB observed with `DECLARED_IN_CODE`/12h orphan grace (`python_modules/dagster/dagster/_scheduler/scheduler.py:291`); Temporal mutable-state + timer tasks driving retries to convergence; containerd GC trigger vs `GarbageCollect` execution (`studies/ultraplan-daemon-events-study/sources/containerd/plugins/gc/scheduler.go:266`, `studies/ultraplan-daemon-events-study/sources/containerd/plugins/gc/scheduler.go:298`). Copy when: any controller that must survive restarts. Requires a durable anchor for crash safety (Dagster/Temporal have it; BuildKit does not).
- **Content-key / run-key dedup as concurrency control.** Problem: thundering herd on identical work. Sources: BuildKit `edgeIndex.LoadOrStore` + `mergeTo` + `flightcontrol` (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/index.go:81-121`, `studies/ultraplan-daemon-events-study/sources/buildkit/solver/jobs.go:995-997`, proven by `execCallCount==1` tests at `studies/ultraplan-daemon-events-study/sources/buildkit/solver/scheduler_test.go:206-207`); containerd transfer `imagestore` digest dedup (`studies/ultraplan-daemon-events-study/sources/containerd/core/transfer/local/pull.go:293`); Dagster scheduler match on `(scheduled_execution_time, run_key, repo selector)` (`python_modules/dagster/dagster/_scheduler/scheduler.py:966`) and sensor per-`run_key` fetch (`python_modules/dagster/dagster/_daemon/sensor.py:1292`); Temporal `RequestId` universal key (`service/history/api/startworkflow/api.go:330-360`, `service/history/api/recordactivitytaskstarted/api.go:118-268`). Why it works: duplicates share pipes/results instead of racing. Copy when: hermetic or idempotent steps. Risky when: non-hermetic side effects without a commit key (BuildKit exec has none).
- **Create-then-submit split (anchor row before external actuation).** Problem: crash between work and acknowledgement. Sources: Dagster `_create_scheduler_run` (NOT_STARTED anchor) + `submit_run()` (`python_modules/dagster/dagster/_scheduler/scheduler.py:1004`); Temporal `BufferedStarts{NominalTime,ActualTime}` intent vs `startWorkflow()` with fresh `RequestId` (`service/worker/scheduler/workflow.go:1354-1365`, `service/worker/scheduler/workflow.go:1475-1560`). Copy when: launching external work. BuildKit lacks this (memo set only after `op.Exec` returns, `studies/ultraplan-daemon-events-study/sources/buildkit/solver/jobs.go:1261-1274`) and containerd restart `startChange.apply` bumps label then `NewTask`+`Start` with no fencing (`studies/ultraplan-daemon-events-study/sources/containerd/plugins/restart/change.go:45`).
- **Re-fetch before mutate (the core at-least-once guard).** Problem: concurrent daemon/operator/duplicate-daemon action. Sources: Dagster dequeue re-fetch + skip-if-advanced (`python_modules/dagster/dagster/_daemon/run_coordinator/queued_run_coordinator_daemon.py:372`); Temporal `RecordActivityTaskStarted` same-`RequestId` idempotent return vs `TaskAlreadyStarted` (`service/history/api/recordactivitytaskstarted/api.go:150-171`), token stamp checks (`service/history/api/activity_util.go:58-80`); containerd `IsNotFound`-as-success (`studies/ultraplan-daemon-events-study/sources/containerd/internal/cri/server/podsandbox/controller.go:193`). Copy always for state transitions. Evidence of value: Dagster crash-matrix tests assert single-run resumption (`python_modules/dagster/dagster_tests/scheduler_tests/test_scheduler_failure_recovery.py:155`).
- **Token binds dispatch to attempt generation.** Problem: late completion from a prior generation double-applied. Sources: Temporal task token (`scheduled_event_id/attempt/clock/version/stamp`, `proto/internal/temporal/server/api/token/v1/message.proto:39-55`); Dagster `RETRY_NUMBER=len(group)` (`python_modules/dagster/dagster/_daemon/auto_run_reexecution/auto_run_reexecution.py:106`); BuildKit `SlowCacheError{Index,Result}` attribution (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/jobs.go:1390-1413`) is attribution only, not generation fencing. Copy when: timeouts can cause parallel attempts (heartbeat loss, start-to-close races).
- **Scheduled vs started as distinct events.** Problem: conflating intent with lease hides duplicate-start risk. Sources: Temporal `EVENT_TYPE_ACTIVITY_TASK_SCHEDULED` vs `STARTED` with `StartedEventId==Empty` invariant (`service/history/workflow/mutable_state_impl.go:4334-4395`); Dagster `NOT_STARTED` vs `QUEUED` (`PIPELINE_ENQUEUED`) vs `STARTING` vs `STARTED` vs tick `STARTED` (`python_modules/dagster/dagster/_daemon/run_coordinator/queued_run_coordinator_daemon.py:400`); BuildKit `edgeRequest{desiredState}` vs progress `Started` (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/scheduler.go:220`, `studies/ultraplan-daemon-events-study/sources/buildkit/solver/jobs.go:1368-1388`). Containerd only makes the split on the GC path. Copy when: operators must tell queued from executing, or tests must kill at acknowledgement boundaries.
- **Crash-injection at acknowledgement boundaries for deterministic at-least-once tests.** Problem: redelivery paths untestable without real crashes. Sources: Dagster `check_for_debug_crash(...,"RUN_CREATED"/"RUN_ADDED"/"TICK_SUCCESS")` (`python_modules/dagster/dagster/_scheduler/scheduler.py:825`) with SIGKILL/SIGTERM/exception matrix (`python_modules/dagster/dagster_tests/scheduler_tests/test_scheduler_failure_recovery.py:155`); Temporal duplicate-`RecordActivityTaskStarted` / start-reuse/conflict matrix (`service/history/history_engine2_test.go:989-1050`, `service/history/history_engine_test.go:2701-3155`); BuildKit parallel same-digest `execCallCount==1` tests (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/scheduler_test.go:159-208`); containerd shim failpoint backoff test (`studies/ultraplan-daemon-events-study/sources/containerd/integration/sandbox_run_linux_test.go:25`). Copy whenever claiming idempotency.
- **Capacity as semaphore + quota composition (concurrency, tags, pools, rate limits).** Problem: bounding blast radius without starving tenants. Sources: BuildKit `max-parallelism` semaphore (`studies/ultraplan-daemon-events-study/sources/buildkit/cmd/buildkitd/config/config.go:155-157`); containerd transfer `limiterU/limiterD/limiterP` (`studies/ultraplan-daemon-events-study/sources/containerd/core/transfer/local/transfer.go:50`); Dagster `max_concurrent_runs` + `TagConcurrencyLimitsCounter` + `GlobalOpConcurrencyLimitsCounter` (`python_modules/dagster/dagster/_daemon/run_coordinator/queued_run_coordinator_daemon.py:269`); Temporal namespace/priority rate limiters + forwarder tokens (`service/matching/configs/quotas.go:10-96`). Copy the composition; avoid semaphore-only designs that cannot shed load or report depth.
- **Stable-sort priority with FIFO preservation + shuffled round-robin for fan-out.** Problem: priority without starvation. Sources: Dagster `_priority_sort` (stable descending, FIFO within band, `python_modules/dagster/dagster/_daemon/run_coordinator/queued_run_coordinator_daemon.py:345`) tested with `-100/-1/3/100/foobar` tags (`python_modules/dagster/dagster_tests/daemon_tests/test_queued_run_coordinator_daemon.py:320`); `shuffled_round_robin_by_key` for cross-location fan-out (`python_modules/dagster/dagster/_daemon/utils.py:17`); Temporal `fairLevel{pass,id}` + weighted round-robin (`service/matching/fair_level.go:15-31`, `service/history/queues/scheduler.go:95-185`) with `TestOrder` (`service/matching/matcher_data_test.go:546-607`). Copy when: multi-tenant queues. Neither BuildKit (strict FIFO, `studies/ultraplan-daemon-events-study/sources/buildkit/solver/scheduler.go:31-52`) nor containerd has this.

## Key Differences

- **One scheduler vs fleet vs fragmented loops.** BuildKit has a single `loop()` goroutine (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/scheduler.go:61-97`); Dagster runs a supervised fleet (one thread per daemon, `python_modules/dagster/dagster/_daemon/controller.py:133`) with heartbeat duplicate detection; Temporal layers matching + history + rescheduler + generic `common/tasks` schedulers; containerd has five independent loops with no supervisor. Consequence: BuildKit reasoning is local but a serial bottleneck (`TestHugeGraph` still fine); Dagster/Temporal pay fleet complexity for isolation; containerd pays the most in unpredictability (budgets multiply).
- **Retry ownership: absent vs ad-hoc stacked vs budgeted stacked vs two-layer deliberate.** BuildKit: no step-retry object; only `flightcontrol` coalescing backoff (`1ms + rand(10ms)`, ×1.2, 15s cap, `studies/ultraplan-daemon-events-study/sources/buildkit/util/flightcontrol/flightcontrol.go:34-55`) and cancel-bypasses-memoization. Containerd: each layer owns constants (GC `retryDelay`, CRI 1s→5min doubling, registry 5×50ms, stop-container 3×quadratic, sandbox Wait 128ms→4s doubling, content 16→2048 random) with no shared helper. Dagster: five budgeted layers (op delay/backoff/jitter; run-group count; dequeue enqueue-event count; tick `failure_count`; resume `ENGINE_EVENT` count) coordinated only by `RetryMode.DEFERRED`. Temporal: exactly two layers by design — durable timer-owned (attempts+expiry in history) vs ephemeral `ThrottleRetry` (in-memory) — composed via `max(data-plane, throttle)` (`common/backoff/retry.go:41-102`). The divergence reflects product shape: builds are hermetic and caller-retried; container runtimes favor local simplicity; orchestrators need per-layer observability; workflow engines need crash-surviving timers.
- **Failure taxonomy: binary vs errdefs-as-taxonomy vs reachable/permanent vs published matrix.** BuildKit: canceled vs failed (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/errdefs/context.go:12-27`). Containerd: `NotFound`/`AlreadyExists`/`Unavailable` used as both classes and idempotency signals, plus HTTP 408/429/5xx in `retryRequest` (`studies/ultraplan-daemon-events-study/sources/containerd/core/remotes/docker/resolver.go:863`) but no `Retry-After` or conflict-retry. Dagster: user-code-unreachable = retry forever / pause location vs framework `DagsterError/CheckError` = permanent (`python_modules/dagster/dagster/_scheduler/scheduler.py:702`, `python_modules/dagster/dagster/_daemon/backfill.py:155`), plus `RunAlreadyExists` retryable in backfill but dedup-hit in scheduler. Temporal: `IsRetryableFailure` matrix (terminated/canceled never; only start-to-close/heartbeat timeouts; `NonRetryable` flags honored, `common/retrypolicy/retry_policy.go:27-64`) plus separate RPC taxonomy (`common/util.go:291-374`). Only Temporal distinguishes throttle (`ResourceExhausted` slows all layers coherently).
- **Duplicate-execution posture: prevent concurrently vs tolerate via guards.** BuildKit prevents concurrent duplicates (single-flight) but re-executes across time (RAM memo). Containerd/Dagster/Temporal expect duplicates: containerd via `IsNotFound`-means-done + digest resume; Dagster via tag keys + re-fetch; Temporal via `RequestId` + token generations + transient-start deferral. The crash-ack answers diverge accordingly (see Tradeoffs).
- **Capacity recovery: reset vs re-derive.** BuildKit semaphore and containerd transfer limiters reset to full on restart (in-flight work orphaned). Containerd restart labels (`StatusLabel`/`CountLabel`, `studies/ultraplan-daemon-events-study/sources/containerd/core/runtime/restart/restart.go:44`), Dagster DB re-query (`max - len(in_progress)` can go negative and yield empty batch), and Temporal persistence re-read + `Rescheduler` re-buffer all re-derive. Containerd CRI `backOff.queuePool` (plain map, `studies/ultraplan-daemon-events-study/sources/containerd/internal/cri/server/events/events.go:54`) and Dagster `_location_timeouts` (in-memory pause) are the two in-memory gaps that lose state on crash — one drops redeliveries (under-delivery), the other clears backoff (fail-open hammering).
- **Priority/fairness testability: none vs deterministic.** BuildKit: no priority field, nothing to test (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/scheduler.go:192-207`). Containerd: no priority/fairness; tests assert counts/delays (`studies/ultraplan-daemon-events-study/sources/containerd/plugins/gc/scheduler_test.go:30`). Dagster: `_priority_sort` pure + deterministic tests; `shuffled_round_robin_by_key` intentionally probabilistic. Temporal: `TestOrder`, forward-timing, fairness/rate-limit suites all deterministic. The difference is maturity + need: single-tenant builders do not need fairness; multi-tenant queues do.

## Tradeoffs

- **At-most-once + content cache (BuildKit) vs durable at-least-once (Temporal/Dagster).** Benefit of at-most-once: zero recovery cost, no retry storms, sticky errors avoid duplicate billing. Cost: transient blip fails the whole build; caller (client/CI) retries the whole solve; non-hermetic ops can duplicate with no safety. Best fit: hermetic builds. Failure mode: daemon crash mid-`Exec` orphans external work; rebuild re-executes. Alternative: Dagster tick redo + run reuse, Temporal timer `RetryActivity` with same `ScheduledEventId`/bumped `Attempt`.
- **Local ad-hoc budgets (containerd) vs shared retry helper.** Benefit: each loop ships independently, tuned to its latency (50ms transport vs 5min backoff). Cost: budgets multiply under outage (transport × status × host-fallback × content-resume); no jitter in most paths → thundering herd after mass 500s; no `maxElapsedTime` where loops are unbounded (`OpenWriter`, sandbox `Wait`). Best fit: early-stage or resource-constrained daemons. Alternative: Temporal `common/backoff` + per-client factories; Dagster `RetryPolicy.calculate_delay` (`python_modules/dagster/dagster/_core/definitions/policy.py:87`).
- **Stacked explicit budgets (Dagster) vs two-layer deliberate (Temporal).** Benefit of stacked: each layer counts its own observable (op attempts, run-group size, enqueue events, tick `failure_count`, resume events) without clock coupling. Cost: multiplicative execution (op 4× × run 4× = 16×); documented manual+auto race grants one extra retry (`python_modules/dagster/dagster/_core/execution/retries.py:101`); operator must check multiple knobs. Temporal's two-layer split is cleaner but still requires debugging both durable backoff and ephemeral throttle. Best fit: orchestrators with distinct user/infra failure domains.
- **Infinite-retry defaults vs fast failure.** Temporal defaults `MaximumAttempts=0` (infinite) with 1s→100x-max exponential (`common/retrypolicy/retry_policy.go:66-81`); Dagster treats unreachable as retry-forever; containerd `OpenWriter`/sandbox `Wait` loop until `ctx.Done`. Benefit: durability across transient outages. Cost: workflows held open for a year, transfers blocked for context lifetime, poison tasks cycling to DLQ. Mitigation seen: `MaximumInterval` + `expirationTime` clamps; DLQ/drop for terminal executables (`service/history/queues/executable.go:590-623`); tick `failure_count` caps for framework errors.
- **Semaphore-at-op vs scheduler-aware admission.** BuildKit ops block in `Acquire` holding a pipe goroutine; scheduler sees `hasActiveOutgoing` but cannot shed/reorder/report depth. Containerd transfer semaphores prevent OOM but one large pull starves others. Dagster/Temporal compose semaphores with quotas, weights, and rate limiters — more config surface, but post-crash catch-up surge is bounded (`service/history/queues/scheduler_quotas.go:10-87`, `service/matching/configs/quotas.go:10-96`).
- **Jitter everywhere vs documented absence.** Temporal `addJitter = 0.8x + Intn(0.2x)` and `FullJitter`/`Jitter` helpers (`common/backoff/retrypolicy.go:141-185`, `common/backoff/jitter.go:6-22`); Dagster op `Jitter{FULL, PLUS_MINUS}` (`python_modules/dagster/dagster/_core/definitions/policy.py:35`) and daemon `random.uniform(0,jitter)` (`python_modules/dagster/dagster/_daemon/daemon.py:249`) — but infra `backoff()` explicitly has no jitter (`python_modules/dagster/dagster/_utils/backoff.py:11`); containerd randomizes only `OpenWriter` and losetup; registry/CRI/GC use fixed/doubling. Cost of absence: synchronized retry waves after shared dependency (registry 500) recovers.
- **Crash-after-work-before-ack across sources.** BuildKit: retry expected only as rebuild; unsafe (no idempotency key; `Save` after `Exec`, `studies/ultraplan-daemon-events-study/sources/buildkit/solver/edge.go:997-1015`). Containerd: retry expected and mostly safe via digest resume + `IsNotFound` guards — except restart `startChange.apply` can double-start/double-count with no fencing. Dagster: retry expected; safe for scheduler/sensor (tag-key reuse) and dequeue (re-fetch), safe for ops only if user code idempotent; one unsafe window (crash between `launch_run` success and executor `STARTED` flip) can double-launch (`python_modules/dagster/dagster_tests/scheduler_tests/test_scheduler_failure_recovery.py:189`). Temporal: retry expected; server contains damage via `RequestId`/token checks, but external side effect safe only if activity idempotent or heartbeat-gated (`service/history/workflow/mutable_state_impl.go:2107-2132`); workflow-start path is safest (same `RequestId` returns existing `RunId`).

## Decision Guide

- Choose **in-memory DAG reconcile + content dedup (BuildKit shape)** when steps are hermetic, caller retries whole units, and daemon lifetime bounds correctness. Skip when any step has external side effects — then you need a commit key or a durable anchor.
- Choose **fragmented local loops (containerd shape)** when shipping a runtime with independent subsystems and no shared store for retry state. Graduate to a shared backoff/jitter helper + attempt caps as soon as two loops contend on one dependency (registry, store).
- Choose **tick + queue with tag-key idempotency (Dagster shape)** when scheduling cron/sensor-driven runs onto a queued executor with per-tenant quotas. Budget per layer (op/run/tick/dequeue/resume), keep `RetryMode.DEFERRED`-style coordination so inner engines do not double-retry, and persist circuit-breaker state if flapping upstreams matter.
- Choose **durable timer-owned retries + ephemeral RPC retries (Temporal shape)** when steps must survive worker/daemon crashes with bounded attempts+time budgets. Enforce one `RetryPolicy` object, a published `IsRetryable`-style matrix, jittered exponential backoff, `RequestId` dedup, and attempt-generation tokens. Accept the two-stack операtional cost and infinite-default discipline (`MaximumInterval` + expiry always set).
- For capacity: process-local semaphores suffice for single-node bounding; add tag/pool quotas + priority + weighted fair sharing + rate limits when multi-tenant or bursty. Persist desired-state (labels, DB rows, history) so capacity re-derives after crash; never persist only in a map that resets.
- For failure classes: at minimum separate unreachable/infra (pause + retry, do not consume budget) from permanent/framework-invariant (fail fast) from throttle (slow all layers coherently). Map transport (timeout/EOF), status (408/429/5xx), and conflict (`AlreadyExists` = dedup-hit vs retryable) explicitly — the sources disagree most here, and silent misclassification is the top retry-storm/poison-pill cause.

## Practical Tips

- Patterns to copy: single-owner reconcile loop; `desiredState` escalation with lazy dep fetching; `LoadOrStore` + single-flight dedup with `execCallCount==1`-style tests; create-then-submit anchor rows; re-fetch-before-mutate on every transition; `RequestId`/run-key idempotency keys queryable via existing indexes; token/generation binding on completions; scheduled-vs-started event split; crash-injection at each ack boundary; stable-sort priority (FIFO within band) + shuffled round-robin fan-out; `max(data-plane, throttle)` backoff composition; per-key backoff queues to avoid head-of-line blocking across tenants.
- Patterns to delay: weighted fair sharing + per-key rate limits (copy only with noisy neighbors); DLQ/drop plumbing (add when poison tasks observed); 12h orphan grace / catchup windows (tune after measuring code-location flaps); global retry-ceiling dashboards (add when stacked budgets demonstrably multiply).
- Decision rules: if step re-execution is possible, require idempotent handler or heartbeat-gated progress before adding retries; if retry spans crashes, budget must live in durable state (DB/history/labels), not a map; if two layers can retry the same fault, define which layer defers (`DEFERRED`) and cap the product; if backoff lacks jitter and fans into one dependency, add `FullJitter` before the next incident.
- Caution signs: `waiters` broadcast on single failure (retry wave); unbounded `until ctx.Done` loops with no attempt cap; counter-init failure failing open (capacity silently disabled); serial per-key dedup queries without a perf note; `NOT_STARTED`→`STARTED` flip outside the launch transaction (double-launch window); `mergeTo` refused across dep boundaries causing silent duplicate execution; clock-comparison trigger drops (`lastCollection.After(e.ts)`).

## Anti-Patterns / Caution Signs

- **Sticky non-classified errors.** BuildKit memoizes transient fetch failures identically to deterministic errors (`studies/ultraplan-daemon-events-study/sources/buildkit/solver/jobs.go:1261-1274`) — whole-build retry required. Sign: no `transient/permanent/throttle/conflict` predicate anywhere.
- **In-memory redelivery queue with no persistence.** Containerd CRI `backOff.queuePool` (`studies/ultraplan-daemon-events-study/sources/containerd/internal/cri/server/events/events.go:54`) drops crash-time events; `RecoverContainer` (`studies/ultraplan-daemon-events-study/sources/containerd/internal/cri/server/podsandbox/recover.go:51`) heals only still-running tasks. Sign: `queuePool` is a plain map with no re-derivation scan.
- **Fail-open circuit breaker.** Dagster `_location_timeouts` clears on crash and hammers sick code servers; containerd-equivalent first-GC-failure falls back to `scheduleDelay` with no history. Sign: pause state in memory only.
- **Unbounded redelivery.** Containerd `OpenWriter`/`Wait` loop until ctx; Temporal infinite-attempt default; Dagster unreachable-retries-forever. Sign: no `MaximumAttempts`/`MaximumInterval`/`expirationTime` triple on a retry path.
- **No-jitter synchronized backoff.** Dagster infra `backoff()` self-documents no jitter; containerd CRI/GC/registry fixed-doubling. Sign: multiple daemons/containers retrying one store with identical delays.
- **Scheduled/started conflation.** Containerd restart emits closures that execute inline (`studies/ultraplan-daemon-events-study/sources/containerd/plugins/restart/monitor.go:131`); CRI enqueues the work item itself (`studies/ultraplan-daemon-events-study/sources/containerd/internal/cri/server/events/events.go:160`). Sign: no attempt counter or last-error on waiters; operators cannot tell queued from executing.
- **Duplicate daemon without fencing.** Dagster logs `daemon_id` mismatch (`python_modules/dagster/dagster/_daemon/daemon.py:176`) but does not fence; two schedulers can double-spend `max_concurrent_runs`. Sign: heartbeat detection without lease.
- **Single dispatch thread as silent bottleneck / FIFO without escape.** BuildKit `loop()` serializes all dispatch; containerd per-key FIFO head-blocks later events for a poisoned sandbox (`studies/ultraplan-daemon-events-study/sources/containerd/internal/cri/server/events/events.go:167`). Sign: no queue-depth/semaphore-utilization metric, no priority lane.

## Notable Absences

- No source has a **global cross-tenant retry budget or retry-storm shedder** beyond per-namespace/host rate limiters. Temporal per-source notes call this out explicitly (searched `common/quotas`, `scheduler_quotas.go`); containerd has no circuit breaker or global budget; Dagster suggests a future retry-ceiling dashboard.
- No source implements **exactly-once execution**; all rely on at-least-once + guards or at-most-once + rebuild. No dedup IDs with sequence numbers on containerd's event bus (`convertEvent` keys by name, `studies/ultraplan-daemon-events-study/sources/containerd/internal/cri/server/events/events.go:90`); no `Retry-After`/token-bucket throttle handling in containerd; no throttle-specific classification in Dagster (only reachable/unreachable/permanent/transient/conflict).
- **Priority/fairness absent in two sources.** BuildKit: no priority field on `edge`/`edgeRequest`/`dispatcher` (searched `solver/*.go`). Containerd: no priority queues, weighted sharing, or deterministic order tests (searched `core/transfer/`, `plugins/restart/`, `plugins/gc/`, `core/remotes/docker/`). Dagster fairness (`shuffled_round_robin_by_key`) has no deterministic bound tests by design.
- **Durability gaps even in mature sources.** BuildKit: no journal/checkpoint, no capacity recovery protocol (`Solver`/`scheduler`/`edgeIndex` not serializable). Containerd: whole-`Transfer` retry/resume semantics unclear (per-request + per-writer retries observed, per-transfer DAG retry not confirmed). Dagster: scheduler `max_tick_retries` numeric default lives outside sampled files; throttle classification missing. Temporal: `RequestIds` map TTL/GC story open; history-scheduler priority-inversion tests config-level only; production `BacklogNegligibleAge`/`MaxWaitForPollerBeforeFwd` deployment-supplied.

## Per-Source Notes

- **BuildKit (5/10).** In-memory DAG controller with the clearest reconcile core (`unpark` rules, `dispatch` self-check invariants at `studies/ultraplan-daemon-events-study/sources/buildkit/solver/scheduler.go:180-189`, two-phase slow-cache skips, late-joiner key backfill at `studies/ultraplan-daemon-events-study/sources/buildkit/solver/edge.go:638-647`, progress-coupled lifecycle) and strong dedup tests — but the dimension's core (retry budgets, taxonomy, backoff for step failures, durability, fairness) is absent. - **Containerd (6/10).** Five locally-clear loops with tests (GC timing tests, restart table tests, registry table tests, sandbox failpoint test) but decentralized constants, fixed/doubling delays without jitter (except content/losetup), and multiplicative budgets. ## Open Questions

- How should a global retry ceiling compose with per-layer budgets without reintroducing clock coupling — and what dashboard (attempt, next-backoff, throttle-vs-policy source) makes stacked retries debuggable? - Can the launch-vs-acknowledgement race be closed structurally — flip `NOT_STARTED→STARTED` in the launch transaction (Dagster future) or make `launch_run` idempotent on run ID — rather than worked around with `wait_for_all_runs_to_start`? Same question for containerd restart double-start fencing.
- Should in-memory backoff/circuit-breaker state (containerd CRI `queuePool`, Dagster `_location_timeouts`) be persisted or re-derived by store scan at startup (as containerd `RecoverContainer` already does for running tasks), and what is the bounded re-scan cost?
- What is the correct throttle taxonomy: is `Retry-After` + token-bucket + `ThrottleRetry max()` composition (Temporal) proportionate for smaller daemons, or does documented no-jitter fixed backoff suffice until a measured herd?
- For hermetic-build schedulers (BuildKit shape), is adding a `RetryPolicy` + transient/throttle/conflict/permanent taxonomy + idempotency/commit key worth the complexity, or is "caller retries whole solve + document non-idempotent ops as at-most-once" the right contract? What persists — committed `ExportableCacheKey` set — gives the cheapest crash win?
