# Dimension 01.08: Crash Recovery, Reconciliation, and Checkpoints

## Purpose

Study restart behavior when the long-lived executor dies: reconciliation, safe checkpoints, interrupted attempts, and operation-specific resume semantics.

## Steps

1. Trace startup reconciliation of non-terminal work.
2. Identify durable checkpoints and what state they contain.
3. Distinguish resumable logical operations from non-resumable in-memory/runtime calls.
4. Inspect takeover/new-attempt rules after crashes.
5. Check orphan process/resource cleanup and interrupted-state handling.

## Evidence to Capture

- Startup/reconciliation loops
- Checkpoint/snapshot schemas
- Interrupted/retry states
- Recovery planners/controllers
- Orphan cleanup code
- Crash/restart tests

## Questions

1. What survives a client crash, daemon crash, and host reboot?
2. Can arbitrary in-memory execution resume, or only checkpointed work?
3. When is a new attempt started automatically?
4. When is human/manual retry required?
5. How are orphaned resources discovered?
