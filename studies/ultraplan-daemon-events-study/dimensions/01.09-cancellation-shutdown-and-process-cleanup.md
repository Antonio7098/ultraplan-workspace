# Dimension 01.09: Cancellation, Shutdown, and Process Cleanup

## Purpose

Study cancellation as a durable control request plus bounded runtime cleanup, including graceful daemon shutdown and OS process-tree termination.

## Steps

1. Trace cancellation from client request to durable intent and runtime acknowledgement.
2. Inspect cancellation polling/propagation into active work.
3. Study daemon shutdown policy: detach, drain, interrupt, or cancel.
4. Inspect process-tree/group/cgroup termination and timeout escalation.
5. Check cleanup contexts and deadlines after parent cancellation.

## Evidence to Capture

- Cancellation state/events
- Context/token propagation
- Shutdown handlers
- Signal/process-group/cgroup code
- Kill escalation deadlines
- Cleanup/finalization tests

## Questions

1. Is client disconnect different from explicit cancellation?
2. Is cancellation durable if no worker is currently attached?
3. Can cleanup hang indefinitely?
4. Can child/grandchild processes escape termination?
5. How are cancellation and completion races arbitrated?
