# Dimension 01.02: Operation, Step, Attempt, and Process Identity

## Purpose

Study how systems distinguish durable user intent, checkpointable progress, retry attempts, and concrete runtime/process instances.

## Steps

1. Map the durable execution hierarchy and identifiers.
2. Identify parent/root relationships and nesting rules.
3. Trace which entity owns status, result, retry count, and terminal outcome.
4. Inspect correlation, causation, and external-process identifiers.
5. Check whether retries create new attempts without changing logical operation identity.

## Evidence to Capture

- Run/job/task/attempt models
- Database schemas
- Parent/root ID fields
- Process/task handles
- Correlation and causation metadata
- Retry-attempt creation code

## Questions

1. What is the durable user intention?
2. What is the smallest checkpointable unit?
3. Does each retry get a distinct identity?
4. Can one logical operation span multiple runtime calls or OS processes?
5. Can events be unambiguously attributed to the right entity?
