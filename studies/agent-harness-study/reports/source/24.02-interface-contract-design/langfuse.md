## Summary

Langfuse is a multi-runtime observability platform where the contract discipline is anchored in three layered models: a client-safe root package (`@langfuse/shared`) holding the domain types, filter operators, prompt/eval schemas, and a comprehensive event payload grammar (`packages/shared/src/server/queues.ts:21-291`); a server-only subtree (`@langfuse/shared/src/server`) owning the queue/payload contracts, ClickHouse record schemas, service classes, and storage/transport adapters (`packages/shared/src/server/index.ts:1-157`); and per-runtime adapters (`web/src/features/public-api`, `worker/src/queues`) that consume the shared contracts. The shared-package AGENTS.md makes the dependency direction explicit and ties it to the build (`packages/shared/AGENTS.md:14-19`): `web` and `worker` consume `@langfuse/shared/src/server`; `@langfuse/shared` itself never imports from `web`, `worker`, or `ee`. The Fern sources under `fern/apis/**` are the source of truth for public REST contracts (per `web/AGENTS.md:171-177`), and `generated/**` outputs are explicitly not hand-edited.

Queue payload schemas are the spine of the inter-runtime contract. `IngestionEvent`, `OtelIngestionEvent`, `BatchActionProcessingEventSchema`, `CreateEvalQueueEventSchema`, `WebhookInputSchema`, `WebhookOutboundEnvelopeSchema`, and `EntityChangeEventSchema` are zod discriminated unions over `type`/`deletionType`/`entityType`/`actionId` discriminators (`packages/shared/src/server/queues.ts:21-291`), with derived TypeScript types (`IngestionEventQueueType`, `BatchActionProcessingEventType`, `WebhookInput`) co-located. The discriminated-union style is the central design choice: every variant carries its own required fields, and unknown discriminators are rejected at parse time. `TQueueJobTypes` (`packages/shared/src/server/queues.ts:419-603`) is a `Record<QueueName, …>` keyed on the `QueueName` enum (`packages/shared/src/server/queues.ts:342-380`), which forces the producer and consumer to agree on payload shape per queue and lets BullMQ workers be typed at the boundary (e.g. `Job<TQueueJobTypes[QueueName.IngestionQueue]>` at `worker/src/queues/ingestionQueue.ts:38`). `RetryBaggage` (`packages/shared/src/server/queues.ts:335-340`) is the only carry-over state for retries and lives in shared because both producer (DLQ) and consumer (replay) need it. The companion worker seam `SHARDED_QUEUES` / `resolveQueueInstance` (`worker/src/queues/shardedQueueRegistry.ts:17-108`) lets queue producers and consumers address a sharded queue family by `baseQueueName` + `getShardNames()` + `getInstance(shardName)` so that adding a shard does not break caller code.

Domain object schemas use Zod and are paired with strict Prisma types: `LLMApiKeySchema.strict()` (rejects extra keys, `packages/shared/src/server/llm/types.ts:504-525`), `LLMAdapter` enum (`packages/shared/src/server/llm/types.ts:239-246`) plus `supportedModels` mapping (`packages/shared/src/server/llm/types.ts:489-496`) makes the LLM-provider contract a closed set; the seven `LLMConnectionConfigSchema` variants (`packages/shared/src/interfaces/customLLMProviderConfigSchemas.ts:11-58`) cover AWS / OpenAI / Vertex AI / GCP / Bedrock credentials with `z.union` and `.strict()` enforcement; `ToolCallResponseSchema` (`packages/shared/src/server/llm/types.ts:108-112`) is the cross-provider tool-call envelope; `ChatMessageSchema` is a `z.union` of typed message variants (`packages/shared/src/server/llm/types.ts:201-220`) with a fallback variant that records ingested messages as `PublicAPICreated` rather than rejecting them. ClickHouse record schemas `observationRecordReadSchema` / `observationRecordInsertSchema` / `eventRecordReadSchema` / `traceRecordReadSchema` / `scoreRecordReadSchema` (`packages/shared/src/server/repositories/definitions.ts:34-749`) are the wire format between ingestion writers and ClickHouse readers; converters (`convertTraceReadToInsert`, `convertPostgresTraceToInsert`, `convertPostgresScoreToInsert`) normalize between Postgres and ClickHouse representations at the seam.

Service classes follow a uniform pattern: input zod schemas in `<service>/types.ts`, a static-method service in `<service>/service.ts`, mapping helpers in `<service>/helpers.ts`, and a barrel index. `DashboardService` (`packages/shared/src/server/services/DashboardService/DashboardService.ts:20-477`), `TableViewService` (`packages/shared/src/server/services/TableViewService/TableViewService.ts:62-343`), `MonitorService` (`packages/shared/src/features/monitors/service/service.ts:45-199`), and `DefaultEvalModelService` / `DefaultViewService` each own a single `Service` class with explicit `create / update / getById / list / delete` methods and a `SessionContext` parameter that scopes writes (`packages/shared/src/features/monitors/service/service.ts:38-43` documents that RBAC is enforced by the caller and the service trusts `SessionContext.userId`). Validation is enforced by `.superRefine(validateMonitorQuery).superRefine(validateThresholdOrder).superRefine(validateAtLeastOneTrigger)` chains on the input DTO (`packages/shared/src/features/monitors/service/types.ts:45-52`), so that no business rule is split between the service and the API layer.

Storage and transport adapter contracts are explicit interfaces: `StorageService` (`packages/shared/src/server/services/StorageService.ts:222-255`) is the canonical nine-method interface implemented by `S3StorageService`, `AzureBlobStorageService`, `GoogleCloudStorageService`, `OCIObjectStorageService`; `StorageServiceFactory.getInstance(params)` (`packages/shared/src/server/services/StorageService.ts:275-327`) is the single resolution point that returns the right implementation by env flags, and `BufferStorageClient` shape is reused across all of them. `ChunkedUploadStrategy` (`packages/shared/src/server/services/BufferedStreamUploader.ts:29-43`) is a strategy interface with `initialize / uploadPart / complete / abort / uploadSingleObject`, used by `S3ChunkedUploadStrategy` and consumed by `BufferedStreamUploader`. `StorageClient` (`packages/shared/src/server/media-deletion.ts:42-44`) is the minimal `{ deleteFiles(paths[]) }` interface used in deletion paths; `S3SseConfig` (`packages/shared/src/server/services/StorageService.ts:43-46`) is the SSE configuration contract for S3-family services. For ChatML ingestion, `ProviderAdapter` (`packages/shared/src/utils/chatml/types.ts:25-34`) is the duck-typed `detect / preprocess / extractToolEvents?` interface that eight framework adapters implement (`packages/shared/src/utils/chatml/adapters/index.ts:11-22`) and `selectAdapter` is the resolution point. Mail transport exposes `createMailTransport(connectionUrl)` (`packages/shared/src/server/services/email/transport.ts:27-33`) which dispatches between SES and SMTP; SES-region parsing is exported as `__testing` for unit testing (`packages/shared/src/server/services/email/transport.ts:34`).

The error contract is centralized in `BaseError` (`packages/shared/src/errors/BaseError.ts:1-27`) with `httpCode`, `isOperational`, and `isUserError()`; the catalog (`packages/shared/src/errors/index.ts:1-13`) is small and named after HTTP semantics (`NotFoundError`, `InvalidRequestError`, `UnauthorizedError`, `ForbiddenError`, `MethodNotAllowedError`, `ConflictError`, `PayloadTooLargeError`, `NotImplementedError`, `InternalServerError`, `ServiceUnavailableError`). LLM execution has its own dedicated error class `LLMCompletionError` (`packages/shared/src/server/llm/errors.ts:31-63`) carrying `responseStatusCode`, `isRetryable`, `blockReason`; `inferLLMCompletionBlockReason` (`packages/shared/src/server/llm/errors.ts:12-29`) maps raw status + message to a Prisma enum (`EvaluatorBlockReason`). `SlackApiError` (`packages/shared/src/server/services/SlackService.ts:21-29`) preserves Slack error codes. The web layer builds a discriminated `UnstablePublicApiError` (subclass of `BaseError`) with stable `code` and optional `details` (`web/src/features/public-api/server/unstable-public-api-error-contract.ts:33-47`) so that the unstable evals API has a stable error code contract even though the surface is unstable.

Public REST API routes pass through `createAuthedProjectAPIRoute` (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:299-474`) — a higher-order function that wraps every handler with: API-key verification (`verifyApiKeyAuth` at `createAuthedProjectAPIRoute.ts:106-146`, `verifyAdminApiKeyAuth` at `164-251`), rate limiting via `RateLimitService` (`web/src/features/public-api/server/RateLimitService.ts:52-99`), zod parsing of query/body with the route-declared schemas, OpenTelemetry context propagation, and dev-mode response-schema validation (`createAuthedProjectAPIRoute.ts:448-454`). Every route declares `bodySchema` / `querySchema` / `responseSchema` so the contract is enforced at the boundary, not at the handler. The same module documents `rejectInEventsOnlyMode` (`createAuthedProjectAPIRoute.ts:77-83`) as a deployment-mode-aware contract opt-out.

Contract tests are present but uneven. `packages/shared/src/server/queues.test.ts:1-47` exercises `WebhookOutboundEnvelopeSchema` discriminated union parsing (accepts `monitor-alert`, rejects unknown `type`, rejects missing `payload`). `web/src/__tests__/server/unit/mail-transport.servertest.ts:1-71` exercises both `parseSesRegion` and `createMailTransport` across `smtp://`, `smtps://`, and `ses://` schemes, including the NextAuth deep-merge compatibility assertion. `packages/shared/src/features/monitors/isValidQuery.test.ts` and `isValidThresholdOrder.test.ts`, plus `packages/shared/src/features/monitors/service/service.test.ts` and `types.test.ts`, exercise the monitor validation surface. The full integration suite for public APIs lives in `web/src/__tests__/server/*.servertest.ts` (e.g. `traces-api.servertest.ts:1-2586` uses `makeZodVerifiedAPICall` to round-trip requests through the route factory and assert response shapes). However, **no conformance suite** exists for `StorageService` implementations, `ProviderAdapter` implementations, or queue payload variants — substitutability is tested only indirectly by full-stack integration tests.

## Rating

**8 / 10** — Clear model with tests, explicit interfaces, and operational safeguards. Earned by (a) the strict `@langfuse/shared` → `@langfuse/shared/src/server` → `{web, worker}` dependency direction with build-time enforcement (`packages/shared/AGENTS.md:14-19`); (b) Zod discriminated-union queue payload contracts with co-located TS types and BullMQ `Record<QueueName, …>` typing (`packages/shared/src/server/queues.ts:21-603`); (c) the higher-order `createAuthedProjectAPIRoute` route factory that enforces auth, rate limiting, schema validation, and OTel context at every public-API boundary (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:299-474`); (d) the explicit `StorageService` / `ChunkedUploadStrategy` / `StorageClient` / `ProviderAdapter` adapter interfaces with a single resolution point each (`StorageServiceFactory`, `selectAdapter`, `createMailTransport`); (e) the centralized `BaseError` hierarchy with operational flag and HTTP code, plus the typed `LLMCompletionError` and `UnstablePublicApiError` for cross-runtime error contracts; (f) Zod `.strict()` on `LLMApiKeySchema` (`packages/shared/src/server/llm/types.ts:504-525`) preventing accidental extra-field writes; and (g) the cross-feature reuse of `singleFilter` (`packages/shared/src/interfaces/filters.ts:120-132`) so dashboards, monitors, table views, traces, observations, and public APIs all share one filter algebra. Falls short of 9–10 because (i) there is no `StorageService` / `ProviderAdapter` / queue-payload conformance suite — substitutability is only verified via integration tests; (ii) `ChatMessageSchema`'s catch-all variant (`packages/shared/src/server/llm/types.ts:209-219`) silently coerces unknown message shapes to `PublicAPICreated` rather than rejecting them, weakening the chat-message contract for arbitrary SDK inputs; (iii) `createAuthedProjectAPIRoute` validates the response only in `NODE_ENV === "development"` (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:448-454`); (iv) several contract seams are typed as `any`/`unknown` (e.g. `dashboardWidget: Array<{ id: string; widgetId: string; ... }>.map((w: any) => ...)` at `packages/shared/src/server/services/DashboardService/DashboardService.ts:462`); and (v) some `ChatMessage` ingest transforms allow `content: z.any()` (`packages/shared/src/server/llm/types.ts:212`).

## Answers to Dimension Questions

**1. Are interfaces small, coherent, and owned by the consumer side?**

Yes for the shared, narrowly-scoped contracts; mixed for the service-class API surface.

Truly consumer-facing surfaces are small and owned by the consumer side:
- `ProviderAdapter` is four members (`id`, `detect`, `preprocess`, optional `extractToolEvents`) at `packages/shared/src/utils/chatml/types.ts:25-34`. The eight framework adapters implement it without inheritance (`packages/shared/src/utils/chatml/adapters/index.ts:11-22`), and `selectAdapter` is the single resolution point.
- `StorageService` is nine methods, but each maps to one operation (`uploadFile`, `download`, `listFiles`, `getSignedUrl`, `deleteFiles`, etc.); `StorageServiceFactory.getInstance` is the single place that decides S3 vs Azure vs GCS vs OCI (`packages/shared/src/server/services/StorageService.ts:275-327`).
- `ChunkedUploadStrategy` has five methods (`initialize / uploadPart / complete / abort / uploadSingleObject`); `S3ChunkedUploadStrategy` is the only implementation today, but the interface allows drop-in replacement (`packages/shared/src/server/services/BufferedStreamUploader.ts:29-43`).
- `StorageClient` is the minimal `{ deleteFiles(paths: string[]) }` used by media-deletion paths (`packages/shared/src/server/media-deletion.ts:42-44`).
- `Filter` is a four-field interface with one `apply()` method (`packages/shared/src/server/queries/clickhouse-sql/clickhouse-filter.ts:20-26`).
- `MonitorFiltersSchema = z.array(singleFilter)` is a thin alias to the shared filter algebra, so monitors, dashboards, table views, traces, observations, and public APIs all consume the same `singleFilter` discriminated union (`packages/shared/src/interfaces/filters.ts:120-132`).

Wider contracts are intentional but cluster all responsibilities into one object: `createAuthedProjectAPIRoute` runs auth + rate limit + schema parsing + OTel context in a single wrapper (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:299-474`); `LLMApiKey` schema carries `secretKey`, `baseURL`, `customModels`, `config` all in one row (`packages/shared/src/server/llm/types.ts:504-525`); `Monitor` carries query config, monitor config, alert config, monitor state, and scheduler state in one schema (`packages/shared/src/features/monitors/types.ts:244-291`).

Ownership direction is uniformly consumer-side: the shared package defines the contract; `web` and `worker` consume; `ee` consumes shared; providers (`S3StorageService`, `BedrockAccessKeys`, `langgraphAdapter`) implement. The build is gated by the `package.json#exports` map plus the AGENTS.md text.

**2. Do contracts specify behavior, not just method signatures?**

Mostly yes, with specific limits. The behavior contract is encoded through:

- **Discriminated unions force routing decisions to be explicit.** `WebhookOutboundEnvelopeSchema` discriminated over `type` makes the HTTP outbound shape stable (`packages/shared/src/server/queues.ts:261-264`); `BatchActionProcessingEventSchema` over `actionId` (`packages/shared/src/server/queues.ts:141-216`) requires each action to declare its own payload; `EvalTargetObject` with `BatchEvalSourceTable` mapping makes the source-table → target-object relationship a single function (`packages/shared/src/features/evals/types.ts:61-67`).
- **Validators encode semantic rules.** `validateQuery` (`packages/shared/src/features/query/validateQuery.ts:137-234`) enforces that high-cardinality dimensions must have both `row_limit` and `orderBy desc on measure`; `validateMonitorQuery / validateThresholdOrder / validateAtLeastOneTrigger` (`packages/shared/src/features/monitors/types.ts:186-242`) check monitor inputs at the schema boundary; `createFilterFromFilterState` rejects filter operators that don't match the column type via `COMPATIBLE_FILTER_TYPES` (`packages/shared/src/server/queries/clickhouse-sql/factory.ts:48-60`).
- **State-machine derivation.** `deriveEvaluatorDisplayState` / `isJobConfigBlocked` / `isJobConfigExecutableForExecutionMode` derive evaluator status from `(status, blockedAt, timeScope, hasPendingJobs, totalJobCount)` rather than letting callers compute it (`packages/shared/src/features/evals/evalConfigBlocking.ts:34-168`).
- **Canonicalization for stable fingerprints.** `canonicalizeFilter` sorts `stringOptions / categoryOptions / arrayOptions` value arrays so `["prod","staging"]` and `["staging","prod"]` produce the same `schedulerBatchId` (`packages/shared/src/features/monitors/service/helpers.ts:81-110`); `sortFiltersCanonically` is called on every write path in `MonitorService.create / update`.
- **Capability predicates** (`supportsStopWords`, `supportsMultimodal`, `getContextWindowSize` from `BaseLLM`, and `getValidAggregationsForMeasureType` from the query module) let callers branch without downcasting.
- **Doc-comments carry semantic guarantees.** The `BaseChatClient._validate_options` comment documents "Subclasses should call this at the start of _inner_get_response to validate options" (`packages/shared/src/server/llm/types.ts:326-340`); `safeBlobKeySegment` documents the invariants (`≤ maxBytes`, no forbidden chars, injective mapping) and that producers and consumers MUST resolve `maxBytes` from the same env (`packages/shared/src/server/services/safeBlobKeySegment.ts:46-66`); the `bucketPrefix` field in the queue payload documents "set so the consumer never reconstructs the path and therefore can't drift from the producer when env values differ across containers" (`packages/shared/src/server/queues.ts:28-33`).

Limits: `ChatMessageSchema`'s catch-all variant accepts `role: z.string()`, `content: z.union([string, array, any])` and retypes the message as `PublicAPICreated` (`packages/shared/src/server/llm/types.ts:209-219`). This is a deliberate pragmatic concession — without it, ingestion of arbitrary SDK message shapes would 4xx — but it weakens the chat-message contract because every "valid" message is also a valid "public-API-created" message. Several seams are typed as `any` / `unknown` (e.g. `dashboardWidget: Array<{...}>.map((w: any) => ...)` at `packages/shared/src/server/services/DashboardService/DashboardService.ts:462`).

**3. Can providers, tools, stores, and runtimes be replaced safely?**

Yes, with several caveats.

- **Storage is fully substitutable.** `StorageServiceFactory` returns one of `S3StorageService`, `AzureBlobStorageService`, `GoogleCloudStorageService`, `OCIObjectStorageService` (`packages/shared/src/server/services/StorageService.ts:275-327`); all implement the same nine methods. `BufferedStreamUploader` is independent of the strategy — only the `ChunkedUploadStrategy` interface matters, so swapping S3 for Azure requires only a new strategy implementation (`packages/shared/src/server/services/BufferedStreamUploader.ts:29-43`).
- **Mail transport is substitutable.** `createMailTransport(connectionUrl)` returns a Nodemailer `Transporter` and dispatches between `ses://<region>` (AWS SESv2) and `smtp://...`/`smtps://...` URLs (`packages/shared/src/server/services/email/transport.ts:27-33`); the unit test exercises both (`sources/langfuse/web/src/__tests__/server/unit/mail-transport.servertest.ts:1-71`).
- **ChatML providers are substitutable.** Eight framework adapters (LangGraph, AI SDK, OpenAI, Gemini, Microsoft Agent, Semantic Kernel, Pydantic AI, generic) share the `ProviderAdapter` interface; `selectAdapter` is the resolution point (`sources/langfuse/packages/shared/src/utils/chatml/adapters/index.ts:11-38`). Order is meaningful — LangGraph before OpenAI because both use langfuse-sdk scope.
- **LLM providers are substitutable.** `fetchLLMCompletion` routes every provider through `AIMessage#contentBlocks`, normalizing Bedrock `reasoning_content` and Gemini `{ thought: true }` text parts into a standard `{ type: "reasoning", reasoning: string }` block (`sources/langfuse/packages/shared/src/server/llm/fetchLLMCompletion.ts:106-118`); `ToolCallResponseSchema` is the canonical return shape (`packages/shared/src/server/llm/types.ts:108-112`).
- **Storage backends are substitutable through the protocol.** `StorageClient = { deleteFiles }` allows the media-deletion pipeline to take any object-store client (`packages/shared/src/server/media-deletion.ts:42-44`).
- **Queues are substitutable in shape.** `TQueueJobTypes` is the type-level map between `QueueName` and payload schema (`packages/shared/src/server/queues.ts:419-603`); sharded queues extend this through `SHARDED_QUEUES` (`sources/langfuse/worker/src/queues/shardedQueueRegistry.ts:17-108`). To add a new shard family you register a new `ShardedQueueDef`.

Caveats:
- **No `StorageService` conformance suite.** None of `S3StorageService`, `AzureBlobStorageService`, etc. are exercised by a uniform conformance test; substitutability is verified only indirectly through full-stack ingestion/exports integration tests.
- **No `ProviderAdapter` conformance suite.** Each adapter is smoke-tested by its own unit tests (`packages/shared/src/utils/chatml/adapters/*.ts`) but no harness asserts every adapter satisfies `ProviderAdapter`'s full contract under boundary inputs.
- **`createAuthedProjectAPIRoute` validates the response only in development.** `if (env.NODE_ENV === "development" && routeConfig.responseSchema)` (`sources/langfuse/web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:448-454`); production routes rely on the type system + handler tests but no runtime assertion.
- **`ChatMessageSchema` fallback variant** means an alternative implementation can submit arbitrary `z.string()` roles and still pass validation, reducing the contract's strictness.

**4. Are compatibility failures caught early by tests or validation?**

Yes, in layers; gaps exist for adapter surfaces.

- **Compile-time**: TypeScript narrows zod discriminated unions into exhaustive switches. `getQueue`'s default case asserts `_exhaustiveCheckDefault: never` (`packages/shared/src/server/redis/getQueue.ts:105-108`); `LLMApiKeySchema.strict()` rejects extra keys at parse time (`packages/shared/src/server/llm/types.ts:504-525`); `PublicApiCreateScoreSourceDomain` uses `satisfies readonly ScoreSourceType[]` to make the subset provable (`packages/shared/src/domain/scores.ts:18-21`); `LLMApiKey = z.infer<typeof LLMApiKeySchema> extends LlmApiKeys ? z.infer<typeof LLMApiKeySchema> : never` makes the schema compatible with Prisma at compile time (`packages/shared/src/server/llm/types.ts:527-530`).
- **Schema-time (zod parse at boundary)**: every public REST API route declares `bodySchema / querySchema / responseSchema`; the route factory parses both with the same zod schemas and translates errors to `UnstablePublicApiRequestValidationError` (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:388-430`); `filterToPrisma` and `orderByToPrisma` translate the same `singleFilter` to ClickHouse predicates, so filter grammar cannot drift (`packages/shared/src/server/filterToPrisma.ts`, `orderByToPrisma.ts`).
- **Schema-test files**: `packages/shared/src/server/queues.test.ts:1-47` exercises `WebhookOutboundEnvelopeSchema` (accepts monitor-alert, rejects unknown `type`, rejects missing payload); `web/src/__tests__/server/unit/mail-transport.servertest.ts:1-71` covers SES region parsing + transport dispatch + NextAuth deep-merge safety; `packages/shared/src/features/monitors/isValidQuery.test.ts`, `isValidThresholdOrder.test.ts`, `service/types.test.ts`, `service/service.test.ts`, `service/helpers.test.ts` cover monitor validation + service mapping; `packages/shared/src/features/monitors/processor/*.test.ts` cover state machine + severity computation.
- **Integration tests**: `web/src/__tests__/server/*.servertest.ts` (e.g. `traces-api.servertest.ts:1-2586`) run full HTTP round-trips through `createAuthedProjectAPIRoute` and assert against `makeZodVerifiedAPICall`; `worker/src/services/IngestionService/tests/*.test.ts` and `worker/src/services/ClickhouseWriter/ClickhouseWriter.unit.test.ts` test ingestion.
- **Runtime enforcement in handlers**: `createAuthedProjectAPIRoute`'s `rejectInEventsOnlyMode` returns 404 if the deployment is in `LANGFUSE_MIGRATION_V4_WRITE_MODE=events_only` for legacy-table reads (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:308-320`); `verifyAdminApiKeyAuth` requires `NEXT_PUBLIC_LANGFUSE_CLOUD_REGION` to be unset (self-hosted only) and uses `crypto.timingSafeEqual` for the dual-header check (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:178-215`).

Gaps:
- **No `StorageService` adapter conformance suite** — implementation differences would only show up in integration tests.
- **`PromptService` cache invalidation has no contract test** — the cached-prompt vs DB-prompt branches in `getPrompt` are not exercised by a unit test verifying semantic equivalence.
- **No `ProviderAdapter` parameterized harness** — adding a new framework adapter relies on per-adapter unit tests only.
- **No exhaustive test that every `MonitorViewSchema` measure/dimension in `dataModel.ts` resolves to a registered ClickHouse column** — schema-time validation stops at zod parsing, not at the SQL builder.

## Architectural Decisions

- **Three-tier public/private package layout.** `@langfuse/shared` (client-safe, exports zod schemas, domain, table definitions, prompt/eval helpers), `@langfuse/shared/src/server` (server-only, exports queue helpers, repositories, ClickHouse client, LLM completion, SlackService, StorageService, queues contracts, Redis helpers), and `@langfuse/shared/src/db` (Prisma client singleton, server-only). Per-feature sub-barrels (`@langfuse/shared/query`, `@langfuse/shared/encryption`, `@langfuse/shared/src/server/auth/apiKeys`, `@langfuse/shared/src/server/ee/ingestionMasking`) keep cross-package imports narrow (`packages/shared/AGENTS.md:31-46`).

- **Discriminated unions over generics.** Queue payloads (`IngestionEvent`, `BatchActionProcessingEventSchema`, `WebhookOutboundEnvelopeSchema`, `EntityChangeEventSchema`), filter conditions (`singleFilter`), action configs (`ActionConfigSchema`), score data (`NumericData / CategoricalData / BooleanData / TextData`), chat messages (`ChatMessageSchema`), and dashboard widget configs (`ChartConfigSchema`) all use `z.discriminatedUnion` rather than polymorphic base classes. This gives compile-time exhaustiveness (`_exhaustiveCheckDefault: never` in `getQueue.ts:106`) and runtime rejection of unknown discriminators.

- **Higher-order route factory.** `createAuthedProjectAPIRoute` is a generic `<TQuery, TBody, TResponse>(config: AuthedProjectAPIRouteConfig<TQuery, TBody, TResponse>) => handler` that bundles auth + rate limit + schema parsing + OTel context + dev-mode response validation (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:299-474`). The RouteConfig carries the route's zod schemas as type parameters so handler signatures stay typed.

- **Single resolution point for each adapter.** `StorageServiceFactory.getInstance` (`packages/shared/src/server/services/StorageService.ts:275-327`), `selectAdapter` (`packages/shared/src/utils/chatml/adapters/index.ts:23-38`), `createMailTransport` (`packages/shared/src/server/services/email/transport.ts:27-33`), `getQueue` (`packages/shared/src/server/redis/getQueue.ts:34-110`), and `resolveQueueInstance` (`worker/src/queues/shardedQueueRegistry.ts:87-108`) are the only places that pick an implementation. To add a backend you implement the interface and register it with the factory.

- **Service-class input/output DTO separation.** Every service module ships `service.ts` (the class), `types.ts` (zod DTOs), `helpers.ts` (mapping helpers, intentionally not re-exported), `service.test.ts` and `types.test.ts`. The DTOs are what tRPC and REST routes parse; the service trusts the inputs are pre-validated (`MonitorService.ts:38-43` documents this).

- **ClickHouse insert/read schema separation.** `observationRecordInsertSchema` uses `z.number()` for timestamps; `observationRecordReadSchema` uses `clickhouseStringDateSchema` (transform `... '2024-05-23 18:33:41.602000'` to ISO and parse). Converters (`convertTraceReadToInsert`, `convertPostgresTraceToInsert`, `convertPostgresScoreToInsert`, `convertPostgresObservationToInsert`, `convertTraceToStagingObservation`) are the explicit seams between stores and between timestore representations (`packages/shared/src/server/repositories/definitions.ts:332-632`).

- **Capability predicates instead of interface splitting.** `supports_stop_words / supports_multimodal / get_context_window_size` from `BaseLLM` (not present in this codebase as a single interface but in `packages/shared/src/server/llm/types.ts:489-496` for `supportedModels`), `getValidAggregationsForMeasureType` (`packages/shared/src/features/query/types.ts:127-138`), and the evaluator block reason metadata map (`packages/shared/src/features/evals/evalConfigBlocking.ts:59-93`) let callers branch without downcasting.

- **Producer-supplied path prefix on queue payloads.** `IngestionEvent.data.bucketPrefix` is set by the producer so the consumer never reconstructs the S3 path; `safeBlobKeySegment` is the producer-side helper and the consumer falls back to `rawEventBucketPrefix` for legacy jobs (`packages/shared/src/server/queues.ts:28-33`, `worker/src/queues/ingestionQueue.ts:65-81`).

- **No consumer-side runtime conformance tests for adapters.** Substitutability is validated by full-stack integration tests rather than per-adapter conformance harnesses; this trades test isolation for fewer artifacts but accepts that new adapter behavior might pass the integration suite while subtly diverging from the documented contract.

## Notable Patterns

- **`z.strict()` on DB-mapped schemas.** `LLMApiKeySchema.strict()` (`packages/shared/src/server/llm/types.ts:504-525`) and `OpenAIConfigSchema.strict()` (`packages/shared/src/interfaces/customLLMProviderConfigSchemas.ts:24-29`) reject extra fields, which prevents accidental additions from leaking through round-trips to Prisma.

- **Type-bounded `extends` to Prisma.** `LLMApiKey = z.infer<typeof LLMApiKeySchema> extends LlmApiKeys ? z.infer<typeof LLMApiKeySchema> : never` (`packages/shared/src/server/llm/types.ts:527-530`) makes the schema incompatible with the Prisma row type a compile error.

- **Discriminated action + target.** `BatchActionProcessingEventSchema` is a discriminated union over `actionId`, and each action carries its own `query / tableName / cutoffCreatedAt` plus its action-specific fields (`packages/shared/src/server/queues.ts:141-216`); `EvalTargetObjectSchema + BatchEvalSourceTableSchema + getEvalTargetObjectFromSourceTable` separates source from target cleanly (`packages/shared/src/features/evals/types.ts:28-67`).

- **Hook for testing internals.** `__testing = { parseSesRegion }` on the mail transport module exposes the URL parser for unit tests without re-implementing it (`sources/langfuse/packages/shared/src/server/services/email/transport.ts:34`); this is the same pattern used in `BaseError`'s `Error.captureStackTrace` and `BufferedStreamUploader.ErrorSink`.

- **Producer-supplied payload fields to avoid drift.** The `bucketPrefix` field on `IngestionEvent` is the canonical example: the producer computes the S3 path once, the consumer reads it back, and a fallback exists for legacy jobs (`packages/shared/src/server/queues.ts:28-33`).

- **Schema-time discrimination over string-typed branches.** `EventActionSchema = z.enum(["created", "updated", "deleted"])` (`packages/shared/src/domain/automations.ts:10`) replaces loose string literals; `LLMAdapter` (`packages/shared/src/server/llm/types.ts:239-246`) replaces magic strings.

- **Capability discovery as runtime predicates.** `getValidAggregationsForMeasureType` (`packages/shared/src/features/query/types.ts:127-138`) and `BufferStorageClient`'s strategy swap pattern (`packages/shared/src/server/services/BufferedStreamUploader.ts:29-43`) generalize cross-implementation behavior as predicates rather than subclasses.

- **Backward-compat conversion functions.** `convertTraceReadToInsert`, `convertPostgresTraceToInsert`, `convertPostgresScoreToInsert` are pure functions named so the data flow is obvious in callers (`packages/shared/src/server/repositories/definitions.ts:332-632`); each converter is a documented seam between stores.

- **Validation predicates reusable as pure functions.** `isValidQuery` / `isValidThresholdOrder` (`packages/shared/src/features/monitors/isValidQuery.ts`, `isValidThresholdOrder.ts`) are exported as pure predicates, then `validateMonitorQuery` / `validateThresholdOrder` adapt them to `ctx.addIssue` for `.superRefine` (`packages/shared/src/features/monitors/types.ts:186-242`). This lets the same predicate drive both zod validation and ad-hoc tests.

## Tradeoffs

- **Single root `@langfuse/shared` vs. finer-grained subpath exports.** Subpath exports (`@langfuse/shared/query`, `@langfuse/shared/encryption`) reduce bundle size for client code, but the AGENTS.md guidance is non-trivial to enforce without tooling — packages can still import the root barrel by accident.

- **Strict-mode schemas reject extra fields.** This is correct for DB round-trips (`LLMApiKeySchema.strict()`), but it means SDKs that add new fields must coordinate a schema bump or those fields are silently dropped at parse time.

- **Discriminated unions over polymorphic classes.** Discriminated unions give compile-time exhaustiveness, but the JSON parse path accepts an unknown discriminator and returns a validation error rather than falling through to a default branch — which means a producer that adds a new `type` will silently 400 the entire ingest path until both producer and consumer are upgraded.

- **Catch-all `PublicAPICreated` chat message variant.** Permits arbitrary SDK message shapes to be ingested, but it means the type system cannot distinguish "well-typed chat message" from "anything that looks roughly like a message" once the variant is in the system (`packages/shared/src/server/llm/types.ts:209-219`).

- **No conformance suite for `StorageService` / `ProviderAdapter` / queue payload variants.** Substitutability is verified indirectly via integration tests; new backends can drift from the documented contract without breaking any test.

- **Response-schema validation only in development.** `createAuthedProjectAPIRoute` parses the response against its `responseSchema` only when `NODE_ENV === "development"` (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:448-454`). Production relies on the TypeScript types; a runtime drift between handler output and declared schema is silent.

- **`allowInAppAgentKey` is opt-in but easy to mis-apply.** The flag allows non-mutating GET routes to be called by in-app agent keys without confirmation; misusing it on a mutating route would let agents write through their own key without an extra gate.

- **Admin API key auth is dual-header timing-safe compare.** The dual-header pattern is documented and intentional (redundancy for self-hosted deployments), but it is unusual enough that a future change to single-header auth could miss test coverage (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:164-251`).

- **Centralized error catalog is small but centralized.** `BaseError` subclasses map 1:1 to HTTP semantics; the `LLMCompletionError` adds evaluator-specific fields. Custom services that want to add an HTTP-400-class error must extend `BaseError` or import `InvalidRequestError`, which keeps the surface tight but can be limiting for service-specific error fields.

## Failure Modes / Edge Cases

- **Rolling deploys with queue payload schema additions.** `IngestionEvent.data.bucketPrefix` is documented as optional with a fallback to `rawEventBucketPrefix` for in-flight jobs (`packages/shared/src/server/queues.ts:28-33`); the consumer explicitly handles the missing-field case (`worker/src/queues/ingestionQueue.ts:65-81`). New fields should follow the same `.optional()` + fallback pattern; the AGENTS.md guide codifies this (`packages/shared/AGENTS.md:175-176`).

- **Sharded queue registration drift.** Adding a new sharded queue without registering it in `SHARDED_QUEUES` (`worker/src/queues/shardedQueueRegistry.ts:17-108`) means `resolveQueueInstance` falls through to `getQueue` for the non-sharded form, which throws on the sharded queue names (`packages/shared/src/server/redis/getQueue.ts:34-46`).

- **`ChatMessageSchema` catch-all masks upstream SDK changes.** If an SDK changes its message shape, the catch-all variant silently retypes it as `PublicAPICreated` rather than flagging a contract drift (`packages/shared/src/server/llm/types.ts:209-219`).

- **`createFilterFromFilterState` rejects operator/column mismatches.** `COMPATIBLE_FILTER_TYPES[colDef.type]` ensures that, e.g., a `number` operator is not used on a `string` column (`packages/shared/src/server/queries/clickhouse-sql/factory.ts:48-60`); the error message names both the column and the expected filter type.

- **`StorageServiceFactory` env-flag precedence.** Each storage backend has an explicit `params.useAzureBlob ?? env.LANGFUSE_USE_AZURE_BLOB` pattern (`packages/shared/src/server/services/StorageService.ts:291-325`), so call-time flags win over env flags. Misreading the precedence can result in the wrong backend being used for blob storage integrations.

- **`safeBlobKeySegment` over-budget inputs are injective but lose readability.** When sanitization fires the result is the original string with forbidden chars replaced and a sha256 prefix appended (`packages/shared/src/server/services/safeBlobKeySegment.ts:54-66`); pre-existing S3 keys remain readable after upgrade (no-op fast path), but oversized or forbidden-char inputs produce opaque hashes.

- **`MonitorService.update` does not check `nextRunAt` consistency.** The service recomputes `schedulerBatchId` and lets the worker re-claim; if two concurrent updates race, the loser overwrites the winner and the worker picks up the latest version on the next claim.

- **`Bucket prefix` mapping error in `BufferedStreamUploader` empty-stream fallback.** When `partNumber === 0`, the strategy aborts the chunked upload and falls back to `uploadSingleObject(Buffer.alloc(0))` (`packages/shared/src/server/services/BufferedStreamUploader.ts:127-135`); an alternative implementation must implement both `complete(parts)` and `uploadSingleObject(data)` to honor this fallback.

- **`JSON.stringify` size limit on large response bodies.** `createAuthedProjectAPIRoute` catches `RangeError("Invalid string length")` from `res.json` and translates it to `PayloadTooLargeError` (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:33-35`, `462-471`) — an alternative handler must do the same.

- **`UnstablePublicApiError` translation depends on class identity.** `toUnstablePublicApiError` switches on `error instanceof` for each `BaseError` subclass (`web/src/features/public-api/server/unstable-public-api-error-contract.ts:182-256`); adding a new `BaseError` subclass requires updating this map.

## Future Considerations

- **Add conformance suites for `StorageService`, `ProviderAdapter`, and queue payload variants.** A `verifyStorageService(s)` helper that probes each interface method with a known-good input would let alternative backends be validated at startup, mirroring the `.NET AgentConformance.IntegrationTests` pattern.

- **Promote response-schema validation in production.** The dev-only check in `createAuthedProjectAPIRoute` (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:448-454`) is the right shape for production but should be gated by a feature flag and sampled rather than entirely disabled.

- **Move the chat-message catch-all behind an explicit ingestion flag.** Today, any `role: z.string()` and `content: z.any()` is silently coerced to `PublicAPICreated`. A typed `unknownMessage: z.unknown()` variant that the ingestion pipeline routes through a normalizer would let the SDK opt into permissive ingestion without weakening the chat-message contract.

- **Formalize the `tool_type` and `templateVariable` registries.** `variableMapping` and the legacy prompt `isActive` field are wire formats that downstream systems depend on; a version field on each would prevent silent breakage.

- **Add a `verifyAdapter` runtime helper for `ProviderAdapter` implementations.** Since `ProviderAdapter` is duck-typed (`packages/shared/src/utils/chatml/types.ts:25-34`), a small probe-based conformance helper would catch missing-method implementations early.

- **Standardize `safeBlobKeySegment` guarantees across the producer and consumer.** Today the contract documents "Producers and consumers MUST resolve `maxBytes` from the same source" (`packages/shared/src/server/services/safeBlobKeySegment.ts:43-45`); a `safeBlobKeySegment` schema or a check at worker startup that the env matches the producer's would convert this into a runtime guarantee.

- **Split the public REST contract into a single source of truth.** `web/src/features/public-api/types/*.ts` defines the request/response zod schemas, `fern/apis/**` defines the API description, `web/src/pages/api/public/**` consumes both. Today the two are kept in sync by hand-editing `generated/**` (forbidden by AGENTS.md). A build step that diffs `fern/apis` against the handler-declared schemas would close the loop.

## Questions / Gaps

- **No `StorageService` conformance suite** — search found no parameterized test that runs every backend through the same upload/download round-trip; substitutability is exercised by per-backend integration tests only.
- **No `ProviderAdapter` conformance harness** — adapters are unit-tested individually; whether the eight registered adapters all conform to the documented `detect / preprocess / extractToolEvents` contract under boundary inputs is unverified by a unified test.
- **Whether `MonitorViewSchema` measures and dimensions resolve to registered ClickHouse columns** — there is no exhaustive test that every dimension in `dataModel.ts` has a backing column in the migration set; contract drift would only surface at query execution time.
- **`PromptService` cached-prompt vs DB-prompt semantic equivalence** — no test asserts that a cache hit returns the same object that a DB query would have returned (e.g. after a prompt edit), only that the cache path is hit (`packages/shared/src/server/services/PromptService/index.ts:47-79`).
- **`ChatMessageSchema`'s `PublicAPICreated` variant's downstream consumer assumptions** — the variant sets `role` and `content` to arbitrary strings; whether downstream rendering, score aggregation, and eval logic handle the variant identically to a typed message is unverified by a dedicated test.
- **Response-schema validation is dev-only** — production handlers can drift from their declared `responseSchema` silently (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:448-454`).
- **`actions.type` adding new action kinds** — `ActionTypeSchema` is a closed zod enum (`packages/shared/src/domain/automations.ts:43`); a new action kind requires coordinated updates to `ActionConfigSchema`, `ActionCreateSchema`, `SafeActionConfigSchema`, the type guards (`isWebhookActionConfig`, etc.), and every consumer (`webhooks.ts`, Slack route, automation router). No conformance test verifies the full chain.
- **`web/src/__tests__/server/`** integration tests use `makeZodVerifiedAPICall` for many endpoints but not all (`traces-api.servertest.ts` is the most exhaustive); whether every documented public-API endpoint has at least one round-trip test was not exhaustively verified within the scope of this study.
