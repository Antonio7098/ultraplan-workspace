## Summary

The repository is a single Python distribution (`openai-agents`) with one wheel target declared at `pyproject.toml:108`. The package surface under `src/agents/` is organised into one top-level package with named subpackages for every concern (runtime, model adapters, MCP, memory, realtime, voice, sandbox, tracing, handoffs, voice models, extensions), plus one explicitly-private subpackage called `run_internal/`. The dependency direction is largely bottom-up: leaf utility modules (`util/_json.py`, `util/_types.py`, `util/_approvals.py`, `util/_transforms.py`, `util/_custom_data.py`) sit at the bottom; core data types (`exceptions.py`, `items.py`, `tool.py`, `agent.py`, `handoffs/__init__.py`, `models/interface.py`) sit above them; `run.py` orchestrates the top-level `Runner` and wires `run_internal/*` helpers (`run.py:48-117`). The `run_internal` package is a deliberately underscored zone with a module-level comment marking its symbols as "internal and not part of the public SDK" (`run_internal/run_loop.py:1-3`, `run_internal/tool_execution.py:1-3`, `run_internal/session_persistence.py:1-3`), and it is excluded from the public MkDocs nav (it appears under `docs/ref/run_internal/` but is not listed in `mkdocs.yml` — verified by grepping `mkdocs.yml` for `run_internal`, zero hits). Module visibility is signalled three ways: (a) a curated `__all__` in most public modules (e.g. `agents/__init__.py:340-585`, `agents/tracing/__init__.py:45-91`, `agents/extensions/memory/__init__.py:29-37`), (b) `__getattr__` lazy-import shims for optional-dep modules (e.g. `agents/mcp/__init__.py:32-83`, `agents/extensions/memory/__init__.py:48-77`, `agents/extensions/sandbox/__init__.py:1-209`, `agents/__init__.py:260-267`), and (c) an `agents/_*.py` underscore-prefixed set of private helpers (`_config.py`, `_debug.py`, `_mcp_tool_metadata.py`, `_public_agent.py`, `_tool_identity.py`) that are never re-exported. Optional dependencies are explicit: the `[project.optional-dependencies]` block in `pyproject.toml:37-60` enumerates every extra (`voice`, `viz`, `litellm`, `any-llm`, `realtime`, `sqlalchemy`, `encrypt`, `redis`, `dapr`, `mongodb`, `docker`, `blaxel`, `daytona`, `cloudflare`, `e2b`, `modal`, `runloop`, `vercel`, `s3`, `temporal`), and each consumer module either guards the import with `try/except ImportError` (`sandbox/sandboxes/__init__.py:30-41`, `extensions/sandbox/__init__.py:1-111`) or raises an `ImportError` pointing at the right extra (`extensions/memory/_optional_imports.py:1-15`, `extensions/memory/__init__.py:69-77`, `voice/imports.py:1-9`, `extensions/models/litellm_model.py:21-28`, `extensions/sandbox/e2b/sandbox.py:331-344`). The same boundary is exercised by tests: `tests/extensions/memory/test_memory_imports.py:1-154` injects a `_BrokenImportFinder` meta-path hook to verify every optional backend raises `ImportError` mentioning the right extra, and `tests/sandbox/test_sandboxes_import.py:1-84` monkey-patches `sys.platform` to verify `agents.sandbox.sandboxes` skips the Unix backend on Windows. Modules are usable independently: the `Session` Protocol in `agents/memory/session.py:11-122` lets any external class satisfy the runtime contract, the `Model`/`ModelProvider` ABCs in `agents/models/interface.py:37-150` let third-party providers plug in without subclassing anything internal, and the `Model` is constructed through the `MultiProvider` router which lazily resolves alternate providers from `agents.extensions.models.*` (`agents/models/multi_provider.py:158-168`). There is no `requirements.txt`-style enforcement of "must import X to use Y" beyond the run-loop itself. Boundary caveats: the codebase still has a few minor leaks — `agents/realtime/agent.py:10` imports `from agents.prompts import Prompt` (absolute-path typo, should be `..prompts`), `extensions/sandbox/blaxel/mounts.py:453` and `extensions/sandbox/blaxel/mounts.py:511` reach back into `agents.extensions.sandbox.blaxel` from inside the same package (self-cycle), and `extensions/experimental/codex/codex_tool.py:24-49` uses absolute `from agents.X` imports even though relative `..X` would be just as easy and would let extensions be moved. None of these are load-bearing, but they show that the boundary is enforced by convention rather than by packaging.

**7 / 10** — Clear, durable, well-instrumented model: one top-level package, explicit `run_internal/` zone, curated `__all__` per public module, `__getattr__` lazy-import for optional deps, `py.typed` marker (`agents/py.typed`, `agents/sandbox/py.typed`), three different test suites that assert boundary behaviour (`tests/test_exception_exports.py`, `tests/extensions/memory/test_memory_imports.py`, `tests/sandbox/test_sandboxes_import.py`, `tests/conftest.py:81-93`), and `AGENTS.md:20-26` codifies the `run.py` vs `run_internal/` split as a contributor rule. Three things hold the score below 8: (a) the public API has no machine-checked boundary — every public module is reachable from anywhere inside the repo (e.g. `run_state.py:51-105` and `run.py:10-46` reach into `_tool_identity`, `agent_tool_state`, `agent_tool_input` which are underscore-prefixed but not enforced), and tests routinely reach into `run_internal` (e.g. `tests/sandbox/capabilities/test_apply_patch_tool.py:15-16`, `tests/memory/test_session_persistence_sanitize.py:8`, `tests/extensions/experiemental/codex/test_codex_tool.py:31-33`) so the boundary is social, not enforced; (b) there is no Dependabot/import-linter policy file (no `import-linter.toml`, no `pydeps` config, no `grimp` config in the repo root) and no tests for circular import detection; (c) a handful of small boundary violations exist (`agents/realtime/agent.py:10` wrong absolute import, self-cycles inside `extensions/sandbox/blaxel/mounts.py:453,511`, `extensions/sandbox/daytona/mounts.py:173`, `extensions/tool_output_trimmer.py:11`).

## Answers to Dimension Questions

1. **Are modules cleanly separated?**
   Yes, with caveats. The top-level package is split by concern into `tracing/`, `models/`, `mcp/`, `memory/`, `realtime/`, `voice/`, `sandbox/`, `extensions/`, `handoffs/`, `util/`, plus a private `run_internal/` zone. Each sub-package has its own `__init__.py` that curates `__all__`, and the runtime helpers are explicitly segregated into `run_internal/`. Optional-dep modules are isolated by `try/except` and `__getattr__` shims. Caveats: a handful of small boundary violations exist (see "Architectural Decisions").

2. **Do dependencies flow in one direction?**
   Mostly yes — leaf utilities → public types (`items`, `tool`, `agent`, `handoffs`, `models/interface`) → orchestration (`run.py` + `run_internal/*`) → public top-level. Specific direction checks:
   - `models/interface.py:10-13` imports `..agent_output`, `..handoffs`, `..items`, `..tool` (upward into public types), nothing in `models/` imports `run_internal` (grep returns 0 hits).
   - `realtime/` imports only from `agent`, `handoffs`, `tool`, `tool_guardrails`, `tracing`, `util` — never `run_internal` (grep `run_internal` in `realtime/` returns 0 hits).
   - `voice/` imports only from `agent`, `items`, `result`, `run`, `tracing` — never `run_internal` (grep returns 0 hits).
   - `extensions/memory/*` and `extensions/sandbox/*` depend on `agents.*` (downstream into the core) — never the reverse.
   - Caveat: `sandbox.runtime` and `sandbox.memory.rollouts` reach into `run_internal.agent_bindings` and `run_internal.items` (`sandbox/runtime.py:15-18`, `sandbox/memory/rollouts.py:14`), and `result.py` reaches into `run_internal.items`/`run_internal.run_steps` (`result.py:33-38`). These are one-way dependencies from a feature module into the runtime-private zone, which is the right direction but blurs the social convention.

3. **Can modules be used independently?**
   Yes, with one exception (`voice`). Each sub-package can be imported independently of the others for type-checking purposes (every sub-package `__init__.py` only re-exports symbols from its own files). Tests confirm this with `tests/conftest.py:81-93` (autouse fixture that prevents tests from accidentally hitting the OpenAI API by monkey-patching `OpenAIResponsesModel.get_response` and `OpenAIChatCompletionsModel.get_response` to `pytest.fail`). The `Session` Protocol (`memory/session.py:11-122`) is the documented extension point for third-party session backends, and the `Model`/`ModelProvider` ABCs (`models/interface.py:37-150`) are the documented extension points for third-party providers. Optional-dep backends (`extensions/sandbox/e2b`, `extensions/memory/redis`, `extensions/memory/sqlalchemy`, etc.) can each be installed in isolation and are guarded by `try/except`. Exception: importing `agents.voice` eagerly pulls in `voice/models/openai_stt.py` and `voice/models/openai_tts.py`, which in turn raise `ImportError` without the `[voice]` extra (`voice/imports.py:1-9`). So `voice` is not independently usable without the extra; this is a known intentional coupling enforced via `pyproject.toml:38`.

4. **Are public APIs distinguished from internal ones?**
   Yes, four distinct mechanisms:
   - **Curated `__all__`** at every public module (`agents/__init__.py:340-585`, `tracing/__init__.py:45-91`, `voice/__init__.py:27-53`, `realtime/__init__.py:98-193`, `memory/__init__.py:20-31`, `extensions/__init__.py:1-3`, `extensions/memory/__init__.py:29-37`, `extensions/sandbox/__init__.py:112-209`).
   - **Lazy `__getattr__`** for optional-dep and platform-conditional modules (`agents/__init__.py:260-267` for `SQLiteSession`, `agents/memory/__init__.py:34-40`, `agents/mcp/__init__.py:32-83`, `agents/extensions/memory/__init__.py:48-77`, `agents/extensions/sandbox/__init__.py:1-209`, `agents/extensions/experimental/__init__.py:1-6`).
   - **Underscore-prefixed modules** for top-level private helpers (`agents/_config.py`, `agents/_debug.py`, `agents/_mcp_tool_metadata.py`, `agents/_public_agent.py`, `agents/_tool_identity.py`) and per-module underscore-prefixed symbols (`tool.py:526,591,599,747,1200,1502,1511,1519,1575,1601`).
   - **A dedicated `run_internal/` sub-package** with module docstrings declaring its symbols as internal (`run_internal/__init__.py:1-7`, `run_internal/run_loop.py:1-3`, `run_internal/tool_execution.py:1-3`, `run_internal/session_persistence.py:1-3`), excluded from the public MkDocs nav (verified by grep on `mkdocs.yml`, 0 hits for `run_internal`), and codified in `AGENTS.md:20-21` as a contributor rule.
   - **Test enforcement**: `tests/test_exception_exports.py:1-30` asserts every `AgentsException` subclass is re-exported from the top level, and `tests/extensions/memory/test_memory_imports.py:1-154` injects a `MetaPathFinder` to verify each optional backend raises `ImportError` mentioning the right extra.

## Architectural Decisions

- **Single wheel, single top-level package.** The hatchling build target packages only `src/agents` (`pyproject.toml:108`); there is no monorepo, no `libs/*` split, no per-feature wheel. This means all boundaries are intra-package, enforced by import paths and `__all__` lists, not by packaging. Tradeoff: simpler CI and a single release, but no ability to install just `agents-memory` or `agents-voice` independently of the rest.
- **Public/private separation by sub-package name and underscore prefix.** `run_internal/` is the only sanctioned "private" sub-package, and it is the only one excluded from public docs (verified by grepping `mkdocs.yml` for `run_internal`, 0 hits). Helpers that need to be shared across `run_internal/*` and `realtime/*` (e.g. approval-evaluation logic in `util/_approvals.py`) are placed in `agents/util/_X.py` rather than inside `run_internal/`, with a comment explaining why (`util/_approvals.py:4-5`: "Keep this helper here so both run_internal and realtime can import it without creating cross-package dependencies."). This is a deliberate decision to prevent cross-private-package coupling.
- **Lazy import for optional dependencies.** Every optional dependency (voice, sandbox backends, memory backends, litellm, any-llm) is loaded through `try/except` plus either a module-level guard (`voice/imports.py:1-9`, `extensions/sandbox/e2b/sandbox.py:331-344`, `extensions/memory/__init__.py:48-77`) or an `__getattr__` shim (`agents/__init__.py:260-267`, `agents/mcp/__init__.py:32-83`, `agents/extensions/sandbox/__init__.py:1-209`). The `MultiProvider` router defers `litellm` / `any-llm` provider discovery to call time (`models/multi_provider.py:158-168`) so `import agents` does not pull in optional providers.

## Notable Patterns

- **Lazy `__getattr__` shim for optional imports.** Every optional sub-package uses the same shape: a `_LAZY_EXPORTS` dict mapping symbol name → `(module_name, optional_dependency)` tuple, and a `__getattr__` that imports on demand and produces a friendly `ImportError` mentioning the right extra. - **`try/except Exception` for completely-optional modules.** The `extensions/sandbox/__init__.py:1-111` block uses bare `try: from .e2b import ...` / `except Exception` for each provider; if the extra is not installed, that provider simply does not appear in `__all__`. - **Platform-conditional imports.** `agents/sandbox/sandboxes/__init__.py:13-28` checks `sys.platform != "win32"` at module-load time and only imports the Unix-local backend on POSIX. Tests assert this in `tests/sandbox/test_sandboxes_import.py:27-53` by monkey-patching `sys.platform` to `win32`.

- **Curated `__all__` discipline.** Every public `__init__.py` ships an explicit list. `agents/__init__.py:340-585` enumerates 240+ symbols; `agents/realtime/__init__.py:98-193` groups its `__all__` by section with comments ("Agent", "Handoffs", "Config", "Events", "Items", "Model", ...).

## Tradeoffs

- **No machine-checked boundary.** Everything below the top-level `agents/` is reachable from anywhere inside the repo. Tests routinely reach into `run_internal` (e.g. `tests/sandbox/capabilities/test_apply_patch_tool.py:15-16`, `tests/memory/test_session_persistence_sanitize.py:8`, `tests/extensions/experiemental/codex/test_codex_tool.py:31-33`), so the boundary is social, not enforced by an import-linter or a packaging split.
- **Single wheel couples everything.** Users who only want tracing or only want the tool abstractions still have to install the full SDK. There is no `agents-tracing` or `agents-tools` separate distribution.
- **Some helpers are dual-purpose.** `_tool_identity.py`, `_public_agent.py`, and the `util/_X.py` helpers are imported by both runtime code and test fixtures without an enforced rule.
- **Extensions sub-package uses absolute imports.** `extensions/experimental/codex/codex_tool.py:24-49` uses `from agents.X` instead of `from ..X`, which means moving the extensions package to a separate distribution would require rewriting every import.
- **Voice requires numpy/websockets to import.** `agents/voice/__init__.py:1-26` eagerly imports `from .models.openai_stt import OpenAISTTModel`, which triggers `voice/imports.py:1-9` to raise `ImportError` if `[voice]` is not installed. Users who only want `VoicePipelineConfig` or `VoiceWorkflowBase` cannot get them without the heavy extra.
- **`run_internal` is not lint-enforced.** Nothing prevents a contributor from `from agents.run_internal.run_loop import X` in a public module; the rule lives in `AGENTS.md:20-21` and in code review only.
- **No circular-import detector.** No `grimp`/`import-linter` config in the repo, no `pydeps` baseline, and no CI step that asserts the dependency direction documented above.

## Future Considerations

- **Add an import-linter or grimp policy.** The `run_internal/` zone is enforced by code review today; a small `import-linter.toml` forbidding `from .X import Y` into `run_internal` from non-`run_internal` modules (with allow-listed exceptions like `sandbox.runtime`) would make the boundary mechanical. - **Split the wheel per concern.** Optional extras (`voice`, `sandbox`, `extensions.*`) could be split into separate distributions (`agents-voice`, `agents-sandbox`, etc.) so users who only need one piece can install just that. Today everything is in one wheel (`pyproject.toml:108`).
