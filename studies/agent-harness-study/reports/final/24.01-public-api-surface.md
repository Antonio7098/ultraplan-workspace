## Executive Summary

Eleven sources were provided for this dimension: ten agent-harness and harness-adjacent codebases, plus one empty artifact (`sources/reports`, rated 1 below as an absence audit rather than a design verdict). Across the ten real codebases, scores cluster between 6 and 9 with a mean of 7.5 — the dimension is universally *attempted*, and almost universally *measurable*, but the leap from "explicit" to "durable" is where ratings diverge.

The first convergence is that every codebase publishes an enumerated inventory of its public API. Import-API repos curate `__all__` lists with grouped comments: agent-framework's ~275 entries grouped by import origin (`python/packages/core/agent_framework/__init__.py:342-618`), pydantic-ai's ~180 categorized exports (`pydantic_ai_slim/pydantic_ai/__init__.py:166-341`), openai-agents-sdk's 244-name flat root (`src/agents/__init__.py:340-585`), crewai's intentionally small 17-symbol root (`lib/crewai/src/crewai/__init__.py:187-205`), and langgraph's facet-submodule design with no root `__init__.py`. Wire-API repos maintain the same discipline at the route level — langfuse's `createAuthedProjectAPIRoute` factory centralizes auth, rate limits, and error mapping (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:37-92`), letta registers 33 routers with explicit `operation_id` on 207 of 252 routes (`letta/server/rest_api/routers/v1/__init__.py:34-68`), temporal registers `WorkflowService` and `OperatorService` on a single frontend listener (`service/frontend/service.go:479-483`), and opa's `v1/rego`/`v1/sdk`/`cmd` split maps cleanly onto the integration guide (`docs/docs/integration.md:23-36`).

The second finding is that the stable/internal boundary is well-articulated everywhere but only mechanically enforced in a handful. Go and .NET provide language-level enforcement: opa hides ~44 packages behind `internal/`, lets v0 packages share implementations with v1 through type aliases (`sdk/opa.go:13-18`, `rego/rego.go:193`), and produces machine-readable capability/builtin metadata via `go:generate` (`v1/ast/capabilities.go:39`); agent-framework's .NET side uses a dedicated `Microsoft.Agents.AI.Abstractions` package (`dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs:38`), narrowly scoped `InternalsVisibleTo` (`dotnet/src/Microsoft.Agents.AI/Microsoft.Agents.AI.csproj:50-54`), `[Experimental("MAAI001")]` compiler diagnostics, and binary-compat validation against a baseline version (`dotnet/nuget/nuget-package.props:19-24`). Python sources have to rely on curated `__all__` and underscore-prefixed modules — conventions that langgraph's `_internal` boundary (`libs/langgraph/langgraph/_internal/__init__.py:1-4`) and openai-agents-sdk's `run_internal/` zone (`src/agents/run_internal/__init__.py:1-5`) formalize with disclaimers, but that several other sources leak past (crewai's `crewai.agents.__all__` re-exports `CacheHandler`/`ToolsHandler`/`parse` internals, `lib/crewai/src/crewai/agents/__init__.py:3-19`; openhands has zero `@deprecated` decorators despite declaring the dependency, `pyproject.toml:33,256`).

The third finding is that stability claims are not worth much without a way to verify them. The two highest scores are earned by sources whose contracts are *executed* in CI: pydantic-ai's `tests/test_examples.py:86,141-297` discovers and runs every example in docs, docstrings, and the three packages with mocked models and ruff linting; openai-agents-sdk's `tests/test_source_compat_constructors.py:31-167` pins the positional constructor order of every public dataclass, and `tests/test_exception_exports.py:16-30` asserts every public exception appears in `__all__`; opa's 22 godoc `Example*` functions (`v1/rego/example_test.go:30-985`) include a complete program for the documented SDK path that depends on a *publicly importable* `v1/sdk/test` mock server. By contrast, openhands' Makefile and Docker `CMD` still launch the deprecated `openhands.server.listen` shim (`openhands/server/listen.py:1-4`) while `__main__.py:1-2` directs users to `openhands.app_server.app` — a launch-path split that no test verifies, and the kind of fragility that costs the source a full point.

The fourth finding is that wire-API repos invest in a different layer than import-API repos, and the bets are rational for each shape. Langfuse, letta, and temporal all do contract-first codegen (Fern YAML / committed OpenAPI / external proto module) and let the wire format *be* the public API, with SDKs generated downstream; agent-framework, pydantic-ai, crewai, langgraph, and openai-agents-sdk invest in curated exports and version policy because the import path *is* the API. opa and openhands straddle both worlds (Go libraries plus a CLI/server). The divergences are explained by these product shapes, not by carelessness: langfuse's `createAuthedProjectAPIRoute` exists because every new HTTP behavior must land in one place for quotas and rate limiting to work; pydantic-ai's example-tests exist because its users encounter the library through `Agent(...)` and `run(...)` calls.

## Core Thesis

A public API stays usable when its stability claims are backed by mechanisms rather than conventions. The cohort demonstrates a consistent maturity ladder: enumeration (everyone, including the empty artifact by virtue of nothing to enumerate), tiering and experimental quarantine (most), mechanical enforcement (few), and executable documentation (one — pydantic-ai). What separates a 9 from a 6 is whether the project has converted claims into tests: does the API-diff gate exist in CI (agent-framework .NET yes, Python side no; pydantic-ai only socially), are deprecation warning classes tested (langgraph yes, opa lint-enforced, openhands comment-only), are docs examples executed (pydantic-ai yes, langgraph archival, openhands absent), does the generated SDK round-trip against the server (letta yes, no CI diff of the spec). The single biggest insight across all sources is that the act of *publishing* a public surface is cheap; the act of *guaranteeing* it scales with how much of the contract the project runs in CI.

## Approach Models

Four approach models emerge across languages and product shapes.

**Model 1 — Curated-import-root library (Python libraries).** All Python library sources expose a top-level namespace with an explicit `__all__`, differing mainly in shape. The small-curated variant (`crewai`) ships 17 symbols (`lib/crewai/src/crewai/__init__.py:187-205`) and forces everything else into subpackages, optimizing for learnability at the cost of discoverability. The categorized-large variant (`pydantic-ai`, ~180 symbols with `# agent`/`# messages`/`# toolsets` section comments at `pydantic_ai_slim/pydantic_ai/__init__.py:166-341`) and `agent-framework` (~275 grouped by import origin at `python/packages/core/agent_framework/__init__.py:342-618`) keep a wide surface navigable through documented groupings. The flat-large variant (`openai-agents-sdk`, 244 names at `src/agents/__init__.py:340-585`) trades grouping for one-line importability. The facet-submodule variant (`langgraph`, no root `__init__.py`) avoids a god-module entirely and forces callers to learn the facet map, accepting that discoverability depends on external docs. What unifies all four is that the curated list *is* the contract — every project invests in keeping it accurate (`agent-framework` most aggressively with PACKAGE_STATUS.md:14-46 lifecycle buckets and ADR-0005 naming rules).

**Model 2 — Contract-first wire API → generated SDKs (servers with multiple SDKs).** `langfuse`, `letta`, and `temporal` all do this, with the contract taking a different form per language. Langfuse treats Fern YAML as the single source of truth (`CONTRIBUTING.md:504-513` mandates that contract changes update `fern/apis/**` and regenerated outputs), exported to OpenAPI specs and SDK generators, with a one-line `createAuthedProjectAPIRoute` factory funneling auth, rate limiting, validation, and error mapping through one chokepoint (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:37-92`). Letta checks `fern/openapi.json` into the repo and regenerates SDKs from it, with FastAPI's `deprecated=True` markers flowing into the spec and then into SDK type stubs (`letta/server/rest_api/routers/v1/agents.py:819`, `:875`; `letta/server/rest_api/routers/v1/telemetry.py:12-19`); the server itself dogfoods the generated SDK as a runtime dependency (`pyproject.toml:46`), so every API change is forced through the contract. Temporal separates wire API from server implementation entirely, pinning `go.temporal.io/api v1.62.15-...` by pseudo-version (`go.mod:67`) and projecting gRPC onto HTTP via an in-process `ClientConn` (`service/frontend/http_api_server.go:146-175`), with per-RPC dynamic-config gates keeping unfinished RPCs dark (`service/frontend/service.go:167-243`). The payoff is guaranteed doc/spec parity; the cost is dual maintenance (letta explicitly notes that regeneration writes to CWD and nothing diffs it against the committed spec — a gap the report flags as the top operational concern).

**Model 3 — Structural language-enforced boundary (Go and .NET).** `opa` and `agent-framework` (on the .NET side) leverage what their type systems give them. OPA hides ~44 packages behind `internal/` and a nested `v1/**/internal/` set that Go's compiler rule makes invisible to external importers (`internal/`, `v1/ast/internal/scanner`); it converts deprecated v0 packages into type aliases over the `v1/` implementation (`sdk/opa.go:13-18` declares `type OPA = v1.OPA`) so both import paths share one code path; and `go:generate` produces `capabilities.json`/`builtin_metadata.json` and an embedded `v1/ast/version_index.json` (`v1/ast/capabilities.go:39`) so the wire-level feature surface becomes data. Agent-framework's .NET side uses a dedicated `Microsoft.Agents.AI.Abstractions` package that depends only on `Microsoft.Extensions.AI.Abstractions` (`dotnet/src/Microsoft.Agents.AI.Abstractions/Microsoft.Agents.AI.Abstractions.csproj:27-29`), narrowly scoped `InternalsVisibleTo` to test assemblies (`dotnet/src/Microsoft.Agents.AI/Microsoft.Agents.AI.csproj:50-54`), `[Experimental("MAAI001")]` compiler diagnostics that reuse upstream IDs (`dotnet/src/Shared/DiagnosticIds/DiagnosticsIds.cs:18-31`), and `PackageValidationBaselineVersion=1.0.0` for released packages (`dotnet/nuget/nuget-package.props:19-24`). Temporal partially inherits this — separate proto module, separate test-server package with an explicit Go-API backwards-compatibility promise (`temporaltest/README.md:5-8`) — but the bulk of the server is one `go.mod`, so most of its boundary discipline is conventional. The model offers zero-maintenance enforcement where available; its limit is that nothing the language doesn't enforce is enforced at all.

**Model 4 — Lifecycle/stability tiering as a first-class mechanism.** Every source above 6 does some form of this; what separates them is whether the tiers are *machine-readable* and *enforced*. `agent-framework` is the strongest: every Python package has an `alpha`/`beta`/`rc`/`released`/`deprecated` bucket in `python/PACKAGE_STATUS.md:14-46`; .NET builds read `IsReleased`/`IsReleaseCandidate` MSBuild properties (`dotnet/nuget/nuget-package.props:4-11`); experimental APIs carry `@experimental(feature_id=...)` decorators that emit `ExperimentalWarning(FutureWarning)` and inject docstring banners (`python/packages/core/agent_framework/_feature_stage.py:29-40, 79-84, 383-403`), plus once-per-feature-id deduplication (`:233-235`). `crewai` uses an explicit `crewai.experimental` module with a `CREWAI_EXPERIMENTAL=1` env gate that raises `ExperimentalFeatureDisabledError` at use time (`lib/crewai/src/crewai/experimental/skills/_flag.py:9-24`). `langfuse` quarantines new eval functionality under `/api/public/unstable` with its own machine-readable `{message, code, details}` error contract (`fern/apis/server/definition/unstable/errors.yml:2-26`). `temporal` uses dynamicconfig booleans per unfinished RPC plus named experiments like `ChasmSchedulerExperiment = "chasm-scheduler"` checked via `IsExperimentAllowed` (`service/frontend/experiments.go:5-6`). `pydantic-ai` writes a version policy into `docs/version-policy.md:3-17` and marks beta features by module. `openai-agents-sdk` does the minimum: a 0.Y.Z scheme where minor bumps signal breaking changes to non-beta public interfaces (`docs/release.md:1-13`) and prose-only labels elsewhere. `langgraph` uses LangChain's `@beta(...)` and `@deprecated(...)` decorators plus versioned warning classes whose behavior is pinned by tests (`libs/langgraph/tests/test_deprecation.py:28-379`). `openhands` does tiering only in code comments — `openhands/app_server/user_auth/user_auth.py:1-8` carries "Legacy V0 Code - Deprecated since version 1.0.0, scheduled for removal April 1, 2026" but no `@deprecated` decorator is applied to the active V1 extension point, and the declared `deprecation` dependency (`pyproject.toml:33,256`) goes unused. The pattern: where tiers are data, they survive refactors; where they are comments, they erode.

## Pattern Catalog

**1. Curated `__all__` as the single source of truth.** Problem: Python's import system lets any underscore module leak through `import *`. Sources: all Python library sources. The execution: agent-framework declares a ~275-entry `__all__` in `python/packages/core/agent_framework/__init__.py:342-618`; pydantic-ai's `pydantic_ai_slim/pydantic_ai/__init__.py:166-341` carries section comments; openai-agents-sdk enumerates 244 names at `src/agents/__init__.py:340-585`; langgraph curates every public module (`libs/langgraph/langgraph/types.py:52-85`, `libs/prebuilt/langgraph/prebuilt/__init__.py:14-23`). Why it works: the list becomes a reviewable contract and a target for tests. Copy when: any Python library. Risk: the list itself is hand-maintained — agent-framework notes no test asserts `__all__` matches module contents; pydantic-ai's `agent.__all__` and top-level `__all__` drift; langgraph's checkpoint package has no `__all__` at all. Evidence-backed uniqueness: every Python source has the list; none has a test that asserts it.

**2. Consolidated `_internal` boundary with disclaimer.** Problem: convention-only privacy is weak. Sources: langgraph (`libs/langgraph/langgraph/_internal/__init__.py:1-4`), openai-agents-sdk (`src/agents/run_internal/__init__.py:1-5`). Why it works: the docstring stating "not part of the public API" gives language-agnostic support, and a single package is easier to fence off in tooling than scattered `_*` files. Copy when: in any language that lacks `internal/`. Risk: docs generators may still publish the package (openai-agents-sdk's `docs/ref/run_internal/` is built into the published site, only excluded from nav). Overkill when: the language provides a stricter mechanism (Go `internal/`).

**3. Versioned deprecation taxonomy with test pinning.** Problem: free-form deprecation warnings are forgotten. Sources: langgraph's `LangGraphDeprecatedSinceV10`-style warning classes carry `(since, expected_removal)` tuples (`libs/langgraph/langgraph/warnings.py:25-48`) and 15+ tests assert exact categories/messages (`libs/langgraph/tests/test_deprecation.py:28-379`); pydantic-ai's `PydanticAIDeprecationWarning(UserWarning)` deliberately inherits `UserWarning` so warnings are visible by default (`pydantic_ai_slim/pydantic_ai/_warnings.py:9-15`), with 52 `@deprecated` decorations across models/providers/toolsets. Why it works: removing a warning becomes a red test. Copy when: any long-lived library. Risk: classes proliferate — langgraph's `warnings.py:51-69` lists since/expected_removal pairs from v0.5→v2.0 to v1.1→v3.0.

**4. Migration ladders via forwarding shims and stable-path aliases.** Problem: renaming a symbol or moving it between packages breaks consumers. Sources: pydantic-ai's module `__getattr__` remaps `BuiltinToolCallPart`→`NativeToolCallPart` etc. (`pydantic_ai_slim/pydantic_ai/__init__.py:345-370`); opa's `type OPA = v1.OPA` / `type Rego = v1.Rego` aliases (`sdk/opa.go:13-18`, `rego/rego.go:193`) so values flow between old and new APIs without conversion; langgraph's deprecated constants and runners still re-export from `langgraph.constants` with `LangGraphDeprecatedSinceV10` (`libs/langgraph/langgraph/constants.py:34-62`); crewai keeps `crewai.plus_api` as a stable import path while new code targets `crewai_core.plus_api` (`lib/crewai/src/crewai/plus_api.py:1-11`); agent-framework's lazy provider namespaces (`python/packages/core/agent_framework/openai/__init__.py:17-47`) make optional-package usage import-safe. Why it works: the migration story becomes a code path, not a doc note. Risk: shims must eventually die — langgraph's `utils/runnable.py:1-2` claims removal "in v1" yet persists at v1.2.6; pydantic-ai's `_a2a.py` shim is slated for v2 removal (`pyproject.toml:362`).

**5. Contract-first spec → generated SDKs pipeline.** Problem: SDK and server drift. Sources: langfuse (Fern YAML → OpenAPI → generated SDKs, with PR-time `fern check` enforcement and mandated workflow in `AGENTS.md`), letta (checked-in `fern/openapi.json` consumed by Fern generators with `x-fern-ignore` overrides to hide MCP endpoints from SDKs without removing them from the wire — `fern/openapi-overrides.yml:11-45`), temporal (external `go.temporal.io/api` module pinned by pseudo-version so wire evolves independently of server). Why it works: there is exactly one wire contract and changes flow through it. Risk: regeneration must be automated — letta's `letta/server/generate_openapi_schema.sh:11-12` writes to CWD and no CI diffs it against the committed spec. Copy when: HTTP/RPC is the product.

**6. Single route harness as stability chokepoint.** Problem: cross-cutting behavior (auth, rate limits, error mapping) needs to apply uniformly. Sources: langfuse's `createAuthedProjectAPIRoute` factory (`web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:37-92`) plus `withMiddlewares` (`web/src/features/public-api/server/withMiddlewares.ts:159-196`) handle auth, rate limits, zod validation, dev-mode response checking, and migration-mode 404s in one place. Why it works: new behavior ships once. Risk: adoption is opt-in — langfuse's own audit shows 21 of 73 public routes bypass the harness, including `prompts.ts:31-77` which duplicates the auth/ratelimit/error logic line-for-line. Copy when: building a REST API with cross-cutting requirements.

**7. Machine-readable stability/capability metadata.** Problem: tiering and capability contracts must survive refactors. Sources: opa (`go:generate` emits `capabilities.json`/`builtin_metadata.json`/`v1/ast/version_index.json`, the last `//go:embed`-ed at `v1/ast/capabilities.go:39`); agent-framework (`python/PACKAGE_STATUS.md:14-46` lifecycle table plus `IsReleased`/`IsReleaseCandidate` build flags plus `CompatibilitySuppressions.xml:4-11` for tracked removals); langfuse (`PublicApiErrorCode` enum in `fern/apis/server/definition/unstable/errors.yml:2-26` so clients branch on `code`); temporal (dynamicconfig keys per unfinished RPC plus named experiments). Why it works: tooling can reason about the contract instead of parsing prose. Copy when: any multi-tier or long-lived API.

**8. Examples as executable truth.** Problem: docs rot. Sources: pydantic-ai's `tests/test_examples.py:86,141-297` discovers every code block in docs, docstrings, and three packages, executing each against a mocked `infer_model` with ruff linting; openai-agents-sdk's `tests/test_example_workflows.py:33-42` imports example modules and drives them with `FakeModel`; opa's 22 godoc `Example*` functions including a complete SDK program that depends on a *publicly importable* `v1/sdk/test` mock server (`v1/sdk/test/test.go:27`); letta's `tests/sdk/conftest.py:64-256` factory generates CRUD contract tests per resource. Why it works: docs and behavior cannot drift. Risk: `examples/` directories become archival (langgraph's `examples/README.md:3-5` says "retained purely for archival purposes and is no longer updated"); letta's `examples/` contains only data files.

**9. Compatibility enforced by regression tests.** Problem: documented contracts without tests erode. Sources: openai-agents-sdk's positional-constructor regression suite (`tests/test_source_compat_constructors.py:31-167`) pins the parameter order of `RunConfig`, `ModelSettings`, `FunctionTool`, `RunResult(Streaming)`, `ToolContext`, `AgentHookContext`, and even legacy keyword aliases like `_run_impl_task`→`run_loop_task` (`:343-414`); exception-export test (`tests/test_exception_exports.py:16-30`) asserts every public exception subclass appears in `agents.__all__`; agent-framework's .NET `PackageValidationBaselineVersion=1.0.0` with `CompatibilitySuppressions.xml:4-11` records removed members against baseline assemblies; langgraph's deprecation tests pin exact warning messages. Why it works: refactors that would silently break the surface fail CI. Copy when: dataclasses, models, or generated clients are part of the API.

**10. Experimental tier with runtime gating.** Problem: unstable features bleed into stable perception. Sources: agent-framework's `@experimental(feature_id=...)` decorators that emit `ExperimentalWarning(FutureWarning)` with user-frame attribution (`python/packages/core/agent_framework/_feature_stage.py:29-40, 79-84, 192-250`) and .NET `[Experimental("MAAI001")]` diagnostics (`dotnet/src/Microsoft.Agents.AI.Harness/HarnessAgent.cs:83`); crewai's `CREWAI_EXPERIMENTAL=1` env gate raising `ExperimentalFeatureDisabledError` (`lib/crewai/src/crewai/experimental/skills/_flag.py:9-24`); langfuse's `/api/public/unstable` URL namespace with dedicated `createUnstablePublicEvalsRoute` wrapper (`web/src/features/public-api/server/unstable-public-evals-route.ts:29-46`); temporal's dynamicconfig gates plus `AllowedExperiments` config (`service/frontend/service.go:252-260, 416-417`). Why it works: opt-in for users, observable for maintainers. Copy when: any feature ships before its contract is final.

**11. Helpful failure for missing optional dependencies.** Problem: lazy imports can confuse users. Sources: agent-framework's lazy provider namespaces catch `ModuleNotFoundError` and re-raise with `"The package X is required to use Y. Install it with: pip install X"` (`python/packages/core/agent_framework/openai/__init__.py:34-40`); pydantic-ai's CLI extra raises a targeted `ImportError` naming the extra group (`pydantic_ai_slim/pydantic_ai/_cli/__init__.py:39-43`); openai-agents-sdk's lazy `SQLiteSession` (`src/agents/__init__.py:256-267`). Why it works: the failure message teaches the fix. Copy when: any package exposes optional integration groups.

**12. Dogfooding the generated SDK.** Problem: the team might bypass the contract. Sources: letta's server depends on `letta-client>=1.7.12` (`pyproject.toml:46`) and its own integration tests drive the server through `letta_client` rather than raw HTTP (`tests/integration_test_send_message_v2.py:15-25`, `tests/conftest.py:12`). Why it works: no path around the contract exists internally either, so breakage is caught first at home. Copy when: the wire API is the product.

**13. `operation_id` discipline stabilizing SDK method names.** Problem: refactors rename generated methods. Sources: letta's 207 of 252 route declarations carry an explicit `operation_id` (`letta/server/rest_api/routers/v1/agents.py:613, 670`), pinning SDK method names (`create_agent`, `attach_tool_to_agent`) regardless of source refactors. Copy when: any spec→SDK pipeline.

## Key Differences

**What converges despite different implementation choices:**

- *Explicit inventories.* Every codebase publishes an enumerated public surface — `__all__` lists in Python, route tables and operation IDs in servers, command registries in CLIs, manifest+exports maps in JavaScript. This convergence is forced by the problem: the act of separating "supported" from "internal" requires enumeration. Even the empty `reports` artifact cannot enumerate, which is why its rating is 1.
- *Deprecation-with-warning machinery.* All sources above 1 carry some form of it. The mechanism varies — `langgraph` ships versioned warning classes plus tests, `pydantic-ai` uses a `UserWarning` subclass with `@deprecated` decorations plus forwarding shims, `crewai` uses `DeprecationWarning` with version-targeted removal messages, `agent-framework` emits runtime warnings once per feature id, `letta` uses FastAPI `deprecated=True` flowing through OpenAPI into SDKs, `opa` uses uniform `Deprecated:` package banners plus staticcheck lint rules (`.golangci.yaml:94-102`). The convergence is on *intent*; the divergence is on enforcement.
- *Helpful-failure patterns for missing optional deps.* `agent-framework`, `pydantic-ai`, and `openai-agents-sdk` all convert `ModuleNotFoundError` into an actionable message naming the extra to install. The pattern recurs because it is the cheapest UX win in the space.
- *Stability tiering as a vocabulary.* Across the cohort, the same set of tiers appears in slightly different shapes: alpha/beta/rc/released/deprecated (agent-framework), `experimental`/`stable` (crewai), `stable`/`unstable` (langfuse), `stable`/`experimental` (temporal), `GA`/`beta`/`experimental` (openai-agents-sdk), `released`/RC/alpha (agent-framework .NET). Every project above 6 has the concept, even when the tier names differ.
- *Executable examples where investment exists.* `pydantic-ai`, `openai-agents-sdk`, `opa`, `letta`, and `langfuse` all exercise at least some examples or contracts in CI. The difference is breadth — `pydantic-ai` runs every example; `langgraph` archives its examples directory and points to external docs (`docs/llms.txt:3`); `openhands` keeps a 27-line module listing in `openhands/app_server/README.md:1-27` and no endpoint reference; `crewai` has no generated Python API reference (the `api-reference/` section documents only the enterprise HTTP API, `docs/edge/en/api-reference/kickoff.mdx:6`).

**Why sources diverge:**

- *Product shape.* Library repos (`pydantic-ai`, `agent-framework`, `langgraph`, `openai-agents-sdk`, `crewai`) invest in import-side curation because their users encounter the product through `import` and a function call. Server repos (`letta`, `langfuse`, `openhands`, `temporal`) invest in wire contracts because their users encounter the product through HTTP/gRPC, and SDKs handle the import side for them. Dual-purpose repos (`opa`, `agent-framework .NET`, `temporal`) carry both investments and accept the cost of maintaining two discipline paths. The shape drives where the score lands.
- *Language affordances.* Go and .NET supply enforcement (Go `internal/`, C# `internal` + `InternalsVisibleTo` + package validation). Python supplies nothing structural, so Python sources either buy structure with packaging and curated lists (pydantic-ai, langgraph, agent-framework) or manage chaos with lazy imports (crewai, letta). JS supplies `exports` maps, which is why langfuse's package boundaries are structurally enforced. These affordances explain why the Python-only sources (crewai 7, openai-agents-sdk 7, openhands 6) cluster lower than mixed-stack or Go sources (agent-framework 8, opa 8, langfuse 8, temporal 7).
- *Maturity and migration state.* `openhands` sits mid-V1 re-architecture — its agent core has been extracted into pinned external SDKs (`pyproject.toml:60-62`) and the repo is the control plane, but the documented launch path still imports the deprecated shim (`Makefile:262`, Docker `CMD`). `letta` carries legacy entanglement (`letta/client/streaming.py:19` is a dead in-tree client module). `agent-framework` designed its topology under an accepted ADR evaluating the alternatives (`docs/decisions/0005-python-naming-conventions.md:13,18` records renames "while preserving discoverability and mapping to the .NET names"). Greenfield governance produces the cohort's best result (pydantic-ai 9).
- *Team philosophy on enforcement.* pydantic-ai socializes enforcement through a written policy and CI-run examples; openai-agents-sdk operationalizes it through positional regression tests; langgraph enforces partially (per-lib CI) and tests the rest (deprecation warnings); opa enforces via `golangci-lint` rules and machine-readable capability metadata; langfuse enforces via mandated workflow plus a single route harness. The scores track this axis more tightly than any technical variable.

## Tradeoffs

**Curated root vs. facet submodules vs. flat wide root.** `crewai` (17 symbols) optimizes for learnability at the cost of discoverability — every additional concept pushes into a subpackage with its own `__init__.py`. `openai-agents-sdk` (244 symbols) optimizes for one-import ergonomics at the cost of having to learn the organization from docs nav (`mkdocs.yml:93-191`) instead of from the surface itself. `pydantic-ai` (~180 symbols with section comments) splits the difference: a wide root remains navigable through commented groupings. `langgraph` (no root `__init__.py`) makes the discipline explicit — every import names a facet — accepting that IDE auto-complete on `import langgraph` yields nothing. Choice should follow how many domains ship in the library: one or two → small curated root (crewai); one coherent domain → flat wide root (openai-agents-sdk); several cohesive domains → categorized large root (pydantic-ai); subdomains with stable boundaries → facet submodules (langgraph).

**Contract-first codegen vs. in-tree curation.** Langfuse's contract-first pipeline guarantees doc/spec parity because the spec *is* the public API and SDKs are derived from it; the cost is dual maintenance and the risk that 21 of 73 routes bypass the harness (`prompts.ts:31-77`). Letta commits the same bet but does not enforce it — `letta/server/generate_openapi_schema.sh:11-12` regenerates against CWD and nothing diffs the result. Temporal sidesteps the dual-maintenance cost by externalizing the wire module entirely (`go.temporal.io/api`), letting wire and server evolve independently. Pydantic-ai and langgraph avoid codegen entirely — the import surface is curated by hand and tested with positional-constructor and export-completeness tests. The right answer depends on whether SDK ergonomics are a first-class deliverable.

**Runtime-visible deprecations vs. user quietness.** Pydantic-ai deliberately subclasses `UserWarning` rather than `DeprecationWarning` so deprecations are visible by default (`pydantic_ai_slim/pydantic_ai/_warnings.py:9-15`); agent-framework dedupes once per feature id so repeated usage doesn't spam (`python/packages/core/agent_framework/_feature_stage.py:233-235`). Crewai takes the opposite bet, globally monkey-patching `warnings.warn` at import time to suppress Pydantic deprecations (`lib/crewai/src/crewai/__init__.py:28-49`) — a tradeoff that improves user quietness at the cost of hiding their own deprecations from them.

**Convention privacy vs. structural enforcement.** Python underscore-prefixed modules are zero-cost but don't stop determined imports — `crewai` leaks `CacheHandler`/`ToolsHandler`/`parse` through `crewai.agents.__all__` (`lib/crewai/src/crewai/agents/__init__.py:3-19`), `agent-framework` underscore modules define no `__all__` so star-imports leak everything, and `crewai`'s root `__init__` writes into `sys.modules[...]` of eight modules (`lib/crewai/src/crewai/__init__.py:128-145`). Go `internal/` is free from Go and stops external importers cold (opa hides ~44 packages). C# `internal` + `InternalsVisibleTo` is structural and narrowly scoped (agent-framework .NET, `dotnet/src/Microsoft.Agents.AI/Microsoft.Agents.AI.csproj:50-54`). When the language provides the mechanism, use it; otherwise invest in tests.

**Global configuration convenience vs. test isolation.** `openai-agents-sdk` exposes `set_default_openai_key/client/api/responses_transport/harness/agent_registration` (`src/agents/__init__.py:270-330`) for script convenience, paid for in library-embedding awkwardness. OPA's `sdk.SetDefaultOptions` mutates package-global state consulted by every `sdk.New` call (`v1/sdk/options.go:23-33`), with a maintainer hedge ("consider this experimental... I have the hunch that we'll find a better way", `cmd/commands.go:19-23`). Temporal's `client.Factory` interface requires `testhooks.TestHooks` even in production builds (`client/clientfactory.go:23,45`), turning any test refactor into a breaking API change for embedders. The alternative is per-instance configuration, but the API surface grows.

**Documentation centralization off-repo vs. in-repo reproducibility.** Langgraph moved all guides to `docs.langchain.com` (`docs/llms.txt:3`) and froze `examples/` (`examples/README.md:3-5`); agent-framework's canonical reference lives on `learn.microsoft.com` (`README.md:96-100`, `dotnet/README.md:31-35`). The trade is that off-repo docs cannot be tested against the source in-repo — langgraph has no doctest runner — so doc drift is silent. Letta and openhands keep in-repo docs thin, pointing users to external sites. Only pydantic-ai runs the full documentation surface through CI.

**Lifecycle tiering as data vs. comments.** Agent-framework encodes tier in `IsReleased` MSBuild properties and `python/PACKAGE_STATUS.md:14-46`; opa encodes feature versions in `v1/ast/version_index.json`; langfuse encodes tier in `PublicApiErrorCode` enum; temporal encodes tier in dynamicconfig booleans. The alternatives are comment headers (openhands: zero `@deprecated` decorators despite declaring the `deprecation` dependency, `pyproject.toml:33,256`), which erode under review pressure. Data survives refactors.

**SDK surface curation distinct from wire surface.** Langfuse exposes `/api/public/mcp` over HTTP without surfacing it in SDKs (`fern/apis/server/definition/unstable/evaluators.yml:9`); letta hides MCP endpoints from SDKs via `x-fern-ignore: true` (`fern/openapi-overrides.yml:11-45`) while keeping them reachable over HTTP. The opposite choice — one surface, used by wire and SDK alike — is simpler but constrains the team to ship features through the SDK pipeline even when they only need wire exposure.

## Decision Guide

- **If your public API is an HTTP/gRPC service**, adopt contract-first codegen: a committed spec (Fern YAML or OpenAPI), generated SDKs, and a single route harness for cross-cutting concerns. Add a CI job that regenerates the spec from the running app and fails on diff — this is the missing gate in `letta` and the single highest-leverage addition any wire-API repo can make. Use `operation_id` discipline to stabilize SDK method names. Pin the wire types to an external module if your language allows (temporal's pattern) so wire and server can version independently.
- **If your public API is a Python library**, decide your root shape by domain breadth: small curated root for one-or-two concepts (crewai's 17-symbol `__all__`); categorized wide root when you have several cohesive domains (pydantic-ai's commented `__all__`); facet submodules when subdomains have stable boundaries (langgraph's no-root-`__init__`). In every case, pair the curation with: a test asserting the export list, machine-readable stability metadata (`__stability__` attribute or decorator-tagged tiers), runtime-visible deprecation warnings with version-targeted removal messages, and an `examples` directory executed in CI. Use a `UserWarning` subclass so deprecations are visible by default; dedupe once per feature id.
- **If you publish a CLI**, treat it as a separate package with its own `__init__.py` and lazy command dispatch (crewai's `crewai_cli` shims commands behind `__new__` factories at `lib/cli/src/crewai_cli/cli.py:63-105`). Mark deprecated subcommands explicitly (temporal's `cmd/server/main.go:130-162` keeps deprecated flags functional with warnings). Pair the CLI with a public "server" API for users who prefer programmatic access.
- **Add mechanical enforcement where the language provides it.** Go `internal/`, C# `internal` + narrowly scoped `InternalsVisibleTo`, .NET binary-compat validation baselines — use them. Where the language doesn't provide it, convert conventions into tests: export-completeness assertions, positional-constructor regression tests, spec-diff CI, export-snapshot fixtures.
- **Choose tiering as data, not as comments.** Lifecycle tables, MSBuild flags, dynamicconfig keys, error-code enums, `@deprecated` decorators — anything that survives a refactor. Free-form `# Deprecated:` banners and `Deprecated:` godoc lines without lint enforcement get ignored.
- **If your product is dual-language**, declare the parity contract in an ADR (agent-framework's ADR-0005 at `docs/decisions/0005-python-naming-conventions.md:13,18`) and add a cross-language parity manifest. The drift signals are real — agent-framework's Python `1.9.0` vs .NET `1.10.0` version prefixes are visible in the source manifests.
- **For experimental features**, quarantine by URL namespace (`/api/public/unstable`), dedicated error contract, opt-in env gate, or compiler diagnostic ID — never just a banner. Make the opt-in visible in OpenAPI/SDKs so users and tools can detect it.
- **Keep examples executable.** At minimum, run godoc/Examples in CI (opa's 22), tests/test_examples.py covering every doc block (pydantic-ai), or example modules imported by tests (openai-agents-sdk). Make the documented example depend only on publicly importable packages (opa's SDK example depends on `v1/sdk/test` — a deliberate choice at `docs/docs/integration.md:204`).

## Practical Tips

Patterns worth copying outright:

- Subclass `UserWarning` (not `DeprecationWarning`) for runtime-visible deprecations; dedupe once per feature id to keep logs clean (agent-framework's `_feature_stage.py:233-235`).
- Encode deprecation timelines as data: `since`/`expected_removal` fields on warning classes, removal-target versions on `DeprecationWarning` strings (langgraph's `warnings.py:25-48`; crewai's `"removed in CrewAI v1.0.0"`, `lib/crewai/src/crewai/task.py:561-566`).
- For dataclass-based public types, pin positional constructor order with regression tests — openai-agents-sdk's `tests/test_source_compat_constructors.py:31-167` is the template, including acceptance of legacy keyword aliases (`_run_impl_task`→`run_loop_task` at `:343-414`).
- For wire APIs, add a CI job that regenerates the OpenAPI/Fern spec and diffs against the committed version — the missing gate in `letta` and the highest-leverage operational improvement.
- For stable-path migration, use type aliases (opa's `type OPA = v1.OPA`) and module `__getattr__` forwarding shims (pydantic-ai's `__init__.py:345-370`; langgraph's deprecated constants at `libs/langgraph/langgraph/constants.py:34-62`). Document a removal date at declaration time; honor or update it on every release.
- Make lazy-optional-dep errors name the missing extra (agent-framework's "install it with: pip install X"; pydantic-ai's targeted `ImportError` in `pydantic_ai_slim/pydantic_ai/_cli/__init__.py:39-43`).
- Publish a mock-server test package so documented examples actually run (opa's `v1/sdk/test/test.go:27` is publicly importable for this reason).
- Add `operation_id` discipline to every route declaration (letta's 207 of 252) so SDK method names survive source refactors.
- Route migration pressure through runtime responses: langfuse's legacy endpoint returns 422 with the v2 replacement named (`web/src/features/public-api/server/withMiddlewares.ts:45-58`); rate-limited legacy listings advertise upgrade paths (`web/src/pages/api/public/traces/index.ts:74-77`).
- Centralize cross-cutting behavior in one route factory (langfuse's `createAuthedProjectAPIRoute`) so quotas, auth, and error mapping apply uniformly.
- For monorepos with optional features, expose provider namespaces via lazy facades that re-export symbols and raise helpful errors on missing extras (agent-framework's `python/packages/core/agent_framework/openai/__init__.py:17-47`).

Patterns to delay or avoid until needed:

- Meta-package aggregation with all extras: only when the optional groups actually justify a single install command (pydantic-ai's `pyproject.toml:49-51`; agent-framework's umbrella).
- Capability protocols with optional sub-features: only when more than one provider opts in (agent-framework's `SupportsMCPTool`/`SupportsShellTool` family); below that, ABC inheritance is fine.
- Multi-tier lifecycle machinery (`alpha`/`beta`/`rc`/`released`): only when the project releases packages at multiple maturity levels simultaneously (agent-framework's 30 Python packages). Single-package projects rarely need more than stable+experimental.
- Externalized wire types as a separate module: only when wire and server version independently. For a single-language service this is overkill.
- Custom DSL for doc-snippet markers (`@@@SNIPSTART`): only if your docs site extracts snippets from source. For small surfaces, copy-paste is fine.

Decision heuristics observed across sources:

- If a module's name says "internal" or "_internal" but the package's contributors reach for it from production code, the boundary isn't real (temporal's `chasm/` is imported by `service/frontend/service.go:12-14` and yet has no stability marker; openhands' `openhands/app_server/user_auth/user_auth.py:1-8` is labeled "Legacy V0" while still defining the active V1 extension point).
- If you can write `from X._y import *` and get a working symbol, your public surface is whatever the underscore says it isn't (no Python source in this cohort prevents it mechanically; only curation does).
- If your launch path still imports a module marked deprecated, your deprecation hasn't shipped (openhands' `Makefile:262` and Docker `CMD` target `openhands.server.listen:app`).
- If your examples directory says "no longer updated", your docs are losing to time (langgraph's `examples/README.md:3-5`; agent-framework's external `learn.microsoft.com`).
- If your CLI registers two packages for the same script name, one will be removed and the user will pick the wrong one (crewai's `lib/crewai/pyproject.toml:146-147` and `lib/cli/pyproject.toml:34-35` both register `crewai`).
- If your deprecation is in comments while a deprecation dependency is declared in `pyproject.toml`, the dependency is wasted (openhands).

## Anti-Patterns / Caution Signs

- **Deprecated path as the documented launch path.** `openhands` is the canonical example: `Makefile:262` and the Docker `CMD` run `openhands.server.listen:app`, while `openhands/server/__main__.py:1-2` directs users to `openhands.app_server.app:app`. The deprecated path is the one most operators will execute; the comment-marked removal is a fiction until the launch path follows.
- **Comment-only deprecation while a `deprecation` library is a declared dependency.** Same source: zero `@deprecated` decorations in `openhands/` despite `pyproject.toml:33,256` declaring the library. Tooling cannot detect deprecated surface; humans forget to remove it.
- **Stale removal promises.** Langgraph's `libs/langgraph/langgraph/utils/runnable.py:1-2` claims removal "in v1" but persists at package version 1.2.6 (`libs/langgraph/pyproject.toml:7`). When removal dates outrun releases, the versioned-deprecation system loses credibility.
- **Manual spec regeneration without CI verification.** Letta's `letta/server/generate_openapi_schema.sh:11-12` regenerates `openapi_letta.json` to CWD; nothing in `.github/workflows/` diffs it against `fern/openapi.json`. Routes can silently diverge from the published contract.
- **Internal re-exports in `__all__`.** Crewai's `crewai.agents.__all__` includes `CacheHandler`, `ToolsHandler`, `parse` (`lib/crewai/src/crewai/agents/__init__.py:3-19`); openai-agents-sdk's `src/agents/__init__.py:435` exports `SessionABC` whose own docstring directs third parties to the `Session` protocol instead (`src/agents/memory/session.py:57-65`); `AgentRunner` appears in `run.py`'s `__all__` (`src/agents/run.py:131`) while sibling functions are marked non-public (`:151-166`); letta's `_internal_*` routers are mounted publicly and schema-documented (`letta/server/rest_api/routers/v1/__init__.py:47-51`). Each example erodes the discipline.
- **Internal modules published in generated docs.** Openai-agents-sdk's `docs/scripts/generate_ref_files.py:52` only skips `_`-prefixed files, so `docs/ref/run_internal/agent_bindings.md:1-3` is built into the published site — internal modules become discoverable even when the nav excludes them.
- **Import-time global monkey-patching.** Crewai's root `__init__` globally rewrites `warnings.warn` to suppress Pydantic deprecations (`lib/crewai/src/crewai/__init__.py:28-49`) and writes into `sys.modules[...]` of eight modules (`:128-145`) — fragile coupling that a new integration can trip over.
- **Global mutable configuration that lives outside instance lifetime.** OPA's `sdk.SetDefaultOptions` (`v1/sdk/options.go:23-33`) is consulted by every `sdk.New` call; `cmd.UserAgent` (`cmd/commands.go:19-23`) is process-global with a maintainer hedge ("consider this experimental... I have the hunch that we'll find a better way"). Openai-agents-sdk's `set_default_openai_*` family (`src/agents/__init__.py:270-330`) follows the same shape.
- **Test infrastructure in production signatures.** Temporal's `client.Factory` interface requires a `testhooks.TestHooks` parameter even in non-test builds (`client/clientfactory.go:23,45`), which means test refactors become breaking API changes for embedders.
- **Harness/spec bypasses accumulating.** Langfuse's 21 of 73 public routes bypass `withMiddlewares`/`createAuthedProjectAPIRoute` (`web/src/pages/api/public/prompts.ts:31-77` duplicates the harness's auth/ratelimit/error logic line-for-line). The pattern is recognizable: each bypass starts as "this route is special" and ends as drift.
- **Misaligned export lists.** Pydantic-ai's `pydantic_ai_slim/pydantic_ai/agent/__init__.py:129-130` includes `PydanticAIDeprecationWarning` and `ToolsPrepareFunc` while the top-level `__all__` does not — `from pydantic_ai import ToolsPrepareFunc` fails while `from pydantic_ai.agent import ...` works. Langgraph's `libs/checkpoint/langgraph/checkpoint/base/__init__.py` lacks an `__all__` entirely. Agent-framework's underscore modules define no `__all__` so star-imports leak.
- **Accidental packaging surface.** Openhands ships `pyproject.toml`/`poetry.lock` inside the wheel (`pyproject.toml:149-153`); letta ships `letta/test_gemini.py:1` inside the installed package and keeps an empty `letta/client/__init__.py` plus dead `letta/client/streaming.py:19`. These are accidental surface that can rot silently.
- **Version skew/drift signals.** Agent-framework's Python `1.9.0` (`python/pyproject.toml:7`) vs .NET `1.10.0` (`dotnet/nuget/nuget-package.props:4`) version prefixes tell consumers operating both stacks that feature alignment at equal version numbers cannot be assumed. Letta's hardcoded `0.16.7` fallback in `letta/__init__.py:8` against `0.16.8` in `pyproject.toml:3` means version reporting is not single-sourced.
- **Spec/exec division that hides errors.** Langfuse's stable error contract mixes shapes — `{message, error:name}` for `BaseError`s but raw Zod issues arrays for validation failures (`web/src/features/public-api/server/withMiddlewares.ts:159-196`) — and the harness's Zod instance differs from consumers', acknowledged by a duck-typed `instanceof` check (`:179-180`). The unstable tier has a cleaner typed envelope (`web/src/features/public-api/server/unstable-public-api-error-contract.ts:27-31`); promoting it is on the roadmap.
- **Auth endpoints placed in the public tree without public auth.** Langfuse's Slack OAuth routes under `/api/public/slack/install/index.ts:16-30` use browser session cookies, not API keys. The directory boundary no longer means "API-key-authenticated surface".
- **No automated API-diff gate in CI.** No source has a mechanical Go or Python API compatibility check that fails the build. Agent-framework .NET has `EnablePackageValidation` (`dotnet/nuget/nuget-package.props:19-24`); the Python counterpart was searched for and not found. OPA searches for `apidiff`/`gorelease` returned nothing (`Makefile:161-165` runs `golangci-lint` only). This is the cohort's universal gap.
