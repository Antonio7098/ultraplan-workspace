## Executive Summary

No studied source can deploy a prompt change with automated confidence that it won't regress. The strongest substrates — `pydantic-ai` (7/10) and `langfuse` (6/10) — provide typed datasets, LLM-as-judge evaluators, and experiment comparison, but still require the consumer to build the dataset and wire the CI gate. `agent-framework` (5/10) ships a clean provider-agnostic `Evaluator` protocol with both local checks and hosted Foundry judges plus CI-ready assertions (`python/packages/core/agent_framework/_evaluation.py:470`), yet leaves dataset persistence, prompt versioning, and PR gating to manual wiring. `crewai` (4/10) and `openhands` (3/10) have functional LLM-as-judge code (six rubric judges in `lib/crewai/src/crewai/experimental/evaluation/metrics/goal_metrics.py:36` and a 27-label `APIBasedCritic` in `_sdk_inspect/sdk/critic/impl/api/client.py:74`) but both are experimental or runtime-only, with no shipped datasets and no CI enforcement. `langgraph` (2/10) and `openai-agents-sdk` (2/10) explicitly delegate evaluation to LangSmith or external tracing sinks (`docs/tracing.md:200`, `docs/redirects.json:121`), offering only plumbing tests (`tests/test_agent_prompt.py:52`, `libs/prebuilt/tests/test_react_agent.py:148`) and no in-repo harness.

The convergent lesson: treating prompts as free-form strings (`Agent.instructions`, `str | SystemMessage | Callable` in `libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:121`, `translations/en.json:8`, `system_prompt.j2:1`) maximizes flexibility but removes the auditable surface needed for regression testing. Teams that need confidence must add it themselves: versioned datasets with `expected_output`, structured-output judges, `EvaluationReport`/`EvalResults` diffing, and an explicit threshold gate in CI.

## Core Thesis

Prompt evaluation in agent harnesses is a **user-owned concern, not a framework-owned quality gate**. Sources diverge along a single axis: whether evaluation is offered as *infrastructure* (langfuse), as *library* (pydantic-ai, agent-framework), as *experimental opt-in* (crewai, openhands), or as *explicitly out-of-scope* (langgraph, openai-agents-sdk) — but all converge on the same failure mode: no PR can be blocked automatically on prompt quality without custom wiring.

The mature pattern, demonstrated most clearly by `pydantic-ai`, is **code-first, typed datasets + pluggable evaluators + report diff + OTel observability** (`pydantic_evals/pydantic_evals/dataset.py:177`, `pydantic_evals/pydantic_evals/evaluators/common.py:224`, `pydantic_evals/pydantic_evals/reporting/render_numbers.py:62`). `agent-framework` proves the complementary pattern: **provider-agnostic `Evaluator` protocol with progressive disclosure** (`python/packages/core/agent_framework/_evaluation.py:681`, `python/packages/core/agent_framework/_evaluation.py:1415`) — `keyword_check:1062` for 80% of cases, `@evaluator` for custom LLM judges, `FoundryEvals:728` for hosted judges. `langfuse` proves the platform pattern: **versioned datasets + `ExperimentCreate` queue + ClickHouse `dataset_run_items_rmt`** (`packages/shared/src/server/repositories/dataset-items.ts:211`, `packages/shared/src/server/queues.ts:131`, `worker/src/features/experiments/experimentServiceClickhouse.ts:42`) — powerful for users of the platform, but its own prompts (`web/src/features/in-app-agent/prompts/in-app-agent-system-prompt.txt:1`) have zero self-evaluation.

Sources that abdicate evaluation pay a hidden cost: `langgraph`'s `FakeToolCallingModel._generate` (`libs/prebuilt/tests/model.py:28`) and `openai-agents-sdk`'s `FakeModel.get_response` (`tests/fake_model.py:51`) make CI deterministic and fast, but blind it to semantic drift. `crewai`'s file-local JSON baseline (`lib/crewai/src/crewai/experimental/evaluation/experiment/result.py:32`) and `openhands`'s remote `/classify` critic (`_sdk_inspect/sdk/critic/impl/api/critic.py:47`) show what happens when the substrate exists but is not integrated into the prompt lifecycle: regressions are detectable in principle, invisible in practice.

## Approach Models

### Model A — Evaluation Platform (Langfuse)

Provides the infrastructure *for users* to evaluate prompts. Users create versioned `Dataset` items (`input`/`expectedOutput`/`metadata` with `validFrom`/`validTo` at `packages/shared/src/server/repositories/dataset-items.ts:211`), versioned prompts with labels (`web/src/features/prompts/server/routers/promptRouter.ts:297`), and `EvalTemplate` job configs (`web/src/features/evals/server/router.ts:941`). Experiments are queued (`QueueName.ExperimentCreate` at `packages/shared/src/server/queues.ts:359`) and executed via `createExperimentJobClickhouse` (`worker/src/features/experiments/experimentServiceClickhouse.ts:292`) persisting to Postgres + ClickHouse `dataset_run_items_rmt`. Judges run via `runLLMAsJudgeEvaluation` (`worker/src/features/evaluation/evalService.ts:736`) with `compileEvalPrompt` + `structuredOutputSchema` + `toNormalizedScores`. Tracking is durable and queryable (`getExperimentsFromEvents` at `packages/shared/src/server/repositories/experiments.ts:138`). Best fit: teams that want a hosted prompt/dataset/experiment store and already centralize observability. Cost: platform coupling; own prompts remain untested (`web/src/features/in-app-agent/prompts/in-app-agent-system-prompt.txt:1`).

### Model B — Pluggable Evaluation Library (Pydantic-AI, Agent-Framework)

Ships as code, not service. Consumer owns datasets and CI wiring.

- **pydantic-ai**: `Dataset[InputsT,OutputT,MetadataT]` (`pydantic_evals/pydantic_evals/dataset.py:177`) with YAML/JSON persistence (`pydantic_evals/pydantic_evals/dataset.py:747`), `Case`/`evaluators`/`report_evaluators`, `Dataset.evaluate` with `max_concurrency`/`repeat`/`retry_task` (`pydantic_evals/pydantic_evals/dataset.py:281`), and `EvaluationReport` with `build_diff_table` (`pydantic_evals/pydantic_evals/reporting/render_numbers.py:62`). Evaluators are `Equals`/`Contains`/`MaxDuration` plus `LLMJudge`/`GEval` (`pydantic_evals/pydantic_evals/evaluators/common.py:224`) wrapping four typed judge agents (`pydantic_evals/pydantic_evals/evaluators/llm_as_a_judge.py:46`) and span-aware `ToolCorrectness`/`TrajectoryMatch` (`pydantic_evals/pydantic_evals/evaluators/agentic.py:190`). Online path emits OTel `gen_ai.evaluation.result` (`pydantic_evals/pydantic_evals/online.py:194`). Judge invariants pinned by snapshots (`tests/evals/test_llm_as_a_judge.py:60`).

- **agent-framework**: Minimal `Evaluator` protocol (`python/packages/core/agent_framework/_evaluation.py:681`) with `LocalEvaluator` (`python/packages/core/agent_framework/_evaluation.py:1518`), built-in `keyword_check:1062`/`tool_call_args_match:1215`, `@evaluator` decorator with param-name injection (`python/packages/core/agent_framework/_evaluation.py:1415`), `evaluate_agent`/`evaluate_workflow` stamping `expected_output` (`python/packages/core/agent_framework/_evaluation.py:1809`), and `EvalResults` assertions (`python/packages/core/agent_framework/_evaluation.py:470`). Hosted judges delegated to `FoundryEvals` (`python/packages/foundry/agent_framework_foundry/_foundry_evals.py:728`). Experiments are ephemeral Foundry runs linked via `report_url` (`python/packages/foundry/agent_framework_foundry/_foundry_evals.py:415`), not a local store.

Best fit: library consumers who want types, version control, and no vendor lock-in. Cost: team must add persistence, prompt versioning, and CI gating.

### Model C — Experimental / Runtime-Only Judges (CrewAI, OpenHands)

Evaluation code exists but is not integrated into the prompt lifecycle.

- **crewai**: `experimental.evaluation` (`lib/crewai/src/crewai/experimental/evaluation/__init__.py:1`) with `AgentEvaluator` (`lib/crewai/src/crewai/experimental/evaluation/agent_evaluator.py:248`), `ExperimentRunner` over user-supplied `list[dict]` datasets (`lib/crewai/src/crewai/experimental/evaluation/experiment/runner.py:27`), six LLM judges (`lib/crewai/src/crewai/experimental/evaluation/metrics/goal_metrics.py:36`, `tools_metrics.py:66`, `reasoning_metrics.py:114`), and file-local `ExperimentResults.compare_with_baseline` (`lib/crewai/src/crewai/experimental/evaluation/experiment/result.py:48`) with `assert_experiment_no_regression` (`lib/crewai/src/crewai/experimental/evaluation/testing.py:13`). Legacy lane is `Crew.test()`/`CrewEvaluator` via an evaluator Agent (`lib/crewai/src/crewai/crew.py:2227`, `lib/crewai/src/crewai/utilities/evaluators/crew_evaluator_handler.py:58`). Prompts live in `translations/en.json:8` composed via `utilities/prompts.py:93` with no versioning.

- **openhands**: No prompt-eval harness. The `APIBasedCritic` (`_sdk_inspect/sdk/critic/impl/api/critic.py:47`) POSTs full conversation + `SystemPromptEvent` to `/classify` via `CriticClient` (`_sdk_inspect/sdk/critic/impl/api/client.py:74`), maps 27 label probs through `categorize_features` (`_sdk_inspect/sdk/critic/impl/api/taxonomy.py:82`), and optionally triggers iterative refinement (`_sdk_inspect/sdk/critic/base.py:20`). It judges *trajectory success*, not prompt A vs B. Prompts are Jinja2 (`_sdk_inspect/sdk/context/prompts/prompt.py:88`, `_sdk_inspect/sdk/agent/base.py:381`) with `FlexibleFileSystemLoader` and `lru_cache` (`_sdk_inspect/sdk/context/prompts/prompt.py:16`), but no golden tests.

Best fit: exploration or runtime quality gating where an extra classifier call is acceptable. Cost: judges are not reproducible without network/model pinning, and prompt changes remain unguarded.

### Model D — Delegated / Absent (LangGraph, OpenAI Agents SDK, partially OpenHands)

No in-repo evaluation. Prompt is an unversioned runtime adapter.

- **langgraph**: `Prompt` typed as `str | SystemMessage | Callable | Runnable` via `_get_prompt_runnable` (`libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:119`), tested only with `FakeToolCallingModel._generate` joining message contents (`libs/prebuilt/tests/model.py:28`, `libs/prebuilt/tests/test_react_agent.py:148`). All evaluation redirects to LangSmith (`README.md:56`, `docs/redirects.json:121`). CI has no eval job (` .github/workflows/ci.yml:58`).
- **openai-agents-sdk**: `Prompt` TypedDict (`src/agents/prompts.py:23`) forwarded via `PromptUtil.to_model_input` (`src/agents/prompts.py:56`) and `Agent.get_prompt` (`src/agents/agent.py:325`). Testing is plumbing-only (`tests/test_agent_prompt.py:52`, `tests/test_prompt_cache_key.py:34`). LLM-as-judge is an illustrative loop (`examples/agent_patterns/llm_as_a_judge.py:31`) tested with `FakeModel` (`tests/test_example_workflows.py:90`), not a harness. Dependencies contain no `mlflow`/`wandb` (`pyproject.toml:9`).

Best fit: thin harnesses that deliberately push evaluation to the consumer or platform. Cost: zero confidence on prompt edits; contributors cannot run prompt regressions locally.

## Pattern Catalog

### 1. Typed Dataset with Expected Output and Persistence

*Problem:* Prompt changes need ground truth to compare against.
*Sources:* pydantic-ai (`pydantic_evals/pydantic_evals/dataset.py:111`, `pydantic_evals/pydantic_evals/dataset.py:177`, `pydantic_evals/pydantic_evals/dataset.py:747`), langfuse (`packages/shared/src/server/repositories/dataset-items.ts:211`, `packages/shared/src/server/repositories/dataset-items.ts:841`), agent-framework (`python/packages/core/agent_framework/_evaluation.py:182`, `python/packages/core/agent_framework/_evaluation.py:1809`), openhands absent (`.gitignore:191`), crewai `list[dict]` (`lib/crewai/src/crewai/experimental/evaluation/experiment/runner.py:27`).
*Why it works:* Strong typing (`Dataset[InputsT,OutputT,MetadataT]`) plus YAML/JSON + `$schema` enforces shape at load time; `expected_output`/`expected_tool_calls` stamped per `EvalItem` enables `similarity`/`tool_call_accuracy` scoring; temporal `validFrom`/`validTo` in langfuse (`dataset-items.ts:1367`) supports time-travel experiments.
*When to copy:* Any team with >10 prompt variants. Start with `Case(inputs, expected_output, evaluators)` and `Dataset.to_file`/`from_file`.
*When overkill:* Single static prompt with deterministic tools — just assert tool args via `tool_call_args_match:1215`.
*Evidence:* `pydantic_evals/pydantic_evals/dataset.py:111`, `packages/shared/src/server/repositories/dataset-items.ts:537`, `python/packages/core/agent_framework/_evaluation.py:182`.

### 2. Dual-Layer Evaluation: Fast Local Checks + LLM Judges

*Problem:* LLM judges are expressive but slow, expensive, non-deterministic.
*Sources:* agent-framework (`LocalEvaluator:1518` + `FoundryEvals:728`, `docs/decisions/0023-foundry-evals-integration.md:30`), pydantic-ai (`Equals`/`Contains`/`MaxDuration` in `pydantic_evals/pydantic_evals/evaluators/common.py:358` plus `LLMJudge`/`GEval`), crewai (six judges + `CrewEvaluator` fallback), langfuse (CODE vs `LLM_AS_JUDGE` at `web/src/features/evals/server/router.ts:1109`).
*Why it works:* Local checks run in CI without credentials; LLM judges cover open-ended quality (relevance, coherence, task_adherence). Combining them in one `evaluate_agent` call keeps concept count low (`0023-foundry-evals-integration.md:52`).
*When to copy:* Always. Gate PRs on local checks; run LLM judges nightly or on `label:eval`.
*Evidence:* `python/packages/core/agent_framework/_evaluation.py:1518`, `python/packages/foundry/agent_framework_foundry/_foundry_evals.py:142`, `pydantic_evals/pydantic_evals/evaluators/common.py:224`.

### 3. Structured-Output Judge Contracts over Raw Text

*Problem:* Free-form LLM judge output requires brittle fence-stripping.
*Sources:* pydantic-ai agents with `output_type=GradingOutput`/`GEvalOutput` (`pydantic_evals/pydantic_evals/evaluators/llm_as_a_judge.py:29`, `pydantic_evals/pydantic_evals/evaluators/llm_as_a_judge.py:291`), langfuse `structuredOutputSchema` via `callLLM` (`worker/src/features/evaluation/evalRuntime.ts:46`, `worker/src/features/evaluation/evalService.ts:1039`), crewai brittle `extract_json_from_llm_response` (`lib/crewai/src/crewai/experimental/evaluation/metrics/goal_metrics.py:71` — negative example), agent-framework `_coerce_result:1354` accepting `bool/float/dict/CheckResult`.
*Why it works:* Typed outputs (`reason/pass/score` at `pydantic_evals/pydantic_evals/evaluators/llm_as_a_judge.py:29`) eliminate markdown fence parsing, enable `score_range` validation (`pydantic_evals/pydantic_evals/evaluators/common.py:314`), and support multimodal `UserContent` preservation (`pydantic_evals/pydantic_evals/evaluators/llm_as_a_judge.py:240`).
*When to copy:* For any LLM-as-judge. Prefer function-calling / structured output over `llm.call(prompt)` + JSON extraction.
*Evidence:* `pydantic_evals/pydantic_evals/evaluators/llm_as_a_judge.py:29`, `worker/src/features/evaluation/evalRuntime.ts:46`.

### 4. Report + Diff + Assertion Gate for CI

*Problem:* Scores without a gate do not block regressions.
*Sources:* pydantic-ai `EvaluationReport` + `EvaluationRenderer.build_diff_table` (`pydantic_evals/pydantic_evals/reporting/render_numbers.py:62`, `tests/evals/test_reporting.py:187`) + `ReportAnalysis` (`pydantic_evals/pydantic_evals/reporting/analyses.py:62`), agent-framework `EvalResults.raise_for_status:470` / `assert_score_at_least:502` / `assert_no_failed_items:616` (`python/packages/core/agent_framework/_evaluation.py:470`), crewai `assert_experiment_successfully` / `compare_with_baseline` (`lib/crewai/src/crewai/experimental/evaluation/testing.py:13`), langfuse `getExperimentsFromEvents`/`getExperimentItemsFromEvents` (`packages/shared/src/server/repositories/experiments.ts:138`, `packages/shared/src/server/repositories/experiments.ts:1029`).
*Why it works:* `build_diff_table` renders absolute + relative deltas the way engineers reason; assertion helpers turn a report into a failing test. Pairing with `inline-snapshot` goldens (`tests/evals/test_llm_as_a_judge.py:60`) blocks silent prompt drift.
*When to copy:* Once you have >1 dataset. Add a CI job that loads `baseline.json`, runs `Dataset.evaluate_sync`, and fails if `assert_score_at_least` or `build_diff_table` exceeds threshold.
*Evidence:* `pydantic_evals/pydantic_evals/reporting/render_numbers.py:62`, `python/packages/core/agent_framework/_evaluation.py:502`, `lib/crewai/src/crewai/experimental/evaluation/testing.py:13`.

### 5. Trace / Span-Aware Agentic Evaluation

*Problem:* Text-only judges miss tool-use, loop, and trajectory quality.
*Sources:* pydantic-ai `ToolCorrectness`/`TrajectoryMatch`/`MaxToolCalls` via `SpanTree` (`pydantic_evals/pydantic_evals/evaluators/agentic.py:190`, `pydantic_evals/pydantic_evals/dataset.py:1140`), agent-framework `ConversationSplitter.LAST_TURN/FULL` (`python/packages/core/agent_framework/_evaluation.py:78`) + `evaluate_workflow:1832` with `sub_results` per executor (`python/packages/core/agent_framework/_evaluation.py:373`), crewai `EvaluationTraceCallback` singleton capturing `AgentExecutionStartedEvent`/`ToolUsageFinishedEvent`/`LLMCallStarted/CompletedEvent` (`lib/crewai/src/crewai/experimental/evaluation/evaluation_listener.py:30`), langfuse `JobConfiguration` filter by `targetObject: TRACE/DATASET/OBSERVATION` (`worker/src/features/evaluation/evalService.ts:195`).
*Why it works:* Grounding evaluation in the trace (not final text) enables per-agent breakdown and cheap heuristics before the LLM call (crewai's Jaccard loop detector at `lib/crewai/src/crewai/experimental/evaluation/metrics/reasoning_metrics.py:227`).
*When to copy:* For any agent with tools. Capture `tool_uses`/`llm_calls` and evaluate last-turn vs full trajectory separately.
*Evidence:* `pydantic_evals/pydantic_evals/evaluators/agentic.py:190`, `python/packages/core/agent_framework/_evaluation.py:78`, `lib/crewai/src/crewai/experimental/evaluation/evaluation_listener.py:30`.

### 6. Sampling, Concurrency, and Deduplication at Scale

*Problem:* Evaluating every trace with an LLM judge is prohibitively expensive.
*Sources:* langfuse `EvaluationExecution` queue with `delay` + `sampling` (`worker/src/features/evaluation/evalService.ts:243`, `packages/shared/src/server/queues.ts:347`) + dedup via `jobExecution.findMany` (`worker/src/features/evaluation/evalService.ts:256`), pydantic-ai `max_concurrency` + `sample_rate` + `sampling_mode` in `OnlineEvalConfig` (`pydantic_evals/pydantic_evals/online.py:194`, `pydantic_evals/pydantic_evals/online.py:415`), agent-framework `num_repetitions` (`python/packages/core/agent_framework/_evaluation.py:1790`), `worker/src/queues/experimentQueue.ts:16` rate-limit retry.
*Why it works:* Queue-level sampling reduces cost by ~10x; concurrency caps prevent provider throttling; dedup avoids double-scoring re-ingested traces.
*When to copy:* When dataset >100 cases or online evaluation is on. Start with `max_concurrency=10` + `sample_rate=0.1` with correlated sampling, log drops explicitly.
*Evidence:* `worker/src/features/evaluation/evalService.ts:243`, `pydantic_evals/pydantic_evals/online.py:194`.

### 7. Prompt Invariant Pinning (Snapshot / Ordering Tests)

*Problem:* Judge and system prompts drift silently without compile-time errors.
*Sources:* pydantic-ai `test_build_prompt_section_order_matches_few_shot_examples` (`tests/evals/test_llm_as_a_judge.py:118`) + concise-reason instruction check (`tests/evals/test_llm_as_a_judge.py:60`) with `inline-snapshot`, langgraph `syrupy` graph snapshots (`libs/prebuilt/tests/test_react_agent_graph.py:39`) — unused for prompts but proves infra exists, openhands zero snapshots (gap).
*Why it works:* Section order `Input -> Output -> ExpectedOutput -> Rubric` (`pydantic_evals/pydantic_evals/evaluators/llm_as_a_judge.py:262`) is load-bearing for judge quality; snapshot diffs force explicit review on any prompt edit.
*When to copy:* For any prompt that is a product artifact. Add `tests/test_prompts_snapshot.py` asserting `I18N().slice("tools")` / `_build_prompt` output against checked-in goldens.
*Evidence:* `tests/evals/test_llm_as_a_judge.py:60`, `pydantic_evals/pydantic_evals/evaluators/llm_as_a_judge.py:262`.

## Tradeoffs

**Provider-agnostic protocol vs. hosted evaluator depth**
- Benefit of protocol (`agent-framework` `Evaluator:681`): mix local + Foundry + third-party judges in one call; low concept count. Cost: loose contract — new Foundry evaluators require hardcoded `_BUILTIN_EVALUATORS:142` updates and risk mis-mapping `query` vs `query_messages` (`_build_testing_criteria:218`). Alternative in `pydantic-ai` (`DEFAULT_EVALUATORS` registry at `evaluators/common.py:358` + `custom_evaluator_types`) is more extensible but dataclass-serialization-bound.

**Deterministic fakes vs. live judges**
- Benefit of `FakeToolCallingModel` (`libs/prebuilt/tests/model.py:28`) / `FakeModel` (`tests/fake_model.py:51`): hermetic, fast, no secrets, 85% coverage gates pass. Cost: zero signal on semantic drift; `assert content == "Foo-hi?"` (`test_react_agent.py:148`) catches only string-prepend bugs. Live judges flip this: expressive but flaky, cost 6 calls per case (`agent_evaluator.py:264`), JSON parse failures degrade to `score=None` (`goal_metrics.py:84`) and can be averaged away (`runner.py:114`).

**Transient vs. versioned datasets**
- Benefit transient (`agent-framework`, `crewai`): no storage, no migration. Cost: reproducibility relies on caller re-supplying same `queries`/`expected_output`; Foundry re-creates eval definitions per run (`foundry_evals.py:892`). Versioned (`langfuse` `validFrom`/`validTo` at `dataset-items.ts:1367`, `pydantic-ai` `to_file`/`from_file` at `dataset.py:747`) gives auditability and time-travel but adds schema governance. CrewAI's middle ground — file-local JSON baseline (`result.py:48`) — is VCS-commitable but not concurrent-safe (no lock, `JSONDecodeError` warning at `result.py:66`).

**Library vs. platform experiment tracking**
- Benefit library (`pydantic-ai` `EvaluationReport`, `agent-framework` `EvalResults:305`): no infra, works offline, types enforce shape. Cost: history is ephemeral unless user persists `report.to_json` (`crewai` `result.py:32`, `pydantic-ai` `dataset.py:396`). Platform (`langfuse` `dataset_runs`+`dataset_run_items_rmt`+`events` aggregation at `experiments.ts:138`) gives dashboards and score CTEs (`experiments.ts:875`) but ties you to ClickHouse + BullMQ sharding (`queues.ts:347`, `worker/src/app.ts:279`).

**Immediate prompt availability vs. safety**
- Benefit immediate (`langfuse` `setLabels` at `promptRouter.ts:801` + `PromptService.invalidateCache`, `openhands` `lru_cache` at `prompt.py:57`): fast iteration. Cost: `latest` can ship without any experiment; openhands `StrictUndefined` is off (`prompt.py:67`) so typos render as empty strings. Gating promotion on `datasetId -> threshold` would add safety but slows iteration — no source implements it today.

## Decision Guide

Use this when choosing how to add prompt evaluation to a harness or product:

1. **Do you ship an observability platform?** → Follow `langfuse`. Add versioned datasets (`dataset-items.ts:211`), prompt registry with `labels` (`promptRouter.ts:297`), `ExperimentCreate` queue (`queues.ts:131`), and `getExperimentsFromEvents` comparison (`experiments.ts:138`). Require `prompt.name@version` on every generation trace. Do not ship prompts without a dataset.

2. **Do you ship a library/harness and want zero infra?** → Follow `pydantic-ai` > `agent-framework`.
   - Start with `Dataset`/`Case` (`dataset.py:177`/`dataset.py:111`), `LLMJudge` (`evaluators/common.py:224`) with structured output (`llm_as_a_judge.py:29`), and `EvaluationRenderer.build_diff_table` (`reporting/render_numbers.py:62`).
   - Add `LocalEvaluator`-style fast checks (`_evaluation.py:1518`) + `@evaluator` injection (`_evaluation.py:1415`) for contributors without API keys.
   - Copy `agent-framework`'s `_resolve_evaluators:2056` auto-wrapping — adjacent `EvalCheck` callables become one `LocalEvaluator` without boilerplate.

3. **Do you need a lightweight judge quickly?** → Follow `crewai` *pattern* not its *packaging*. Copy single-responsibility judges with rubric + JSON contract (`goal_metrics.py:36`) but replace `llm.call` + fence stripping with structured output (`pydantic-ai` `GradingOutput` or `langfuse` `structuredOutputSchema`). Avoid `experimental` gate without docs — crewai's `docs/edge/en/concepts/testing.mdx:1` documents only `crewai test`, hiding experimental judges.

4. **Do you need runtime gating (not offline evaluation)?** → Follow `openhands` `APIBasedCritic` (`critic/impl/api/critic.py:47`) only if you can tolerate network + 27-label coupling (`client.py:324` `len(probs) != len(all_labels)`). Otherwise use `AgentFinishedCritic` (`critic/impl/agent_finished.py:20`) as a cheap deterministic gate.

5. **Should you delegate entirely?** → Only if you commit to making delegation testable. If you choose LangSmith/tracing-export (`README.md:56`, `docs/tracing.md:200`), add a `make eval` harness with 20–50 golden `input -> expected prepared messages` pairs exercised by `FakeModel` locally, plus a nightly `RUN_LIVE_EVAL=1` job that uses the external platform — otherwise delegation is abdication.

**Caution rule:** If `prompt` is `str | SystemMessage | Callable | Runnable` (`chat_agent_executor.py:121`) or a free-form `instructions` string with no registry, add a snapshot test before adding any judge. Judges without a versioned prompt surface produce incomparable scores.

## Practical Tips

- **Copy these now (low cost, high signal):**
  - Typed `Case` + `Dataset` with `expected_output` and YAML persistence (`pydantic_evals/pydantic_evals/dataset.py:111`, `pydantic_evals/pydantic_evals/dataset.py:747`). Inject with `FakeModel` first, swap to live model later.
  - `LocalEvaluator` + `keyword_check`/`tool_call_args_match` (`python/packages/core/agent_framework/_evaluation.py:1062`) for every tool-using prompt — deterministic, no cost.
  - `@evaluator` with param-name injection (`python/packages/core/agent_framework/_evaluation.py:1415`) so a judge is `async def llm_judge(query: str, response: str) -> float` with no protocol learning.
  - Snapshot-pin judge prompts: assert section order `Input->Output->ExpectedOutput->Rubric` (`pydantic_evals/pydantic_evals/evaluators/llm_as_a_judge.py:262`) and system-prompt concise-reason instruction (`tests/evals/test_llm_as_a_judge.py:60`) via `inline-snapshot`/`syrupy`.
  - `EvalResults.raise_for_status` / `assert_score_at_least` (`python/packages/core/agent_framework/_evaluation.py:470`) wired into `pytest` — the cheapest CI gate.
  - Dual-target scoring: evaluate `LAST_TURN` and `FULL` trajectory separately (`python/packages/core/agent_framework/_evaluation.py:78`, `python/packages/core/agent_framework/_evaluation.py:1629`) and report `sub_results` per agent (`python/packages/core/agent_framework/_evaluation.py:373`).

- **Delay until you have scale:**
  - Hosted LLM-as-judge over 100+ cases — cost multiplies (crewai: 6 calls/case at `agent_evaluator.py:264`). Start with a 20-case golden set, sample at 10% via `sample_rate` (`pydantic_evals/pydantic_evals/online.py:194`).
  - `GEval` with `evaluation_steps` + logprob weighting (`pydantic_evals/pydantic_evals/evaluators/llm_as_a_judge.py:321`) — powerful but needs rubric calibration; use `LLMJudge` first.
  - Online `@evaluate` with `gen_ai.evaluation.result` OTel emission (`pydantic_evals/pydantic_evals/online.py:496`) — valuable for production drift but requires Logfire/OTel sink governance.

- **Decision rules:**
  - If evaluator needs ground truth → require `expected_output` on `Case`/`EvalItem`; filter tool evaluators when `tool_definitions` missing (`python/packages/foundry/agent_framework_foundry/_foundry_evals.py:352`) rather than failing silently.
  - If judging every trace → add queue-level `sampling` + `delay` (`worker/src/features/evaluation/evalService.ts:243`) and `max_concurrency` semaphore (`pydantic_evals/pydantic_evals/online.py:415`); monitor dropped evaluations.
  - If serving versioned prompts → invalidate cache on label change (`promptRouter.ts:297` + `PromptService.invalidateCache`) and test `lru_cache` staleness (`_sdk_inspect/sdk/context/prompts/prompt.py:57`); set `jinja2.StrictUndefined` to fail on typos.

## Anti-Patterns / Caution Signs

- **Notebook-driven LLM-as-judge** (`langgraph_self_rag_pinecone_movies.ipynb:179`, `langgraph_adaptive_rag_local.ipynb:253`, `langgraph_crag_local.ipynb:653`): `hub.pull("efriis/self-rag-retrieval-grader")` without revision pinning + `evaluate(..., experiment_prefix=...)` in a notebook is a demo, not a harness. Scores are not reproducible across PRs.
- **Raw `llm.call` + JSON fence stripping** (`lib/crewai/src/crewai/experimental/evaluation/metrics/goal_metrics.py:71`, `semantic_quality_metrics.py:71`, `tools_metrics.py:66`): every evaluator catches `Exception` and returns `score=None` (`goal_metrics.py:84`, `tools_metrics.py:141`); `ExperimentRunner._run_test_case` (`runner.py:114`) drops `None` before averaging, so a broken judge pool can yield `avg_scores={}` and still pass partial intersections (`runner.py:155`).
- **Singleton event-bus trace capture** (`lib/crewai/src/crewai/experimental/evaluation/evaluation_listener.py:30`, `_instance`, `traces: dict`): requires manual `reset_iterations_results()` (`runner.py:48`) and `conftest.py:186` handler clearing; parallel runs interleave traces.
- **File-local JSON baseline without locking** (`lib/crewai/src/crewai/experimental/evaluation/experiment/result.py:48`): `compare_with_baseline` reads-then-appends without `flock`; `JSONDecodeError` only warns (`result.py:66`) and overwrites. Not safe for CI matrix or concurrent workers.
- **Jinja without `StrictUndefined`** (`_sdk_inspect/sdk/context/prompts/prompt.py:67`): missing `system_prompt_kwargs` render as empty strings; prompt drift is silent. Pair with golden tests.
- **Empty cache / heuristic critic as quality proxy** (`_sdk_inspect/sdk/critic/impl/api/client.py:128` 27 hard-coded labels, `extract_prob_map` raises `ValueError` on mismatch at `client.py:324`): label churn breaks client; `AgentFinishedCritic` (`critic/impl/agent_finished.py:20`) only checks `FinishAction + non-empty patch` — useful as smoke, harmful as quality gate.
- **Coverage gate masking prompt surface** (`Makefile:59` `--fail-under=85` at `openai-agents-sdk`): plumbing can be 85% covered while prompt-regression lines are 0%; prompt changes ship green (`tests.yml:80` `OPENAI_API_KEY=fake-for-tests`).
- **Unpinned judge model / rubric version** (`python/packages/foundry/agent_framework_foundry/_foundry_evals.py:61` `GeneratedEvaluatorRef` warns on `latest:92`, `pydantic_evals/pydantic_evals/evaluators/llm_as_a_judge.py:26` `openai:gpt-5.2`): repeated runs diverge silently; CI should pin `version`.
- **Ignoring `status="timeout"`** (`python/packages/foundry/agent_framework_foundry/_foundry_evals.py:383`, `python/packages/core/agent_framework/_evaluation.py:462`): `_poll_eval_run` returns `status="timeout"` not an exception; callers summing `passed/failed` without status check treat timeout as zero results.

## Open Questions

- **Do maintainers intend library harnesses to ever own prompt regression?** `langgraph` (`README.md:56`, `redirects.json:121`) and `openai-agents-sdk` (`docs/tracing.md:200`) document delegation as intentional; `agent-framework` ADR `0023-foundry-evals-integration.md:47` notes datasets as future work. Confirm whether bundling a minimal golden set and snapshot suite is in-scope or permanently user-owned.
- **What validates judge quality?** No source ships rubric calibration data, inter-rater agreement, or prompt-injection sanitization for `_build_prompt` interpolating raw `Input`/`Output` (`pydantic_evals/pydantic_evals/evaluators/llm_as_a_judge.py:262`); `openhands` judge model (`Qwen/Qwen3-4B-Instruct-2507` tokenizer at `client.py:111`) is opaque. How is judge drift detected without live-model CI (`pipeline.yml:466` skips validation)?
- **How is dataset version pinned per run?** `langfuse` `jobInputDatasetItemValidFrom` is optional (`evalService.ts:501`) and resolves to latest if absent (`dataset-items.ts:1367`); `pydantic-ai` `Dataset.to_file` (`dataset.py:747`) has no hash/version tying `EvaluationReport` back to exact dataset revision. Is lineage best-effort or enforced?
- **Can existing snapshot infra be reused for prompts?** `langgraph` has `syrupy` for graph diagrams (`test_react_agent_graph.py:39`), `pydantic-ai` has `inline-snapshot` for judges (`test_llm_as_a_judge.py:60`), `openai-agents-sdk` has `inline-snapshot` for spans (`test_agent_tracing.py:53`). Should prompt rendering snapshots be a mandated companion to every prompt file (`system_prompt.j2`, `translations/en.json:8` slices, `chat_agent_executor.py:119`)?
- **What is the minimal experiment store for library users?** File-local JSON (`crewai` `result.py:48`) is VCS-commitable but racy; ephemeral Foundry runs (`agent-framework` `foundry_evals.py:892`) are cloud-coupled; full ClickHouse (`langfuse` `experiments.ts:138`) is heavyweight. Would a filesystem-backed hashed run registry (`Dataset` + task version hash) satisfy 80% of teams?
