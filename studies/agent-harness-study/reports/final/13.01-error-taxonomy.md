## Executive Summary

Error taxonomies in agent harnesses and related systems converge on **three axes of classification**: *where* the failure came from (source category), *what stage* it occurred at (parse/eval/dispatch/response), and *what to do next* (retry/escalate/stop). The strongest taxonomies encode all three axes simultaneously — `letta` (central `ErrorCode` enum + per-source families + typed dispatch), `pydantic-ai` (single hierarchy where the class itself encodes source and the standard `except` clause encodes the disposition), `langfuse` (HTTP-aligned root + source-classified domain classes + retryable flag), and `temporal` (typed service errors with `{Cause, Scope}` enums). Mid-tier frameworks split the axes: `agent-framework` is excellent on the Python side (single root, parallel leaves, dispatch sites) but absent on .NET; `crewai` is excellent in the A2A and file-upload subsystems but relies on **string/substring matching** for provider error classification in the core agent loop. `langgraph` is structurally explicit but classifies by **runtime role** (control vs node vs validation) rather than by the dimension's requested source axis, which makes "is this a model error or a tool error?" answerable only after unwrapping. `opa` uses layer-local string codes with subsystem prefixes rather than a global enum — a deliberate decoupling choice. `openhands` is fragmented across subsystems with `SlackErrorCode` as the most mature component.

Across all sources, the dimension's guiding question — *can you tell from the error type whether to retry, escalate, or stop?* — has **three structural answers**: (a) the type itself carries a `retryable`/`is_retryable`/`isOperational` field (letta, openai-agents-sdk sandbox, langfuse LLMCompletionError); (b) the type is checked against a `_RETRYABLE_ERRORS` tuple or `fallback_on` callable (pydantic-ai, letta); (c) the type is interpreted by a dispatch function whose knowledge lives in prose and code (agent-framework, langgraph, opa, crewai). Sources that pick (a) or (b) score 7–8; sources that rely on (c) alone score 5–6 because the knowledge is non-portable. No source scored 9–10.

## Core Thesis

A mature error taxonomy for an agent harness should **encode source on the exception itself** — not as a separate `category` attribute that callers must remember to check — and should make the retry/escalate/stop decision either derivable from the type or expressed as a declarative policy (`fallback_on`, `_RETRYABLE_ERRORS`, `isRetryable`) rather than scattered across `except` clauses. The single most load-bearing decision is whether source classification is structural (class hierarchy, single root, parallel leaves) or federated (each subsystem owns its own). Structural wins for cross-subsystem dispatch and telemetry but costs duplication; federated wins for subsystem autonomy and parallel evolution but costs the ability to answer repo-wide questions like "list all retryable errors." The strongest source — `letta` — shows the structural pattern working well; the second strongest — `temporal` — shows the structural pattern working under production load with typed wire-format errors; both pay a per-error boilerplate cost to keep the type system honest.

## Approach Models

Five distinct approach models emerge from the eleven sources. The empty `reports` source represents the null case (absent taxonomy) and is excluded from clustering.

### A. Single-rooted class hierarchy with parallel leaves (subclassing)

**Sources**: `agent-framework` (Python), `pydantic-ai`, `openai-agents-sdk` (core).

The codebase owns one root exception (`AgentFrameworkException` at `python/packages/core/agent_framework/exceptions.py:15`; `RuntimeError`/`UserError` at `pydantic_ai_slim/pydantic_ai/exceptions.py:159`; `AgentsException` at `src/agents/exceptions.py:46`) and grows the taxonomy by subclassing. Source categories become L1 branches — `AgentException`, `ChatClientException`, `IntegrationException`, `ToolException`, `WorkflowException` in agent-framework; `ModelAPIError`, `UnexpectedModelBehavior`, `UsageLimitExceeded`, `UserError` in pydantic-ai. agent-framework layers a **parallel-leaf pattern** on top: each transport-style branch (`Agent`, `ChatClient`, `Integration`) carries the same set of children (`InvalidAuth`, `InvalidRequest`, `InvalidResponse`, `ContentFilter`) so callers can `except` the failure mode uniformly across subsystems (`python/CODING_STANDARD.md:215-217`). pydantic-ai uses inheritance *and* payload fields — `ModelHTTPError` carries `status_code` and `body` so terminal code is reachable without `isinstance` (`exceptions.py:236-266`).

Dispatch is `isinstance`-based. Control-flow types (`ModelRetry`, `CallDeferred`, `ApprovalRequired`, `SkipModelRequest`; `MiddlewareTermination` in agent-framework) are exceptions too, deliberately, so hooks can `raise` to divert. This is the most ergonomic model in Python because it composes with the language, but it has one sharp edge: a broad `try/except Exception` in user code can accidentally intercept deferral/interrupt signals — pydantic-ai documents this and compensates by instrumenting deferrals as non-error spans (`capabilities/instrumentation.py:358-361`).

### B. Two-track taxonomy: HTTP-shaped root + source-classified domain

**Sources**: `langfuse`, `letta`.

These two libraries want both a stable wire-level identifier (HTTP code, SSE `error_type`, API `code`) *and* a source-classified type. They solve this by maintaining two parallel hierarchies that converge at boundaries.

- `langfuse`: a flat HTTP-aligned `BaseError` family in `packages/shared/src/errors/BaseError.ts:1-27` (sort of like Pydantic's `HTTPException` but as a parent), plus per-source domain classes — `ClickHouseResourceError` with `MEMORY_LIMIT|OVERCOMMIT|TIMEOUT` discriminators (`packages/shared/src/server/repositories/clickhouse.ts:36-99`), `LLMCompletionError` with `isRetryable` and inferred `EvaluatorBlockReason` (`packages/shared/src/server/llm/errors.ts:31-67`), `SlackApiError` with `slackErrorCode`, `UnrecoverableError`, `ObservationNotFoundError`, `CodeEvalDispatcherError` with `RETRYABLE_ERROR_CODES`/`USER_ERROR_CODES` sets (`packages/shared/src/server/evals/codeEvalDispatcherTypes.ts:124-140`). The two tracks meet at five dispatch sites — `toUnstablePublicApiError()`, `formatErrorForUser()`, tRPC `withErrorHandling`, REST `withMiddlewares`, and worker queues (`web/src/features/public-api/server/unstable-public-api-error-contract.ts:160-262`; `web/src/features/mcp/core/error-formatting.ts:27-104`; `web/src/server/api/trpc.ts:140-215`).

- `letta`: one central `errors.py` with `ErrorCode` enum (`letta/errors.py:11-24`), one `LettaError` root carrying `(code, details)`, and per-source families. The "HTTP-shaped" track is the FastAPI exception handler table that maps every class to a specific status code (`letta/server/rest_api/app.py:556-779`) and the SSE `event: error` channel that emits fixed `error_type` strings (`letta/services/streaming_service.py:639-776`). The "source-classified" track is the `LLMError` subtree (`letta/errors.py:259-314`), the `LettaMCPError` subtree (`letta/errors.py:208-237`), the context-window family (`letta/errors.py:352-371`), the database family in `letta/orm/errors.py:1-38`, and the BYOK-attribution flag threaded through every mapper (`letta/llm_api/openai_client.py:1240-1242`).

**Differentiation**: letta's `ErrorCode` is a single enum shared by every exception; langfuse's `name` + `httpCode` is the universal identifier, but the source-classified domain classes are not children of `BaseError`. letta centralizes; langfuse federates by domain.

### C. Federated per-subsystem with bounded independence

**Sources**: `crewai`, `openhands`, `agent-framework` (.NET), and partially `langgraph`.

Each subsystem owns its own exception family; the framework never consolidated them. `crewai` has `a2a/errors.py` (`A2AErrorCode` IntEnum with JSON-RPC codes; `is_retryable_error` / `is_client_error` predicates — `lib/crewai/src/crewai/a2a/errors.py:25-503`), `crewai-files/.../exceptions.py` (`TransientUploadError`/`PermanentUploadError` files; `classify_upload_error` — `lib/crewai-files/src/crewai_files/processing/exceptions.py:86-135`), `events/types/*.py` (typed error events per source — `lib/crewai/src/crewai/events/types/llm_events.py:117`), and the core harness which falls back on `e.__class__.__module__.startswith("litellm")` and 8 hardcoded phrases (`lib/crewai/src/crewai/utilities/exceptions/context_window_exceeding_exception.py:4-13`). `openhands` mirrors this shape with `OpenHandsError` as one small root (`openhands/app_server/errors.py:6-43`), provider errors as siblings (`service_types.py:171-198`), a Slack subsystem with proper `SlackErrorCode` enum and `_USER_MESSAGES` registry (`enterprise/integrations/slack/slack_errors.py:18-134`), and two unrelated `AuthError` classes (`errors.py:18` and `auth_error.py:1`) that coexist without collision detection.

This model is robust to subsystem churn but pays for it: the central `crewai/utilities/exceptions/__init__.py` is empty (`utilities/exceptions/__init__.py:1`); openhands' frontend classifies budget errors by regex over provider error text (`frontend/src/utils/error-handler.ts:40-55`) because there is no shared type to import. Cross-subsystem questions ("list every retryable error in this repo") are unanswerable.

`langgraph` is a special case of this model: it has *one* file (`libs/langgraph/langgraph/errors.py:1-241`) but partitions errors by *runtime role* (control-flow, node-attributable, validation, infrastructure) rather than by source. `GraphBubbleUp` separates control flow from fatal; `NodeError` is a dataclass (not an exception) carried in the handler's configurable; `ErrorCode` enum is a documentation-bridge for external troubleshooting URLs. The runtime taxonomy is honest and load-bearing — `_panic_or_proceed` (`libs/langgraph/langgraph/pregel/_runner.py:650-697`) and `commit` (`libs/langgraph/langgraph/pregel/_runner.py:574-613`) both branch on it — but the dimension's "model vs tool vs policy vs context" axis is delegated to the third-party exception types, so callers cannot answer source questions from `type(error)` alone.

### D. Layer-local string codes with subsystem prefix

**Source**: `opa`.

OPA explicitly rejects a global hierarchy. Each layer defines its own `Error` struct with a string `Code`: `ast.Error` with `rego_*` codes (`v1/ast/errors.go:48-66`), `topdown.Error` with `eval_*` codes (`v1/topdown/errors.go:35-60`), `storage.Error` with `storage_*` codes (`v1/storage/errors.go:11-42`), `bundle.Error` with `bundle_error` (`v1/plugins/bundle/errors.go:25-53`). The REST API boundary has a separate, coarser code set (`internal_error`, `evaluation_error`, `unauthorized`, `invalid_parameter`, `invalid_operation`, `resource_not_found`, `resource_conflict`, `undefined_document` at `v1/server/types/types.go:119-128`). A separate `Halt` type carries stop semantics (`v1/topdown/errors.go:14-24`).

The motivation is decoupling: each package owns its vocabulary without import cycles. The cost is that `ErrorAuto` (`v1/server/writer/writer.go:27-42`) and similar dispatch sites must type-switch per layer, and there is no shared `errors.As` target for "any OPA error". The WASM SDK deliberately closes the taxonomy (`internal/wasm/sdk/opa/errors/errors.go:39-46`) — `New` panics on unknown codes, which is a stronger contract than the Go layers. Documentation is well done for user-facing errors (`docs/docs/errors/index.md` organizes by stage with per-error pages), but a single reference enumerating all codes across layers does not exist.

### E. Typed wire-format errors with cause/scope enums

**Source**: `temporal`.

Temporal's taxonomy is shaped by its wire protocol. Layer-owned error structs (`common/persistence/data_interfaces.go:102-158`, `common/serviceerror/*.go`) are converted at boundaries (`service/history/handler.go:2233-2258`, `service/history/chasm_engine.go:1261-1329`) to gRPC status codes with typed proto details (`proto/internal/temporal/server/api/errordetails/v1/message.proto:12-61`) that decode back to typed errors on the receiving side (`common/serviceerror/convert.go:11-57`). `ResourceExhausted{Cause, Scope}` is the load-bearing pattern: 11 distinct causes (`RPS_LIMIT`, `BUSY_WORKFLOW`, `APS_LIMIT`, `SYSTEM_OVERLOADED`, `PERSISTENCE_STORAGE_LIMIT`, ...) crossed with `system`/`namespace` scopes enable `isUserError` (`service/history/queues/executable.go:398-405`) and the dual throttle policy at `common/backoff/retry.go:80-82`. Workflow failures are stored as a discriminated proto union (`ApplicationFailureInfo`, `TimeoutFailureInfo`, `ServerFailureInfo`, ...) so retry decisions survive restarts and are evaluated later from history (`service/history/workflow/retry.go:115-152`).

The model is operationally excellent (typed, observable, tested) but requires per-error boilerplate: every new typed server error needs a proto detail message, `Status()` plumbing, and a `FromStatus` case. The docs acknowledge this: "typed errors round-trip losslessly" but the wire contract is a versioning commitment.

## Pattern Catalog

Patterns that appear across multiple sources or that one source demonstrates unusually clearly.

### P1. Provider normalization as an enforced interface

Every source that talks to multiple LLM providers writes an adapter that catches vendor SDK exceptions and converts them to a local taxonomy. The strongest versions turn this into an abstract method.

- `letta`: `handle_llm_error()` is abstract on `llm_client_base.py:368-397`; every provider implements it; regression tests pin the mappings (`tests/adapters/test_letta_llm_stream_adapter_error_handling.py:179-363`).
- `pydantic-ai`: every `models/{provider}.py` has the same wrapper pattern — OpenAI `models/openai.py:189-192`, Anthropic `models/anthropic.py:250-253`, Bedrock `models/bedrock.py:123-124`, Groq `models/groq.py:84-87`, xAI `models/xai.py:86-87`, Cohere `models/cohere.py:203-204`, Mistral `models/mistral.py:109-110`, Gemini `models/gemini.py:277`, Google `models/google.py:836-841`, HuggingFace `models/huggingface.py:83`.
- `agent-framework`: `_handle_request_error` in `python/packages/openai/agent_framework_openai/_chat_client.py:598-611` (OpenAI-specific dispatch).
- `openhands`: `handle_http_status_error` / `handle_http_error` in the shared `HTTPClient` base (`app_server/integrations/protocols/http_client.py:82-110`), tested per branch (`tests/unit/integrations/protocols/test_http_client.py:126-220`).

**Why it works**: downstream code never sees vendor exception types; one `except ModelAPIError` (pydantic-ai) or `except LLMError` (letta) catches every provider. **When to copy**: when you have ≥3 provider integrations or expect to add more. **When overkill**: a single-provider project can skip it. **Risk**: string/phrase-based fallback layers (letta `letta/llm_api/error_utils.py:8-41`, crewai `context_window_exceeding_exception.py:32-44`) become load-bearing when SDK types don't expose the right signal.

### P2. Cause-chain propagation as a classification mechanism

Several taxonomies deliberately walk `__cause__` chains to recover the underlying failure, because vendor SDKs wrap fetch errors as `APIConnectionError { cause: original }`.

- `langfuse`: `findNonRetryableCauseMessage` and `extractCleanErrorMessage` walk `.cause` chains (`packages/shared/src/server/llm/fetchLLMCompletion.ts:890-892`); same walk drives the user-visible message and `isRetryable`.
- `letta`: `with` chaining on `original_exception` preserved through DB wrappers (`letta/orm/sqlalchemy_base.py:84-106`).
- `agent-framework`: `AgentFrameworkException(inner_exception=...)` propagates through `super().__init__` (`python/packages/core/agent_framework/exceptions.py:21-38`).
- `opa`: `bundle.Error` implements `Unwrap` so `errors.As` recovers `download.HTTPError` (`v1/plugins/bundle/errors.go:51-53`).

**Why it works**: keeps fidelity through wrapping. **Risk**: only useful if every wrapping site preserves the chain; some layers (temporal persistence `common/persistence/data_interfaces.go:1358-1392` returns only `Msg`) discard it.

### P3. Errors-as-data payloads (rather than just signals)

Several taxonomies attach structured fields to the exception so downstream layers don't have to re-parse.

- `agent-framework`: `UserInputRequiredException.contents` carries the user-input-request Content items (`exceptions.py:197-209`); `OpenAIContentFilterException` carries `param`, `content_filter_code`, `content_filter_result` (`openai/.../_exceptions.py:56-90`); `WorkflowValidationError` carries `ValidationTypeEnum` + per-subclass fields (`validation.py:19-82`).
- `letta`: `details` dict carries `error_code`, `pending_request_id`, `run_id`, `lock_holder_token`, `max_retries`, `is_byok` (`letta/errors.py:55,68,77,101-104,118-122`); BYOK-aware `__str__` (`errors.py:27-45`).
- `langgraph`: `NodeError` is a frozen dataclass `(node: str, error: BaseException)` injected via `CONFIG_KEY_NODE_ERROR` (`libs/langgraph/langgraph/errors.py:148-165`; `_internal/_constants.py:77-80`).
- `openai-agents-sdk`: `RunErrorDetails` carries input, new_items, raw_responses, last_agent, guardrail results (`src/agents/exceptions.py:30-43`); attached to every `AgentsException` (`src/agents/run.py:1505-1517`, `src/agents/run_internal/run_loop.py:1175-1187`).
- `temporal`: gRPC status details carry full error structure round-trip (`common/serviceerror/retry_replication.go:52-70`).

**Why it works**: post-mortem context is preserved without logging the whole input. **Risk**: payloads grow; serialization must be designed (pydantic-ai pins pickle round-trip in `tests/test_exceptions.py:73-140`).

### P4. Retry/escalate as a *property on the exception* (not a separate table)

The dimension's guiding question has the cleanest answer in sources that encode retryability on the type.

- `letta`: `_RETRYABLE_ERRORS = (httpx.ReadError, WriteError, ConnectError, RemoteProtocolError, LLMConnectionError)` tuple; circuit-breaker logic in agent loop (`letta_agent_v3.py:1183-1226`).
- `openai-agents-sdk` sandbox: `retryable: bool | None` field where `None` means "SDK cannot safely classify" (`src/agents/sandbox/errors.py:86-87`); propagated through `__post_init__` from the cause chain (`errors.py:97-99`); surfaced to traces and session events (`session/sandbox_session.py:354-356`, `events.py:73`).
- `langfuse`: `LLMCompletionError.isRetryable` (default false; set by `fetchLLMCompletion` based on `responseStatusCode` + name + cause-chain inspection — `packages/shared/src/server/llm/fetchLLMCompletion.ts:880-928`); `CodeEvalDispatcherError` paired with `RETRYABLE_ERROR_CODES`/`USER_ERROR_CODES`/`INTERNAL_CODE_EVAL_ERROR_CODES` sets (`packages/shared/src/server/evals/awsLambdaCodeEvalDispatcher.ts:39-54`).
- `temporal`: retryability keyed off cause enum + scope + non-retryable flag (`service/history/workflow/retry.go:115-152`); `ResourceExhausted{Cause}` drives throttle policy (`common/backoff/retry.go:80-82`).
- `openhands`: `RateLimitResult.retry_after` carried as data (`enterprise/server/rate_limit.py:39-47`).
- agent-framework, langgraph, crewai, opa: retryability knowledge lives in dispatch functions and prose (not on the type), making it harder to audit and easier to lose.

**Why it works**: callers decide from `e.retryable` without remembering per-type rules. **Risk**: requires discipline at construction (where does `isRetryable` get set?); langfuse sets it once in `fetchLLMCompletion`; letta/agent-framework keep it as catch-site tuples.

### P5. Type-configurable fallback routing

A higher-order pattern: the user declares which exception types should trigger escalation.

- `pydantic-ai`: `FallbackModel.fallback_on` accepts `(type[Exception], ...)` tuples, handler callables, or mixed sequences; default `(ModelAPIError,)` (`models/fallback.py:33-41,91`). Users can fall back on any class — including `UserError` — without library changes.
- `agent-framework`: Per-provider classifier pattern (separate classifier hooks per client) — no central registry.
- `langfuse`: `EvaluatorBlockReason` enum with `EVALUATOR_BLOCK_METADATA` table mapping every reason to a resolution path URL (`packages/shared/src/features/evals/evalConfigBlocking.ts:59-99`) — declarative but value-typed, not class-typed.

**Why it works**: type-configurable policies survive library growth. **Risk**: nothing forces the policy to be exhaustive; an empty `fallback_on` triggers `UserError` (pydantic-ai `models/fallback.py:143-148`).

### P6. Control-flow exceptions as first-class types

Multiple Python ecosystems reuse the exception channel for non-failure signaling.

- `pydantic-ai`: `ModelRetry`, `CallDeferred`, `ApprovalRequired`, `SkipModelRequest`, `SkipToolValidation`, `SkipToolExecution` — all `Exception` subclasses (`exceptions.py:40-156`); instrumentation explicitly treats deferrals as non-error spans (`capabilities/instrumentation.py:358-361`).
- `agent-framework`: `MiddlewareTermination(MiddlewareException)` short-circuits the middleware loop; `log_level=None` distinguishes it from real errors (`python/packages/core/agent_framework/_middleware.py:72-79`).
- `langgraph`: `GraphBubbleUp` superclass with `GraphInterrupt`, `GraphDrained`, `ParentCommand`; runner detects via `isinstance` and excludes from re-raise (`libs/langgraph/langgraph/pregel/_executor.py:81-86,171-181`).
- `opa`: `topdown.Halt` and `rego.HaltError` mark "stop evaluation immediately" (`v1/topdown/errors.go:14-24`, `v1/rego/errors.go:5-18`).
- `agent-framework` MCP: `_MCPTaskAbandoned(ToolExecutionException)` private marker distinguishes "cancel before raise" from "terminal failure" for SEP-2663 long-running tasks (`python/packages/core/agent_framework/_mcp.py:244-248`).

**Why it works**: hook composition via `raise to divert`; no separate signal channel needed. **Risk**: user `try/except Exception` can intercept signals accidentally; mitigation is documentation + instrumentation special-cases.

### P7. Trace/telemetry integration via class name

The class name becomes the operational classifier for observability — without adding a `category` field.

- `agent-framework`: `observability.capture_exception` stamps OpenTelemetry `error.type = type(exception).__name__` (`python/packages/core/agent_framework/observability.py:2278-2282`).
- `langgraph`: `_AttemptEvent.error_type = type(error).__name__` (`libs/langgraph/langgraph/pregel/_retry.py:124-126`).
- `letta`: SSE `event: error` emits fixed `error_type` strings per class; stream watchdog emits `error_type="stream_incomplete"` if terminal event missing (`streaming_service.py:601-629`).
- `temporal`: metrics tagged by `metrics.ResourceExhaustedCauseTag` per cause (`service/history/queues/executable.go:465-466`); distinct metrics for `TaskSkipped`, `TaskThrottledCounter`, `TaskCorruptionCounter`, `TaskTerminalFailures`.

**Why it works**: no extra dispatch code; the class system already exists. **Risk**: if `name`-based guards (langfuse `isLLMCompletionError` checks `e.name === "LLMCompletionError"`) coexist with class-based observability, subclassing silently breaks the guards.

### P8. Discriminator tables for message-pattern classification

When SDK types don't expose the right signal, several libraries use `Record<Type, { discriminators: string[] }>` tables.

- `langfuse`: `ERROR_TYPE_CONFIG` keyed by `"MEMORY_LIMIT"|"OVERCOMMIT"|"TIMEOUT"` with message-pattern discriminators (`packages/shared/src/server/repositories/clickhouse.ts:36-51`); `wrapIfResourceError()` iterates entries.
- `crewai`: `CONTEXT_LIMIT_ERRORS` phrase list of 8 lowercase substrings (`context_window_exceeding_exception.py:4-13`); matched via `_is_context_limit_error` static method.
- `letta`: `is_context_window_overflow_message` (5 provider phrasings) and `is_insufficient_credits_message` (quota/billing phrasings); docstrings admit "best-effort" (`letta/llm_api/error_utils.py:8-41`).
- `openhands` frontend: `isBudgetOrCreditError` substring regex over provider error text (`frontend/src/utils/error-handler.ts:40-55`).

**Why it works**: covers cases where SDK types are absent (HTML-wrapped ALB errors, streaming `APIError`). **Risk**: vendor rewording silently misclassifies — and is load-bearing (letta `openai_client.py:1314-1321` works around streamed `APIError`s specifically).

### P9. Cause/scope enums for resource exhaustion

- `temporal`: `ResourceExhausted{Cause, Scope}` with 11 causes crossed with 2 scopes enables `isUserError` (`service/history/queues/executable.go:398-405`) and dual throttle policy (`common/backoff/retry.go:80-82`). The two-axis design is what lets "namespace hit its limit" be treated differently from "system is overloaded."

**Why it works**: separates *what limit* from *who hit it*. **Risk**: requires enum constants at every level of the code; langfuse does this for `EvaluatorBlockReason` (`packages/shared/prisma/schema.prisma:1037-1044`) but only spans eval failures.

### P10. Docstring + When-to-use table as the durable contract

Two sources invest in a single docstring-driven reference.

- `agent-framework`: full ASCII tree in `python/CODING_STANDARD.md:227-271`; 12-row When-to-use table at `python/CODING_STANDARD.md:273-291`; branch-selection rule at `python/CODING_STANDARD.md:292-302`.
- `pydantic-ai`: every exception class has a docstring rendered into `docs/api/exceptions.md:1-3`; `docs/agent.md:1203-1231` documents `__cause__` inspection pattern; `RetryPromptPart` enumerates its six trigger sources (`messages.py:1410-1419`).

**Why it works**: docstrings render to docs sites automatically. **Risk**: drifts from code; agent-framework mitigated with `test_exception_exports` tests but `openai-agents-sdk` omissions (`ModelRefusalError`, `MCPToolCancellationError`, both tool-guardrail tripwire types) show the drift is real.

### P11. Retry classification via third-party exception allow/deny list

- `langgraph`: `default_retry_on` (`libs/langgraph/langgraph/_internal/_retry.py:1-29`) allowlists `ConnectionError`, 5xx HTTP, `NodeTimeoutError`; denylists `ValueError`, `TypeError`, etc. Anything not listed is retried by default.

**Why it works**: zero-configuration safety net for unknown providers. **Risk**: silently retries 4xx errors as if transient when a new provider ships; the agent-framework `_handle_request_error` model (only treats `BadRequestError(code="content_filter")` as content filter, everything else `ChatClientException`) is more conservative by default.

## Key Differences

### Where taxonomies converge

Despite different implementation choices, several patterns appear in nearly every mature source:

1. **Source classification by subsystem origin**, not HTTP code. Even langfuse's HTTP-shaped `BaseError` is overridden by source-classified domain classes for the cases that matter (`ClickHouseResourceError`, `LLMCompletionError`, `EvaluatorBlockReason`). Only `reports` (empty) and openhands (frontend substring matching) genuinely lack source classification.
2. **Per-provider normalization as an adapter concern** (P1) — every multi-provider source has one.
3. **Cause-chain propagation** as a classification mechanism (P2).
4. **Errors-as-data payloads** attached to exceptions (P3).
5. **Control-flow exceptions as first-class types** in Python (P6) — pydantic-ai, agent-framework, langgraph all reuse the exception channel for non-failure signals.
6. **Stream/SSE/HTTP error type identification** — letta, langfuse, agent-framework, pydantic-ai all convert typed exceptions into wire-format error types at the boundary.

### Where taxonomies diverge and why

**Structural (class hierarchy) vs. federated (per-subsystem)**: agent-framework Python and pydantic-ai centralize; crewai and openhands federate. The choice is product-shape driven: frameworks with a single Python module (pydantic-ai) or a tightly-coupled monorepo (agent-framework) can centralize; multi-language libraries (agent-framework .NET, openhands OSS + Enterprise + Slack) must federate. The price of centralization is per-subpackage duplication (agent-framework Purview `_exceptions.py`); the price of federation is cross-subsystem questions being unanswerable (crewai empty `__init__.py`).

**Source-based vs. role-based classification**: langgraph classifies by runtime role (control vs node vs validation). Every other source classifies by source. langgraph's choice is honest — its taxonomy is engineered around control-flow vs. fatal-vs-handler-routing — but means model/provider/tool errors surface as third-party exception types, and source classification happens only via the third-party `default_retry_on` allowlist. This is a deliberate scoping decision: langgraph doesn't want to be in the business of classifying OpenAI/Anthropic errors.

**Retry on the type vs. retry at the catch site**: letta and openai-agents-sdk sandbox put `retryable` on the type. agent-framework, langgraph, opa, crewai keep retryability in dispatch functions and prose. The first is more discoverable; the second is more flexible. The agent-framework position is documented but unenforced — there is no `Retryable` flag — so retry decisions scatter across `chatkit/_converter.py:165-388`, `bedrock/_chat_client.py:244-371`, etc.

**String codes vs. typed errors**: opa and (partially) langfuse use string codes for wire-friendliness and additive extensibility. temporal uses typed errors with proto details for lossless round-tripping. agent-framework, pydantic-ai, letta, openai-agents-sdk use class hierarchies for `isinstance` ergonomics. There is no clear winner — string codes are easier to add but typos compile fine (OPA's WASM SDK panics on unknown codes to compensate); typed errors are richer but cost per-error boilerplate.

**Centralized vs. distributed taxonomy documentation**: agent-framework centralizes in `CODING_STANDARD.md`; opa centralizes in `docs/docs/errors/index.md`; langfuse fragments across AGENTS.md, the backend skill, the Fern contract, and inline comments; crewai, openhands, langgraph have no taxonomy reference document. Centralized documentation reduces drift but ages faster; distributed documentation is more current but harder to discover.

**BYOK / multi-tenancy attribution**: letta threads `is_byok` through every mapper (`letta/errors.py:55`; `letta/llm_api/openai_client.py:1240-1242`) so HTTP/SSE responses attribute billing responsibility. langfuse carries project/tenant context via the resolution path in `getEvaluatorBlockResolutionPath` (`packages/shared/src/features/evals/evalConfigBlocking.ts:101-120`). agent-framework, pydantic-ai, and crewai do not have multi-tenant attribution on the type. This is the dimension's most product-shape-dependent axis: BYOK hosting platforms need it; library code does not.

**Why the divergence is not "quality"**: langgraph's role-based taxonomy is appropriate for a graph execution engine where the dispatch protocol is control-vs-fatal, not source-vs-source. agent-framework's no-central-taxonomy on .NET is consistent with .NET culture (BCL exceptions). opa's string codes are consistent with the wire protocol. The differences trace back to product shape, language conventions, and library-vs-application status.

## Tradeoffs

### T1. Centralized hierarchy vs. federated per-subsystem

- **Benefit (centralized)**: one import point; cross-subsystem questions answerable; tests can assert the full surface (agent-framework `python/packages/core/tests/core/test_exceptions.py:1-27`; openai-agents-sdk `tests/test_exception_exports.py:16`).
- **Cost (centralized)**: per-subpackage must import from core; risk of layering inversion (agent-framework `MiddlewareTermination` lives in `_middleware.py:72` to avoid exceptions.py depending on middleware).
- **Best-fit**: single-language library with a tightly-coupled monorepo (pydantic-ai, openai-agents-sdk core, agent-framework Python).
- **Failure mode**: tightly-coupled hierarchy turns into a "everything extends Exception" soup without discipline.
- **Alternative seen**: federated with one-stop-shop aggregator (crewai `utilities/exceptions/__init__.py` is empty — the aggregator exists but was never populated).

### T2. Retryable on the type vs. at the catch site

- **Benefit (on type)**: callers don't have to maintain per-type knowledge; telemetry can label by class (`error_type="LLMCompletionError"`).
- **Cost (on type)**: requires discipline at construction; if the type is wrong, the dispatcher is wrong.
- **Best-fit**: open public APIs where consumers cannot enumerate every retry policy; multi-tenant systems where retry decisions vary per caller.
- **Failure mode**: hard-coded `isRetryable` defaults (langfuse defaults to false; certain LLM providers may treat 503 as terminal but the decision is made once in `fetchLLMCompletion`).
- **Alternative seen**: per-catch tuples (letta `_RETRYABLE_ERRORS`); provider-aware classifier (`pydantic-ai`'s `get_openai_retry_advice` honors `x-should-retry` header).

### T3. Two-track HTTP+source vs. single source-only taxonomy

- **Benefit (two-track)**: stable wire identifier (HTTP code, API `code`) AND rich source attribution; intermediates (letta HTTP 504 for LLM timeout, langfuse `code: "rate_limited"` with `details: { retryAfterSeconds }`) are richer than either alone.
- **Cost (two-track)**: requires convergent dispatch (langfuse's `toUnstablePublicApiError` is 100 lines of `instanceof` switch); risk of mismatch (langfuse generic `BaseError` with `httpCode = 401` becomes `"invalid_request"` because the dedicated `UnauthorizedError` branch is what produces `"authentication_failed"` — `unstable-public-api-error-contract.ts:249-255`).
- **Best-fit**: systems with both internal classes and external APIs (langfuse, letta).
- **Failure mode**: when the two tracks diverge (langfuse `BaseError` HTTP 422 → `unprocessable_content` only when cause is `ClickHouseResourceError`; otherwise the generic base-error fallback misclassifies).
- **Alternative seen**: pure source-only (pydantic-ai); pure HTTP-only would be uninformative.

### T4. Type-configurable fallback vs. closed handler registry

- **Benefit (type-configurable)**: extensible without library changes; user can fall back on `UserError` or any third-party class.
- **Cost (type-configurable)**: nothing forces the policy to be exhaustive; an empty `fallback_on` triggers `UserError` (pydantic-ai `models/fallback.py:143-148`).
- **Best-fit**: libraries used by external developers; multi-provider setups.
- **Failure mode**: silent misconfiguration (agent-framework `_handle_request_error` exists for OpenAI but not Anthropic/Bedrock — `chat_client.py:598-611` is the only dispatch site for that class; the others use a mix).
- **Alternative seen**: closed handler registry (`openai-agents-sdk` `RunErrorHandlers` is a `TypedDict` with exactly two keys — `max_turns` and `model_refusal`).

### T5. String codes vs. typed errors

- **Benefit (string codes)**: wire-friendly; additive; no import cycles.
- **Cost (string codes)**: typos compile fine; OPA WASM SDK has to `panic` on unknown codes to compensate (`internal/wasm/sdk/opa/errors/errors.go:39-46`); cross-package handling requires per-layer type switches (`ErrorAuto`).
- **Best-fit**: systems with wire-format stability as a primary concern (opa REST API, langfuse public API `code` enum).
- **Failure mode**: write-conflict HTTP 404 (opa `writer.go:31-32`) — the HTTP code doesn't match the conceptual conflict condition.
- **Alternative seen**: typed errors with proto wire details (temporal `common/serviceerror/shard_ownership_lost.go:35-48`).

### T6. Control-flow exceptions vs. separate signal channel

- **Benefit**: hook composition via `raise to divert` (pydantic-ai `on_model_request_error` accepts any Exception and lets the hook return a response or raise — `capabilities/abstract.py:596-617`).
- **Cost**: user `try/except Exception` can intercept signals accidentally.
- **Best-fit**: library code where the framework controls the hook surface.
- **Failure mode**: user code that catches `Exception` around `agent.run()` may swallow `CallDeferred` (pydantic-ai `docs/logfire.md:333` notes spans deliberately don't mark them ERROR).
- **Alternative seen**: status enums for long-running infrastructure (openhands `SandboxStatus` enum — `app_server/sandbox/sandbox_models.py:9-14`).

## Decision Guide

When designing an error taxonomy from scratch, choose by product shape and library status:

**Library code, single Python module → Pydantic-AI / OpenAI-Agents-SDK shape**: single canonical `exceptions.py`; class hierarchy with source families; type-configurable fallback routing; control-flow exceptions as first-class; pickle/serialization tested.

**Library code, single Node/TS module → Langfuse shape**: HTTP-aligned `BaseError` root + per-source domain classes + `isRetryable` flag; `instanceof`-based dispatch at boundaries; `name`-based type guards are acceptable but watch for subclassing.

**Server with multi-language stack → Federated shape (CrewAI/OpenHands)** with one well-designed subsystem as the exemplar (OpenHands Slack). Do not attempt to unify; do not duplicate names; document the per-subsystem vocabularies.

**Domain-rich policy/infra engine → OPA shape**: per-layer struct with prefixed string codes; coarse API codes at boundary; `errors.As`/`Is` semantics tested; `Halt` for stop.

**Durable execution engine → Temporal shape**: typed errors with proto wire details; cause/scope enums for resource exhaustion; classifier predicates (`isUserError`, `isInvalidTaskError`) compose into one decision function; metrics tagged by cause.

**BYOK / multi-tenant hosting → Letta shape**: single central `errors.py`; `ErrorCode` enum shared by every exception; abstract provider mapping method; BYOK flag threaded through every mapper; regression tests pin mappings.

## Practical Tips

1. **Make the type the answer to the guiding question.** If a caller cannot tell from `type(e).__name__` whether to retry, escalate, or stop, your taxonomy is incomplete. Add `retryable`, `is_retryable`, or a typed predicate (`fallback_on`).
2. **Move provider-specific exceptions behind an adapter.** Every multi-provider source has one; do not skip it.
3. **Use `__cause__` chains, not message strings, for fidelity.** Walk `.cause` to recover the underlying error; do not regex on the message unless you have to.
4. **Encode control flow as exceptions deliberately.** If you do, document which classes are control flow (pydantic-ai `capabilities/instrumentation.py:358-361` excludes deferrals from ERROR spans).
5. **Centralize the taxonomy in one module when feasible** (`pydantic_ai_slim/pydantic_ai/exceptions.py`, `letta/errors.py`, `agent-framework/.../exceptions.py`). Federate only when the codebase is multi-language or has hard layering constraints.
6. **Test the public surface.** `tests/test_exception_exports.py:16` in openai-agents-sdk asserts every leaf is re-exported; agent-framework `python/packages/core/tests/core/test_exceptions.py:1-27` covers the base class. Add a test that catches every leaf at the package root.
7. **Document with an ASCII tree + When-to-use table** (agent-framework `python/CODING_STANDARD.md:227-291`). Docstrings alone drift; a diagram + table is harder to miss.
8. **Make string-code dispatch tolerant of unknown codes.** OPA `ErrorAuto` defaults to 500 (`writer.go:39-40`); WASM SDK panics (`opa/errors.go:39-46`). Choose one but be explicit.
9. **Use a discriminator table for message-pattern fallback** (langfuse `ERROR_TYPE_CONFIG`, letta `error_utils.py`). The table is the single place to add new phrases.
10. **Surface error type to telemetry.** OpenTelemetry `error.type = type(exception).__name__` is the cheapest operational classifier you can add.
11. **Pin provider mappings with regression tests** (letta `tests/adapters/test_letta_llm_stream_adapter_error_handling.py:179-363`). Provider wording changes break this layer first; tests catch it.
12. **Carry structured context on the exception** (`NodeError`, `RunErrorDetails`, `details["is_byok"]`). Do not rely on log correlation alone.

## Anti-Patterns / Caution Signs

1. **String/substring matching for provider classification as the primary mechanism.** crewai `context_window_exceeding_exception.py:4-13` (8 hardcoded phrases), openhands `frontend/src/utils/error-handler.ts:40-55` (regex over provider text). Vendor wording changes silently misclassify.
2. **Module-prefix tests as retry policy.** crewai `e.__class__.__module__.startswith("litellm")` (`crew_agent_executor.py:445`) ties behavior to library packaging; swapping the LLM stack changes retry semantics invisibly.
3. **Two unrelated classes with the same name.** openhands `AuthError` in both `errors.py:18` and `auth_error.py:1`; crewai's three `StartingConvoException` definitions (`slack_types.py:136`, `jira_types.py:53`, `jira_dc_dc_types.py:37`). The wrong-import bug is a realistic breakage mode.
4. **Classifier-return convention that requires caller to `raise`.** openhands `handle_http_status_error` returns an instance; callers must explicitly raise (`github/service/base.py:92-95`). Forgetting `raise` silently drops errors.
5. **`name`-based type guards that don't survive subclassing.** langfuse `isLLMCompletionError` checks `e.name === "LLMCompletionError"` (`packages/shared/src/server/llm/errors.ts:65-67`); a subclass of `LLMCompletionError` is not detected. Switch to `instanceof` if subclassing is anticipated.
6. **Vestigial fields that nothing reads.** langfuse `BaseError.isOperational` is set on every constructor (`BaseError.ts:17`) but never read by any dispatch site. Remove or wire in.
7. **Vestigial classifiers via parameter.** crewai `_passthrough_exceptions` taxonomy is always empty in-repo (`agent/core.py:133`); the intended extension mechanism is unused. Either populate it or remove it.
8. **Default-to-stop masking transient/unrecognized states.** openhands `docker_sandbox_service.py:125-127` maps any unrecognized Docker status to `SandboxStatus.ERROR`, triggering the hard 503 stop path. Be conservative with the unknown bucket.
9. **Documentation that omits subclasses.** openai-agents-sdk `docs/running_agents.md:553-564` does not list `ModelRefusalError`, `MCPToolCancellationError`, or tool-guardrail tripwires. The handler-keyed registry can't help if users don't know what exceptions exist.
10. **No exception-handler tests.** Several sources (letta `app.py:556-779` has 51 FastAPI handlers but no test for status-code-per-class assertions) ship handlers without regression tests. Pin at least the canonical mappings.
11. **Empty aggregator at the top of the taxonomy package.** crewai `utilities/exceptions/__init__.py:1` invites inconsistent import paths. If you can't centralize, at least re-export what you have.
12. **Default-retry permissiveness on unknown types.** langgraph `default_retry_on` retries anything not denylisted (`libs/langgraph/langgraph/_internal/_retry.py:1-29`). New third-party providers silently retry 4xx errors unless users opt in.
13. **Failure modes buried in prose only.** agent-framework's `inner_exception` loss was a real bug fixed by PR #5167 (`CHANGELOG.md:251`); a test now guards the contract (`test_exceptions.py:8-13`). Without the test, the regression would have come back.
14. **Taxonomy bypassed by bare `Error` throws.** langfuse dozens of sites throw bare `new Error(...)` (`worker/src/scripts/verifyClickhouseRecords/index.ts:300-948`); opa decision-log mask rule failures use bare `fmt.Errorf` (`v1/plugins/logs/mask.go:69,110,161`). A lint rule that flags bare throws outside test/seed/CLI code would push all runtime errors through the taxonomy.
15. **Manual-sync contracts between duplicate converters.** temporal has two `convertError` implementations (`service/history/handler.go:2233`, `service/history/chasm_engine.go:1261`) with a "Keep in sync" comment. A new persistence error handled in one but not the other passes through unconverted.

## Notable Absences

- **`reports`**: empty corpus; no taxonomy to analyze. Indicates a harness population gap, not an artifact judgment.
- **pydantic-ai timeout category**: tool timeouts collapse into `ModelRetry` (`toolsets/function.py:655-656`); programmatic handling cannot distinguish "tool timed out" from "model asked to correct args" without string-matching the message.
- **letta legacy uncoded exceptions**: `LLMJSONParsingError`, `LocalLLMError`, `LocalLLMConnectionError`, `BedrockError` construct `LettaError` without a code (`letta/errors.py:331-349`), so `__str__` degrades and clients cannot branch on category.
- **agent-framework .NET**: no central taxonomy; sub-packages define their own; the main `Microsoft.Agents.AI` package uses built-in BCL exceptions throughout (`ChatClient/ChatClientAgent.cs:454,717,729,735,742,816,838,997,1008,1100,1110,1120`).
- **langgraph policy/context/user source categories**: no class names a model, provider, tool, policy, context, or user failure; those surface as third-party exceptions.
- **langfuse `isOperational`**: set on every constructor (`BaseError.ts:17`) but no dispatch site reads it.
- **crewai `user` source category**: not present; user-caused problems surface as validation errors or generic `ValueError`s.
- **openai-agents-sdk core retry metadata**: core `AgentsException` classes carry no `retryable`/`escalate` hint; the capability exists only in the sandbox and retry-policy subsystems.
- **opa retry classifier**: retry decisions are count-based or schedule-based, not code-based (`v1/plugins/bundle/plugin.go:408`); the taxonomy cannot express "do not retry."
- **temporal automated round-trip coverage**: `TestFromToStatus` only exercises `ShardOwnershipLost` (`common/serviceerror/convert_test.go:11-26`); no test asserts every typed server error round-trips.
- **openhands `LLMAuthenticationError` raise site**: caught in seven managers but never raised inside the repo (lives in the external `software-agent-sdk`).
