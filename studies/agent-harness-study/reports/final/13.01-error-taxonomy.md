## Executive Summary

Across ten sources, error taxonomy maturity ranges from **5/10 (crewai, ad-hoc multi-base)** to **8/10 (letta, openai-agents-sdk, source-classified single root)**. Three patterns converge regardless of language or product shape:

1. **Provider-translation is the universal seam.** Every source that talks to LLMs (agent-framework, letta, pydantic-ai, openai-agents-sdk, crewai) wraps native SDK exceptions into a *framework-owned* taxonomy. The per-provider `handle_llm_error`/`_map_api_errors` pattern is the load-bearing piece: it normalizes OpenAI/Anthropic/Vertex differences into a small set of leaves that downstream code can dispatch on.
2. **Dispatch happens at a handful of well-known sites**, not everywhere. FastAPI exception handlers (`letta/server/rest_api/app.py:557-794`), tRPC/REST middlewares (`langfuse/web/src/server/api/trpc.ts:175-215`), agent-loop except-chains (`pydantic-ai/_agent_graph.py:823-829`), gRPC interceptors (`temporal/common/rpc/interceptor/frontend_service_error.go:40-58`), and worker queue processors (`langfuse/worker/src/queues/evalQueue.ts:178-269`) all behave the same way: classify once at a choke point, route from there.
3. **The leading question "can I tell retry/escalate/stop from the type?" is partially answered everywhere.** Source categories exist (model/provider/tool/validation/policy/context/user/infrastructure/timeout), but operational semantics are *usually not encoded on the class*. Only `letta.LLMError`, `langfuse.LLMCompletionError.isRetryable`, and `openai-agents-sdk.SandboxError.retryable` carry a built-in retry bit; everything else relies on dispatch-site knowledge.

**Where sources diverge:**
- **Single L0 root vs. per-subsystem roots.** Python agent frameworks tend toward a single `AgentsException`/`AgentFrameworkException`/`LettaError` root with parallel L1 branches by subsystem; Go services and ad-hoc Python codebases prefer per-subsystem `Error` structs with closed-code enums (opa, temporal) or just no shared root (crewai, openhands).
- **Class hierarchy vs. enum+code.** Langfuse's `SlackErrorCode` (IntEnum) + `SlackError(enum)` and CrewAI's `A2AErrorCode(IntEnum)` + 22 dataclass subclasses show that *one exception + a code enum* can carry richer classification than a wide class hierarchy — at the cost of `except` ladders.
- **Role-based vs. source-based dispatch.** LangGraph explicitly classifies by *runtime role* (control-flow / node / validation / infrastructure), not by source. This is the right answer for a workflow engine that needs to route interrupts vs. failures vs. validation errors, but it does not address the dimension's source-category checklist.
- **Operational semantics live in different layers.** Langfuse encodes retry on the type (`LLMCompletionError.isRetryable`); OpenAI Agents SDK defers it to a separate `RetryPolicy` that classifies normalized provider facts; Pydantic-AI uses capability hooks (`on_*_error`) as the recovery point; Letta uses `StopReasonType` as a durable persisted record. Same need, four solutions.

## Core Thesis

**A source-classified taxonomy is most useful when three conditions co-exist:** (1) a single L0 root or per-subsystem roots with parallel L1 branches by *subsystem of origin*, (2) dispatch at a small number of well-defined choke points (HTTP boundary, agent loop, queue processor), and (3) per-provider mappers that translate native exceptions into the framework's vocabulary at one well-known boundary. Sources that satisfy all three (letta, openai-agents-sdk, pydantic-ai, langfuse) score 7–8/10. Sources that satisfy only one or two (crewai at 5/10, openhands at 6/10) leave callers writing `except Exception` ladders that throw away the classification. Sources that classify by *runtime role* (langgraph at 6/10) answer a different question than the dimension asks and benefit workflow engines more than agentic pipelines.

## Approach Models

The ten sources cluster into six approach models for error taxonomy. Each is a valid response to a different product shape.

### Cluster A: Single-rooted source-classified hierarchy

**Sources:** agent-framework, openai-agents-sdk, letta, pydantic-ai.

**Shape:** One L0 exception class (`AgentFrameworkException`, `AgentsException`, `LettaError`, `UserError`-rooted + `AgentRunError`) with L1 leaves classified by *subsystem of origin* (model, tool, validation, policy, user/developer). Each leaf carries a structured payload (`OpenAIContentFilterException.param + content_filter_code`, `ModelRefusalError.refusal`, `ToolTimeoutError.tool_name + timeout_seconds`, `LLMError` subclasses with provider-agnostic payloads).

**Why it works:** Polymorphic `except BaseException` matches everything; granular `except ModelBehaviorError` matches the right slice. New leaves auto-fit via inheritance.

**Why it falls short:** A *central* L0 means every leaf must be exported and discoverable; missed re-exports break downstream (`tests/test_exception_exports.py:16-30` in openai-agents-sdk is the explicit guard). Source classification by class name does *not* answer "retry or stop?" — that knowledge is implicit in dispatch sites or in a sibling `RetryPolicy` (openai-agents-sdk), `LLMCompletionError.isRetryable` (langfuse), `LLMError` fallbacks (letta).

### Cluster B: Local / parallel taxonomies

**Sources:** crewai, openhands.

**Shape:** No central root. Each domain defines its own exception type extending `Exception`, `ValueError`, `RuntimeError`, `ImportError`, or `HTTPException` independently. CrewAI's `crewai/utilities/errors.py` and `crewai/utilities/exceptions/__init__.py` (empty docstring) are local; OpenHands has 79+ classes across 5+ base types.

**Why it works:** Locality of reasoning — the exception lives next to the code that raises it. Domains can evolve independently. CrewAI's A2A module demonstrates that a *single domain* can still have a rigorous `A2AErrorCode(IntEnum)` + 22 dataclass subclasses + routing helpers, even without a global root.

**Why it falls short:** Callers cannot `except BaseFrameworkError`; they must `except OutputParserError` AND `except LLMContextLengthExceededError` AND `except DatabaseOperationError` separately. Cross-domain routing is impossible without manual knowledge of every module. CrewAI's `is_retryable_error`/`is_client_error` exist in the A2A module but are never referenced (`lib/crewai/src/crewai/a2a/errors.py:464-503` — dead code).

### Cluster C: HTTP-shaped + source-typed hybrid

**Source:** langfuse.

**Shape:** Two tracks running in parallel — a flat HTTP-aligned `BaseError` family (`packages/shared/src/errors/`) with 12 subclasses keyed by HTTP code (`InvalidRequestError` 400, `UnauthorizedError` 401, `LangfuseNotFoundError` 404, `InternalServerError` 500, etc.), plus per-source domain classes (`ClickHouseResourceError` with `MEMORY_LIMIT | OVERCOMMIT | TIMEOUT`, `LLMCompletionError` with `responseStatusCode + isRetryable + blockReason`, `SlackApiError` with `slackErrorCode`, `UnrecoverableError`, `ObservationNotFoundError`, MCP `UserInputError`/`ApiServerError`).

**Why it works:** The HTTP subclass tree is uniform across `web` (tRPC + REST + MCP), `worker` (BullMQ), and SDK code. The domain classes carry *structured metadata* the HTTP tree cannot (`LLMCompletionError.isRetryable` is the load-bearing field for queue retry decisions). `EvaluatorBlockReason` Prisma enum is the cleanest source-classified taxonomy in the study.

**Why it falls short:** `BaseError.isOperational` is vestigial (set on construction but never read). The HTTP layer is *not* a source taxonomy — `BaseError` does not directly map to model/provider/tool/validation/policy/context/user/infrastructure/timeout. The two-track enforcement is informal: many sites still throw bare `new Error(...)` and bypass every dispatch (`worker/src/queues/monitorQueue.ts:24`, `packages/shared/src/encryption/encryption.ts:20-42`).

### Cluster D: Closed-code per-subsystem with predicate matching

**Source:** opa.

**Shape:** Each subsystem declares its own typed `Error` struct with a closed `Code` constant set (`v1/ast/errors.go:48-66`, `v1/topdown/errors.go:35-60`, `v1/storage/errors.go:11-42`, `internal/wasm/sdk/opa/errors/errors.go:12-30`). The WASM ABI enforces a closed code set by panicking on unknown codes (`internal/wasm/sdk/opa/errors/errors.go:39-46`). Empty-wildcard `Is(target error) bool` lets `errors.Is(err, &topdown.Error{Code: topdown.BuiltinErr})` match any error with that code.

**Why it works:** Go's `errors.Is`/`errors.As` is the *lingua franca*; adding a new `Code` constant is non-breaking because callers use `errors.Is` not `==`. The HTTP envelope (`v1/server/types/types.go:118-128`) is decoupled from internal codes — the writer (`v1/server/writer/writer.go:27-42`) translates between them via a switch. The closed WASM ABI prevents downstream embedders from silently emitting codes the host cannot handle.

**Why it falls short:** No central `opa.Error` interface. A function returning any OPA error has to enumerate `*ast.Error`, `*topdown.Error`, `*storage.Error`, `*sdk.Error`, etc. Aggregators (`v1/loader/errors.go:14-39`, `v1/rego/rego.go:592-619`) lack `IsCode(code string) bool` predicates, so callers flatten. The writer's `switch` falls through to `default → 500 internal_error`, silently mis-classifying any new typed error.

### Cluster E: Wire-code + proto detail (gRPC-shaped)

**Source:** temporal.

**Shape:** Two layers — RPC errors (`common/serviceerror/*.go`) and workflow-history failures (`common/failure/failure.go:1-91`). Each server-specific error has a proto detail message (`proto/internal/temporal/server/api/errordetails/v1/message.proto:12-61`) and pins a specific gRPC code (`codes.Aborted` for persistence failures, `codes.FailedPrecondition` for obsolete tasks, `codes.Unavailable` for sticky-worker / shard-lost). Single rehydration switch `common/serviceerror/convert.go:18-54` keys on (gRPC code, detail type). The workflow-history layer has its own source-tag: `failureSourceServer = "Server"` (`common/failure/failure.go:11`).

**Why it works:** The wire contract is explicit and stable; proto detail messages carry structured payloads (branch tokens, owner host, partition counts) that cross process boundaries. `errors.AsType[*serviceerrors.ShardOwnershipLost]` is the codebase idiom (`.github/copilot-instructions.md:30, 56`). The single rehydration switch is auditable. DI wires `IsServiceClientTransientError` as the central classifier (`common/resource/fx.go:286-302`).

**Why it falls short:** Hand-maintained switch + hand-maintained retry predicates — adding a new error without updating both silently misclassifies. No central `ErrorKind` enum to map to source categories. Documentation is one paragraph (`docs/architecture/retry.md:14-33`). Most error types have no dedicated unit test beyond `ShardOwnershipLost` round-trip.

### Cluster F: Role-based dispatch (workflow engines)

**Source:** langgraph.

**Shape:** Single-file registry (`libs/langgraph/langgraph/errors.py:1-241`) classified by *runtime role* — control-flow (`GraphBubbleUp` superclass for `GraphInterrupt`, `GraphDrained`, `ParentCommand`), node-attributable (`NodeError` dataclass, `NodeCancelledError`, `NodeTimeoutError`), validation/infrastructure (`InvalidUpdateError`, `EmptyInputError`, `EmptyChannelError`, `TaskNotFound`), resource exhaustion (`GraphRecursionError`). `ErrorCode` enum brands the message with a docs URL. `NodeError` is a frozen dataclass, not an exception — injected via `CONFIG_KEY_NODE_ERROR` into per-node handlers.

**Why it works:** Inheritance-based dispatch is unambiguous (`isinstance(exc, GraphBubbleUp)` at every choke point). The role split mirrors what a workflow engine actually needs: control-flow vs. fatal vs. handler-routable. `NodeTimeoutError(Exception)` deliberately does *not* inherit from `TimeoutError(OSError)` so the default retry policy treats it as retryable (`libs/langgraph/langgraph/_internal/_retry.py:1-29`).

**Why it falls short:** No model/provider/tool/policy/context leaf exists. The taxonomy answers "should the runner panic, route to a handler, or collect interrupts?" — not the dimension's "model/provider/tool/validation/policy/context/user/infrastructure/timeout" question. Remote errors are flat (`libs/langgraph/langgraph/pregel/remote.py:112-115` — `RemoteException(Exception): pass`). Documentation is docstrings + URL fragments only; no in-repo taxonomy reference.

## Pattern Catalog

### Pattern 1: Provider-translation via per-provider mappers

**Problem:** Native LLM SDKs (OpenAI, Anthropic, Vertex, Bedrock) raise different exception classes with overlapping semantics. A caller cannot `except openai.RateLimitError` and `except anthropic.RateLimitError` together.

**Solution:** Define a *framework-owned* LLMError hierarchy. Each provider client implements `handle_llm_error(e, llm_config)` that translates native exceptions into the unified set.

**Demonstrated by:**
- **letta** — `LLMClientBase.handle_llm_error(e, llm_config)` is `@abstractmethod` (`letta/llm_api/llm_client_base.py:368-397`); each provider client (`openai_client.py:1216-1427`, `anthropic_client.py:965-1153`, `chatgpt_oauth_client.py:411-448`, `google_vertex_client.py:895-1122`) maps HTTP status codes + SDK exception names to the ~12-class `LLMError` taxonomy.
- **agent-framework** — `OpenAIChatClient._handle_request_error` switches on `BadRequestError` code → `OpenAIContentFilterException` vs generic `ChatClientException` (`python/packages/openai/agent_framework_openai/_chat_client.py:598-611`).
- **pydantic-ai** — Per-provider `_map_api_errors(model_name)` context managers (`models/openai.py:184`, `models/anthropic.py:245`, plus 7 sibling providers) translate `httpx.HTTPStatusError` → `ModelHTTPError(status_code, model_name, body)` vs other → `ModelAPIError`.
- **openai-agents-sdk** — Provider-specific responses normalize via `ModelRetryNormalizedError` facts (`status_code`, `is_network_error`, `is_timeout`) consumed by `RetryPolicy`.

**Why it works:** Translation happens *once* at the SDK boundary; downstream code sees only the framework's vocabulary.

**When to copy:** Whenever the framework talks to more than one LLM provider, or to any third-party service with its own exception hierarchy.

**When overkill:** For a single-provider wrapper with no abstraction needs.

**Evidence:** `letta/llm_api/openai_client.py:1216-1427`, `letta/llm_api/anthropic_client.py:965-1153`, `python/packages/openai/agent_framework_openai/_chat_client.py:598-611`, `pydantic_ai_slim/pydantic_ai/models/openai.py:184`.

### Pattern 2: Dispatch at choke points, not everywhere

**Problem:** `try/except` scattered everywhere produces inconsistent handling and makes the taxonomy fragile.

**Solution:** Funnel all errors through a small number of dispatch sites — HTTP boundary, agent loop, queue processor, gRPC interceptor.

**Demonstrated by:**
- **letta** — `~30` FastAPI exception handlers in `letta/server/rest_api/app.py:557-794` keyed by exception class, each returning a typed HTTP status + JSON body.
- **langfuse** — Three middlewares (`trpc.ts:175-215`, `withMiddlewares.ts:82-200`, `formatErrorForUser` in `web/src/features/mcp/core/error-formatting.ts:27-104`) handle every throw in their respective domains.
- **temporal** — Single rehydration switch (`common/serviceerror/convert.go:18-54`) + gRPC interceptors (`frontend_service_error.go:40-58`, `mask_internal_error.go:67-112`, `dc_redirection_policy.go:177-183`) + per-service retryable clients (`client/admin/retryable_client.go:20`, etc.).
- **agent-framework** — Five concrete dispatch sites: `OpenAIChatClient._handle_request_error`, the function-calling loop in `_tools.py:1554-1645`, the middleware pipeline via `contextlib.suppress(MiddlewareTermination)`, the foundry hosting Responses handler, and the `WorkflowInterrupted(BaseException)` escape.
- **pydantic-ai** — Three dispatch sites: `_agent_graph.py:617, 700-743, 823-829`, `tool_manager.py:330-350`, `_output.py:107-226`.

**Why it works:** Callers write `raise XError(...)` and trust the choke point to classify. The taxonomy is enforced in a small number of files.

**When to copy:** Always. This is the single most useful pattern in the study.

**When overkill:** For tiny frameworks where the choke point would be the only place.

**Evidence:** `letta/server/rest_api/app.py:557-794`, `web/src/server/api/trpc.ts:175-215`, `web/src/features/public-api/server/withMiddlewares.ts:82-200`, `common/serviceerror/convert.go:18-54`, `python/packages/openai/agent_framework_openai/_chat_client.py:598-611`.

### Pattern 3: Source-classified L1 branches under a single L0 root

**Problem:** A single flat `Error` class is too coarse to dispatch on; per-domain classes cannot be caught with `except BaseError`.

**Solution:** One L0 base class + parallel L1 branches by subsystem (model/tool/validation/policy/user) + L2 leaves only where structured data is needed.

**Demonstrated by:**
- **agent-framework** — `AgentFrameworkException` (L0) + 7 L1 (`AgentException`, `ChatClientException`, `IntegrationException`, `ContentError`, `ToolException`, `MiddlewareException`, `WorkflowException`) + parallel 4-leaf pattern (`InvalidAuth`, `InvalidRequest`, `InvalidResponse`, `ContentFilter`) shared across `Agent*`/`ChatClient*`/`Integration*`.
- **openai-agents-sdk** — `AgentsException` (L0) + 9 L1 leaves (`ModelBehaviorError`, `ModelRefusalError`, `UserError`, `MCPToolCancellationError`, `ToolTimeoutError`, four `*TripwireTriggered`) + `MaxTurnsExceeded`.
- **letta** — `LettaError` (L0) + parallel L1 (`LLMError`, `LettaMCPError`, `LettaMessageError`, `LettaToolCreateError`, `LettaConfigurationError`, `ContextWindowExceededError`, `LettaAgentNotFoundError`, `LettaServiceUnavailableError`) + `LLMError` subtree of 12 subclasses.
- **pydantic-ai** — `RuntimeError` (L0) + `UserError`, `AgentRunError` + parallel L1 (`UnexpectedModelBehavior`, `ModelAPIError`, `UsageLimitExceeded`, `ConcurrencyLimitExceeded`, `FallbackExceptionGroup`) + `Exception` for control-flow signals (`ModelRetry`, `CallDeferred`, `ApprovalRequired`, `Skip*`).

**Why it works:** `except AgentsException` catches the SDK; `except ModelBehaviorError` catches one source category. The class name *is* the source category.

**When to copy:** When the framework has 5+ distinct subsystem failure modes and needs a discoverable public contract.

**When overkill:** For libraries with one or two failure modes; for services where the wire shape (HTTP/gRPC code) is the primary contract.

**Evidence:** `python/packages/core/agent_framework/exceptions.py:15-258`, `src/agents/exceptions.py:46-174`, `letta/errors.py:11-492`, `pydantic_ai_slim/pydantic_ai/exceptions.py:19-309`.

### Pattern 4: Enum + code as the durable, versioned taxonomy

**Problem:** Class hierarchies evolve; the SDK-facing contract should be more stable than the internal one.

**Solution:** Define a closed enum (or Zod enum) of error codes that is the *contract*; the class hierarchy is implementation detail.

**Demonstrated by:**
- **crewai** — `A2AErrorCode(IntEnum)` with 22 codes (`lib/crewai/src/crewai/a2a/errors.py:25-99`) + 22 `@dataclass` subclasses with `field(init=False)` locking the code + default-message dictionary + JSON-RPC serialization helpers.
- **langfuse** — `EvaluatorBlockReason` Prisma enum (`packages/shared/prisma/schema.prisma:1037-1044`) with 6 source categories + `EVALUATOR_BLOCK_METADATA` table (`packages/shared/src/features/evals/evalConfigBlocking.ts:59-99`) mapping each to user-facing message + shortLabel + resolution path. Unstable public API uses Zod-defined `unstablePublicApiErrorCodes` (`web/src/features/public-api/shared/unstable-public-api-error-schema.ts:3-25`).
- **letta** — `ErrorCode` enum (`letta/errors.py:11-24`) with 11 wire-level codes + companion `StopReasonType` enum (`letta/schemas/letta_stop_reason.py:9-49`) for run-status classification.
- **agent-framework** — `ValidationTypeEnum` discriminator on `WorkflowValidationError` (`python/packages/core/agent_framework/_workflows/_validation.py:19-82`) so leaves carry a `validation_type` field.
- **openhands** — `SlackErrorCode` (`SLACK_ERR_001`…`SLACK_ERR_999`) carried by a single `SlackError` class with a centralized `_USER_MESSAGES` dispatch table (`enterprise/integrations/slack/slack_errors.py:18-134`).
- **openai-agents-sdk** — Sandbox `ErrorCode(str, Enum)` (`src/agents/sandbox/errors.py:12-56`) is more rigorous than the agents-side taxonomy.
- **langgraph** — `ErrorCode` enum (`libs/langgraph/langgraph/errors.py:34-40`) brands channel-update and recursion-limit errors with documentation URLs via `create_error_message`.

**Why it works:** Enums can be persisted (Postgres column), serialized (JSON), and versioned as a contract. The class hierarchy is the *implementation*; the enum is the *wire*.

**When to copy:** When the framework has a public SDK contract or persists error reasons to a database.

**When overkill:** When no persistence or SDK contract exists.

**Evidence:** `lib/crewai/src/crewai/a2a/errors.py:25-99`, `packages/shared/prisma/schema.prisma:1037-1044`, `letta/schemas/letta_stop_reason.py:9-49`, `enterprise/integrations/slack/slack_errors.py:18-134`.

### Pattern 5: Re-export tests as the public-contract enforcer

**Problem:** A new exception added to the file but forgotten in `__init__.py` breaks `from framework import NewError` for downstream users.

**Solution:** A test that walks the exception module and asserts every subclass is re-exported from the top-level package.

**Demonstrated by:**
- **openai-agents-sdk** — `test_all_public_exception_classes_are_reexported` (`tests/test_exception_exports.py:16-30`) introspects `agents.exceptions` and asserts every `AgentsException` subclass is reachable from the top-level `agents` namespace AND listed in `agents.__all__`.

**Why it works:** Adds a new leaf → test fails → reviewer fixes the re-export.

**When to copy:** Any framework with a curated public API and an `__all__` declaration.

**When overkill:** For libraries without a public API contract.

**Evidence:** `tests/test_exception_exports.py:16-30`, `src/agents/__init__.py:388-403`.

### Pattern 6: Provider mapping via central heuristics

**Problem:** Every provider client reimplements "is this a context-overflow error?" with the same regex/substring list, drifting across providers.

**Solution:** Centralize the heuristics in one module imported by every provider mapper.

**Demonstrated by:**
- **letta** — `is_context_window_overflow_message()` (6 substring patterns) + `is_insufficient_credits_message()` (7 patterns) in `letta/llm_api/error_utils.py:8-41`, used by every LLM client.
- **crewai** — `CONTEXT_LIMIT_ERRORS: Final[list[str]]` (9 phrases) in `lib/crewai/src/crewai/utilities/exceptions/context_window_exceeding_exception.py:4-13`, used by `_is_context_limit_error` and called from every provider's translation path.

**Why it works:** One source of truth for "context overflow" detection; updating the regex updates all providers simultaneously.

**When to copy:** When 2+ providers need the same disambiguation logic.

**When overkill:** For single-provider wrappers.

**Evidence:** `letta/llm_api/error_utils.py:8-41`, `lib/crewai/src/crewai/utilities/exceptions/context_window_exceeding_exception.py:4-13`.

### Pattern 7: Structured payloads on leaves (vs. string messages)

**Problem:** `str(exc)` parsing to recover the failure mode is fragile and untyped.

**Solution:** Each leaf carries typed fields (`status_code`, `error_type`, `tool_name`, `refusal`, `guardrail_result`, `slackErrorCode`).

**Demonstrated by:**
- **agent-framework** — `OpenAIContentFilterException.param: str | None` + `content_filter_code: ContentFilterCodes` enum + `content_filter_result: dict[str, ContentFilterResult]`.
- **letta** — `ContextWindowExceededError.details` + `SystemPromptTokenExceededError(system_prompt_token_estimate, context_window)` + `ConversationBusyError.lock_holder_token`.
- **langfuse** — `LLMCompletionError.responseStatusCode + isRetryable + blockReason` + `ClickHouseResourceError.errorType: ErrorType + tags` + `SlackApiError.slackErrorCode`.
- **openai-agents-sdk** — `ToolTimeoutError(tool_name, timeout_seconds)` + `ModelRefusalError(refusal)` + `*TripwireTriggered(guardrail_result)`.
- **pydantic-ai** — `ModelHTTPError(status_code, model_name, body)` + `ToolRetryError(tool_retry: RetryPromptPart)`.

**Why it works:** Callers inspect `e.status_code` not `str(e)`. Promotes observability and routing.

**When to copy:** Always for leaf classes; the cost is small.

**When overkill:** Never — even minimal leaves benefit from carrying their primary field.

**Evidence:** `python/packages/openai/agent_framework_openai/_exceptions.py:55-90`, `letta/errors.py:352-371`, `packages/shared/src/server/llm/errors.ts:12-67`, `pydantic_ai_slim/pydantic_ai/exceptions.py:250-266`.

### Pattern 8: Control-flow exceptions that escape the normal hierarchy

**Problem:** A new exception type (HITL pause, function-call cancellation, recursion interrupt) needs to bypass user `except Exception` handlers that would treat it as fatal.

**Solution:** Either inherit from `BaseException` (Python) or use a marker superclass (langgraph's `GraphBubbleUp`).

**Demonstrated by:**
- **agent-framework** — `WorkflowInterrupted(BaseException)` deliberately escapes `except Exception` (`python/packages/core/agent_framework/_workflows/_functional.py:87-93`); `MiddlewareTermination` uses `contextlib.suppress` at every pipeline boundary (`_middleware.py:911-1082`).
- **langgraph** — `GraphBubbleUp(Exception)` superclass for `GraphInterrupt`, `GraphDrained`, `ParentCommand` (`libs/langgraph/langgraph/errors.py:50-51`); `BackgroundExecutor.done` recognizes it and drops from re-raise (`_executor.py:77-88`).
- **pydantic-ai** — `ModelRetry`, `CallDeferred`, `ApprovalRequired`, `Skip*` are `Exception` subclasses used as typed data carriers, caught and re-raised within dispatchers (`_agent_graph.py:617, 823-829`).

**Why it works:** The type system encodes the dispatch key. No string tags needed.

**When to copy:** When a class needs to be a control signal, not a failure.

**When overkill:** When all leaves are real failures and there is no control-flow pattern.

**Evidence:** `python/packages/core/agent_framework/_workflows/_functional.py:87-93`, `libs/langgraph/langgraph/errors.py:50-51`, `pydantic_ai_slim/pydantic_ai/exceptions.py:40-156`.

### Pattern 9: Retry classifier as a central predicate, not per-call `isinstance`

**Problem:** Retry policy scattered across call sites with `tenacity.retry_if_exception_type(X)` at each site is unmaintainable.

**Solution:** A central classifier function (`IsServiceClientTransientError`, `IsRetryable`) injected via DI.

**Demonstrated by:**
- **langfuse** — `LLMCompletionError.isRetryable` set by the source; worker queue `evalQueue.ts:178-269` and `experimentQueue.ts:24-49` read it; `retryLLMRateLimitError` helper (`worker/src/features/utils/retry-handler.ts:49`) is the shared retry decision point.
- **temporal** — `common.IsServiceClientTransientError` (`common/util.go:311-327`) injected via DI (`common/resource/fx.go:286-302`) and consumed by both `RetryableInterceptor` and `RetryableClient`.
- **openhands** — `tenacity.retry_if_exception_type(KeycloakConnectionError)` at five call sites (`enterprise/server/auth/saas_user_auth.py:292-298`, `enterprise/server/auth/token_manager.py:170-173, 270-272, 558-560`) — explicit per-call choice, no central registry.
- **openai-agents-sdk** — `RetryPolicy` predicates (`src/agents/retry.py:231-358`) classify on normalized provider facts (`status_code`, `is_network_error`, `is_timeout`), decoupled from `AgentsException` subclass hierarchy.

**Why it works:** The retry decision lives in one place and is testable; adding a new retryable type is one edit.

**When to copy:** When the framework has a queue, worker, or retry layer that decides per-error retry.

**When overkill:** For libraries that don't own the retry layer.

**Evidence:** `worker/src/features/utils/retry-handler.ts:49`, `common/util.go:311-327`, `src/agents/retry.py:231-358`.

### Pattern 10: Hashable, picklable, comparable exceptions

**Problem:** Cross-process resume (Temporal, durable exec) needs exceptions to round-trip serialization; test assertions want stable equality.

**Solution:** Override `__hash__`, `__eq__`, `__reduce__` on every exception class.

**Demonstrated by:**
- **pydantic-ai** — Every named exception overrides `__hash__` and `__eq__` (`pydantic_ai_slim/pydantic_ai/exceptions.py:55-59, 58-59`); `__reduce__` for pickling on classes with non-trivial state (`exceptions.py:94-95, 112-113, 222-223, 246-247, 265-266, 285-286`). Tests: `test_exceptions_hashable`, `test_exceptions_pickle_round_trip` (`tests/test_exceptions.py:58-71, 118-141`).
- **temporal** — `RetryReplication.Equal` (`common/serviceerror/retry_replication.go:72-80`) and `SyncState.Equal` (`common/serviceerror/sync_state.go:73-80`) provide deep field equality for idempotency checks.

**Why it works:** Pickling enables durable-exec and cross-process resume; equality enables idempotency assertions in retry loops.

**When to copy:** When the framework integrates with Temporal, durable execution, or cross-process resume.

**When overkill:** For stateless libraries without serialization needs.

**Evidence:** `pydantic_ai_slim/pydantic_ai/exceptions.py:55-59, 94-95`, `tests/test_exceptions.py:58-141`.

## Key Differences

1. **Single-root (letta, openai-agents-sdk, agent-framework, pydantic-ai) vs per-subsystem (opa, temporal) vs local (crewai, openhands).** The single-root model wins on discoverability and `except BaseError` catchability; the per-subsystem model wins on package independence and ABI stability (opa's closed WASM code set); the local model wins on locality but loses on cross-domain routing.
2. **Class hierarchy (letta, openai-agents-sdk, agent-framework) vs enum+code (langfuse, crewai A2A, opa, temporal).** Class hierarchies are polymorphic and `except`-friendly; enums are durable, wire-stable, and DB-friendly. The hybrid (letta's `ErrorCode` + `LettaError`; langfuse's `EvaluatorBlockReason` + `BaseError`) is the most defensible answer for a framework with both internal and external surfaces.
3. **Source classification (letta, agent-framework, openai-agents-sdk, pydantic-ai) vs role classification (langgraph).** Source classification answers "what subsystem failed?"; role classification answers "should I panic, route to a handler, or collect interrupts?". They are *complementary*, not substitutes — and langgraph explicitly does not address source categories because its domain is workflow control.
4. **Operational semantics on the type (langfuse `LLMCompletionError.isRetryable`, openai-agents-sdk `SandboxError.retryable`) vs in a sibling layer (openai-agents-sdk `RetryPolicy`, pydantic-ai `on_*_error` hooks, langfuse `EvaluatorBlockReason` + retry queue dispatch, letta `StopReasonType` run-status).** Putting the bit on the type is *answerable* from the exception; deferring to a sibling layer is *flexible* but requires the caller to know the layer exists.
5. **Per-call `isinstance` dispatch (crewai agent loop's three-branch dispatch, agent-framework `_tools.py:1554-1645`, pydantic-ai tool manager) vs central choke-point dispatch (langfuse tRPC/REST middlewares, letta FastAPI handlers, temporal gRPC interceptors).** Per-call dispatch is fine when the call site is the right choke (agent loop, queue processor). Central dispatch is correct at HTTP/gRPC boundaries. The pattern is "right choke for the right error class" — not one-vs-the-other.
6. **Documented in a coding standard / docs page (agent-framework `python/CODING_STANDARD.md:205-302`, letta per-class docstrings + `tests/adapters/test_letta_llm_stream_adapter_error_handling.py`, langfuse `web/AGENTS.md:179-183` + `.agents/skills/backend-dev-guidelines/references/middleware-guide.md:552-633` + `fern/apis/server/definition/unstable/errors.yml:192-269`, pydantic-ai per-class docstrings + `_agent_graph.py:2068` doc link) vs inline only (crewai, openhands).** The strongest taxonomies come with a coding standard, an in-repo doc page, AND a tests-as-documentation file. Weaker ones rely on inline docstrings alone.

## Tradeoffs

### Single L0 root vs per-subsystem roots

| | Single L0 (letta, openai-agents-sdk, pydantic-ai, agent-framework) | Per-subsystem (opa, temporal, langgraph) |
|---|---|---|
| **Benefit** | `except BaseError` catches all; one `__all__` to maintain; discoverable | Packages are independent; no god-module; ABI can be closed (opa WASM) |
| **Cost** | Every new exception touches one file; missed re-exports break downstream | No central catch; callers must enumerate types |
| **Best fit** | Single-package framework with public API contract | Multi-package services with wire-level contracts (gRPC, WASM) |
| **Failure mode** | Forgot to re-export → downstream `ImportError` | New error type not in dispatch table → silent fall-through |
| **Alternative** | langfuse's hybrid: HTTP-shaped `BaseError` + per-source domain classes | local taxonomies (crewai, openhands) |

### Operational semantics on the type vs in a sibling layer

| | On the type (langfuse `isRetryable`, letta `StopReasonType` enum) | Sibling layer (openai-agents-sdk `RetryPolicy`, pydantic-ai hooks) |
|---|---|---|
| **Benefit** | Caller can ask `e.isRetryable` directly | Decoupled — adding retry policies doesn't change the type tree |
| **Cost** | The bit must be set correctly at the source; one forgotten leaf = wrong retry | Caller must know the layer exists; framework can quietly retry the wrong thing |
| **Best fit** | Queue/worker retry decisions where the error *is* the dispatch key | HTTP-boundary retries where transport semantics matter |
| **Failure mode** | `isRetryable` defaults to `false`; new types silently non-retryable | `RetryPolicy` falls through to `retry on status >= 500`; 4xx errors retried |
| **Alternative** | langgraph's `default_retry_on` allowlist + denylist (heuristic) | temporal's `IsServiceClientTransientError` central predicate |

### Class hierarchy vs enum+code as the durable taxonomy

| | Class hierarchy (openai-agents-sdk, agent-framework, letta, pydantic-ai) | Enum+code (langfuse `EvaluatorBlockReason`, crewai `A2AErrorCode`, letta `ErrorCode`) |
|---|---|---|
| **Benefit** | Polymorphic dispatch via `except`; rich payloads on each leaf | Wire-stable, versionable, DB-persistable |
| **Cost** | Class rename is breaking; ABI drift on subclass addition | `except Code.X` ladders or string-switching needed |
| **Best fit** | In-memory exception flow | Persisted records, SDK contract, wire format |
| **Failure mode** | Subclass added without dispatch site = silently mis-routed | New enum value with no handler = default branch |
| **Alternative** | Hybrid: class hierarchy internally + enum on the L0 for the wire (letta, langfuse hybrid) | langgraph's `ErrorCode` enum branding messages with docs URLs |

### String message parsing vs typed field for classification

| | String message parsing (crewai `CONTEXT_LIMIT_ERRORS`, openhands `_classify_error_type`, pydantic-ai `groq.py:221`) | Typed field (letta `LLMEmptyResponseError`, langfuse `LLMCompletionError.status_code`, pydantic-ai `ModelHTTPError.status_code`) |
|---|---|---|
| **Benefit** | Works when the upstream exception type is unstable (litellm re-exposing); resilient to library refactors |
| **Cost** | Provider message changes break detection; no compile-time signal |
| **Best fit** | Third-party providers with unstable type hierarchies |
| **Failure mode** | Provider changes "context length exceeded" → "context overflow" → silent misclassification |
| **Alternative** | Central heuristics module (`letta/llm_api/error_utils.py`) with a single regex list |

## Decision Guide

### "Should I use a single L0 root?"

**Use single L0 root if:**
- The framework has a public API contract (`__all__` declared, SDK users import exceptions).
- 5+ subsystem failure modes need distinct dispatch.
- Cross-domain routing matters (caller wants `except BaseError` to mean "any framework error").

**Use per-subsystem roots if:**
- The framework is a multi-package service with wire-level contracts (gRPC, WASM).
- Package independence is more important than cross-domain catch.
- ABI stability requires closed code sets (opa WASM).

**Use local taxonomies if:**
- The codebase is a single-package application, not a library.
- Each domain is genuinely independent and cross-domain routing is rare.

### "Should retry semantics be on the type?"

**Encode on the type if:**
- Queue/worker retry decisions are made based on the exception alone (langfuse, openhands tenacity).
- The retry decision is the *primary* use of the classification.

**Defer to a sibling layer if:**
- The framework's primary interface is HTTP/gRPC and retry is a transport concern.
- Retry policies need to be configurable per-call (openai-agents-sdk `RetryPolicy`).
- Multiple retry policies coexist (e.g., short for HTTP, long for durable execution).

### "Should I use a class hierarchy or an enum?"

**Use class hierarchy if:**
- Polymorphic `except` dispatch is the primary use.
- Each leaf carries structured data (`tool_name`, `status_code`, `error_type`).

**Use enum+code if:**
- The taxonomy must be wire-stable (SDK contract, persisted to DB).
- You need a closed set with versioning (opa WASM, langfuse `EvaluatorBlockReason`).

**Use both if:**
- The framework has an internal hierarchy AND a public wire contract. Internal class hierarchy + wire-facing enum (letta's `ErrorCode` + `LettaError`, langfuse's `BaseError` + `EvaluatorBlockReason`).

### "Should dispatch be at HTTP boundary or in the framework?"

**Dispatch at HTTP boundary if:**
- The framework is an HTTP service (FastAPI, tRPC, REST). The FastAPI exception handler is the right choke.

**Dispatch in the framework if:**
- The framework is a library or worker (queue processor, agent loop). The library needs internal choke points.

**Both if:**
- Library *and* service: dispatch at both boundaries. The internal choke protects the library's invariants; the external choke maps to the wire format.

## Practical Tips

### Patterns to copy

1. **Single L0 root + parallel L1 by subsystem + L2 leaves with typed payloads.** The combination of agent-framework (Python) + openai-agents-sdk + letta + pydantic-ai demonstrates that this is the most extensible shape for agent frameworks with 5+ failure modes.
2. **Per-provider `handle_llm_error` abstract method.** letta's `LLMClientBase.handle_llm_error` is `@abstractmethod` and forces every provider to map to the framework's vocabulary. New provider = new subclass, not new dispatch logic.
3. **Central heuristics module for ambiguous disambiguation.** letta's `letta/llm_api/error_utils.py:8-41` and crewai's `CONTEXT_LIMIT_ERRORS` show that one module owns the substring/regex lists.
4. **Re-export test as the public-contract enforcer.** openai-agents-sdk's `tests/test_exception_exports.py:16-30` is 14 lines that prevent an entire class of bugs.
5. **Typed payloads on every leaf.** `ToolTimeoutError(tool_name, timeout_seconds)` carries more diagnostic value than `ToolTimeoutError("tool X timed out")`.
6. **Enum+code for the durable contract, class hierarchy for the in-memory dispatch.** langfuse's hybrid (HTTP `BaseError` + `EvaluatorBlockReason` Prisma enum + `LLMCompletionError` domain class) is the most defensible answer for a service with both an internal runtime and an external SDK.
7. **Central retry classifier injected via DI.** langfuse's `LLMCompletionError.isRetryable` + `retryLLMRateLimitError` helper; temporal's `IsServiceClientTransientError` + DI wiring; both demonstrate the pattern.
9. **HTTP boundary dispatch via FastAPI exception handlers** (letta) or **gRPC interceptors** (temporal). One choke point per protocol.
10. **Pickle/hashable/equality overrides for cross-process resume** (pydantic-ai). Necessary if integrating with Temporal or durable execution.

### Patterns to avoid or delay

1. **Don't build a single L0 root if you have <3 distinct failure modes.** The cost of maintenance outweighs the benefit.
2. **Don't use substring matching as the *only* classification mechanism.** It's a fallback for ambiguous upstream exceptions, not a primary mechanism. letta's `error_utils.py` is fine because it's used by the per-provider mapper, not by generic dispatch.
3. **Don't put operational semantics on the type if you have multiple retry policies.** openai-agents-sdk's choice to keep retry in `RetryPolicy` (not on `AgentsException`) is correct for a framework with multiple transport-layer concerns.
4. **Don't use `BaseException` for control-flow signals unless you absolutely need to bypass `except Exception`.** agent-framework's `WorkflowInterrupted(BaseException)` is correct for HITL pauses that must escape user code, but the cost is that callers can't `except BaseFrameworkError` and catch it. The langgraph `GraphBubbleUp(Exception)` approach is safer.
5. **Don't make the public API contract on a string field.** openhands' `_classify_error_type` returns one of 6 strings, and a typo (`'budget_exceed'`) silently falls through to `runtime_error`. Use an enum.
6. **Don't document the taxonomy only in inline docstrings.** Every source that scored 7+ has either a coding-standard page (agent-framework `python/CODING_STANDARD.md:205-302`), an in-repo docs page (langfuse `fern/apis/server/definition/unstable/errors.yml:192-269`, opa `docs/docs/errors/index.md:14-32`), or a tests-as-documentation file (letta `tests/adapters/test_letta_llm_stream_adapter_error_handling.py`).
7. **Don't write `except Exception` as the dispatch strategy.** Multiple sources (openhands, pydantic-ai, openai-agents-sdk) have this pattern at the boundaries, but it's a fallback, not a strategy. The choke point should dispatch on type.
8. **Don't skip the `__all__` re-export test.** openai-agents-sdk's test catches a whole class of bug.

### Decision rules

- **5+ source categories, single package, public SDK** → single L0 root + parallel L1 + L2 with payloads (Cluster A).
- **5+ source categories, multi-package service, gRPC/WASM wire** → per-subsystem roots + closed-code enum (Cluster D/E).
- **2-3 source categories, single package** → local taxonomies (Cluster B) are acceptable; don't over-engineer.
- **Provider-translation layer is essential** → implement per-provider `handle_llm_error` (Pattern 1); centralize heuristics (Pattern 6).
- **Public SDK contract or DB persistence** → enum+code (Pattern 4); otherwise class hierarchy suffices.
- **Worker/queue retry decisions** → encode retry semantics on the type or in a central classifier (Pattern 9).
- **HTTP service** → FastAPI exception handlers or equivalent at the boundary; don't scatter `try/except` per route.
- **Cross-process resume** → hashable + picklable exceptions (Pattern 10).

### Caution signs

1. **`except Exception` at the dispatch site instead of `except BaseFrameworkException`.** Indicates the central root isn't actually catching what should be caught.
2. **Substring matching as the primary classification.** Brittle to provider message changes.
3. **No `__all__` test for exceptions.** A new leaf is silently unreachable from the top-level package.
4. **Operational semantics scattered across per-call `isinstance` chains.** Each call site reimplements retry/escalate/stop; central classifier is missing.
5. **Bare `new Error(...)` or `raise RuntimeError(...)` in domain code.** Bypasses every dispatch site.
6. **The `__str__` of the L0 base is the only diagnostic.** Observability tools cannot recover the source category without parsing the class name.
7. **Multiple root classes with overlapping names** (openhands has two `AuthError` classes). Code reading `except AuthError` cannot tell which one is meant.
8. **No test asserting the dispatch contract** (e.g., `tests/test_exceptions.py` for pydantic-ai; `tests/test_retry.py` for langgraph). Adding a new exception type has no safety net.
9. **The taxonomy is documented only in inline docstrings.** Discoverability is low; new contributors must read every file.
10. **The wire format (HTTP code, SSE event, gRPC code) loses the source category.** Letta's SSE wire uses only `stream_incomplete | stream_task_cancelled | internal_error` — clients cannot distinguish context-window-exceeded from rate-limit-exceeded.

## Anti-Patterns / Caution Signs

### Anti-pattern 1: Single-string `error_type` field

**Where seen:** CrewAI's MCP failure events (`error_type: str | None`, `lib/crewai/src/crewai/events/types/mcp_events.py:46-98`); openhands' `_classify_error_type` (`webhook_router.py:70-90`); letta's SSE `error_type` field (`letta/schemas/letta_message.py:386-403`).

**Why it's bad:** No type system catches typos. `"timout"` (typo) silently falls through. No enum to constrain values.

**What to do instead:** Use `Enum` (Python), `StrEnum` (Python 3.11+), `z.enum` (TypeScript), or `IntEnum` for stable machine-readable codes. Let langfuse's `unstablePublicApiErrorCodes` (Zod) be the model.

### Anti-pattern 2: Two classes with the same name

**Where seen:** openhands has `AuthError(OpenHandsError)` in `errors.py:18` (open-source) and `AuthError(Exception)` in `enterprise/server/auth/auth_error.py:1` (enterprise).

**Why it's bad:** `except AuthError` in enterprise code does not catch the open-source one. A developer cannot tell which one is meant without context-switching.

**What to do instead:** Rename one (`SaasAuthError`) or import the other. Document the boundary.

### Anti-pattern 3: Operational semantics in dispatch site knowledge, not the type

**Where seen:** agent-framework has no retry field; openai-agents-sdk has `SandboxError.retryable` only for sandbox; pydantic-ai uses capability hooks.

**Why it's bad:** A caller that wants "is this retryable?" must know the dispatch site's policy. Multiple dispatch sites may have inconsistent policies.

**What to do instead:** Add a `retryable: bool | None = None` field to the L0 root (letta's `LLMError` pattern; langfuse's `LLMCompletionError.isRetryable`). Or use a central classifier (temporal's `IsServiceClientTransientError`).

### Anti-pattern 4: `assert_never` not used over exception unions

**Where seen:** pydantic-ai dispatchers use `except (X, Y, Z)` lists, not `assert_never`. Adding a new subclass is silent at type-check time.

**Why it's bad:** New error class added → silently not handled → only VCR-based integration tests catch it.

**What to do instead:** Future pydantic-ai work proposes `assert_never` over explicit `AgentRunError` union (`pydantic_ai_slim/pydantic_ai/_agent_graph.py:823-829`).

### Anti-pattern 5: Multiple dispatch switches without exhaustiveness

**Where seen:** temporal's `common/serviceerror/convert.go:18-54` falls through to `default → 500 internal_error`; opa's `v1/server/writer/writer.go:39-41` falls through to `default → 500 internal_error`.

**Why it's bad:** Adding a new error type compiles cleanly and silently misclassifies.

**What to do instead:** Either (a) registry-initialized in `init()` blocks (future consideration in opa, temporal); or (b) `map[errorType]httpStatus` table; or (c) test that asserts every type is reached.

### Anti-pattern 6: Operational bit is silently defaulted wrong

**Where seen:** langfuse's `LLMCompletionError.isRetryable` defaults to `false` (`packages/shared/src/server/llm/errors.ts:45`); the source decides based on `status_code + name + cause`. A new error type with `isRetryable=False` will silently not retry.

**Why it's bad:** The default can be wrong for some error types (e.g., 408 Request Timeout is non-retryable by default in langfuse but might want to retry in some flows).

**What to do instead:** Default to "ask the classifier" — let the central predicate (`IsServiceClientTransientError` pattern) decide, not the type itself.

### Anti-pattern 7: Sandbox / control-flow family outside the L0 root

**Where seen:** openai-agents-sdk's `SandboxError(Exception)` is not a subclass of `AgentsException`. langfuse's `UnrecoverableError`, `ObservationNotFoundError` are worker-local.

**Why it's bad:** A caller `except AgentsException` (or equivalent) does not catch the parallel family. Sandbox failures leak past the SDK's contract.

**What to do instead:** Either make the parallel family a subclass (bridge `SandboxError` to `AgentsException`), or document the boundary explicitly.

### Anti-pattern 8: Substring-based error message classification

**Where seen:** crewai's `CONTEXT_LIMIT_ERRORS` (9 phrases); letta's `is_context_window_overflow_message` (6 phrases); openhands' `_classify_error_type` (string matching).

**Why it's bad:** Provider message changes ("context length exceeded" → "context overflow") break detection. No compile-time signal.

**What to do instead:** When the upstream exception class is stable, use `isinstance`. When the upstream class is unstable (litellm re-exposing many types), use central heuristics *with a test that asserts the substring list is current*.

### Anti-pattern 9: Bare `new Error(...)` bypassing the taxonomy

**Where seen:** langfuse `worker/src/queues/monitorQueue.ts:24`, `worker/src/scripts/verifyClickhouseRecords/index.ts:300-948`, `packages/shared/src/encryption/encryption.ts:20-42`; agent-framework `dotnet/src/Microsoft.Agents.AI.Purview/Exceptions/PurviewException.cs:10` (no .NET MAF base).

**Why it's bad:** Bare errors get the default 500 / generic message. The taxonomy is partial.

**What to do instead:** Lint rule (no bare `raise RuntimeError` in domain code); or exception-handler registry that requires registration; or test that walks the codebase and asserts every `raise` is from the taxonomy.

### Anti-pattern 10: No `__all__` re-export test

**Where seen:** openai-agents-sdk has it; everyone else doesn't.

**Why it's bad:** A new exception added to the file but forgotten in `__init__.py` breaks downstream `from framework import NewError`. This is silent until a user reports it.

**What to do instead:** Test that walks the exception module and asserts every subclass is in the top-level `__all__` and reachable from the top-level namespace. 14 lines (openai-agents-sdk).

## Notable Absences

1. **No source scored 9-10.** None of the ten sources has a *mature, durable, observable, extensible, and proven-under-failure* taxonomy. The closest are letta and openai-agents-sdk at 8/10. The dimension description for 9-10 ("Mature, durable, observable, extensible, and proven under failure or scale") is unmet by all sources.
2. **No source has a `Retryable interface { RetryAfter() time.Duration }`.** opa's `Future Considerations` notes this as missing; nobody implements it. Temporal's `Retry-After: 1` header is the closest (letta, langfuse `RESOURCE_LIMIT_ERROR_MESSAGE`).
3. **No source has a typed `ContextWindowExceeded` *and* `Timeout` *and* `RateLimit` *and* `Authentication` *and* `Tool` taxonomy in the same L0.** letta comes closest (`LLMError` subtree covers all of these), but other sources (agent-framework) lack a timeout leaf; langgraph has only `NodeTimeoutError`; openhands has only `RateLimitException`.
4. **No source has an exhaustive `assert_never` over the exception union.** pydantic-ai uses multi-`except` lists; everyone else uses `if/elif` chains.
5. **No source has a telemetry/category attribute on the L0 root.** agent-framework could add one; openai-agents-sdk could add one; nobody has. Observability tools must parse `type(exc).__name__` or `str(exc)`.
6. **No source has a central "errors" documentation page that maps each leaf to retry/escalate/stop.** agent-framework has the dimension-leading question implicitly answered (content filter = stop, invalid auth = escalate) but never written down. pydantic-ai references `docs/agent.md#model-errors` but no such page was found. langfuse has `fern/apis/server/definition/unstable/errors.yml:192-269` for the public API but not the internal hierarchy.
7. **No source has a `Validation` leaf.** agent-framework uses Python built-ins (`ValueError`, `TypeError`); openai-agents-sdk uses `UserError` for SDK misuse and `ModelBehaviorError` for malformed model output; langgraph has `InvalidUpdateError` but it's channel-specific. The "validation" category in the dimension checklist maps to *built-in* exceptions in most sources.
8. **No source has a `Context` category leaf *except* letta (`ContextWindowExceededError`).** Other sources handle context overflow via upstream provider exceptions (which may or may not be typed).
9. **No source has a typed `Policy` category distinct from `Validation`.** openai-agents-sdk has `*TripwireTriggered` (policy) but they're 4 flat siblings, not a `GuardrailTripwireTriggered` parent. Letta has `LettaConfigurationError` but it's distinct from guardrail/validation.
10. **No source has a `User` category leaf *except* openai-agents-sdk (`UserError`) and agent-framework (implicit in `UserInputRequiredException`).** Other sources treat user errors as either validation (`ValueError`) or as SDK misuse (`pydantic-ai.UserError`).
11. **No source has a single document enumerating *all* error types and their dispatch paths.** The closest is langfuse's `web/AGENTS.md:179-183` (tRPC + REST playbook) and opa's `docs/docs/errors/index.md:14-32` (parsing/compilation/evaluation table). Both are partial.

## Per-Source Notes

### agent-framework (7/10)

- Single L0 base `AgentFrameworkException` (Python) with parallel L1 branches by subsystem (`Agent*`/`ChatClient*`/`Integration*`/`ContentError`/`ToolException`/`MiddlewareException`/`WorkflowException`/`SettingNotFoundError`).

## Open Questions

1. **Why don't more sources encode retry semantics on the type?** Only langfuse (`LLMCompletionError.isRetryable`), letta (`StopReasonType`), openai-agents-sdk (`SandboxError.retryable`), and langgraph (`default_retry_on` allowlist/denylist) attempt this. Is there an empirical reason or is it just convention? **No clear evidence found** of a "best practice" rationale.
2. **Why is `Validation` rarely a typed category?** agent-framework uses Python built-ins; openai-agents-sdk uses `UserError` for SDK misuse and `ModelBehaviorError` for malformed model output. Is "validation" not a real category for agent frameworks, or is it absorbed into "user" / "model behavior"?
3. **Why is `Context` rarely a typed category?** Only letta has `ContextWindowExceededError`. Other sources handle context overflow via upstream provider exceptions. Is this a deliberate choice (don't re-type upstream behavior) or an oversight?
4. **Why is `Policy` rarely distinguished from `Validation`?** openai-agents-sdk's `*TripwireTriggered` (policy) and `UserError` (validation) coexist without a parent. Is the policy/validation distinction load-bearing for agent frameworks?
5. **Why are SSE wire formats always coarser than the in-memory taxonomy?** letta's SSE uses 3 string codes; openai-agents-sdk streams `SandboxError` directly; langfuse's MCP errors use `McpError` codes. Is there a reason not to surface the full taxonomy on the wire?
6. **What is the empirical evidence that taxonomy maturity correlates with operational reliability?** No source provides metrics. The rating is based on structural analysis, not on outage/incident data.
7. **Why are worker/queue retry decisions more likely to encode retry on the type, while HTTP boundary decisions defer to a sibling layer?** langfuse's `LLMCompletionError.isRetryable` is consumed by the worker; openai-agents-sdk's `RetryPolicy` is consumed by the HTTP client. Is this because workers have stable retry semantics while HTTP clients have configurable policies?
8. **Should the public SDK contract use the same taxonomy as the internal one?** langfuse says no (`unstablePublicApiErrorCodes` is separate from `BaseError`); letta says yes (`ErrorCode` enum is the wire contract); agent-framework says partially (`OpenAIContentFilterException` is public, others are lazy-exported). What factors determine the choice?
9. **Is the dimension-leading question "can I tell retry/escalate/stop from the type?" actually answerable without a central `retryable` field?** Every source answers "partially yes" — content filter = stop, invalid auth = escalate, transport timeout = retry. But the long tail (LLM malformed JSON, tool invalid args, ambiguous provider errors) is ambiguous. Is there a source that answers this fully?
10. **Why do some sources have extensive documentation (coding standards, docs/) while others rely only on docstrings?** agent-framework, langfuse, opa, openai-agents-sdk have docs; crewai, openhands, langgraph rely on inline docstrings. Is this a function of framework maturity, organizational practice, or something else?
