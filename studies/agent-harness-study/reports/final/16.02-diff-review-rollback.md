## Executive Summary

No source answers the dimension's headline question — *can a bad artifact change be reverted with full audit trail?* — in the affirmative. All three expose one leg of the workflow and leave the rest manual or missing.

- **Diff/comparison** is mature only in openhands, where git *is* the artifact store (`_sdk_inspect/sdk/git/git_diff.py:53`, `open.../app_conversation_router.py:1308-1366`) with size guards, rename canonicalization, and Monaco rendering. Both SDKs have zero diff generators: agent-framework's `deepdiff` sits unused in `python/uv.lock:2142`; langgraph grep for `diff` across `libs/langgraph`/`libs/checkpoint` finds only CI `git diff` and `pyperf compare_to`.
- **Review** is execution-gated HITL in both SDKs — `ToolApprovalMiddleware`/`function_approval_request` (`python/packages/core/agent_framework/_harness/_tool_approval.py:86-158`) and `interrupt()`/`Command.resume` (`libs/langgraph/langgraph/types.py:811-934`) — not artifact governance. Openhands has no artifact review model at all; the only review in the repo is external GitHub PR triage.
- **Rollback** is manual restore-via-checkpoint in agent-framework (`Runner.restore_from_checkpoint` at `python/packages/core/agent_framework/_workflows/_runner.py:240-300` with `graph_signature_hash` guard) and manual branch-via-fork in langgraph (`bulk_update_state` with `source="fork"` at `libs/langgraph/langgraph/pregel/main.py:1589-1660`). Neither offers `rollback(to_checkpoint_id, reason)` with tombstone/audit. Openhands has no revert API at all — `grep rollback` returns only `db_session.rollback()` — and its archive (`openhands/app_server/sandbox/workspace_archive.py:334-543`) is a pre-delete backstop, not a restore point.
- **Traceability** is partial everywhere: `WorkflowCheckpoint` carries `workflow_name`, `graph_signature_hash`, `previous_checkpoint_id` (`python/packages/core/agent_framework/_workflows/_checkpoint.py:71-88`) but no `run_id`; `CheckpointMetadata.run_id` exists (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:61-62`) but stamping is caller-dependent; openhands stitches `conversation_id.hex` across DB/event/archive without a join index.

The archetype split explains the scores: the two agent runtimes (both 4/10) invest in checkpoint durability and HITL at the expense of diff/comment/ledger; the workspace platform (3/10) invests in diff fidelity at the expense of versioned rollback and review. No source combines all five evidence types (diff generator, review state machine, rollback handler, comment model, change log).

## Core Thesis

Diff, review, and rollback maturity correlates with whether the system *owns a versioned artifact*, not with how sophisticated its execution engine is. SDKs (agent-framework, langgraph) own execution checkpoints and therefore deliver hardened save/load/list/delete, parent-linked chains, and superstep coverage — but they treat agent definitions, declarative YAML, and workspace files as unversioned inputs, so diff, artifact-level approval, comments, and a unified run↔artifact ledger have nowhere to attach. The platform (openhands) owns the git working tree and therefore delivers real diff — but it treats the workspace as a single mutable git repo rather than a versioned artifact registry, so review, typed comments, and revert have no store or policy.

Convergence despite different stacks: all three reconstruct history as an immutable, parent-linked sequence (agent-framework `previous_checkpoint_id` at `python/packages/core/agent_framework/_workflows/_checkpoint.py:75`, langgraph `parents` map at `libs/checkpoint/langgraph/checkpoint/base/__init__.py:56-60` + `CheckpointTuple.parent_config`, openhands implicit git DAG) and all substitute execution HITL or external PR review for artifact governance. Divergence is constraint-driven: libraries must stay backend-agnostic and storage-trust-explicit (RestrictedUnpickler allowlist `python/packages/core/agent_framework/_workflows/_checkpoint_encoding.py:72-145`, DeltaChannel warnings `libs/checkpoint/langgraph/checkpoint/base/__init__.py:331-414`), while the platform can assume a running sandbox, proxy diff through it, and pay for archive durability with sandbox-lifetime cost (`_finalize_sandbox_delete` at `openhands/app_server/app_conversation/app_conversation_router.py:878-936`).

The missing primitive everywhere is an explicit artifact registry with its own version, diff, review, comment, and rollback linkage to runs — without it, each capability is either ad-hoc manual work (deserialize two checkpoints and eyeball) or delegated to git/external tooling without audit.

## Approach Models

Three approach labels emerged by normalizing the per-source reports against the dimension vocabulary:

**Model A — SDK Checkpoint-Surrogate with Execution HITL (agent-framework, langgraph)**

*Problem framed as:* make long-running graph execution resumable and human-gateable without running an artifact registry.
*Where implemented:* core runtime packages (`python/packages/core/agent_framework/_workflows/_checkpoint.py`, `python/packages/core/agent_framework/_workflows/_runner.py`, `libs/checkpoint/langgraph/checkpoint/base/__init__.py`, `libs/langgraph/langgraph/pregel/main.py`).
*Main mechanism:* versioned checkpoint storage via an explicit protocol (`CheckpointStorage` at `python/packages/core/agent_framework/_workflows/_checkpoint.py:119-189`, `BaseCheckpointSaver` at `libs/checkpoint/langgraph/checkpoint/base/__init__.py:227-650`) with save/list/get_latest/delete and a parent pointer (`previous_checkpoint_id` / `parents` map). Rollback is explicit-restore (agent-framework) or fork-from-history (langgraph). Review is per-execution approval (`function_approval_request`/`ToolApprovalMiddleware` at `python/packages/core/agent_framework/_harness/_tool_approval.py:345-618` and `interrupt()` at `libs/langgraph/langgraph/types.py:811-934`), not per-artifact governance.
*Supporting:* graph-signature hash or channel-versions for compatibility, RestrictedUnpickler/msgpack allowlists, status/event timelines (`WorkflowEvent` at `python/packages/core/agent_framework/_workflows/_events.py:104-131`, `StateSnapshot` at `libs/langgraph/langgraph/types.py:643-661`), multi-backend stores (memory/file, memory/sqlite/postgres).
*Operational contract:* storage is caller-supplied and, in agent-framework, explicitly trusted (`python/packages/core/agent_framework/_workflows/_checkpoint_encoding.py:27-44`).

**Model B — Platform Git-Native Diff with No Artifact Governance (openhands)**

*Problem framed as:* show what the agent changed in its sandbox and keep a copy before deletion.
*Where implemented:* `_sdk_inspect/sdk/git/` (local generators) + app-server proxy (`openhands/app_server/app_conversation/app_conversation_router.py:1224-1366`) + frontend Changes tab (`frontend/src/routes/changes-tab.tsx:23`, `frontend/src/components/features/diff-viewer/file-diff-viewer.tsx:75`) + workspace archive (`openhands/app_server/sandbox/workspace_archive.py:77-543`).
*Main mechanism:* `get_git_diff(relative_path, ref)` fetching original via `git show {ref}:{path}` (`_sdk_inspect/sdk/git/git_diff.py:53-128`) and `get_changes_in_repo` via `git diff --name-status` + `ls-files --others` (`_sdk_inspect/sdk/git/git_changes.py:37-202`), proxied through the app-server with `X-Session-API-Key` and `ref`-resolution via `get_valid_ref` (`_sdk_inspect/sdk/git/utils.py:104-206`). Durability is a best-effort `git-delta`+`tar.gz`+manifest archive at sandbox delete, gated by `RUNTIME_FILE_ARCHIVE_ENABLED`.
*Supporting:* `GitChange`/`GitDiff` models (`_sdk_inspect/sdk/git/models.py:9-25`), Monaco diff viewer with stale-while-revalidate hooks, event log flat-file history (`openhands/app_server/event/event_service_base.py:190-205`).
*Explicit non-mechanisms:* no `ArtifactVersion`/`Review`/`Comment` table, no `POST .../revert` handler, no indexed run↔hunk join (grep `artifact*` in `openhands/` yields zero hits).

**Why the split is not a quality ranking:** SDKs optimize for embeddability (in-memory stores for tests, pluggable persistence, no required infra) and thus under-invest in cross-version diff/comment/ledger that needs a registry. The platform optimizes for immediate operability (thin git wrappers, one-hop proxy, file-backed event log) and under-invests in versioned artifact semantics that would duplicate git. Both choices are valid for their product shapes — but neither answers the dimension end-to-end.

## Pattern Catalog

**Pattern 1 — Checkpoint-as-Artifact with Parent-Linked Chain (enables manual rollback and audit ordering)**

- *Problem:* without a registry, how do you version anything and walk back to a good state?
- *Sources:* agent-framework `WorkflowCheckpoint{checkpoint_id, previous_checkpoint_id, timestamp, iteration_count}` (`python/packages/core/agent_framework/_workflows/_checkpoint.py:30-88`) chained per superstep by `Runner._create_checkpoint_if_enabled` (`python/packages/core/agent_framework/_workflows/_runner.py:212-238`) with test `previous_checkpoint_id == prev.checkpoint_id` (`python/packages/core/tests/workflow/test_checkpoint.py:285-336`); langgraph `Checkpoint{id: UUIDv6, ts, channel_versions}` (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:92-123`) with `CheckpointMetadata{source, step, parents, run_id}` (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:38-86`) and `get_state_history` walking the DAG (`libs/langgraph/langgraph/pregel/main.py:1479-1530`).
- *Why it works:* immutable, ordered nodes with explicit parents give linear/forking auditability and cheap "get chain" without a ledger table.
- *When to copy:* any stateful execution that needs crash-resume or time-travel; essential before you add diff/review.
- *When it is risky/overkill:* without tombstones or a `RollbackReason`, `delete(checkpoint_id)` erases forensic history (agent-framework `FileCheckpointStorage.delete → unlink` at `python/packages/core/agent_framework/_workflows/_checkpoint.py:392-410`); and without snapshot awareness, `prune` severs lineage. Use soft-delete or compensating `source="rollback"` checkpoint instead.
- *Evidence:* agent-framework tests `test_checkpoint_validation.py:34-165` and langgraph `test_time_travel.py:345-371` assert `metadata.source` values `input/loop/fork`.

**Pattern 2 — Time-Travel / Fork as Rollback (preserves audit, no atomic revert)**

- *Problem:* how to revert without mutation and with preserved history?
- *Sources:* agent-framework `Workflow.run(checkpoint_id=..., checkpoint_storage=...)` + `Runner.restore_from_checkpoint` (`python/packages/core/agent_framework/_workflows/_workflow.py:630-670`, `python/packages/core/agent_framework/_workflows/_runner.py:240-300`) validating `graph_signature_hash`, clearing state via `State.clear+import_state` (`python/packages/core/agent_framework/_workflows/_runner_context.py:370-427`); langgraph `bulk_update_state`/`update_state` handling `as_node=="__copy__"` fork via `source="fork"` and DeltaChannel stub at `step=-1` (`libs/langgraph/langgraph/pregel/main.py:1589-1660`, `1798-1877`), plus `_prepare_state_snapshot` applying pending writes (`libs/langgraph/langgraph/pregel/main.py:1144-1265`).
- *Why it works:* branching keeps the bad checkpoint reachable for forensics while the fork becomes the new head — more auditable than in-place overwrite.
- *When to copy:* when audit is more important than storage cost; preferred over hard delete.
- *Overkill/risk:* caller must explicitly thread the forked `config` as the new head; the bad branch stays enumerable so UI must hide it. No built-in `rollback_to(checkpoint_id, reason)` helper — openhands reports explicitly that such a handler does not exist, and both SDK reports call for one.
- *Evidence:* langgraph `test_time_travel.py:69-520` and agent-framework `test_checkpoint.py:160-223` both verify roundtrip restore/fork semantics.

**Pattern 3 — Execution-Gated Review via Interrupt/Approval (substitute for artifact gates)**

- *Problem:* how to get human sign-off without building a full artifact review lifecycle?
- *Sources:* agent-framework `ToolApprovalMiddleware` with session-backed `ToolApprovalState`/`ToolApprovalRule` keyed by `server_label` (`python/packages/core/agent_framework/_harness/_tool_approval.py:86-158`, `345-618`), queued `function_approval_request` Content types (`python/packages/core/agent_framework/_types.py:338-362`, `1212-1253`), and workflow `WorkflowEvent.request_info` with `request_id`/`request_type` (`python/packages/core/agent_framework/_workflows/_events.py:114-145`, `python/packages/core/agent_framework/_workflows/_runner_context.py:244-260`); langgraph `interrupt(value)` raising `GraphInterrupt` with stable `Interrupt.id` (xxhash at `libs/langgraph/langgraph/types.py:577-578`), graph-level `interrupt_before`/`interrupt_after` (`libs/langgraph/langgraph/pregel/main.py:767-769`, `libs/langgraph/langgraph/graph/state.py:1116-1252`), resume via `Command(resume=...)`, surfaced in `StateSnapshot.interrupts` (`libs/langgraph/langgraph/types.py:597-605`, `643-661`).
- *Why it works:* reuses the execution superstep boundary to pause, render `next_tasks`/`interrupts`, and durably checkpoint pending requests (`python/packages/core/agent_framework/_workflows/_runner_context.py:385-390`) — no separate review service.
- *When to copy:* when gating side-effects (tool calls, deploy steps) matters more than gating artifact definitions.
- *When it is overkill/risky:* conflates run-level gating with artifact governance — no `pending_approval/approved/rejected` states, no multi-reviewer, no diff+comment affordance, and approval state lives in ephemeral `AgentSession.state` (`python/packages/core/agent_framework/_harness/_tool_approval.py:160-217`) or requires a live checkpointer, so loss of session/checkpointer loses the queue.
- *Evidence:* langgraph `interrupt.py:75` and agent-framework `Workflow._send_responses_internal` (`python/packages/core/agent_framework/_workflows/_workflow.py:936-960`) with `try_coerce_to_type` validation both mark this as execution review, not artifact review.

**Pattern 4 — Hardened Checkpoint Persistence (atomic write, traversal guard, restricted deserialization)**

- *Problem:* file-backed checkpoints must not tear or be traversable, and pickles must not be universal RCE.
- *Sources:* agent-framework `FileCheckpointStorage` — JSON+pickle+base64 with `.tmp`+`os.replace` atomic commit, `_validate_file_path` via `resolve().is_relative_to()`, `allowed_checkpoint_types` allowlist, `_validate_file_path` even handles symlink-resolved paths (`python/packages/core/agent_framework/_workflows/_checkpoint.py:239-450`), plus `RestrictedUnpickler` with `_BUILTIN_ALLOWED_TYPE_KEYS`/`agent_framework.*`/`openai.types.*` and `_verify_type` mismatch detection (`python/packages/core/agent_framework/_workflows/_checkpoint_encoding.py:14-145`) and explicit "storage must be trusted" caveat (`python/packages/core/agent_framework/_workflows/_checkpoint_encoding.py:27-44`); langgraph `get_next_version` monotonic per-channel versions and Postgres/Sqlite savvy (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:692-711`) for type-safe blobs.
- *Why it works:* cheap filesystem invariants that survive crashes and path attacks without a DB; allowlist bounds pickle surface.
- *When to copy:* always for file/object-store checkpoints; the `.tmp`+`replace` + `is_relative_to` pair is table-stakes.
- *Overkill/risk:* agent-framework still allows `builtins:getattr` and `copyreg:_reconstructor` (`python/packages/core/agent_framework/_workflows/_checkpoint_encoding.py:95-97`), so compromised storage remains high-severity — documented as must-be-trusted. Prefer typed msgpack/JSONPB with strict allowlists if you can tolerate the schema cost.
- *Evidence:* hardening tests `test_checkpoint_validation.py:34-165` and `test_checkpoint_unrestricted_pickle.py:45-182`.

**Pattern 5 — Git-Native Diff Pipeline with Size Guard and Nested-Repo Support**

- *Problem:* how to expose artifact diff without building a versioned store?
- *Sources:* openhands only. `get_git_diff(relative_path, ref)` with 1 MiB `MAX_FILE_SIZE_FOR_GIT_DIFF` guard, `git show {ref}:{path}` original fetch (`_sdk_inspect/sdk/git/git_diff.py:53-128`), `get_changes_in_repo` via `git diff --name-status {ref}` + `ls-files --others` with `R`→`DELETED+ADDED` canonicalization (`_sdk_inspect/sdk/git/git_changes.py:37-202`, `104-120`), `get_git_changes` aggregating nested `.git` repos (`_sdk_inspect/sdk/git/git_changes.py:205-246`), `get_valid_ref` with `origin/{branch}`→`origin/default`→empty-tree fallback (`_sdk_inspect/sdk/git/utils.py:104-206`), proxied via `_proxy_git_runtime_call` (`openhands/app_server/app_conversation/app_conversation_router.py:1224-1306`) to `GET /{id}/git/changes`+`/git/diff` (`openhands/app_server/app_conversation/app_conversation_router.py:1308-1366`), rendered in `FileDiffViewer` Monaco `DiffEditor` collapsed-by-default (`frontend/src/components/features/diff-viewer/file-diff-viewer.tsx:75-254`).
- *Why it works:* delegates merge/conflict semantics to git, keeps SDK thin, and renders diff in existing Changes tab without versioning the artifact separately.
- *When to copy:* when artifacts *are* the workspace tree and git is already canonical; pair with `get_valid_ref` to avoid empty-tree surprises on shallow clones (`live_status_app_conversation_service.py:223` warning).
- *Overkill/risk:* conflates "agent output" with "repo state" — untracked files handled but `.gitignore` gaps leak; rename tracking is lost (`MOVED` enum at `_sdk_inspect/sdk/git/models.py:10` never emitted); changes capped at `slice(0,100)` (`frontend/src/routes/changes-tab.tsx:96`) silently hides beyond-100 files; oversize/binary files hard-fail with `GitPathError` rather than chunk.
- *Evidence:* `GET /{id}/git/changes` and `/git/diff` are the only diff endpoints surfaced; `V1GitService.getGitChanges/getGitChangeDiff` fetch them (`frontend/src/api/git-service/v1-git-service.api.ts:32-91`).

**Pattern 6 — Event/Status Timeline as Change-Log Surrogate (no typed diff/comment)**

- *Problem:* without a change-log table, how to see what happened when?
- *Sources:* agent-framework `WorkflowEvent` enum (`started`, `status`, `output`, `intermediate`, `request_info`, `superstep_started/completed`, `executor_invoked/completed/failed` at `python/packages/core/agent_framework/_workflows/_events.py:104-131`), filtered via `WorkflowRunResult.get_outputs/get_intermediate_outputs/get_request_info_events/status_timeline` (`python/packages/core/agent_framework/_workflows/_workflow.py:101-164`), with OTel `WORKFLOW_RUN_SPAN` but no artifact↔run ledger (`python/packages/core/agent_framework/_workflows/_workflow.py:480-542`); langgraph `CheckpointMetadata` provenance (`source/step/parents/run_id` at `libs/checkpoint/langgraph/checkpoint/base/__init__.py:38-86`) tested at `libs/langgraph/tests/test_time_travel.py:345-351`; openhands flat JSON files `{prefix}/{user_id}/v1_conversations/{conv_hex}/{event.id.hex}.json` queryable by `kind`/`timestamp` (`openhands/app_server/event/event_service_base.py:86-110`, `openhands/app_server/event/event_router.py:19-110`) with conversation metadata `created_at/updated_at/sandbox_id/tags[archiveworkspacepath]` (`openhands/app_server/app_conversation/app_conversation_models.py:110-138`).
- *Why it works:* enough for replay and timeline rendering without designing a schema.
- *When to copy:* for early observability; don't mistake it for a version-comparison or per-hunk traceability system.
- *Risk:* no `artifact_id → run_id → checkpoint_id → diff → comment` join anywhere. Openhands `batch_get_events` rehydrates but cannot answer "which run touched file X?" without forensic `git blame`; langgraph `run_id` is config-dependent; agent-framework `InMemoryHistoryProvider` lives only in `session.state` with no version diff (`python/packages/core/agent_framework/_sessions.py:413-535`).
- *Evidence:* all three reports explicitly label traceability "weak/partial" for this reason.

Convergence that matters: all three lack the full loop `version → diff → comment → approval → rollback → audit`. Each funds a different shortcut — checkpoints + HITL (SDKs) or git diff + archive (platform) — and treats the remainder as out-of-scope or external.

## Tradeoffs

- **Checkpoint fidelity vs artifact coverage (SDKs).** Agent-framework's hybrid JSON+pickle with base64 and `RestrictedUnpickler` (`python/packages/core/agent_framework/_workflows/_checkpoint_encoding.py:72-112`) and langgraph's per-channel `"{seq:032}.{rand:016}"` versions (`libs/checkpoint/langgraph/checkpoint/memory/__init__.py:619-628`) preserve Python objects and minimize copy-on-write churn. *Benefit:* exact resume and efficient delta. *Cost:* the artifact that gets versioned is execution state, not the workspace file or prompt — so diff/comment/review have no object to annotate. *Alternative seen elsewhere:* openhands versions files directly via git and avoids pickling, at the price of shallow-clone and size-guard fragility. *Best fit:* keep fidelity for state, but don't mistake state versioning for artifact versioning.

- **Topology/compatibility guard vs urgent revert (agent-framework).** `graph_signature_hash` validation in `restore_from_checkpoint` (`python/packages/core/agent_framework/_workflows/_runner.py:274-279`) prevents silent replay on drift. *Benefit:* safe. *Cost:* legitimate emergency rollback after a graph change is blocked — you must rebuild the old topology exactly, and tests `test_checkpoint_validation.py:34-165` enforce that hard fail. *Alternative:* langgraph's branch-based fork tolerates graph evolution but leaves the bad head readable; openhands delegates to git ref which tolerates any topology. *Best fit:* hash-guard if your executor graph is an API contract; branch-fork if you expect frequent topology iteration.

- **Fork-preserves-history vs explicit rollback verb (SDKs).** Langgraph never tombstones; bad checkpoints stay in `get_state_history`. *Benefit:* full audit DAG. *Cost:* callers must track which `config` is the current head and explicitly hide bad branches; no single `rollback_to(checkpoint_id, reason)` that atomically moves head and records reason (both reports flag this). *Alternative:* a compensating `source="rollback"` checkpoint that points `parents` at `target` would give both audit and linear head. *Failure mode today:* last-writer ambiguity on concurrent forks (`libs/langgraph/langgraph/pregel/main.py:1933-1942`).

- **Execution HITL vs artifact governance (SDKs).** Session-backed `ToolApprovalMiddleware` (`python/packages/core/agent_framework/_harness/_tool_approval.py:160-217`) and `interrupt()`/`Command` (`libs/langgraph/langgraph/types.py:811-934`) gate tool calls and node entry in-process. *Benefit:* no review service, testable, portable across storage backends. *Cost:* approval is per-call, per-node, per-session — not per-artifact version, not multi-reviewer, not diff-aware. Losing session or running without checkpointer drops pending approvals. *Alternative:* artifact review is what openhands also lacks — it has an empty chair where a `pending_approval → approved/rejected` state machine would go. *When to keep HITL-only:* if your only gated action is "should this tool run?"; when to add governance is when you need "should this prompt/file version ship?".

- **Git-native diff vs no diff (platform vs libraries).** Openhands `get_changes_in_repo` + `get_valid_ref` + proxy (`openhands/app_server/app_conversation/app_conversation_router.py:1224-1366`) gives human-readable diff immediately via Monaco (`frontend/src/components/features/diff-viewer/file-diff-viewer.tsx:152-203`). *Benefit:* no registry needed, semantics from git. *Cost:* conflates agent output with repo state, loses true renames (`R`→`DELETED+ADDED`), caps at 100 entries, fails on >1 MiB, and requires `RUNNING` sandbox (`get_conversation_git_changes` returns 409 at `openhands/app_server/app_conversation/app_conversation_router.py:1252-1256` when paused). SDKs have the opposite cost: zero diff means reviewers restore blind. *Best fit:* git diff when workspace *is* git; explicit `diff(checkpoint_a, checkpoint_b)` utility (e.g., leveraging the `deepdiff` already in `python/uv.lock:2142` or per-channel `versions_seen` + `get_delta_channel_history`) when artifacts are checkpoints.

- **Best-effort archive durability vs versioned restore (openhands).** `archive_workspace` streaming via `_stream_to_tempfile` (`openhands/app_server/sandbox/workspace_archive.py:176-193`) plus manifest and `REQUIRED`-gated teardown (`openhands/app_server/sandbox/workspace_archive.py:77-83`, `openhands/app_server/app_conversation/app_conversation_router.py:904-926`) ensures data not lost on delete. *Benefit:* prevents disappearance of the bad change too. *Cost:* archives are opaque objects under `workspace-archives/{sandbox}/{conv}/{ts}.*` with no index and no `restore` path; failed `REQUIRED` archiving leaks a running sandbox until idle-reap, while best-effort mode silently loses data if bucket env is misconfigured (`openhands/app_server/sandbox/workspace_archive.py:369-394`). *Alternative:* langgraph/agent-framework already diverge with per-run checkpoint grouping that *is* restorable — the platform could adopt the same `checkpoint_id → restore` verb for git refs.

- **Generic metadata bag vs typed annotation (langgraph + openhands).** `CheckpointMetadata(total=False)` and `tags: dict[str,str]` (`openhands/app_server/app_conversation/app_conversation_models.py:40-47`) allow ad-hoc `run_id`/`archiveworkspacepath` keys. *Benefit:* extensible without migrations. *Cost:* no schema enforcement for `author`/`commit`/`comment`, so traceability is inconsistent — openhands `get_checkpoint_metadata`-style stamping at `libs/checkpoint/langgraph/checkpoint/base/__init__.py:757-775` depends on caller discipline. *Alternative:* a typed `CheckpointAnnotation{target_checkpoint_id, author, text, run_id, created_at}` would give filterable comments; neither SDK has it.

## Decision Guide

- **Are your artifacts primarily files in a repo?** Copy openhands Model B: thin `get_git_diff`/`get_changes_in_repo` wrappers over subprocess with `shlex.join` logging (`_sdk_inspect/sdk/git/utils.py:17-36`), size guard, `get_valid_ref` fallback to empty tree, nested-repo aggregation, app-server proxy for CORS/auth, and Monaco rendering collapsed-by-default with lazy `enabled: !isCollapsed` fetch (`frontend/src/components/features/diff-viewer/file-diff-viewer.tsx:101`). Do not copy its lack of `POST .../revert` — add a `revert?ref=` endpoint that validates via `get_valid_ref` and records a revert event so "bad change → revert → audit" is one call.

- **Are your artifacts graph execution states you must resume?** Copy SDK Model A: define a `CheckpointStorage`/`BaseCheckpointSaver` protocol with `save/load/list/delete/get_latest` and a parent pointer (`previous_checkpoint_id` or `parents` map), mint time-ordered IDs (`uuid6` at `libs/checkpoint/langgraph/checkpoint/base/id.py:79-108` gives DB locality + cheap ORDER BY), chain per superstep/iteration, and validate restore compatibility (hash on topology or per-channel versions). Do not stop at `restore/fork` — add a typed `rollback_to(checkpoint_id, reason)` that creates a new compensating checkpoint with `source="rollback"` and a tombstone marker for the abandoned branch so head, audit, and reason are explicit.

- **Do you need human gating?** Use SDK HITL patterns as a first gate: agent-framework `ToolApprovalMiddleware` if you gate per-tool by `server_label` with persisted rules, langgraph `interrupt()` + `Command.resume` + `interrupt_before/after` if you gate per-node pre/post entry. Treat both as run-level gates, not artifact approval. Add true artifact review only when you need "approve this version to promote" — model it as `pending_approval → approved/rejected` with required reviewers, diff binding, and comment anchors, not by overloading `interrupt` or `function_approval_request`.

- **Decision rule — do you need to answer "every artifact for run X" in one call?** If yes, no studied source does this today. Build a small `run_artifacts` manifest: `{run_id, artifact_kind, artifact_id, uri/ref/checkpoint_id, etag/sha256, version, created_at}` written atomically at close, with `GET /runs/{id}/artifacts` reading it. Langgraph already has `run_id` on the type but not on the query path (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:752-785`); agent-framework needs `run_id` added to `WorkflowCheckpoint.metadata`; openhands needs to persist archive keys back into `conversation_metadata` or a `workspace_archives` table (`openhands/app_server/sandbox/workspace_archive.py:403` notes the gap).

- **Decision rule — is history size unbounded (>10 MB) or append-heavy?** Only then adopt langgraph's per-channel `DeltaChannel` with `get_delta_channel_history` and periodic `_DeltaSnapshot` (`libs/checkpoint/langgraph/checkpoint/memory/__init__.py:142-229`). Otherwise prefer simple full-snapshot checkpoints with atomic `tmp+replace` — per-channel versioning doubles lifecycle surface (checkpoint row + N blobs + M writes) and requires snapshot-aware `prune` (the studied code explicitly warns `prune`/`delete_for_runs` silently returns empty without it at `libs/checkpoint/langgraph/checkpoint/base/__init__.py:374-414`).

- **Decision rule — do you need crash-safe persistence on file/object store?** Small blobs: `LocalFileStore` temp+`fsync`+`os.replace` (`python/packages/core/agent_framework/_workflows/_checkpoint.py:317-321`); large blobs: `_stream_to_tempfile` + `write_from_path` (`openhands/app_server/sandbox/workspace_archive.py:176-204`). Pair with path sanitization (`resolve().is_relative_to()` + `~session-{b64}` at `python/packages/core/agent_framework/_sessions.py:1094-1101`).

## Practical Tips

**Patterns to copy now:**

- Make checkpoint/artifact creation atomic for small blobs (temp file + `os.replace`) and streaming for large blobs (`write_from_path` + tempfile) — the only place all three agree, and the cheapest durability win.
- Hash or sanitize any user-supplied ID into file keys (`~session-{b64}` or `farmhash`) and re-validate with `resolve().is_relative_to()` on load — agent-framework gets this right.
- Stamp `run_id` (and `author`/`graph_version`) into every artifact at creation — agent-framework `WorkflowCheckpoint.metadata`, langgraph `CheckpointMetadata.run_id`, openhands archive manifests — and maintain `run_id → [artifact_ids]` even if grouping is by `workflow_name`/`thread_id`/`conversation_id`.
- For git diff, always go through `get_valid_ref` before `git show`/`git diff` (`_sdk_inspect/sdk/git/utils.py:129-135`) so shallow clones and misspelled refs degrade to an empty-tree diff rather than a 502/500. Canonicalize `R`/`C` statuses consistently (even if you choose true rename tracking instead of openhands' `DELETED+ADDED`).
- Validate topology/version on restore and fail closed (`graph_signature_hash` mismatch at `python/packages/core/agent_framework/_workflows/_runner.py:275`, `historyMutated`-style check if you have failover versions). Keep the error message actionable (point to `allowed_checkpoint_types` or stable graph rebuild).
- Persist pending HITL requests durably: checkpoint `pending_request_info_events` with the workflow snapshot (`python/packages/core/agent_framework/_workflows/_runner_context.py:385-390`) rather than keeping them only in process memory.

**Patterns to delay until you have scale:**

- Per-channel versioned blobs / DeltaChannel append optimization — copy simple history-chunking first; only introduce per-channel versioning when profiling proves write amplification.
- Bucket lifecycle delegation for archives — safe to delay only if you also add a storage-budget guard and `max_count`/`max_bytes` alert; otherwise unbounded `*.json` event blobs (`openhands/app_server/event/event_service_base.py:66-84`) and `*.json` checkpoint files scanned via `glob("*.json")` (`python/packages/core/agent_framework/_workflows/_checkpoint.py:374`) silently grow.
- Typed msgpack/JSONPB envelope encryption — start with allowlist + trusted-storage, rotate to typed serialization once you have more than two backends.

**Caution signs the design is becoming brittle:**

- `list_checkpoints(workflow_name=...)` or `list_namespaces` scanning `*.json` without pagination or `run_id` filter — unbounded growth and `get_latest` silently returning an old artifact if latest is corrupted and `logger.warning` skips it (`python/packages/core/agent_framework/_workflows/_checkpoint.py:385-387`, `443-447`).
- Corrupted files skipped with `warning` and `get_latest` via `max(datetime.fromisoformat(timestamp))` vulnerable to clock skew — add explicit ordering and a "corruption detected" signal.
- `prune`/`delete_for_runs` documented as "will break DeltaChannel" but still exposed as abstract — either implement snapshot-aware GC (walk to nearest `_DeltaSnapshot`) or remove the surface.
- Archive files growing without checksum/manifest — you cannot verify integrity on `Get`.
- Event blobs never deleted after `DELETE /conversations/{id}` — prefix `list` byte counts growing monotonically, and no `GET /runs/{id}/artifacts` inventory to prove completeness.
- Review state living only in `AgentSession.state` or requiring a live sandbox/checkpointer (`openhands/app_server/app_conversation/app_conversation_router.py:1252-1256` returns 409 when paused) — approvals are lost on crash or pause.

## Anti-Patterns / Caution Signs

- **Workflow-name / thread-name as retention scope.** All interleaved runs share one directory/partition; there is no `run_id` partitioning. Signals: `list_checkpoints(workflow_name=...)` scan (`python/packages/core/agent_framework/_workflows/_checkpoint.py:374`), `thread_id+checkpoint_ns` primary key (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:176`, `libs/checkpoint-postgres/langgraph/checkpoint/postgres/base.py:554`). Fix: store under `{workflow_name}/{run_id}/{checkpoint_id}.json` and add `list_by_run`.

- **Manual `delete(checkpoint_id)` as the only GC with hard `unlink`.** No TTL, `max_count`, `max_bytes`, or soft-delete/tombstone. Signals: `FileCheckpointStorage.delete → unlink()` (`python/packages/core/agent_framework/_workflows/_checkpoint.py:392`), langgraph `DELETE FROM checkpoints|blobs|writes WHERE thread_id` (`libs/checkpoint/langgraph/checkpoint/memory/__init__.py:511`), `delete_for_runs`/`prune` abstract despite corruption warnings. Forensic trail can be erased with one call.

- **Abstract lifecycle that is documented unsafe but still callable.** `delete_for_runs`/`prune`/`copy_thread` raise `NotImplementedError` while docstrings warn naïve use "silently reconstructs as empty" (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:320-415`). Either implement snapshot-aware GC or remove the surface.

- **Trusted-storage disclaimer without hardening.** `checkpoint storage is trusted data source` disclaimer plus 4-point checklist (`python/packages/core/agent_framework/_workflows/_checkpoint_encoding.py:18-45`) documents but does not enforce access controls; `builtins:getattr` and `copyreg:_reconstructor` remain allowlisted (`python/packages/core/agent_framework/_workflows/_checkpoint_encoding.py:95-97`). Prefer typed serialization with strict allowlists, or treat checkpoints as untrusted input.

- **Hash-opaque or UUID-random names without a companion index.** `uuid4` random names give no temporal scan (`python/packages/core/agent_framework/_workflows/_checkpoint.py:74`), `uuid6` helps but still needs DB ordering, hash-opaque archive keys (`openhands/app_server/sandbox/workspace_archive.py:398-403`) require recomputing prefixes to locate one run — add a manifest/visibility cross-link.

- **In-process-only locks for cross-process stores.** `threading.Lock` + `asyncio.Lock` striped by `hash(path)%64` (`python/packages/core/agent_framework/_sessions.py:916`) and `LocalFileStore` atomic writes do not protect multi-process hosts (multi-replica app-server) — expect interleaved JSONL.

- **Silent truncation of diff.** `changes.slice(0,100)` (`frontend/src/routes/changes-tab.tsx:96`) plus `enabled: !isCollapsed` lazy loading (`frontend/src/components/features/diff-viewer/file-diff-viewer.tsx:101`) hides beyond-100-file changes and defers diff fetch — reviewers may approve partial view without realizing it.

## Notable Absences

- **Unified run→artifacts manifest or index.** No source offers `GET /runs/{id}/artifacts` or a manifest file written atomically at close. Agent-framework's `WorkflowRunResult` holds events but not checkpoint IDs; langgraph's `run_id` is in `CheckpointMetadata` but has no `list_for_run` index; openhands stitches `conversation_id.hex` across DB/event/archive but notes "no single API" explicitly.

- **First-class diff/comparison for checkpoints.** Agent-framework static dependence on manual `deepdiff` comparison; langgraph `DeltaChannel` internals expose `writes + seed` but no user-facing `diff_state(before, after)`; openhands diffs only files via git — no semantic checkpoint/message/state diff.

- **Artifact review/approval lifecycle.** No `Artifact`/`ArtifactVersion` with `pending_approval → approved/rejected`, no approver role or required-reviewers policy, no promotion gate. Closest are per-execution `ToolApprovalMiddleware`/`interrupt()` which gate side-effects, not artifact promotion.

- **Typed comment/annotation model anchored to artifacts.** No `CheckpointComment{checkpoint_id, author, body, created_at}` stored beside checkpoints or `Comment{file:line → hunk}` for diffs. Agent-framework `Content.annotations` is citation metadata (`python/packages/core/agent_framework/_types.py:374-385`); openhands `Comment` is PR/issue-scoped (`openhands/app_server/integrations/service_types.py:162-228`).

- **Explicit rollback verb with audit.** No `rollback_to(checkpoint_id, reason)` / `POST .../git/revert?ref=` with validation, compensating checkpoint, tombstone, and `rollback_reason` in metadata/audit log. Agent-framework requires caller to pick `checkpoint_id` and call `run(checkpoint_id=...)`; langgraph requires fetch-via-`get_state_history` plus `invoke(before_b.config)` or `update_state(historical_config, ...)` fork; openhands requires manual `git checkout/revert` inside the sandbox.

- **Automated retention/GC for primary artifacts.** Agent-framework `FileCheckpointStorage`/`FileHistoryProvider` have no `delete`/`TTL`/`compaction`; langgraph `Store TTLConfig` with `supports_ttl=false` by default and no sweeper; openhands no `expires_at` and bucket lifecycle as only reaper comment (`openhands/app_server/sandbox/workspace_archive.py:408`).

- **Archived artifact integrity.** No `sha256` on checkpoint files or `HistoryBlobHeader`, no ETag persisted beside archive object, no envelope encryption — noted explicitly as gaps across all reports.

## Per-Source Notes

**agent-framework (4/10)** — Hardest checkpoint durability story for an SDK: atomic `os.replace`, traversal guard, allowlist, chaining invariant tested, and topology-aware restore. Execution HITL is the most complete (two mechanisms: `ToolApprovalMiddleware` per-tool and `request_info` per-workflow-superstep, both durably checkpointed). Ceiling is scope: checkpoints version workflow state, not declarative YAML or file artifacts — so diff/comment/ledger have no object. Time-travel via `get_state`/`get_state_history`/`bulk_update_state` fork (`source="fork"`) is well-tested (`tests/test_time_travel.py:69-677`, `test_delta_channel_update_state.py:1-280`).
