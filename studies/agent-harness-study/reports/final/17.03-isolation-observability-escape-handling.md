## Executive Summary

No source in this study implements a mature, end-to-end answer to "would the system know if an agent tried to escape its sandbox?" The dimension reveals a fundamental mismatch between threat model and observability investment. Two sources that actually run untrusted agent code in OS containers — **agent-framework** (4/10) and **openhands** (4/10) — delegate the hard boundary to Docker/gVisor/Hyperlight but invest almost nothing in observing that boundary: no syscall audit, no filesystem breakout detection, no egress anomaly monitor, and no operator alert pipeline. Two sources that do not run untrusted code in-server — **opa** (7/10) and **temporal** (4/10) — achieve far clearer observability for the boundaries they do own (Rego evaluation decisions and namespace fences) precisely because their isolation is logical, interceptable, and total.

The synthesis takeaway is not that one implementation is generically better, but that observability follows interposition. OPA and Temporal can log every decision at a single gRPC/decision-log interceptor (`v1/plugins/logs/plugin.go:715-821`, `common/authorization/interceptor.go:129-185`). Agent-framework and OpenHands must observe an opaque container boundary they do not instrument, leaving them with pre-execution pattern matching and construction-time flag blocklists (`python/packages/tools/agent_framework_tools/shell/_docker.py:73-125`, `_sdk_inspect/sdk/security/defense_in_depth/pattern.py:140`) that prevent naive escapes but cannot detect a successful breakout.

Across all four, the strongest shared pattern is the **audit-bus abstraction** (OPA `EventV1`, OpenHands `EventService`, Temporal `CallTarget`+history, agent-framework `ShellResult`+OTel). The weakest shared gap is **alerting**: every violation terminates at `logger.warning` or a Prometheus counter; no source ships a paged alert rule for an isolation breach.

## Core Thesis

Isolation observability is mature only where the system interposes on every action at a pluggable boundary it controls. OPA's decision log and Temporal's authorizer interceptor are mature because every evaluation/request *must* flow through them. Agent-harness sandboxes (agent-framework, openhands) are fragile because the sandbox is a delegated container boundary the harness observes only via stdout/exit_code and optional callbacks, with no runtime breakout sensor, no structured sandbox audit log, and no escape taxonomy. Prevention (hardened Docker flags, gVisor, AllowNet) is present; detection and alerting after prevention fails is absent everywhere.

## Approach Models

Three approach models emerge, clustered by product shape rather than code language:

**Cluster A — Delegated OS sandbox harnesses (agent-framework, openhands).** Both intend to run untrusted shell/code. Isolation is chosen per tool instance (library) or per deployment (app-server). The mechanism is OCI/microVM flags at `docker run`/`pod` creation. Observability is an afterthought: agent-framework captures `ShellResult{stdout,stderr,exit_code,duration_ms,truncated,timed_out}` (`python/packages/tools/agent_framework_tools/shell/_types.py:14-47`) and an optional `on_command` callback (`python/packages/tools/agent_framework_tools/shell/_tool.py:135-136`); OpenHands persists every `ActionEvent` to S3/GCS filesystem (`openhands/app_server/event/event_service_base.py:190`) and emits structured JSON logs (`openhands/app_server/utils/logger.py:30`). Neither inspects the kernel boundary the sandbox enforces.

**Cluster B — Language/logical-boundary engines (opa, temporal).** Both explicitly do *not* run untrusted OS code in-server. Isolation is a language capability or a database fence. OPA's sandbox is Rego+Wasm+`AllowNet` (`v1/ast/capabilities.go:94-101`, `v1/topdown/http.go:374-384`); Temporal's sandbox is Namespace (`service/frontend/workflow_handler.go:460-463`) with a `CallTarget{APIName,Namespace,Request}` fence (`common/authorization/authorizer.go:24-34`). Every action traverses a single interceptor, so every action is observable without kernel instrumentation. This alignment is why OPA scores 7 and the others 4: its observable boundary *is* its isolation boundary.

**Hybrid outlier within Cluster A — tiered vs. delegated.** Agent-framework offers three tiers (host subprocess, Docker, Hyperlight microVM with no kernel) documented at `python/packages/tools/README.md:157-171` and lets the caller pick trust per tool. OpenHands delegates to a single remote runtime (`runtime_class=gvisor` at `openhands/app_server/sandbox/remote_sandbox_service.py:1089` or `sysbox-runc` at `openhands/app_server/sandbox/remote_sandbox_service.py:491`). Agent-framework's tiering is more explicit about trust; OpenHands' delegation is more operationally hardened but less visible to the harness.

## Pattern Catalog

**1. Decision/Event Audit Bus as the observability spine**
- *Problem:* Ad-hoc `logger.info` lines are unqueryable and lossy under backpressure.
- *Sources:* OPA `EventV1`+`Logger` interface+buffer+upload (`v1/plugins/logs/plugin.go:49-76`, `v1/plugins/logs/plugin.go:38-43`, `v1/plugins/logs/plugin.go:466-473`), OpenHands `EventService.save_event`+`iter_events_for_export` (`openhands/app_server/event/event_service.py:61`, `openhands/app_server/event/event_service_base.py:190`), Temporal `CallTarget`+history persistence (`common/authorization/authorizer.go:24-34`, `service/history/api/respondworkflowtaskcompleted/workflow_task_completed_handler.go:90-94`), agent-framework `ShellResult`+OTel (`python/packages/tools/agent_framework_tools/shell/_types.py:14-47`, `python/packages/core/agent_framework/observability.py:76-92`).
- *Why it works:* Every decision/action is reified as a struct with stable schema, enabling masking, buffering, retry, and fan-out.
- *When to copy:* Any harness that wants reproducible audit or downstream SIEM. OPA's triple sink (console/service/plugin at `v1/plugins/logs/plugin.go:304-317`) is the most complete template.
- *When overkill:* Small CLI tools where `ShellResult`+OTel span is sufficient; do not build S3/GCS persistence for ephemeral local runs.
- *Evidence:* OPA buffer tests assert `counter_decision_logs_dropped_*` on overflow (`v1/plugins/logs/plugin_test.go:1240-1478`); OpenHands trajectory zip is Redis-locked and size-bounded (`openhands/app_server/app_conversation/live_status_app_conversation_service.py:2895`).

**2. Construction-time flag blocklist (prevent-at-init)**
- *Problem:* Runtime policy on shell arguments is trivially bypassable via expansion and encoding.
- *Sources:* agent-framework `_BLOCKED_EXTRA_RUN_FLAGS` (18 flags including `--privileged`, `--cap-add`, `--pid=host`, `--volume`) with `_validate_extra_run_args` raising `ValueError` at `__init__` (`python/packages/tools/agent_framework_tools/shell/_docker.py:73-125`), tested with 19 variants at `python/packages/tools/tests/test_docker_shell_tool.py:144-170`. OPA's `AllowNet` is analogous but per-request (`v1/topdown/http.go:374-400`).
- *Why it works:* Construction is the only moment the harness fully controls args; after `docker run`, tampering requires a new code path.
- *When to copy:* Always for container harnesses — block `--privileged`, `--cap-add`, `--security-opt`, `--network`, `--volume`/`--mount`, `--device`, `--pid/--ipc/--userns`, and set `--cap-drop ALL`/`--security-opt no-new-privileges`/`--read-only`/`--pids-limit` as agent-framework does at `python/packages/tools/agent_framework_tools/shell/_docker.py:174-199`.
- *Risk:* Blocklist is substring-flag only, ignores positional payloads, and misses novel flags (`python/packages/tools/agent_framework_tools/shell/_docker.py:111-117`). Prefer allowlist of explicitly permitted flags plus architecture review over ever-growing deny tuple.
- *Alternative seen:* OpenHands sets only `init=True` at `openhands/app_server/sandbox/docker_sandbox_service.py:498` without `cap_drop`/`security_opt`/`read_only`, relying on remote gVisor — weaker local containment.

**3. Capability/allowlists for egress confinement**
- *Problem:* Agent code's most valuable escape is network exfiltration, not `rm -rf`.
- *Sources:* OPA `Capabilities.AllowNet` (`v1/ast/capabilities.go:94-101`, `v1/topdown/http.go:374-384`, `v1/topdown/http.go:667-670` re-checks redirects), Temporal cross-namespace re-authorization per `(namespace:api)` (`common/authorization/interceptor.go:347-417`), agent-framework `--network none` default (`python/packages/tools/agent_framework_tools/shell/_docker.py:10-20`), OpenHands pattern `curl https://` as MEDIUM (`_sdk_inspect/sdk/security/defense_in_depth/pattern.py:91`) but no host verification.
- *Why it works:* Host-level allowlist is deterministic, testable (`v1/topdown/net_test.go:165-195`), and fails closed (`AllowNet == []` denies all).
- *When to copy:* Any harness that allows `http.send`/`curl`/`fetch`. OPA's model (nil=allow any, empty=deny all, per-request `verifyHost`) is a proven minimal contract. Extend to CIDR/port/path only when product requires it.
- *Overkill:* Applying to fully trusted internal workflows where egress is expected.

**4. Pre-execution deterministic rails with normalization and segment awareness**
- *Problem:* LLM-generated shell is obfuscated via Unicode, base64, and string expansion.
- *Sources:* OpenHands `PatternSecurityAnalyzer`+`PolicyRailSecurityAnalyzer`+`EnsembleSecurityAnalyzer` (`_sdk_inspect/sdk/security/defense_in_depth/pattern.py:140`, `_sdk_inspect/sdk/security/defense_in_depth/policy_rails.py:147`, `_sdk_inspect/sdk/security/ensemble.py:22`) with `_normalize` stripping ~200 invisible chars+NFKC at `_sdk_inspect/sdk/security/defense_in_depth/utils.py:310` and per-segment `_extract_exec_segments` at `_sdk_inspect/sdk/security/defense_in_depth/policy_rails.py:68`; agent-framework `ShellPolicy` explicitly documents trivial bypasses and ships empty-by-default (`python/packages/tools/agent_framework_tools/shell/_policy.py:8-35`, `python/packages/tools/tests/test_security.py:124-164`).
- *Why it works:* Two-corpus scanning (executable leaves vs text fields at `_sdk_inspect/sdk/security/defense_in_depth/utils.py:75`) and segment-aware rail checks prevent `thought: curl` + `tool: ls` false positives while catching `curl | sh`.
- *When to copy:* When confirmation gating must be local and fast without LLM call. Copy the normalization + hard-cap (`_EXTRACT_HARD_CAP=30_000` at `_sdk_inspect/sdk/security/defense_in_depth/utils.py:41`) + fail-closed ensemble (`EnsembleSecurityAnalyzer` maps exception → HIGH at `_sdk_inspect/sdk/security/ensemble.py:84`).
- *Risk:* Hard-cap creates a disclosed bypass ceiling; content beyond 30k is invisible. Long obfuscated payloads can evade detection.

**5. Pluggable sinks with graceful degradation and explicit drop counters**
- *Problem:* Audit durability under backpressure — silent loss is worse than no audit.
- *Sources:* OPA `sizeBuffer`/`eventBuffer` with `counter_decision_logs_dropped_*` (`v1/plugins/logs/plugin.go:274-277`, `v1/plugins/logs/plugin.go:466-473`) and `PushFIFO` in Temporal status (`v1/util/channel.go:13-27`); OPA's `doOneShot` retry with exponential backoff (`v1/plugins/logs/plugin.go:902-961`) and shutdown `flushDecisions` with deadline (`v1/plugins/logs/plugin.go:664-713`).
- *Why it works:* Drop is metered, not silent; tests assert counters (`v1/plugins/logs/plugin_test.go:1240-1370`). Operators get quantifiable coverage loss.
- *When to copy:* Any audit bus with remote upload. Always emit `dropped` counters and surface them in status (`v1/plugins/status/plugin.go:537-552`).
- *Alternative failure:* agent-framework `on_command` hook swallows exceptions via `logger.exception` and continues (`python/packages/tools/agent_framework_tools/shell/_tool.py:254-255`); OpenHands event persistence is unbounded with no drop counter.

**6. Anti-spoof and deduplication at the enforcement point**
- *Problem:* Callers can inject principal headers or replay cross-namespace commands.
- *Sources:* Temporal `headers.StripPrincipal(ctx)` on every path (`common/authorization/interceptor.go:156-158`, `common/authorization/interceptor.go:219-221`) and `authorizedNamespaceAPIs` dedup map (`common/authorization/interceptor.go:347-417`, tested at `common/authorization/interceptor_test.go:497-539`); agent-framework persistent sentinel `__AF_END_{hex}_{hex}__` via `secrets.token_hex(4)` at `python/packages/tools/agent_framework_tools/shell/_session.py:211-212`.
- *When to copy:* Always strip caller-supplied identity headers at the edge; dedup cross-scope checks to avoid log amplification.

## Key Differences

**Sandbox boundary definition.** Agent-framework and OpenHands treat the sandbox as an OS container/microVM boundary, but document it differently: agent-framework explicitly tables three tiers with trust labels (`python/packages/tools/README.md:157-171`), while OpenHands implicitly assumes remote gVisor is the boundary (`openhands/app_server/sandbox/remote_sandbox_service.py:1089`). OPA and Temporal define the sandbox as a language or namespace fence (`v1/ast/capabilities.go:94-101`, `service/frontend/workflow_handler.go:460-463`). This explains why the former pair has richer hardening flags and the latter pair has richer decision observability — each invests where it interposes.

**Audit shape and durability.** OPA emits a bounded, retried, compressed, masked event stream with explicit drop accounting (`v1/plugins/logs/plugin.go:1143-1162`, `v1/plugins/logs/plugin.go:274-277`). OpenHands persists every event durably to filesystem/S3/GCS with no bound (`openhands/app_server/event/event_service_base.py:190`) — stronger durability, weaker backpressure handling, and no `dropped` metric. Temporal relies on durable workflow history as implicit audit (`service/history/api/respondworkflowtaskcompleted/workflow_task_completed_handler.go:90-94`) plus ephemeral error logs. Agent-framework has no audit bus; it has `ShellResult` plus an optional `on_command: Callable[[str],None]` the operator must wire (`python/packages/tools/agent_framework_tools/shell/_tool.py:251-255`). Convergence: all agree an `Event`-like struct is the right abstraction. Divergence: only OPA and OpenHands ship a bus; agent-framework and Temporal make the operator build it.

**Policy violation scope.** Agent-framework splits violations across two disconnected planes: `ShellPolicy` regex pre-filter for shell (`python/packages/tools/agent_framework_tools/shell/_policy.py:70-121`, explicitly not a boundary) and FIDES `PolicyEnforcementFunctionMiddleware` taint labels for prompt-injection (`python/packages/core/agent_framework/security.py:1728-1844`), plus an in-memory `audit_log` at `python/packages/core/agent_framework/security.py:1539-1541`. OpenHands conflates violations into `SecurityRisk` (pattern/rail/LLM, ` _sdk_inspect/sdk/security/risk.py:13`) gated by `ConfirmationPolicyBase` (`_sdk_inspect/sdk/security/confirmation_policy.py:9`). OPA treats deny as result, not violation — errors alone are alertable (`v1/plugins/logs/plugin.go:66`). Temporal treats violation as `DecisionDeny` on `(scope, role)` (`common/authorization/default_authorizer.go:35-65`). No source models "namespace breakout" or "container escape" as a distinct violation type.

**Escape handling depth.** Agent-framework hardens the container at creation most thoroughly (`--network none`, `--user 65534:65534`, `--cap-drop ALL`, `--security-opt no-new-privileges`, `--read-only`, `--pids-limit 256` at `python/packages/tools/agent_framework_tools/shell/_docker.py:174-199`) and blocks flag escalation (`_BLOCKED_EXTRA_RUN_FLAGS`). OpenHands delegates hardening to gVisor/sysbox and creates local Docker with only `init=True` (`openhands/app_server/sandbox/docker_sandbox_service.py:484`) while exposing `privileged`, `host_network`, and `/dev/kvm` as config toggles (`config.template.toml:341`, `openhands/app_server/sandbox/docker_sandbox_service.py:49`, `openhands/app_server/sandbox/docker_sandbox_service.py:59`). OPA confines only `http.send` via `AllowNet` per request. Temporal handles only logical cross-namespace escape via `authorizeTargetNamespaces`. No source detects a successful breakout post-execution (no eBPF, seccomp audit, or Falco feed in any sandbox path).

**Alerting maturity.** OPA propagates `decision_log_error` via `lstat.Status` → status plugin (`v1/plugins/logs/plugin.go:1373-1382`, `v1/plugins/status/plugin.go:312-315`) to console/service/Prometheus (`v1/plugins/status/plugin.go:74-83`). Temporal emits `service_errors_unauthorized`/`service_errors_authorize_failed` counters (`common/authorization/interceptor.go:315-316`). Agent-framework emits `logger.warning("Policy violation detected")` and `logger.warning("BLOCKED")` (`python/packages/core/agent_framework/security.py:1913`, `python/packages/core/agent_framework/security.py:1771-1775`) with no sink. OpenHands surfaces HIGH as a frontend `RiskAlert` confirmation dialog (`frontend/src/components/shared/risk-alert.test.tsx:3`) and `_logger.warning` (`openhands/app_server/sandbox/sandbox_service.py:209`). In all four, paging/Slack/PagerDuty is an operator build, not a shipped rule.

## Tradeoffs

**Prevention vs. detection.** Agent-framework invests in prevention (construction-time blocklist, hardened defaults) at low runtime cost, but cannot detect a zero-day container breakout or daemon misconfiguration — a `podman`/`docker` misconfig produces no signal (`python/packages/tools/agent_framework_tools/shell/_docker.py:73-125` vs. no runtime detector). OPA invests in detection (every `http.send` checked, every redirect re-checked) but only for its narrow egress vector. Copy prevention for cheap hardening; do not mistake it for observability.

**Empty-by-default vs. secure-by-default.** Agent-framework's `ShellPolicy` ships empty to avoid false safety (`python/packages/tools/agent_framework_tools/shell/_policy.py:23-29` citing LangChain/AutoGen removals), and Temporal's authorizer defaults to `noop` open (`common/authorization/noop_authorizer.go:12-14`). OPA defaults to allow-any when `AllowNet == nil` (`v1/topdown/http.go:374-384`). All three favor developer experience over safe defaults, honest but risky: an operator who forgets to configure gets no violation, no log, and no alert. OPA mitigates with explicit buffer validation (`v1/plugins/logs/plugin.go:319-464`); the others rely on documentation.

**Pluggable vs. mandatory audit.** Agent-framework's `on_command` is pluggable and optional (`python/packages/tools/agent_framework_tools/shell/_tool.py:251-255`, exception swallowed), avoiding opinionated storage but guaranteeing many deployments have zero audit. OpenHands' `EventService` is mandatory and durable but unbounded with no drop counter. OPA's bus is mandatory-if-configured with bounded buffers and explicit drops. The tradeoff is dependency weight vs. coverage guarantee. For isolation, mandatory structured audit with a trivial console JSON default (as OpenHands does at `openhands/app_server/utils/logger.py:30`) is preferable to opt-in.

**Privacy vs. investigability.** OpenHands redacts secrets aggressively (`SensitiveDataFilter` at `openhands/app_server/utils/logger.py:248`, `RedactURLParamsFilter` at `openhands/app_server/utils/logger.py:549`) and hashes `session_api_key` without emitting a correlation ID. OPA redacts via Rego-native `mask_decision`/`drop_decision` (`v1/plugins/logs/plugin.go:272-273`, `v1/plugins/logs/plugin.go:1048-1100`). Agent-framework taints data via FIDES labels. Redaction protects keys but removes the ability to correlate which key accessed which secret; emitting a truncated `session_api_key_hash[:8]` as a fingerprint (suggested in OpenHands future considerations) is a balanced compromise.

**Delegated hardening vs. observable hardening.** OpenHands delegating to gVisor simplifies code but offloads escape telemetry to the runtime provider (`openhands/app_server/sandbox/remote_sandbox_service.py:491`). Agent-framework hardening the container itself keeps flags visible and testable (`python/packages/tools/tests/test_docker_shell_tool.py:244-249` asserts `--network none` via `wget` failure) but trusts the local Docker daemon. Delegation is operationally stronger; local hardening is more auditable in the harness repo.

**Polling vs. streaming status.** OpenHands `poll_agent_servers` every 15s (`openhands/app_server/sandbox/remote_sandbox_service.py:880`, `openhands/app_server/sandbox/remote_sandbox_service.py:1078`) is simple and robust for local dev but introduces detection lag for transient `ERROR`. Temporal and OPA stream decisions/logs eagerly. Polling trades MTTD for implementation simplicity.

## Decision Guide

Use this decision tree when designing isolation observability for a new agent harness:

**1. Does your system execute untrusted code/shell?**
- *Yes (agent harness):* You need an OS boundary *and* a way to observe it. Choose agent-framework's hardened Docker flags as the minimal local baseline (`--cap-drop ALL`, `--security-opt no-new-privileges`, `--read-only`, `--pids-limit`, `--network none` at `python/packages/tools/agent_framework_tools/shell/_docker.py:174-199`) plus a runtime with real user-namespace or microVM (Hyperlight `no kernel/shell` at `python/packages/tools/README.md:167-171`, or gVisor `runtime_class=gvisor` at `openhands/app_server/sandbox/remote_sandbox_service.py:1089`). Do not ship local Docker with only `init=True` as OpenHands does.
- *No (policy/orchestration engine):* OPA/Temporal model is sufficient. Interpose at a single interceptor and log `CallTarget`/`EventV1` with `DecisionDeny` counters. Do not add container instrumentation you do not need.

**2. What audit durability do you need?**
- *Compliance/replay (SOC2, forensics):* Copy OpenHands `EventService` with S3/GCS backend (`openhands/app_server/event/event_service_base.py:190`) and OPA's buffer+retry+flush (`v1/plugins/logs/plugin.go:902-961`, `v1/plugins/logs/plugin.go:664-713`). Emit drop counters.
- *Operational debugging:* OPA's `EventV1` console+service dual sink (`v1/plugins/logs/plugin.go:304-317`) with Rego-native mask/drop (`v1/plugins/logs/plugin.go:1048-1141`) is the leanest complete model.
- *Ephemeral dev harness:* Agent-framework's `ShellResult`+OTel spans (`python/packages/tools/agent_framework_tools/shell/_types.py:14-47`, `python/packages/core/agent_framework/observability.py:1371-1380`) plus a default JSON logger (enable `LOG_JSON` as OpenHands does at `openhands/app_server/utils/logger.py:30`) is enough — but make the audit logger default-on, not opt-in.

**3. How should violations be detected?**
- *Known dangerous patterns (rm -rf, curl|sh, dd of=/dev):* Copy OpenHands segment-aware rails (`_sdk_inspect/sdk/security/defense_in_depth/policy_rails.py:68`) with invisible-char normalization (`_sdk_inspect/sdk/security/defense_in_depth/utils.py:310`) and fail-closed ensemble (`_sdk_inspect/sdk/security/ensemble.py:84`). Gate with `ConfirmRisky(threshold=HIGH)` (`_sdk_inspect/sdk/security/confirmation_policy.py:43`).
- *Egress/data exfiltration:* Copy OPA `AllowNet` verified per request+redirect (`v1/topdown/http.go:374-400`, `v1/topdown/http.go:667-670`). Host allowlist is enough for most deployments; extend to path/port only if product demands.
- *Cross-tenant escape:* Copy Temporal `authorizeTargetNamespaces` with `(namespace:api)` dedup (`common/authorization/interceptor.go:347-417`) and `StripPrincipal` at edge (`common/authorization/interceptor.go:156-158`).

**4. How should escape attempts be handled?**
- *Prevent at construction* for containers (agent-framework blocklist at `python/packages/tools/agent_framework_tools/shell/_docker.py:73-125`, gated overrides via explicit constructor args like `network`/`user`/`memory`) rather than per-command regex.
- *Pause for confirmation* for actions (OpenHands `should_require_confirmation` at `_sdk_inspect/sdk/security/analyzer.py:72`). Never auto-execute HIGH.
- *Do not rely on regex alone:* Agent-framework's `ShellPolicy` honest docs (`python/packages/tools/agent_framework_tools/shell/_policy.py:8-35`) and bypass tests (`python/packages/tools/tests/test_security.py:124-164` with backslash, `${RM:=rm}`, `python -c`, base64 smuggling) prove regex cannot be a boundary.

**5. What is the minimum alerting to ship?**
- At least: structured `logger.warning` *plus* a Prometheus counter *plus* a status forwarding path. OPA's `counter_decision_logs_dropped_*` (`v1/plugins/logs/plugin.go:274-277`) → `UpdateDecisionLogsStatus` (`v1/plugins/logs/plugin.go:1373-1382`) → `status` plugin metrics (`v1/plugins/status/plugin.go:537-552`) is the reference; Temporal's `ServiceErrUnauthorizedCounter` (`common/authorization/interceptor.go:315-316`) is the minimum. Document the PromQL alert (`rate(counter_sandbox_escape_attempt[5m]) > 0`) rather than shipping paging.

## Practical Tips

**Patterns to copy immediately:**

- Set hardened Docker defaults by copying agent-framework's flag set verbatim: `--network none`, `--user 65534:65534`, `--cap-drop ALL`, `--security-opt no-new-privileges`, `--read-only`, `--tmpfs /tmp`, `--memory 512m`, `--pids-limit 256` (`python/packages/tools/agent_framework_tools/shell/_docker.py:174-199`). Add `security_opt: seccomp=RuntimeDefault` and `read_only: true` where missing (OpenHands `DockerSandboxService.start_sandbox` at `openhands/app_server/sandbox/docker_sandbox_service.py:484` lacks them).
- Emit a mandatory structured sandbox event per command (timestamp, session/conversation id, command hash, policy decision, approval outcome, `ShellResult` summary, container id). Use OPA `EventV1` (`v1/plugins/logs/plugin.go:49-76`) as schema reference and OpenHands `LOG_JSON` with `SensitiveDataFilter` (`openhands/app_server/utils/logger.py:248`) as logger reference.
- Verify egress per request and per redirect as OPA does (`v1/topdown/http.go:459-462`, `v1/topdown/http.go:667-670`), not once at startup.
- Strip caller-supplied principal headers unconditionally (`common/authorization/interceptor.go:156-158`) and dedup cross-scope checks with a map (`common/authorization/interceptor.go:347-417`).
- Fail closed on detector error: analyzer exception → HIGH (`_sdk_inspect/sdk/security/ensemble.py:84`, `_sdk_inspect/sdk/security/analyzer.py:107`), missing label → warn+call_next is *not* appropriate for container boundaries.

**Patterns to avoid or delay:**

- Do not ship empty-by-default policies without a `logger.Fatal`/metric on the noop path. Temporal's silent `noopAuthorizer` (`common/authorization/noop_authorizer.go:12-14`) and agent-framework's `ShellPolicy()` allow-all (`python/packages/tools/agent_framework_tools/shell/_policy.py:70-121`) are honest in docs but invisible in metrics.
- Do not make audit pluggable-only with swallowed errors. Agent-framework's `on_command` (`python/packages/tools/agent_framework_tools/shell/_tool.py:254-255`) where `logger.exception` hides audit pipeline outage is the anti-pattern; make audit mandatory with a default sink.
- Do not use flat-string matching across concatenated fields. Copy segment-aware extraction (`_sdk_inspect/sdk/security/defense_in_depth/policy_rails.py:68`) and two-corpus separation (`_sdk_inspect/sdk/security/defense_in_depth/utils.py:75`).
- Do not allow `privileged`/`host_network`/`/dev/kvm` as warn-only toggles (`openhands/app_server/sandbox/docker_sandbox_service.py:49`, `openhands/app_server/sandbox/docker_sandbox_service.py:390`, `openhands/app_server/sandbox/docker_sandbox_service.py:59`, `config.template.toml:341`). Gate behind an explicit `SandboxSecurityPolicy` admission check that fails closed.

**Caution signs the design is becoming brittle:**

- `privileged=true` or `host_network=true` appears in a compose or config template (`containers/dev/compose.yml:4`) without a corresponding policy gate or metric.
- `ShellPolicy` denials or Docker `ValueError` rejections are not forwarded to any audit log or OTel span (noted as disconnected planes in agent-framework gaps).
- Audit hook exceptions are caught and not counted — search for `logger.exception("on_command` + no counter increment.
- Polling interval (15s at `openhands/app_server/sandbox/remote_sandbox_service.py:1078`) is the only status path; no push webhook for `SandboxStatus.ERROR`.
- `AllowNet` confusion (`nil` vs `[]` at `v1/topdown/http.go:374-384`) is undocumented for operators — policy that depends on `http.send` silently breaks or silently opens.
- Metric cardinality guard buckets attacker probes as `NamespaceUnknown` (`common/authorization/interceptor.go:334-345`), losing attribution on enumeration attempts.

## Anti-Patterns / Caution Signs

- **Warn-only widening of attack surface:** OpenHands `use_host_network` with `max_num_sandboxes > 1` only warns about port collision (`openhands/app_server/sandbox/docker_sandbox_service.py:390`) and `privileged=false` is a commentable toggle (`config.template.toml:341`). Detected by grepping `privileged|host_network|kvm_enabled` and finding no `cap_drop`/`security_opt`/`read_only` at `openhands/app_server/sandbox/docker_sandbox_service.py:484`.
- **Regex as security boundary:** Agent-framework `ShellPolicy` header (`python/packages/tools/agent_framework_tools/shell/_policy.py:8-35`) explicitly states "Not a security boundary" and tests prove 13 bypass classes (`python/packages/tools/tests/test_security.py:124-164`). Any pipeline that gates an `rm -rf /` block solely on regex is theater.
- **Silent audit failure:** Agent-framework `on_command` hook (`python/packages/tools/agent_framework_tools/shell/_tool.py:254-255`) and OPA `maskEvent`/`dropEvent` swallowed errors (`v1/plugins/logs/plugin.go:767-788`, logs unmasked on mask failure) hide coverage loss.
- **Silent open on misconfiguration:** Temporal `GetAuthorizerFromConfig` → `NoopAuthorizer` on empty string (`common/authorization/authorizer.go:67-68`) and OPA `AllowNet == nil` allow-any are invisible without canary requests. Absence of deny metric is indistinguishable from healthy idle.
- **Hard-cap disclosed but unmitigated:** OpenHands `_EXTRACT_HARD_CAP=30_000` (`_sdk_inspect/sdk/security/defense_in_depth/utils.py:41`) means a 31k-padded payload can push `curl | sh` past the visible window. Documented bypass ceiling with no chunked re-scan.
- **Polling-only status:** `poll_agent_servers` (`openhands/app_server/sandbox/remote_sandbox_service.py:880`) lag means transient `SandboxStatus.ERROR` flaps are missed; no push-based webhook status feed.
- **In-memory audit loss:** Agent-framework FIDES `audit_log` is a process-local list (`python/packages/core/agent_framework/security.py:1539-1541`, `python/packages/core/agent_framework/security.py:1923-1925`) discarded on crash/`clear_audit_log()`, and Temporal authz has no tamper-evident audit log — `logger.Error` is best-effort (`common/log/throttle_logger.go:36-54`).

## Notable Absences

- **OS-level escape monitoring everywhere.** No seccomp/AppArmor/SELinux audit, no syscall anomaly detector, no cgroup/namespace breakout sensor, no filesystem-change journal, no `falco`/eBPF sidecar in any source. Searched `seccomp|syscall|AppArmor|selinux` returns only unrelated hits in OpenHands (`kind/manifests/nginx.yaml:504`) and Temporal (`temporal/interrupt.go:6-11`); OPA explicitly has no `seccomp|nsenter|container.*escape` in `v1/`; agent-framework has no runtime escape heuristics beyond static Docker arg checks.
- **Network egress anomaly detection.** Beyond OPA's host allowlist and agent-framework's `--network none`, no source monitors egress anomaly (volume, entropy, destination reputation). OpenHands pattern `curl` as MEDIUM is a label, not a confinement check; Temporal has no egress policy; agent-framework relies on `--network none` with no per-request host verification.
- **Structured sandbox audit log for container actions.** Agent-framework `ShellResult` lacks user identity/policy tag/audit envelope (`python/packages/tools/agent_framework_tools/shell/_types.py:14-47`); OpenHands `EventService` has no `security_risk` filter (`openhands/app_server/event/event_service.py:26`); Temporal has no audit sink (grep `audit` yields one comment at `service/frontend/admin_handler.go:1001`); OPA's `EventV1` is the only true structured sandbox log, but for decisions, not syscalls.
- **Operator alerting pipeline.** No source ships an alerting rule, Prometheus alert, webhook, PagerDuty/Slack hook, or severity routing for isolation breaches. OPA status propagation stops at reporting (`v1/plugins/status/plugin.go:498-511` single POST, no paged retry); Temporal alerts are CI-only (`tools/ci-notify/slack.go:129-147`, `tools/testrunner/junit.go:16-18`); agent-framework `get_audit_log()` returns an in-process list not exported via OTel (`python/packages/core/agent_framework/security.py:1915-1922`); OpenHands greps `alert|prometheus|grafana` in `openhands/app_server/` return zero hits.
- **Escape taxonomy and kill-on-escape.** No source defines an escape-attempt taxonomy (privilege escalation, mount breakout, `nsenter`, `cgroup` escape), no `on_escape_attempt` signal, no quarantine/kill/capture playbook, and no post-escape forensic capture beyond OpenHands `archive_conversation_workspace` (`openhands/app_server/sandbox/remote_sandbox_service.py:731`).
- **Unified violation record joining data-flow and shell behavior.** Agent-framework FIDES (`audit_log` for taint) and shell (`on_command`/`ShellResult`) are disconnected planes; shell escapes driven by tainted content appear in neither or only one.

Strongest concrete primitives: Docker hardened defaults (`python/packages/tools/agent_framework_tools/shell/_docker.py:10-20`) and `_BLOCKED_EXTRA_RUN_FLAGS` at construction (`python/packages/tools/agent_framework_tools/shell/_docker.py:73-98`), plus Hyperlight microVM with no kernel (`python/packages/tools/README.md:167-171`).
