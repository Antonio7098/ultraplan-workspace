## Executive Summary

No source achieves mature (9-10) "send traces to your existing stack without an adapter" under failure or scale. The field splits by product shape rather than maturity alone.

- **agent-framework (8/10)** is the only harness that answers the rubric question with "yes" out-of-box: it delegates transport to the OpenTelemetry SDK, accepts any OTLP endpoint via standard env vars or `configure_otel_providers(exporters=[...])`, and fans out to multiple backends via per-exporter `BatchSpanProcessor`s (`python/packages/core/agent_framework/observability.py:905-947`). It supports gRPC and HTTP/protobuf, standard `OTEL_EXPORTER_OTLP_*` headers, GenAI semconv (`OtelAttr` at `python/packages/core/agent_framework/observability.py:176-311`), and W3C trace propagation — but leaves health, retry tuning, and commercial adapters as documentation.
- **langfuse (7/10)** inverts the dimension: it *is* the backend. Inbound OTLP (`POST /api/public/otel/v1/traces` at `web/src/pages/api/public/otel/v1/traces/index.ts:78-114`, `fern/apis/server/definition/opentelemetry.yml:7-34`) is durable via S3-as-WAL plus sharded BullMQ (`packages/shared/src/server/redis/otelIngestionQueue.ts:13-88`) and covers live interop. Outbound from stored data is batch-only (blob-storage integrations to S3/GCS/Azure/OCI every 20 min at `fern/apis/server/definition/blob-storage-integrations.yml:57-62` or pull `GET /api/public/v2/traces`), with no live OTLP forwarder and a single `OTLPTraceExporter` URL per process (`web/src/observability.config.ts:114-116`). Standard protocol inbound, proprietary Zod envelope outbound.
- **temporal (6/10)** is an infra emitter, not a harness: OTLP/gRPC-only via `otlptracegrpc`/`otlpmetricgrpc` (`common/telemetry/config.go:13-14`), YAML `otel:` stanza (`common/config/config.go:53`) plus `OTEL_TRACES_EXPORTER` env (`common/telemetry/env.go:29-52`), per-service `BatchSpanProcessor` (`temporal/fx.go:1037-1065`). It works with any OTLP/gRPC collector (Honeycomb via `x-honeycomb-team` at `docs/development/tracing.md:60-76`) but rejects `http/protobuf` (`common/telemetry/config.go:404-407`, `common/telemetry/env.go:44`), and documented multi-backend fan-out is silently broken by map key collision on `SpanExporterType(model)` (`common/telemetry/config.go:227`).
- **openai-agents-sdk (5/10)** and **openhands (5/10)** both require adapters for interop. The former ships a proprietary `{"object":"trace"}` JSON to `https://api.openai.com/v1/traces/ingest` (`src/agents/tracing/processors.py:44-90`, `src/agents/tracing/traces.py:568-575`) behind a clean `TracingProcessor`/`TracingExporter` seam (`src/agents/tracing/processor_interface.py:9-142`) multiplexed by `SynchronousMultiTracingProcessor` (`src/agents/tracing/provider.py:93-220`), with ~27 community adapters listed at `docs/tracing.md:196-226` but none vendored. The latter hard-pins `lmnr>=0.7.20` + `opentelemetry-exporter-otlp-proto-grpc==1.39.1` (`pyproject.toml:64-65`) and gates on `LMNR_PROJECT_API_KEY` or `OTEL_*` (`_sdk_inspect/sdk/observability/laminar.py:25-30`), but auto-forwards only `LMNR_` prefixes (`openhands/app_server/sandbox/sandbox_spec_service.py:151`) and exposes a single `Laminar.initialize()` with no sink SPI or fan-out.

Convergence: all five assume OTLP as the narrow waist and accept standard env vars for collector targeting. Divergence is explained by constraints: harness SDKs minimize deps and delegate; platforms own storage and batch-export; infra servers minimize exporter matrix.

## Core Thesis

Export maturity in 2025-2026 agent systems is not determined by "does an OTLP client exist" but by **who owns transport, how fan-out is modeled, and whether configurability survives process boundaries**.

- Harness-native delegation (agent-framework) achieves "no adapter" by doing the *least*: instrument richly, then delegate transport, headers, retry, and sampling to the OTel SDK and collector.
- Platform ownership (langfuse) achieves durability for ingest (S3 + queue) but necessarily introduces a proprietary canonical format (`packages/shared/src/server/ingestion/types.ts:259-279`) and batch egress, trading live fan-out for query control.
- Vendor-hub/adapter models (openai-agents-sdk, openhands) minimize core dependencies and optimize for a first-party dashboard, at the cost of requiring code (`add_trace_processor` at `src/agents/tracing/__init__.py:94-98` or installing a community `TracingProcessor`) to reach any other stack — coherent given their product goals but failing the rubric's "without writing an adapter" test.
- Infra-constrained emitters (temporal) reduce operational surface to one proven transport (`otlp+grpc`) and lifecycle-bound batch processors, which is rational for a server that expects a collector tier but breaks down for HTTP-only or multi-destination deployments.

The durable pattern is: *standard semconv spans + SDK-delegated exporters + collector-tier fan-out*. Sources that bypass the collector tier either re-implement its jobs poorly (retry, multi-sink) or leave them undone.

**Model A — Delegated OTel-Native Pipeline (agent-framework).** Framework instruments (`ChatTelemetryLayer`/`AgentTelemetryLayer` at `python/packages/core/agent_framework/observability.py:1371,1663`) and leaves transport to `opentelemetry-sdk`. ## Pattern Catalog

### 1. Delegated SDK Pipeline — instrument, don't transport
*Problem:* Every exporter matrix, retry policy, and protocol variant is a maintenance burden.
*Sources:* agent-framework (`python/packages/core/agent_framework/observability.py:1168-1339`, `365-484`), temporal (`common/telemetry/config.go:292-325`), openhands (`_sdk_inspect/sdk/observability/laminar.py:95-112` via lmnr).
*Why it works:* Framework stays small (`opentelemetry-api` only at `python/packages/core/pyproject.toml:29`) while SDK handles batching, compression (`Compression.Gzip` at `python/samples/02-agents/observability/configure_otel_providers_with_parameters.py:127-161`), and spec evolution.
*When to copy:* Harness SDKs and servers that must interoperate with "whatever the customer already runs."
*When to avoid:* Platforms that need to own storage/query — delegation loses canonical format control (langfuse intentionally does not delegate stored-trace egress).
*Evidence:* agent-framework error UX for missing exporter packages (`python/packages/core/agent_framework/observability.py:421-423`); temporal shared-conn optimization (`common/telemetry/config.go:132-140`).

### 2. Env-Driven Zero-Code Configuration
*Problem:* Operators need to retarget collectors, rotate keys, and toggle sensitive data without code deploys.
*Sources:* agent-framework (`python/packages/core/agent_framework/observability.py:487-577`, `524-553`, `643-653` + `.env.example:50-52`), temporal (`common/telemetry/env.go:29-52`, `common/telemetry/config.go:52-53` + `temporal/fx.go:949-970` precedence), langfuse infra (`worker/src/env.ts:172-173`, `web/src/observability.config.ts:115,162`, `.env.prod.example:40-41`), openhands (`_sdk_inspect/sdk/observability/laminar.py:57-82`, `openhands/app_server/utils/llm_metadata.py:28-91`), openai-agents-sdk partial (`src/agents/tracing/provider.py:346-356`, `src/agents/run_config.py:53-56`).
*Why it works:* Standard `OTEL_EXPORTER_OTLP_*` / `OTEL_SERVICE_NAME` / `OTEL_TRACE_SAMPLING_RATIO` names are already known to SREs; `load_dotenv` + env precedence keeps local and container workflows unified.
*When to copy:* Any system that distinguishes app code from deploy config.
*Risk:* Inconsistent prefixing breaks sandbox propagation — openhands documents `LMNR_*` auto-forward but requires manual `OH_AGENT_SERVER_ENV` JSON for `OTEL_*` (`openhands/app_server/sandbox/sandbox_spec_service.py:151` vs `_sdk_inspect/sdk/observability/laminar.py:25-30`), flagged in tests at `tests/unit/app_server/test_agent_server_env_override.py:298-357` only for `LMNR_*`.
*Evidence:* agent-framework HTTP base-endpoint auto-append (`python/packages/core/agent_framework/observability.py:546`) and header merge (`python/packages/core/agent_framework/observability.py:564-566`) matching spec; temporal `OTEL_EXPORTER_OTLP_TRACES_PROTOCOL==grpc` guard (`common/telemetry/env.go:44`) that rejects otherwise.

### 3. Durable Ingest via S3-as-WAL + Sharded Queue
*Problem:* Burst LLM traces must survive web/worker crashes and noisy neighbors without blocking the hot HTTP path.
*Sources:* langfuse (`packages/shared/src/server/otel/OtelIngestionProcessor.ts:182-219` S3 `uploadJson` then `OtelIngestionQueue.add`, `packages/shared/src/server/queues.ts:43-60` event contract, `packages/shared/src/server/redis/otelIngestionQueue.ts:13-88` sharding/retry).
*Why it works:* Web thread does minimal work (validate, `markProjectAsOtelUser` at `web/src/pages/api/public/otel/v1/traces/index.ts:48`, S3 PUT, queue add) and returns quickly; BullMQ provides `attempts:6, backoff exponential 5000ms` and horizontal scale via `projectId-fileKey` hash.
*When to copy:* Platforms that ingest external OTLP and must guarantee at-least-once translation to a canonical store.
*When to avoid:* Harnesses/sidecars where adding S3 + Redis would be heavier than BatchSpanProcessor in-memory batching.
*Evidence:* Secondary queue for noisy-neighbor isolation (`packages/shared/src/server/queues.ts:352-353`), oversized span metric `langfuse.ingestion.otel.oversized_span` (`packages/shared/src/server/otel/OtelIngestionProcessor.ts:331-343`).

### 4. Processor/Exporter Seam for Community Ecosystems
*Problem:* You cannot vendor every observability backend without dependency explosions and version pins.
*Sources:* openai-agents-sdk (`src/agents/tracing/processor_interface.py:9-142`, `src/agents/tracing/provider.py:93-220`, `docs/tracing.md:196-226` listing 27 adapters), agent-framework (`python/packages/core/agent_framework/observability.py:1172` accepting any `SpanExporter`/`LogRecordExporter`/`MetricExporter` at `python/samples/02-agents/observability/configure_otel_providers_with_parameters.py:127-161`).
*Why it works:* Minimal core + single global hook (`add_trace_processor` at `src/agents/tracing/__init__.py:94-98` or `configure_otel_providers(exporters=[...])`) enables an ecosystem without touching core; lazy defaults avoid import-side effects (`src/agents/tracing/processors.py:720-763`).
*When to copy:* SDKs where dep minimalism matters more than out-of-box breadth.
*When to avoid:* When you need env-only multi-sink without code — the seam still requires code to register (openai-agents-sdk has no `OTEL_EXPORTER_OTLP_*` handler in `src/agents/tracing`).
*Evidence:* openai-agents-sdk endpoint-aware sanitization bypass for custom endpoints (`src/agents/tracing/processors.py:258-291`, tested at `tests/test_trace_processor.py:804-839`); agent-framework IronError guidance for missing exporter package (`python/packages/core/agent_framework/observability.py:458-460`).

### 5. Batched Background Export with Jittered Retry and Deadline-Aware Shutdown
*Problem:* Export must not block the agent/LLM loop, must survive transient 5xx, and must not lose tail spans on shutdown.
*Sources:* openai-agents-sdk (`src/agents/tracing/processors.py:541-718` `BatchTraceProcessor` with `max_queue_size=8192/max_batch_size=128/schedule_delay=5.0/export_trigger_ratio=0.7`, `src/agents/tracing/processors.py:121-256` jitter `delay*2 capped max_delay +10%`, `src/agents/tracing/processors.py:623-669` deadline propagation, `src/agents/tracing/setup.py:11-66` `atexit` 5s), agent-framework per-exporter `BatchSpanProcessor`/`BatchLogRecordProcessor` (`python/packages/core/agent_framework/observability.py:905-947`), temporal `otlpmetricgrpc.WithRetry` 5s/30s/1m (`common/telemetry/config.go:38-41`, `temporal/fx.go:941-982` lifecycle with 1s shutdown ignoring `DeadlineExceeded`).
*Why it works:* Queue + scheduled flush decouples tail latency; grouped-by-key retry and deadline propagation preserve exit codes (regression test `tests/test_trace_processor.py:558-648` for exit code 7 on 504).
*When to copy:* Always for harness-side export; for server-side, Fx lifecycle hooks (`temporal/fx.go:1073-1103`) are the idiomatic variant.
*Risk:* Silent drop on `queue.Full` (`src/agents/tracing/processors.py:604,621` warning only) — observability lost at peak load; temporal's 1s shutdown drop is documented lossy.
*Evidence:* Isolation of exporter failures from worker thread (`src/agents/tracing/processors.py:699-717`, tested at `tests/test_trace_processor.py:235-271`).

### 6. Multi-Backend Fan-Out Topology
*Problem:* Operators want the same trace in Honeycomb *and* Tempo *and* a local file without running a collector.
*Sources:* agent-framework succeeds (merges env + programmatic + console + VS Code at `python/packages/core/agent_framework/observability.py:849-877`, iterates by `isinstance` at `python/packages/core/agent_framework/observability.py:905-947`), openai-agents-sdk structurally supports via `SynchronousMultiTracingProcessor` (`src/agents/tracing/provider.py:93-220`) and `add_trace_processor` (`src/agents/tracing/__init__.py:94-98`), langfuse/temporal/openhands are single-exporter and fail: langfuse single `url` (`web/src/observability.config.ts:115`), temporal map-key collision (`common/telemetry/config.go:227`), openhands single `Laminar.initialize()` (`_sdk_inspect/sdk/observability/laminar.py:89-112`).
*Why it works when done right:* One `BatchSpanProcessor` per exporter isolates batching/retries per backend (agent-framework) or synchronous broadcast isolates failures per processor (openai-agents-sdk).
*When to copy:* When your primary promise is "works with existing stack" — implement as list, not singleton.
*When to avoid:* If you deliberately require a collector tier as architectural boundary (temporal's stated assumption at `docs/development/tracing.md:15-23`, langfuse's warehouse orientation).
*Evidence:* agent-framework `GAIATelemetryConfig` adding `FileSpanExporter` alongside OTLP (`python/packages/lab/gaia/agent_framework_lab_gaia/gaia.py:111-113`); temporal docs claim vs implementation mismatch (`docs/development/tracing.md:78-80` vs `common/telemetry/config_test.go:34-55`).

### 7. Semantic-Convention-Correct Attribute Mapping
*Problem:* Collectors and platforms need uniform queryability (`gen_ai.*`, `service.name`, `workflow.*`) without bespoke per-vendor mangling.
*Sources:* agent-framework `OtelAttr` enum covering `gen_ai.operation.name`, `gen_ai.request.model`, `gen_ai.usage.*`, `gen_ai.agent.*`, `gen_ai.tool.*`, `workflow.*` (`python/packages/core/agent_framework/observability.py:176-311`) and MCP W3C propagation via `params._meta` (`python/samples/02-agents/observability/README.md:156-160`), langfuse `OtelIngestionProcessor` mapping `gen_ai.*`/`ai.*`/`gcp.vertex.*`/`mlflow.*`/`traceloop.*` plus `langfuse.observation.type` (`packages/shared/src/server/otel/OtelIngestionProcessor.ts:1436-1505`, `fern/apis/server/definition/opentelemetry.yml:58-63`), temporal minimal `WorkflowIDKey`/`RunIDKey` cardinality budget (`common/telemetry/grpc.go:160-182`) and `semconv.ServiceNameKey` resource (`temporal/fx.go:1018-1031`).
*Why it works:* Standard attributes travel through any OTel collector unchanged; platform-specific mapping (Langfuse `observationTypeMapper`) happens once at ingest boundary.
*Risk:* Langfuse's reverse mapping (Langfuse → OTel) is unimplemented and lossy — proprietary envelope (`packages/shared/src/server/ingestion/types.ts:405-453`) cannot round-trip without translation layer.
*Evidence:* openai-agents-sdk `GenerationSpanData` carrying `usage:{input_tokens,output_tokens,details}` (`src/agents/tracing/span_data.py:169-210`) vs agent-framework semconv coverage — same concept, different envelope.

### 8. Sensitive-Data Gating as Export Policy
*Problem:* Traces may contain prompts, tool arguments, and system instructions that cannot leave the VPC in plaintext.
*Sources:* agent-framework `OBSERVABILITY_SETTINGS.SENSITIVE_DATA_ENABLED` gating `gen_ai.input.messages`/`gen_ai.output.messages`/`gen_ai.system_instructions` (`python/packages/core/agent_framework/observability.py:806-812,1491-1506`), openai-agents-sdk `OPENAI_AGENTS_TRACE_INCLUDE_SENSITIVE_DATA` / `RuleConfig.trace_include_sensitive_data` (`src/agents/run_config.py:53-56`) and `ConsoleSpanExporter` redaction flags (`src/agents/tracing/processors.py:32-37`), langfuse ioredis hook redaction (`web/src/observability.config.ts:109-165`), openhands tagging without payload capture (metadata-only enrichment at `openhands/app_server/app_conversation/live_status_app_conversation_service.py:1587-1867`).
*Why it works:* Gating at call time (re-read via property) allows per-request and env overrides without redeploy; truncation preserves shape (`src/agents/tracing/processors.py:355-446`).
*Risk:* Agent-framework re-reads but does not tear down providers on mid-process disable (`python/packages/core/agent_framework/observability.py:1466` early-return while `BatchSpanProcessor` queue still flushes); openai-agents-sdk `_refresh_disabled_flag` has manual-override precedence that ignores mid-run env changes (`src/agents/tracing/provider.py:339-356`).
*Evidence:* Both agent-framework and openai-agents-sdk test gating extensively (`python/packages/core/tests/core/test_observability.py:208-878`, `tests/test_trace_processor.py:676-1301`).

## Key Differences

- **Transport ownership:** agent-framework and temporal own transport via OTel SDK (`python/packages/core/agent_framework/observability.py:408-483`, `common/telemetry/config.go:292-325`); openai-agents-sdk owns HTTP but not OTel (custom `BackendSpanExporter` at `src/agents/tracing/processors.py:44-90`); openhands delegates to lmnr wrapper; langfuse splits — inbound owned, stored egress owned, infra transport delegated to `OTLPTraceExporter` (`web/src/observability.config.ts:114-116`).
- **Protocol breadth:** agent-framework covers gRPC *and* HTTP/protobuf with base-endpoint `/v1/{signal}` replication (`python/packages/core/agent_framework/observability.py:535-553`, tested at `python/packages/core/tests/core/test_observability.py:774-878`); openhands covers both via `force_http` (`_sdk_inspect/sdk/observability/laminar.py:69-71`); langfuse inbound covers both (`web/src/pages/api/public/otel/v1/traces/index.ts:64-114`); temporal only gRPC (`common/telemetry/config.go:408-413`, `common/telemetry/env.go:44`); openai-agents-sdk neither (proprietary JSON).
- **Configuration surface:** agent-framework and temporal offer YAML + env with clear precedence (`temporal/fx.go:969-970`, `python/packages/core/agent_framework/observability.py:1296-1318` dotenv); langfuse infra env + sampling ratio (`web/src/observability.config.ts:162`) but stored-export is API-driven (`fern/apis/server/definition/blob-storage-integrations.yml:92-146`); openai-agents-sdk env only for disable/key (`src/agents/tracing/provider.py:346-356`); openhands env-only with undocumented `OH_AGENT_SERVER_ENV` fallback for `OTEL_*`.
- **Fan-out realism:** agent-framework fan-out is proven by construction; openai-agents-sdk fan-out is structurally ready but ships size-1; temporal fan-out is documented but broken by key collision; langfuse and openhands are singletons. This is not a quality gradient — it reflects intent: langfuse *wants* a single query store, temporal *wants* a collector tier.
- **Trace format longevity:** agent-framework and temporal emit standard OTel semconv; langfuse stores proprietary versioned envelope (`ingestionEvent` discriminated union plus 5 legacy schemas at `packages/shared/src/server/ingestion/types.ts:276-383,689-718`); openai-agents-sdk emits unversioned proprietary dict (`src/agents/tracing/traces.py:568-575`, `src/agents/tracing/spans.py:396-422`) — the latter is the riskiest for long-term consumers (gap noted in every synthesis).
- **Local-file story:** agent-framework proves `FileSpanExporter` twice (`python/packages/lab/gaia/agent_framework_lab_gaia/gaia.py:126-162`, `dotnet/samples/02-agents/Harness/Harness_Shared_Console/FileSpanExporter.cs:10`) as custom `SpanExporter`; openhands provides ZIP artifact (`openhands/app_server/app_conversation/live_status_app_conversation_service.py:2869-2893`) that is not OTel-shaped; openai-agents-sdk only `ConsoleSpanExporter` (`src/agents/tracing/processors.py:27-42`) plus `TraceState` JSON for resumption (`src/agents/tracing/traces.py:195-277`); temporal and langfuse have no file sink (langfuse `S3_COMPATIBLE` can point at MinIO but is internal-only, `worker/src/scripts/replayIngestionEventsV2/README.md:135-143`).

## Tradeoffs

- **Delegate to OTel SDK vs own the wire (agent-framework/temporal vs openai-agents-sdk):** Benefits: spec compliance, collector interop, shared retry/sampling semantics, minimal custom code. Costs: global `TracerProvider` singleton (`python/packages/core/agent_framework/observability.py:922-947`) conflicts with apps that pre-configure providers; env-var parsing drift (agent-framework replicates `OTEL_EXPORTER_OTLP_ENDPOINT` `/v1/` append logic manually). Best fit: harnesses that prioritize "works with existing stack." Failure mode: SDK version skew (`opentelemetry-semantic-conventions>=0.60b1` override at `python/pyproject.toml:63`, `go.mod:62` pinned `otlptracegrpc v1.43.0` at `common/telemetry/config.go:309`). Alternative seen: openai-agents-sdk avoids SDK dep (`pyproject.toml:9-17` no `opentelemetry-*`) and optimizes for zero-config dashboard, but pays with per-backend adapters.
- **Platform durability vs live fan-out (langfuse):** Benefits: S3 WAL + 6-attempt exponential backoff survives crashes; sharding scales. Costs: 20-min batch floor (`fern/apis/server/definition/blob-storage-integrations.yml:57`), no per-trace OTLP forwarding, hand-managed proto (`web/src/pages/api/public/otel/otlp-proto/generated/root.ts:1-8`). Best fit: platforms owning warehouse ETL. Failure modes: S3 unavailability surfaces as 500 not `retry-after` (`web/src/pages/api/public/otel/v1/traces/index.ts:190-195`), queue `removeOnFail:100_000` silently drops earliest failures (`packages/shared/src/server/redis/otelIngestionQueue.ts:71`). Alternative: agent-framework's collector-tier fan-out avoids S3 latency entirely.
- **Code-seam ecosystem vs vendored adapters (openai-agents-sdk vs agent-framework docs):** Benefits: single `add_trace_processor` enabled 27 integrations with no core churn (`docs/tracing.md:196-226`). Costs: every new backend is user code + dependency; no env-only selector (`OPENAI_AGENTS_TRACE_EXPORTER` not existent), trace format unversioned. Best fit: vendor SDKs that want minimal hard deps. Failure mode: `queue.Full` silent drop at high throughput (`src/agents/tracing/processors.py:604`). Alternative: agent-framework's OTEL headers + endpoint approach supports Langfuse/Opik without custom code (`python/samples/02-agents/observability/README.md:135-145`).
- **Single-vendor default vs neutral (openhands):** Benefits: one-line `LMNR_PROJECT_API_KEY` gives rich instrumentation with minimal docs; `lmnr observe` lazy import (`_sdk_inspect/sdk/observability/laminar.py:115-196`) avoids cold-start. Costs: couples to `lmnr>=0.7.20` API surface; `AUTO_FORWARD_PREFIXES` asymmetry breaks generic OTLP in sandboxes; single sink prevents dev→local + prod→SaaS routing. Best fit: SaaS-first products. Alternative: agent-framework config formalizes both vendor and generic paths equally.
- **gRPC-only simplicity vs breadth (temporal):** Benefits: one retry/timeout/header code path, shared `grpc.ClientConn` avoids double dial, smaller dep surface. Costs: HTTP-only networks need sidecar, protocol mismatch aborts start (`common/telemetry/env.go:43-47`), duplicate `otlp` entries silently collide. Best fit: infrastructure servers already deploying collectors. Alternative: agent-framework proves dual-protocol support is modest code (`python/packages/core/agent_framework/observability.py:408-483`) and could be copied here.
- **Synchronous broadcast vs async per-processor queues:** openai-agents-sdk `SynchronousMultiTracingProcessor` (`src/agents/tracing/provider.py:117-175`) guarantees order and simplicity but a slow exporter blocks `on_span_end`; agent-framework per-exporter `BatchSpanProcessor` isolates latency per backend. Both avoid async fan-out complexity; neither offers bounded per-processor concurrency as a safeguard (future consideration in openai-agents-sdk).

## Decision Guide

**If you are choosing a harness/framework for teams that already own an observability stack (Honeycomb, Tempo, Datadog, Grafana):**
Choose delegated OTel (agent-framework pattern). Require: supports both `otlp+grpc` and `otlp+http/protobuf` in `_create_otlp_exporters` style, accepts `OTEL_EXPORTER_OTLP_*` env vars with `/v1/{signal}` handling, and registers one `BatchSpanProcessor` per exporter (`python/packages/core/agent_framework/observability.py:905-947`). Rule of thumb — if `grep -r OTEL_EXPORTER_OTLP` returns only docs, you will write an adapter.

**If you are building an observability platform:**
Copy langfuse's S3-as-WAL + sharded BullMQ + Zod envelope (platform durability), but budget for the reverse mapper (`OtelIngestionProcessor` forward at `packages/shared/src/server/otel/OtelIngestionProcessor.ts:226-593` needs a `langfuseToOtelMapper` for live export) and a per-project exporter list rather than single URL. Do not block on proprietary storage for infra traces — keep path at `web/src/observability.config.ts:114-116` generic.

**If you are building a vendor SDK that must stay lean:**
Copy openai-agents-sdk's `TracingProcessor`/`TracingExporter` seam (`src/agents/tracing/processor_interface.py:9-142`) and `SynchronousMultiTracingProcessor` broadcast with exception isolation, but add: (a) env-driven exporter selector (`OPENAI_AGENTS_TRACE_EXPORTER=otel|console|none`), (b) a vendored `OtelSpanExporter` under an `[otel]` extra (mapping `SpanData.type` at `src/agents/tracing/span_data.py:28-452` to OTel `SpanKind`), and (c) a `FileTraceExporter` for air-gapped replay. Otherwise you inherit its 5/10 portability cost.

**If you are deploying behind sandboxes/containers:**
Copy temporal's three-layer precedence (YAML → env → programmatic backdoor at `temporal/fx.go:949-970`) but avoid its model-keyed map. Key exporters by `signal+model+name`. For sandbox forwarding, extend allowlists to include `OTEL_` (openhands fix: add `'OTEL_'` to `AUTO_FORWARD_PREFIXES` at `openhands/app_server/sandbox/sandbox_spec_service.py:151`); otherwise generic OTLP will appear broken while vendor key works — a subtle support trap evidenced by `TestLMNRAutoForwarding` covering only `LMNR_*` at `tests/unit/app_server/test_agent_server_env_override.py:298-357`.

**When to prefer collector-tier fan-out over in-process multi-sink:**
If you need sampling, tail-based decisions, or multi-destination routing, put an OTel Collector between harnesses and backends. In-process fan-out (agent-framework style) is correct when the harness is the only exporter owner and destinations are homogeneous; otherwise temporal and langfuse are right to push fan-out outside the process.

## Practical Tips

**Patterns to copy immediately:**
- Standard env vars everywhere (`OTEL_EXPORTER_OTLP_ENDPOINT`/`OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` + `OTEL_EXPORTER_OTLP_HEADERS`/`OTEL_EXPORTER_OTLP_PROTOCOL`, `OTEL_SERVICE_NAME`/`OTEL_RESOURCE_ATTRIBUTES`, `OTEL_TRACE_SAMPLING_RATIO`). Proven in agent-framework (`python/packages/core/agent_framework/observability.py:487-577`), langfuse (`worker/src/env.ts:172-173`), temporal (`common/telemetry/env.go:19-24`).
- One processor per exporter. Registering separate `BatchSpanProcessor` per `SpanExporter` (`python/packages/core/agent_framework/observability.py:905-947`) isolates queue depth and retry without sharing fate.
- `FileSpanExporter` as a one-class custom sink (`python/packages/lab/gaia/agent_framework_lab_gaia/gaia.py:126-162` appending JSONL with `trace_id`/`span_id`/`attributes`/`status`, or C# `dotnet/samples/02-agents/Harness/Harness_Shared_Console/FileSpanExporter.cs:10`) for offline/air-gapped use — promote from sample to core.
- Batch + jitter + deadline-aware shutdown (openai-agents-sdk `src/agents/tracing/processors.py:541-718` + `121-256` + `623-669`) — preserves exit codes and survives transient 5xx (tested at `tests/test_trace_processor.py:558-648`).
- Sensitive-data gating at property-read time (agent-framework `python/packages/core/agent_framework/observability.py:806-812`, openai-agents-sdk `src/agents/run_config.py:53-56`) so toggles can change per request without provider tearddown.

**Patterns to avoid or delay:**
- Do not model exporter registries as `Map<model, exporter>` when `model` is not unique — temporal's `SpanExporterType(model)` key (`common/telemetry/config.go:227`) silently drops duplicates. Use composite keys or lists and warn on collision.
- Do not make generic OTLP second-class in sandboxed architectures. Openhands' `OTEL_*` omission (`openhands/app_server/sandbox/sandbox_spec_service.py:151`) forces `OH_AGENT_SERVER_ENV` JSON and is undiscoverable without reading SDK docstrings. Fix before shipping OTLP docs.
- Do not emit unversioned proprietary envelopes. Openai-agents-sdk `TraceImpl.export`/`SpanImpl.export` (`src/agents/tracing/traces.py:568-575`, `src/agents/tracing/spans.py:396-422`) lacks `version` — add a `schema_version` and gate consumers (langfuse already versions `x-langfuse-ingestion-version>4` at `web/src/pages/api/public/otel/v1/traces/index.ts:147-160`).
- Do not capture unbounded payloads under debug flags. Temporal `payloadCapture.Bytes.Buffer` (`common/telemetry/http.go:283-284`) and langfuse `LANGFUSE_OTEL_MAX_SPAN_BYTES=9.5MB` (`packages/shared/src/env.ts:159`) need caps/redaction even in debug.

**Decision rules:**
- If rubric asks "without writing an adapter": need OTLP in core. Agent-framework qualifies; openai-agents-sdk does not without community package; openhands qualifies only if operator knows `OH_AGENT_SERVER_ENV` workaround; temporal qualifies only for gRPC collectors.
- If you need multiple backends simultaneously: need `exporters: [ ... ]` list in config/code (agent-framework, openai-agents-sdk). Single-url designs (langfuse `web/src/observability.config.ts:115`, openhands `laminar.py:95-112`, temporal single-model) require an external collector.
- If you need local-file export: copy agent-framework `FileSpanExporter` pattern now; don't expect langfuse S3 bucket or openhands ZIP to substitute for OTel-shaped file output.

**Caution signs the design is becoming brittle:**
- Mixing global `TracerProvider` mutation with app-level providers (agent-framework `_executed_setup` idempotency at `python/packages/core/agent_framework/observability.py:846` and sticky `disable_instrumentation` at `python/packages/core/agent_framework/observability.py:1075-1130`) — signals need for `TracerProvider` ref-counting or merge semantics.
- Second `configure_otel_providers()` being a no-op (agent-framework `python/packages/core/tests/core/test_observability.py:2296-2317`) or `OTEL_*` env changes ignored after `set_tracing_disabled` (openai-agents-sdk `src/agents/tracing/provider.py:339-356`) — brittle lifecycle.
- Export size cliffs (`openhands/app_server/app_conversation/live_status_app_conversation_service.py:284` `export_max_events=10000` hard fail) or queue silent drops (`src/agents/tracing/processors.py:604`) — backpressure is hidden.
- Hand-managed compiled proto (`web/src/pages/api/public/otel/otlp-proto/generated/root.ts:1-8`) with no regen script — drift risk across OTel spec revs.

## Anti-Patterns / Caution Signs

- **Undocumented env-forward asymmetry.** Only `LMNR_` auto-forwarded, `OTEL_*` requires manual JSON (`openhands/app_server/sandbox/sandbox_spec_service.py:151` vs `_sdk_inspect/sdk/observability/laminar.py:25-30`). Results in "works on my host, silent no-op in sandbox" (`_sdk_inspect/sdk/observability/laminar.py:83-87` logs at DEBUG only) — add `OTEL_` to allowlist and warn when `OTEL_*` present on host but missing in sandbox `initial_env`.
- **Model-keyed exporter map.** Temporal dedups by `model` (`common/telemetry/config.go:227`) — user believes dual `otlp` entries work, last wins with no warning or metric. Repair by keying on `signal+model+name` and validating at `UnmarshalYAML`.
- **Silent empty-list on unknown protocol.** Agent-framework unknown `OTEL_EXPORTER_OTLP_PROTOCOL` yields empty exporter list (`python/packages/core/agent_framework/observability.py:533` defaults `.lower()` to `grpc`, unknown branch no exporter) — fail fast with warning instead.
- **Unversioned trace envelope.** Openai-agents-sdk exports without `version`/`schema_version` (`src/agents/tracing/traces.py:568-575`, `src/agents/tracing/spans.py:396-422`) — downstream parsers cannot detect breaking changes; Langfuse analog (`x-langfuse-ingestion-version>4` 400 at `web/src/pages/api/public/otel/v1/traces/index.ts:147-160`) shows the cost of late gating.
- **Single exporter URL as architecture.** Langfuse `OTLPTraceExporter { url: ${OTEL_EXPORTER_OTLP_ENDPOINT}/v1/traces }` (`web/src/observability.config.ts:114-116`, `worker/src/instrumentation.ts:28-32`) and openhands `Laminar.initialize` singleton (`_sdk_inspect/sdk/observability/laminar.py:89-112`) preclude "send to existing stack + platform simultaneously" without external tier — document the collector pattern explicitly if this is intentional.
- **Sticky enablement without disable path.** Openhands `_observability_enabled` never flips back (`_sdk_inspect/sdk/observability/laminar.py:201-202`); agent-framework `_user_disabled` is one-way (`python/packages/core/agent_framework/observability.py:1106-1130`) — transient env injection becomes permanent overhead until restart. Add explicit `shutdown`/`reset` for tests and operators.
- **Batch processor lifecycle swallowed.** Temporal 1s shutdown ignoring `DeadlineExceeded` (`temporal/fx.go:1095-1098`) and openai-agents-sdk silent skip when `OPENAI_API_KEY` missing (`src/agents/tracing/processors.py:132-134`) hide misconfiguration — surface counters/metrics for dropped spans.
