## Executive Summary

No source offers a mature, unified artifact lifecycle. All four model durability around *run execution state* rather than a generic file/blob registry, but they scatter that state across different stores and leave retirement largely manual. Temporal (7/10) provides the only end-to-end deterministic lifecycle — primary persistence → external archival copy → jittered retention deletion with scavenger GC — and earns its lead on explicit interfaces, multi-backend archivers, and hard failure guards (history-mutation detection, idempotent 4-stage delete). The three agent frameworks cluster at 6/10: agent-framework and langgraph excel at checkpoint creation/naming/versioning but have no automated retention or single-call run→artifacts inventory; openhands excels at pre-delete durability (streaming workspace archives with REQUIRED gating) but leaks event blobs and lacks TTL/GC. The universal gap is candidacy for the dimension's headline question — *can you find every artifact for a given run in one call?* — which no source answers without multi-store stitching, timestamp filtering, or hash reconstruction.

## Core Thesis

Artifact lifecycle maturity does not correlate with checkpoint sophistication — it correlates with whether the system *owns the run lifecycle*. SDKs (agent-framework, langgraph) treat checkpoints as opt-in, client-supplied durability with pluggable backends and strong encoding safety, but delegate naming isolation, versioning, and retention to the caller; the result is fragmented stores, `workflow_name`/`thread_id` grouping instead of `run_id` scoping, and unbounded growth. Platform and server systems (openhands, temporal) treat the run as a first-class record with a stable identity (`conversation_id`, `NamespaceID/WorkflowID/RunID`) and a deterministic close path, allowing them to engineer durability (openhands' detached `archive-then-delete` finalizer; temporal's `ArchiveExecutionTask → DeleteHistoryEventTask` chain) and operational safeguards (jitter, atomic writes, mutation guards). Divergence is thus constraint-driven, not quality-driven: libraries optimize for embeddability and testability (in-memory stores, runtime-over-buildtime overrides), platforms/servers optimize for operability and data-loss prevention at the cost of opacity (hash-based filenames, split SQL vs object-store consistency).

## Approach Models

Three archetypes emerged, after normalizing the per-source reports before comparison:

**Archetype 1 — SDK-Embedded Opt-In Checkpointing (agent-framework, langgraph)**
*Problem framed as:* give library consumers resumable graph execution and optional durability without imposing ops. *Where implemented:* core SDK packages (`python/packages/core/agent_framework/_workflows/_checkpoint.py`, `libs/checkpoint/langgraph/checkpoint/base/__init__.py`, `libs/langgraph/langgraph/pregel/`). *Main mechanism:* pluggable `CheckpointStorage`/`BaseCheckpointSaver` protocol with in-memory and file/SQL backends; creation on every superstep/loop iteration via `RunnerContext.create_checkpoint` / `PregelLoop._put_checkpoint`. *Supporting:* graph-signature hash or channel-versions for compatibility, pickle/msgpack allowlists for fidelity, `workflow_name`/`thread_id`+`checkpoint_ns` as grouping key. *Ops delegated* — caller chooses storage path/URI, when to enable checkpointing (build-time vs `run(checkpoint_storage=...)` or `durability="exit"`), and when to `delete()`.

**Archetype 2 — Platform Conversation Durability (openhands)**
*Problem framed as:* preserve a SaaS conversation's full trace (DB row + trajectory events + filesystem) across deploys and prevent loss on delete. *Where implemented:* app-server (`openhands/app_server/app_conversation/`, `openhands/app_server/event/`, `openhands/app_server/sandbox/workspace_archive.py`). *Main mechanism:* split storage — SQL `StoredConversationMetadata` for identity/indexing, `FileStore`/`EventService` (local/S3/GCS) for per-event JSON blobs under `{user_id}/v1_conversations/{hex}/`, and unconditional workspace-archiving (`*.patch`+`*.tar.gz`+manifest) to an independent bucket on conversation delete. *Supporting:* `StorageProvider` env factory, atomic local writes + streaming uploads for large archives, Redis-locked export ZIP, `archive-then-delete` detached finalizer with `REQUIRED`/best-effort branching.

**Archetype 3 — Server-Managed Archival + Retention (temporal)**
*Problem framed as:* guarantee history/visibility are copied out before primary store deletion under namespace retention, across persistence engines and cloud stores. *Where implemented:* `common/archiver/*`, `service/history/workflow/task_generator.go`, `service/history/archival_queue_task_executor.go`, `service/history/shard/context_impl.go`. *Main mechanism:* close-time decision `GenerateWorkflowCloseTasks` → `ArchiveExecutionTask` at `close+min(ArchiveDelay, retention)` → timed `DeleteHistoryEventTask` at `close+retention+jitter` → 4-stage `DeleteWorkflowExecution` (visibility, pointer, mutable state, history branch). *Supporting:* `ArchiverProvider` dispatched by URI scheme, `HistoryBlob`/`VisibilityRecord` schemas, 2 MB history iterator chunking, failover-version filenames, jitter, scavenger GC for orphans.

## Pattern Catalog

**Pattern 1 — Pluggable Storage Protocol with Multiple Concrete Backends**
- *Problem:* one interface must serve tests (in-memory), local dev (file/sqlite), and prod (S3/GCS/Postgres) without forking durable logic.
- *Sources:* all four. agent-framework `CheckpointStorage` protocol with `InMemory`/`File` (`python/packages/core/agent_framework/_workflows/_checkpoint.py:119-450`); langgraph `BaseCheckpointSaver` with `InMemorySaver`/`SqliteSaver`/`PostgresSaver` + `BaseStore`/`InMemoryStore` (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:320`, `libs/checkpoint-postgres/langgraph/checkpoint/postgres/base.py:43`); openhands `FileStore`/`EventService` ABCs with local/S3/GCS + env `config_from_env` factory (`openhands/app_server/file_store/files.py:8-42`, `openhands/app_server/config.py:307-328`); temporal `HistoryArchiver`/`VisibilityArchiver` + `ArchiverProvider` switch on URI scheme with custom factory hooks (`common/archiver/interface.go:44-94`, `common/archiver/provider/provider.go:123-247`).
- *Why it works:* decouples checkpoint/archive logic from I/O, enables deterministic tests, and allows incremental rollout (namespace URI picks backend).
- *When to copy:* any system that must run in both ephemeral and durable modes.
- *When it is risky/overkill:* without a unified manifest, pluggability fragments inventory — agent-framework's checkpoints and session histories live in unrelated directories; openhands' DB vs object-store split yields orphaned blobs on partial delete.
- *Evidence:* agent-framework's runtime-over-buildtime storage override tests (`python/packages/orchestrations/tests/test_sequential.py:273`), langgraph's per-backend DDL divergence (Postgres `checkpoint_blobs` vs Sqlite inline @ `libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/__init__.py:139`), openhands' rejection of `memory` for archives (`openhands/app_server/file_store/memory.py:12`), temporal's per-scheme singleton cache.

**Pattern 2 — Time-Ordered or Opaque Deterministic Naming for Ordering & Collision Safety**
- *Problem:* artifacts need sortability for "latest" and safety for arbitrary workflow/run IDs.
- *Sources:* agent-framework `checkpoint_id uuid4` plus filename `{checkpoint_id}.json` with `resolve().is_relative_to()` traversal guard and session stem `~session-{b64}` sanitization (`python/packages/core/agent_framework/_workflows/_checkpoint.py:74-299`, `python/packages/core/agent_framework/_sessions.py:1094-1101`); langgraph `uuid6` monotonic IDs minted `str(uuid6(clock_seq=step))` with `ORDER BY checkpoint_id DESC` (`libs/checkpoint/langgraph/checkpoint/base/id.py:79-108`, `libs/checkpoint/langgraph/checkpoint/memory/__init__.py:283`); temporal `farm.Fingerprint64` hash prefix + `_<closeFailoverVersion>.history` and `<closeTime.UnixNano()>_<hash(runID)>.visibility` (`common/archiver/filestore/util.go:163-174`); openhands `{prefix}/{user_id}/v1_conversations/{hex}/{event_id.hex}.json` and `{PREFIX}/{sandbox_id}/{conversation_id}/{ts}.{suffix}` (`openhands/app_server/event/event_service_base.py:66-84`, `openhands/app_server/sandbox/workspace_archive.py:398-403`).
- *Why it works:* time-ordering gives DB locality and cheap "latest" without extra index; hashing neutralizes special characters.
- *When to copy:* when discovery is scan-based without a secondary index.
- *Overkill/risk:* UUID-random names (agent-framework) give no temporal scan; hash-opaque names (temporal) require recomputing 3 hashes or a visibility query to locate one run; second-granular `ts` (openhands) still collides on rapid retries without the `conversation_id` fix; `uuid6` cross-process collision relies on `random.getrandbits(48)`.
- *Evidence:* agent-framework `get_latest` via `max(datetime.fromisoformat(timestamp))` vulnerable to clock skew; langgraph's `_last_v6_timestamp` bump for monotonicity; openhands pre-fix sibling collision (`workspace_archive.py:408-411` comment).

**Pattern 3 — Parent-Linked Lineage Instead of Flat Listing**
- *Problem:* resuming/forking needs the chain, not just the head.
- *Sources:* agent-framework `previous_checkpoint_id` linked list built by `Runner` per superstep, validated in `test_checkpoint_chaining_via_previous_checkpoint_id` but never exposed as `get_chain()` (`python/packages/core/agent_framework/_workflows/_checkpoint.py:51`, `python/packages/core/tests/workflow/test_checkpoint.py:285`); langgraph `parent_config` chain walked by `get_delta_channel_history` rather than `list(before=...)` to collect delta writes until `_DeltaSnapshot` seed (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:582-649`); temporal `BranchToken`/`HistoryBranch` ancestors + `HistoryIteratorState {NextEventID, FinishedIteration}` for resumption, plus `parents` in `CheckpointMetadata` (`proto/internal/temporal/server/api/archiver/v1/message.proto:13`, `common/archiver/history_iterator.go:23-44`); openhands `parent_conversation_id` + `get_sub_conversation_ids` + `_delete_sub_conversations` enumeration (`openhands/app_server/app_conversation/sql_app_conversation_info_service.py:369-387`).
- *Why it works:* makes fork/time-travel semantics explicit and cheap to traverse.
- *When to copy:* any DAG/branching execution with resets/forks.
- *Risk:* deleting/pruning without snapshot awareness corrupts lineage — langgraph's abstract `prune`/`delete_for_runs` warns of silent empty reconstruction ("simply returns no `seed`" @ `libs/checkpoint/langgraph/checkpoint/base/__init__.py:397-401`); temporal mitigates via `historyMutated` guard but still leaves orphan branches if stage-3 delete crashes before stage-4.

**Pattern 4 — Atomic Small-Write + Streaming Large-Write Split**
- *Problem:* crashes must not leave torn files, but large artifacts must not OOM.
- *Sources:* agent-framework `.json.tmp` + `os.replace` for checkpoints (`python/packages/core/agent_framework/_workflows/_checkpoint.py:317-321`) vs striped 64-lock JSONL appends for history (`python/packages/core/agent_framework/_sessions.py:916-1120`); openhands `LocalFileStore` temp+`fsync`+`os.replace` for small JSON vs `_stream_to_tempfile`+`write_from_path`/`shutil.copyfile` for multi-GB archives (`openhands/app_server/file_store/local.py:26-57`, `openhands/app_server/sandbox/workspace_archive.py:176-204`); temporal 2 MB `targetHistoryBlobSize` iterator sharding into multiple `HistoryBlob`s with GCS per-part objects (`common/archiver/filestore/history_archiver.go:44`, `common/archiver/gcloud/history_archiver.go:31`); langgraph `put_writes` coalescing `delta_write_futs` before `put` to preserve ordering (`libs/langgraph/langgraph/pregel/_loop.py:408-510`).
- *Why it works:* bounds memory while preserving durability invariants.
- *When to copy:* always for file/object stores in multi-tenant services.
- *Risk:* history JSONL/file appends remain only in-process locked (agent-framework/openhands warn multi-process interleaving); temporal S3/filestore cannot resume a crashed multipart upload (only GCS has `ProgressManager`).

**Pattern 5 — Compatibility Guard on Restore/Archive (Not Semver)**
- *Problem:* topology or failover drift must not silently replay wrong state.
- *Sources:* agent-framework `graph_signature_hash = sha256(canonical JSON of executors+edges)` rejected on `restore_from_checkpoint` mismatch (`python/packages/core/agent_framework/_workflows/_workflow.py:1077-1080`, `python/packages/core/agent_framework/_workflows/_runner.py:275`); langgraph per-channel `f"{n:032}.{random}"` versions + checkpoint format `v` (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:692-711`, `libs/langgraph/langgraph/pregel/_checkpoint.py:21`) with `get_new_channel_versions` diffing; temporal `CloseFailoverVersion` embedded in filename/header + `historyMutated` rejecting `lastFailoverVersion > CloseFailoverVersion` or `lastEventID+1 != NextEventID` (`common/archiver/filestore/util.go:211-223`); openhands only sentinel `conversation_version='V1'` hard-filter (`openhands/app_server/app_conversation/sql_app_conversation_info_service.py:755-759`) — intentionally minimal.
- *Why it works:* cheap structural gate prevents cross-topology or cross-failover corruption.
- *When to copy:* when workflows are redefined between runs.
- *Risk:* agent-framework provides no migration — hash mismatch hard-fails; langgraph's `LATEST_VERSION` split (4 vs 2) needs compat shim; temporal's archive has no top-level `archive_format_version` field — proto field-presence is the only compatibility story.

**Pattern 6 — Archive-Before-Delete Ordering with Jitter and Stage Tracking**
- *Problem:* retention deletion must not precede durable copy, and thundering-herd on shared retention must be smoothed.
- *Sources:* temporal only in full form: `archivalEnabled()` double-gate (cluster + namespace), archive at `close+min(jittered ArchiveDelay, retention)`, delete at `close+retention+RetentionTimerJitterDuration` (`service/history/workflow/task_generator.go:196-275`), fan-out `archiveHistory`+`archiveVisibility` in parallel with `multierr.Combine` (`service/history/archival/archiver.go:107-174`), then 4-stage bitmask `DeleteWorkflowExecution` + scavenger best-effort orphan GC after `historyDataMinAge` (`service/history/shard/context_impl.go:910-1019`, `service/worker/scanner/history/scavenger.go:118-379`); openhands partial analogue: detached `_finalize_sandbox_delete` that archives workspace first and only then `delete_sandbox` if `count==0`, with `REQUIRED` blocking teardown on 5xx/422/429 (`openhands/app_server/sandbox/workspace_archive.py:334-541`, `openhands/app_server/app_conversation/app_conversation_router.py:885-937`).
- *Why it works:* eliminates the "delete before copy" data-loss window and makes retries idempotent.
- *When to copy:* any system with retention + external archival.
- *Risk:* still not a conditional invariant — temporal's delete fires on wall time even if archival backend is down, so prolonged outages can still lose data; openhands' `REQUIRED` can instead leak a running sandbox/VM forever on persistent archive misconfig.

## Tradeoffs

- **Fidelity vs safety (agent-framework).** Hybrid JSON + `pickle+HIGHEST_PROTOCOL` + base64 with `__pickled__` marker preserves Python types (datetime, dataclasses, tuples) with roundtrip tests (`python/packages/core/tests/workflow/test_checkpoint.py:993`), but requires a `RestrictedUnpickler` allowlist and an explicit "storage is trusted, never from HTTP" contract. Benefit: exact object recovery. Cost: any compromise of the checkpoint directory is code execution until allowlist is tightened. Alternative seen in langgraph/temporal: typed msgpack/JSONPB with strict allowlists (temporal delegates compat to proto).

- **Per-channel copy-on-write blobs vs operational complexity (langgraph).** `ChannelVersions` + `checkpoint_blobs[(tid,ns,ch,ver)]` means unchanged channels cost no duplication — critical for append-heavy reducers (DeltaChannel). Cost: lifecycle doubles (checkpoint row + N blobs + M writes) and GC is unsafe without snapshot-awareness. The abstract `prune` docstring prescribing "walk to nearest `_DeltaSnapshot` or force resnapshot" shows the design knows the cost but leaves enforcement to the deployer; temporal avoids this by making history a single linear branch with 2 MB chunking instead of per-channel versioning.

- **Appending JSONL / inline JSON vs compact archive (agent-framework, openhands).** Append-only `FileHistoryProvider` JSONL with 64-stripe locks is simple and debuggable, but unbounded with no `delete`/`compact` on `HistoryProvider` (`python/packages/core/agent_framework/_sessions.py:1048-1071`). Same for openhands events. Temporal instead shards large histories into multiple `HistoryBlob`s and human-readable JSONPB files that are queryable by close-time prefix. Benefit: human debuggability. Cost: density/compression must be delegated to the store, and tight JSONPB without checksums leaves bit-rot undetectable.

- **Pluggable FileStore/ArchiverProvider vs consistency.** All four dispatch by URI/env, which enables OSS→cloud moves with no code change. Benefit: extensibility via custom factories (temporal tested in `temporal/fx_test.go:383`). Cost: split-brain — openhands SQL commit can succeed while event blob or archive upload fails (swallowed `delete_from_agent_server` warning, orphaned `{hex}/` prefix), temporal's archive queue and timer queue are separate so retention delete can overtake failed archival.

- **Manual retirement control vs automated GC.** Explicit `delete()` keeps control with the caller (agent-framework, langgraph `delete_thread`, openhands `DELETE /conversations/{id}`) and avoids surprising eviction. Benefit: no accidental data loss. Cost: unbounded growth under scale; all three agent frameworks lack TTL for primary artifacts, and openhands' comment that retry leaves orphaned timestamped objects until "bucket lifecycle" reaps them makes growth the default. Temporal's jittered retention + scavenger is the only automated primary GC, but intentionally leaves archives forever — storage grows without bound unless external bucket rules are set.

- **Hash/opaque naming vs human navigability.** `farmhash` (temporal), `uuid6`/`uuid4` (langgraph/agent-framework), hex UUIDs (openhands) neutralize unsafe characters and give locality, but sacrifice operability. Operators cannot `ls` and eyeball a run's archive; they must hash or query. Hierarchical `user_id/v1_conversations/{hex}/` (openhands) restores navigability at the cost of user-resolution indirection.

- **Durability then delete vs delete then durable (ordering).** openhands and temporal both do archive-then-delete, but openhands blocks sandbox teardown on `REQUIRED` archive failures (leaking a VM until idle-reap), while temporal lets retention delete fire on wall time even if archival is down (risking loss). Neither offers a "hold until archived" invariant or DLQ for poisoned archival tasks (`ArchivalTaskInvalidURI` blocks the queue forever).

## Decision Guide

- **If you are an SDK/library and must embed without ops assumptions:** copy agent-framework/langgraph's pluggable protocol + atomic file replace + allowlisted serialization. Choose `uuid6` over `uuid4` if you need DB locality + cheap "latest" (langgraph @ `libs/checkpoint/langgraph/checkpoint/base/id.py:79`); choose per-channel copy-on-write blobs only if your state has hot append reducers — otherwise it doubles GC complexity. Do not copy their `workflow_name`/`thread_id` grouping alone — add `run_id` scoping from day one.

- **If you are a platform that owns conversations beyond one process:** copy openhands' split SQL + object-store with streaming large-artifact uploads, Redis-locked export, and detached `archive-then-delete` finalizer with `REQUIRED` gating for high-value runs. Derive archive location once at creation and persist it beside the DB row; don't recompute from env at read time.

- **If you are a server with retention + cross-store durability:** copy temporal's close-time `min(ArchiveDelay, retention)` scheduling, jitter, `historyMutated` guard, and 4-stage idempotent delete. Adopt incremental 2 MB iteration sharding (not per-channel versioning) unless profiling proves channel skew.

- **Decision rule — do you need to answer "every artifact for run X" in one call?** If yes, you must add a manifest/index. No studied source has it. Build a small `run_artifacts` table or manifest file written alongside the head artifact: `{run_id, artifact_kind, uri, etag/sha256, version, created_at}` populated atomically at close. Provide `GET /runs/{id}/artifacts`.

- **Decision rule — is history size unbounded (>10 MB)?** Use temporal's iterator + 2 MB chunking with progress checkpointing (extend to all backends, not only GCS). Alert on langgraph's `counters_since_delta_snapshot` growth against `DELTA_MAX_SUPERSTEPS_SINCE_SNAPSHOT` instead of silently returning empty on missing seed.

- **Decision rule — retention?** Start with primary-TTL (temporal model) before worrying about archive lifecycle. Never wire `REQUIRED` blocking teardown without a visible poison-task signal (DLQ/metrics) or you will leak sandboxes/compute.

## Practical Tips

**Patterns to copy now:**
- Define a `CheckpointStorage`/`ArchiverProvider`-style protocol and keep concrete stores thin; add a custom-factory hook from the start (`common/archiver/provider/provider.go:34`).
- Make artifact creation atomic for small blobs (temp + `os.replace` + `fsync` @ `openhands/app_server/file_store/local.py:26` / `python/packages/core/agent_framework/_workflows/_checkpoint.py:317`) and streaming for large blobs (`write_from_path` + tempfile @ `openhands/app_server/sandbox/workspace_archive.py:176`).
- Emit `run_id` into every artifact at creation — in `WorkflowCheckpoint.metadata`, `CheckpointMetadata.run_id`, and archive `HistoryBlobHeader.run_id` — and maintain `run_id → [checkpoint_ids]` separately if your store groups by thread/workflow.
- Hash or sanitize any user-supplied ID into file keys (`farmhash` or `~session-{b64}` @ `python/packages/core/agent_framework/_sessions.py:1094`) and re-validate with `resolve().is_relative_to()` on load.
- Validate topology/version on restore and fail closed (`graph_signature_hash` @ `python/packages/core/agent_framework/_workflows/_runner.py:275`, `historyMutated` @ `common/archiver/filestore/util.go:211`).

**Patterns to delay until you have scale:**
- Per-channel versioned blobs / DeltaChannel append optimization — copy temporal's simpler 2 MB history chunking first; only introduce per-channel versioning when profiling shows write amplification.
- Multipart progress resumption — implement after you see large-history retries in prod; start by re-uploading from scratch with a history iterator.
- Bucket-lifecycle delegation for archives — safe to delay only if you also add a storage-budget guard and `max_count`/`max_bytes` alert.

**Caution signs the design is becoming brittle:**
- `list_checkpoints(workflow_name=...)` or `list_namespaces` scanning `*.json` without pagination or `run_id` filter.
- Corrupted files skipped with `logger.warning` and `get_latest` silently returning an older artifact (`python/packages/core/agent_framework/_workflows/_checkpoint.py:386`).
- `prune`/`delete_for_runs` documented as "will break DeltaChannel" but still exposed as abstract without runtime guard.
- Archive files growing without checksum/manifest — you cannot verify integrity on `Get`.
- Event blobs never deleted after `DELETE /conversations/{id}` — prefix `list` byte counts growing monotonically.

## Anti-Patterns / Caution Signs

- **Workflow-name / thread-name as retention scope.** All interleaved runs share one directory/partition; there is no `run_id` partitioning. Signals: `list_checkpoints(workflow_name=...)` scan (`python/packages/core/agent_framework/_workflows/_checkpoint.py:374`), `thread_id` primary key pattern (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:176`). Fix: store under `{workflow_name}/{run_id}/{checkpoint_id}.json` and add `list_by_run`.

- **Manual `delete(checkpoint_id)` as the only GC.** No TTL, `max_count`, `max_bytes`, or cron. Signals: `FileCheckpointStorage.delete → unlink()` (`python/packages/core/agent_framework/_workflows/_checkpoint.py:392`), `delete_thread` as only concrete path (`libs/checkpoint/langgraph/checkpoint/memory/__init__.py:511`, `libs/checkpoint-postgres/.../__init__.py:381`), `StoredConversationCostEvent ondelete CASCADE` but no event-blob cascade (`openhands/app_server/app_conversation/live_status_app_conversation_service.py:2779`), archive plane "never deleted" (`service/worker/scanner/history/scavenger.go:118` only cleans primary branches).

- **Abstract lifecycle that is documented unsafe but still callable.** `delete_for_runs`/`prune`/`copy_thread` raise `NotImplementedError` while docstrings warn naïve use "silently reconstructs as empty" (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:320-415`). This is an invitation to misuse; either implement snapshot-aware GC or remove the surface.

- **Trusted-storage assumption without hardening.** `checkpoint storage is trusted data source` disclaimer plus 4-point checklist (`python/packages/core/agent_framework/_workflows/_checkpoint_encoding.py:18-45`) documents but does not enforce access controls; pickle still executes if allowlist is widened. Prefer typed msgpack/JSONPB with strict allowlists.

- **Hash-opaque filenames without a companion index.** `constructHistoryFilename → hash(ns)+hash(wf)+hash(run)` (`common/archiver/filestore/util.go:163`) and `ORDER BY checkpoint_id DESC` without secondary index both optimize write locality at the cost of operator debuggability. Add a manifest/visibility cross-link (`VisibilityRecord.history_archival_uri` is the one place temporal gets this right).

- **In-process-only locks for cross-process stores.** `threading.Lock` + `asyncio.Lock` striped by `hash(path)%64` (`python/packages/core/agent_framework/_sessions.py:916`) and `LocalFileStore` atomic writes do not protect multi-process hosts (Azure Functions, multi-replica app-server) — expect interleaved JSONL.

## Notable Absences

- **Unified run→artifacts manifest or index.** No source offers `GET /runs/{id}/artifacts` or a manifest file. Agent-framework's `WorkflowRunResult` holds events but not checkpoint IDs; langgraph's `run_id` is in metadata but has no `list_for_run` index; openhands stiches `conversation_id.hex` across DB/event/archive but notes "no single API" explicitly; temporal's `VisibilityRecord.history_archival_uri` is the closest but still requires prefix reconstruction and failover-version knowledge.

- **Automated retention/GC for primary artifacts (except temporal primary).** Agent-framework: zero TTL/GC for checkpoints or history files (`FileHistoryProvider` has no `delete`). Langgraph: only `delete_thread`, Store `TTLConfig` with `supports_ttl=false` by default and no sweeper. Openhands: no `expires_at`, no reaper job, bucket lifecycle only by comment (`workspace_archive.py:408`). Temporal: primary GC is solid, archive GC is absent.

- **Archived artifact integrity (checksum/hash/encryption).** No `sha256` on `HistoryBlobHeader`, no ETag persisted in `VisibilityRecord`, no envelope encryption — noted explicitly as gaps in temporal (`codec.JSONPBEncoder` plaintext) and agent-framework (`RestrictedUnpickler` only, not integrity).

- **Artifact versioning beyond sentinel/format-version.** Agent-framework static `version="1.0"`, openhands `V1` only, langgraph `v` with compatibility shims but no migration dispatch, temporal without top-level `archive_format_version`. Content-hash deduplication and multi-version coexistence are absent.

- **Observability for lifecycle.** No metrics for checkpoint count/bytes/age, no alert on replay depth. Openhands has `export_max_events=10000` guard but no storage budget guard; temporal has `ArchivalTaskInvalidURI` metric as the only poison-task signal.

- **Generic file/blob artifact primitive.** Langgraph grep for `artifact` returns only CI uploads; temporal states "user-uploaded file must be stored externally." Generic model/scratch outputs are out-of-band in all four.

**agent-framework (6/10)** — Best hardening story for an SDK: atomic `os.replace`, `is_relative_to` traversal guard, `RestrictedUnpickler` allowlist, striped locks for concurrent history appends (`python/packages/core/agent_framework/_workflows/_checkpoint.py:317`, `python/packages/core/agent_framework/_checkpoint_encoding.py:115`, `python/packages/core/agent_framework/_sessions.py:913`). Fragmentation is the ceiling — checkpoints, histories, and durable entities share no catalog, `Workflow.id` per-instance is ephemeral and not persisted into checkpoints, and retirement is `delete()` with double-delete true/false edge only.

**langgraph (6/10)** — Most sophisticated checkpoint model: time-ordered `uuid6`, per-channel string versions, copy-on-write blobs that minimize write amplification, and efficient two-stage `get_delta_channel_history` (metadata scan then `UNION ALL` per channel @ `libs/checkpoint-postgres/langgraph/checkpoint/postgres/base.py:93-289`). The `InMemorySaver`/`Postgres`/`Sqlite` matrix is the broadest storage coverage, but the Postgres vs Sqlite divergence (blobs table vs inline) is an ops hazard. Lifecycle is incomplete by design: `delete_for_runs`/`prune` are abstract with explicit corruption warnings and no concrete override, so operators must implement GC themselves.

**openhands (6/10)** — Strongest durability-before-delete engineering: pulls workspace via `GET /api/file/archive`, streams to tempfile, `write_from_path` to GCS/S3, writes `*.manifest.json` with repo metadata, enriches cap headers, and gates sandbox teardown behind `RUNTIME_FILE_ARCHIVE_REQUIRED` with idle-reap fallback (`openhands/app_server/sandbox/workspace_archive.py:334-541`). Pluggable `FileStore`/`EventService` (`openhands/app_server/config.py:307`) enables OSS→cloud without code change. Weakness is lifecycle debt: `conversation_version='V1'` only, events overwrite (`event_id.hex.json`), event blobs and archives orphan after `DELETE`, and no inventory/lifecycle endpoint.

**temporal (7/10)** — Strongest lifecycle discipline: deterministic `GenerateWorkflowCloseTasks` branching on `archivalEnabled()` (cluster+namespace), `ArchiveExecutionTask` → retention `DeleteHistoryEventTask` with `FullJitter`, parallel `archiveHistory`+`archiveVisibility`, idempotent 4-stage `DeleteWorkflowExecution` bitmask, and scavenger GC for orphans after `historyDataMinAge` (`service/history/workflow/task_generator.go:196-365`, `service/history/archival_queue_task_executor.go:92-256`, `service/history/shard/context_impl.go:910`). Provider dispatch by URI scheme plus hash-safe filenames closes operability gaps that SDKs leave open. Deductions are archive-plane only: no TTL/GC, GCS-only resume (`common/archiver/gcloud/history_archiver.go:355`), no manifest, JSONPB without checksum.
